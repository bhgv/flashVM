# Coco/R для C

Русская версия [README.md](README.md). Оригинал сохранён.

Порт генератора синтаксических анализаторов [Coco/R](http://www.ssw.uni-linz.ac.at/Coco/) на C.

Версия 1.17 Frankie Arzu с исправлениями автора репозитория: `realloc` иногда
приводил к повреждению памяти программы, поэтому алгоритм был изменён.

Сборка и регрессионные проверки:

```sh
make -C sources -f unix.mk
python3 tests/regression.py
```

Генератор C теперь поддерживает условия `IF(C-expression)` в альтернативах,
опциональных частях и повторениях. См. [семантику, поддержку UTF-8 и результаты проверки](docs/RESOLVERS_UTF8-ru.md)
и [пример с комментариями](samples/resolvers/README-ru.md).
Строки UTF-8 поддерживаются как последовательности байтов; сканер не работает
с отдельными кодовыми точками Unicode.

## Краткое введение

### Часть Coco/R

- Слова в кавычках (`'..'` или `".."`) обозначают токены, как в lex/flex.
- `Foo = ... .` задаёт правило, соответствующее C-функции `void Foo() { ... }`.
- `Foo< ..a.. > = ..b.. .` задаёт функцию `void Foo(..a..) { ..b.. }`.
- `( ... )` группирует выражение; аналог скобок в регулярных выражениях.
- `[ ... ]` задаёт необязательную часть; аналог `( ... )?`.
- `{ ... }` задаёт повторение; аналог `( ... )*`.
- `..a.. | ..b..` задаёт альтернативы: генератор выбирает их через `if`/`else if`
  или `switch`. В исходном кратком описании это сопоставлено с C `||`.
- `..a.. ..b..` задаёт последовательность. В исходном описании она сопоставлена
  с C `&&`; это поясняющая аналогия, а не буквальное вычисление C-выражения.
- `SYNC` задаёт точку синхронизации: после ошибки можно пропустить вход до
  символа, с которого разбор способен продолжиться. Ошибку можно обработать
  через встроенные функции либо продолжить разбор.
- `( IF(..cond..) ..a.. | ..b.. )` соответствует
  `if (cond) { a } else if (lookahead_for_b) { b }`.
  Ветка без IF сохраняет проверку предсказания по токену.
- `{ IF(..cond..) ... }` соответствует C `while (cond) { ... }`.
- `(. ... .)` вставляет код целевого языка в соответствующую точку разбора:
  например, для выполнения действия после распознавания конструкции.
- `COMPILER ..Name.. ... END ..Name.. .` обозначает начало и конец описания.
  `Name` также задаёт начальный нетерминал, с которого начинается разбор.
  В кратком введении оригинала рекомендуется размещать его первым.
- `CHARACTERS` объявляет именованные множества символов: `+` объединяет,
  `-` вычитает элементы.
- `TOKENS` описывает классы токенов, распознаваемые по шаблону, а не по одному
  фиксированному значению. В шаблонах используются строки в кавычках,
  множества символов и регулярные выражения Coco/R.
- `IGNORE` задаёт игнорируемые символы и их множества; `+` добавляет,
  `-` исключает. Пробелы игнорируются по умолчанию. Примечание к оригиналу:
  табуляцию следует явно включать в `IGNORE`; одного утверждения из краткого
  введения о её игнорировании по умолчанию недостаточно.
- `COMMENTS FROM ..a.. TO ..b..` задаёт комментарии: текст между ограничителями
  не передаётся синтаксическому анализатору.
- `PRAGMAS` задаёт специальные токены, допустимые в произвольных местах входа.
  Они распознаются отдельно от обычной грамматики, но, в отличие от комментариев,
  могут иметь действия `(. ... .)` для обработки. В оригинальном введении
  раздел назван `PRAGMA`; действительное ключевое слово — `PRAGMAS`.
- `PRODUCTIONS` завершает описание сканера и начинает описание правил парсера.

### Интерфейс C

- `S_Pos`, `S_Len`, `LexString()`, `LexName()` — позиция и длина уже разобранного
  токена, получение его текста и получение имени с переводом ASCII в верхний
  регистр при `IGNORE CASE`.
- `S_NextPos`, `S_NextLen`, `LookAheadString()`, `LookAheadName()` — те же
  сведения для токена предпросмотра, то есть следующего токена разбора.
- `SynError()` сообщает о синтаксической ошибке.
- `SemError()` сообщает о семантической ошибке.
- `Successful()` проверяет, завершился ли разбор без зарегистрированных ошибок.
  В оригинальном кратком введении это имя ошибочно написано `Successfull()`.

Это основные элементы синтаксиса Coco/R и часть внутреннего C API.
Декларации API находятся в [шаблоне заголовка парсера](frames/parser_h.frm)
и [шаблоне заголовка сканера](frames/scan_h.frm).
