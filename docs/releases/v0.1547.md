# v0.1547: interactive Limbo IDE console with real native I/O

Menu item 5 now launches an interactive editor running as Dis, while item 6 keeps
the noninteractive workspace demonstration. `all` builds and installs the editor,
matching .dis/.sbl files, heavily commented Limbo source, launcher and guide.
There is no external emu dependency.

The frontend sends real channel requests to idecore for Unicode text edits,
character-offset insert/delete, literal search/ReplaceAll, Undo/Redo and saved
revisions. Actual IDE completion owners serve independent AS/Limbo catalogs and
structured active-parameter help through `complete` and `hint` commands. Both
index owners and the document owner acknowledge shutdown before normal exit.
These are initial declaration catalogs, not contextual local-variable inference.

Sys now supports borrowed descriptors 0/1/2, bounded standard-stream reads/writes,
file create(OWRITE,0666), and actual file output through FlashVM's common port.
File descriptors reserve standard slots and retain ordinary-file finalizers.
Flags and counts are validated before narrowing or destructive file opens; result
storage is allocated before create. Embedded NUL paths are rejected. Save marks
a revision saved only after successful checked/flushed writes. Invalid UTF-8,
oversized files/commands and failed writes preserve the document state.

Module imports resolve beside the entry .dis without changing caller cwd, so a
relocated application finds its modules while user file paths remain meaningful.
The interpreter/JIT budget renews on actual standard-input bytes, not EOF. Display
maps hidden controls to visible pictures using copy-on-write strings; saved bytes
remain exact. Source syntax is accepted by our Coco/R Limbo frontend as well as
the matching native bootstrap.

Validation: 29 native Dis/IDE/port CTest entries, including interactive sessions
in both execution modes; AS/Limbo completion and parameter help; real Unicode
save/load; repeated I/O beyond descriptor-table capacity; dirty exit/load guards;
invalid UTF-8, NUL paths, oversized input/files; display/source separation; resource
lookup from an unrelated cwd; and binary standard-stream round trips. Menu,
packaging and preflight regression checks pass. The installed editor is exercised
with its relocated modules/launcher, and native editor sessions are also run
under UBSan.

This remains the Linux AMD64 NC64 experimental owner. The graphical editor,
complete Sys/Styx/VFS coverage, transactional file replacement and parallel VM/GC
owners remain open. Interactive input currently blocks this single native owner;
file writes are checked/flushed but do not promise power-loss durability.
