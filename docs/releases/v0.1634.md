# v0.1634 — typed big shifts and refreshed AMD64/ARM64 slice/length guards

FIR compiler 0.20.0 and runtime 0.23.0 support checked big << / >> with explicit
int counts in our Coco/R big-result profile. New value.int normalizes int/big to
the signed low 32 bits, preserving this compiler's existing i32 contract even on
NC64. This does not change Inferno's target-native WORD semantics. Big stays 64
bits; the right shift is arithmetic and the left shift wraps unsigned bits.
Counts outside 0..63 after conversion raise invalid argument, even when unused
after optimization. Bare profile literals remain big, so counts are explicit.

Three FIR operation IDs are appended. Verifier enforces i64/i32 shift operands.
Peephole folds only valid constant counts, handles signed bits without undefined
C shifts and retains MAY_THROW for errors. Both scalar CFG and hosted DAG Dis
emit existing SHLL/SHRL (127/128); int normalization uses scalar AND/XOR/SUB.
Int copies remain unmapped scalars. Explicit big/string conversions and typeof
understand int; hosted type-name tag 4 is appended without changing 0..3 or key
namespaces. The reference runner follows the same exact integer semantics.
