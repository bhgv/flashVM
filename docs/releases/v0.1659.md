# v0.1659 — Forward source aliases and checked alias casts

[Contract EN](../../fir/v1/doc/SOURCE_ALIASES.md) / [RU](../../fir/v1/doc/SOURCE_ALIASES.ru.md) · [Tutorial EN](../../fir/v1/examples/type-aliases/README.md) / [RU](../../fir/v1/examples/type-aliases/README.ru.md) · [New commented source](../../fir/v1/examples/type-aliases/casts.b) · [Upstream check](../../disVM/SYNC.md)

FIR **0.50.0**, textual format **FIR 1.0**. Our Coco/R source compiler now records exact named type edges and validates the entire file/module prefix before the value export. Iterative resolution supports forward references, detects self/mutual cycles and unknown unused targets, and retains declaration-scope binding across module shadows. The 128-declaration cap remains explicit. Successful canonical paths are cached; no heap allocation or depth-proportional C recursion is needed.

Alias identifiers in unary position are selected by a read-only predicate over the scanner's exact lookahead token. In the big/table profile int/big/string casts reuse canonical checked conversions, including strict decimal parsing, signed32 narrowing and snapshot keys. Matching int/real identity casts in homogeneous numeric profiles emit no extra FIR instruction. Unsupported mixed numeric and table-object casts remain rejected. No new FIR opcode, runtime representation or native module ABI is introduced.

All emitted cast operations retain the authored alias token's UTF-8 byte span. Failed binding/casts preserve staged outputs. Tests cover 128-edge forward chains/cycles, wrong-scope and unused errors, optimizer preservation of failing unused casts, skipped branches, exact debug spans and long-lived C API recovery with the same alias names rebound to different types. Tutorial sources have comments on every nonblank line and detailed bilingual instructions; the installed SDK executes the new casts.b in both Dis modes.

Inferno experiment is still at 2bd9f3c after fresh fetches. Previously published reverse corrections are verified in its history; both selected manifests remain unchanged and verify exact hashes. This series changes our compiler rather than importing a nonexistent new upstream JIT revision.

## По-русски

Наш исполняемый компилятор Limbo теперь поддерживает опережающие псевдонимы, проверяет весь префикс объявлений и обнаруживает циклы/неизвестные имена даже без использования. Связывание сохраняет область объявления. Приведения через имена псевдонимов используют существующие проверяемые операции FIR/Dis; в однородных int/real-профилях разрешены совпадающие тождественные приведения. Ошибки не теряются при оптимизации, а отладочные позиции указывают на имя оператора приведения.

Добавлен построчно комментированный пример casts.b и обновлены русские/английские инструкции. Полный компилятор произвольных тел, локальные объявления типов, импорты и смешанные числовые преобразования остаются отдельными этапами. Репозиторий Inferno проверен: новых коммитов после 2bd9f3c нет, обе наши обратные правки присутствуют.
