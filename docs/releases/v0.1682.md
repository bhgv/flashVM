FIR 0.62 removes paired integer operations: add/subtract cancellation, repeated
XOR, AND/OR absorption and nested idempotence. Rules preserve int32/big wraparound,
dominating definitions and observable errors in operand producers. They do not
apply to binary64, dynamic ActionScript or reference operations. CLI, C99 APIs
and the Dis-owned IDE compiler worker share the optimizer. The fully commented
[Limbo example](../../fir/v1/examples/dis/integer-pairs.b) returns 42 through
Dis interpreter/JIT and the existing SWF8 pipeline. Grammar and target ABI remain
unchanged; own compiler parsers continue to use Coco/R.

## Direct Inferno synchronization

tree, then published unchanged as Inferno
`4b8cb80bf5cc745b3e2e3e0bad1c3d44a00fd4f4`. The explicit payload response is
`c7d08e71e808e37457d92b2ee86c67e070426ecf`. Shared string-pool codecs, tests and

`305cf8de02855afb8f9223f98582bd43d2e672e9`.
Both selected closures pin that last immutable commit: 846 manifest-hashed
DisVM files and 280 explicit legacy Limbo bootstrap files. Vendored bytes remain
identical to upstream. Coordination continues directly through the
[FlashVM journal](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-flashvm-journal.md)
and the [Inferno journal](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-inferno-journal.md).

The borrowed, allocation-free string-pool API checks exact extents and preserves
ordinal IDs, duplicate contents and signed32 Rune comparison. Writers validate
all inputs and capacity before writing. Lookup is linear; callers retain stable,
non-overlapping storage as documented.

## Build-menu and relocated tools

Build-menu entry **13**, `--launch envelope`, runs the actual Dis64 inspector.
Standalone, core, host and runtime builds provide the shared C99 headers, actual
upstream inspector and fully commented example. Relocated SDKs ship the source,
headers, guides and launcher. Cross configuration does not execute target-built
sample generators: installation can decode the checked textual fixture instead.

The inspector explicitly reports `envelope_only: true` and
`execution_supported: false`. Its M/C/T sample payloads are opaque markers.
Module/type/code semantic readers, a complete executable Dis64 compiler/loader,
reference-result GC/unwind and physical ARM64 acceptance remain future gates.
Additional payload-role/signature proposals await Inferno agreement. The existing
NC64 runtime is not silently reinterpreted as the new WORD32/ref64 ABI.
