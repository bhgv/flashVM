## Implemented compiler path

Our Coco/R source compiler 0.11 now lowers the explicit Limbo value(): big subset: table of big declarations/creation, typed or inferred locals, exact big constants, numeric/string keys, dotted-key sugar, checked copied slices, keysof and len. t.k means literal t["k"], independently of a local k. Table assignments preserve owner identity. General arithmetic/control flow, omitted slice bounds, keyseq indexing, pair iteration and typeof/any are outside this first table subset.

FIR gains exact i64 constants and typed table, location, range and key-snapshot operations. Verification checks types, arity and dominance; table effects remain conservative. A location contains owner/key identity rather than an address. Optimisation preserves failing unused loads and reads across writes. Debug origins cover all SSA definitions and the exact written member occurrence instead of the RHS.

The optional fir1_tables C99 library/fir1_table_run CLI execute the verified single-block table subset against our existing C core, with independent slice/key owners, alias-safe cleanup and staged traces. This is hosted reference execution, not Dis/JIT. The existing native Bigtable module remains separately tested on Dis. The SWO and Dis backends explicitly reject the new operations before publishing output; automatic native calls and frame GC maps are pending. No new Dis container/opcode or Inferno extension is introduced.
