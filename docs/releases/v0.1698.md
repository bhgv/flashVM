# v0.1698 — Shared-desktop debugger and MDI/SDI foundations

2026-10-30. Workspace0.1698; engine0.1693/FIR0.69.0 unchanged.
This series preserves one MovieClip desktop. It does **not** introduce separate
Source, Graphics or Debug workspaces. Source and graphic documents remain beside
ordinary debugger panels. Their eventual MDI containers must remain separate by
tool family and detachable back to SDI.

## Debugger scaffold

Debug → Open panels creates source/location, stack and data windows on the same
desktop. Each has a separate readonly pane owner and ordinary move/dock/zoom/
miniature behavior. Reopening reuses existing panel owners; closing a panel does
not terminate the debugger session. The ordinary8-pane limit remains shared;
existing documents are never overwritten to make room.

A separate typed Limbo session has exact incarnation checks, copied snapshots,
explicit disconnected capabilities and terminal shutdown. Attach/Pause/Continue/
Step/Next return Unsupported and preserve state. No target PC, stack frames,
variables or successful run control are fabricated. The existing imported
SBL/debug library remains available, but the host has no attached target `/prog`
interface. This is a graphical/session scaffold, not Inferno deb parity.

Reviewed Inferno deb/debdata/debsrc/debug.m as the source/stack/data/control
reference, without importing Draw/Tk. Next steps require actual owner safe-point
pause, stop epochs and rooted frame/value copies with interpreter/JIT parity.

## MDI/SDI membership

The new private Idemdi owner tracks document identities, source/graphics families,
container identities and membership through channels. The actual desktop registers
source/vector owners and retires their identities before slot reuse. Join refuses
mixed-family containers. Leave restores SDI membership; Dissolve restores every
child without discarding or reopening documents. Exact revisions guard mutation;
reply arrays are independent copies. Explicit initialization avoids relying on
fresh arena contents for scalar registry/panel identity storage.

**Visual MovieClip containers, child parenting/clipping, group toolbars and
interactive join/detach are still pending.** The screen currently has SDI panes.
The tested registry is a foundation, not a substitute claim of completed MDI.
Multiple source/graphics containers may eventually coexist on this same desktop;
there is no workspace switcher.

## Existing text and graphics functionality

Lazy Coco/R Limbo/AS colours retain independent revision-bound owner jobs and
copied asynchronous TextField palette updates. No new frame pacing or synchronous
parse is added to editing. Existing brush/shape/colour/fill/history and strict SVG
read/write remain usable alongside source and debugger windows. New debug panels
are read-only and cannot receive source compiler/editor mutation operations.
