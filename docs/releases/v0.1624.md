# v0.1624 — our table compiler reaches native Dis

Inferno experiment was fetched and checked first. No commit newer than b9a569efc622c8f72a34e5e76c0089feb5a57700 was available at that check. Both selected manifests remain verified byte-for-byte: 428 core and 174 bootstrap files. No table extension or host-specific change was exported to Inferno.

## Executed compiler path

Our Coco/R source compiler → typed FIR → direct NC64 Dis now runs the supported table of big subset on the actual Dis interpreter and guarded native JIT. Program emission uses no bootstrap, assembler, Python or reference-execution archive. FIR compiler version is 0.12.0; matching hosted runtime is 0.15.0.

The table backend emits existing HASLDT import metadata with checked Bigtable signatures and existing load/mframe/mcall/lea/move instructions. Table/key owners and string location keys have precise frame/data root maps. Numeric keys/ranges remain plain scalars. Paired location/range copies preserve the correct layout. Eager index/range helpers and get/set status checks keep missing/error states observable. No new Dis opcode or container extension was added.

Native acceptance runs original/optimized images with quantum=1, exercising collector passes between every instruction, including frame preparation and argument moves. Large pointer maps, exact signed-big extrema, numeric/string key separation, sparse indices, Unicode, aliases, snapshots, independent slices, typed copies and mismatched ABI signatures are covered. Successful frame retirement leaves zero native table/key owners. C table services remain ordinary compiled runtime functions; counters distinguish native Dis leaves from interpreter execution.

## Debugging and robustness

Scalar inspection validates the requested cells against GC maps instead of rejecting every module containing strings. Mapped cells and crossing ranges stay forbidden. A registered native GC root retains the inspected graph until report/error cleanup. Native exceptions resolve the actual caller PC without subtracting from a builtin's absent program segment. The compiler also handles unused undefined public symbols without indexing instruction[-1] and rejects module names beyond the Dis loader's 127-byte limit before writing output.
