# v0.1680 — checked literal-count SWF shifts and Dis64 helper synchronization

[Repository](../../README.md) · [Русское руководство](../../fir/v1/doc/SWF_INT_SHIFTS.ru.md) ·
[English guide](../../fir/v1/doc/SWF_INT_SHIFTS.md) ·
[Commented source](../../fir/v1/examples/dis/int-shifts-swf.b)

FIR 0.60 lowers checked int32 left/right shifts to ordinary AVM1 only after
proving that the count's live SSA definition is a literal in 0…31. The left
operand may be dynamic. CLI, C99 library and IDE compiler service share this
backend. Unknown or invalid counts reject before writing; no runtime error is
silently replaced by AVM1's five-bit count masking. Explicit optimization can
expose a literal through copy/constant calculation. No new parser, opcode,
SWO version or active Dis ABI is introduced.

The new source example runs a dynamic loop and returns 42. Source comments
explain every line; English/Russian guides give compile, link, execution,
proof and rejection rules. The installed SDK includes the example, libraries
and guides. Its acceptance relinks C99 clients, compares canonical CLI/API
Dis/SWO output, links SWF8 and executes the Dis in both dispatch modes.

The preceding comparison follow-up is also included: integer SSA reflexivity
and signed endpoint proofs remove impossible branches while preserving
producer exceptions. It does not apply integer reflexivity to IEEE NaNs.

## Reproduce affected checks

```sh
export TMPDIR="$PWD/build/tmp"
cmake --build build/fir --parallel 4
ctest --test-dir build/fir --output-on-failure
ctest --test-dir build/core --output-on-failure
ctest --test-dir build/runtime --output-on-failure
python3 tools/vendor-sync.py disVM
```

For actual SWF execution, pass the explicitly built host and linker:

```sh
FIR_SWL="$PWD/build/linker/swl" \
FIR_FLASHVM_RUNNER=/path/to/fir-run \
ctest --test-dir build/fir -R swf_int_shifts --output-on-failure
```

Build the host against FlashVM's public API using [the test instructions](../../fir/v1/doc/TESTING.md),
then substitute its actual path. Without those environment
inputs a compiler-only run does not establish player execution. The new test
uses 8 signed inputs × 32 counts × 2 directions, before/after optimization,
with Python oracles, actual SWF output and interpreter/JIT payload/flag checks.
Separate C99 tests repeat atomic rejection, optimizer proof and parser reuse.

There is no physical ARM64 acceptance claim or complete new-ABI module run.
The existing NC64 interpreter/JIT and separate FlashVM heaps remain active.

## Follow-up synchronized before publication

Inferno advanced during validation. The final pins above include its shared
signed30 operand writer, descriptor builder, immutable table lookup and lossless
Rune32 codec. Both selected closures are synchronized: DisVM has 827 files;
the explicit native Limbo bootstrap has 280. The direct include dependency
include/dis-operand.h is present in both snapshots with limbo/dis.c.

[FLASHVM-0003](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-flashvm-journal.md)
explicitly accepts signed32 lexicographic ordering of full Rune32 values for
compatibility with existing Inferno, with lossless BE u32 storage. This is a
normative direction agreed in the journals, not a newly enabled runtime ABI.
No implementation-defined unsigned-to-int cast is required by the wire rule.

On the later pin, the provided fixtures passed: 260364 operand writer cases,
397800 descriptor builds, 2304 single-bit maps, 6112 table validation cases,
17338 selections, 388404 Rune codec cases, and 42137 production string-view
checks in each of the WORD64/WORD32 models on an x64 host. Selected core
checks passed 7/7; rebuilt legacy bootstrap checks passed 27/27. The earlier
full 223-test core run belongs to the preceding helper revision; it is not
relabeled as a full run of the later 225-test configuration.

After rebuilding the native-cell bootstrap/runtime against the later encoder,
all 84 existing runtime .dis images were byte-identical. The installed SDK's
disvm and disvm-editor executables also matched the rebuilt files. An additional
10/10 compiler/table/shift/export runtime checks passed after that rebuild.
