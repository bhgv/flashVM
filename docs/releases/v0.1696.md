## Draw inside the IDE / Рисование в IDE

Menu **8 → Draw**, or **Ctrl+Shift+N**, creates an independently owned vector
window alongside source editors. Existing move/zoom/max/dock/reveal and live
thumbnails apply. The right Draw button and build-menu description expose the
feature; a separate mock native/browser application is not substituted.

- **B/R/E/L**: brush, rectangle, ellipse, line. **1–6**: colours; **F**: same-colour
  closed fill; **+/-**: stroke width. The current style appears in the legend.
- A continuous brush gesture becomes one midpoint-quadratic path and one Undo
  unit. A click creates a dot. Samples decimate at capacity, retaining endpoints.
  Separate gestures are separate paths; arbitrary boolean paint union is future work.
- **Ctrl+Z/Y**:16 Undo/Redo states; **Ctrl+S/O**: real SVG Save/Open. Dirty source
  refusal, path adoption, saved revision and close/quit protection use pane owners.
- A `.svg` launcher document automatically starts as a vector owner. Example:
  `sh out/disvm-editor/run-desktop-ide.sh --document /absolute/path/drawing.svg`.

One private Limbo process owns each document/history. Native rendering consumes
copied scalar commands, uses actual FlashVM MovieClip primitives, and detaches
contours for existing raster workers. Hit proposals use real composed matrices;
Limbo checks view ticket, frontmost pane and document revision. Ordinary SDL
letters/digits arrive as asynchronous/batched Text; vector tools handle this route
as well as explicit Key input. Source text editors retain their own input path.

SVG reading is a strict, documented subset: one1000×600 page, path M/L/Q/Z,
rect/ellipse/line, integer coordinates, RGB and supported fill/stroke attributes.
Unsupported features are rejected before adopting any document. Exported files
roundtrip exactly through the same model. This is not a general SVG/CSS/transform
implementation, node-selection editor or animation system. Current tool selection
uses keys; Draw is the window-creation button. Filesystem writes are checked
overwrite, not atomic replacement/fsync. See the guide for complete limits.

Реализован настоящий векторный тип MDI-документа с отдельным Limbo-владельцем,
кистью/фигурами, историей и SVG. Неподдерживаемый SVG не теряется молча: чтение
отказывает целиком. Анимация, слои, редактирование узлов и булева склейка областей
пока остаются дальнейшими этапами. Команды UI передаются только по типизированным
каналам; отдельные процессы Dis не выдаются за OS-thread-parallel VM/GC.

## Inferno synchronization and compiler correctness

INFERNO-0023 was read/reviewed and imported: private callback-free generated
native64 specifications, transactional native64bind and qualified ADT method
record names. The independent gate includes full maps, late-refusal unchanged
output, qualified methods and actual Math calls through four bound records.
This is consistency binding, not runtime registration, structural signatures or
reference-result/forced-GC handoff.43-op np0/general inspector/NC64 defaults stay.

Vector development exposed an owning Limbo Oarray bug: allocation overwrote an
ADT array field before initializer expressions read that same field/alias.
The old compiler fails the actual-runtime ADT oracle on both dispatch paths.
The owning fix uses a fresh typed/rooted array temporary and publishes only
after initialization. It was published non-force to Inferno experiment as
**1a98deb32f6409d990fd49771b63c3cc54c753b3**, then reimported byte-for-byte:
DisVM **916 files**, bootstrap **281 files**. No VM zeroing hides the caller dataflow.
The vector model also retains its explicit local Point capture for readability.
