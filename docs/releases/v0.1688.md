## MovieClip desktop

Windows can move beneath both rails using signed copied coordinates. Left docking
uses the window's right edge reaching x100 (20px beyond the80px left rail),
including motion before release. Pre-drag normal geometry and document ownership
are preserved. The pointer crossing the rail alone no longer minimizes a pane.

Thumbnail click/right swipe reveals hidden and already-open panes. Dis computes
a whole-table pan/scroll target exposing the full pane between the rails, with
5px side margins. Every logical window position and relative spacing is retained;
only an oversized pane requires reducing table zoom. Show All includes negative
origins. Hidden windows uniformly scale/move through their thumbnail; camera
reveal pans/zooms all panes. Both use240ms smoothstep with zero endpoint velocity.

Elapsed SDL time and the existing Async paint notification drive visual work
independently of SWF frames. Dis owns layout/focus/visibility and documents;
native presentation interpolates copied values, with glyph/rail contour caches.
Parallel raster workers receive immutable paths and redraw dirty tiles. Typing
retains its frame-free fast path. Resize/retirement cancel stale trajectories.

Both rails have60-percent tinted alpha, subtle deterministic grain and a mirrored
32px inward fade. There is no opaque backing rectangle beneath the glass. This
is a frosted-glass imitation, not a background-blur filter. Rounded widgets remain.
Extended BeginView metadata preserves legacy32-byte input; optional pan/reveal
fields do not expose addresses. Deterministic replay clocks test real MovieClip
pixels and elapsed-time motion, without claiming physical touch-device coverage.
Build-menu entry8 remains the same installed IDE, now with the new guides/modules.

the proven carry/borrow analysis. Known low bits and nonzero proofs survive,
including MIN wraparound. Eager producer errors remain observable when an outer
operation becomes constant or unused. No parser/opcode/format/ABI changes.

The matrix now checks384 raw/optimized results in both widths; the C99 fixture
adds10240 negation samples to the previous exhaustive arithmetic evidence.

big operations remain a Dis capability; the new source is not claimed as SWF big
support. Existing int32 matrix still links/runs actual SWF through SWL/FlashVM.
