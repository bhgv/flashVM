# v0.1748 — two real managed OS executors

Runtime0.52.0 adds opt-in `--gc-worker --managed-workers 2`. The controller and
one helper execute the same production scheduler/interpreter/JIT, with separate
TLS up/REG/native error stacks. Live Dis processes migrate after ordinary turn
completion. A native continuation remains pinned to the OS owner that suspended
it. Default execution still uses one managed executor.

One NativeWorld gate serializes managed heap/root/module/cache access. This is
an actual two-thread executor with native-wait overlap, not parallel heap
mutation. The controller releases an empty turn before startup rendezvous or
helper join; helper detaches and destroys its own TLS before GC teardown.
Claim/finish balance is checked on success, caught/unhandled errors and quota
termination. A shared input-progress epoch prevents stale per-owner idle budgets;
the instruction quota remains global.

Logical process state now follows Prog: embedded bounded error buffers, supported
floating control/status, including rounding. Host FP state is restored before
rotation, native default environment before destruction. `Sys_werrstr` has a
captured-frame implementation with full native WORD return publication. Native
C jump frames stay OS-local. This is not a full Inferno namespace/group port or
hardware FP trap context.

Audited standard I/O and sleep release heap ownership with rooted frames and
immutable staging. Ordinary FILE-backed reads/writes/formatted writes keep the
heap gate in two-executor mode to serialize their shared cursor/error state.
The graphical host admits copied UI RPC from a claimed helper turn, while
FlashVM/SDL remain on the UI owner. `--sequential-ui` with two executors refuses.
General release/acquire and arbitrary C callbacks are not promoted to resumable
continuations; synchronous native64holds still refuse release. Shutdown remains
cooperative and can wait for blocked native I/O.

[Four commented Limbo examples](../../disVM/examples/managed-workers/README.md)
and installed menu entry19 exercise migrated calculations, channels/cyclic roots,
per-Prog errors/rounding, real pipe backpressure, a shared file and helper UI RPC.
The driver compares exact instruction totals with a one-executor reference and
requires both OS owners to execute bytecode. The pipe test observes two suspended
native calls and131072 staged bytes before draining/counting200006 payload bytes.
The shared-file test verifies2176 bytes and at least257 serialized operations.
Unhandled exceptions/global-quota80 exits must retire claims and join services.
