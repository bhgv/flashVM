# v0.1820 — guarded array allocation / runtime0.121

Selected worker-mode NEWA and NEWAZ capture the full native descriptor index and
length before callbacks. Descriptor validation and the existing array extent
check precede allocation. The shared record and array coordinator acquires the
element Type and array header Type separately, initializes the complete owning
header, and writes H into every mapped element field. NEWAZ also zeros scalar
bytes. The monitor sees the rooted candidate.

The same candidate is used on a stale destination comparison. Root publication
refusal frees the private block and drops both descriptor retains. After the
handoff, errors retire the candidate through the rooted hold and preserve the
first exception. The guarded leaf classifier directs both array opcodes through
C, alongside the three record constructors. The selected worker route allocates
fresh storage even for an RC1 plain array.

The native fixture checks the mapped header and elements, stale retry, refusal
of the candidate root, monitor failure, zero length, negative and overflowing
lengths, and descriptor baselines after Fast. A Limbo guest exercises actual
array dispatch in interpreter and x64 JIT sessions. The JIT fixture verifies
that guarded constructor entries use the C path. The release and ThreadSanitizer
fixtures passed.

NativeWorld still serializes managed execution. Channels remain a separate
constructor family. Dis64 storage diagnostics and executable admission have
their own verification work.
