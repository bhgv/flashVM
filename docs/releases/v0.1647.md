# v0.1647 — ordered Unicode strings and checked text/key int values

## Русский

Компилятор **0.30.0** расширяет Coco/R big/table-профиль Limbo всеми шестью
отношениями однотипных строк и явным int-cast строки либо отдельного ключа
неизменяемого снимка. Порядок лексикографический по Unicode-скалярам, как в
stringcmp/BLTC Inferno; локали, нормализации, UTF-16-порядка и числовой сортировки нет.

В FIR дописана string.lt: string/string → bool, READS_MEMORY. Остальные отношения
понижаются через string.eq/string.lt, перестановку уже вычисленных операндов и
отрицание нормализованного bool. Свёртка корректного UTF-8 использует порядок
unsigned-байтов. Эталонный исполнитель сравнивает точные длины, включая срезы
без NUL. Dis использует готовую BLTC и карты корней кадра.

Cast строки/ключа в int составляет прежний строгий разбор decimal big и сужение
signed32 по модулю 2^32. Пробелы, суффиксы, не-ASCII цифры, пустая строка и
переполнение signed64 дают invalid big conversion до сужения. Числовой ключ
использует свой точный big. Вид ключа и пригодность снимка после удаления
оригинала сохраняются. Это контракт нашего ограниченного профиля; нативные
CVTCW/strtol Inferno и ABI VM не меняются.

[Руководство](../../fir/v1/doc/TEXT_VALUES.ru.md),
[комментированный пример](../../fir/v1/examples/tables/text-values.b),
[README](../../fir/v1/examples/tables/README.ru.md).
Пример разбирает текстовый параметр из Unicode-среза и сохранённого ключа,
сравнивает имена файлов и возвращает 42.

## English

The compiler now supports Unicode scalar string ordering and explicit checked
text/key-to-int conversion across Coco/R semantics, FIR verification/optimization,
reference execution and hosted Dis. Direct value.int FIR still rejects string
operands: source casts compose value.big and value.int, keeping parsing errors
observable even when the narrowed result is unused. Debug JSON preserves the
exact authored int token span after a Unicode prefix.

[Contract and commands](../../fir/v1/doc/TEXT_VALUES.md). Constant and dynamically
concatenated/sliced strings cover all six relations, prefixes, empty strings,
combining sequences and non-BMP scalar order. Numeric conversion tests cover
signed64 endpoints, signed32 wrap, decimal key snapshots after deletion, strict
errors, lazy skips, forged IR signatures and preservation of old output files.

During publication, a final branch check found incoming **637d618** after the
initial 5b9bdcf verification. The incoming change is included in this series:
exact snapshots now retain **560 core/reference + 174 bootstrap files**. Existing
reverse fixes remain upstream; no further shared defect requiring a reverse
patch was confirmed. Language extensions remain FlashVM-only.

## Late Inferno import / Позднее обновление Inferno

AMD64/ARM64 now expose complete decoded JIT entries for **173/173 active opcodes**,
while guarded native fast-path availability remains **166/173**. ALT, NBALT,
SPAWN, MSPAWN, LOAD, EXIT and RAISE use a safe tail bridge to the shared C executor.
The bridge leaves the original host return context intact so a C handler can
release its source Module/Jit mapping. Both entry tables share W^X publication.
Compiler header/program/cache preflight and unaligned opcode scanning fixes are
also imported. This is per-opcode dispatch, not block JIT or full semantic/native
coverage. [Upstream contract](../../disVM/upstream/libinterp/tests/README.complete-dispatch.md).

При адаптации сохранена наша NC64-политика: прямые и complete fast-входы используют
один обработчик. CASE/CASEL/GOTO с классическими четырёхбайтовыми таблицами
переходят в наши C-адаптеры, счётчик native увеличивается только при настоящем
быстром успехе. После callback не перечитывается Jit. Политика хоста отдельно
проверяется для обоих путей, включая отрицательное ненулевое завершение.
Снимок Inferno не изменяется ради этой адаптации.
