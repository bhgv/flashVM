# v0.1570–v0.1573: our compiler now emits executable Dis

This series advances the compiler/runtime path, rather than adding IDE widgets.
Our C99 FIR compiler **0.6.0** directly emits existing NC64 Dis instructions,
descriptors and initializers. Our Coco/R Limbo numeric frontend, FIR verifier,
optional peephole and direct emitter now produce programs that actually execute
on our DisVM interpreter and AMD64 JIT. No Inferno compiler/assembler emits these
test programs. The [bilingual target contract](../../fir/v1/doc/DIS_BACKEND.md)
and [commented example](../../fir/v1/examples/dis/README.md) describe the limits.

## Implemented compiler and VM work

- `fir1 dis INPUT.fir OUTPUT.dis`, public `fir_dis` and `fir_run(FIR_DIS, ...)`.
  Both CLI and embedding use the same emitter. Backend rejection preserves
  existing destination bytes; direct stream I/O failures can leave a prefix.
- One verified block, i32 constants/copy/wrapping add/subtract/multiply,
  captured trace and return. Every arithmetic intermediate is normalized to
  signed i32 despite NC64's wider native word. Constants use existing DEFL;
  no new Dis opcode, file tag or container is introduced.
- Runtime **0.8.0** adds explicit `--inspect-words OFFSET COUNT`: retain the
  actual entry-instance scalar data, validate its range/alignment/descriptor,
  report it after completion and release ownership on report or execution error.
  Pointer-bearing descriptors are rejected. Output is `DATA byte_offset signed_word`.
- Trace in this target captures ordered values in module-data cells; it does
  not invoke Sys printing or stream live SWF trace. Without inspection the
  program still runs but does not print those captured values.
- A C99 example calls source/FIR/Dis libraries in-process. Installed libraries,
  headers and examples can relink that client without source-checkout headers
  or subprocess compilers. An IDE can use this API from its build worker;
  connecting the complete IDE build service is still separate work.

## Inferno synchronization and returned fix

Both selected manifests pin
`b2746431baf23bafe653651c0fb118db6b965717` on experiment. This integrates
`7a4c7b2` FRAME leaves/channel-retain preflight and `49c4de7` MFRAME leaves/
malformed frame-map guards. Imported files remain byte-for-byte upstream blobs.

Three instruction-emulation fixtures failed during review: the Python ctypes
LeafLayout lacked new frame/import fields and passed an undersized record to
the C emitter. The repaired record includes those fields; independent C
sizeof/offsetof probes now reject future layout drift before emission.
The fix was published to Inferno experiment as **b274643**, author/committer bhgv,
then reimported through the source manifest. It is a fixture ABI repair, not a
claim that production string semantics were broken.

The repaired cases pass 15474 AMD64 byte-branch checks, 15474 ARM64 checks and
6814 character checks across AMD64/ARM64/RISC-V64. Foreign instruction emulation
does not establish physical-device/native-runtime acceptance on those platforms.

The new runtime test executes 90 dependent integer operations plus copy against
an independent signed-i32 oracle, raw and optimized, with interpreter/native
counters checked. It also executes our actual Coco/R Limbo scopes/wrap pipeline
and rejects malformed inspection ranges and pointer-bearing module data.

Final error-path review found that the inner process-error return bypassed the
outer inspection-retain cleanup. A shared release helper now also covers that
return and explicit test halt. The full suites above preceded this small cleanup
follow-up; targeted FIR/entry-failure, document-core/test-halt and standard-stream
checks then passed in both runtime builds. The new fault fixture changes the
opcode of one valid pointer-free MULW to DIVW with a zero operand; execution
fails after capture and publishes no successful DATA snapshot.

An initial compiler-example check rejected a comment before the required
physical `FIR 1.0` header. The example was corrected and the full 16-check suite
then passed. Earlier core failures were repaired upstream as described above;
the final full core/runtime runs above pass without failed entries.

Installed FIR and DisVM packages were relocated together into a path containing
spaces. CLI output, packaged embedded client and a freshly relinked C99 client
produce identical `.dis` bytes. Both runtime modes observe `2147483647`.
`tools/test_installed_workspace.py --fir-dis-only` repeats that acceptance.
All **59** installed Markdown guides have resolved relative links.

Packaging review found that symlinked build directories caused archive scanning
to omit SDK libraries. The installer now resolves the scan directory before
walking it, preserving archive-relative paths. FIR ships the new example,
backend/API guides and libraries; the native-console guide is linked locally.
The documentation source index reports zero stale files; both vendor manifests
and Git whitespace checks pass. Backup patches cover this four-commit series
and the independently published upstream fixture fix.

## Deliberate limits and next work

The target is experimental NC64 magic 819264 on our tested Linux AMD64 runtime,
not classic Dis or the proposed standard ABI64. General functions/signatures,
imports/exports, CFG, f64/strings/channels, complete AS/Limbo lowering, Dis linking
and SBL/source-PC mapping remain unimplemented in this backend. AS source
profiles still target the existing binary64/SWO path. Source `-g DEBUG.json`
metadata is not automatically Dis SBL. The complete graphical IDE still uses
temporary source-built bootstrap modules until our language coverage is sufficient.

## Русский

В этой серии развивается именно собственный тракт компиляции: наш Coco/R
Limbo→FIR и C99 FIR→Dis создают настоящий исполняемый NC64-код без bootstrap-
emitter. Есть консольная команда и библиотечные API, нормализация каждого i32
результата, скалярная инспекция нашего DisVM и переносимый C99-клиент.
[Русский контракт](../../fir/v1/doc/DIS_BACKEND.ru.md) и
[подробный пример](../../fir/v1/examples/dis/README.ru.md) связывают исходники,
API, запуск, владение и ограничения.

Из Inferno перенесены FRAME/MFRAME и проверки дескрипторов. Найденное
несоответствие ctypes/C исправлено и отправлено обратно как b274643; затем обе
выборки обновлены из опубликованного коммита. Пройдены полные 85/87/79 тестов
ядра/обычного runtime/UBSan runtime и по 16 тестов FIR в трёх сборках. Проверены
реальная генерация и исполнение, а не только распознавание синтаксиса.

Это ещё не полный Limbo→Dis: первая цель — один i32-блок с захватом trace в
данных модуля. Функции/модули, CFG, другие типы, каналы, Dis-линкер и полноценная
отладочная информация остаются следующими этапами. Инспекция скаляров не
подменяет breakpoint и пошаговую отладку.
