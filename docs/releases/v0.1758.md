# v0.1758 — explicit native strong-owner scopes

Native owner scopes record distinct strong references on an exact bound context.
Caller-provided stable entries need no separate malloc per retain. Nil assignment
consumes one entry; explicit close drains remaining entries in reverse order.
Entries clear before callbacks, callback reentry refuses and held object guards
prevent cleanup. Open scopes prevent TLS unbind.

Native transfer envelopes move one existing owner between scopes without an
extra retain. Sending code retains BEFORE thread publication; failed startup
cancels only an unpublished envelope. The updated mutable-object example uses
one scope per OS worker and closes it in the normal epilogue.

The local/shared compiler strategy is documented: local slots differ from their
referents; module instances differ from shared code; publication must invalidate
all old local aliases before another executor runs. Unknown/dynamic cases use a
conservative shared path. Refcounts count owners, not threads or locality.

This is a native library/SDK step, not a new managed allocation domain, automatic
Dis process exception cleanup, GC-root registration or implemented compiler escape
analysis. Managed Heap/Type/Jit, runtime file format and exclusive NativeWorld
admission stay unchanged. The existing runtime version remains 0.61.0.

See [ownership rules and exact scope](../../disVM/runtime/LOCAL-OWNERSHIP.ru.md)
and the [commented example](../../disVM/examples/native-object-guard/README.md).

Validation on native Linux x64: both count backends pass normal, nonrecovering
UBSan and focused TSan, including fourteen semantic removal controls. Eight OS
workers hold seventeen strong owners at a checked barrier; one hundred transferred
objects are actually freed after sender scope close. Native owner/world/REG suites,
five affected runtime regressions, independent CMake example, installed example/
driver and strict C89/C++98 public-header compilation pass. Vendor manifests stay
unchanged. These are not whole-VM/JIT/platform or managed parallel-heap proofs.
