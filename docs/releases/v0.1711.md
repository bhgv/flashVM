## Reverse contribution and coordination

[FLASHVM-0040](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-flashvm-journal.md)
answers INFERNO-0036 through INFERNO-0042. It supports the private C direction,
requires exact result Type identities and preserves the distinction between a
failed result publication and already completed native output. A future richer
status is proposed for review; no unilateral wire decision is made.

The new owning `native64-module-order.c` independently covers all request and
retirement orders of three modules: 72 scenarios per compatible model, with and
without an older owner. It checks exact remaining registry order, borrowed alias
lifetimes, actual surviving C calls and empty transactions with unreadable unused
spans. Existing atomic-publication and staged-retirement removal controls remain.
No production defect was found in the reviewed scope.

## Reproducible local review

Two opt-in runtime CTest groups are defined in their own CMake module. They use
the source-built compiler for C metadata and strict UBSan; installed runtime
execution gains no sanitizer dependency. Detailed commands and limits:
[English](../../disVM/NATIVE64-REVIEW.md),
[Русский](../../disVM/NATIVE64-REVIEW.ru.md). Both guides are installed in the SDK. FLASHVM-0041 adds an explicit existing
`NATIVE64_TMPDIR` scratch location to the two owning drivers; CTest selects a
build directory so review-generated files do not pollute the selected snapshot.

## Unchanged admission and evidence limits

Frame64/map8, default 43-op np0, `execution_supported=false`, packed Sys refusals,
full-startup guard and NC64/SDK executable defaults remain unchanged. Private C
tags are not Dis64 wire kind IDs. Atomic module graph publication does not roll
back initializer effects. Native output cannot be rolled back after a late
publication failure; automatic retries are unsafe.

Existing optimized UTF/injected-unwind ASan evidence remains open. Host fixtures
and cross-compilation are not physical ARM64/RV64 execution or full-VM boot.
The earlier unrelated Python host-driver timeout-cleanup limitation is not fixed
by this source synchronization. Compiler/FIR wire formats are unchanged.
