# v0.1635 — string-branch and owner preflight on AMD64/ARM64

Inferno experiment synchronization imports 808a4f6 and 70611aa, followed by our
reverse checkpoint ca53cc69902388ee5b982f9d669f0d32534d9539 and incoming
85cd4e5d01df291b04215b501db406817b8662b0. The exact selected
snapshot has 503 core/reference and 174 bootstrap files. This release changes
existing guarded native paths, without adding new opcode availability or
changing the native WORD ABI. Language table/any/int extensions stay in FlashVM.

String predicates validate both decoded source slots and both nil owners before
String headers. A false predicate leaves even an invalid/unmapped destination
slot unread. Taken-target bounds are checked before loading or publishing PC.
This preserves source-error priority, signed Rune comparison and empty/identity
behavior on C, AMD64 and ARM64.

MOVP, SELF, HEADP and TAIL preflight pointer slots, selected List fields, source
Heap-header spans and source lifetime before previous-owner reads or mutation.
The previous destination owner is validated before reference retain, GC marking
or source publication. Declined JIT execution preserves VM-visible bytes and FP
state. SELF ignores its unused source. C HEADP/TAIL preserve their existing
REG.s redirection convention after successful List-field selection.

Our returned Inferno `owner-optimized.py` checkpoint runs all 1,600 preflight
cases under Python -O. It forces both priority architectures and clears family
filters; compiler and dependency paths remain configurable. FlashVM's CMake now
registers both this checkpoint and the previously omitted full owner-JIT matrix.
The full matrix checks 193,896 ownership/alignment/GC/FP cases in addition to the
1,600 preflight cases. Replaying pre-repair cd402a0 emitters under -O reproduces
invalid-source-slot memory-read faults on both AMD64 and ARM64; repaired emitters
pass. These negative controls are validation evidence, not shipped old emitters.
