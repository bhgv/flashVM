# v0.1708 — Sparse FIR products and bidirectional native64 validation

FIR implementation 0.71 preserves known-zero/known-one bits through multiplication
by an exact constant with one or two set bits. Two shifts and a bounded modular
carry transfer replace no IR instruction. Both 32/64-bit widths and operand orders
work, including sign-bit factors. Arbitrary/dynamic factors keep the conservative
transfer. Producer errors and debug origins remain; FIR1.0/SWO/Dis formats and
public C99 layouts do not change.

`(x&7)*3` now supplies the raw SWF backend with a proof that an int32 shift count
fits 0..31. `(x&15)*3` remains rejected before replacing an existing object. This
is bit analysis, not a general interval solver. Shared carry logic and product
logic have separate private headers. See [proof](../../fir/v1/doc/SPARSE_PRODUCT_FACTS.md)
/ [объяснение](../../fir/v1/doc/SPARSE_PRODUCT_FACTS.ru.md), and the fully commented
[Limbo example](../../fir/v1/examples/dis/sparse-facts.b) with detailed
[README](../../fir/v1/examples/dis/README.md#sparse-factor-example-fir071).
