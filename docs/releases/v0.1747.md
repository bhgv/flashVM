# v0.1747 — managed-turn claims and synchronized Dis64 verifier gates

Runtime0.51.0 introduces explicit dispatch ownership for complete managed turns,
separate from runnable membership and native continuation ownership. Claim is
restricted to the runnable head and an idle bound context. Foreign pops/finishes,
duplicate/nested claims and early finish during a native wait refuse. Whole REG
copies cannot replace the native metadata. All successful, caught/fatal error,
blocked and module-retirement paths release exactly one claim before rotation
or free. Host callers retain context/process lifetime under heap exclusion.

A native waiter keeps its original dispatch owner off the runnable FIFO while
another real OS context can claim a DIFFERENT runnable Prog. After ordinary
finish/wake, that same original Prog can be assigned to another context. The
20000-operation FIFO oracle and eight active controls cover synchronous holds,
foreign native restore/claim/finish, duplicate append, missing withdrawal,
nested dispatch after clearing roots and early unbind. Default/UBSan/focused TSan run separately. Production
GC/UI native-queue probes now check the real dispatch owner and require balanced
NATIVEDISPATCH claims/finishes with active0 on normal and budget-error exits.
There is still one production managed executor, not a completed parallel pool.
