# FlashVM v0.1725 — dense contour selection crash and picking cost

Fixed the reported object-selection → Nodes transport failure and reduced the
work performed by the Limbo owner for dense figures. IDE version:0.7.11.

## Reproduced failure

An actual desktop replay opens a filled oval with256 quadratic segments, selects
it, switches to Nodes and touches its contour. Installed v0.1724 terminates with
`desktop wire code=65577` and `graphical editor transport/presentation failure`.
The node overlay contains an open control guide followed by a square handle;
the native reader incorrectly applied the source-contour Close-before-Move rule
to that transient path. The final presentation path in editing modes now admits
valid open-subpath transitions. Source-path restrictions and all existing bounds,
verb, command/count and post-Close validation remain active. Four-sided handle
clamping also prevents an above-page rotation handle from emitting negative
coordinates. SVG/history source geometry is unchanged.

## Picking and presentation

The old reverse-order picker flattened every quadratic into32 segments before
checking stroke distance and even/odd filled interior, including distant curves.
Now an admitted immutable brush coverage mask supplies an O(1) interior hit.
Invalid-size/missing masks fall back safely. Conservative bounds are cached by
exact immutable shape identity. Disjoint figures/control hulls are skipped;
short surviving curves use8 samples, others32. A release without displacement
restores the baseline array without a full node transform pass.

`idevectorpresentation.b` separately caches selection serialization. Unchanged
Snapshots reuse both source and overlay strings through four bulk segments.
Source bytes are extracted once per geometry identity; pointer/mask/tool/selection
changes invalidate only the overlay. Undo/worker publication invalidate through
array identity. Idle Cancel keeps the cache. Mutable caches stay in the pane;
raster workers receive only immutable copied geometry.

## Evidence

- Same x64 JIT executable, same256-quadratic imported-style model and20 interior
  clicks: old Idevector6390ms, new Idevector112ms. Initialization, GUI/transport
  and raster time are outside this interval. A new-runtime repeat measured118ms.
  This is a synthetic picking measurement, not a physical end-to-end latency or
  universal speed claim. The commented optional benchmark ships in the SDK.
-16 affected picking/editing/viewport/native-ink/retained/parser checks passed.
  Five focused model/dense-UI/parser cases passed after final bounds/mask guards.
  Repeated Snapshot tests verify no extra presentation rebuilds.
- Dense UI replays cover real Open, selection, Nodes, contour click and source-only
  Save in interpreter/JIT. The regression additionally draws a filled oval plus
  connected same-colour Brush ink, selects the union and enables Nodes; one
  source object survives Save. The old installed product reaches its real wire
  failure, rather than a compile failure or mocked decoder.

Full matching runtime/Dis rebuild is required because the private owner document
layout gained presentation/bounds caches. No shared SWF/Dis64 registry or native
file-call admission changes. [English guide](../../ide/VECTOR-PICKING.md) ·

Installed SDK acceptance also compiled its shipped benchmark with limbo-native
