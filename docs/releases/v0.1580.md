# v0.1574–v0.1580: scalar control flow from Coco/R Limbo to our DisVM

Our C99 compiler 0.7.0 now emits executable NC64 Dis for verified scalar FIR
control flow: boolean constants/copy, signed i32 comparison, conditional branches,
forward/backward jumps and wrapping arithmetic. Relocations use instruction PCs,
including targets requiring four-byte operands. CLI and public C99 library share
this backend. No Inferno compiler or assembler emits these programs.

The Coco/R Limbo numeric adapter accepts terminal `if`/`else` decision trees with
all six integer relations. Branch and comparison source spans are retained in
FIRDBG1. This is a bounded language subset: no mutable source loops, phi nodes,
imports or complete Limbo compiler are claimed. The FIR target supports backward
edges; source decision trees remain terminal. AS numeric adapters retain their
existing scope. See the [target contract](../../fir/v1/doc/DIS_BACKEND.md),
[source syntax](../../fir/v1/doc/SOURCE_SYNTAX.md) and fully commented
[examples](../../fir/v1/examples/dis/README.md).

Capture cells follow static trace-site order, with a separate executed flag per
site. An untaken arm is distinguishable from a captured zero. Repeated visits
replace that site's value; this is not an event log. Optimization can change
physical site numbering. The conditional example produces values `0,42,0` and
flags `0,1,0`.

DisVM runtime 0.9.0 adds `--max-instructions COUNT`: a process-wide dispatch quota
checked at instruction safepoints, including before translated execution. It is
not a wall-clock timeout. Default dispatch increments the counter inline, avoiding
an external call per instruction when no quota was requested. Exhaustion reports
the current instruction, cleans up retained inspection data and emits no partial
DATA report. Tests cover real cycles, exact success/failure boundaries and
interruption between a capture value and its executed flag.

Verifier fixes reject interleaved live blocks and mismatched first live blocks,
including a removed prefix supplied through the public API. The Coco/R structural
frontend distinguishes following block labels from optional return operands;
comments, empty groups and typed block parameters have regressions. Generated
parsers remain build outputs; grammars are authoritative.
