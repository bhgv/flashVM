# v0.1704 — Reusable task records without reused identities

2026-10-31. Workspace 0.1704. Ordinary Limbo task service and host acceptance tools.

`asinctasks` can now process more than 32 tasks without replacing its owner.
Capacity 32 limits retained records, while monotonically issued task IDs and claim
leases never recycle. Retire removes a terminal record only after its result has
been taken. Unfinished work and untaken results, including valid empty strings,
return Busy. A cancelled worker must still acknowledge termination first.

A new task can occupy a freed earlier slot without overtaking old queued work:
Claim chooses the lowest queued ID. Snapshots copy retained records sorted by ID.
Messages naming issued but retired tasks return Stale; zero, negative and
never-issued IDs return Invalid. A late finish cannot complete a replacement task.
The last positive int ID 2147483647 works normally, but all later submissions
return Full even after retirement empties the table. No counter wraps or ID reuse.
A replacement owner still requires a new caller-managed incarnation.

These are application-local protocol changes, not a new Dis64 format/ABI.
Existing request/reply fields and old operation constants remain compatible;
Retire is appended. The service remains scalar-only cooperative Limbo, with
AS closure/FIR lowering, arbitrary captured object graphs, forced cancellation
and recoverable OOM still pending. Directional capture publication is separate.

## Example and verification

The commented example executes 96 real spawned-worker tasks on one owner, takes
each result and retires the record. EN/RU contracts explain capacity, stale IDs,
FIFO, independent snapshot ownership and exhaustion. Installed packages contain
the library, example bytecode, interfaces, source and acceptance source.

Lifecycle acceptance passes 2531 active predicates per execution in interpreter
and JIT, with both default scheduling and quantum 1. The tiny-quantum runs report
534432 collector calls/100452 completed epochs each; JIT reports505805 native
instructions, interpreter0. This exercises the actual runtime with these managed
State/Task/string roots, not native admission of arbitrary AS closure graphs.

A private temporary-source fixture seeds only the initial ID counter immediately
below its maximum, then executes 16 predicates per runtime profile through actual
Submit/Claim/Complete/TakeResult/Retire paths. It proves boundary behavior without
a public counter-seed API or a claim that two billion submissions were executed.

Five Limbo inputs pass our Coco/R syntax frontend. Bytecode emission still uses
the documented source-built bootstrap. The six focused normal/quantum/limit gates
pass; example and complete lifecycle bytecode pass both profiles after installed
package relocation to a path containing spaces. Installed guide links and 36
menu/desktop menu checks pass.

Full SDL-enabled runtime/IDE validation passes **343/343**. The final affected
six-gate task subset passes again after source-comment formatting. A separate
compatibility check loads the original installed v0.1703 acceptance bytecode
against the new owner and passes all 167 original predicates in both modes.
