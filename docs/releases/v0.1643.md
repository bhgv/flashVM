# v0.1643 — Unicode string operations and C99 IR validation

## English

Compiler **0.26.0** adds Unicode string length, indexed scalars and half-open
slices to the Coco/R Limbo big/table profile. String len and indexed characters
return int; bounds are int, while hybrid table/key lengths remain big. Positions
are Unicode scalars, not bytes, UTF-16 units or graphemes. Source aliases remain
unchanged across empty/full/nested slices. Numeric conversion of reference slices
uses explicit byte extents, not an assumed trailing NUL.

Three append-only FIR IDs — string.len, string.at, string.slice — retain existing
types and prior operation IDs. The hosted Dis backend uses existing LENC/INDC/
SLICEC and retains the source into a distinct rooted destination before slicing.
Correct frame middle operands carry indexes and slice ends. Existing native
paths or C fallback remain authoritative; there is no new opcode/helper ABI/tag.
The current hosted string path still uses existing Bigtable/range-check setup.

A separate API bug fix rejects malformed live string constants constructed through
public C99 IR fields. Textual and direct-IR callers now share strict UTF-8 checks:
continuation, overlong, surrogate, >U+10FFFF and truncation cases fail before
Dis/SWF output changes. This is our FIR verifier fix, not an Inferno VM patch.

The tutorial checks emoji/scalar geometry and unchanged aliases, then converts
an x42y slice to 42. In-process source+FIR C99 clients and original/optimized
backend/reference clients are used by relocated SDK acceptance in both VM modes.
String source events preserve exact len/bracket bytes after UTF-8 prefixes.
General int arithmetic, full languages, Dis SBL/debugger attachment and IDE
Build/Run/Debug panels remain separate work.

Inferno experiment was checked at **dd0f5d6**: no new incoming commit since the
previous series. Exact snapshots remain **545 core/reference + 174 bootstrap**.
Earlier reverse fixes are present; no new shared native defect required an
outgoing patch. Frontend/FIR changes stay FlashVM-only. Native availability is
unchanged at 164/173; physical ARM64/full OS boot are not claimed.

Acceptance: FIR **31/31**, no-table-core **29/29**, focused UBSan **4/4**.
Rebuilt runtime **135/135**, 330.24 seconds. Strengthened Unicode tests passed
again on both actual dispatch modes, covering U+10FFFF, exact origins, typed FIR,
eager bounds, lazy skips and one-instruction GC/scheduler quanta.

## Русский

Компилятор **0.26.0** добавляет Unicode-длину, индексирование символов и
полуоткрытые срезы в Coco/R Limbo big/table-профиль. Длина строки и символ имеют
тип int; границы — int. Длины таблиц/ключей остаются big. Позиции — Unicode-
скаляры, а не байты, UTF-16-единицы или графемы. Пустые/полные/вложенные срезы
сохраняют исходные псевдонимы; числовой cast эталонного среза учитывает длину,
не требуя NUL за последним выбранным байтом.

В конец enum FIR добавлены string.len, string.at, string.slice; прежние типы и ID
сохранены. Dis использует LENC/INDC/SLICEC, удерживая исходник в отдельном GC-корне
назначения. Индексы/концы читаются из кадра. Работают существующие native-пути
или C fallback; новых opcode/helper ABI/тегов нет. Hosted-путь строк пока сохраняет
существующую зависимость Bigtable/range-check.

Исправлен FIR API: некорректные живые строковые константы из прямых C99-структур
теперь отвергаются так же строго, как текстовый ввод. Проверены continuation,
overlong, суррогаты, >U+10FFFF и обрывы; выход Dis/SWF не меняется. Это исправление
нашего verifier, а не патч VM Inferno.
