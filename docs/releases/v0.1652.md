# v0.1652 — graphical Limbo browser and codec owner guards

Runtime **0.28.0**, IDE backend **0.7.0**, Limbo IDE package **0.12.0**.
[Graphical contract EN](../../ide/dis/GRAPHICAL-BROWSER.md) / [RU](../../ide/dis/GRAPHICAL-BROWSER.ru.md) ·
[Model](../../ide/dis/bridge/idebrowser.m) · [Tutorial](../../ide/dis/examples/directory-browser/README.md).

Ctrl+B opens the directory path field in the actual FlashVM-rendered IDE. The
selected-entry footer supports Up/Down, PageDown, Enter, B, R and Escape. The
exclusive Limbo Idebrowser model exchanges typed Idefiles requests and owns at
most one published cursor plus one staged candidate. Only bounded copied labels
cross to the renderer; native filesystem calls remain in OS ports.

Candidate path and first-batch admission preserve the old cursor on failure.
Selection returns the complete native file path; the controller checks dirty
state, validates actual source data and waits for document acknowledgements
before adopting its save destination. All clean/forced application close paths
acknowledge the directory owner first. Correlation IDs reserve terminal cleanup;
near-exhaustion rejects candidate admission before a native cursor can be stranded.

Callable Browse/Move/Next/Choose/Close commands require both current document
revision and completed-view ticket. The native renderer adds Panel 9 (read-only
browser) and Panel 10 (ordinary Unicode directory path field). Source text, paste,
Delete and pointer gestures are never forwarded from the browser into document
editing. Names appear before long path previews in the footer.

The selected Inferno pin is **3760fc951987915d4c823ba30f56f07386e98b18**:
packed Rune exports use aligned locals, and C plus AMD64/ARM64 codec paths reject
malformed result owners/descriptors before side effects. Original codec-owner
C/JIT regressions are selected. Exact snapshot: 650 core/reference/library files
and 207 bootstrap files. The upstream revision retains our prior reverse 73a6b5a;
no new shared source defect requiring another reverse patch was found here.

## Scope and acceptance

Tests replay actual channels, native files and FlashVM pixels in both execution
modes: Unicode path adoption/save, nested directory entry, dirty-source refusal,
stale ticket rejection, failed candidate preservation, bounded paging/EOF and
normal modal/window close behavior. The reusable tutorial exercises model bounds,
label bytes, request-ID exhaustion and repeated shutdown at quanta 1/2048.

The footer presents one selected entry, not a fully expanded tree. Native order
is preserved; B edits another path, R restarts the first batch. Native I/O is still
blocking. Graphical path fields permit 256 scalars, callable envelopes 1024 UTF-8
bytes, direct model/service paths 4096 bytes. Windows/macOS/Android native and
physical input acceptance remain open. ARM64 leaves run under Unicorn; Linux
AMD64 is the native execution target. No complete debugger or compiler self-hosting
milestone or Flash compatibility stage is closed.
