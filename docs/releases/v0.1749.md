# v0.1749 — bounded managed OS-executor pool

Runtime0.53.0 extends `--managed-workers` from1/2 to1..8 total OS executors.
Default remains1; the installed menu19 launcher defaults to2 and accepts
`DVM_MANAGED_WORKERS=8`. Above1 requires worker GC and threaded UI for the
editor. Every helper executes the same production scheduler/interpreter/JIT,
with its own TLS up/REG/error stack and native continuation affinity.

Stable per-helper native slots replace the single helper identity. Startup
rendezvous waits outside heap ownership for every helper; shutdown and partial
creation failure join every started helper before clearing service storage or
stopping collectors. A Linux-only test interposes actual pthread creation and
refuses it after0/1/5/6 managed helpers, requiring all successful creations and
joins to pair; a non-hit control checks normal forwarding. No production failure
injection option is added. UI authorization checks the live helper set only inside
an ACTIVE claimed turn in the same world. Native-only counters are read after
join. `NATIVEPOOL_WORKER` distinguishes actual bytecode turns, rootless scheduler
handoffs, and native I/O release/reentry counts; a compute-only helper may have
zero I/O releases.

The new [eight-writer Limbo example](../../disVM/examples/managed-workers/backpressure-eight.b)
and [capacity driver](../../disVM/runtime/test_managed_pool.py) test C/JIT,
4/8 executors and every helper's real bytecode work/retirement. Compute instruction
totals must equal a one-executor reference. An actual4096-byte OS pipe is kept
full until EIGHT native continuations are suspended; then800024 payload bytes
are counted, with peak524288 staged bytes and paired leases/reentries. Eight-owner
unhandled-error and global-quota80 exits must retire claims and join services.
The editor also checks helper UI RPC at4/8. Existing two-owner quanta1/31/2000,
locked/atomic polling, cyclic roots, per-Prog error/rounding and shared-file tests
remain in place. Native Linux x64 is the execution target tested here.

One NativeWorld FIFO gate still serializes heap/root/module/cache mutation.
More executors overlap more native waits; CPU-bound managed computation does not
become parallel. Ordinary file operations still retain the heap gate pending
per-handle auditing. Arbitrary C callbacks, native64holds and cooperative shutdown
restrictions remain unchanged. There is no unsafe forced native cancellation.
