# v0.1678 — ввод и параллельное рисование по изменениям

[Workspace](../../README.md) · [English contract](../../flashVM/doc/RENDER_ASYNC.md) ·
[Русский контракт](../../flashVM/doc/RENDER_ASYNC.ru.md) ·
[Рабочий стол](../../ide/DESKTOP-WORKSPACE.ru.md)

Задержка ввода была связана с барьером растеризации перед следующим событием и
полным рисованием стола у владельца VM. Кадровый такт SWF в этом пути не является
часами обработки клавиатуры. Нативные клавиши теперь проходят по завершённому
подтверждённому состоянию Dis без ожидания пикселей. FIFO и канальный порядок
сохранены; попадание указателем ждёт совпадения пикселей и геометрии.

Владелец сохраняет иерархию MovieClip, исполняет AS и подготавливает неизменяемые
команды. Новый API захвата использует настоящий защищённый обход FlashVM, а не
подменённые прямоугольники. Текст, выделение, обрезка, слои и группы прозрачности
передаются нативными значениями. Потоки не обращаются к объектам VM, шрифтам,
документам, каналам, GC или SDL.

Постоянный координатор очереди распределяет изменившиеся плитки 64×64 максимум
между четырьмя потоками пакета. Для каждой плитки воспроизводятся все пересекающие
слои в исходном порядке. Старые и новые области перемещения/удаления учитываются;
добавленная буква не инвалидирует все прежние контуры. Та же сцена не запускает
растеризацию плиток. База сравнения — последний действительно показанный снимок,
а не пропущенное промежуточное задание. SDL получает только изменившиеся плитки.
Expose повторно показывает сохранённые пиксели без пересборки сцены в Dis.

Пакет клавиатуры может заменить ещё не нарисованные состояния; граница пакета
или 16 мс при очередном опросе запрашивают рисование независимо от FPS SWF.
Это не гарантия задержки. Явные replay/capture сохраняют показ каждого состояния.
Обычные синхронные API MovieClip не меняют поведения.

Ограничения: новый захват поддерживает сплошные заливки и круглые штрихи, а не
bitmap/gradient или произвольный SWF. Потоки плиток создаются на пакет; постоянный
пул плиток пока не реализован. Полные копии базовых пикселей и работа раскладки
у владельца остаются. Физическая задержка ввода и другие платформы не измерены.
Dis64, ABI, контейнеры, собственные Coco/R-компиляторы и снимок Inferno не менялись.

Проверки и воспроизведение:

- [Нативный захват](../../disVM/runtime/test_movieclip_capture.c): все пиксели
  совпадают с обычным MovieClip после уничтожения VM; ошибки калбэка проверены.
- [Плитки](../../disVM/runtime/test_editor_incremental.c): все пиксели совпадают
  с независимым полным рисованием; перекрытия, альфа, движение, удаление,
  неизменившаяся сцена и добавленный локальный контур.
- [Очередь SDL](../../disVM/runtime/test_desktop_touch.c): клавиши при pending
  raster, FIFO, указатель, replay/capture и прежние жесты.
- Реальные сценарии стола проверяют непрозрачность, каналы и владельцев файлов
  в интерпретаторе и JIT; dummy/replay не считаются физической проверкой устройства.

Итоговая проверка: полный runtime — **265/265**; после финального изменения показа
повторены 7 затронутых проверок — **7/7**. Четыре прежние проверки синхронного
MovieClip прошли отдельно. Перенесённый установленный редактор проверен в
интерпретаторе/JIT; реальное build-menu собрало пакет, 28 проверок меню прошли.
Компиляторам в тестах задан доступный TMPDIR внутри рабочего каталога: начальный
запуск без него не мог создать временные файлы компиляции. Общая проверка
установленных модулей требует отдельного IDE-пакета; для этого графического
пакета выполнена целевая проверка переноса рабочего стола.
