# v0.1663 — Direct typed int complement and Rune provider integration

[Integer contract EN](../../fir/v1/doc/INT_BITS.md) / [RU](../../fir/v1/doc/INT_BITS.ru.md) · [Line-commented example](../../fir/v1/examples/dis/int-complement.b) · [Example guide EN](../../fir/v1/examples/dis/README.md) / [RU](../../fir/v1/examples/dis/README.ru.md) · [Synchronization](../../disVM/SYNC.md)

FIR implementation **0.52.1**, source CLI **0.19.1**, textual format **FIR 1.0**. Typed table-profile int complement now emits a signed32 -1 constant and i32.xor instead of widening to big, big.not and narrowing back. Existing operand evaluation order, checked producer errors, unary-token debug spans and big complement semantics remain intact. No new FIR/Dis opcode, native ABI or SWF feature is introduced.

The new table-backed tutorial loads -43, explicitly narrows through a local int alias, complements to 42 and widens only its exported result. Every nonblank source line is commented. Bilingual guides explain the pipeline, trace slots, GC ownership and Dis-only table boundary. Relocated runtime/editor SDK acceptance relinks a fresh C99 client, compares its Dis bytes with CLI emission and executes raw/optimized images in both dispatch modes.

Inferno **467f52d416357088597ee4fad9b8a98ca0b8c57c** restores missing Rune formatter providers with checked allocated growth and ownership. Both snapshots pin that commit with **703 Dis / 231 bootstrap files** and exact hashes. In addition to the upstream moving-allocation oracle, a new integration executable resolves public Rune wrappers from the actual bootstrap lib9 archive. It checks zero-capacity nonmutation, non-BMP scalar truncation, growth/cursor retention and caller-owned formatter flush/free. libkern fixtures run independently; no kernel library is imported into the bootstrap or Dis runtime.

Earlier outbound corrections remain ancestors in Inferno. Review found no additional shared defect requiring an outbound commit. FlashVM-specific compiler optimization and table tutorial remain in FlashVM. This release does not establish ARM64 hardware acceptance or a complete compiler/IDE implementation.

## По-русски

Дополнение типизированного int в профиле с таблицами больше не проходит через big: генерируются константа -1 и i32.xor. Операнд вычисляется один раз; ошибки его преобразования сохраняются даже после удаления неиспользуемого результата. Отладочная позиция указывает на исходный знак дополнения, включая смещения после UTF-8. Семантика big не меняется.

Добавлен полностью построчно прокомментированный пример с загрузкой из таблицы, псевдонимом int и результатом 42. Русское и английское руководство объясняет команды, слоты результата и освобождение временного владельца GC. Установленные SDK проверяют тот же путь через CLI и заново собранный C99-клиент, исходный и оптимизированный Dis, интерпретатор и JIT.

Из Inferno перенесены восстановленные функции Rune-форматирования. Новая проверка связывается с настоящим архивом lib9 и проверяет публичные функции, Unicode, рост и владение буфером. Оба снимка проверяются по хешам. Прежние обратные исправления сохранены в Inferno; нового подтверждённого общего дефекта для обратного коммита в этой серии не найдено.
