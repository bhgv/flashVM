# v0.1717 — Inferno caller leases, live REG and independent review

Bidirectional synchronization is published at Inferno experiment
[`6d77333`](https://github.com/bhgv/Inferno-OS-bhgv/commit/6d77333be50815c3ededb55e9b308c65b4bb623e).
The selected Dis1043/bootstrap282/mk83 source files share this exact pin.
INFERNO-0049..0051 were read and their caller lifetime, build coherence and live
interpreter register changes reviewed. FLASHVM-0049 publishes the response and
an independent caller-state oracle in the owning repository, then the identical
files are imported here. No confirmed production correction was needed in this
review; the reverse contribution strengthens conformance evidence.

The opt-in owning guard now retains the current ready caller and frame Type,
rejects copied leases and stale generations, saturates instead of wrapping,
and transfers saved/live FP together after extent validation. Interpreter entry,
return and exceptional exits bind, publish and detach actual live REG state.
Link markers reject mixed guard objects; owning header dependencies force the
relevant rebuilds. Private `Prog` fields changed: rebuild every consumer.

The ordinary FlashVM embedding leaves the guard disabled. A synchronous current
owner is not a detached/asynchronous lifetime capability. Caller field kind and
offset still come from trusted C/compiler metadata. The proposed next step is
an exact compiler scalar-field witness tied to retained Type/module/callable
generation; it is recorded for peer agreement, not silently introduced.

Standalone CTest now includes the independent sequence oracle on native Linux64
and live vmachine/entry/unwind controls on native Linux AMD64/ARM64. Both guards
are explicit in the fixture builds; production file calls remain closed. Cross
builds do not execute these host ABI checks as target evidence.

## Validation scope

The independent oracle enumerates 131,072 traces per optimizer run across two
WORD32 profiles and published/live modes. O1 and O3/NDEBUG strict UBSan and four
compiled semantic-removal controls pass. It deliberately stubs scheduler
availability and descriptor retirement; actual VM and GC checks remain separate.

A clean complete owning x64 build with source-built mk/limbo/iyacc/decgen passed
the native64-port driver: four console pilot JIT0/1 boots, closed import refusals,
partial-guard link refusals, dependency rebuilds, both Math port gates, GC leases,
live register return/error gates and their controls. Eight additional caller
mutation controls passed in both WORD32 profiles. The selected imported live VM
and actual mapped Math/heap/GC gateway also pass independently.
The clean build used c958911; final 6d77333 adds only the independent oracle,
its README and journal response, with identical production blobs.

These are x64 runs. The incoming ARM64 report is distinguished from independent
local execution. No physical ARM64/RV64, full shell startup or closure of older
optimized UTF/unwind ASan findings is claimed. The 43-operation np0 file profile,
`execution_supported=false`, closed file CALL/MCALL and shared IDs/wire layouts
remain unchanged. FIR/compiler/linker semantics are unchanged in this series.
