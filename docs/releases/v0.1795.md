# v0.1795 — compact guards for three small arithmetic spans

Runtime0.97 replaces the generic 256-entry range metadata used by fifteen guarded
integer operations with a new six-key DVM_TripleAccess. Each operand/result is at
most pointer-width, so first/last canonical cells cover its complete byte span.
The new small_range module sorts/deduplicates up to six keys and claims the SAME
guards/domain as existing cell and wide APIs. No computation, ownership, root,
geometry, owner admission or BUSY rollback policy is removed. Existing access
layouts/default profiles and Dis64 wire/IDs/admission remain unchanged.

[Contract and reproduction](../../disVM/runtime/SMALL-RANGES.md).
[Commented C example](../../disVM/examples/native-small-range/README.md).
[Parallel heap status](../../disVM/runtime/HEAP-PARALLELISM-STATUS.ru.md).

All 38 affected checks pass: 37 initial passes, then the isolated managed-owner role
fixture passes after linking the new host module. Eight joined native writers mix
compact/wide/cell operations:16000 paired and 10664 third-counter updates, exact
geometry/order/deduplication, BUSY rollback, cleanup, allocator-free access and strict
compact/wide omission controls. The existing actual C oracle still covers 877500
arithmetic value/alias cases and all 15 real x64 cache/error/return-PC tail entries.
TSan positives pass all three paths. Generated machine code is uninstrumented;
no new hosted UBSan/physical ARM64/RV64 or parallel managed-program proof claimed.
Installed native tests, source/header closure and the C example pass; vendors
verify 1096 DisVM / 312 bootstrap files at ba26acc. Public header is a new native API,
not a shared file layout. A domain count still cannot protect racing first lookup.

[SMALL-097 measurement](../../disVM/runtime/PERFORMANCE-COSTS.md): native64 access
metadata 72 instead of 2072 bytes. Both sides of the matched workload are protected:
C generic 3.406701185→compact 2.703036849 seconds (elapsed down 20.66%);
JIT 3.421904895→3.031322135 (down 11.41%). Same image, production objects/flags,
quantum2000 and checksum; private relink changes only guard metadata/entry names.
One warmup then three alternating samples, all raw samples retained. Variability
is visible; no universal or isolated per-lock gain is inferred.

Separate current default→guarded profile cost is C 2.776729707→2.885887481 (+3.93%)
and JIT 1.905204034→3.281296924 (+72.23%). Historical ARITH-096 remains open and
preserved; cross-run percentages are not subtracted or added. Preflight, guards
and C-tail overhead still need separate analysis and compiler locality work.

NativeWorld still serializes general managed compute. Remaining reads/writers,
list construction, channel/scheduler ownership, graph/root/GC epochs and frame/
module/code lifetime remain before global admission can be removed. No new
Dis64 contract is introduced. Inferno correspondence continues in FLASHVM-0113;
the prior partial-schema checkpoint does not admit code/exports or typed calls.
