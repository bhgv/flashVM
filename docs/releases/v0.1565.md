# v0.1565: fresh Inferno Rune/Type integration and final clipboard-series acceptance

Inferno experiment advanced during the clipboard work. Both selected manifests
now pin public `5ca377017fe42eac2d95ed0638a5b42ab45ac212`, preserving the prior
ASCII/wide-decimal checkpoint and native-dispatch fixture follow-up. Matching
Rune ADDC now retains signed representation and exact Rune bits; capacity,
overlap and owner checks precede writes. Heap/array/loader Type preflight rejects
dead or saturated descriptors before allocation and reserves two retains for
Tarray aliasing. Public layouts and the 64-unit native staging limit are unchanged.

The selected core runs the new Type-retain UBSan driver plus existing native,
loader, decimal and instruction-emulation matrices. The first full 76-entry run
exposed one local test-adapter issue: upstream reformatted its C fixture main,
so an exact one-line rename stopped matching. The adapter now accepts whitespace
variants and requires exactly one entry before compilation. All other 75 entries
passed; the repaired memory-parser, loader and Type-retain checks then pass.
All 76 registered core entries have therefore passed at this source snapshot.
This is our fixture adaptation, not a mutation of the exact upstream snapshot.
