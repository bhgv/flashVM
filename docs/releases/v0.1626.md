# v0.1626 — x64/ARM64 channels and TCMP bounds

The priority platforms are x86-64 and ARM64. Inferno experiment now includes our
returned fix `875d12263efa72bab84d27f0d4215713e7da9465`, on top of cc51c63 scalar-channel constructors.
Selected snapshots preserve 453 core/reference and 174 bootstrap files exactly.

Five new guarded native operations, NEWCB/NEWCW/NEWCL/NEWCF/NEWCP, capture full
Dis WORD capacities, preserve the unbuffered operand alias, allocate through the
shared runtime and publish only into an empty destination after success. Native
availability is 160/173 active commands on AMD64/ARM64; nonempty replacements and
invalid preflight retain checked C. Shared allocation is not a native allocator.

Our TCMP repair checks both backward Type-field spans before reading either
metadata pointer. A source H stays a no-op. C uses bytewise Type-field reads;
AMD64/ARM64 emit unsigned lower-bound checks. No owner retain/release or GC color
change occurs. The parent interpreter reproduces an address-underflow UBSan
failure. The fixed C/actual AMD64 RX fixture passes 76 cases per WORD model;
focused emulation passes 8,682 checks per priority ISA, including the existing
Type matrix, aliases, unaligned slots and new low addresses. The regression does
not claim validation of arbitrary mapped memory or forged-object liveness.
