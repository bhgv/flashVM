# v0.1762 — protected source slots and native publication

Runtime0.64 adds opaque native strong-owner slots. Copying a shared reference
retains directly into an owner-local scope before releasing source protection.
Exchange moves both incoming and previous owners without retain/drop callbacks;
old owners retire after unlocking. Empty assignment and quiescent destruction
are explicit. These operations protect lifetime/publication, not mutable payload.

The actual managed-owner probe now publishes a rooted ticket through a slot.
Eight bare OS receivers copy distinct native owners, then the controller removes
the source slot owner. The existing 32 actual cycle passes, role refusals,
native error cleanup, Fast retirement and complete joins remain verified.
There is no new managed pointer API, parallel Heap admission or shared Dis64 ID.

Sources, header, tests, docs and helpers ship in both runtime/editor source SDKs.

Validation on Linux x64:

- Eight OS readers,16000 snapshots,1001 real malloc/free lifetimes per backend;
  native-selected and forced-mutex count/guard implementations.
- Nil/occupied/overflow/guarded/unbound/malformed refusals and exact final counts;
  six actual-source semantic controls for publication, move and distinct retain.
- Full native fixture UBSan; joined positive fixture TSan on both backends.
  Fatal negative controls are excluded from TSan, not treated as clean joins.
- Six runtime checks including console/editor rooted-owner C/JIT runs, both
  poll selections, scope/error cleanup and refusal roles. Actual root removal
  and forced producer-overlap/pin controls retain their semantic predicates.
- Instrumented interpreter C source rooted-owner runs and joined producer overlap
  pass TSan. Generated JIT instructions are not TSan-instrumented; no full-VM
  race-freedom or target ARM64/RV64 execution is inferred.
- Extension helper compilation passes C89 and C++98 with strict warnings.

The managed heap still admits one executor at a time. Full owning C/JIT reference
and mark conversion, allocator concurrency, graph publication/invalidation,
managed process retirement and collector integration remain substantial work.
Vendor snapshots remain unchanged; Inferno journal synchronization reports this
host boundary separately from the shared Dis64 format and target native64 work.
