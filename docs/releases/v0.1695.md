## Implemented / Реализовано

The lazy owner now requests cooperative cancellation when a newer valid edit
supersedes its active analysis. It still acknowledges Update without waiting for
scanner completion, keeps only the newest pending snapshot and discards stale
results. Shutdown also requests cancellation before draining the active result.

`Idesyntax.startcancellable` exposes job/result channels plus a single-producer,
capacity-one cancellation channel of positive active tickets. Only the exact
active ticket cancels; job tickets must be unique over that worker lifetime.
A match observed at a checkpoint returns `Cancelled` with the original correlation
and no partial token array/counters; an already completed result can remain `Ok`.
Late/nonpositive requests do not poison the
following job. Metadata/size validation retains priority. Ordinary `start` and
job/result request shapes remain unchanged; the module export signature changes,
so rebuild and deploy the matching modules together.

The worker retains its private last-success catalog after cancellation. The next
unchanged snapshot can therefore reuse the entire baseline instead of rescanning.
Checkpoints are before analysis, every 256 scalars during validation, prefix/
suffix comparison and byte-boundary preparation, and between generated records.
A long generated string/comment scan, encoding/allocation or array/suffix copy
is not preempted midway. This is scheduled Dis work, independent of Flash frames,
not an OS-thread-parallel VM/GC implementation or measured typing-latency guarantee.

Ленивый владелец теперь отменяет устаревший активный разбор при принятой новой
правке и при остановке. Отмена адресуется ticket конкретного задания и не
уничтожает успешную инкрементальную базу. Незавершённые токены не публикуются,
запоздалый запрос не отменяет следующий снимок. Ввод, Undo, выделение и
ревизии документа не изменяются анализатором. Проверки кооперативные;
длинный токен внутри Coco/R пока не прерывается посередине.
