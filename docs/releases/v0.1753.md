# v0.1753 — native open/create without holding the Dis heap

Runtime0.57.0 releases the active heap lease for supported Sys.open and Sys.create
native work, including the read-only directory probe/open. A separate open_wait
adapter copies the validated UTF-8 path before release and constructs an unpublished
native handle. Only native locals are touched while outside the heap. Mode strings
are immutable C literals. Publication and error construction occur after reentry;
no shared string2c scratch pointer is read after another owner could reuse it.

The descriptor table reserves an empty slot by allocating its native gate BEFORE
release. Both file and directory slots exclude any existing reservation, preventing
a competing open from taking an unpublished slot. The mapped result FD is allocated
before a potentially destructive create, explicitly retained/marked across the
wait, and initialized with fd=-1 until publication. Failure frees the reservation
and returns nil. Native path staging is freed on success and error. NATIVEOPEN
reports attempts, actual lease releases and simultaneous/peak snapshot bytes.

Loader opens retain their protected synchronous boundary. FD destruction/close
also remains synchronous: its GC/finalizer lifetime requires a separate audit.
There is no new forced native cancellation, filesystem transaction/durability
promise, larger descriptor quota or parallel managed heap mutation. The automatic
executor mode remains opt-in; ordinary runtime default remains one.

The existing real native barrier test now covers seven phases: path metadata,
file metadata, directory metadata, directory batches, file open, directory open
and exclusive create. Linux/glibc interposition pauses actual stat64/fstat64/
readdir64/fopen64/opendir/open64 calls. Another actor must create a competing
UTF-8 file, compute and print BEFORE the driver releases the held operation.
This verifies reservation uniqueness and snapshot isolation as well as managed
progress. Missing-file and existing exclusive-create failures are checked;
all descriptor gates and staging must retire. C/JIT and four/eight OS executors
run in console and graphical hosts. These are local Linux x64 checks, not a new
ARM/RV hosted-runtime or whole-VM race-freedom claim.

Validation:29/29 selected runtime tests passed, including fixed/elastic pools,
file FIFO, native waits and the extended barrier cases. The installed graphical
package passed all seven phases in C/JIT with4/8 executors. An instrumented Debug
interpreter passed the same actual metadata/open/create barriers with4/8
executors under ThreadSanitizer; that focused run overrides the driver to select
interpreter only and does not establish JIT/UI/whole-VM race freedom. Private
header C++98 syntax, Python/shell checks, diff checks and both unchanged vendor
manifests passed. Inferno experiment still points to FLASHVM-0070 at this review
boundary; no new peer message, shared file ID or format activation was imported.
