# v0.1710 — Native live ink and native-sized maximized SDI/MDI

IDE 0.7.3 keeps maximized content at native scale independently of the desktop
camera and saved ordinary window zoom. Maximized SDI/MDI roots use the physical
overlay layer; returning to normal preserves the camera and stored rectangles.
MDI child transforms follow the actual root parent. Container reparenting retires
all borrowed child handles before any allocation can collect the old subtree.
Show All restores ordinary rectangles before measuring their complete bounds.

Live Brush/Pen trajectories remain in native C. After an admitted Begin, queued
same-device motion is collected in bounded batches, with conservative close,
collinear mouse-jitter compaction. Motion does not cause a document/channel round
trip or serialize the growing path through Limbo. A 4 ms native paint-coalescing
budget is independent of Flash timelines and does not promise a display FPS.

Release freezes the C buffer and sends a scalar token. A separate scheduled
Limbo process copies the frozen points, builds raw geometry and refines it.
FIFO jobs carry prior geometry and whole-stroke history; ordinary non-native
geometry/history operations join earlier work before changing it. A coalescing
notifier keeps readiness while the UI controller is busy. Invalid native buffer
acquisition cannot publish an incomplete Save. Expose keeps capture alive; Escape
cancels it; admitted input/lifecycle barriers seal it in FIFO order.

Raw native preview uses a circular coverage stamp rather than constructing a
filled circle path for every sample. Only explicitly marked live-ink commands
use approximate stamping. Final vector paths and ordinary captured Flash drawing
retain exact backend rasterization. The first broad pass caught two pixel-parity
regressions when stamping was applied too broadly; explicit command marking fixed
both, including cache/damage identity. Stamp centres are quantized to pixels;
Limbo owns the final Brush region union and Pen centreline fitting.

The native preview remains until its exact cumulative replacement is accepted in
a complete scene. Its publication fence follows the actual outgoing document
wire after Undo, style changes or a subsequent gesture, rather than an intermediate
worker result that might never be displayed. Closing a source retires its preview
before the numeric pane slot can be reused. Native buffers have 32 slots and 4096
points/stroke; capacity keeps the retained raw prefix and reports Limit. Existing
portable document path/node bounds remain.

Committed vector commands now bypass per-vertex AVM1 method calls during normal
raster preparation. Vector-toolbar graphics, ordinary pane bitmaps and unchanged
immutable toolbar controls are reused. Existing object-local damage, root tiles,
parallel C raster work and partial SDL texture uploads remain active. Limbo/AS
retains document, command and theme ownership; native workers receive no VM/font
or channel pointers.

The graphical `$Idehost` builtin adds `inkadmit`, `ink` and `inkdone`, with generated
native-frame metadata. GUI modules must be rebuilt with their matching runtime.
No SWF/Dis64 file format or shared format identifier changes. Algorithms live in
separate native buffer, motion-batch and stamp files and the separate portable
`ideinkworker` module. The installer includes the new module, matching declarations,
C sources, linked English/Russian contracts and readable C/Dis examples.

## Validation

- Final native x86-64 runtime: 361/361. Both interpreter and JIT execute real pane,
  worker, SVG, Undo/Redo and invalid-token publication controls.
- Actual SDL capture test: 600 queued motions produce only Begin and token End
  proposals; actual raster pixels at three turns are checked. Its copied layout
  setup is an explicit boundary, separate from the real Dis-worker integration.
- Exact SDI/MDI interior RGB across saved table/window zooms, changes after maximize
  and normal restore. Legacy MovieClip capture parity, frame-free drawing, retained
  scene, pool backgrounds, clipping, workspace gestures and vector controls pass.
- Build-menu 37/37. Fresh SDK relocated into a path containing spaces passes native
  scale checks in JIT and frozen-buffer worker/SVG/history checks in interpreter.
  The worker fixture runner is a development-only executable; the installed IDE
  does not use Python or a test runner for its native drawing path.
- Headless C99 object compilation covers the editor adapter and fixture entry;
  this is not a separate complete headless-runtime acceptance run.
- Changed native buffer/stamp primitives and their independent pixel/capacity test
  pass strict UBSan. Their FlashVM/graphics dependencies are prebuilt and not
  instrumented. A combined Address/LeakSanitizer attempt cannot complete because
  this environment does not expose the required `/proc` thread information; no
  ASan/LSan acceptance is claimed.
- The primitive timing report has no speed threshold: for an isolated complete
  polyline the optimized vector backend can be faster than the stamp. The main
  latency improvement removes per-motion Dis/AVM1 work and unchanged chrome work;
  these tests do not measure physical device FPS or end-to-end input latency.

ARM64/RV64 physical execution and display/touch acceptance are not inferred from
native x86-64 replay and SDL dummy-driver checks. The earlier Python host-driver
staging-cleanup timeout finding remains outside this renderer change.
