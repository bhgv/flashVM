# v0.1653 — AS2 through FIR, linked IDE view and graphical browsing

## English

The IDE view now executes authored AS through the required shared pipeline:
**AS2/Coco/R → FIR → verification/peepholes → SWO → SWL → SWF → FlashVM**.
There is no direct AVM1 emitter in the new AS frontend. The AS2 language project
builds both the syntax frontend and the limited display-profile CLI/library.
The library emits FIR atomically, shares the full AS2 syntax validator, resets
between calls and recovers scanner failures. Its source coverage remains explicit
and limited; this is not complete AS2 semantic lowering or full IDE self-hosting.

FIR adds effectful `as.global_get`, `as.global_set`, `as.member_set` operations.
The verifier/printer, optimizer effect model and AVM1 target backend handle them.
SWL admits emitted SetMember records and creates the SWF container. Dis rejects
these AS object operations until a foreign-object target adapter exists.
[Compiler/API/tutorial](../../compiler/as2/view/README.md) ·
[FIR contracts](../../fir/v1/doc/AS_PROPERTIES.md).

The graphical browser shows up to eight entries at once, with selected-row
highlighting, file/directory markers and a clickable toolbar. Mouse row selection,
Open, parent navigation, next batch, refresh/path/close use Limbo policy and checked
revision/view tickets. File ownership and OS access stay in existing services and
ports. Unsaved source is protected. AS sets the actual TextField content/geometry;
the native adapter still supplies font/raster/window primitives and legacy range
painting. This is a basic listing: tree expansion, sorting, previous-batch history,
timed double-click and a complete migration of remaining widgets are open.
[Browser](../../ide/dis/GRAPHICAL-BROWSER.md).

Loading a real SWF exposed a zoom integration bug: current source runs retained
the old format while caret geometry used the new size. Zoom now updates both
existing text runs and future insertion format in both TextFields. Existing
independent pixel/caret tests verify their agreement after scaling.

Inferno is pinned to **9a87d74eb4f47cf7b8ea35c804f86c7c20e40d36**:
- mapped-copy operands survive destructor callbacks, including complete AMD64 JIT;
- Sys UTF/tokenizers validate full frame/string/array/result spans and owners;
- packed delimiter Rune reads are safe;
- public formatted-result calls capture frame and previous owners before allocation.

Exact selection: **662 core/reference/library files + 207 bootstrap files**.
Original production sources/tests are preserved byte-for-byte. The runtime source
adapter recognizes the new staged byte-array validation without weakening it.
Bidirectional review confirms our existing reverse fixes remain in experiment;
no additional shared defect was found to send back. IDE/AS/FIR extensions stay
in flashVM. No empty or unrelated Inferno commit was made.

The installer ships commented AS source, FIR/optimized FIR/SWO/SWF products,
RU/EN guides and the embedded executable. The root builder reuses/builds AS2,
FIR and SWL; they are build tools, not runtime dependencies. Independent Linux
AMD64 execution, emulated ARM64 leaves and physical OS acceptance remain distinct.

## Русский

Представление IDE теперь исполняет исходный AS через согласованный тракт:
**AS2/Coco/R → FIR → проверка/пипхолы → SWO → SWL → SWF → FlashVM**.
Прямого emitter AVM1 во фронтенде нет. Проект AS2 собирает общий синтаксический
фронтенд, библиотеку и CLI ограниченного профиля отображения. Библиотека атомарно
выдаёт FIR, переиспользует общий валидатор AS2, восстанавливается после ошибок и
перехватывает сбои сканера. Полный AS2 и самокомпиляция всей IDE ещё не реализованы.
[Компилятор/API/пример](../../compiler/as2/view/README.ru.md) ·
[Операции FIR](../../fir/v1/doc/AS_PROPERTIES.ru.md).

В FIR добавлены чтение/запись глобального AS-значения и запись именованного
свойства. Верификатор проверяет типы/арность, печать сохраняет ключи, эффекты не
позволяют оптимизатору переставлять обращения. Инструкции генерирует backend,
контейнер — линкер. Dis явно отказывает этим AS-операциям до реализации адаптера.

Браузер показывает до восьми строк, выделяет выбранную, различает каталоги/файлы
и принимает мышь на строках и панели действий. Открытие, родительский каталог,
следующая порция, обновление, путь и закрытие управляются Limbo с проверкой
билета/ревизии. Несохранённый текст защищён. AS задаёт настоящий текст и геометрию
TextField; нативными остаются графические/оконные примитивы и прежняя отрисовка
диапазонов. Это базовый список: дерево, сортировка, история предыдущих порций,
двойной щелчок по таймеру и перенос всех оставшихся виджетов ещё впереди.
[Контракт](../../ide/dis/GRAPHICAL-BROWSER.ru.md).

Исправлена найденная при загрузке SWF рассинхронизация масштаба: уже имеющийся
текст оставался старого размера, а каретка рассчитывалась по новому. Теперь
обновляются текущие диапазоны и формат будущего ввода обоих TextField. Проверки
по настоящим пикселям подтверждают совпадение каретки, глифов и координат мыши.

Снимок Inferno — **9a87d74**, **662 + 207 файлов**. Приняты сохранение операндов
копирования при деструкторах, проверки полных диапазонов Sys UTF/tokenize,
безопасные packed Rune-разделители и сохранение кадров/старых владельцев
форматированного вывода до выделения памяти. Исходники и регрессии сохранены
побайтно. Прежние обратные исправления присутствуют; нового общего дефекта для
обратного коммита здесь не найдено. Расширения IDE/AS/FIR в Inferno не переносились.

Поставка содержит AS-исходник, продукты всех этапов FIR/SWO/SWF, русские и английские
руководства. Компиляторы/линкер нужны при сборке, не при исполнении. Нативная
проверка Linux AMD64, эмуляция листьев ARM64 и физические испытания других ОС
не смешиваются в одну заявленную готовность.
