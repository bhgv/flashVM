# v0.1702 — Complementary root-buffer transfers

2026-10-31. Workspace0.1702; FlashVM/FIR formats and Dis/SWF ABI unchanged.

Preparing a native successor now copies only **clean** root tiles from its
immutable displayed baseline. Workers completely rebuild the dirty tiles.
After rendering, presentation copies only **dirty** tiles to the owner's pixel
buffer. Adjacent selected tiles merge into horizontal runs; tight full-width
bands use contiguous copies. Row padding is never included.

For a valid compatible display baseline, the two disjoint transfers total one
canvas of pixel bytes, replacing two complete canvas copies. All-dirty frames
copy no baseline pixels; unchanged frames copy no presentation pixels. This is
not zero-copy: independent full frame buffers remain, as do object-image updates,
root composition and SDL texture uploads. Work counters do not predict FPS.

A native nonreused identity records each candidate's exact preparation baseline
without retaining a prior-frame pointer. If a different frame has meanwhile been
shown, partial presentation is invalid. The owner then performs a complete copy
and texture upload, including when the candidate itself has zero dirty tiles.
New/resized/recreated owner buffers also require complete initialization. This
prevents stale pixels after queue supersession or a baseline change.

`FRAMECOPY ticket baseline_bytes presented_bytes` exposes actual transferred pixel
bytes. Normal compatible transfers sum to `width*height*4`; fresh or mismatched
presentation can require more. `ROOTDAMAGE` remains the composition tile mask;
a newly initialized texture can need a full upload independently of that mask.
