# v0.1670 — Native compiler jobs on Dis and bidirectional Inferno synchronization

[Compiler service EN](../../ide/COMPILER-SERVICE.md) / [RU](../../ide/COMPILER-SERVICE.ru.md) · [Commented tutorial](../../ide/dis/examples/compiler-service/README.md) · [Synchronization](../../disVM/SYNC.md) · [Published Inferno fix](https://github.com/bhgv/Inferno-OS-bhgv/commit/34d019f22b80d01385db737e13b20c0ff443aa8b)

Runtime **0.33.0**, independent compiler service **0.1.0**. Existing matching
FIR **0.58.0**, source compiler **0.25.0** and SWL libraries now serve actual
Limbo/Dis workspace builds without spawning CLI tools. A VM-independent C99 API
owns source/FIR/linker staging and returns complete FIR, NC64 Dis or SWF8 plus
original FIRDBG1. The optional $Fircompiler builtin captures generated frames,
validates wide options and primitive byte-array layouts, and copies native output
into independently rooted Dis values under protected allocation cleanup.

The portable idecompiler worker owns a sequential request channel. BeginBuild
captures a real document revision/ticket; FinishBuild admits only that current
snapshot. Native failure, stale jobs, target changes, artifact copies and balanced
shutdown use actual workspace rendezvous channels. Original UTF-8 source locations
are returned separately from plain diagnostics. Both source and output budgets
are explicit; failed stages expose no partial bytes. Compilation blocks the VM
owner and supplies no cancellation or UI authority. Automatic execution and the
graphical Build/Run/Debug panels remain future work.

The small tutorial comments every nonblank line, handles cleanup on failure and
requires acknowledgements from both owners. A separate acceptance module generates
24 artifacts for AS1/2/3/Limbo × raw/optimized × Dis/FIR/SWF. Host tools compare
all bytes/debug with independent CLIs and execute the Dis and linked SWF results.
Both GC quanta must produce identical artifact/debug bytes. New linked EN/RU
contracts explain the native boundary, C99 ownership, job status domains, budgets,
blocking behavior and current language/ABI limits.

Root graphical builds link matching FIR/SWL libraries after building them;
runtime-only builds opt in by selecting both projects. Standalone builds require
explicit headers/archives. Packages record Fircompiler=ON/OFF, ship interfaces,
bytecode/source/debug data and the service archive, and retire their stale service
products when switched OFF. Relocated SDK checks relink a C99 client and exercise
the real service; installed documentation links are rewritten and verified.

## Two-way Inferno work

Both snapshots now pin **34d019f22b80d01385db737e13b20c0ff443aa8b**:
**781 Dis / 277 bootstrap files**. Incoming experiment changes add checked
optimizer storage/positions, iterative SBL Type output with metadata preflight,
native-safe Dis-to-C scalar/address handling and a checked normal VM fetch loop.
The AOT translator is a selected reference with its original tests, not a newly
integrated NC64 IDE execution mode.

The inverse audit identified an actual common Math defect previously handled
by FlashVM's local adapter: canonical descriptor identity rejected legitimate
module-local primitive arrays. The old source reproduces in WORD32 and WORD64.
The fix was committed and published to **Inferno-OS-bhgv/experiment**, then imported
back exactly. It accepts matching pointer-free layouts under checked module
signatures while rejecting wrong known canonical primitives, including big at
equal native widths. Nil/type/length error order and all arithmetic remain intact.
The obsolete host Math source rewrite and helper file are removed.

The host adaptation of the new executor preserves its checked PC/opcode identity,
places the GC safepoint after fetch preflight and before quota/AOT/decode, and
calls the captured fast pointer instead of rereading a Jit after enter. Explicit
source-generation guards reject drift; byte-identical regeneration also checks
Math. Both publication routes use expected-head checks and non-force updates.
All **938 unique selected upstream source files** were compared byte-for-byte
with the published Inferno commit; no unpublished shared source delta remains.

## По-русски

Добавлен настоящий сервис сборки IDE: C99-библиотеки Coco/R/FIR/SWL вызываются
из Dis через проверенный нативный модуль, а Limbo worker управляет снимком,
билетом, ревизией и допуском результата. Возвращаются полные FIR/Dis/SWF,
исходный debug и UTF-8 диагностика. CLI-процессы при нативном вызове не запускаются.
Пример, документация и оба переносимых SDK проверены на реальном исполнении.

Синхронизация выполнена в обе стороны. Из Inferno взяты защиты оптимизатора,
итеративный SBL, безопасные операции AOT и проверяемая выборка инструкций VM.
В Inferno опубликовано общее исправление Math для локальных дескрипторов массивов;
оно возвращено в FlashVM точным снимком, местный обход удалён. Новая интеграция
сохраняет GC/quota-границы и захваченные callback-адреса. Полные финальные наборы
ядра и runtime проходят. Графические панели сборки/запуска/отладки этим сервисным
этапом ещё не объявляются завершёнными.
