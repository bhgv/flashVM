# v0.1636 — decoded-slot preflight for eight integer shifts

C, AMD64 and ARM64 used to load a shift count before validating its decoded
slot, and access a value/result slot after checking only the count value. A null,
H or wrapping slot could therefore reach a host/emulator memory fault. The new
checks reject the complete count span before the first read; invalid count values
still win before consulting value/result slots. With a valid count both other
spans are checked before reading value. Source/result overlap remains valid.

The owning Inferno commit is `d899383090f6013e8be41da7e3e2c09888856b0b`. It covers
SHLB/SHRB/SHLW/SHRW/LSRW/SHLL/SHRL/LSRL and registers independent C and emitted
instruction checkpoints. FlashVM imports the same sources at that commit: 507
exact core/reference files and 174 bootstrap files. Both new checkpoints are
registered in its CMake suite, raising the selected test count from 182 to 184.
There were no newly incoming changes after 9de5fe9 at the initial synchronization.

Native pointer bounds are independent of WORD32/WORD64 counts and BYTE/WORD/LONG
values. Interpreter errors are bounds for malformed slots and the existing
invalid-argument error for invalid count values. Declined JIT execution preserves
all VM-visible storage and FP state. Existing arithmetic and alias fixtures now
include the bounds-error identities required by extracted production handlers.

The C checkpoint has 2,944 cases, active with NDEBUG/UBSan. The instruction
checkpoint has 51,200 cases under Python -O, including all legal counts, signed
edge values, byte alignments, invalid spans, forbidden early value reads, PC/REG
images, write-free decline, FP state, every short code capacity, exact-size output
and a trailing canary. All 24 old-version C/AMD64/ARM64 command probes reproduce
the original invalid count-slot read. Existing shift/division and integer tests
continue checking successful arithmetic and overlapping operands.

## По-русски

Исправлены восемь сдвигов C/AMD64/ARM64: проверка счётчика раньше выполнялась
после чтения из непроверенного слота. Теперь проверяется полный диапазон слота
счётчика, затем его значение; при допустимом счётчике — оба оставшихся слота до
чтения значения. Сохраняются порядок ошибок, работа с перекрытиями и отсутствие
записей при отказе JIT.

Исправление опубликовано в исходном репозитории Inferno и импортировано обратно.
Независимые тесты: 2 944 случая C и 51 200 случаев эмуляции JIT; все 24 проверки
на прежних версиях воспроизводят исходный дефект. В CMake теперь 184 теста.
Расширения языка и ABI не переносились и не менялись.

The stack-only C fixture also passes AddressSanitizer with NDEBUG/UBSan. This
host cannot enumerate processes for LeakSanitizer; the standard fixture hook
disables that unsupported leak check while preserving address instrumentation.
The sanitizer emits its existing setjmp/no-return warning without an address
finding. Leak detection is not included in this evidence.
