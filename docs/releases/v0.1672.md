# v0.1672 — Явный экспорт IDE и двусторонняя синхронизация Inferno

После F7 теперь доступны Ctrl+F7 для бинарника и Ctrl+Shift+F7 для оригинального
FIRDBG1. Dis-контроллер открывает явное поле пути; Enter создаёт новый файл,
Escape отменяет действие. История, исходник, выделение и отметка сохранения не
изменяются. Существующий файл или симлинк никогда не перезаписывается.

## Реализовано

- Ideartifact — отдельный FIFO-сервис Dis. Проверяет ID, ревизию, наличие успешной
  сборки, ожидаемый target, часть Binary/Debug и суффикс до записи. Выдаёт статус,
  фактический формат и число полностью принятых байтов. Shutdown не завершает
  заимствованные сервисы; все выходы редактора закрывают exporter перед panel.
- Библиотечный путь поддерживает Dis/FIR/SWF и debug. Графический F7 сохраняет
  прежний выбор: Dis для .b, SWF 8 для .as/.as1/.as2/.as3. Имя экспорта берётся из
  фактического формата артефакта. Ошибка оставляет поле пути редактируемым.
- Idefileops.readbytes/writebytes сохраняют произвольные байты, включая нули и
  невалидный UTF-8. Прежнее строгое чтение исходников остаётся строгим, обычная
  текстовая запись сохраняет overwrite-политику. Только экспорт всегда exclusive.
- Sys.create принимает OWRITE|OEXCL, permission 0666. Общий порт добавляет wx:
  POSIX O_CREAT|O_EXCL и Windows _O_CREAT|_O_EXCL, без stat/open race. Владельцы
  выделяются до создания. Публичный FlashVM C ABI не меняется.
- Приёмка экспорта обнаружила отличие библиотеки от CLI после свёртки констант:
  одинаковый FIR имел разные временные слоты в памяти. Dis/SWO backend теперь
  читает канонически сериализованный/повторно разобранный FIR. Самостоятельный
  regression сравнивает точные Dis-байты четырёх языков с двумя вариантами opt;
  прежний engine воспроизводит ошибку для Limbo optimize=1.
- Построчно прокомментированный artifact-export пример создаёт два явно названных
  новых файла и завершает владельцев в порядке зависимостей. SDK поставляет
  модули, заголовки, исходники, пример, EN/RU руководство и независимую приёмку.
  ON→OFF удаляет только принадлежащие установщику нативные примеры/тесты/архив.

## Inferno: входящие и исходящие изменения

Входящий 75bc786 заменяет переполняющиеся raw moments benchmark на центрированные
Welford updates/merges, ограничивает преобразования/counts, корректирует разности
таймеров, масштабирование микросекунд и чтение отчётов. Числовая матрица и пять
инструментированных executor fixtures импортированы без изменения исходников.

Полный core выявил общий regression test dependency: gc-idle.py извлекал новый
idlegc, но не его tickspan, и benchmark fixture не линковался. Исправление сначала
сделано и проверено в Inferno, опубликовано как
[573eb1337fd621b6e51b89d16dd86427c9376452](https://github.com/bhgv/Inferno-OS-bhgv/commit/573eb1337fd621b6e51b89d16dd86427c9376452),
затем импортировано обратно. Извлекается настоящая helper-функция из того же
выбранного исходника; старый parent replay без helper продолжает работать.
Производственная логика VM/GC этим исходящим коммитом не меняется.

Итоговый pin обоих manifests — **573eb1337fd621b6e51b89d16dd86427c9376452**:
**791 файл Dis**, **277 bootstrap**, **948 уникальных выбранных исходников**.
Они совпадают с опубликованными Git-объектами Inferno и SHA-256 manifests.
Исправление канонического FIR и политика экспорта относятся к FlashVM и не
переносятся в общий интерпретатор Inferno.

## Границы результата

Экспорт относится к неизменяемому артефакту, допущенному при fetch; более поздняя
правка не отменяет уже начатую запись. Бинарник и debug — два отдельных действия,
не атомарная пара. Ошибка после создания может оставить частичный **новый** файл.
Откат, fsync/долговечность и filesystem sandbox не реализованы. Нативные компиляция
и I/O блокируют владельца VM. Отмены/фоновой отзывчивой сборки пока нет.

Run/Debug controls, полное подключение Dis debugger, карты итоговых/native PC и
полные языки остаются следующими этапами. AS3 не создаёт AVM2. Linux C89 syntax
checks общих POSIX units не означают native macOS/Android acceptance; Windows-порт
адаптирован по исходникам. Санитайзеры выполнены на native AMD64; LSan task
inspection недоступен. Replay не заменяет физические desktop/touch испытания.
