# v0.1819 — imported record allocation / runtime0.120

Guarded MNEWZ holds the source Modlink through Type resolution, record
construction and cleanup. It captures the Type index under the span guard
inside the error checkpoint. The result uses the same rooted publication
protocol as local NEW and NEWZ. Source replacement in the monitor may remove
the application's last reference to the Modlink. The temporary hold covers
that interval and the record retains its own descriptor after publication.

The hosted leaf classifier sends all three record constructors through their C
handlers under guarded copies. This closes the direct RC1 reuse route that was
still available to JIT-enabled guests in v0.1818. The startup selection also
applies to native cache validation. This series tests generated x64 cache
entries and actual hosted C dispatch.

The native fixture invokes MNEWZ with a real Modlink. Its monitor removes the
source owner, then either returns or raises. The fixture checks the hold during
the callback, preservation of the destination and primary error on failure,
and real module unload after Fast. The regular Limbo guest exercises local
record construction in both interpreter and JIT sessions.

NativeWorld still supplies frame, descriptor and collector exclusion. Arrays,
channels, address leases and scheduler lifetime require further work.
