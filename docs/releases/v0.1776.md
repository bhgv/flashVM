# v0.1776 — synchronized external-root metadata

Runtime0.78 moves hosted ptradd/ptrdel/ptrmark metadata into a separate native
module with its own port mutex. Table/free-list operations are synchronized;
allocation and VM errors occur outside the lock. Cached additions use one
critical section. Duplicate registration semantics and process lifetime remain.

Actual native checks race initialization and updates with8 OS threads/16000
pairs/1000 traversals, both publication backends, allocation refusal and six
strict source controls. Keys are native objects in a separate non-VM process.
The actual VM probe verifies real String roots through32 Cycles and final Fast,
separately from those metadata checks. A new CTest guards the native module.

[Contract](../../disVM/runtime/ROOT-REGISTRY.md). This does not authorize root
publication during collection or arbitrary native managed access. Root lifetime,
collector/graph barriers, allocator and shared payloads still need coordinated
work before relaxing NativeWorld serialized admission. No shared Dis64 IDs,
Heap/Type layout changes or pointer serialization are introduced.

Validation:27 selected CTests pass; five affected cases pass again after cached
metadata optimization. Six native read/write/format cases pass. Native registry
joined positives pass TSan with both publication backends; actual C owner and
x64 tail positives pass TSan too (generated bytes uninstrumented). Six strict
source controls and forced-lock root/producer controls pass. Installed SDK's
standalone root checks and both pinned vendor manifests verify.
