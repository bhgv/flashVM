# v0.1757 — native object guards and guard-aware context boundaries

Runtime 0.61.0 adds bounded owner-word spin/CAS and shared native parking stripes,
with exact bound-context ownership and separate AVAILABLE/ACQUIRED outcomes.
Parking does not claim a guard; callers retry after waking. Initialized guards
retain their domain, require stable addresses and cannot be copied/moved. Actual
payload ownership/GC pinning remains the caller's responsibility.

NativeContext now accounts held guards and refuses poll/turn/TLS/world transitions
while they remain. Blocking wait refuses ACTIVE/collector or already-guarded
callers. Role checks precede guard metadata reads. Native HeapOwner transitions
preserve their phase/counters on refusal. This is a protocol fence, not automatic
exception unwinding or asynchronous cancellation support.

The separate native library/example demonstrates real mutable objects, strong
handoff ownership, contention, wake/retry and complete retirement. The test uses
8 OS owners/two objects, actual observed parking, atomic and forced-lock backends,
paired-field invariants and 18 semantic controls. Existing native context/world/
lease/REG suites test compatibility. The installed SDK contains source/header/
port closure for its own build/test, with commented instructions.

No guard has been inserted into Heap. No Type/Jit/wire fields or shared Dis64 IDs
change; general managed mutation still uses exclusive NativeWorld admission.
C/JIT count/mark paths, allocator/object integration, roots and unwind/cancellation
remain before enabling parallel managed execution. See
[protocol and exact scope](../../disVM/runtime/OBJECT-GUARDS.md).

Validation: 34 runtime regressions passed; native guard tests and their eighteen
controls passed normally, with UBSan and with TSan on both backends. The installed
source example/driver and strict C89/C++98 header compilation also passed. These
checks do not prove race freedom of the entire managed interpreter or native JIT.
