2026-10-30. Root development version0.1694. Engine0.1693 and FIR0.69 remain;
this series changes portable IDE modules and imports selected Inferno C/compiler
sources. It does not add shared Dis64 IDs or enable new native calls by default.

## Lazy/incremental Coco/R analysis

The visible desktop colours introduced in v0.1693 now reuse stable token ranges.
The worker retains a private last-success baseline, restarts before the edit's
complete token (including an adjacent generated trivia gap), and accepts an
unchanged tail only after a newly generated token matches shifted extent/class.
Otherwise it scans to EOF. Profile switches, incomplete comments/strings and
large edits can require a full pass. Unicode scalar offsets are preserved even
when UTF-8 byte lengths change. Read-only generated tables initialize once per
private scanner instance; recognition rules/upstream generator sources are unchanged.

Returned catalogs and lazy Snapshot arrays are detached from retained state.
Caller mutation cannot corrupt a later analysis/snapshot. Invalid/quota jobs
retain the previous successful baseline and return no partial success. Existing
coalescing, stale revision/profile rejection and same-ticket paint-only updates
remain. Analysis is a scheduled Limbo/Dis process, not an OS-thread-parallel VM/GC
claim. Byte-boundary validation/copying is still linear; physical latency is not
measured by record counters.

The independent fresh-worker oracle covers34 short edit states and a96-line
fixture, including token merges, comment delimiters, escapes, incomplete text,
profile/Unicode changes, receiver mutation and error recovery. The large local
edit scans at most3 returned records and reuses over600. The counters are logical
records, not exact NFA work: the facade can prefetch a token while returning trivia.

## Context, search and lexical candidates

New [Idetokenquery](../../ide/dis/bridge/idetokenquery.m) provides pure reusable
catalog consumers: scalar token context, bounded KMP literal search with class
masks and sorted/deduplicated prefix candidates from identifier records.
All helpers check revision/profile and complete catalog shape. They do not run
another parser, change selection/source/Undo or access UI/native objects. The
caller supplies the exact source snapshot; same-length contents are not authenticated.
Class5 combines comments/whitespace. Candidates are lexical, not type/scope/import
resolution or a new semantic-completion popup. Query validation is synchronous
and belongs outside a per-keystroke path.

Menu **17** / `--launch tokens` / `run-token-query.sh` executes the actual
[fully commented Limbo example](../../ide/dis/examples/token-query/main.b), also
shipped with [EN](../../ide/dis/examples/token-query/README.md) and
[RU](../../ide/dis/examples/token-query/README.ru.md) readmes. It demonstrates
context, search, names, snapshot value semantics, incremental counters and balanced
worker shutdown. It runs from installed/relocated packages and rebuilds from the
shipped source+headers without Python, a generator or a source checkout.
Menu8 remains the coloured IDE; menu16 remains its analysis-service check.

During query testing, a missing KMP fallback-root initialization caused an actual
array-bounds exception. The new bounded table is explicitly zeroed. The same
uninitialized prefix[0] dataflow in previous document Find/ReplaceAll is repaired.
Existing newa scalar storage remains unspecified; VM allocation semantics were
not changed to hide a caller bug. Existing adversarial search/replace tests pass.

## Inferno/Dis64 response and synchronization

Received INFERNO-0022 during this work and imported exact source pin
**0e86bc847330e47614056bd001ee75b617a22e69**: DisVM **911**, bootstrap **281**
files verified against Git/SHA-256. It adds opt-in immutable generated entries
with separate full map8 arrays and explicitly legacy signature hashes. The20-byte
map fixture has no truncating legacy map[16] adapter or variadic callable record.

The complete actual math.c compiles against the generated header; selected
actual entry pointers call four scalar bit-conversion routines. The opt-in
experimental mathmodinit refuses old runtime registration. Math_realbits64 now
copies representation instead of implementation-defined unsigned-to-signed value
conversion. Normal runt.h/NC64 paths and build defaults are preserved.

This is a real scalar producer/record/actual-C-consumer checkpoint, not all68
Math functions, dispatcher/table binding, reference-result ownership or forced-GC
handoff. Shared43-op/np0, general inspector false and registry remain unchanged.
Calls with references, caller/result/temp roots, unwind, full boot and physical
ARM64/RV64 remain separate agreed gates. [Sync](../../disVM/SYNC.md).
