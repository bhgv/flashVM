# v0.1735 — atomic stop requests and fewer empty GC rendezvous

Runtime0.43.0 lets unrequested instruction safepoints return without the world
mutex. Atomic acquire/release stop requests gate the existing root publication,
park/scan/resume protocol. Collection still waits for all active owners and
preserves the previous generation's resume fence. Unsupported atomic compilers
conservatively keep mutex polling. --gc-locked-poll retains the reference route.

Owner-private fast/locked poll counts are copied only by that owner and reported
after joins. Empty RC queues no longer cause useless Fast requests; Cycles and
shutdown drains retain their normal protocol. New deterministic fixture checks
10000 idle polls per route plus100 two-mutator root rendezvous. Managed heap
checks cover both routes, JIT/interpreter, reclamation, saturation, direct-byte
limits and managed-error retirement. A whole-process benchmark alternates five
runs per route and requires identical application instruction counts.

This optimizes the existing stopped-world worker model. It does not claim
concurrent marking, a complete managed-reference barrier or parallel spawn.
See [contract](../../disVM/runtime/THREADING.md) and
[Russian contract](../../disVM/runtime/THREADING.ru.md).


Validation also exercises the conservative no-atomics path, repeated native
Fast/Cycles rendezvous and strict UBSan fixtures. Native Linux x64 is executed;
no new physical ARM64/RV64/Windows acceptance is implied. Whole-process timings
are reported as observations, without a required speedup threshold.
