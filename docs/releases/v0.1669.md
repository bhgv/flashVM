# v0.1669 — Counted numeric loops, postfix updates and bounded lexical scopes

[Contract EN](../../fir/v1/doc/NUMERIC_FOR.md) / [RU](../../fir/v1/doc/NUMERIC_FOR.ru.md) · [Int tutorial](../../fir/v1/examples/dis/numeric-for-int.b) · [Real tutorial](../../fir/v1/examples/dis/numeric-for-real.b) · [Nested scopes](../../fir/v1/examples/dis/numeric-for-nested.b)

FIR tools **0.58.0**, source CLI **0.25.0**. Homogeneous Limbo int/real entries
now accept counted for loops, optional initializer/condition/step, initialized
header declarations and statement-only postfix ++/--. CLI and libraries share
the authoritative Coco/R grammar. No FIR type/opcode or runtime ABI is added.

The compiler stages each step once and emits it after the body. Continue reaches
the innermost step, while break and return skip it. Nested loops retain independent
streams. Numeric headers own a loop scope; bodies have a nested lexical scope,
so shadowing i in a body cannot redirect the header's staged update. Existing
table counted/snapshot loops preserve their prior scope contract. Step declarations,
header aliases, prefix/update expressions, comma clauses and numeric for-in reject.

A deep numeric-for fixture found a real scope-array overflow: one parser descent
can create a header scope and a body scope. Lexical admission now checks its own
64-level budget independently of parser depth. Sticky errors freeze scope entry/
exit until the next source reset, preventing recovery from indexing unadmitted
owners. Repeated in-process deep rejections prove recovery and preserve exact
caller FIR/debug sentinel bytes. This defect belongs to FlashVM's source adapter;
it is not a copied Inferno compiler defect.

Existing numeric cell verification, effects, peephole optimization and Dis/SWF
lowering execute the new CFG. Int postfix wraps; real uses binary64 exact-one
updates with established IEEE behavior. Debug checks retain authored UTF-8 for,
transfer and two-byte postfix spans, including deferred step sites. Full function
ABI, final target/native-PC debugger maps and complete IDE self-hosting remain
separate work. Checked int division/remainder/shifts retain their Dis-only target
restrictions; the SWF suite excludes those explicit backend-specific cases.

Three new tutorials comment every nonblank line. Detailed linked EN/RU guides
explain execution order, scope retirement, optional headers, transactions,
backend limits, C99 embedding and expected captures. Both portable SDK variants
ship the guide and execute the real counted tutorial after relocation/relinking.

## По-русски

Добавлен числовой счётный for с необязательными частями заголовка и отдельными
операторами ++/--. Шаг выполняется после тела и при continue, пропускается при
break/return; вложенные циклы и затенение переменных проверены исполнением.
Исправлен найденный UBSan выход за массив лексических областей: их глубина теперь
ограничивается независимо от рекурсии парсера. Ошибки сохраняют FIR/debug целиком,
а следующая библиотечная компиляция работает после повторных глубоких отказов.
Три подробно прокомментированных примера, руководства и оба переносимых SDK
проверены вместе с исходным/оптимизированным Dis и связанным SWF.
