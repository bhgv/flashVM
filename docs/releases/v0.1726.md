# FlashVM v0.1726 — editable cubic Bézier contours

IDE version0.7.12. Vector paths now retain two independent controls for cubic
segments. Existing M/L/Q/Z paths remain readable; absolute SVG C commands round
trip both controls. Ellipses use four cubic segments with four distinct anchors
and kappa0.55228475, rounded to logical page coordinates. These ordinary cubics
approximate an ellipse; they are not exact rational conics.

## Geometry and execution

[The fitter](../../ide/dis/bridge/idevectorbrushfit.b) replaces neighbouring-point
clustering with interval least-squares fitting using chord-length parameters.
It starts with four spans of a closed contour, fixes interval endpoints, checks
all original samples against the rounded curve separately along X/Y, and splits
at the worst sample when either error exceeds the complete figure extent/40.
A bounded reverse check samples each proposed curve at63 interior parameters
against the source polyline to reject bows between knots. Failed intervals split;
short intervals retain their original lines. No curve count is guaranteed for
arbitrary drawings. The finite reverse sampling is not a continuous Hausdorff
error proof; source raster precision remains one logical page unit.

[The existing worker](../../ide/dis/bridge/ideinkworker.b) receives frozen ink
only after release. Motion keeps native raw ink; fitting, union and serialization
run on a separate Limbo process. The pane accepts only the current revision's
completion and then publishes the new immutable geometry/cache together.
Pending edits still preserve stroke ordering and Save/Undo synchronization.
This is separate VM scheduling, not a claim that every Dis process runs on its
own operating-system thread. No live preview point arrays cross to Limbo.

[Picking](../../ide/dis/bridge/idevectorpick.b) gives Objects the topmost filled
containing figure; otherwise it chooses the globally nearest contour within20
screen pixels. Nodes chooses a nearby contour or keeps the selected figure for
handle/marquee editing. The native owner converts the screen budget through the
completed pane and canvas transforms and passes a copied scalar through the
existing typed request. The conversion has0.001 logical-unit resolution;
portable model clients default to20 logical units. Curve hit tests use bounded
flattening, not exact algebraic distance. Source coordinates themselves are integers.

The private desktop stream adds tool flag0x20000 and seven-word records for
cubic-capable geometry. Unflagged five-word streams remain valid. This changes
neither SWF nor Dis/Dis64 containers. Decoder validation covers both controls,
record lengths, aggregate budgets and legacy refusal cases. The native renderer
uses [FVM_PATH_CUBIC](../../flashVM/include/flashvm/path.h#L24); the legacy MovieClip-only presentation fallback tessellates
cubics. Handles/selection overlays never enter SVG or history.

## Проверка и ограничения

Модель расширена до кубических Безье: две управляющие ручки на сегмент,
отдельное выделение/перемещение ручек, перенос, масштабирование и вращение фигур.
Овал задаётся четырьмя сегментами; совпадающие начальная и конечная точки
замкнутого кубического контура остаются соединёнными при редактировании.
Старые квадратичные контуры сохраняются без автоматической переделки.

Векторизация кисти запускается после отпускания в отдельном Limbo-процессе;
результат подменяет геометрию только для актуальной ревизии. Проверка ошибки
использует размеры всей объединённой фигуры, включая составные контуры.
Проверяются исходные точки и дискретные обратные расстояния до ломаной;
непрерывная математическая гарантия расстояния между всеми точками кривых
пока не реализована. Точность исходной маски — одна единица страницы.

Выбор объектов: верхняя содержащая залитая фигура либо ближайший контур
не дальше20 экранных пикселей. Выбор контура: ближайший в том же допуске либо
контур уже выбранной фигуры. Масштаб страницы/окна учитывается через канал.
Перо сохраняет свой прежний алгоритм сглаживания; новые кубические сегменты
добавлены для примитивов, векторизации кисти, SVG и редактирования.

Tests exercise four-segment ellipses, both cubic controls, closed-anchor welding,
cubic SVG round trips, nested fills, nearest-contour selection and tolerance,
legacy dense quadratic selection, actual native ink workers, and private decoder
negative controls in interpreter/JIT and native host paths. Dummy-SDL replays
exercise actual VM/rendering code; physical touch/desktop acceptance remains manual.


Rebuild the complete matching runtime and all Dis modules: Node/Document layouts
changed. Mixing old `.dis` files or `.m` headers with the new package is unsupported.
The installed SDK ships the matching native-profile compiler, headers, helper
sources and [commented cubic SVG](../../ide/dis/examples/vector/cubic.svg).


Validation:13 affected native/model/pane/worker/editing/viewport/dense-selection
cases passed across the final runs. The two pane header expectations were updated
for the explicit cubic record flag and passed again in both modes. Final model
reruns include record-cache upgrade and welded-anchor regressions. The installed
SDK passed the dense/imported and oval-plus-brush desktop replay under JIT.
