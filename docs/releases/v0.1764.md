# v0.1764 — retained heap Type ownership conversion

Runtime0.66 converts hosted heap.c Type ownership to checked atomic primitives:
4 retains,4 ordinary releases,1 static-baseline release and8 preflight loads.
Pinned vendor source, native layouts, destruction order, GC and Dis64 IDs stay
unchanged. Preparation refuses source-boundary drift rather than silently
omitting a site. Helpers preserve LAST retirement and avoid post-release reads.

A real dtype/freetype/array/Fast probe checks element-Type ownership through
collector retirement. Two actual-runtime relink controls skip only the probe's
retain/drop and require exact semantic status10 before unsafe final freeing.
Console/editor C/JIT, GC cycles, OS executor/helper-RC and array paths exercise
the converted code. Instrumented interpreter probe paths use TSan; forced-lock
count relinks preserve root/pin controls. Target ARM64/RV64 execution and full
JIT instruction instrumentation are not inferred from local Linux x64 evidence.

Invalid native count invariants terminate instead of recovering after partial
allocation. Normal guest allocation preflights retain their existing errors.
Other C/JIT Type operations and Heap.ref are still plain under serialized
admission: no parallel managed heap or atomic allocation reservation is enabled.
Inferno synchronization reports this hosted stage separately from shared format
activation. Vendor manifests remain unchanged.
