# v0.1563: preserve path transactions while removing quadratic fragment work

`fvm_path_append` stages only new transformed commands and reserves destination
capacity geometrically. No complete destination copy occurs for every glyph.
All failing work precedes destination writes; scalar POD pushes preserve public
allocation/transform failure atomicity and transformed self-append behavior.

[Русское описание](../../flashVM/doc/PATH_APPEND_GROWTH.ru.md).

The independent regression covers allocation boundaries, a late invalid point,
command order, contour-open state, self-alias and a linear cumulative allocation
budget over 1024 fragments. The parent fails the budget; the fixed code passes.
125 selected path/raster tests pass. The same transaction test is also registered
with the editor's native/UBSan builds. The change fixes the long-line path
construction bottleneck found during the clipboard size-boundary regression.
Public geometry, API, command limits and compatibility status are unchanged.
