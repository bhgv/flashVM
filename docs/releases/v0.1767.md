# v0.1767 — Module/link ownership and MP isolation

Runtime0.69 converts lookmod/$self Module retains and unload release to checked
native signed-int counts. Nonfinal unload rereads no count storage; LAST retains
registry unlink/MP/export/type/code cleanup order. link.c/load.c add3 checked
Type retains and8 preflight loads; $self adds2 Module observations. Unpublished
initializations remain plain; pinned source and Dis64 layouts/IDs are unchanged.

[Contract](../../disVM/runtime/MODULE-COUNTS.md),
[actual Module/MP probe](../../disVM/runtime/module_counts_probe.c),
[remaining work](../../disVM/runtime/HEAP-PARALLELISM-STATUS.ru.md).

The probe uses real legacy empty-table registration, lookup/link/unload and Fast.
A scalar MP clones into a distinct allocation:7 copies, writing9 preserves the
source7. Exact Module/Type/Modlink baselines, nil-import owner consumption, error
text restoration and final unlink are checked. No guest export is introduced.
Two actual-runtime relink controls omit only its retain/nonfinal drop and must
reach exact semantic status10 before invalid freeing. Earlier selectors remain.

Validation targets console/editor C/JIT, arrays/bounds, actual cycles, OS executor/
helper RC and owner/error/role paths. TSan checks instrumented interpreter C,
not JIT machine instructions. Source SDK includes private helpers/probe/preparer/
docs. Local x64 tests do not certify ARM64/RV64 execution or full VM race freedom.

Registry publication, code lifetime, snapshots, remaining C/JIT/GC sites, allocator
and graph/collector protocol still require serialized managed admission. Atomic
preflight is not allocation reservation, and counter atomicity is not a protected
registry lookup. No automatic miniheap or parallel managed mode is enabled.
