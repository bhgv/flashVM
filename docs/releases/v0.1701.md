# v0.1701 — Retained IDE bitmaps and captured drag input

2026-10-31. Workspace0.1701; FlashVM engine/FIR formats and Dis/SWF ABI unchanged.

## Result

The actual desktop preparation/worker path now associates a local bitmap with
each admitted visual window/widget. Content, affine transform/opacity and child
composition have separate dirty bits. Changed children propagate composition bits
through native parents; successful root composition clears them. Parent bodies
and children stay separate painter layers, preserving the MDI capture correction.

Unchanged native images/local commands are immutable and reference-counted.
Transform-only changes share their data; eligible ordinary panes also bypass
MovieClip reconstruction and glyph-outline cloning/comparison on the VM owner.
Translation, zoom, rotation and opacity are composed from cached pixels; integer
translations use direct sampling and opaque copying. Other transforms use
premultiplied bilinear filtering. Drag opacity remains exactly90 percent.

Content edits compare complete changed contours. Only a local rectangle is cleared
and repainted inside a copy of the old object bitmap. Root64×64 damage includes
old/new transformed bounds, removed objects and painter-order changes. Unchanged
intersecting cached layers are blitted there; whole-scene vector rasterization is
not repeated. Four native workers build changed images and compose packed damage.

An already captured mouse-header continuation no longer waits for raster completion
or performs another hit test. New clicks/focus/lifecycle events keep pixel ordering;
FIFO/replay/capture semantics are preserved. Other touch/selection gestures retain
the previous barrier. SDL tries accelerated presentation with software fallback.
Desktop GC uses its normal allocation threshold at safe points, instead of forcing
a full collection per movement. Full root pixel-buffer copies remain.

## Limits and diagnosis

Stable acyclic native layers1..63, bounded extents/transforms, exact owner keys and
64MiB associated-image budget are checked. Budget exhaustion retries the ordinary
vector/tile path; malformed scenes fail. Queue replacement/shutdown and destruction
of an old baseline cannot invalidate shared pixels/local commands. Physical image
counts return to zero after all frame/queue owners are released.

`DVM_EDITOR_RENDER_STATS=1` prints bitmap build/reuse/local-pixel and root-damage
counts in the installed IDE. `DVM_EDITOR_RETAINED=0` permits development comparison
with the vector path. These are diagnostic settings, not a new editor mode/button.
Ordinary IDE launch after rebuild/install uses retained rendering by default.

## Validation

Frozen SDL-enabled compiler/runtime/IDE suite **337/337** PASS, including the
new retained native and actual IDE replay checks. The native implementation/test
also pass ASan/strict UBSan (prebuilt raster libraries; unavailable LSan scan disabled).
Installed SDK replay passes interpreter/JIT after relocation to a path containing
spaces. Package/document checks **7/7** and installed retained-guide links pass.

The actual initial desktop builds28 object bitmaps; subsequent ordinary window
motion reuses28 with zero local content pixels repainted. Separate source edits
invalidate only affected content, and root damage remains bounded. These are
verified work counters, not a claim about physical-device FPS.

Native fresh/incremental tests cover exact RGBA, zero content repaint on transforms,
partial glyph contours, ancestor flags, deletion/order, queue replacement, budget/
cycle refusal, surviving base-frame destruction and image-count0. Real IDE replay
checks actual bitmap reuse/owner skips during drag and selective text invalidation.
Native SDL FIFO tests exercise captured continuation without crossing a new hit or
replay barrier. Dummy-driver checks verify software fallback, not physical GPU FPS.
ASan/strict UBSan cover the retained implementation and native test with prebuilt
raster dependencies; only unavailable LSan process scanning is disabled.

## Remaining scope

The cache granularity is desktop windows/widgets, not a texture per glyph/vector
primitive. Images are local-resolution; large zoom uses filtering, not additional
vector detail. Per-subtree precomposed textures, external opacity masks, tiled COW
pixels, GPU object composition, delta scene transport and a wider native input
capture lease remain future work. Clipped/vector/mirrored/animated panes still
prepare owner commands, while their unchanged native bitmaps can be reused.
No user-device latency or physical SDL/touch-board acceptance is claimed.
