The graphical host now defaults to UI/SDL/FlashVM on main and the complete Dis
interpreter/JIT/loader/process/GC runtime on its own OS worker. Native extended
up/REG TLS is used and retired on that worker. Bounded copied queues separate
both heaps; bulk egress no longer presents scenes from Dis. Generated native
frames are captured before UI RPC; startup/ink results cross as copied values.
Main never waits for a Dis turn to pump input and local graphic gestures.

Normal return and startup/transport failures join owners before releasing borrowed
resources. Closing queues rechecks shutdown state. Owned RPC text is freed on
Dis allocation errors. `--sequential-ui` retains a reference route. Diagnostic
roles are checked from actual TLS/worker lifecycle state.

Tests execute8 whole managed interpreter/JIT/channel/GC applications,2 failure
retirements and duplicate-mode refusal. Real SVG/pixel editing, desktop clipboard
and tool replays run with the threaded host. Existing native register/world/
Fast-Cycles fixtures also execute after restoring their production addw guard's
required exception adapter. Those focused fixtures do not imply a parallel heap.

There is one Dis heap mutator in this checkpoint. Parallel Limbo spawn, actual
collector/world integration and shared runtime metadata synchronization remain
next stages. Raster workers are already independent. Native Linux x64 execution
is verified separately from unexecuted ARM64/RV64/physical-display acceptance.
