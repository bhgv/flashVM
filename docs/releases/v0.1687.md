# v0.1687 — arithmetic carry/borrow facts across compiler targets

[Repository](../../README.md) · [Guide EN](../../fir/v1/doc/KNOWN_RESULTS.md) ·
[RU](../../fir/v1/doc/KNOWN_RESULTS.ru.md) · [Commented source](../../fir/v1/examples/dis/known-results.b)

FIR0.66 propagates known-zero/known-one masks through modular int32 and big
addition/subtraction. A bounded unsigned carry scan models subtraction as
`a + ~b + 1`, discarding the final carry. Unknown bits/carries remain unknown;
no signed host overflow, cell-content inference or path correlations are assumed.

This proves new exact results for dynamic producers, including
`((x | 7) + 1) & 7 == 0` and `((x & -8) - 1) & 7 == 7`.
It also feeds existing raw SWF preflight and DCE: `(x & 15) + 16` is a legal
int32 shift count, and `(x & -8) + 1` is a nonzero signed divisor. Counts32…63
and possibly-zero arithmetic divisors remain rejected. Removing a total outer
operation retains a failing inner producer and its zero-division error.

The same analysis serves CLI, public C99 libraries and the actual Dis-owned IDE
compiler worker. The line-commented Coco/R source example now includes carry
and borrow terms; raw/optimized Dis and SWF still return42. Installed SDK checks
relink C99 clients, compare generated Dis/SWO bytes against CLI, link SWF8 and
execute both NC64 interpreter/JIT paths. Detailed EN/RU guides and indexes connect
the arithmetic rules, implementation, example and reproducible commands.

## Independent evidence

The C99 fixture checks all81×81 pairs of four-bit ternary operand domains against
all256 concrete pairs for each domain, in32/64-bit addition/subtraction:
**6,718,464 exhaustive evaluations**. The oracle intersects concrete result bits,
rather than repeating the carry algorithm. Additional192512 carry/borrow samples
cover every low-bit boundary;194560 mask/shift samples cover non-topological CFGs,
immutable IR, sign bits and unsigned wide-shift oracles.

The target matrix now covers352 raw/optimized results (11 forms, eight inputs,
two widths), exact literals, optimizer fixed points and producer errors. The SWF
proof matrix adds arithmetic-derived counts/divisors and conservative rejection.
