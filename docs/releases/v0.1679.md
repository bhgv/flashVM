# v0.1679 — целочисленные тождества и выдача Dis/SWF

[Workspace](../../README.md) · [Контракт EN](../../fir/v1/doc/INTEGER_IDENTITIES.md) ·
[Контракт RU](../../fir/v1/doc/INTEGER_IDENTITIES.ru.md) ·
[Пример и C99-клиент](../../fir/v1/examples/integer-identities/README.ru.md)

FIR 0.59 упрощает точные целочисленные тождества для int/big: нули/единицы,
идемпотентные побитовые операции, деление на ±1, остаток от ±1 и сдвиг на ноль.
Проверки снимаются только после доказательства безопасности самой операции.
Производитель значения сохраняет собственные ошибки/эффекты: `(a/b)*0` не
скрывает деление на ноль. Неизвестные x/x, x%x, 0/x и ошибочные сдвиги остаются.
MIN/-1 использует определённое переполнение по модулю без signed UB компилятора.

CSE теперь переиспользует i32 AND/OR/XOR в том же блоке с тем же порядком
операндов. Floating point, AS-преобразования и reference owners не получают
целочисленных правил. В частности, знак нуля в binary64 сохраняет прежний контракт.

Динамический пример с циклом возвращает 42 в raw/optimized Dis и в SWF после
явной оптимизации и линковки. Raw SWO сохраняет отказ неподдержанного checked
lowering с прежними байтами выхода; общие динамические SWF div/mod/shift этим
не реализованы. Новых команд, парсеров, ABI и контейнеров нет.

CLI и библиотечные fir_optimise/fir_run выполняют один проход. Новый построчно
комментированный C99-клиент принимает исходник Limbo и выдаёт optimized Dis/SWO,
сначала завершая компиляцию во временном потоке. Последующая ошибка файловой
записи может оставить префикс; атомарность записи не заявляется. SDK включает
клиент, исходник, пример, EN/RU-руководства и согласованные библиотеки.

DisVM source snapshot обновлён до Inferno d30013d468e43a8adecb0a46ad7156373bab174b:
812 точных файлов. В этой дельте только документы Dis64 — наше предложение и
ответ Inferno, плюс ссылки. GC-map8 поддержана как направление; точный header,
extensions и calling contract ещё согласуются. Активные NC64, loader, GC/JIT
не переключались. Собственный путь Limbo остаётся Coco/R → FIR; старый Limbo
используется временным bootstrap для ещё не покрытых конструкций IDE.

Проверки включают полный FIR с настоящими SWL/FlashVM, полный FIR под UBSan,
нативные int/big/CFG и сервис компиляции в интерпретаторе/JIT, C99 snapshots,
повторную оптимизацию и перенесённый SDK. Точные итоговые результаты указаны ниже.

На демонстрационном цикле счётчик исполненных Dis-инструкций уменьшился с
344 до 144, native — с 343 до 143, результат/флаг остались 42/1. Это не замер
времени и не обещание такого ускорения для других программ.

Полный FIR с настоящими SWL/FlashVM: **72/72**; полный FIR под UBSan: **72/72**,
после расширения отрицательных случаев отдельно **2/2**. Нативная выборка:
**28/28**, финальная выборка compiler service/экспорт/новые тождества: **8/8**.
Прямой in-memory API сохраняет SSA-номера; текстовый opt round-trip может менять
слоты backend. Для побайтового совпадения с CLI C99-пример явно материализует
канонический FIR; это не обещание одинаковых байтов для всех способов встраивания.

Перенесённый SDK прошёл целиком в режиме `--fir-dis-only`: таблицы,
source/FIR/Dis, заново собранные C99-клиенты, compiler service и оба режима VM.
Новый клиент выдаёт Dis/SWO побайтно как согласованный CLI-путь и сохраняет
старый файл при отказе backend. Реальное build-menu собрало и установило FIR и
IDE, 28 проверок меню прошли. Новые документы/пример имеют проверенные ссылки.
