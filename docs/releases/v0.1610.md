# v0.1605–v0.1610: Limbo-derived values, references and IDE conversion help

[Workspace](../../README.md) · [Value contract](../../ide/dis/VALUES.md) ·
[По-русски](../../ide/dis/VALUES.ru.md) · [Previous series](v0.1604.md)

Six commits add explicit value/reference semantics without changing legacy
FlashVM snapshot transfer or native AS coercions. Our pure Limbo `Idevalue`
module reflects byte/int/big/real/string, with marked bool/char/table extensions.
`int` follows the compiled classic/NC64 profile. Big remains exact signed 64-bit;
`tofloat` aliases `toreal` and means binary64.

The projection owner accepts copied constants, explicit conversions and typed
writes. Table snapshots copy stored data while retaining nested object identity.
Bound Method descriptors retain their receiver and incarnation; another receiver
cannot consume that method even with a matching incarnation number. The inspector
model copies typed replies at admission and rendering, preserving its existing
stale ticket/revision protection. The optional AS client forwards opaque
references and requested Limbo types without evaluating the receiver.

The console IDE now supplies `Projection.to*` completion and parameter help from
the loaded Limbo type catalog. These are optional library declarations, not a
claim that new native AS globals or general compiler lowering already exist.
Packages include the mutually dependent modules, interfaces, source and AS client;
installed documentation is linked locally and checked after relocation.

## Boundaries

Pure Limbo modules currently use the matching source-built bootstrap. Our Coco/R
FIR numeric frontend still does not lower these general ADTs, channels or `any`.
The AS library describes an adapter callback; it does not implement network RPC,
AS Big arithmetic, native builtins or a full AS→SWF execution pipeline. Export GC,
authentication, retry deduplication, arbitrary FlashVM reflection and graphical
watch-panel integration remain separate work. Legacy snapshot APIs keep their
previous documented behavior. All changed `.m` clients must rebuild together.

## По-русски

В основе преобразований теперь типы Limbo: byte/int/big/real/string. Bool/char/table
явно описаны как расширения; tofloat — псевдоним toreal. Разрядность int берётся
из целевого профиля, а big не проходит через неточный AS Number.

Проверены настоящие каналы Dis: константа по значению, типизированная запись,
независимые снимки, вложенная ссылка на объект и метод с сохранением получателя.
Подсказки консольной IDE строятся из отражённого каталога. Сеть, общий any,
экспорт GC и графическая панель не выдаются за уже реализованные возможности.
