# v0.1714 — Bounded input and independent vector geometry

Fill (second button from the right), Pen (rightmost), and color changes formerly
walked/serialized the complete vector document and rerasterized it together with
its toolbar. Idevector now caches immutable committed geometry by array identity;
only tool/history header words change. The geometry worker prepares new contour
bytes before returning them to the owner. The private implementation lives in
`idevectorwire.b`, included by `idevector.b`, and ships with the source SDK.
Rebuild dependent Dis modules together: Document's internal module signature grew.
The existing 56-byte wire header and vector record encoding are unchanged.

Native C separates eligible committed vector canvas, chrome and live ink nodes.
Changing controls reuses the unchanged associated canvas bitmap. Exact bounded
keys include pane dimensions and all geometry bytes, excluding six state words;
keys and images share the existing 64 MiB scene budget. Split capture applies to
fully visible opaque source panes; clipping, mirrors, motion, translucency and
keys over 512 KiB retain the existing capture path. Live samples remain native;
no per-motion point arrays are sent to Limbo. This does not move UI policy into C.

Wheel input consumes at most 16 adjacent vertical packets from the same device,
window, direction and recorded position. Opposite directions, other events and
Ctrl zoom stop batching. A batch preserves the old 120-pixel step per packet,
including boundary clamping order. Private pointer phases 18..32 encode 2..16
steps; old phases 0..3 retain their meaning. No public wire or Dis64 ID changed.
