# v0.1557: repair accumulated caret and mouse-line drift

The caret overlay used natural font line height while TextField rendered with
ascent+descent+leading. The offset accumulated over multiple lines; at Noto 11
the tenth-line caret was about 31 pixels above its actual text ink. Explicit
leading/kerning and matching periodic tabs now keep text, caret, selection,
mouse hits, page rows and footer reserve consistent at every admitted size.

[English explanation](../../ide/dis/CARET.md) ·
[Русское описание](../../ide/dis/CARET.ru.md).

Real raster tests independently locate text ink and the caret, then derive
mouse clicks from the ink. Twelve rows, tabs, AV pairs, sizes 9/11/14 and both
Dis dispatch modes pass. The parent renderer rebuilt with the same controller
fails the regression as expected. Existing editor/SDL/actions/zoom checks also
pass. This changes only the editor's host presentation contract, not global
TextField layout or Dis source offsets.
