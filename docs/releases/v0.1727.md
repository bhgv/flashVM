## Compiler and runtime integration

The temporary ordinary-cell4 native Limbo bootstrap now builds the separate
upstream dis64-inline/dis64-lower modules. Bounded numeric case constructs lower
to existing scalar comparisons/jumps, with target and source-PC remapping.
Direct bounded scalar leaf procedures are specialized into private entry IR;
new scalar locals are zero-initialized afresh for every source call. The original
compiler IR and ordinary Dis output remain intact. This uses the agreed43-op np0
profile; executable-file FRAME/CALL/MCALL and managed/import ABI remain closed.

Both selected snapshots preserve exact upstream source and hashes. Compiler and
reader tests run independently:67 case sources/134 whole x64 C/JIT processes,
67 stale-PC controls;27 helper sources/54 processes and2 stale-local controls,
plus10 valid ordinary-source refusal shapes. The unchanged FlashVM reader admits
the generated images. A format-valid stale-local image fails source semantics
only when executed; reader admission is deliberately not execution proof.

Standalone bootstrap CTest now runs the two source suites on the cell4 profile.
An optional explicit LIMBO_DIS64_READER executable enables independent-reader
cross-checks. Required helper scripts are shipped in its own pinned snapshot;
no sibling Inferno checkout is needed. These reader-only CTests report0 execution
processes; the separately built classic-mk console supplies execution evidence.

The confirmed Sys I/O correction also transfers: compiler-owned byte-array
storage descriptors are checked by byte size/pointer count rather than requiring
the builtin descriptor's singleton address. A fresh x64 classic-mk console passes
the owning UTF/I/O, math, GC, leases, live-VM and field-witness gates. ARM64/RV64
claims in Inferno's journal remain its native-CI/QEMU evidence; this session does
not independently certify those architectures or physical Android. Draw/Tk/GLES
window storage changes are outside FlashVM's selected runtime.

## Our Coco/R frontend

Limbo frontend version0.11.1 adds
[limbo_source_span](../../compiler/limbo/frontend/source_position.h), paired with
limbo_source_position. The pure reentrant C99 helper resolves both half-open byte
anchors on one immutable source snapshot in one pass and publishes both or neither.
It validates the entire input even when malformed bytes lie after both endpoints.
Empty spans/EOF are valid; reversed, interior UTF-8/CRLF and invalid boundaries
refuse without changing output. Coordinates remain physical one-based lines and
Unicode scalar columns, tab one, CRLF/CR/LF one break. No allocation, I/O, parser
state, digest generation or diagnostic counter reinterpretation is introduced.

The21 frontend CTests pass, including independent all-pairs mixed UTF/newline
span fixtures and the existing exhaustive Unicode scalar-boundary tests. The new
span fixture additionally passes O3/NDEBUG strict UBSan. The commented installed
[example](../../compiler/limbo/examples/source-position/README.md) covers ownership,
EOF and range conversion. This API does not emit a Dis64 debug section or change
Coco/R parser authority. Logical #line/fline identities stay separate from physical
snapshots; filenames/digests confer no path access.
