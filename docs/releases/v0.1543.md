# v0.1543: runnable desktop packages and Dis diagnostics

The root builder now enables the actual SDL2 window/input/audio frontend for
graphical profiles, automatically building a pinned source SDK when needed.
`--no-player` explicitly retains console-only builds. The `player` profile uses
AGG and JIT. Installed GUI packages expose the real player as `flashvm`, retain
`flashvm-console` for numeric tests and include portable demo launchers.

`out/run-checks.sh` discovers installed VM checks; `--window` opens the graphical
demo. Pinned SDL/ALSA commits, verified X.org header hashes and upstream licenses
are recorded. Dependency caches are local and do not install system packages.

Native Linux AMD64 Dis builds now install WORD32/WORD64 interpreter/JIT diagnostic
executables without a Python or external emu runtime dependency. Their fixture
boundaries are explicit; they are not a general-purpose Dis host. A fully
commented Limbo channel/Sys example is compiled with debug information and shipped
alongside them. Full native Dis/IDE startup remains unfinished.

Validation used CMake 3.10.2: the root script built and installed the graphical
player, native Limbo bootstrap, Dis core, two diagnostics and console-check module.
Six frontend/SDK CTest entries passed, including keyboard, pointer, option and
playback-policy contracts; menu/preflight tests passed (11 and 5 cases).
Three SDK recovery/extraction tests and four packaging/default tests passed.
The actual installed player executed 60 JIT frames with four sound events, zero
fallbacks and zero audio underruns through SDL dummy drivers. Interpreter and JIT
also ran the three animation/audio movies for 120 frames each. Both native Dis
operand-model diagnostics passed. Installed packages were checked after copying
to a directory containing spaces. Physical display/input/audio devices were not
available for acceptance tests. Video playback remains unsupported.
