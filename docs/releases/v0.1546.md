# v0.1546: real native Dis applications and IDE service execution

`all` in build_menu.py now includes disvm-runtime. Post-build menu items 4 and 5
run a genuine Limbo channel/Sys program and production IDE workspace services.
No external emu is used. The root script builds and installs the native binary,
matching compiler, modules, .sbl files, ABI metadata, launchers and commented
examples under out/disvm-runtime. Installed checks discover this executable.

The runner retains production decoding, instructions, guarded AMD64 native leaves,
module linking, stack/channel implementation, reference counting and cycle GC.
The existing TLS extended up retains named Proc/R fields. One native owner runs
Limbo processes through a FIFO; full shared parallel VM ownership remains open.
A bounded stable-header arena supplies the production collector. Active process
identity is published in its TLS owner, and channel hangup preserves alt cleanup.

An explicit NC64 experimental format (magic 819264) prevents classic four-byte
modules from being silently interpreted with native eight-byte cells/pointers.
The separate bootstrap target regenerates consistent Sys frames/maps. Classic
compiler output is unchanged. NC64 is not the proposed standard Dis64 ABI or a
claim of complete classic 32-bit overflow semantics. The bootstrap is temporary;
our Coco/R-to-FIR compiler path remains the long-term compiler direction.

Real Sys stdout/string helpers and read-only file open/read/readn are connected.
Unsupported services raise errors. The shared FlashVM file port gains a size
query that preserves logical positions. The CLI diagnoses blocked-process
deadlocks and enforces process/heap/execution budgets. A test-only halt node is
explicitly enabled for unchanged existing IDE regression clients. The normal
workspace tutorial waits for balanced owner shutdown without that capability.

Integration exposed two defects: pointer-identity byte-array checks rejected
legal module-local descriptors, and the old yacc parser formed yys[-1] before
its stack. Reviewed build-view adaptations fix these, preserve all upstream
hashes and leave grammar actions intact. The byte-descriptor upstream patch is
provided separately; it has not been published to Inferno. Native formatting
widths, signed constants and alt table layout are adapted only for NC64.

Validation with CMake 3.10.2: the root one-command build/install passes 26 checks:
11 unmodified IDE service clients in native/interpreter modes, input/ABI/deadlock/
unsupported-call/binary-file checks, file-position preservation, a WORD32/WORD64
UBSan byte-descriptor regression, and byte-identical source regeneration.
17 menu tests, four packaging/default tests and five preflight checks pass.
The classic bootstrap still passes its product smoke test, including fresh iyacc
parser output. A UBSan build runs the Dis and IDE console tutorials and input
contracts. An installed package relocated to a path with spaces runs both
examples and recompiles/runs an example using only its installed compiler/headers.
The IDE tutorial executes 1457 instructions, with 1194 accepted native leaves;
interpreter mode reports zero native instructions.

Acceptance is Linux AMD64. The graphical editor is not yet attached to this
native executable. Sys/VFS/Styx coverage, general exception propagation,
allocator coalescing, reusable embedding cleanup and parallel collector/VM owners
remain explicit limitations in the runtime guide. Existing FlashVM windowed
examples remain separately selectable in the same menu.
