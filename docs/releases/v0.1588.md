# v0.1581–v0.1588: binary64 Dis compilation and fixes returned to Inferno

Our C99 FIR compiler **0.8.0** now directly emits NC64 Dis for `const.f64`, real
copy and add/subtract/multiply/divide, alongside the scalar i32/bool CFG backend.
Our existing Coco/R numeric AS1/2/3 frontends therefore execute through our own
FIR→Dis emitter and DisVM interpreter/JIT. No Inferno emitter creates these
programs. The separately selected bootstrap remains necessary for the full IDE.

Real constants preserve IEEE bits and signed zero through existing DEFL records;
real operations use existing Dis opcodes. Finite constants remain required, but
operations may produce Inf/NaN. No integer normalization is applied to reals.
Dynamic AS coercion, strings, complete AS/Limbo languages, phi, imports/exports,
full module linking and SBL remain outside this target.

Runtime **0.10.0** adds explicit `--inspect-reals OFFSET COUNT`. It shares the
retained scalar-data lifetime, pointer-map/range validation and failure cleanup
of word inspection. Output is `REAL byte_offset value` with 17 significant
digits. Flags remain native integer 0/1. Views are mutually exclusive; types
come from the chosen FIR, not automatic guessing. A VM/quota failure prints no
partial REAL snapshot. NaN payload identity is not promised.

The [commented AS example and C99 client](../../fir/v1/examples/dis/README.md#binary64-as-source)
ship in the installed SDK. The client defaults to Limbo and optionally accepts
`as3`. Relocated acceptance relinks it against shipped headers/static archives,
byte-compares CLI/API Dis and runs linear Limbo, conditional Limbo and real AS3
examples in both modes. The [bilingual target contract](../../fir/v1/doc/DIS_BACKEND.md)
explains mixed scalar capture cells and separate executed flags.

## Bidirectional Inferno synchronization

New experiment commit `d9ad662` adds retained-module RET leaves on AMD64/ARM64,
return ownership checks and high-register field-load regressions. It was imported
with its full selected regression closure.

The requested Sys/module audit found two groups of confirmed defects, fixed in
**bhgv/Inferno-OS-bhgv experiment** before refreshing our snapshots:

- `9b8d5bd`: Srv rejects nil/H result slots and invalid/maximum Tptr descriptor
  counts before VM allocation or retain. Error paths free native answer vectors
  and restore locks.
- `9c27167`: Loader ifetch/link/tdesc clear their old output owner before
  destruction and use byte copies for unaligned result slots. Nil/H slots fail
  before construction.
- `7f6143d`: regression fixture frames/canary images have stable storage across
  native error unwinds, avoiding stale ASan stack-shadow state in this sandbox.
  No sanitizer was disabled.

All commits use author/committer bhgv. Both selected manifests pin published
`7f6143d6af8be1a9a59669e7a1423a542c85cd88`; 325 core and 174 bootstrap files
are byte-identical to that revision. There are no private vendor-only fixes.

The [per-module audit](../../disVM/libraries/MODULE_AUDIT.md) distinguishes actual
Sys host support from emulator/OS fixtures, and covers Srv, Loader, Math and the
selected Bufio/String/Arg/Readdir/Debug/Dis/Styx/Styxservers boundaries. No new
Sys/Math source defect was confirmed in the checked paths. Full namespace,
/prog debugging and live Styx serving are not inferred from packaged libraries.

signed zero, very small values, overflow, signed division by zero and NaN; raw

pointer-bearing data, quota failure and unsupported dynamic coercion are rejected.
Parent Srv/Loader and a Srv guard-removal probe fail the new regressions as expected.
Core foreign emitters/emulators are not physical ARM64/RISC-V runtime acceptance.
The final core coverage is a full run plus affected/new reruns, not one 100/100 run.
