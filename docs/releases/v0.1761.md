# v0.1761 — point-of-use compiler locality

FIR 0.73 adds a reentrant proof query separating private frame homes from
referenced table allocation identities. Mutable cells, immutable aliases and
captured slots are tracked separately within one block. Opaque operations and
control-flow boundaries invalidate private-object facts.

The first optimizer consumer forwards stored big values into retained numeric
reads of the same private table/key. Explicit leases, stores, allocation and
throwing producers remain. Unleased, relative/text-key, unknown and cross-block
reads use the existing path. No managed layout, wire ID or public Dis64 activation
changes; runtime remains 0.63.0 with serialized managed-heap admission.

[Proof contract](../../fir/v1/doc/LOCALITY.md) and
[commented example](../../fir/v1/examples/tables/private-forwarding/README.md).

Validation covers the FIR suite, sixteen original/optimized table cases using an
independent evaluator and actual C/JIT Dis execution with GC, two quantums,
error preservation, and three semantic removal controls. The pure fact query is
checked with eight concurrent callers. Focused TSan/UBSan builds instrument the
new analysis; UBSan controls instrument the substituted pass. Existing archive
code in those focused builds is not sanitizer-instrumented; these are not
whole-VM sanitizer or parallel managed-heap certification.

Inferno synchronization receives INFERNO-0089 and independently replays its
allocator-alias module-set fixture on the host. Target Android/ARM64/RV64 evidence
remains attributed to Inferno, not claimed as local execution. Vendor snapshots
are unchanged. Remaining parallel-heap work includes full C/JIT owning-reference
and mark conversion, allocator concurrency, graph publication, root/lifetime
boundaries and GC. This compiler step does not remove their safety gates.
