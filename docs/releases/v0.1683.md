FIR 0.63 derives conservative known-zero/known-one masks for immutable int32
literals, copies, AND, OR and XOR. Shared C99 analysis enables ordinary AVM1
checked shifts with dynamic proven counts such as `n & 31`, and signed div/mod
with proven nonzero divisors such as `d | 1`. Copies of literals also work before
optimization. Unknown or potentially invalid operands still reject before output.
The analysis follows dominating definitions even when blocks are not textually
ordered; it infers no mutable-cell contents, float facts or dynamic AS coercions.

DCE uses the same successful-evaluation facts to discard unused total int32
arithmetic and int32-counted big shifts. Each operand producer retains its own
errors and effects. Big division keeps its existing nonzero-literal proof.
Public fir_effects, CSE, reference ownership, grammar and wire formats are unchanged.
CLI, C99 and the Dis-owned IDE compiler worker share this path. The new
[line-commented Limbo example](../../fir/v1/examples/dis/integer-facts.b) returns42
through raw/optimized FIR, SWF8/SWL/FlashVM and NC64 interpreter/JIT.

## Inferno synchronization and semantic tooling

Imported Inferno's published module/type/code helpers and whole pilot42 from
`bd2a523f001b9ed506eae975eb93288ebefe8000`, through handoff460b2db. FlashVM
extended the actual upstream inspector with explicit --pilot semantic checking,
regressions and direct [FLASHVM-0008 coordination](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-flashvm-journal.md).
This upstream contribution is published as
`a1438350780021a3df89c166273583858abcdbe0`, tree
`226a8d589776cbbe56b37645cfbb7d8065fe9c0d`. Both immutable source closures pin it:
856 manifest-hashed DisVM files and 280 explicit legacy bootstrap files.
Audits confirm byte-for-byte source provenance.

The inspector defaults to opaque envelope validation. Opt-in --pilot checks real
metadata, ordinal name/type IDs, complete descriptor maps, scalar code roles,
entry/frame/data references and supported initializer/section policy. Semantic
rejection preserves an existing rewrite destination. It reports scalar_pilot=true,
envelope_only=false and **execution_supported=false**. It does not call a VM.

The fully commented C99 [pilot example](../../disVM/envelope/examples/pilot.c)
builds the independent 180-byte golden exactly through the shared writers.
Standalone/core/host/runtime builds and relocated SDKs include tools, all transitive
headers, sources, fixtures, guides and launcher. Build-menu entry **14** /
`--launch pilot` is built and launched for real; entry13 keeps the opaque demo.
Cross configuration does not run target sample generators; both fixture installer
fallbacks decode checked hex on the build host and were tested without generated
samples. SDK clients and the inspector itself rebuild outside the source tree.
