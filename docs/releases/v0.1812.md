# v0.1812 — rooted pointer-list preparation / runtime0.113

The common transactional constructor stage now lives in `pointer_stage.c`.
The old CONSP entry keeps its serialized behavior and alias/monitor/error rules.
A new internal `pointer_prepare.c` consumes no input hold: it borrows rooted
source/tail identities, builds and links an unpublished node, publishes a reserved
candidate root, then drops its ordinary construction pin. Failure rolls back the
exact recorded owners, including tail linkage followed by root refusal.

[API and commented native worked fixture](../../disVM/runtime/POINTER-PREPARE.md).

The integration test interleaves an actual compliant MOVP writer, rejects a stale
prepared tail, destroys that candidate, refreshes the observed tail and rebuilds
before committing. Only the real rooted container/map keeps the resulting graph
alive after all input/displaced leases and creator owners are released.32 actual
Cycles plus final Fast restore descriptor baselines. Seven refusal boundaries
cover two native reservation allocations, managed allocation, two descriptor
acquisitions, monitor error and candidate-root publication. Three source omissions
must fail with semantic exit10 before unsafe GC. C/JIT denotes surrounding guest
coverage; preparation is still a native C API, not a new compiled opcode.

NativeWorld, ordinary managed allocator/collector exclusion, caller cell mapping,
Type/frame/code lifetime and monitor restrictions remain mandatory. Full parallel
Dis execution is not admitted. No wire/feature/ABI IDs or Dis64 defaults change.
Known extra preparation/stale-retry paths are recorded under PREPARE-113 in the
[performance ledger](../../disVM/runtime/PERFORMANCE-COSTS.md); no matched timing
or IDE speed improvement is claimed.

prerequisite preserving existing ordinal meaning. Its owning repository test is

the immutable default/named profiles. Coordination is recorded in FLASHVM-0130.
