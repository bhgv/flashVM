# v0.1589–v0.1595: our Limbo real compiler and remaining Loader result fixes

Our C99 compiler **0.9.0** adds a homogeneous Limbo `value(): real` profile through
its authoritative Coco/R grammar. Interface/definition types must match; typed
and inferred locals remain real through assignments and lexical scopes. Decimal
fraction/exponent literals, unary signs, + - * / and return lower to explicit f64
FIR, then our SWO/SWF or direct NC64 Dis backend. No Inferno emitter generates our
programs. The full IDE still uses the separate bootstrap path.

The profile rejects integer/radix/hex literals, mixed int/real bindings, casts and
real comparisons/decisions. It does not silently change integer division into
real division. Existing int wrapping/terminal decisions are preserved. Adding
the Limbo type keyword also preserves `real` as an AS1/2/3 variable name.

## Compiler, provenance and SDK

Coco/R ResultType and BindingType select/check the profile. `FIR_LIMBO_REAL` is
appended to FirSemantics without renumbering older values. FIR keeps first line
1.0, with `source_language limbo` / `source_semantics limbo_real`; older readers
need updating to accept this new optional profile. Print/optimization preserve
provenance, and the verifier rejects forged AS/limbo_real pairs.

Source metadata is published only after successful staged parsing. Real/type
errors preserve both caller FIR and debug streams. A C99 test repeats real,
failure, int and AS translations eight times in one process, checking profile
reset, stream retirement and direct Dis generation. FIRDBG1 continues to map
constant/binary values to source origins; no final Dis PC/SBL mapping is implied.

The fully commented [real.b and SDK guide](../../fir/v1/examples/dis/README.md#limbo-real)
show 125.0/2.0−20.0 = 42.5, block-local inferred real and assignment to an outer
binding. The existing C99 client selects type from the grammar, without a new
argument. Installed acceptance relocates the package, relinks that client from
shipped headers/archives, byte-compares CLI/API output and executes four examples
in both modes: linear int, terminal int CFG, numeric AS3 and Limbo real.

Seven supported function bodies are independently checked by binary64 value/bit
oracles and compiled by the Inferno compiler as a reference, then executed on
our runtime in interpreter/JIT modes. Our own raw/optimized Dis is emitted
separately by our own pipeline. Reference programs additionally exercise actual
Sys printing and Math realbits64. Real SWF acceptance executes four source cases
raw/optimized; decimal SWF trace observation is not a NaN-payload or signed-zero
bit oracle.

## Inferno synchronization and returned fix

New experiment `4d9ce2e` adds unique array-view SLICEA reuse in C and guarded
AMD64/ARM64 leaves, plus self-load Module/MP retain preflight. Selected regressions
cover array geometry, owner counts, canaries, aliases and native code staging.
Self-load/import regression closure is explicitly selected and registered too.

Our confirmed follow-up was published as
[`74c1937`](https://github.com/bhgv/Inferno-OS-bhgv/commit/74c193724a7352b8fda2724a5cf10029885be68c)
on **Inferno-OS-bhgv/experiment**, author/committer bhgv:

- `Loader_newmod/dnew` validate output slots, publish H before destroying the old
  owner and byte-copy the newly completed pointer.
- `Loader_tnew/ext/compile` validate output slots before mutation and publish a
  full native WORD through byte copies, preserving existing status values.
- Existing dynamic-loader/failure/retry acceptance now runs in WORD64 and WORD32.
  New explicit checks cover five APIs at eight alignments, live construction-owner
  replacement and ten nil/H cases per model: **100 added cases** total.

Combined ASan/UBSan passes both WORD models. Nil probes use fresh processes,
keeping one native error unwind per process because the sandbox cannot discover
the native stack top reliably. No sanitizer is disabled. The parent implementation
reproduces a UBSan misaligned WORD store. Snapshot regressions remain separate.
This fixes result-slot geometry/publication, not arbitrary frame-pointer safety
or every construction retain/metadata invariant.

Both manifests pin published `74c193724a7352b8fda2724a5cf10029885be68c`.
Core selection contains 335 files, bootstrap 174; verification checks byte identity.
[Current synchronization](../../disVM/SYNC.md),
[module audit](../../disVM/libraries/MODULE_AUDIT.md) and the
[upstream result contract](../../disVM/upstream/libinterp/tests/README.loader-results.md)

## Dynamic any status

[The status note](../../fir/v1/doc/DYNAMIC_VALUES.md) distinguishes FIR T_ANY,
Inferno's internal Tany and future Flash-compatible dynamic values in Limbo.
No such Limbo implementation is advertised. An ADT/pick and tag+union approach
is described as a proposal requiring constructors, conversions, GC ownership and
a versioned cross-VM value/capability format; raw heap pointers remain separate.
