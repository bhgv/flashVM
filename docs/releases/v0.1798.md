# v0.1798 — TSan-visible native error transfers

Runtime0.100 fixes the cumulative actual-C-fixture TSan failure left open in
v0.1797. On this GCC13/glibc build, fortified siglongjmp calls __longjmp_chk;
the installed TSan intercepts siglongjmp/longjmp, not __longjmp_chk. Repeated
errors bypassed sanitizer stack reset and eventually caused its nested SEGV.
A private same-object experiment replacing only that transfer symbol passed the
unchanged complete fixture in C and JIT. This isolates the observed failure;
it does not classify unrelated sanitizer faults as environmental.

POSIX transfer is separated into native_jump.c/h. Only when GCC/Clang selects
thread sanitizer does this small translation unit disable _FORTIFY_SOURCE so
the actual siglongjmp interceptor observes the transfer. All other translation
units and ordinary builds retain their fortification. Actual normal console/
editor objects use __longjmp_chk; TSan uses siglongjmp. No instrumentation or
native guard/cleanup checking is suppressed. The retained upstream is unchanged.

nexterror still unwinds newer native scopes and consumes the current owner's
Proc label before transfer. Same-thread live continuations and nonzero status
remain mandatory; saved signal masks restore. No thread migration, cross-owner
jump, scheduling, allocation, root or managed admission permission is introduced.
The added wrapper is on the error path; no normal-execution speedup is claimed.
Previous performance measurements remain untouched.

The new native fixture runs four joined OS owners through 96000 nested transfers,
checking independent statuses and both saved SIGUSR1 masks. Two independent
semantic controls corrupt status or omit saved-mask capture; both must exit10
with the expected diagnostic, rather than crash or fail compilation. Normal and
real TSan runs pass; glibc symbol-selection checks distinguish the ordinary and
sanitizer paths. This native fixture does not instantiate a Dis managed heap.

The full actual eight-shift fixture now passes TSan:99000 mixed-width/value/alias
cases, including45000 invalid counts, without sharding or dropping cases; C/JIT
and both poll modes pass. The six real guest-tail/cache suite, twelve invalid-
count guest suite, actual24-op arithmetic fixture with1404000 cases and six zero-
divide guest suite also pass TSan. Generated machine code is uninstrumented.
45 distinct affected CTests have passing final results:31 in the initial selection,
the cleanup fixture rerun after adding its actual new source/header dependency,
and13 additional prior gates. The initial cleanup compile/link failure was not
counted as semantic evidence. Cleanup also passes real TSan for native/locked
backends:each eight OS owners,640 nested transfers,960 native frees and all ten
semantic omission controls. Installed SDK source/test closure matches bytewise;
the example passes ordinary C/guarded C/guarded JIT. Vendor checks pass1096/312
files at ba26acc. No whole-suite repeat or aggregate timing is inferred from
these separate runs.
No new hosted UBSan or physical ARM64/RV64 acceptance is inferred.
