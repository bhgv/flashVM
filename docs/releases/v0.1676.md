# v0.1676 — Новая IDE в конечном build-menu и свежий ALT Inferno

[Точки запуска / Entry points](../../ide/ENTRYPOINTS.md) · [Предыдущая серия](v0.1675.md)

Новые возможности не показывались при привычном запуске из build-menu: они уже
собирались в desktop-ide.dis, но пункт 8 всё ещё выбирал run-ide.sh, отдельный старый
редактор. Новый run-desktop-ide.sh не входил в обнаружение продуктов. Дополнительно
отсутствующий общий run-checks.sh полностью скрывал меню запуска. Это был пропуск
интеграции точек входа, не отсутствие MovieClip/Dis реализации.

Теперь пункт 8 запускает настоящий MovieClip-стол, пункт 9 сохраняет прежний
одиночный редактор, 10/11 запускают переносимые lifecycle/pointer примеры.
Интерактивный и CLI итог сборки показывают фактически установленные команды;
checker не является зависимостью приложения. Старый SDK без нового launcher
получает явное сообщение о пересборке, а не незаметный переход в старый редактор.

Добавлено `--launch desktop|editor|lifecycle|pointer`, для графических приложений —
`--document` с отдельным argv. Неверные сочетания с --no-install или не-графическим
--document отвергаются до сборки. Шрифт поставляется, вопрос о его пути не возникает.
Сообщения menu/Bash больше не объявляют весь встроенный Dis-хост незавершённым:
компонент ide — библиотечный, приложения находятся в disvm-runtime/disvm-editor.

SDK содержит run-desktop-lifecycle.sh, run-desktop-pointer.sh и ENTRYPOINTS.md.
Установка проверяет обязательные desktop .dis и отвергает неполную сборку вместо
тихой поставки пустого пункта. Native launcher и приложения не требуют Python.
Существующие раздельные единичный редактор/экспорт/отладочные сервисы сохраняются;
прикреплённая Run/Debug-сессия в новом столе этим не заявляется.

Проверки:

- **27** тестов build-menu, включая CLI, отсутствие checker, старый SDK,
  literal UTF-8/символьные пути, код возврата и валидацию аргументов.
- **5** preflight и **7** frontend-package проверок.
- Настоящая новая сборка через build-menu.py в отдельные build/menu1676 и
  out/menu-sdk, с автоматическими AS2/FIR/SWL зависимостями и --launch pointer.
  Пример действительно исполняется на собранной VM и возвращает PASS.
- Настоящий установленный desktop запускается через выбор 8 и CLI dispatcher
  в interpreter/JIT, вне дерева сборки и без checker. Проверяются два независимых
  MovieClip-документа, сохранение файла и реальный raster. Только replay-аргументы
  добавлены тестом после формирования настоящего argv; GUI/VM не подменены mock.
- Первый импорт ALT: core **218/218**, runtime **245/245**.
- Итоговый импорт a67032e: полный core **221/221**, runtime **245/245**;
  отдельно зарегистрированы UBSan/NDEBUG матрицы unwind/return/extent.
  Повторная сборка через меню, запуски 8/CLI и установленный SDK тоже проходят.
- Установленные editor/runtime SDK повторно проходят компиляцию, C99-перелинковку,
  interpreter/JIT и публичные launcher-скрипты; редактор проверяется настоящим replay.

Итоговый источник Inferno experiment — a67032e0136219becf692a59ab641b3f2c8bea11.
60837e4 проверяет guard ALT до регистрации, 95df086 исправляет отмену заблокированного
ALT при финализации с уже опустевшими очередями. Последний a67032e сохраняет курсоры
владения unwind и возобновлённое состояние RET/extent через деструкторы, временно
заимствующие REG. Выбраны 804 Dis + 277 bootstrap, 961 уникальный исходник сверены
с Git blob/SHA-256. Нового общего дефекта для обратной отправки не найдено;
специфичные меню/SDK правки оставлены в flashVM.

Для физического окна нужен SDL2-enabled host. Свежая автоматическая приёмка
использовала явный --no-player и настоящий headless FlashVM replay; она не является
физическим touch/SDL тестом и не доказывает нативное исполнение других CPU/OS.
