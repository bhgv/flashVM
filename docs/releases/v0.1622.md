## Executed implementation

The independent C99 core in common/table stores exact int64/big values in a dense region plus sparse numeric/string hash entries. Strings are copied with explicit byte lengths. Sequence length is the first absent nonnegative index; all-pair count is separate. Deletion leaves holes. Checked half-open slices produce independent zero-based tables. Key snapshots sort numeric keys and retain string insertion order; their copied bytes outlive the original owner. An injectable allocator provides failure rollback and leak accounting.

The hosted Bigtable builtin registers generated typed ABI exports in both native disvm and disvm-editor. Private Dis heap owners finalize the C table/key snapshots; no VM references or pointers cross heaps. A fabricated public Handle/Keys ADT is rejected by its private descriptor. Calls execute at the current sequential scheduler owner; this is not a network or concurrent-sharing service. Runtime version is 0.14.0.

## Compiler boundary

The authoritative Coco/R Limbo syntax frontend now accepts table of T, table creation and keysof. Existing dotted/index/slice syntax is accepted. This does not implement semantic resolution of t.k as a table string key or lowering of table operations into FIR/Dis/SWF. The executable example deliberately uses explicit Bigtable module calls compiled by the matching temporary bootstrap. keyseq language syntax, pair iteration, typeof/any, arbitrary values/reference keys, AS adapter and compiler-generated calls remain pending. No new Dis opcode/container ABI or Inferno language extension is introduced.
