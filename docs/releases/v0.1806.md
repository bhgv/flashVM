# v0.1806 — atomic root-group replacement / runtime0.107

A preallocated active root reservation can now replace its complete multiset in
one actual registry-mutex interval. Locked visitors observe either whole old or
whole new groups. Sparse slots, duplicate keys, new vector indices and an active
empty group are supported; all input validation precedes mutation. Replacement
allocates/frees nothing and reads no payload, invokes no owner/GC callback and
does no retain/release. The opaque metadata layout is unchanged.

[Contract, lifetime restrictions and evidence](../../disVM/runtime/ROOT-REPLACEMENT.md).
[Fully commented C89/C++98 client](../../disVM/examples/root-group-replace/README.md).

Each batch has one externally exclusive owner; different batches can update on
independent OS threads. Quiescent handoff is allowed. Old/new referents remain
independently live, new roots inherit publication lifetime and old retirement
still needs collector-lifetime exclusion. This API closes registry visibility
gaps only: it supplies neither a collector snapshot lease nor graph epochs,
strong ownership, pointer provenance or permission to remove NativeWorld.

Actual registry/ports tests run native and forced-lock backends. Eight OS
publishers perform16000 transitions per backend with a coherent locked scanner;
a midpoint rendezvous requires a full visit after8000 and before the remaining
8000. Exact lock/unlock and allocator wrappers verify one interval/no allocation.
Ordinary independent roots survive, batch occurrences resist ordinary removal,
and invalid vectors preserve sparse old groups. Six exact-stage source omissions
per backend detect exclusion, withdrawal, publication, validation, index and
allocation defects; compiler/resource/crash/sanitizer failures never count.

The hosted fixture uses real String/Heap/Type roots: each newly allocated owner
is pinned before subsequent managed allocations. Replacement runs with actual
source/destination cell guards held; ordinary pins are then removed and only
new batch roots remain across32 real Cycles. Payloads survive, new indices work,
empty/clear/destroy balances and final Fast restores the Type baseline. Omitted
replacement fails before collection, refusal preserves old roots/owners.
Surrounding C/JIT guests and both collector polls pass. This is native C API
evidence, not a new compiled Limbo root instruction or concurrent graph GC.

TSan positives pass both native backends and hosted C paths/both polls. It does
not instrument machine-code guest instructions; physical ARM64/RV64 and full GUI
