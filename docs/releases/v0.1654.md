# v0.1654 — our Limbo native C interfaces and module tutorial

## English

Our Coco/R Limbo compiler now generates actual native C interfaces from `.m`:
`limbo_bindings --format native-c-nc64|native-c-classic32`. The new backend uses
the existing owned catalog, not another parser and not a bootstrap subprocess.
It emits callback declarations, frames with explicit padding, structural MD5
signatures, descriptor extents, GC pointer maps and compile-time layout checks.
A library API is exported through `limbo_interfaces`. The earlier `--format c`
external-call scaffold and its FNV descriptor identity remain separate.

The first native profile supports direct byte/int/big/real/string arguments,
scalar/void results, one module and bounded exports/parameters. Composite types,
aliases/imports, self, polymorphism, varargs and raises-qualified signatures fail
before output opening. It does not yet replace complex Sys/ADT native headers.
[Generator and contracts](../../compiler/limbo/frontend/NATIVE_C.md).

A runnable optional `$Nativedemo` is built using **our generated header**. Its C,
`.m` and Limbo sources comment every nonblank code line. It demonstrates exact big
wrap without C signed overflow, managed string returns, a caught native error,
Limbo channel request/reply ownership and acknowledged shutdown. The matched
bootstrap still compiles the Limbo client; executable source compilation keeps
the existing FIR/target/linker architecture. Generating C ABI metadata from `.m`
is interface generation, not a bypass of the executable FIR pipeline.
[Tutorial](../../disVM/examples/native-module/README.md) ·
[ABI/GC/threading guide](../../disVM/runtime/NATIVE_MODULES.md).

The architecture is explicit: direct DisVM → typed channels → Flash-content
control stays available. AS is used for complex presentation, C for native
extensions such as colorizers and raster primitives. One live AS context remains
owned/serialized; immutable independent render jobs can run in parallel. AS is
not required as an extra relay for every display property. The existing host
render-job primitive is linked in the guide, with its actual limits.
[Ownership contract](../../ide/RENDER_OWNERS.md).

The separately requested `bhgv/inferno-os_gfx-engn` renderer was repaired in its
own repository, without importing its GUI into our Dis core. It now validates
packed shape streams, uses synchronized completion records and bounded leaf
batches, serializes shared text/dependent work, retires terminal flags, handles
frame resize/stride, exact PNG reads and a touch-array retain defect. Its own
RU/EN report lists remaining stable-graph/scratch/polling/platform limits.

## Русский

Наш Limbo/Coco/R теперь генерирует настоящий нативный C-интерфейс по `.m`:
`limbo_bindings --format native-c-nc64|native-c-classic32`. Используется прежний
каталог Coco/R, без нового ручного парсера и без запуска bootstrap. Генерируются
прототипы, кадры с явным выравниванием, структурные MD5-сигнатуры, размеры,
карты GC и проверки C-разметки. Доступен библиотечный API `limbo_interfaces`.
Прежний C-scaffold внешнего вызова и его FNV ID не выдаются за этот ABI.
[Контракты генератора](../../compiler/limbo/frontend/NATIVE_C.ru.md).

Первая цель поддерживает прямые byte/int/big/real/string, скалярный/void результат,
один модуль и ограниченное число функций/параметров. Составные типы, алиасы,
импорты, self, полиморфизм, varargs и raises отвергаются до открытия выхода.
Сложные Sys/ADT-заголовки этим пока не заменяются.

Работающий опциональный `$Nativedemo` собран **с нашим заголовком**. Каждая
непустая строка C, `.m` и Limbo прокомментирована. Показаны точное wrap big,
возврат строки под владением Dis, перехваченная C-ошибка, канальная обёртка и
подтверждённая остановка. Bootstrap пока собирает клиента Limbo. Генерация
C-метаданных из `.m` не заменяет тракт исполняемого кода через FIR/целевой
backend/линкер. [Пример](../../disVM/examples/native-module/README.ru.md) ·
[Руководство ABI/GC/потоки](../../disVM/runtime/NATIVE_MODULES.ru.md).

Прямой канальный путь DisVM → Flash-контент сохранён. AS берёт сложное
представление, C — расширения/вычислительные и OS-примитивы. Изменяемый AS-контекст
имеет одного владельца, независимый растр может выполняться параллельно по
неизменяемым заданиям. AS не является обязательным посредником каждой команды.
[Контракт владения](../../ide/RENDER_OWNERS.ru.md).

Экспериментальный renderer `bhgv/inferno-os_gfx-engn` исправлен в своей
репозитории: границы/выравнивание команд, публикация завершения, ограничение
порций, shared text, терминальные флаги, resize/stride, PNG-чтение и retain
нативных touch-данных. GUI в DisVM не импортировался. Ограничения неизменяемого
графа, scratch-canvas, polling и платформ отдельно описаны в RU/EN отчётах.
