# v0.1740 — terminal cleanup of prepared native call frames

Runtime 0.47.1 imports Inferno checkpoint 0070 at
93f173822247aac803b25f710268bd9223f70bcd. FRAME can already own mapped arguments
before CALL publishes FP. The previous terminal destroystack followed the active
chain and skipped these prepared owners, including pending gaps below an active
argument helper or an unentered stack extension.

The owning fix validates allocated suffixes using captured per-extent SP/TS,
links pending frames for ordinary mapped cleanup and captures parent/type/module
cursors before callbacks. There is no allocation, REG layout, opcode or shared
file ABI change. This repairs terminal destruction; it does not prove arbitrary
language-handler recovery/resumption.

Independent Linux x64 strict-UBSan execution passes 448 trusted C/RX cases in
EACH WORD model (896 total), plus four semantic leaked-owner removal controls.
The fixture uses actual FRAME/MOVP/CALL/RET/decoder/xec bodies, with the documented
bounded allocation/OS boundary. It is not shared Dis64 file-call admission.
Existing stack-unwind/lifecycle, native RET and MCALL/RET matrices pass in WORD32
and WORD64. All 16 runtime/GC/FIFO/I/O/file-service gates pass after the import.
Trusted local-call matrices and their controls are now explicit runtime CTests,
using only the selected DisVM sources and its own POSIX header adapter.

The DisVM manifest selects 1077 files; the compiler bootstrap keeps its existing
309-file selection at the same owning revision. No direct snapshot edits or
unrelated owning OS import. Dis64's source specialization and 43-op np0 file
profile remain unchanged. Local native result addresses are eight bytes, whereas
ordinary WORD32 LEA is four bytes: typed frame/result-address slots remain a
shared calling-contract proposal, not a reason to widen LEA or serialize pointers.

The v0.1739 FIFO gate remains enabled for the GC-worker runtime. The managed
scheduler still has one executor; this fix does not make shared-heap spawn or
concurrent marking complete. Inferno agrees that queue/channel/RC/module-cache
mutation must remain under the same exclusion until separately audited.
