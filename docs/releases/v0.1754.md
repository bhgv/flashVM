# v0.1754 — native close worker and GC finalizer ownership

Runtime0.58.0 adds a dedicated native close worker when --gc-worker is selected.
Previously a GC finalizer could hold the common heap while fclose/closedir blocked,
even though GC itself ran on another OS thread. The finalizer now retires the
per-descriptor FIFO gate, detaches the native handle and transfers a prepared
native job. It neither allocates a queue node nor waits for filesystem close.
The worker never reads managed objects, descriptor tables, REG, TLS or VM roots.

Every file/directory construction reserves its close job BEFORE native creation;
allocation failure therefore cannot truncate a file and later lose retirement
storage. Failed construction frees its unused job. Once all pinned operations
finish, kclose removes handles/job from the table before publishing exclusive
ownership. A reused descriptor slot cannot alias the old handle being closed.
The worker consumes jobs in FIFO order under a native mutex/condition, releasing
the mutex during actual close. No callback enters the VM. Reference --gc-inline
and pre-worker loader startup retain inline close. Native port close continues
to have its existing void/error contract, with no new durability promise.

Shutdown joins managed executors, completes collector/RC retirement, then drains
and joins the native closer before terminal statistics. NATIVECLOSE reports
submitted/completed/pending/peak and joined state. Close-worker startup failure
uses existing error cleanup: every already-created executor/collector still joins.
The native-creation failure test covers that extra ordinal as well as partial
managed startup. The worker is not included in --managed-workers executor counts.

Native handles can remain physically open after their logical descriptor slot
is released. The queue uses jobs allocated before open; native resource pressure
still makes later opens fail, rather than promising unlimited buffered retirement.
There is no forced I/O cancellation, close timeout or successful shutdown claim
for a permanently stuck OS close. The largest remaining multithreading block is
still parallel mutation of the shared managed heap, with RC/GC/allocator barriers.

The real native barrier fixture now covers nine phases. It pauses actual fclose
and closedir after finalizer transfer while another actor creates a competing
UTF-8 file and computes/prints. Driver permits are sent ONLY after that progress.
The existing open/create/metadata phases remain. Final gate retirement and equal
submitted/completed with pending0/joined1 are required. Console and graphical
hosts run C/JIT with4/8 executors. This is local native Linux x64 evidence, not
whole-VM race freedom or a new ARM/RV hosted runtime acceptance.

Validation:29/29 selected runtime regressions pass, including partial startup
failure at the closer's creation ordinal, native I/O, fixed/elastic pools and
nine-phase barriers. The installed graphical product passes all nine phases in
C/JIT with4/8 executors. The actual instrumented Debug INTERPRETER passes the same
nine barriers with4/8 under TSan; its driver is explicitly restricted to no-JIT.
This is focused ownership/race evidence, not whole-VM/JIT/UI certification. Private
header C++98 syntax, Python/shell checks, whitespace and both unchanged vendor
manifests pass. The new native closer is hosted adapter code, not an upstream
Inferno body or new Dis64 executable file profile.
