# v0.1627 — checked snapshot keys through our compiler and DisVM

This series follows the compiler/VM/IDE scope. Inferno was checked first: fd2b92d
adds raw/mapped channel JITs after our TCMP repair. Those architecture-specific
changes are not imported here. Both manifests remain verified at the already
published 875d122 snapshot (453 core/reference and 174 bootstrap files). No
Limbo table extension is exported upstream.

Our Coco/R Limbo frontend now lowers `keys[i]` and `t[keys[i]]` reads/writes into
typed FIR and native Dis. FIR appends `table.key` and `keys.at` without renumbering
existing enum IDs. A key retains an immutable snapshot and a checked big position;
no native address or converted string is used as a key identity. Numeric 1 and
text "1" stay distinct. Bounds are checked eagerly even for unused keys and stay
observable after optimization, including indices above the 32-bit range.

The NC64 emitter uses existing Dis instructions and signature-checked Bigtable
helpers. Keys occupy two cells; locations using them occupy three cells and root
both owners. Copies preserve each exact layout. getkey/setkey borrow the snapshot
for the call and preserve embedded-zero key bytes without a String conversion.
No additional key owner is allocated. Successful frame teardown leaves zero native
table/snapshot owners. Compiler version is 0.13.0; matching runtime is 0.16.0.
