# v0.1759 — native scope cleanup before error transfer

Runtime 0.62.0 captures owner-local cleanup generations alongside actual Proc
error labels. On a hosted native error, newer owner scopes close BEFORE longjmp,
while caller-provided scope/entry storage remains live. Nested catches preserve
older scopes; rethrows clean the next generation. Setjmp remains in its caller.

Normal pop refuses leaked newer scopes instead of walking returned stack frames.
Cleanup blocks new registration, nested error push and TLS detach; held object
guards refuse unwind. Callback failure is fatal, possibly after partial cleanup.
No arbitrary OS cancellation or automatic object-lock unwinding is introduced.

Scope/extended-up native metadata grows and requires matching rebuilt clients.
Retained Proc prefix, REG layout, Heap/Type/Jit and file IDs remain unchanged.
No managed roots, managed process-scope drops, local/shared compiler analysis or
parallel managed-heap admission are enabled by this native-only cleanup step.

See [protocol and validation](../../disVM/runtime/NATIVE-UNWIND.md).

Validation on native Linux x64: eight OS owners, 640 nested transfers and 960
actual native message frees per backend. Native/forced-lock backends and ten
semantic removal controls pass normal, optimized nonrecovering UBSan and focused
TSan. Thirteen affected runtime gates pass; native owner/world/REG and ownership
controls pass. The instrumented Debug interpreter also passes helper-RC and
hosted exception workloads under TSan. Independent CMake and installed SDK
examples/drivers plus strict C89/C++98 headers pass. Vendor snapshots stay pinned.
No whole-VM/JIT/ARM/RV race or managed parallel-heap certification is inferred.
