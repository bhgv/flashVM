# Нативные расширения FlashVM и DisVM

Интерфейсы C-расширений уже существуют. Для FlashVM используем регистрацию
`fvm_register_function_rooted`, методы `fvm_object_define_method_rooted` и
аксессоры `fvm_object_define_accessor_rooted`. Есть также стековый Lua-подобный API.
Для Limbo/Dis — объявления `.m`, сгенерированные сигнатуры, кадры и карты корней
соответствующего профиля. Кучи двух VM остаются раздельными; через мост передаются
проверенные значения/возможности, не адреса объектов другой кучи.

Начните с [существующих примеров FlashVM](../flashVM/examples/extending/README.md),
[отдельно компилируемого C-модуля](../flashVM/examples/embedding/native_module/README.md)
и [модулей Limbo/Dis](../disVM/runtime/NATIVE_MODULES.ru.md).
[Таблица точек расширения](NATIVE-EXTENSIONS.md) связывает примеры с API.

Нативное состояние и машинный код callback должны жить до уничтожения контекстов,
которые могут удерживать callback. `void *` сам по себе не корень GC; управляемые
захваты регистрируются явно. Неопубликованный namespace временно закрепляется
до публикации. Аргументы проверяются до изменения состояния; ошибки возвращаются
явно. Пример проверяет настоящую сборку мусора, отказ чужому контексту и исполнение
setter из скомпилированного SWF.

Автоматического протокола поиска/загрузки/выгрузки `.so`/`.dll` эти примеры не
добавляют. Удаление глобального свойства не доказывает исчезновения всех ссылок.
Операции с объектами VM выполняет поток владельца контекста. Фоновые нативные
работы получают копии значений и возвращают результаты через очереди/каналы.

В IDE `ideDraw` даёт общие операции рисования из AS, а оформление остаётся в AS
и поведение в Limbo: [контролы рабочего стола](../ide/dis/DESKTOP-CONTROLS.ru.md).
Примеры classic32/NC64 не подменяют экспериментальный Frame64/map8; согласованный
внутренний typed-tail пока не включает исполнение вариадических функций.
