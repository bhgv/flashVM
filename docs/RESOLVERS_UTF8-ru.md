# Условия IF в C и байтовые строки UTF-8

Перевод [RESOLVERS_UTF8.md](RESOLVERS_UTF8.md). Оригинал сохранён.

## Сборка и проверки

```sh
make -C sources -f unix.mk
python3 tests/regression.py
```

Для генерации требуется только C. Python 3 нужен программе регрессионных
проверок, но не Coco/R или сгенерированным программам. Чтобы получить исправления
сканера, существующие парсеры следует заново сгенерировать с обновлёнными C-шаблонами.

<a id="if-resolvers"></a>
## Условия IF

Условие, или resolver, записывается как `IF(C-expression)` в начале альтернативы,
опции или повторения. Оно имеет нулевую ширину: проверяет выражение, не потребляя вход.

```text
( IF(condition) A | B )
[ IF(condition) A ]
{ IF(condition) A }
```

Первая форма создаёт `if (condition)` для A. Для B остаётся обычное предсказание
по токену предпросмотра: как правило, `else if (FIRST/FOLLOW-test)`, а не
безусловный `else`. У следующих альтернатив тоже могут быть свои начальные IF.
`[]` создаёт `if`, а `{}` — `while` с повторной проверкой перед каждой итерацией.
Обычные скобки группируют выражения грамматики, квадратные делают их необязательными,
фигурные повторяют; IF не меняет эти значения.

Условие заменяет обычную проверку токена, а не дополняет её. Если нужен контроль
предпросмотра, включите его в выражение явно. Выражения могут содержать вложенные
скобки, символьные и строковые литералы, комментарии. Исходные байты копируются в C.
Coco/R проверяет баланс скобок и положение IF, а C-компилятор — синтаксис, имена
и типы выражения. Пустое условие и IF после потреблённого символа или семантического
действия считаются ошибками. Отдельное правило `Rule = IF(condition) A .`
отклоняется: в нём нет точки выбора. Для условной необязательной части используйте
`[ IF(condition) A ]`.

IF разрешает конкретный конфликт предсказания. Множества FIRST/FOLLOW остаются,
как и диагностика обычных неоднозначностей без IF. Альтернатива без условия,
стоящая раньше альтернативы с IF, может скрыть последнюю: порядок существенен.
Избегайте побочных эффектов в условиях, если повторное выполнение не задумано
специально. Повторение должно потреблять вход или менять состояние так, чтобы
условие в конце концов стало ложным; генератор не гарантирует завершение цикла.

<a id="lookahead-and-consumption"></a>
### Предпросмотр и потребление входа

`Sym` в сгенерированном парсере — вид текущего токена предпросмотра. Константы
токенов записываются в заголовок `*c.h`. IF не вызывает `Get()`. Терминалы
в выбранной через IF ветви продолжают вызывать `Expect()`, если их вид ещё
не установлен реальной проверкой токена. Поэтому истинное условие при неверном
токене приводит к синтаксической ошибке, а не к принятию произвольного входа.

См. [пример с комментариями и инструкцией сборки](../samples/resolvers/README-ru.md).

<a id="utf-8-contract"></a>
## Гарантии и ограничения UTF-8

Реализация остаётся **8-битным байтовым сканером** с таблицей переходов на
256 элементов. Она сохраняет и сопоставляет последовательности байтов UTF-8,
но не декодирует скалярные значения Unicode.

Поддерживаются и проверяются регрессионными тестами:

- Точные русские и китайские литералы, emoji и литералы с общим префиксом.
- Ключевые слова UTF-8, распознаваемые внутри более общего токена через `CheckLiteral`.
- Точное получение байтов токена через `S_GetString`/`LexString`.
- BOM UTF-8 в начале грамматики или входа сгенерированного сканера.
- Беззнаковая обработка старших байтов в множествах при знаковом и беззнаковом C `char`.
- ASCII `IGNORE CASE` без изменения старших байтов UTF-8.

Существенные ограничения:

- `CHR(0)..CHR(255)` и `CHARACTERS` описывают **байты**. `"中文"` в правиле
  парсера сопоставляется с полной последовательностью; в `CHARACTERS` это
  множество отдельных байтов кодировки, а не двух Unicode-символов. Токен
  из произвольных старших байтов не проверяет UTF-8 и может принять некорректную
  последовательность. Для Unicode-идентификаторов нужны явные байтовые шаблоны
  UTF-8 либо отдельная архитектура сканера с декодированием.
- Идентификаторы самой грамматики остаются ASCII. Нет Unicode-преобразования
  регистра, нормализации, классов свойств Unicode и диапазонов кодовых точек.
- Позиции, длины и столбцы считаются в байтах с прежним учётом табуляции,
  а не в Unicode-символах или экранных ячейках. BOM занимает три исходных байта.
- Имена таблицы символов, включая литералы правил вместе с кавычками,
  сохраняют исторический предел 31 байт. Общий текст в кавычках, например
  строка множества символов, ограничен 99 байтами. Превышение теперь даёт E132,
  а не незаметное обрезание имени или UTF-8. Для длинной точной последовательности
  используйте именованный токен из нескольких более коротких строковых факторов.
- NUL остаётся признаком EOF; встроенный NUL во входе не поддерживается.
- Сохраняйте грамматику и вход в UTF-8. Компилятор C должен сохранять UTF-8
  в кодировках исходного текста и исполнения, как проверенные настройки GCC.

## Владение буфером сканера

`S_Reset(text, text_len)` при `CUSTOM_BUFF` копирует ровно `text_len` байтов
в собственную память и дописывает EOF там. Буфер вызывающего кода может быть
доступен только для чтения или иметь ровно указанную длину: запасной байт
не требуется. После reset вызывающий код может освободить свой буфер.
Следующий reset заменяет внутреннюю копию. `NULL, 0` означает пустой вход;
отрицательная длина и `NULL` с положительной длиной завершают программу
с диагностикой. Текущая внутренняя копия живёт до следующего reset или завершения
процесса. Это не потоковый API; глобальное состояние сканера не реентерабельно.

`S_CurrentCh` возвращает EOF для позиции вне входа. `S_GetString` и `S_GetName`
останавливаются на его границе; `max` не включает завершающий NUL, поэтому
вызывающий код предоставляет `max + 1` байтов. Ограничение по байтам может
разрезать UTF-8-последовательность: подходящие границы выбирает вызывающий код.
`S_GetName` меняет регистр только ASCII и только при `IGNORE CASE`.
Повторное чтение EOF безопасно.

Изменён и проверен путь линейного буфера, используемый Unix и современными
Windows-сборками. Исторический сегментированный путь MS-DOS не проверялся;
`CUSTOM_BUFF` явно требует сборки с линейным буфером.

## Исправления и проверка

Прежняя коллекция при росте копировала записи, теряя старое выделение памяти,
но сохранённые указатели продолжали ссылаться на старые записи. Теперь адреса
записей стабильны: перемещается только таблица указателей. Изменения через
сохранённый указатель больше не теряются при росте. Отрицательные индексы
и индекс сразу после последней живой записи отвергаются; рост из callback
сохраняет число итераций, определённое при входе. `Clean` повторно использует
память, `New` обнуляет повторно выдаваемую запись, а `Done` освобождает таблицу
и записи, но не выделения, на которые ссылаются поля внутри записей.

Также исправлены знаковые байтовые индексы множеств, диспетчеризация литералов
вне ASCII, уникальность генерируемых имён длинных экранированных UTF-8-литералов,
буферы экранирования ключевых слов, границы отступов шаблона, длинные строки
семантического кода, границы EOF, владение памятью при повторном reset
и неполное чтение файлов. Это целевая проверка, а не доказательство отсутствия
ошибок во всех исторических путях исполнения.

`tests/regression.py` компилирует и запускает сгенерированный C-код. Он проверяет
запасные ветви, неверные токены, вложенные условия, опции, повторения, неверные
условия и расположение IF, UTF-8, длинные действия, буферы и неподвижную точку
самогенерации через два поколения. `tests/collection.c` проверяет 10 000 записей,
рост из callback, стабильные указатели и повторное использование памяти.
Из 16 встроенных грамматик-примеров успешно генерируются 13. `c.atg`,
`pascal.atg` и `umbriel1.atg` не проходили уже на исходной версии и остаются
явно ожидаемыми отказами; их отдельные ошибки грамматик не изменялись.

Запуск санитайзеров на GCC/Linux:

```sh
make -C sources -f unix.mk new CFLAGS='-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie -no-pie'
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 TEST_CFLAGS='-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie -no-pie' python3 tests/regression.py
```

Проверка утечек отключена для этого теста полного процесса, поскольку старый
генератор хранит вложенные выделения графов/множеств до завершения процесса.
Этот запуск проверяет обращения к памяти и неопределённое поведение, но
не доказывает отсутствия утечек.

## Кратко по-русски

Добавлен IF из модели Coco/R C++: условия в начале альтернатив, опций и
повторений генерируют C `if`/`while`. Условие заменяет предсказание по токену;
последующая ветвь без IF всё ещё проверяется по FIRST/FOLLOW. Условия не читают
вход, а проверка ожидаемых терминалов сохраняется.

Нелатинские строки UTF-8 распознаются побайтово, включая ключевые слова внутри
общего токена. Это не полноценный Unicode-сканер: классы, длины и позиции
остаются байтовыми; нормализации и Unicode-регистра нет. Исторический лимит
имён/литералов — 31 байт вместе с кавычками — теперь проверяется явно, а не
обрезает строку незаметно. Для длинной последовательности используйте именованный
токен из нескольких коротких строковых факторов.
