# Каталог Coco/R для контекста, поиска и лексических кандидатов

[English](TOKEN-QUERIES.md) · [Ленивый анализ](SYNTAX-LAZY.ru.md) ·
[Исполняемый пример](dis/examples/token-query/README.ru.md) · [Запуск](ENTRYPOINTS.md)

[Idetokenquery](dis/bridge/idetokenquery.m) — чистая библиотека Limbo над тем же
готовым [каталогом](dis/bridge/idesyntax.m), что используется подсветкой.
[Реализация](dis/bridge/idetokenquery.b) не запускает сканер, не читает файл,
не меняет документ/выделение/Undo и не обращается к объектам FlashVM. Один
каталог обслуживает много запросов. Это библиотечные API и консольный пример;
семантический popup автодополнений к редактору пока не подключён. Ввод каждого
символа не вызывает эти функции.

Передаются каталог, точный снимок исходника, ожидаемые revision и профиль.
Каждый вызов проверяет квоту, классы0..5, непрерывные упорядоченные полуоткрытые
диапазоны скаляров, счётчики и restart. Исходник должен иметь нужную длину и
содержать скаляры Unicode; counted NUL допустим. Совпадение содержимого другого
текста той же длины не удостоверяется: точный снимок предоставляет владелец.
Позиции — скаляры, не байты, UTF-16 AS или пиксели.

Аргументы заимствованы на время синхронного вызова; изменения сериализует
вызывающий. Нет удержания данных, callback, каналов или нативных указателей.
Контекст возвращает токен-значение, кандидаты — новый массив строк с обычной
value-семантикой Limbo. Изменение массива кандидатов не портит другой запрос.
Сам анализатор отдельно защищает базу копиями результатов/Snapshot.

| API | Поведение |
| --- | --- |
| `at(catalog, revision, language, position)` | Покрывающий скаляр токен; на EOF не придумывается предыдущий токен |
| `find(catalog, revision, language, source, needle, first, kinds)` | Первое точное регистрозависимое совпадение от first, без wrap/изменения выделения |
| `complete(catalog, revision, language, source, prefix, limit)` | Отсортированные уникальные написания идентификаторов с префиксом; только лексические кандидаты |

Статусы: Ok0; Invalid1 — неверные данные/границы/ресурсы; Conflict2 — stale
revision/профиль или неготовый/ошибочный каталог; NotFound3 — нет токена/совпадения.
При неуспехе контекст имеет kind=-1, поиск — координаты -1/-1. Пустые кандидаты
могут быть успешным результатом.

Поиск использует KMP и линейный проход скаляров. Needle —1..256 скаляров,
first —0..длина. Бит k маски1..63 допускает класс k; Names=2 — имена,
AllKinds=63 — всё. Запрещённая запись сбрасывает частичное совпадение; через
допущенные записи совпадение может проходить. Класс5 объединяет пробелы и
комментарии, поэтому независимо фильтровать их нельзя. Wrap задаётся повторным
явным запросом владельца. Regex, normalization и case folding не заявлены.

Кандидаты берутся только из класса1: ключевые слова, строки и комментарии не
попадают в имена. Prefix —0..64 скаляра, limit —1..32; имена длиннее128 пропускаются.
Результат отсортирован и без повторов независимо от порядка в файле. Типы,
объявления, области видимости, imports и сигнатуры требуют семантического
frontend компилятора; лексический fallback так и обозначается.

Валидация каждого запроса — O(tokens); затем контекст использует двоичный поиск,
поиск добавляет O(source+needle), кандидаты — ограниченную вставку32 строк.
Это ограниченные синхронные операции без гарантии физической задержки. UI должен
планировать явные запросы вне пути ввода и отбрасывать stale revision.

Пункт **17**, `--launch tokens` и `sh run-token-query.sh` запускают настоящий
пример с генераторными сканерами и согласованной native-cell DisVM. При
исполнении не нужны Python, Coco/R или внешний emu. Исходник и EN/RU readme
поставляются в runtime/editor. Пункт16 проверяет сервис, пункт8 — графическую IDE.

[Проверка](dis/tests/idetokenquery_test.b) проходит в interpreter/JIT: контекст/EOF,
Unicode, stale, маски, перекрывающиеся совпадения, длина исходника, порядок и
владение кандидатами, отвергание испорченного токена. Пример печатает реальные
restart/reuse. В прежних Find/ReplaceAll также явно инициализирован prefix[0]
KMP-таблицы: существующий `newa` оставляет scalar storage неопределённым.
Семантика VM не менялась; таблица нового helper явно обнулена.
