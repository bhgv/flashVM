# Сервис библиотечной сборки на Dis — runtime 0.33

[English](COMPILER-SERVICE.md) · [Workspace](WORKSPACE.md) · [Интерфейс worker](dis/bridge/idecompiler.m) · [Нативный модуль](../disVM/module/fircompiler.m) · [C99 API](../disVM/compiler/compiler_engine.h) · [Пример](dis/examples/compiler-service/README.ru.md)

Реализован сервисный путь сборки IDE: Limbo worker получает настоящий снимок
workspace, вызывает наши библиотеки Coco/R/FIR через типизированный модуль и
возвращает реальные байты с исходными билетом и ревизией. Документы, задания и
допуск результатов остаются на Dis. Нативное расширение не управляет UI и не
запускает shell, CLI-компиляторы, Python или внешний Inferno emu.
Python используется только как инструмент приёмки на машине разработчика.

Сервис подключён к графическим F7 Build/F8 через Idebuildpanel. Run/Debug пока не реализованы.
Автоматическая загрузка/запуск артефакта и подключение полного отладчика остаются
дальнейшими этапами. Ограниченный собственный frontend пока не компилирует всю
IDE: сложные Limbo-модули собираются из закреплённого bootstrap-исходника.

## Интерфейсы и владение

| Уровень | Интерфейс | Работа |
| --- | --- | --- |
| C99 | dvm_compile / dvm_compile_dispose | Исходник → проверенный FIR → необязательная оптимизация → артефакт |
| Нативный Dis | $Fircompiler.compile | Захват согласованного NC64 кадра, проверки, копирование в корни Dis |
| Limbo | idecompiler.start → канал запросов | BeginBuild, вызов библиотеки, FinishBuild, ответ и завершение |

Библиотека C99 не включает заголовки VM. Входные UTF-8 байты заимствуются без
изменения. Потоки, FIR и контекст линкера приватны; успешный результат владеет
артефактом/debug, при ошибке частичные байты не выдаются. Перед повторным вызовом
для того же результата нужен dispose; повторный dispose безопасен. Вызовы
последовательны, поскольку состояние исходного парсера глобально. Все новые
исходные конструкции по-прежнему разбираются Coco/R.

Нативная граница сначала копирует кадр. Упакованные поля читаются/пишутся побайтно.
Старые корни проверяются совместно и очищаются до освобождения. Новый массив
укореняется перед следующим выделением; защищённая публикация освобождает C-буферы
и при исключении Dis. Вход остаётся укоренённым стеком вызывающего. Нативные
указатели, layout кадров и общие heap-объекты через модуль/канал не передаются.
Принимаются канонические и локальные однобайтовые дескрипторы без указательных
полей: в NC64 один лишь адрес дескриптора не определяет примитивный тип.

Worker удерживает модули и заимствованный workspace endpoint на своём стеке.
Документами он не владеет и workspace не закрывает. Shutdown выполняется после
предыдущих запросов, подтверждается и делает канал терминальным. Каждый запрос
с допустимым reply получает один ответ; nil reply игнорируется. Если builtin
не подключён, start возвращает nil и не запускает внешний процесс.

## Форматы, лимиты и диагностика

Языки 1..4: AS1, AS2, AS3 и Limbo с прежним ограниченным исполняемым покрытием.
AS3 означает AVM1-совместимость, а не ABC/AVM2. Форматы 1 Dis, 2 FIR, 3 SWF.
optimize допускает только 0/1. Широкие NC64 int проверяются до сужения в C int.

FIR канонизируется. Dis использует прежний NC64 backend. SWF — полный файл SWF8,
созданный libswl_core из приватного SWO: 640×480, 12 fps, extensions выключены.
Несовместимая с backend операция отвергается явно; SWO не выдаётся за SWF.
Артефакты можно побайтно воспроизвести CLI с теми же параметрами. Сам нативный
вызов их не исполняет и не публикует в файловой системе.

Исходник ограничен 65536 UTF-8 байтами. Артефакт и исходный FIRDBG1 независимо
ограничены 2097152 байтами. Workspace сохраняет свои 2 МиБ на артефакт и 8 МиБ
суммарно. Временные потоки следуют безопасной политике FIR; недоступный TMPDIR
даёт ошибку. Сохранение байтов — отдельное решение клиента. Sys.create в примере
не является полномочием compiler worker.

| Стадия | Значение |
| --- | --- |
| Ok (0) | Полные независимые artifact/debug |
| Invalid (1) | Неверные параметры/представление входа |
| Source (2) | Отказ исходной библиотеки; доступны kind и диапазон |
| Verify (3) | Ошибка чтения, проверки или оптимизации FIR |
| Backend (4) | Отказ Dis/object/линкера |
| Resource (5) | Ошибка выделения, временного потока или вывода |
| Limit (6) | Превышение лимита исходника/результата |

Кортеж также возвращает plain message, вид исходной ошибки, строку с единицы,
UTF-8 смещение с нуля и длину диапазона в байтах. Нет позиции: 0/-1/0.
У EOF длина может быть нулевой. Debug — исходный source/unoptimized FIR,
не меняющийся от формата/оптимизации; итоговой карты Dis/SWF/native PC пока нет.
Имя модуля компиляции — ide_build.

Reply.status относится к workspace; Reply.compiler — нативная стадия либо -1,
если компиляция не запускалась. Ошибка передаётся через FinishBuild и обычно
даёт BuildFailed; новая ревизия/билет могут дать Conflict. Debug выдаётся только
после принятого успеха. Артефакт читается отдельно через workspace.Artifact,
который снова копирует массив. Неудачное задание сохраняет предыдущий успешный
артефакт лишь для текущей ревизии. Успешно скомпилированный старый снимок не
заменяет результат изменённого документа.

Компиляция синхронна и блокирует единственного владельца исполнения VM.
Отмены, параллельного парсинга и гарантии отзывчивости внутри вызова нет.
Ревизионный допуск проверяет изменения между фазами; тест действительно
компилирует старый снимок и отвергает его поздние байты, не изображая параллельное
редактирование во время блокирующего нативного вызова.

## Сборка и проверка

Корневая сборка fir,linker,disvm-editor подключает сервис после согласованных
библиотек. Runtime-only сборка подключает его при выборе fir и linker вместе.
Для отдельного CMake нужны DVM_RUNTIME_COMPILER=ON и четыре явных каталога:
DVM_COMPILER_FIR_INCLUDE/LIB и DVM_COMPILER_SWL_INCLUDE/LIB. Требуются
libfir1_source_api.a, libfir1_ir.a, libfir1_io.a и libswl_core.a.
Команды самостоятельной сборки C99 API приведены в [English](COMPILER-SERVICE.md#build-and-package).
Сборка не скачивает неизвестный SDK и не прячет сборку соседних зависимостей.

Пакет фиксирует Fircompiler=ON/OFF в NATIVE-MODULES.txt. При ON поставляются
compiler-service.dis/.sbl, idecompiler.dis/.sbl, интерфейсы, исходники, руководства
и архив сервиса. При OFF установщик убирает свои устаревшие tutorial/archive;
обычный worker остаётся доступен, но start сообщает отсутствие builtin.
Нативному вызову не нужны установленные CLI-программы.

Приёмка сравнивает 24 реальных артефакта с CLI побайтно, весь исходный debug JSON,
исполняет каждый Dis и связанный SWF с результатом 42. Интерпретатор/JIT запускаются
с quantum 1/2048; статистика подтверждает режим и GC. Настоящие каналы проверяют
сборку, устаревший запрос без запуска компилятора, сохранение старого результата
после отказа, смену формата, независимые копии, поздний результат после правки и
подтверждённое завершение. C99 тест перемежает 24 успеха и 32 чистых отказа,
проверяет повторное освобождение и недоступный временный каталог.
Перенесённый SDK заново линкует C99-клиент со своими архивами и повторяет сборки
без обращения к исходному checkout. Физические ARM64/RV64, полная self-hosted IDE
и конечное подключение отладчика остаются отдельной приёмкой.

Общий Math fix опубликован в Inferno, локальный обход удалён. Новая выборка
инструкций проверяет PC/opcode до GC/quota и использует захваченные callback-адреса.
Снимок и доказательства: [SYNC](../disVM/SYNC.ru.md).
