# Сессионный буфер между независимыми редакторами — v0.1677

[Рабочий стол](DESKTOP.ru.md) · [Выделение](DESKTOP-POINTER.ru.md) ·
[Запуск](ENTRYPOINTS.md) · [English](DESKTOP-CLIPBOARD.md)

Ctrl+C копирует выделение активного редактора, Ctrl+X вырезает, Ctrl+V вставляет
в его выделение/каретку. Свиток Clipboard справа также содержит три настоящие
MovieClip-кнопки. Буфер принадлежит сеансу IDE: **системный clipboard не читается
и не изменяется**. Прежний одиночный редактор сохраняет свою native-интеграцию.

![Настоящий MovieClip-стол и кнопки сессионного буфера](assets/desktop-v0.1677.png)

После Copy исходное окно можно закрыть: остальные редакторы продолжают вставлять
сохранённое значение. Завершение стола завершает владельца буфера. Help и консоль
не являются редактируемыми источниками. Поля пути пока не используют этот буфер.
Copy/Cut без выделения сохраняет прежнее содержимое; пустой Paste не удаляет
выделенный исходник.

## Владельцы и подтверждения

`Idedeskclip` — отдельный Limbo-процесс с обычным каналом запросов. Get возвращает
скопированные текст, размер и generation. Put/Clear требуют точного generation;
stale или неверная запись сохраняет прежнее значение. Изменение увеличивает
счётчик без переполнения; то же самое значение не меняет generation. Shutdown
освобождает значение до терминального ответа. Старые строки Reply остаются
независимо используемыми после Put/Clear.

Каждый редактор по-прежнему владеет полным Idecore, выделением, saved и undo.
ExportSelection возвращает весь выбранный текст до 64 КиБ UTF-8 независимо от
визуальных 200 символов. Во FlashVM отправляется только ограниченный вид.
Большие значения идут через Dis-каналы, не через native UI envelope и не через
общий управляемый указатель между VM.

Для Cut приложение сначала получает успешное подтверждение Put, затем просит
владельца удалить точный диапазон при захваченной revision. Окно проверяет и
ревизию, и полный диапазон, включая смену выделения при той же revision. Paste
делает один проверенный Idecore Replace и ставит приватную каретку после вставленных
Unicode-символов. Undo остаётся обычной операцией документа; сам буфер истории
редактирования не добавляет.

Это упорядоченная координация, не распределённая транзакция: если после Put окно
отвергло Cut, скопированное значение остаётся в буфере, а Cut не меняет исходник.
Прямой библиотечный клиент обязан соблюдать тот же порядок подтверждений; окно
не аутентифицирует ответ отдельного broker.

## Ограничения значений

Лимит — 65 536 UTF-8 байт, не Unicode-символов. NUL, суррогаты, неверные codepoint
и превышение лимита отвергаются без частичной публикации. Прямой Paste также
проверяется. Неуспешный Export не переводит приложение к Cut. Полная ёмкость
документа остаётся отдельной. Copy не меняет/не сохраняет/не собирает исходник;
Cut/Paste не сохраняют файл автоматически.

Нужно вместе пересобрать согласованные `.m`/`.dis`: Reply окна теперь содержит
полные упорядоченные границы и Export-only строку transfer. Формат MovieClip-сцены
не изменён. Новый парсер, контейнер SWF/Dis, Tk/Draw или поток системного clipboard
не добавлялся.

## Запуск и проверки

IDE — прежний пункт **8** / `--launch desktop`. Полностью комментированный
[переносимый клиент](dis/examples/desktop-clipboard/README.ru.md) — пункт **12** /
`--launch clipboard` либо `sh run-desktop-clipboard.sh` в обоих runtime-пакетах.
При запуске им не нужны Python, внешний emu и компилятор.

Настоящие владельцы проверяются на точной/превышенной границе байт, stale generation,
неизменности старого Reply, смене выделения при той же revision, пустом/неверном
Paste. Настоящий FlashVM replay переносит Unicode между окнами, сохраняет полные
файлы длиннее UI envelope, выполняет Cut/Undo и три MovieClip-кнопки. Native AMD64
interpreter/JIT проверяются отдельно; client работает и при compiler OFF. Физический
touch, прочие CPU/OS и системный clipboard этим сессионным тестом не доказываются.
