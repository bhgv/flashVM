# Ленивые лексические каталоги Limbo и ActionScript

[English](SYNTAX-LAZY.md) · [Запуск](ENTRYPOINTS.md) · [Рабочий стол](DESKTOP.ru.md)

Реализованы процесс анализа на Limbo/Dis, владелец ленивой очереди и сканеры,
генерируемые Coco/R. **Показ разноцветного текста в окнах редактора этой серией
ещё не подключён.** Существующий Flash TextField использует единый формат;
полной поддержки диапазонов AS TextFormat/HTML здесь не добавлено. Следующий
этап — соединить готовые цветовые диапазоны с представлением редактора.

Грамматики [Limbo](syntax/limbolex.atg) и [AS](syntax/aslex.atg) распознаются
сгенерированными таблицами. [Адаптер сборки](syntax/generate.py) добавляет
reset/next и убирает синхронную печать ошибки незаконченного комментария,
не заменяя распознавание ручным сканером. Старый AS-прототип независим и не
используется как запасной путь. Сгенерированные файлы остаются в build.

## Процессы и каналы

[Контракт](dis/bridge/idesyntax.m) и [реализация](dis/bridge/idesyntax.b)
передают только значения. Каждый анализатор владеет отдельными экземплярами
сгенерированных модулей и их изменяемыми таблицами. Это планируемый процесс
Dis, независимый от кадров Flash; одновременное исполнение нескольких VM
в нативных потоках этим не заявляется. Нативные потоки растеризации работают
отдельно с неизменяемыми заданиями.

`start` возвращает два небуферизованных канала. Каждому принятому запросу,
включая stop, соответствует один обязательный приём ответа. Отсутствующие
зависимости дают nil-каналы; ручного обходного анализатора нет.

`startlazy` создаёт владельца, подтверждающего Update/Snapshot без ожидания
окончания анализа. Одновременно хранятся одно активное задание и только последний
ожидающий снимок. Ticket каждого Update строго возрастает; revision неотрицателен,
профиль явно Limbo/AS. Новый запрос сразу делает старый каталог неактуальным.
Результат старого ticket/revision/профиля не заменит новый. Shutdown дожидается
активного ограниченного задания, завершает worker и подтверждается. Клиент
обязан принимать ответы. Уведомления необязательны и могут объединяться;
Snapshot — достоверное состояние. Nil-канал уведомлений не участвует в alt.

Каталог содержит упорядоченные полуоткрытые диапазоны Unicode-скаляров всего
принятого снимка, а не байтов или экранных координат. Классы: 0 — пунктуация,
1 — имя, 2 — число, 3 — строка/rune, 4 — ключевое слово, 5 — пропущенные
сканером комментарии и пробелы. Незавершённые строки/комментарии допустимы для
редактирования; ошибки языка определяет компилятор.

Лимиты сервиса: 65 536 скаляров, 262 144 байта UTF-8, 8192 записи. Surrogate и
не-скаляры отвергаются. Превышение лимита не публикует частичный успех. Это
ограничения ресурсов сервиса, не языка. `project` двоичным поиском выбирает
нужные записи и строит палитру максимум 200 видимых скаляров. Несовпадение
revision/профиля возвращает пустую палитру. Документ, Undo, сохранённость,
каретка, выделение и геометрия не изменяются.

## Повторное использование и границы

Один неизменяемый каталог можно использовать для лексического контекста,
поиска с учётом комментариев/строк и будущих кандидатов дополнений. Разрешение
объявлений, области видимости, типизированные дополнения, диагностика и FIR
остаются работой компиляторных frontend. Эти терпимые к незавершённому тексту
грамматики не заменяют полные парсеры компиляторов. Контекст AS regexp/E4X,
полные правила чисел и Unicode-идентификаторов ещё не реализованы.

## Запуск и проверки

Runtime собирает генератор из явного `DVM_COCOR_LIMBO_ROOT` (по умолчанию
выбранный tools/coco-r-limbo), затем два сканера и сервис согласованным native-cell
bootstrap. Python/генератор при исполнении установленного приложения не нужны.
Временный legacy bootstrap не становится основным компилятором проекта.

После сборки/установки доступен пункт **16** конечного меню либо `--launch syntax`.
Это проверка настоящего сервиса, без разноцветного GUI:

```sh
python3 build-menu.py --projects disvm-runtime --backend cmake --launch syntax
sh out/disvm-runtime/run-syntax-check.sh --no-jit
sh out/disvm-runtime/run-syntax-check.sh --jit
```

[Проверка](dis/tests/idesyntax_test.b) исполняет реальные сканеры/каналы в
интерпретаторе и JIT: Unicode вне BMP, escape и незаконченный текст, квоты,
неизменяемость старого каталога, stale revision, серия правок во время анализа,
повторный ticket и завершение. Задержка физического ввода, показ цветов в GUI
и параллельные владельцы VM этой проверкой не измерялись.
