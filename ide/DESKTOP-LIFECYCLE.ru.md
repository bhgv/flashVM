# Перемещение и завершение окон — v0.1674

[Рабочий стол](DESKTOP.ru.md) · [English](DESKTOP-LIFECYCLE.md) ·
[Переносимый пример](dis/examples/desktop-lifecycle/README.ru.md)

Перетаскивание первых 24 пикселей окна, его заголовка, перемещает само окно.
Перетаскивание пустого стола прокручивает стол. Жест из тела окна не делает ни
того, ни другого: мышиное выделение текста ещё интегрируется отдельно. Фокусируемое
окно рисуется последним и получает события в перекрытой области. Остальные окна
сохраняют порядок стабильных слотов.

Закрыть редактор можно кнопкой `x`, Ctrl+W или инструментом Close справа. Чистый
редактор закрывается сразу через Ctrl+W/заголовок. Для dirty открывается модальное
решение: **Discard this editor** завершает только этот редактор, **Cancel** или
Escape сохраняет его открытым. Чтобы сначала сохранить, отмените закрытие,
нажмите Ctrl+S и закройте снова. Help и build-консоль остаются открытыми; Close
не подменяет собой общий Quit.

## Владение и порядок завершения

1. Flash input предлагает ограниченные координаты/фазы с ticket завершённого вида.
2. `Idedesktop` допускает жест заголовка либо предложение Close. Он владеет
   геометрией, не документом. Предложение Close само по себе ничего не удаляет.
3. Приложение запрашивает реальные revision/saved у владельца документа. Пока
   модальное решение открыто, правки, смена фокуса, другие инструменты и создание
   окон не меняют его цель. Решение завершается Cancel/Escape либо явным discard.
4. При закрытии приложение получает терминальное подтверждение `Shutdown`,
   отбрасывает канал владельца и только затем отправляет layout операцию `Remove`.
5. `Remove` убирает окно, его кнопку закрытия и миниатюру из одной полной сцены,
   отменяет активный жест и выбирает оставшийся фокус.
6. Владелец FlashVM очищает отсутствующие MovieClip, каретки и TextField, проверяя
   настоящее чтение пустого текста. Пустые клипы остаются в ограниченном пуле для
   повторного использования. Контекст FlashVM при каждом закрытии не уничтожается.
7. New создаёт новый процесс документа в свободном слоте. Канал прежнего документа,
   undo, путь, dirty и смещения layout не переходят к новому владельцу.

`Remove` отвергает системные слоты 2/3, отсутствующие окна и неверные ID.
Всего остаётся восемь слотов, включая Help и консоль. При исчерпании лимита New
выводит сообщение в консоль. Нативные ID не становятся каналами или полномочиями
на исходник. После изменения интерфейса нужно вместе пересобрать и установить
согласованные `.m`/`.dis`.

## Жесты и ограничения

Координаты окна локальны относительно стола; scroll применяется отдельно.
Смещения переживают обновление текста/вида и хранятся в памяти текущего приложения.
При resize отображаемая позиция ограничивается границами. После перезапуска или
создания нового владельца используется исходная сетка. Файла сохранённой сессии нет.

Устаревший ticket, потеря фокуса, Cancel, колесо, resize, выбор окна и удаление
отменяют жест. Нажатие `x` должно завершиться внутри той же кнопки; отпускание
снаружи или перемещённое нажатие не закрывает окно. Тело свитка перехватывает
клики по перекрытым окнам. На узком экране используются реальные границы кнопок.

Рисование MovieClip остаётся на владельце FlashVM, в фоновое представление уходят
только завершённые пиксели. Независимые процессы Limbo кооперативны; параллельные
нативные потоки VM этим не заявляются. Новый ABI, контейнер SWF/Dis или парсер
не вводится.

## Проверки

Переносимые тесты проверяют drag, сохранение позиции при обновлении, отмену,
предложение Close, Remove/New, защиту системных окон и узкие границы Cancel.
Настоящий FlashVM replay проверяет трансформации, порядок перекрытия, Cancel/Escape/
discard, блокировку правок, очистку TextField, живые миниатюры и десять циклов
закрытия/создания. Клиенты исполняются на native AMD64 interpreter и JIT. SDK
также запускает пример и графическую оболочку вне путей репозитория. Физический
touch, остальные CPU/OS и подключённые Run/Debug остаются отдельной работой.
