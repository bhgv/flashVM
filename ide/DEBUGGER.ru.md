# Заготовка графического отладчика

[English](DEBUGGER.md) · [MDI/SDI](MDI-SDI.ru.md)

В IDE из пункта8 раскройте **Debug → Open panels**. Появятся три обычных readonly
MovieClip-окна: исходник/позиция, стек, данные. Они находятся на том же столе,
что исходники и рисунки. Повторное открытие использует существующих владельцев;
закрытые панели создаются заново. Общий лимит8 окон сохраняется: чужой документ
ради отладчика не заменяется.

Состоянием владеет отдельная Limbo-сессия [idedebug](dis/bridge/idedebug.m).
UI получает копии через типизированные каналы. Команды защищены точной
инкарнацией сессии; устаревший Shutdown не завершает новую сессию.
Сейчас attached=0, capabilities=0. Attach/Pause/Continue/Step/Next отвечают
Unsupported и не изменяют состояние. Отладка цели, исполнение точек останова,
чтение стека и переменных ещё не подключены. Примерных кадров, вычисления
выражений или getter-ов при открытии панелей нет.

Опорные Inferno deb/debdata/debsrc и debug.m изучены для разделения UI,
позиции исходника, кадров, данных и команд исполнения. Draw/Tk не переносится.
Выбранная debug/SBL-библиотека уже поставляется, но её целевой `/prog`-интерфейс
этим host пока не реализован. Это заготовка, не достигнутый паритет с deb.

Далее нужны разрешённая capability цели, остановка на safe point владельца VM,
точные PC/кадры с эпохой остановки, привязка к исходникам, точки останова и
одинаковая семантика шага в интерпретаторе/JIT. Resume обязан инвалидировать
старые кадры. Значения передаются копиями с проверкой GC/unwind; указатели
нативного стека/регистров/кучи через каналы не передаются. Потоки растеризации
ради паузы VM произвольно не останавливаются.
