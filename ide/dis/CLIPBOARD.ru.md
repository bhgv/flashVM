# Unicode-буфер через каналы: копирование, вырезание и одна операция вставки

[English](CLIPBOARD.md) · [Библиотека](bridge/ideclipboard.m) ·
[Контроллер](examples/graphical-editor/main.b) ·
[Комментированный пример без окна](examples/graphical-editor/clipboard-demo.b) ·
[Настоящий графический тест](../../disVM/runtime/test_graphical_clipboard.py).

Ctrl+C копирует выделенный диапазон исходника. Ctrl+X удаляет его только после
успешного подтверждения записи нативным владельцем буфера для захваченных
ревизии/ticket. Ошибка или превышение размера сохраняет текст, выделение,
историю и сохранённую ревизию. Пустое выделение не меняет буфер. Ctrl+V читает
один неизменяемый UTF-8-снимок и вызывает единственный Replace после приёма всех
частей. Undo отменяет всю вставку. Пустой буфер — пустая операция, даже при
непустом выделении исходника.

Предел — 65536 байт UTF-8, отдельно от скалярного предела документа. NUL, неверный
Unicode, размер, смена total, повтор/пропуск offset и устаревшие ticket/ревизия
отклоняются до редактирования. CRLF и не-BMP сохраняются. Один Dis-контроллер
владеет диапазоном, идентификатором и приватным массивом частей; завершение,
ошибка или посторонний ввод освобождают staging. Нативный код не редактирует
исходник и не выполняет Undo.

Операции существующего конверта fvd1:

| Код | Направление | Значения |
| --- | --- | --- |
| 65554 ClipboardWrite | Dis View → native | ревизия, скалярный диапазон, исходный ticket |
| 65556 ClipboardRead | Dis View → native | ревизия, нулевой диапазон, исходный ticket |
| 65557 ClipboardData | native Request → Dis | захваченная ревизия, байтовые offset/total, ticket+UTF-8 |
| 65558 ClipboardAck | native Request → Dis | ревизия, Ok/TooLarge/Invalid, ticket |
| 65559 ClipboardContinue | Dis View → native | ревизия, следующий offset/total, исходный ticket |

Ticket занимает восемь канонических hex-цифр ASCII. На тело остаётся 1016 байт,
границы частей не разрывают Unicode. Continue разрешает следующую часть без
повторной отправки и растеризации неизменённого документа. Нативный владелец
сверяет credit со своим неизменяемым буфером и освобождает его после копирования
последнего кадра. Указатели, OS handles и нативные структуры между VM не проходят.
Вызов платформенного clipboard API может блокировать нативного владельца UI;
Dis получает только результат по своим каналам.

Интерактивный режим использует SDL_GetClipboardText/SDL_SetClipboardText.
Обычный --events/--window-events хранит изолированный буфер внутри процесса.
Явный --clipboard-events дополнительно проверяет настоящий SDL API; для
автотестов выбирается SDL_VIDEODRIVER=dummy. Физические clipboard-службы и
полные порты runtime других ОС этим отдельно не подтверждаются.

Внутри полей Find/Open/SaveAs/GoTo сочетания буфера исходника пока не действуют;
там остаётся прежняя политика однострочного ввода. Обновлять следует вместе
хост, контроллер и библиотеку компонента 0.6.0. Сохранение файла остаётся
отдельной явной командой. Ошибка последней операции не стирается отпусканием
клавиши/Ctrl или наблюдением фокуса при той же ревизии; новая содержательная
операция публикует собственный статус.

Проверены Unicode/CRLF, подтверждённое Cut, вставка ровно 64 КиБ с одним Undo,
отказ большого Cut без удаления и поздние результаты. Отдельно библиотека
проверяет неверные offset/размер/NUL и отмену приватного префикса.

## Перекомпиляция примера из установленного пакета редактора

```sh
./limbo-native -g -I include/limbo -o clipboard-demo.dis examples/graphical-editor/clipboard-demo.b
./disvm --stats --jit clipboard-demo.dis
./disvm --stats --no-jit clipboard-demo.dis
```

Пример получает шесть байт `Я😀`, затем три байта LF+`AB`. Только после завершения
он возвращает девятибайтовое значение из пяти скаляров. idehost.m используется
для констант, без загрузки GUI-хоста и доступа к OS clipboard. Основная собственная
цепочка остаётся Limbo/FIR с Coco/R; legacy-компилятор здесь — явный временный
инструмент сборки из исходников.
