# Короткий пример сгенерированных сканеров

[English](README.md) · [Исходник](main.b) · [Сервис](../../bridge/idesyntax.m) · [Руководство](../../../SYNTAX-LAZY.ru.md)

Пункт **16** запускает этот консольный Dis-модуль. Он загружает `Idesyntax`,
вызывает [`start`](../../bridge/idesyntax.b), передаёт по каналу заданий по одному
Unicode-снимку Limbo и ActionScript, получает полные каталоги и проверяет, что
`project` отвергает устаревшую ревизию. Распознавание выполняют сгенерированные
Coco/R-сканеры; самописной подмены или внешнего процесса компилятора нет.

```sh
sh out/disvm-editor/run-syntax-check.sh --jit
sh out/disvm-editor/run-syntax-check.sh --no-jit
```

Скрипты есть и в `disvm-runtime`. Флаги выбирают настоящий JIT или интерпретатор.
Файл ввода, GUI-контекст и дополнительная настройка не нужны.

Ожидаемый вывод:

```text
PASS Coco/R syntax example: profiles=2 Unicode=ok stale=reject shutdown=ok
```

Читайте [`init`](main.b) по порядку: загрузить сервис, удерживать оба канала,
передавать запрос и получать ответ по одному, проверить две палитры, передать
`stop=1` и получить подтверждение с тем же ticket. При ошибке после завершения
вызывается исключение. Runtime штатно присоединяет worker при возврате.

[Стресс-проверка](../../tests/idesyntax_test.b) отдельно проверяет максимальные
входы/квоты токенов и серии отмен. Она может работать заметно дольше и не является
программой пункта 16. Успешный короткий пример не означает прохождения всей
стресс-матрицы и не является замером задержки физического ввода.
