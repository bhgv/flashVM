# От байтов настоящего компилятора к выделению в редакторе

[English](README.md) · [Контракт Utf8Span](../../UTF8_SPANS.ru.md) · [Клиент](main.b)

Полный AS-исходник [source.as](source.as): `/*中😀*/ trace(missing);`.
Наш числовой адаптер `fir1_source` отвергает неинициализированное имя: байтовое
смещение 18, длина 7, байтовая колонка 19. В Limbo это символы [13,20), колонка 13,
строка `missing`. Передача числа 18 напрямую в Locate дала бы неверную позицию.
Подробно прокомментированный клиент отправляет Utf8Span через типизированный канал
документа и после правки отвергает ту же диагностику со старой ревизией.

[diagnostic-values.m](diagnostic-values.m) — сохранённый пример для разработчика.
Необязательный сквозной [source_navigation.py](../../tests/source_navigation.py)
вызывает **настоящий FIR-компилятор**, сохраняет точные JSON/исходник, проверяет
сохранение предыдущего артефакта при ошибке компиляции, заново генерирует константы,
компилирует тот же клиент и исполняет его в явно выбранной эталонной VM.
Python не разбирает язык: только переносит диапазон, выданный компилятором.
Нативные компиляторы и Python не добавляются к исполняемой IDE.

Из корня с согласованными нативным Limbo и эталонным эмулятором:

```sh
LIMBO_EXECUTABLE=/matching/bin/limbo \
LIMBO_MODULE_DIR=/matching/module \
EMU_EXECUTABLE=/matching/bin/emu \
./build-workspace.sh --projects fir,ide --tests
```

При выборе FIR и IDE сквозные тесты включаются автоматически. Одна IDE не получает
скрытую зависимость от FIR. При независимой CMake-сборке ide/dis задайте
`-DFIR_SOURCE_EXECUTABLE=/explicit/build/fir1_source` вместе с тремя обычными
переменными SDK, соберите и выполните:

```sh
ctest --test-dir BUILD -R diagnostic_navigation -V
```

Оба режима должны напечатать `PASS idecore compilerlocation ... checks`.
Артефакты и настоящая JSON-диагностика остаются в BUILD/source-navigation-0 и -1;
временные потоки используют tmp внутри сборки. Компилятор, заголовки и эмулятор
должны иметь общий ABI. Корневой disVM пока выпускает архив ядра, не такой runner.

Для запуска только сохранённого примера скомпилируйте main.b, указав include этой
папки, ide/dis и согласованный sys.m; разместите модуль и idecore.dis в отдельном
пространстве имён эмулятора, запустите compilerlocation.dis как init. Обвязка
намеренно останавливает отдельную тестовую VM после отчёта; её нельзя использовать
как init рабочей интерактивной сессии.

Клиент обязан хранить ревизию исходника и идентичность сервиса с момента запроса
компиляции. Ответ применяется только к этому снимку. Управление процессами
компилятора, релокация отладочных PC, нативный мост Dis/SWF и визуальный редактор
этим примером не реализуются.
