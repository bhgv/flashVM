# Пример владельца каталогов и браузера IDE

[English](README.md) · [Протокол](../../DIRECTORIES.ru.md) · [Код](main.b) ·
[Драйвер](../../../../disVM/runtime/test_directory_browser.py)

Пример выполняется на настоящем DisVM и использует `Idefiles.startdirs`, как
консольная IDE. Запросы идут по типизированному каналу, Sys обращается к OS-портам.
Подмены файловой службы нет. Нужны согласованные VM, компилятор Limbo, sys.m,
idefiles.m и собранные idefiles.dis/editor-console.dis с зависимостями.

`FIXTURE_ROOT` в коде — намеренный шаблон. Драйвер создаёт собственные Unicode-
файлы, подставляет экранированный путь, компилирует и запускает пример, затем
удаляет свои данные. Без подстановки шаблон прямо компилировать не следует.
Драйвер нативной проверки сейчас предназначен для Linux: для проверки ошибки
он создаёт отдельное имя с невалидным UTF-8 байтом.

Из корня репозитория после сборки runtime:

```sh
ctest --test-dir build/runtime -R directory_browser --output-on-failure
```

Из установленного SDK, в том числе после переноса в каталог с пробелами:

```sh
python3 examples/directory-browser/run.py ./disvm ./limbo-native \
  ./include/limbo ./include/limbo ./examples/directory-browser/main.b . jit
```

Повторите с `interpreter`. В SDK редактора первый аргумент — `./disvm-editor`.
Ожидается `PASS directory service and IDE browser jit`. Каждый режим выполняет
клиент с quantum 1/2048, проверяет счётчики исполнения и затем консольные команды.

Создаются 74 элемента: Unicode-имена, двоичный файл из четырёх байтов, пустой
каталог, разреженный файл 4294967303 байта и имя с управляющими символами.
Нужны поддержка разреженных файлов и место для метаданных. Отдельный каталог
с невалидным именем проверяет ошибку без выдачи частичной порции.

Проверяются независимые курсоры и массивы, три порции по максимуму 32 записи,
стабильный End, жизнь метаданных после закрытия, квота восемь ID и отказ девятому.
Старый ID не получает новый каталог в переиспользованном слоте. StatPath
работает при заполненной квоте. Есть неверные запросы, NUL, URI, отрицательный
ID и nil reply. Затем — 80 open/close и 32 запуска/завершения с восемью открытыми
курсорами. Replay проверяет сохранение документа, прежнего курсора при ошибке
нового open, экранирование имён и завершение с активным курсором.

Все владельцы закрываются явно. Записи и массивы принадлежат VM независимо от
FD; их можно менять и хранить после закрытия. ID локален для endpoint: сохраняйте
пару `(endpoint, id)`. Брошенный ответ не является отменой — его надо прочитать.

Назначение каждой операции, статусы, владение и блокировки описаны в
[контракте](../../DIRECTORIES.ru.md#протокол-и-владение). Нативный I/O пока блокирует
одного владельца VM, обход не атомарен и не сортируется. Графическое дерево,
/prog, сетевые аренды и асинхронная отмена остаются отдельными задачами.
