# Массовая замена с одним Undo

[English](README.md) · [Контракт](../../REPLACE_ALL.ru.md) · [Исходник](main.b)

Подробно прокомментированный Limbo-пример загружает сервис документа, открывает
`old中 old中 old中`, заменяет три вхождения `old中` на `old中新`, отклоняет запрос со
старой ревизией и одним Undo восстанавливает исходник. Вставка содержит образец:
вставленные вхождения нельзя искать снова. Ревизии: 1 → 2 → 3, saved остаётся 1.
Ранее полученный ответ сохраняет первоначальный текст. Sys нужен только обвязке
примера для печати и остановки отдельной тестовой VM; производственный модуль
импортирует лишь свой заголовок и принимает команды через каналы.

Из корня проекта с явно выбранным согласованным по ABI SDK:

```sh
LIMBO_EXECUTABLE=/matching/bin/limbo \
LIMBO_MODULE_DIR=/matching/module \
EMU_EXECUTABLE=/matching/bin/emu \
./build-workspace.sh --projects ide --demo replaceall
```

Либо выберите `ide` и пример `replaceall` в `python3 build-menu.py`. Корневая сборка
умеет собрать временный bootstrap Limbo из tools, но для запуска нужен настоящий
совместимый эмулятор. disVM пока выпускает архив ядра, а не такой исполняемый файл;
указывать архив вместо EMU_EXECUTABLE нельзя.

При отдельной сборке ide/dis задайте те же три переменные CMake, соберите проект
и выполните `ctest --test-dir BUILD -R replaceall_example -V`. Оба эталонных режима
должны напечатать `PASS idecore replaceallexample ... checks`.
Тестовые модули/примеры не устанавливаются с производственной библиотекой.
Это консольный пример сервиса, а не визуальный редактор, файловая транзакция или
полная IDE внутри FlashVM. Все клиенты должны использовать интерфейс 0.5.0.
