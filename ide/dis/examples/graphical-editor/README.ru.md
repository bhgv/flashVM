# Графический редактор: логика Limbo/Dis, графика FlashVM

[English](README.md) · [Полностью комментированный контроллер](main.b) ·
[Канальный интерфейс хоста](../../bridge/idehost.m) ·
[Рантайм](../../../../disVM/runtime/README.md)

Это исполняемый первый графический редактор. Контроллер на Limbo работает в
нашем NC64 Dis-интерпретаторе/JIT. Документ и Undo/Redo принадлежат отдельному
процессу Idecore; ввод и выделение обрабатывает существующий Ideinput. Снимки
передаются через Idebridge по обычным каналам Dis и очередям FlashVM. Загрузка,
сохранение и защита несохранённых изменений выполняются на Limbo через Sys.
Python/Node, внешний emu и Inferno Draw/Tk для исполнения не нужны.

Отдельный контекст FlashVM владеет закреплённым TextField. Он получает только
полные проверенные снимки и рисует реальные контуры текста, выделение и каретку.
SDL2 выводит готовые пиксели и принимает события. Нативная часть не хранит
авторитетную историю документа и не определяет политику сохранения. На этом
этапе представление — C-адаптер встраивания; существующие AS-представление и
работник подсветки ещё не запускаются этим графическим приложением.

## Сборка и запуск

```sh
./build-workspace.sh --projects disvm-editor --jobs 4
FVM_EDITOR_FONT=/полный/путь/font.ttf sh out/disvm-editor/run-graphical-editor.sh \
    --document /полный/путь/existing.b
# Для нового назначения явно используйте --new; файл создаётся при сохранении.
FVM_EDITOR_FONT=/полный/путь/font.ttf sh out/disvm-editor/run-graphical-editor.sh \
    --new /полный/путь/new.b
```

В меню сборки есть компонент `disvm-editor`, после сборки — запуск **8** с
запросом пути к шрифту и существующему файлу. Шрифт выбирается явно и копируется
в FlashVM; системный поиск и подмена шрифтов не выполняются. Пакет можно
переместить. Модули ищутся рядом с входным `.dis`, пользовательские относительные
пути относятся к рабочему каталогу запуска. `--jit`/`--no-jit` выбирают реальный
режим исполнения Dis. Отладочные `.sbl` поставляются, отладчик пока не подключён.

Прямая сборка CMake: `DVM_RUNTIME_EDITOR=ON`, для окна — `DVM_EDITOR_SDL=ON` и
явный `SDL2_DIR`. Для графических CTest задайте `DVM_EDITOR_TEST_FONT` — путь к
настоящему TTF/OpenType. Подробные команды есть в английском руководстве.
Консольный runtime сохраняет сборку без графического SDK. Без SDL графический
target поддерживает проверочное воспроизведение и реальную внеэкранную растеризацию.

## Управление

| Действие | Результат в Dis |
| --- | --- |
| Текст/IME, Enter, Tab | Вставка Unicode по каналу документа. |
| Left/Right, Home/End, Shift | Перемещение каретки и выделение. |
| Backspace/Delete, Ctrl+A | Удаление диапазона либо выделение всего документа. |
| Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y | Undo/Redo настоящего владельца истории. |
| Ctrl+S | Сохранение UTF-8 в настроенный путь и подтверждение записанной ревизии. |
| Ctrl+O | Перечитывание того же файла только при отсутствии несохранённых правок. |
| Закрытие окна | Завершение либо отказ при несохранённых изменениях. |
| Shift + закрытие | Явное отбрасывание правок и завершение. |

Заголовок окна показывает текущую/сохранённую ревизии и статус: 0 — успех,
1 — конфликт, 4 — ошибка операции/I/O. Входной файл ограничен 64 KiB;
неверный UTF-8, превышение размера и ошибка чтения не меняют его содержимое.
При начальной ошибке загрузки приложение завершается. Сохранение обрабатывает
короткие записи и подтверждает только успешную запись. Это перезапись файла,
без атомарной замены и гарантии при потере питания; ошибка может оставить
частично записанный файл. `--new ПУТЬ` явно выбирает назначение для перезаписи
при сохранении. Для буфера без пути Save возвращает ошибку; Save As ещё нет.

Потеря фокуса сбрасывает модификаторы. Нативный хост заимствует каналы, пока их
держит стек Limbo-контроллера. После подтверждённого Shutdown контроллер вызывает
`detach` до освобождения корней. Память, GC и регистры двух VM не смешиваются.

## Проверки и текущие границы

[Регрессия](../../../../disVM/runtime/test_graphical_editor.py) исполняет настоящий
Limbo/Dis-код, movers каналов, GC и TextField/растеризатор FlashVM. Проверяются
Unicode-смещения, история, защита dirty-состояния, запись файла, некорректный
UTF-8, размер, многофрагментные снимки и счётчики интерпретатора/JIT.
`--events ФАЙЛ` читает ограниченные кадры: четыре little-endian байта длины,
затем envelope `fvd1:`. `--capture ФАЙЛ.ppm` сохраняет реальные пиксели.
Конец событий без подтверждённого Quit — ошибка. `--window-events ФАЙЛ` также
проверяет загрузку пикселей в SDL-окно; автоматический dummy driver проверяет
протокол вывода, не физическое окно, клавиатуру, IME или устройство.

Приёмка пока Linux AMD64, NC64, один нативный владелец. Окно фиксировано
960×640; показываются первые 4096 UTF-8 байт без разрезания символа, а полный
документ хранится и сохраняется в Dis. Прокрутка, Up/Down, мышиное попадание,
цветная подсветка, popup-подсказки, запуск AS-работников и команды компилятора/
отладчика ещё не подключены. Каретка/выделение используют кластеры глифов;
полная bidi/grapheme-семантика не заявляется. Покрытие символов зависит от шрифта.
Синхронный I/O может блокировать единственного владельца VM.
