# Пример векторной модели и начальный SVG

[English](README.md) · [Руководство редактора](../../../VECTOR-EDITOR.ru.md)

Настоящий редактор встроен в **пункт8 → Draw**, также Ctrl+Shift+N. Кнопка Max/N
увеличивает активное векторное окно. B/P/R/E/L выбирают кисть/перо/прямоугольник/эллипс/
линию;1..6 — цвет, F — заливку, +/- — толщину. Ctrl+S/O сохраняют/читают SVG;
Ctrl+Z/Y отменяют/возвращают целый жест.

В v0.1697 добавлены экранные контролы: сверху инструменты/Undo/Redo/толщина, снизу шесть цветов/заливка/индикатор текущей толщины. Последняя нижняя плитка теперь выбирает перо и показывает толщину.

При движении сохраняются сырые точки. Кисть после отпускания строит контур
заполненного следа; перо сглаживает осевую линию с обводкой. В живом окне
обработку выполняет отдельный процесс Limbo; этот небольшой библиотечный
пример вызывает `pointer` синхронно. Точность, лимиты и владение описаны в
полном руководстве.

## Открыть готовый рисунок

```sh
sh out/disvm-editor/run-desktop-ide.sh --document "$PWD/ide/dis/examples/vector/starter.svg"
```

В установленном комплекте используйте `examples/vector/starter.svg`. Окончание
.svg запускает отдельного векторного владельца. Окно и миниатюра показывают
одинаковые настоящие пути MovieClip.

В `starter.svg` добавлены XML1.0 UTF-8 декларация и поясняющие комментарии.
Импортёр v0.1697 принимает их как нерисующие метаданные и опускает при
каноническом сохранении. Полное объяснение рисунка:

- Корень svg задаёт стандартное пространство имён и viewBox1000×600, совпадающий
  с логическим листом. Размер окна/масштаб стола эти координаты не меняет.
- Синий path без заливки имеет толщину12. Начинается в(100,120), затем содержит
  две явные Q-команды, каждая с контрольной и конечной точкой. Последняя L
  сохраняет прямой конечный сегмент. Это команды геометрии, не анимации.
- Красный rect имеет углы(120,340)/(380,500). Отсутствие stroke означает фигуру
  только с заливкой; при импорте строится замкнутый путь без native-обводки.
- Зелёный ellipse имеет центр(650,420), радиусы140/90 и толщину12. Импорт строит
  восемь квадратичных дуг; сохранение записывает получившиеся обычные SVG path.

## Собрать и выполнить Limbo-пример

[main.b](main.b) содержит комментарий к каждой строке кода. Пример использует ту
же модель Idevector, что MDI: создаёт непрерывную синюю кривую и красный эллипс,
записывает SVG с исключительным созданием, читает настоящий файл и сравнивает
канонический результат. Во время исполнения не нужны UI, чужой emu, внешняя
SVG-библиотека или Python.

Сборка создаёт `vector-demo.dis`. Запускайте из нового рабочего каталога:

```sh
package=/полный/путь/out/disvm-editor
mkdir vector-example-work
cd vector-example-work
"$package/disvm" --no-jit "$package/vector-demo.dis"
```

Ожидается `PASS vector example: vector-example.svg, two paths, exact SVG roundtrip`.
Созданный файл можно открыть в IDE или обычном SVG viewer. Пример отказывает в
перезаписи существующего файла; для повтора используйте новый каталог. `--jit`
включает настоящее guarded JIT-исполнение вместо интерпретатора.

Пересборка из установленного исходника и соответствующих заголовков:

```sh
cd /полный/путь/out/disvm-editor
./limbo-native -I include/limbo -o vector-demo-local.dis examples/vector/main.b
```

Выполните модуль по абсолютному пути из нового каталога, как выше. Bootstrap —
временный инструмент сборки, а пример исполняется как Dis bytecode. Это не
заявление о полном семантическом компилировании нашим Limbo→FIR frontend.
После расширения интерфейса окна нельзя смешивать старые и новые .dis/.m.

## Владение и границы

Документ, неизменяемые пути и история принадлежат одному процессу примера.
В MDI каждый векторный документ имеет отдельного Limbo-владельца, UI управляется
только типизированными каналами. Подмножество SVG, бюджеты и особенности ошибок
I/O описаны в [руководстве](../../../VECTOR-EDITOR.ru.md). Булева склейка областей,
редактирование отдельных узлов, слои и анимация пока не реализованы.
