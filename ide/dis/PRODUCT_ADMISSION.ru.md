# Допуск продуктов компилятора IDE, 0.2.8

[English](PRODUCT_ADMISSION.md) · [Сборка](README.ru.md) · [Проверки](VALIDATION.md)

Компилятор может завершиться успешно, оставив отсутствующий или повреждённый
результат. [CMake guard](compile_module.cmake) удаляет прежние продукты, запускает
явно выбранный компилятор и проверяет оба новых файла. При обнаруженной ошибке
оба файла удаляются. Установленный релиз следует хранить вне каталога сборки.

Модуль должен начинаться с `c0 0c 80 30`: unsigned Dis XMAGIC 819248 в кодировке
`discon`. Signed SMAGIC не входит в этот контракт продуктов компилятора. Символы
должны начинаться с точных физических строк `limbo .sbl 2.1` и `Idecore`, каждая
завершается LF или CRLF. Пустые строки, начальный/встроенный NUL, лишние пробелы
и суффиксы имени модуля отклоняются. Читаются только четыре байта модуля и не
более 25 байт символов; остальной файл ради распознавания сигнатуры не сканируется.

Константы сверены с experiment
[`c15785eb`](https://github.com/bhgv/Inferno-OS-bhgv/commit/c15785ebcf3611457ab72737f354bd806dc44780):
[isa.h](https://github.com/bhgv/Inferno-OS-bhgv/blob/c15785ebcf3611457ab72737f354bd806dc44780/include/isa.h)
и [discon](https://github.com/bhgv/Inferno-OS-bhgv/blob/c15785ebcf3611457ab72737f354bd806dc44780/limbo/dis.c).
Исходники upstream этим изменением не импортируются.

## Host-регрессия без Limbo toolchain

Из корня workspace при наличии Python 3 и CMake:

```sh
# Process doubles проверяют настоящий CMake-скрипт допуска.
# Первый аргумент явно выбирает CMake; компилятор и VM не скачиваются.
# Временные продукты создаются отдельно и удаляются после проверки.
python3 ide/dis/tests/build_guard.py "$(command -v cmake)" \
  "$PWD/ide/dis/compile_module.cmake"
```

Ожидается: `46 compiler product-admission contracts passed; no bytecode validity claim`.
При BUILD_TESTING эта проверка зарегистрирована в CTest как
`ide_dis_compiler_products`. Отдельный запуск не требует настроенной сборки.
Для отделённой копии замените оба пути IDE путями внутри этой копии.

Fixtures проверяют ошибочный exit с файлами, отсутствующие/старые файлы,
неполные и пустые пары, произвольную/signed/обрезанную сигнатуру модуля,
повреждённые и все обрезанные LF-заголовки символов, четыре сочетания LF/CRLF
и непрозрачные хвосты. Успешные fixtures намеренно состоят только из сигнатур
или произвольных хвостов; поставлять или исполнять их как Dis-модули нельзя.

## Границы

Это допуск по сигнатурам, не бинарный парсер. Полный Dis verifier и Coco/R reader
source maps остаются отдельными слоями. Проверки не выявляют некорректные
инструкции, чужой модуль с такой же magic или символы другой сборки с тем же
именем. Module identity, криптографическая привязка, управление отладкой и native
JIT здесь не реализованы. Сигнатура сама по себе не гарантирует безопасной
загрузки недоверенного байткода. Limbo-приложение, схема каналов и зависимости
исполняемой IDE не меняются.
