# Живые проекции документа и графический инспектор

[Полный контракт](LIVE-PROJECTIONS.md) · [Типы и значения](VALUES.ru.md) ·
[Исполняемый пример](examples/document-projection/README.ru.md)

`Idedocprojection` подключён к настоящему каналу Idecore. Второго текста или
истории нет, внутренний ADT документа наружу не передаётся. Чтение получает
снимок владельца; запись и методы Undo/Redo выполняются у того же владельца,
который обслуживает обычное редактирование.

Доступны text, length, revision, saved, dirty, self и ссылки на undo/redo.
Длина считается в Unicode-символах Limbo. Полная копия текста ограничена 4096
символами: большой текст отклоняется целиком. Снимок метаданных содержит только
length/revision/saved/dirty/self и доступен и для больших документов.

Для изменения документа `request.number` передаёт ожидаемую ревизию. Это аргумент
данного адаптера, а не переопределение всех проекций. Проверка выполняется сначала
в адаптере, а затем атомарно у Idecore вместе с изменением. Старый ответ или
изменение между запросами не позволяет перезаписать новую ревизию. У метода
дополнительно проверяются получатель, поколение и явное разрешение выполнения.

В консольной IDE появились команды:

```text
watch length big
watch text string
watch self object
watch undo method
watchtable
callref undo 2
setref 3 replacement text
```

Числа 2/3 — примеры, требуется актуальная ревизия документа. Тип берётся из
каталога Limbo. Чтение/раскрытие не выполняет метод; callref является явным
действием. Неуспешный вызов автоматически не повторяется.

В графическом редакторе Ctrl+I открывает readonly-панель документа. Логика Limbo
получает данные через проекцию и отправляет FlashVM только значение для отрисовки.
Esc или Ctrl+I возвращает редактирование. Пока панель открыта, текст, Delete,
вырезание/вставка и Undo не меняют документ. Размер шрифта остаётся 11, используется
поставляемый Noto. Масштаб, размер окна и завершение идут прежними проверяемыми
путями. Нативный режим Panel 7 лишь рисует данные без курсора ввода.

Pause запрещает изменения через данный адаптер, не останавливая остальные
клиенты документа. Release завершает только адаптер; документ после этого
остаётся работоспособным. Освободить адаптер надо до остановки владельца документа,
после подтверждения его endpoint больше не используется. Идентичность задаётся
сессией адаптера, не именем открытого файла.

Проверены реальные каналы, интерпретатор/JIT и счётчики исполнения, Unicode,
копии, старые ревизии, настоящий Undo, запись по значению, квота большого текста
и завершение. Графический тест проверяет метаданные, защиту readonly и изменение
реальных пикселей FlashVM. Это headless-проверка растра, не физический тест SDL
или сенсорного устройства. Пакет также проверяется после переноса.

При проверке панели найден и возвращён в Inferno дефект string big: временная
ссылочная ячейка могла ещё держать ADT, который VM принимала за строковый буфер.
Теперь числовой ввод захватывается до освобождения, повторно используется только
настоящая Tstring, а иной владелец отпускается после успешной подготовки результата.
Для AMD64/ARM64 добавлены проверки типа и безопасный отказ в C-путь; регрессии
проверяют память, ошибки выделения, внешнего владельца и FP-состояние.

Это инспектор живого документа IDE. Универсальный просмотр локальных переменных
отлаживаемой программы, сетевой RPC, экспорт GC и общий any ещё не реализованы.
ADT/канальные модули пока собираются согласованным bootstrap, не ограниченным
числовым FIR-компилятором.

## Тип переменной и запрос к владельцу

Типизированный `chan of ref Ideprojection->Request` уже обслуживает живой документ.
Это явный протокол запрос/ответ: обычная переменная Limbo не становится удалённой
переменной автоматически. Поле `asType` выбирает требуемый тип при каждом `ReadAs`;
владелец получает актуальный снимок, затем выполняет проверяемое преобразование.
Например, чтение length как Int даёт целое, а как Text — строку. Несовместимое
значение возвращает Invalid с nil, а не ноль или старое значение. Между двумя
чтениями другой клиент вправе изменить документ; ранее полученная копия не меняется.

В стандартном Limbo нет встроенного словаря. Известная структура описывается ADT;
динамические имена можно представить библиотечной таблицей. Наш Value.Table —
ограниченный неглубокий снимок с уникальными именами, а не общий словарь языка.
Объект с методами сохраняет владельца: Object/Method содержат идентичность и
поколение; запрос выполняется через канал адаптера. Одна такая запись не содержит
endpoint и сама по себе не является сетевой capability. ADT внутри одной Dis VM
может передаваться по ref со своей семантикой разделяемой памяти; этот ref нельзя
переносить как указатель в другую VM или по сети.

Автоматический вывод ReadAs из статического типа выражения, экспорт произвольных
переменных FlashVM, сборка распределённых циклов GC и сетевой транспорт ещё требуют
реализации. Передача копии, объектного прокси и явное создание нового объекта из
снимка должны оставаться разными операциями. Тест document-projection проверяет
изменение владельца между чтениями, два требуемых типа и отказ преобразования.

В FlashVM именованные и числовые свойства FVM_Object пока хранятся в отдельных таблицах. Отдельный hybrid_table.hpp ещё не подключён к FVM_Object. Общего перенесённого из Lua модуля универсальных таблиц для Limbo сейчас нет. Файл runtime/native_tables.c обслуживает таблицы переходов Dis switch/case, а не пользовательские словари.
