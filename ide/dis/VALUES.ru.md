# Значения и ссылки на основе типов Limbo

[Живой документ и графический инспектор](LIVE-PROJECTIONS.ru.md)

[English: полный контракт](VALUES.md) · [Инспектор](PROJECTIONS.md) ·
[Интерфейс](bridge/idevalue.m) · [Проверки](tests/values_test.b)

`Idevalue.types()` возвращает описание типов из скомпилированного Limbo-модуля:
имя типа, базовое представление, разрядность, имя AS-помощника, признак копии.
Подсказки IDE строятся по этому каталогу, а не по размеру указателя компьютера.

| Помощник AS | Основа в Limbo | Результат |
| --- | --- | --- |
| `tobyte` | `byte` | Копия, 0..255 |
| `toint` | `int` | Копия; 32 бита в classic, 64 в NC64 |
| `tobig` | `big` | Точная знаковая 64-битная копия |
| `toreal`, `tofloat` | `real` | Один тип binary64, два имени |
| `tostring` | `string` | Копия Unicode-строки |
| `tobool` | `int` | Расширение: 0 или 1 |
| `tochar` | `int` | Расширение: один Unicode-скаляр |
| `totable` | Именованный снимок | Копии полей, вложенные объекты по ссылке |

Отдельных скалярных типов bool/char/table в Limbo нет. Эти расширения явно
помечены в описании. `tofloat` не означает float32, а `tochar` не возвращает
половину суррогатной пары AS. Обычные операции преобразования Limbo и AS не
заменяются новыми глобальными функциями.

Константу можно передать значением без экспорта переменной. У переменной можно
передать снимок либо проекцию для последующих чтений/записей у владельца.
Объект остаётся ссылкой с идентичностью и поколением. Ссылка на метод дополнительно
содержит имя метода и сохраняет получателя: вызов происходит именно у него.
Чужой получатель или устаревшее поколение отклоняются до выполнения.

`totable` — явный снимок данных. В примере копируются сохранённые number/text,
вложенный self остаётся проекцией, методы исключаются. Геттеры не вызываются.
Не копируются прототипы и исполняемый код. Снимок ограничен 32 уникальными полями;
вложенные и циклические таблицы отвергаются без рекурсивного обхода. Копируются
массивы имён и записи значений: изменение ответа не меняет владельца или модель.

`int`/`big` читаются из целой десятичной строки с проверкой диапазона. Переполнение,
дробная часть, пробелы и хвостовой мусор дают ошибку. `big` не проходит через real.
Обратное преобразование real в целое консервативно ограничено точными целыми
±(2^53−1). При явном big→real возможно округление; это свойство binary64.
Текст real проверяется полностью, включая дробь и экспоненту; бесконечный результат
и неверная запись отвергаются. Char проверяет диапазон Unicode и запрещает
суррогаты. Непустая строка `"false"` при tobool истинна; Null/Undefined ложны.

У владельца есть отдельные команды ReadAs, Convert, WriteValue, ToTable, InvokeRef.
Convert принимает в том числе константу по значению. WriteValue принимает копию
точного типа поля. Записи и вызовы выполняются последовательно у владельца;
кооперативная пауза запрещает изменения, но оставляет чтение. Модель инспектора
копирует типизированный ответ и повторно копирует его для отрисовки, сохраняя
защиту билетами от старых ответов.

Массивы/списки требуют отдельной политики снимка. `tobytes` требует явной
кодировки; живые каналы, модули и устройства сохраняют ссылочную природу.
Значение уже существующего ключевого слова `ref` в Limbo не меняется.

AS-файл — подключаемая библиотека: `makeProjectionValues(request)` возвращает
помощники, передающие адаптеру операцию, непрозрачную ссылку, тип и callback.
`tofloat` является тем же объектом функции, что и `toreal`. Библиотека сама не
читает поля объекта и не выполняет его код. Адаптер транспорта ещё должен
обеспечить обмен, удержание корней, проверку и единственный ответ.

Проверены настоящие Dis-каналы в интерпретаторе/JIT, пакет после переноса,
AS-синтаксис нашим Coco/R и контракт AS-помощников под Node. Для classic проверяется
компиляция; полная runtime-проверка относится к NC64. Универсальный сетевой RPC,
экспорт GC и общий инспектор локальных переменных ещё не реализованы. Общие ADT/каналы пока
компилируются согласованным bootstrap, не ограниченным числовым FIR-фронтендом.
