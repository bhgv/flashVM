# Канальный протокол Idecore

Схема — [idecore.m](idecore.m), единственный владелец состояния — `serve` в
[idecore.b](idecore.b). Все изменения идут через канал запросов; наружу не выдаются
изменяемый Document или прямой UI API.

## Значения, идентичность и порядок

Каждый `start()` создаёт отдельный сервис: документ закрыт, revision=0, saved=0,
текст пустой. Запросы/ответы — **значения ADT**, копируемые при rendezvous, не общие
изменяемые ссылки ADT. Строки/каналы удерживаются средствами Dis; строковая семантика
сохраняет ранний текст запроса/ответа после следующих изменений. Общей кучи разных
VM и передачи native-указателей нет. Сериализация/handles удалённого транспорта
потребуют отдельного адаптера; локальные каналы сами его не создают.

Владелец получает и применяет команды в порядке rendezvous. Пока ответ не принят,
следующий запрос не получает. Конкурирующие правки одной expected-ревизии
сериализованы: только первая меняющая правка может её продвинуть. ID неотрицателен
и возвращается без изменений; это не replay-cache и не гарантия exactly-once.
При общем канале ответов клиенты согласуют ID; удобнее отдельный канал на запрос.

Запрос с nil reply принимается и игнорируется **без изменения состояния**, включая
Shutdown. Остальные запросы получают один ответ, в том числе при ошибке.
Непринятый ответ блокирует владельца и ограничивает приём одной командой.
Клиент обязан принять ответ. Отмена, таймауты, потоки подписок и восстановление
после потери клиента пока отсутствуют. Этот цикл нельзя выполнять на владельце
рендеринга/событий FlashVM: будущему адаптеру нужны отдельный pump и бюджет.

## Операции

| Операция | Условия | Результат |
| --- | --- | --- |
| Snapshot | Неотрицательный ID | Чтение; expected игнорируется |
| Open | Закрыт, expected совпал, длина допустима | revision++, открыть с текстом, saved=revision |
| Replace | Открыт, expected совпал, `[first,last)` корректен, длина допустима | Замена; revision++ только при изменении; saved прежний |
| MarkSaved | Открыт, expected совпал | saved=revision без изменения revision |
| Close | Открыт, expected совпал | revision++, очистить и закрыть, saved=revision |
| Shutdown | expected совпал | Ответ с текущим состоянием, затем выход владельца |

Open/Close всегда продвигают ревизию за всё время жизни сервиса. Она не сбрасывается
при повторном открытии, поэтому старая правка не совпадёт с новым документом.
MarkSaved подтверждает уже выполненное внешнее сохранение, сам файл не записывает.
Грязное состояние: `opened && revision != saved`. Замена одинаковым содержимым —
no-op; она не очищает dirty. Позиции измеряются символами `len string` Limbo,
не байтами UTF-8, единицами UTF-16, графемами, строками или экранными столбцами.
Преобразования UI и политика курсора/графем ещё впереди. first/last использует
только Replace, text — только Open/Replace.

После проверки диапазона длина проверяется как `insertion <= MaxCharacters - surviving`,
без сложения, способного переполниться. MaxCharacters=1048576. Revision ограничена
2147483647; необходимое увеличение на границе отклоняется без изменений.
Snapshot, MarkSaved, одинаковая Replace и Shutdown на границе работают.
Shutdown терминален: сначала остановить остальных производителей, принять ответ,
затем перестать использовать канал. Уведомления о закрытии канала нет; последующая
посылка может ждать бесконечно. Освобождение после выхода сервера принадлежит GC
Dis, а не публичной операции освобождения указателя.

## Порядок ошибок

Отрицательный ID — Invalid; неизвестная операция — Unknown. Затем Snapshot
успешен независимо от expected. Остальные команды сначала проверяют expected
(Conflict), затем свои условия. Open проверяет уже открытый документ (Invalid),
длину (TooLarge), границу ревизии. Остальные документные команды требуют открытого
состояния (Closed). Replace проверяет диапазон, длину, no-op, затем границу ревизии.
Любая ошибка возвращает полное неизменённое состояние; частичных правок нет.
Игнорирование nil reply — отдельный случай без подтверждения.

## Навигация с проверкой ревизии (0.3.0)

Locate и Offset читают открытый документ с точным expected и неотрицательным id.
Сохраняется приоритет Conflict/Closed; текст, revision и saved не меняются,
включая MaxRevision. Ответ содержит полный снимок состояния.

- Locate: first — смещение в символах [0, len text], включая EOF; last/text
  игнорируются. Возвращает offset, строку от 1 и символьный столбец от 0.
- Offset: first — строка от 1, last — символьный столбец от 0; text игнорируется.
  Допустим конец строки перед LF, но не переход через LF. Пустая последняя строка
  после завершающего LF также допустима.

Только LF начинает строку. CR считается обычным символом, в том числе в CRLF.
Любая граница символов преобразуется туда и обратно, даже между CR и LF.
Astral-символ занимает одну позицию, combining mark — отдельную. Это единицы
Limbo string, не UTF-8 bytes, UTF-16, graphemes или экранные столбцы. Позиции
компилятора/отладчика требуют явно выбранного преобразования перед запросом.

Reply дополнен offset/line/column: для ошибок и прочих операций все равны -1.
Сигнатура Limbo-интерфейса изменилась: пересоберите ядро и всех клиентов с одним
idecore.m. Смешение клиентов 0.2.x и модулей 0.3.x не поддерживается. Номера прежних
операций и статусов сохранены; обновление ABI на лету не реализовано.
Сканируется не более MaxCharacters символов с постоянной дополнительной памятью.
До ответа владелец занят запросом; не исполняйте этот pump на render owner.

## Точный поиск в диапазоне (0.3.1)

Find требует открытый документ и точную expected revision, как Locate/Offset.
first/last задают символьный полуинтервал [first,last) внутри документа, text —
непустой буквальный шаблон. RangeError проверяется раньше Invalid пустого шаблона.
Возвращается первое полное точное совпадение с учётом регистра, его offset/line/
column и неизменённое состояние. При отсутствии совпадения новый добавленный
статус NotFound сопровождается координатами -1. Пустой шаблон — Invalid. Нет
автоматического перехода к началу, regex, case folding и Unicode normalization.
Совпадение может включать LF/CRLF и combining marks. Длину выделения клиент знает
из шаблона; перед применением нужно сохранить проверку ревизии.

Таблица префиксов обеспечивает O(длина диапазона + длина шаблона), плюс один
просмотр префикса документа для координат найденного совпадения. Дополнительная
память — O(длина шаблона) Dis-managed int, ограниченная MaxCharacters. Если шаблон
не помещается в диапазон, таблица не создаётся. Владелец занят до ответа;
асинхронная отмена и render budgets ещё не реализованы.
