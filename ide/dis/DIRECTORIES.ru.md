# Канальный владелец каталогов Idefiles

[English](DIRECTORIES.md) · [Интерфейс](bridge/idefiles.m) ·
[Реализация](bridge/idefiles.b) · [Исполняемый пример](examples/directory-browser/README.ru.md) ·
[OS-порты](../../disVM/runtime/FILESYSTEM.ru.md)

[`Idefiles.startdirs(sys)`](bridge/idefiles.m#L82) создаёт процесс Limbo и возвращает типизированный
[`chan of DirectoryRequest`](bridge/idefiles.m#L56). При nil Sys возвращается nil. Это отдельный endpoint
от прежнего `start(sys)` для двоичных окон. Реальные stat/fstat/dirread идут через
Sys; все обращения к ОС остаются в выбранных ports. Логика IDE не переносится в C.

В консольной IDE работают `dir ПУТЬ`, `dirnext`, `dirclose`, `stat ПУТЬ`.
`dir` открывает каталог и показывает одну порцию; каждый `dirnext` читает ровно
следующую. Большой каталог не выгружается целиком. Новый курсор заменяет старый
только при успешном открытии; ошибка сохраняет прежнюю позицию. Текст, ревизия,
признак сохранения и история документа не меняются. Длинные имена выводятся
полностью ограниченными фрагментами; управляющие C0/C1, кавычки и обратные слэши
экранируются. Сами имена и записи не модифицируются.

Это готовый консольный клиент и интерфейс для будущего браузера FlashVM.
Графическое дерево файлов в эту серию не входит.

## Протокол и владение

Нужны согласованные sys.m, idefiles.m и пересобранный idefiles.dis рядом с
приложением. Входные значения неизменны до получения ответа по отдельному каналу.
Каждый принятый запрос получает один коррелированный ответ; дополнительных
диагностических событий об успешном обмене нет. Nil reply игнорируется без
изменения состояния; отрицательный ID получает Invalid.

| Операция | Вход | Результат и ресурсы |
| --- | --- | --- |
| OpenDir | cursor=0, корректный путь | Ok, положительный big ID и fstat открытого каталога; без первой порции. |
| NextDir | живой положительный ID | Ok с 1–32 записями либо End/nil в конце. |
| CloseDir | живой ID | Закрытие FD и удаление ID до Ok; повторное закрытие — Stale. |
| StatPath | cursor=0, путь | Копия метаданных; слот каталога не расходуется. |
| Shutdown | неотрицательный ID запроса | Все FD закрываются до Ok, затем процесс завершается. |

У владельца максимум восемь ID. Full означает исчерпание квоты или пространства
монотонных номеров. Номера не используются повторно: старый ID не откроет новый
каталог в том же слоте. ID **локален для endpoint**: передавать нужно пару
`(endpoint, cursor)`. Число другого владельца может совпасть с живым местным ID;
это не глобальная и не аутентифицированная сетевая capability. Stale означает,
что ID отсутствует/удалён именно у получившего запрос владельца.

На EOF нативный FD освобождается, но ID остаётся до CloseDir/Shutdown.
Повторный NextDir сразу возвращает End без вызова ОС. Ошибка порции возвращает
Failed без частичных записей и удаляет ID; дальше он получает Stale. Сервис не
хранит возвращённый массив в состоянии курсора: клиент вправе менять его.
Записи живут после закрытия; FD и указатели ОС наружу не передаются.

Путь содержит корректные Unicode-скаляры, без NUL, 1–4096 UTF-8 байтов. Длина
в скалярах проверяется до выделения памяти для UTF-8. OpenDir/StatPath требуют
cursor=0; NextDir/CloseDir не читают path. Неизвестная операция — Invalid.
Обычный файл не становится курсором. Android content:// отвергается OS-портом.
Сообщения об ошибках — обычные строки, не код и не разметка.

Служебные массивы скаляров инициализируются явно: обычное выделение такого массива
в Limbo оставляет содержимое неопределённым. Неявное предположение о нулях
ошибочно при повторном использовании памяти. Ссылочные массивы получают обычное
nil-состояние VM. Закрытие очищает ссылки владельца до ответа.

## Выполнение и проверка

Нативный вызов пока блокирует единственного владельца VM. Отдельные процессы Dis
не делают I/O асинхронным. Непрочитанный ответ блокирует этот сервис; отмены
брошенного запроса, сетевой аренды и фоновых workers здесь нет. Обход не атомарен
и не отсортирован. Изменения каталога, невалидное UTF-8 имя и оборванная ссылка
могут привести к ошибке порции. Для ограниченного полного сортированного списка
можно использовать Readdir; потоковый сервис весь каталог не накапливает.

В runtime 0.27.0 явный `--max-instructions COUNT` имеет приоритет над прежним
лимитом квантов. Поэтому quantum=1 не обрывает разрешённую программу после
100000 инструкций. Без параметра сохраняется прежняя политика ограничения
работы между событиями ввода/UI. Явный предел общий и точный, не сбрасывается
вводом и не зависит от quantum; он не отменяет зависший вызов ОС.

Пример проверяет Unicode, двоичный NUL, разреженный файл 4294967303 байта,
74 элемента в трёх порциях, независимость массивов, жизнь метаданных, пустой и
ошибочный каталоги, EOF, квоту, некорректные запросы и старые ID. Выполняются
32 цикла запуска/завершения владельца с открытыми FD. Оба режима проверяются
с quantum 1/2048. Консольный replay дополнительно проверяет сохранение документа,
ошибку замены каталога, экранирование и закрытие с активным курсором.
Клиент превышает 100000 инструкций и проверяет исправление квоты.
Нативно проверяется Linux AMD64. Ограничения остальных OS-портов сохраняются;
/prog, сетевой протокол объектов, объектный mutex и новые конструкции компилятора
этот сервис не реализует.
