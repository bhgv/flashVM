# Последовательность приёмки интеграции Dis

Это план работ, а не реализация и не отчёт о пройденных тестах. [English](DIS_ACCEPTANCE.md).

1. **Выделение runtime.** Собрать библиотеку интерпретатора Dis с явной ревизией и лицензиями. Проверка линковки/регистрации подтверждает отсутствие Inferno Draw/Tk/Prefab и crypto/Keyring. Запустить настоящий скомпилированный модуль Limbo; успешные фиктивные замены модулей не подходят.
2. **Жизненный цикл host.** Определить loader, allocator, scheduler budgets и shutdown adapters. Проверить строки, массивы, exceptions, вызовы модулей, spawn, buffered/unbuffered channels и alt. Проверить heap roots и teardown отдельно от коллектора FlashVM. Приёмку интерпретатора и JIT разделить.
3. **Локальный канальный мост.** Настоящий Limbo send/receive работает с типизированным endpoint ресурсов FlashVM. Запросы копируются и ставятся в очередь владельцу VM; replies/events возвращаются через каналы. Проверить блокирующие операции, cancellation, queue limits, disconnect, поколения handles и teardown pending operations без блокировки display/input pump.
4. **Первый UI-контрол.** Модуль Limbo создаёт MovieClip/TextField через канальный сервис, изменяет текст, получает настоящее событие ввода и удаляет контрол. Добавить недостающие канальные операции; прямой вызов из приложения границу не обходит. Неизвестные capabilities возвращают unsupported.
5. **Срез редактора.** Документ редактора и сложный контрол на Limbo собраны из примитивов FlashVM: text editing, cursor/selection, focus, scrolling, keyboard input и dirty-document indicator. Open/save и ответы команд проходят через каналы. Одной отрисованной надписи недостаточно.
6. **Build/debug services.** Native API компилятора/оптимизатора/линкера вызываются за каналами и возвращают коррелированную диагностику. Подключаются launch/stop/debug. Развёрнутая IDE не требует host Python driver. Для Limbo используется настоящий компилятор, а не численный учебный поднабор FIR.
7. **Распределённость и платформы.** Показать те же Limbo-операции через второй транспорт без изменения UI logic. Явно проверить ordering, backpressure и ошибки; локальные каналы сами по себе не доказывают сетевую распределённость. Упаковать модули IDE с FlashVM и отдельно принять выбранные OS/CPU/devices.

Перед отметкой implemented каждый шаг требует исполняемых тестов и краткого EN/RU-контракта. Не предполагается, что все Dis JIT и любые библиотеки Inferno можно встроить без изменений. Недостающие примитивы FlashVM могут стать явными расширениями built-ins; совместимость SWF <= 8 и приёмка расширений остаются отдельными задачами.

## Обязательная приёмка JIT/debug targets

После запуска interpreter/bridge отдельно принять x86/i386, x86-64, arm64 и riscv64 с доказательством JIT-entry и эквивалентности отладки. Успех одного интерпретатора этот пункт не закрывает. Runtime изолируется в flashVM/external/dis/. См. [обязательные контракты отладки](ARCHITECTURE.ru.md).
