# Каналы Dis, представление AS и параллельный native-рендер

Текущее исполнение: графический редактор готовит независимые контуры у владельца
и растеризует их на одном постоянном фоновом потоке. Показывается только последний
результат; раскладка/AS/GC и SDL остаются у своих владельцев. [Контракт очереди](../flashVM/doc/RENDER_ASYNC.ru.md).

[English](RENDER_OWNERS.md) · [Нативные C-модули](../disVM/runtime/NATIVE_MODULES.ru.md) ·
[AS2 → FIR → SWF](../compiler/as2/view/README.ru.md) ·
[API заданий рендера](../flashVM/include/flashvm/render_jobs.h)

Прямой путь **DisVM → типизированные каналы → Flash-контент** сохраняется.
AS не становится обязательным посредником для каждого свойства и команды.
Перенос сложного представления с C на AS меняет сборку виджетов, не канальный
контракт. Логика приложения/документа/брокера остаётся Dis/Limbo; AS может
реализовать представление и поведение визуальных компонентов FlashVM.
C предоставляет расширения, например колоризаторы/рендер-примитивы, и OS-порты.

| Работа | Владелец и конкурентность |
| --- | --- |
| Документ, ревизии, маршрутизация | Сервис Limbo, типизированные каналы остаются основой. |
| Живые AS-объекты, callbacks, изменение дисплея | Владелец контекста FlashVM, сериализованно. |
| Независимые AS workers | Отдельные контексты/кучи и проверенные сообщения, не общая mutable VM. |
| Растр независимых клипов/областей | Неизменяемые входы, раздельные выходы, возможна параллельная работа. |
| Применение результата и публикация кадра | Владелец проверяет ревизию/поколение, порядок и отмену. |

Исходная однопоточность event/execution owner AS1/2 не заставляет считать все
пиксели одним потоком. Существующий `fvm_render_jobs_run` — синхронный примитив
параллельных заданий: callbacks не исполняют живой AVM1 и не меняют общий дисплей;
перед возвратом выполняется join. Сам по себе это не законченный SWF-рендерер.
Тысячи клипов/грязных областей нужно разбивать на ограниченные порции или пул,
а не создавать неограниченно по потоку на объект.

Колоризатор получает копию ограниченного окна исходника, язык, ревизию,
Unicode-смещение и ID. C вычисляет диапазоны без вызовов API VM и возвращает
проверенные копии. Владелец отбрасывает устаревшие/отменённые результаты и
применяет только к соответствующему виду. Очередь требует обратного давления
и определённого времени жизни буферов. Полная асинхронная интеграция колоризатора
и перенос всех виджетов ещё впереди; простой AS-профиль их не доказывает.

Нынешняя IDE уже общается через Dis-каналы и исполняет AS-представление через
FIR/SWO/SWL/SWF. Часть прежней отрисовки глифов/диапазонов пока нативная.
Нативный модуль не получает обход UI-протокола. Кучи VM остаются раздельными;
адрес C не становится канальной ссылкой.

[Экспериментальный renderer отдельной репозитории](https://github.com/bhgv/inferno-os_gfx-engn/tree/master/libinterp/graph)
проверен без импорта Cairo/GUI в DisVM. Исправленные публикация завершения,
ограниченные порции и работа с общим текстовым helper только владельцем
показывают полезные границы. Для вызова по-прежнему нужен неизменяемый ациклический
граф; остаются фиксированный scratch-canvas и кооперативное ожидание join.
Это не доказательство безопасной конкурентной мутации графа или готовности всех ОС.
