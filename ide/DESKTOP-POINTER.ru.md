# Каретка и выделение по геометрии глифов — v0.1675

[Рабочий стол](DESKTOP.ru.md) · [Жизненный цикл окон](DESKTOP-LIFECYCLE.ru.md) ·
[English](DESKTOP-POINTER.md) · [Переносимый пример](dis/examples/desktop-pointer/README.ru.md)

Клик по тексту редактора ставит каретку. Shift-клик расширяет выделение от прежнего
anchor; перетаскивание внутри тела выделяет диапазон. Ввод заменяет полный
допущенный диапазон через существующие Ideinput/Idecore и обычный undo. Под текстом
рисуются настоящие MovieClip-прямоугольники выделения; их же показывает миниатюра.
Клавиатурное выделение использует тот же путь представления.

![Настоящее выделение по глифам](assets/desktop-v0.1675.png)

Клик по телу другого редактора активирует его без скачка стола. Заголовки по-прежнему
перемещают окна, пустое место прокручивает стол, кнопки закрытия сохраняют свою
защиту dirty. Help и build-консоль остаются нередактируемыми.

## Три независимых допуска

1. Владелец FlashVM измеряет настоящую матрицу завершённого MovieClip и ту же
   геометрию шрифта/wrap/tab, по которой рисуются каретка и выделение. Он предлагает
   стабильный ID и Unicode-позицию внутри скопированного TextField. Верхние свитки,
   боковые панели, заголовки и кнопки закрытия не превращаются в текстовые попадания.
2. Limbo layout независимо проверяет тело окна, ticket и порядок перекрытия.
   `Activate` меняет фокус без прокрутки. Нативная геометрия сама по себе не даёт
   права выбирать произвольного владельца документа.
3. Окно преобразует позицию видимого текста в полный исходник и проверяет точную
   revision/диапазон. Полные anchor/caret остаются в приватном Ideinput. Новый
   snapshot также не даёт статусу предыдущей отклонённой команды мешать корректному
   выделению той же revision. Выделение не меняет исходник, saved, файлы, результат
   компиляции или undo.

Root хранит revision показанного документа, смещение начала viewport и длину
caption для полной сцены. UTF-8 byte clusters преобразуются в Unicode-символы;
байты заголовка не являются координатами исходника. Полные границы документа
сохраняются у владельца, даже когда подсветка обрезана текущим viewport.
Нативные объекты, шрифты и управляемые указатели между VM не передаются.

## Отмена жеста

Begin/move/end идут по порядку 1/2/3. Begin запоминает приватный anchor, либо оставляет
прежний при Shift. Move/end без допущенного begin отвергаются. Устаревшие source
revision/view, повреждённые метаданные, потеря фокуса, другой ввод, модальное решение,
колесо/resize и выход из тела отменяют продолжение. Позднее отпускание не оживляет
жест. Отмена сохраняет исходник и уже допущенное выделение; она не изображает
редактирование и не откатывает прежние концы диапазона.

Первый вариант выделяет внутри видимого тела. Захват через другие окна и
автопрокрутка за пределами тела ещё не подключены. Логические позиции — Unicode
scalars; визуальные глифы/кластеры определяют попадание и подсветку. Полная навигация
по grapheme и bidi-affinity этим не заявляется. Для перевода строки не рисуется
дополнительная заливка всей строки. Clipboard ещё интегрируется отдельно.

## Протокол значений

Нужно вместе пересобрать/установить согласованные `.m`, `.dis` и native runtime.
Item содержит девять hex-слов: parent, x, y, width, height, style, caret, mirror,
anchor, затем counted UTF-8. Скрытая граница — `ffffffff`. Предложение указателя
содержит четыре слова: phase, button, widget, TextField scalar offset; нет попадания
— widget=0/offset=`ffffffff`.

`Idedeskpane.Place` получает Uibridge Request: code=phase, flags=точная source
revision, first=абсолютная Unicode-позиция, second=Shift 0/1. `CancelPointer`
отменяет только жест. Reply.anchor обрезан видимым телом; полный anchor приватен.
Layout `TextHit` проверяет тело/ticket и не редактирует документ. Это ограниченные
канальные значения, не новый контейнер SWF/Dis и не новый парсер.

Измерение/рисование остаётся на владельце FlashVM, в отделённое представление
уходят завершённые пиксели. Процессы Limbo кооперативны. Проверяется настоящий
AMD64 interpreter/JIT, glyph readback/raster, Unicode/CRLF, перемещённые окна,
независимый фокус, dirty/modal-защита и stale/cancel. Физический touch и остальные
CPU/OS остаются отдельной приёмкой.
