## Разделение обязанностей

Dis владеет документом, ревизиями, Undo/Redo, курсором и выделением, политикой
команд, индексом автодополнения и координацией сервисов. Компиляция/отладка,
проекты и доступ через виртуализованную ФС должны подключаться здесь же.
Провайдеры имён используют декларации Coco/R-фронтендов и `.m`-интерфейсов;
второй самописный парсер программ ради автодополнения не добавляется.

AS ближе к отображению: его задачи — видимые текстовые окна, эффекты, палитры,
список подсказок и быстрая лексическая подсветка на собственном исполнении/JIT.
Работник подсветки получает значения, не MovieClip/TextField. Результат применяется
только UI-владельцем и только при совпадении ревизии, окна и задания. Независимый
AS-работник не превращается в конкурентного владельца display list.

Это распределение допускает дальнейшую композицию каналов между процессами и
машинами. Наличие локального envelope не объявляется готовой 9P/Styx-сессией,
виртуальной ФС или распределённым запуском: соответствующие модули ещё предстоят.

## Что выполняется в Dis

`Idebridge.serveapp` создаёт настоящий документный owner `Idecore` и использует
`Ideinput` для ввода. Текст вставляется одним путём Text, не дублируется из ASCII
клавиш. Left/Right/Home/End, Shift-выделение, Backspace/Delete, Ctrl+A/Z/Y и потеря
фокуса обрабатываются в Dis. Внешняя подтверждённая правка синхронизирует выбор
через `observe`; непредвиденная смена ревизии не приводит к автоматическому
удалению по старым координатам. Pointer пока возвращается как необработанный:
пиксельное попадание в текст/геометрия указателя ещё не подключены.

`Idebridge.serve` остаётся вариантом композиции: он передаёт сырые события в
другой Dis-сервис через типизированный канал. Оба варианта используют обычные
Dis rendezvous, а не потоки ОС вместо `spawn`.

Снимки документов разбиваются на сообщения с максимумом 1024 UTF-8 байта payload.
Каждый снимок содержит 56 байт метаданных и до 968 байт текста в одном фрагменте.
Границы не разрезают Unicode. AS собирает весь снимок и лишь затем показывает его.
Один запрос по-прежнему ограничен 1024 байтами: загрузка большого файла требует
отдельного потокового файлового/редакторского протокола, она не объявляется готовой.

`Idecomplete` — отдельный владелец индекса. Публикация копирует/проверяет весь пакет,
сортирует merge sort и только затем меняет поколение. Поиск использует binary search
и ограничивает результат 64 элементами. Выдаваемые записи также копируются.
Начальный Idebuiltins содержит 135 AS и 64 Limbo декларации с параметрами и
короткой справкой; проверяются перегрузки, optional/rest параметры и call tips.
Провайдер символов из фактических выводов компиляторов пока не подключён;
тестовые кандидаты не выдаются за семантический анализ текущего файла.

## Подсветка и автодополнение на экране

`syntax-worker.as` сканирует ограниченное окно AS/Limbo и возвращает диапазоны,
state/escape/star для следующего смежного окна, ревизию и ticket. Это лексическая
окраска, не Coco/R-парсер и не новая реализация семантики языка. Regex/E4X, полная
семантика чисел, вложенные языки и семантические категории пока не реализованы.

`presentation.as` принимает готовые Dis-снимки/выделение и результаты работников.
Устаревшее задание или поколение индекса не меняет отображение. Его callbacks
выполняет только UI-владелец. Отказ renderer при нанесении syntax spans возвращается
как отказ, а не подменяется успешной колоризацией.

В текущем FlashVM `TextField.setTextFormat` меняет стиль всего поля. Смешанные
цвета по диапазонам ещё не поддержаны. Для настоящей колоризации одного поля
нужно расширение, описанное в [TEXT-COLOR-EXTENSION](TEXT-COLOR-EXTENSION.md).
Нативная отрисовка mixed colour spans, popup виджеты, полноценный AS-worker launch
и встроенный запуск всего приложения ещё не прошли сквозную приёмку.

## Сборка и честные границы проверок

Обычная `./build-workspace.sh --projects ide` теперь явно передаёт SDK кодека и
собирает `idecore`, `uibridge`, `ideinput`, `idebridge`, `idecomplete`, `idebuiltins` с `.sbl`.
Дополнительный `emu` для компиляции не нужен. Собранный из исходников bootstrap
остаётся временным: собственный Coco/R Limbo/FIR-компилятор остаётся приоритетом.

На Linux AMD64/CMake 3.10.2 прошёл набор из 43 нативных тестов Dis/моста, включая
настоящие movers, ожидание/ошибки и ввод FlashVM. Шесть новых прикладных запусков
прошли в явно выбранном **эталонном** runtime, в режимах 0 и 1: цепочка редактора
проверяет 36 декодированных кадров, индекс — поколения/префиксы/копирование, каталоги — AS/Limbo параметры/перегрузки.
Это не исполнение всей IDE в нашем ещё незавершённом Dis-хосте и не приёмка
64-битного JIT по факту одного выбора режима.

Модули также компилируются нашим source-built bootstrap. Его Dis/frame ABI нельзя
считать совместимым с чужим runtime: проба с другой парой была отвергнута loader.
Для reference-запуска нужен согласованный compiler/header/runtime набор.
AS2-фронтенд разбирает оба AS-файла; Node дополнительно проверяет алгоритмы и
stale-result gates. Это не доказательство исполнения этих файлов как SWF/JIT.
Python/Node — только необязательные хостовые проверки, не runtime IDE.
