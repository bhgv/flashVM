## Идентификаторы и позиции исходного текста

AS1/AS2 0.4.0 и AS3 0.5.0 принимают UTF-8-имена и точные escape-последовательности
`\uXXXX`. Первый символ: `$`, `_` либо категория Lu/Ll/Lt/Lm/Lo/Nl. Продолжение
допускает также Mn/Mc/Nd/Pc и U+200C/U+200D. Данные зафиксированы на
**Unicode 3.2.0**: версия libc не меняет язык. Более поздние Unicode-символы не
включаются автоматически. Это явный профиль, а не обещание точного поведения
всех выпусков Adobe Flash. Escape суррогатного code unit недопустим в имени;
прямые supplementary UTF-8-буквы, существующие в этой базе, допустимы.
Нормализация и разрешение имён относятся к будущему семантическому проходу.

ATG задаёт байтовую запись и проверки категорий. Каждый отделяемый фронтенд
содержит собственный одинаковый `unicode_ident.inc`. В корне репозитория:

```sh
python3 tools/generate_parser_unicode.py
python3 tools/generate_parser_unicode.py --check
python3 tools/atg_format.py --check compiler/*/frontend/*.atg
```

Скрипт разработчика использует неизменяемую `unicodedata.ucd_3_2_0` Python и
сверяет список зарезервированных слов с литералами грамматики. Сама C99-сборка
использует готовые данные и не требует Python, ICU или Unicode-функций wchar_t.
Escape не позволяет объявить переменную с именем ключевого слова. AS3 отдельно
сохраняет IdentifierName свойств: `obj.\u0069f` и `{\u0069f: 1}` допустимы,
а `var \u0069f=1` отклоняется.

Unicode-пробелы, BOM как пробел, VT/FF и LS/PS больше не становятся частями
идентификатора. Исходные байты не переписываются. Смещения диагностики остаются
байтовыми; столбцы считают UTF-8-байты с табуляцией по восемь позиций. CRLF
считается одним переводом, CR/LF/LS/PS меняют строку. Монотонный курсор позиций
обходит также текст raw XML/regexp. `//` завершается любым из четырёх переводов.
Контекстное опережающее чтение меток, metadata и типов учитывает те же пробелы.

## Строковые литералы

Проверяется запись `\xHH` и `\uHHHH`. Строки сохраняют UTF-16 code units:
суррогатный escape здесь разрешён, в отличие от имени. Экранированные CR, LF,
CRLF, LS и PS продолжают строку; неэкранированные переводы недопустимы.
Вычисление значений строк, помещение их в AST и преобразования типов не добавлены.

## Regexp AS3

Лексическая цель `/.../gimsx` выбирается только для операнда, отдельно от `/` и
`/=`. ATG разбирает альтернативы, пустые ветки, группы/захваты, lookahead,
lookbehind/atomic groups, AS3 `(?P<name>...)`, числовые и именованные ссылки,
классы/упорядоченные диапазоны, control/hex/Unicode escapes, assertions,
квантификаторы и lazy/possessive-суффиксы. Режим `x` учитывает ASCII-пробелы и
`#`-комментарии вне классов. Десятичные границы сравниваются как участки цифр,
без переполнения целого числа платформы.

Неверные разделители, группы/escape, повторные имена, отсутствующие ссылки,
обратные диапазоны, квантификаторы assertions и повторные квантификаторы дают
E1103. Рекурсию ограничивает общий guard. На паттерн хранится до 512 именованных
определений и 512 ссылок; числовые ссылки находятся в диапазоне 1..99.
Это ограниченный структурный парсер, не компилятор и не исполнитель regexp.
Фиксированная длина lookbehind, все PCRE-расширения и режимы совместимости не
проверяются. Inline PCRE options и трактовка неправильных фигурных скобок как
обычного текста не входят в профиль. Принятие не доказывает совместимость с
конкретным regexp-движком Adobe.

[Группы](https://airsdk.dev/docs/development/core-actionscript-classes/using-regular-expressions/regular-expression-syntax/groups) ·
[Квантификаторы](https://airsdk.dev/docs/development/core-actionscript-classes/using-regular-expressions/regular-expression-syntax/quantifiers) ·
[ECMA lexical rules](https://262.ecma-international.org/5.1/#sec-7.6).

## Директивы, Vector и Limbo

AS3 принимает `new <int>[1,2]`, вложенные типы, пустой initializer и одну
завершающую запятую, затем обычные обращения/вызовы/индексы. Дырки array
недопустимы в typed initializer. `CONFIG::debug { ... }` принимается среди items;
в классе такой блок содержит members. Значение CONFIG не вычисляется, namespace
и привязка имён относятся к семантике. `include "file.as"` не читает файлы хоста.

В Limbo поиск внешней стрелки учитывает initializer-скобки после `of`, круглые
и квадратные скобки. Стрелки в строках, комментариях и вложенных initializer
не меняют границу ветки. Это позволяет следующему qualifier case/alt содержать
list literal или parenthesized array expression. Константность qualifier,
направление каналов, типы и type/value binding проверяются отдельно. Limbo не
получает AS Unicode escapes или автоматическую вставку точек с запятой.

## Генерация и переносимость

Пять самостоятельных синтаксических проектов удаляют старые generated-файлы
перед запуском внешнего host Coco/R, проверяют код возврата, диагностику и
наличие результатов. Регрессионный тест начинает со старых файлов и подаёт
неправильную грамматику. После неудачной сборки нельзя считать запуск старого
бинарника проверкой новых исходников; тесты запускаются после успешной сборки.

Проверенный Coco/R master b91b652 уже возвращает ошибку для неверной грамматики;
исправление exit status не требуется. Отдельная подтверждённая ошибка исправляет
параметры `errno` на `error_number` в C parser frames и self-hosted исходниках.
Windows stdlib.h может определять макрос `errno`, меняющий тип такого параметра.
Перед Windows cross-generation примените приложенный патч Coco/R либо используйте
upstream с этим исправлением. Host-генератор собирается командой
`make -C sources -f unix.mk`; пути к его frames и бинарнику передаются CMake
явно. Код, runtime и документация внешнего Coco/R в FlashVM не копируются.

Проверяются обычные и отделённые/переименованные сборки compiler/FIR. Кросс-цели:
ARM64 Linux/musl, RISC-V64 Linux/musl, Windows x86-64/GNU. Проверяются ELF/PE,
исполнение на других платформах не заявляется. Команды явного выбора SDK находятся
в [BUILDING.ru.md](../BUILDING.ru.md).
