Проект AS2 получил ограниченный исполняемый профиль через общий тракт:

**Фронтенд AS2 → FIR 1.0 → проверки/пипхолы → целевой компилятор → SWO → SWL → SWF.**

`as2_check` проверяет весь исходник, затем созданный Coco/R парсер профиля выдаёт
текстовый FIR. Прямого emitter AVM1 во фронтенде нет. Константы, преобразования и
арифметика используют существующие операции FIR; три новые операции обслуживают
глобальные AS-значения и запись свойств. Инструкции создаёт backend FIR, контейнер
SWF — существующий линкер SWL.

IDE встраивает связанный SWF и исполняет его команды во FlashVM при каждом
завершённом представлении. Компилятор, парсер, Node и Python при работе IDE не нужны.
Unicode-строки и локальные объекты UI привязываются в контексте FlashVM; Dis
передаёт проверенные значения, никогда адреса чужой кучи.

## Реализованный синтаксис

Непустая последовательность присваиваний с явной `;`:
`object.property = expression;` и `global = expression;`. Есть чтение глобальных
значений, неотрицательные десятичные int32, булевы константы и `+ - * /` с обычным
приоритетом. `+` понижается в динамический `as.add`; остальные операции сначала
используют `as.to_number`, затем арифметику f64. Переданные строки сохраняют
семантику AS. Объект левой части читается до вычисления правой. Поддержаны
ASCII-имена, пробельные разделители и `//`, включая комментарий в конце файла.
Unicode-данные приходят как значения во время исполнения.

Функций/вызовов, строковых литералов исходника, вложенного чтения членов,
скобочных выражений, условий, классов и общего понижения AS2 пока нет. Общий
фронтенд распознаёт больше, чем генерирует этот профиль; неподдержанное явно
отвергается. Пределы: исходник 16 КиБ, имя 253 байта, текст FIR 64 КиБ. Комментарии
присваиваний сохраняют строку/колонку/байтовую позицию AS, но не заменяют полную
отладочную карту. Цель профиля сейчас AVM1/SWF. Dis отвергает операции AS-объектов
до появления типизированного адаптера и backend для чужих объектов.

## Сборка и весь тракт

Из корня репозитория, после сборки поставляемого Coco/R:

```sh
# Один проект AS2 собирает общий фронтенд, CLI и библиотеку профиля.
cmake -S compiler/as2 -B build/as2 \
  -DCOCOR_ROOT="$PWD/tools/coco-r-C/upstream" \
  -DCOCOR_EXECUTABLE="$PWD/build/cocor/cocor"
cmake --build build/as2 -j4
ctest --test-dir build/as2 --output-on-failure
# FIR и SWL остаются самостоятельными инструментами.
cmake -S fir/v1 -B build/fir \
  -DCOCOR_ROOT="$PWD/tools/coco-r-C/upstream" \
  -DCOCOR_EXECUTABLE="$PWD/build/cocor/cocor"
cmake --build build/fir -j4
cmake -S linker -B build/linker
cmake --build build/linker -j4
# Каждый промежуточный продукт доступен для проверки.
build/as2/view/as2_viewc ide/as/editor-view.as build/editor-view.fir
build/fir/fir1 check build/editor-view.fir
build/fir/fir1_opt build/editor-view.fir build/editor-view.opt.fir
build/fir/fir1 object build/editor-view.opt.fir build/editor-view.swo
build/linker/swl link build/editor-view.swf build/editor-view.swo
```

`build-workspace.sh --projects disvm-editor` сначала собирает либо переиспользует
AS2, FIR и SWL. Прямой CMake редактора получает явные пути `DVM_AS_VIEW_COMPILER`,
`DVM_FIR_COMPILER`, `DVM_FIR_OPTIMIZER`, `DVM_SWF_LINKER`. В `native/` остаются
`.fir`, `.opt.fir`, `.swo`, `.swf`. Инструмент встраивания копирует только готовый
контейнер: исходный язык он не разбирает и команды VM не генерирует.

`compiler/as2/view` можно собрать отдельно с явным SDK; общий фронтенд берётся
из `../frontend`. Для отдельной поставки переносится весь проект AS2.

## Библиотека, CLI и ошибки

Цель `as2_view`, API `as2_view_compile` и CLI `as2_viewc` используют один код.
Вход, выход и диагностика принадлежат вызывающему; вызовы сериализуются с общим
AS2-фронтендом. Библиотека не выполняет I/O/подпроцессы и не хранит входной
указатель. Ошибка даёт `written=0` и не меняет выход; сбой выделения памяти сканера
перехватывается. Внутренние буферы переиспользуются. Реентерабельность и
одновременные вызовы отсутствуют. CLI пишет FIR без завершающего NUL. Ошибка
разбора оставляет старый файл: код завершения обязательно проверять. Сборка IDE
останавливается при ошибке любого этапа.

## Проверки и оставшийся объём

Библиотечный тест проверяет 600 циклов ошибки/восстановления и неизменность выхода
при нехватке места. Тесты FIR проверяют типы, порядок эффектов, повторный разбор
печатного результата и отказ цели Dis. `disvm_as_view_execution` загружает
**связанный SWF** во FlashVM, меняет геометрию, проверяет Unicode и запускает GC.
Графические повторы проверяют настоящий TextField, выделение и мышь. Физические
окна и сенсорный ввод требуют отдельных испытаний.

Общие AST/FIR для AS, функции/вызовы, полные отладочные карты и перенос остальных
C-виджетов редактора ещё впереди. Документом/браузером управляет Limbo; AS задаёт
реализованные текст и геометрию; шрифт, растр, окно и OS-порты остаются примитивами.

The current profile emits one `@ide_view` initializer; combining multiple profile units requires distinct module naming in a later API. / Текущий профиль выдаёт один инициализатор `@ide_view`; выбор разных имён модулей для нескольких единиц — следующий шаг API.
