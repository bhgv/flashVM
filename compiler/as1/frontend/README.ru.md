# Синтаксический фронтенд AS1

Версия 0.1.0. [English](README.md).

Читаемый файл [as1.atg](as1.atg) — исходник сканера и парсера.
Используется C-бэкенд [bhgv/coco-r-C](https://github.com/bhgv/coco-r-C).
Встроенные предикаты, драйвер и генерируемый код собираются как C99 без расширений.
Это распознаватель синтаксиса. AST, таблица символов, проверка типов, генератор
байткода и запись SWF пока отсутствуют.

## Сборка и отделение

Нужны уже собранный внешний C-генератор и соответствующая ему папка `frames/`.
Его исходники, шаблоны и документация в репозиторий не копируются.
Команды из этой папки фронтенда:

```sh
cmake -S . -B build \
  -DCOCOR_ROOT=/absolute/path/to/coco-r-C \
  -DCOCOR_EXECUTABLE=/absolute/path/to/coco-r-C/cocor
cmake --build build
ctest --test-dir build --output-on-failure
./build/as1_parse /path/to/source
```

Готовой программе генератор не нужен. Python 3 используется только тестами;
для сборки без него задайте `-DBUILD_TESTING=OFF`. Нужны CMake 3.16+ и C99-компилятор.
При многоконфигурационной сборке Windows программа находится в папке выбранной
конфигурации, например `build/Debug`; запуск на Windows здесь не проверялся.
Необязательная сборка всех фронтендов: [../../CMakeLists.txt](../../CMakeLists.txt).
Те же параметры работают при сборке из родительского проекта языка.

Папку можно копировать и переименовывать: сборка не требует FlashVM, линковщика,
соседних фронтендов и файлов общего корня. В отдельном дистрибутиве сохранить
общую корневую MIT LICENSE и уведомления авторов шаблонов в генерируемых файлах.
C-код и заголовки создаются только в `build/generated/` и не коммитятся.
У каждого фронтенда отдельная программа: глобальные имена генерируемого кода
пока не допускают объединение в библиотеку и конкурентные вызовы.
Один исходный файл разбирается за один запуск процесса.

## Драйвер и диагностика

[main.c](main.c) открывает один файл, проверяет UTF-8 и перематывает тот же
дескриптор перед разбором. Отклоняются некорректные, усечённые и избыточные
последовательности, суррогаты, значения выше U+10FFFF и встроенный NUL.
Начальный UTF-8 BOM поддерживается выбранным генератором. Нужен файл с возможностью
позиционирования. Позиции и столбцы считаются **в байтах**. Категории Unicode в
именах и семантика escape-последовательностей пока отдельно не проверяются.
Строки сохраняют исходные байты.

| Функция драйвера | Назначение и контракт |
| --- | --- |
| [main](main.c#L97) | Один путь; открывает/закрывает файл; код 0 — синтаксис принят, 1 — ошибка синтаксиса/кодировки, 2 — ошибка аргументов или ввода-вывода |
| [validate_source](main.c#L33) | Проверяет кодировку без изменения байтов; возвращает 0/1/2; после успеха перематывает дескриптор |
| [report_error](main.c#L85) | Синхронный callback парсера: путь, строка, байтовый столбец, текст/номер ошибки и смещение; памятью не владеет |

`Parse`, `Successful` и `Custom_Error` — интерфейсы генерируемого кода, пока
не публичный стабильный API компилятора. Восстановление после ошибки не обещает
полный список диагностик; ориентироваться на код завершения. Принятый синтаксис
не подтверждает корректность типов, левых частей присваивания, модификаторов,
положения return/break или совместимость будущего байткода/SWF.

## Покрытие и границы синтаксиса

Поддержаны переменные, функции/замыкания, литералы объектов и массивов (включая
пропущенные элементы), цепочки вызовов/полей/индексов, метки, условия и циклы,
for-in, switch, try/catch/finally, with, return и throw. Для приоритетов выражений
есть отдельные правила; присваивание и тернарный оператор рекурсивны справа.
LabelAhead распознаёт метку через пробелы/комментарии без потребления токенов.
Явные предикаты различают блок/объявление функции и выражение, а else связывают
с ближайшим if. Есть проверки принятия и отклонения программ.

Первая версия требует явных точек с запятой. Автоматическая вставка `;` и правила
перевода строки для return/postfix пока не реализованы. Пока отсутствуют литералы
регулярных выражений, общий оператор выражения `in`, препроцессор (`#include`),
контекст привязки к timeline `on`/`onClipEvent`, escape в идентификаторах и полная
проверка категорий Unicode в именах. Это начальный явно ограниченный профиль,
а не заявление о полном соответствии языку AS. Исходный текст не исполняется.

## Проверки

[tests/check.py](tests/check.py): генерация/сборка на Linux, корректный и ошибочный
синтаксис, UTF-8/BOM, повреждённые кодировки, NUL и отсутствующий входной файл.
Время каждого процесса ограничено. Проверена также сборка и тесты отдельно
скопированной и переименованной папки фронтенда с `-pedantic-errors`.
