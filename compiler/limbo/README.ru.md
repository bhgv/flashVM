# LIMBO

Версия 0.6.3. [English](README.md).

Независимый проект компилятора на C99. Сейчас реализован синтаксический
фронтенд: [грамматика, сборка и ограничения](frontend/README.ru.md).
Добавлено [дерево конкретных правил с собственным владением](frontend/TREE.ru.md).
Семантический анализ, типизированный AST, генерация байткода и SWF пока не реализованы.

Сборка из этой папки с теми же явными путями к генератору:

```sh
cmake -S . -B build \
  -DCOCOR_ROOT=/path/to/coco-r-C \
  -DCOCOR_EXECUTABLE=/path/to/coco-r-C/cocor
cmake --build build
ctest --test-dir build --output-on-failure
```

CLI: `--help`, `--version` (без входного файла; код 0).

## C API

`frontend/frontend.h`: `limbo_check(bytes, size, diagnostic)` и
`limbo_read(FILE*, diagnostic)` возвращают 1 при принятии, 0 при отказе.
Буфер и поток принадлежат вызывающему коду; библиотека не печатает сообщения,
не закрывает вход и не завершает процесс. Диагностика: код, строка/колонка,
байтовое смещение, сообщение. NULL вместо диагностики допустим. Максимум 2 MiB.
CMake target: `limbo_frontend`. Глобальные символы генератора имеют префикс языка;
несколько библиотек могут линковаться в одну IDE. Состояние сбрасывается перед
каждым вызовом, но один парсер требует внешней сериализации (не reentrant).
`tests/embed.c` проверяет восстановление после ошибки в одном процессе.

### Синтаксис 0.3.5

Добавлены `list of {a,b}`, завершающая запятая array initializer, унарное `*`
и метки перед while/do/for/case/alt/pick. Типизированные объявления после
двоеточия не превращаются в метки. `a[]` отвергается; с v0.4.2 допустимы также `a[:hi]` и `a[:]`. `array[] of Type` выдаёт E1301: без размера
нужен непустой initializer. Пустой список задаётся nil, не `list of {}`.
`* =>` (wildcard) отличён от `*p` (dereference) явным предпросмотром.

[Грамматика](frontend/limbo.atg): LabeledStatement, ArrayCreation,
InitializerList, Qualifier, Subscript, Unary. [Пример](examples/Syntax.b).
Основа: [Limbo reference, разделы 8 и 9](https://www.inferno-os.org/inferno/papers/limbo.html).
Области видимости меток, типы списков/каналов и исполнение alt/pick не проверяются;
это не понижение в FIR. В C API сохраняется восстановление после ошибки.

### Ограничения разбора для C API

Рекурсивные границы грамматики ограничены 512 активными вызовами, работа —
4000000 посещениями таких границ. Превышение возвращает -3/-4 в diagnostic.code,
а не завершает IDE; после отказа можно разбирать следующий файл. Счётчики и
Coco/R сбрасываются перед каждым вызовом. Координаты при ресурсном отказе могут
быть нулевыми. Точные лимиты — не число скобок: один уровень выражения проходит
несколько правил. Это ограничение реализации, не изменение синтаксиса языка.
Проверка/разбор по-прежнему задаются .atg, guard-функции написаны на C99.

[Подробные примеры](examples/README.ru.md).

## Синтаксис 0.4.2

Добавлены implement со списком модулей, полиморфные функции/ADT/типы и for-ограничения,
exception/raises/raise и обработчики блока, fixed-типы/преобразования, **/**=,
array of byte-преобразование, завершающая запятая list и срезы с пропущенными
границами. Последний параметр * проверяется (E1302); пустые case/alt/pick и
пустое for-ограничение отклоняются. Сверка с текущей грамматикой Inferno исправила
старый запрет нижней границы среза: a[:n] и a[:] допустимы.
Include-файлы не раскрываются; cast по именованному/параметризованному типу поддержан. Символы/типы и полная
семантическая неоднозначность type/value в полиморфных аргументах ещё требуют
работы. Это не полный Inferno-компилятор и не генератор Dis.

[Полиморфный пример](examples/Polymorphic.b), [официальная грамматика](https://github.com/inferno-os/inferno-os/blob/master/limbo/limbo.y).
