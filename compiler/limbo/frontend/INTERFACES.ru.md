# Каталоги явных интерфейсов Limbo

Версия 0.6.6. C99-проход использует [дерево существующей грамматики Coco/R](TREE.ru.md),
а не второй самописный парсер языка. API — [interface.h](interface.h), реализация —
[interface.c](interface.c), утилита — [interface_main.c](interface_main.c).
Это этап объявлений для будущей генерации C по `.m`, **не готовый генератор C**.

`limbo_interface_parse(bytes,size,&out,&diagnostic)` создаёт владельца исходного
дерева, имён и записей в порядке исходника. При ошибке `*out` сохраняется; при
успехе передаётся новый владелец. Старые владельцы освобождает вызывающий код.
Вход копируется и после вызова может быть изменён. Уничтожение —
`limbo_interface_destroy`; null безопасен. Вход/выход/диагностика доступны и не
перекрываются. Разбор сериализуется с обычным синтаксическим и tree API.

`limbo_interface_tree` даёт заимствованное полное дерево, которое нельзя отдельно
уничтожать. `limbo_interface_count` — число развёрнутых записей;
`limbo_interface_declaration` копирует вид с заимствованным именем. При ошибке
выход не меняется. `limbo_interface_find(scope,name,&index)` выполняет двоичный
поиск точного имени без выделения памяти и обращения к парсеру. Область — индекс
модуля того же каталога, `SIZE_MAX` — файл. Выход за границы/не модуль дают отказ;
чужой или устаревший числовой индекс не всегда распознаваем, поэтому идентификаторы
нельзя переносить между владельцами. Имена сравниваются по байтам UTF-8 с учётом
регистра, без нормализации Unicode. Владелец синхронизирует уничтожение с чтением.

Запись хранит вид, имя, область, индекс Top-узла и полуоткрытые байтовые диапазоны
имени/DeclType. Виды: module, adt, прямой fn, constant, alias, exception, import,
value, include. Это синтаксическая классификация: значение с именованным типом,
который окажется псевдонимом функции, пока остаётся value. Диапазон типа сохраняет
исходное написание и особенности пустых правил/комментариев дерева; это не runtime
сигнатура и не нормализованный тип C. Поля/методы ADT, pick-варианты, параметры и
возвращаемые типы доступны в полном дереве, но отдельно ещё не индексируются и
семантически не проверяются.

Группы имён разворачиваются слева направо с общим диапазоном типа. Вложенные
модули имеют отдельные области. Одинаковые экспорты разных модулей допустимы;
повторные имена одной области отклоняются с байтовой позицией самого раннего
повтора. Отдельный сортированный индекс не меняет порядок записей. Повторы полей
неразобранного ADT, импортов и содержимого include этим проходом не проверяются.

Include записывается с пустым именем и диапазоном всего Top, но файл не открывается.
Неизвестные типы сохраняются без разрешения. Тела функций, выводимые/кортежные
объявления, implement, групповые определения модулей и модули, вложенные через
неиндексируемый член ADT, пока отклоняются (-6). Для групп модулей нужно честное
разворачивание областей, а не привязка всех экспортов к первому имени. Обычные
вложенные модули и группы остальных имён поддержаны.

Повтор имён — -7; свыше 16384 записей/переполнение размера — -8; отказ памяти — -2.
Прежние ограничения дерева и исходника сохраняются. Диагностика каталога задаёт
байтовое смещение, строки/столбцы пока нулевые. Частичный каталог наружу не выходит.
Пустой файл/комментарии дают пустой каталог. Проверяется отказ каждой точки
выделения владельца, индекса областей, имён, роста массива и сортированных ключей
с сохранением старого владельца и последующим восстановлением.

Утилита после обычной сборки с явными путями внешнего Coco/R:

```sh
build/frontend/limbo_interface module.m
```

Вывод: `source<TAB>размер`, `declarations<TAB>число`, затем поля через табуляцию:
`decl, index, kind, name, scope, node, name_begin, name_end, type_begin, type_end`.
Область файла — `-`. Код 0 — принят/выведен каталог, 1 — ошибка разбора/каталога/
вывода, 2 — аргументы/чтение. Частичный stdout при отказе не выводится. C-код
утилита не создаёт и не компилирует.

Внешние реальные заголовки проверяются только из явно выбранного checkout:

```sh
python3 tests/interface_upstream.py --upstream /path/to/Inferno-OS-bhgv \
  --tool /path/to/build/frontend/limbo_interface
```

Для CTest можно задать `-DLIMBO_INTERFACE_UPSTREAM=/path/to/Inferno-OS-bhgv`.
Чтение `.m` и имён таблиц Sys/Math не разворачивает include и не подключает реализации.

Dis experiment сверена на
[`0a0a007e`](https://github.com/bhgv/Inferno-OS-bhgv/commit/0a0a007ebf6c0276ada93367dde149df06efce12).
Ориентиры — `limbo/stubs.c`, `appl/cmd/limbo/stubs.b`, проходы типов/сигнатур/layout.
В старом C-компиляторе `-a` выдаёт структуры ADT/кадров, `-t Module` — native-таблицы,
`-T Module` — статическую инициализацию/заготовки C, `-A`/`-d Module` — динамические
варианты. Это ключи upstream, не новой утилиты.

Будущий backend должен сохранить padding ADT, позиции аргументов/результатов,
карты GC, хеши типов, регистрацию и динамическую инициализацию. Размер указателя
нельзя выводить из размера WORD Limbo; смещения одного хоста нельзя переносить
на другой target. Сначала нужны разрешение имён/импортов/типов и явный ABI-профиль
соответствующего Dis. Сейчас сверены только 111 имён Sys/Math, не ABI/GC/JIT/boot.

Компиляторы на C99 и Limbo сохраняют направление Coco/R `.atg` с существующим
[coco-r-limbo](https://github.com/bhgv/coco-r-limbo). Этот проход не реализует
компилятор на Limbo и не подтверждает исполнение native Limbo генератора.
Dis не импортирован; зависимости от Draw/Tk/crypto не добавлены.
