# Сигнатуры функций и первый этап проверки связывания

[English](SIGNATURES.md) · [Каталог](INTERFACES.ru.md) ·
[Общие примеры Dis/AS](../examples/external-modules/README.ru.md)

Версия 0.8.0 добавляет [signature.h](signature.h) и [signature.c](signature.c).
Они работают по существующему дереву продукций Coco/R. Дополнительного парсера,
регулярных выражений для грамматики, вызова нативного Limbo или открытия include нет.

`limbo_interface_signature(owner, declaration, &view)` возвращает узел Type
функции, её непосредственные узлы Parameters и результата, число фиксированных
аргументов после раскрытия групп имён, наличие вариативной звёздочки и синтаксических
полиморфных параметров. Отсутствующий результат — `SIZE_MAX` (void). Объявленные
группой функции разделяют исходный узел Type. Аргументы и результат вложенного
callback не смешиваются с сигнатурой внешней функции.

`limbo_interface_parameter` обращается по номеру: `a,b:int` даёт две позиции.
`limbo_interface_parameter_next` обходит позиции последовательно: сначала передайте
`SIZE_MAX`, затем предыдущий `name_node`. Возвращаются диапазон имени в байтах
исходника, узел Type/NamedType и признак self. Повторяющиеся `nil` занимают отдельные
позиции; звёздочка не является фиксированным аргументом. Числовые индексы принадлежат
конкретному дереву и не являются смещениями нативного кадра или межмодульными ID.

`limbo_interface_type_kind` определяет внешнюю форму Type: byte/int/big/real/string,
array/list/chan/ref/fn, tuple/fixed/named. Псевдонимы остаются named, вложенные типы
не разрешаются. У self-параметра возвращается NamedType и отдельный признак self.
Запросы не выделяют память и не используют глобалы парсера; при ошибке выходная
структура сохраняется. Владелец должен жить до завершения чтения, уничтожение
требует синхронизации. Индексный доступ просматривает предыдущие параметры;
для последовательной генерации используйте курсор.

`limbo_interface_validate_functions` — отдельный работающий семантический этап:
фиксированные имена параметров функции не должны повторяться, кроме заполнителей
`nil`. Сортировка временных UTF-8 ключей требует O(P log P) сравнений и O(P) памяти
на функцию. Код -9 указывает самое раннее повторное имя в первой ошибочной
сигнатуре исходника; -2 — ошибка выделения памяти, -1 — отсутствующий владелец.
Смещения и колонки считаются в исходных UTF-8 байтах, строки/колонки — с единицы,
новую строку начинает LF. Каталог при любом исходе сохраняется.
Это ещё не полная проверка типов: допустимость self, ограничения полиморфизма,
псевдонимы, импорты/include, раскладки ADT и нативные структурные подписи не реализованы.

## Генераторы

`limbo_bindings` выполняет проверку имён до открытия выходного файла для всех
форматов. Ошибка сохраняет прежний выход. JSON сохраняет схему, формат и точный
исходник; добавлено поле `signature`, null для не-функций. В сигнатуре находятся
`fixed_count`, `variadic`, `polymorphic`, упорядоченные имена/внешние виды типов,
self, узлы дерева, смещения имён и вид результата либо `void`.
AS1/2/3 получают такую же структуру в дескрипторе.

AS-модуль проверяет арность и простые аргументы до вызова реализации, затем
простой результат перед успешным ответом. AS-прокси отклоняет ошибочные аргументы
до отправки и расходования ID; ошибочный простой результат ответа завершает вызов
один раз с ошибкой. Последующий дубликат игнорируется.

| Тип | Проверка в общем подмножестве AS |
| --- | --- |
| int | Целый Number в знаковом 32-битном диапазоне, без NaN/бесконечности |
| byte | Целый Number 0..255 |
| real | Number; IEEE NaN/бесконечность допустимы |
| string | Строка либо nil как null/undefined |
| void | null/undefined |
| big, named, контейнер, callback | Разрешение/проверка/перенос остаются обязанностью хоста |

Вариативные функции проверяют фиксированный префикс и минимальное число аргументов.
Полиморфные именованные типы не разрешены. Проверки не заменяют нативный мост
Dis/SWF, владение кучами, GC-корни и официальные подписи. `big` нельзя молча
преобразовывать в теряющий точность AS Number. C-callback остаётся непрозрачной
не реализованной заготовкой; Python не нужен исполняемой IDE.

C99-тесты проверяют вложенность, группы, комментарии, Unicode, вариативность,
полиморфизм, self, недопустимые запросы, сохранение владельца между разборами,
повторные nil и восстановление после отказа выделения памяти. Проверены метаданные
генератора и сохранение старого выхода. Три Coco/R AS-парсера принимают адаптеры.
Необязательный Node исполняет сгенерированный общий AS с двойником транспорта Dis;
это не запуск SWF и не доказательство готовности нативного моста.
