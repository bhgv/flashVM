# Нормализованные координаты исходника

[English](SOURCE-POSITIONS.md) · [Пример](../examples/source-position/main.c)

Чистый C99 API `limbo_source_position` из `source_position.h` включён в
`liblimbo_frontend`. Он не запускает парсер и не меняет старые номера колонок
Coco/R или байтовые колонки interface bindings. Независимые вызовы потокобезопасны:
общего изменяемого состояния, выделений памяти, I/O и callbacks нет.

Вызывающий передаёт исходные UTF-8 байты, точный размер, смещение границы с нуля
и место для результата. Максимум — 2 МиБ. Результат содержит исходное байтовое
смещение, физическую строку с единицы и колонку Unicode-скаляров с единицы.
Табуляция считается одним скаляром. CRLF — один перевод строки; отдельные CR/LF
тоже завершают строку. Комбинируемый знак считается отдельно, astral-символ — одним.
BOM не удаляется, нормализации, display/grapheme/UTF-16 пересчёта нет.

Перед публикацией результата проверяется весь снимок. NUL, неверный UTF-8,
суррогаты, overlong, выход за диапазон, смещение внутрь символа/CRLF, слишком
большой размер и неверные аргументы дают 0 без изменения результата. EOF —
допустимая граница, в том числе начало пустой последней строки. Пустому исходнику
разрешён null. Неизвестное положение протокол должен хранить явно: байт 0 валиден.

Дерево Coco/R уже имеет включающий `begin` и исключающий `end` в исходных байтах.
Эти полуинтервалы остаются опорой преобразования. API возвращает физические
координаты снимка; логические Inferno `#line`/fline нужно хранить отдельно.
Имя в диагностике не даёт разрешения открыть файл. Новые общие секции/IDs Dis64
не вводятся; предложение о колонках отправлено в FLASHVM-0051.

SDK содержит заголовок, библиотеку и `examples/source-position`. Команды сборки
даны в английском руководстве; пример без парсинга/исполнения возвращает EOF на
строке 2, колонке скаляров 3. Проверки перебирают каждый Unicode-скаляр и все его
внутренние байтовые границы, смешанные переводы строк, tab, combining/astral,
EOF, ошибки кодирования и сохранность результата. O3/NDEBUG UBSan и CTest
самостоятельного фронтенда проходят. Политика экранного курсора/IME остаётся
отдельным преобразованием.
