# Генерация нативного C-интерфейса из .m нашим Coco/R-компилятором

[English](NATIVE_C.md) · [API](native.h) · [Реализация](native.c) ·
[Проверки](tests/native_check.py) · [Работающий пример](../../../disVM/examples/native-module/README.ru.md)

`limbo_bindings --format native-c-nc64 INPUT.m OUTPUT.h` выдаёт нативный C-интерфейс
Dis. `native-c-classic32` явно выбирает классический ABI с четырёхбайтовой ячейкой.
Ни один режим не запускает bootstrap-компилятор: используется наш каталог
интерфейса, построенный грамматикой Coco/R. Backend разрешает поддержанные прямые
примитивы, вычисляет разметку/сигнатуры/карты и выдаёт проверяемый C. Библиотечный
API — `limbo_native_header`, цель `limbo_interfaces`; output NULL выполняет preflight.

Старый `--format c` остаётся scaffold’ом внешнего вызова по значениям/дескрипторам.
Его FNV `interface_id` не является нативной сигнатурой Dis. Новые режимы вычисляют
настоящую структурную MD5-сигнатуру со свёрткой как в Inferno `sign()`. Это
идентификация структуры ABI, не аутентификация программы или сетевого узла.

## Что генерируется

- `F_Module_export`: префикс регистров/возврата/временных ячеек, явное выравнивание
  выбранной цели и типизированные аргументы.
- Прототипы `void Module_export(void *frame)`.
- `Modulemodtab`/`Modulemodlen`: имена, структурные сигнатуры, размеры дескрипторов
  с округлением к восьми байтам и карты указателей вместимостью 16 байт.
- Проверки размеров WORD/указателя/LONG/REAL, NREG, размеров кадров и смещений
  каждого аргумента при компиляции C. Заголовок classic32 не компилируется как NC64.

Карта отмечает строковые **входные аргументы**; указатель возврата не является
входным управляемым объектом. Биты вычисляются по слотам выбранной цели, не по
`sizeof(void*)` машины генератора. Результат записывается в ячейку вызывающего.
Для void используется `noret`, а не фиктивный указатель результата.

Поддержаны один модуль, 1–128 функций, до 16 аргументов, прямые
byte/int/big/real/string, скалярный или void результат, ASCII-имена C до 63 байт.
Константы модуля допускаются, но не выводятся как C defines. Nil-параметры получают
имена; коллизии и зарезервированные имена C/кадра отвергаются. Includes, алиасы,
ADT, составные типы, self, varargs, полиморфизм и raises-сигнатуры отвергаются
до открытия выхода. Для неразрешённой структуры приблизительный ABI не выдаётся.

Библиотека проверяет контракт до записи и владеет только временными метаданными.
Указатели каталога/исходника после возврата не сохраняются. Независимые вызовы
могут читать неизменяемые каталоги параллельно; удаление каталога и общий поток
вывода нужно синхронизировать. Сам разбор Coco/R остаётся сериализованным.
Ошибки выделения/I/O возвращаются вызывающему; публикацией/откатом управляет он.

## Проверки

Регрессия независимо считает выравнивание/карты и использует Python hashlib для
MD5. При явных путях к эталонным компиляторам дополнительно сравнивается вывод
Inferno classic32/NC64. Заголовок NC64 компилируется как C99, неверный host ABI
отвергается. Неподдержанный вход сохраняет старый файл. Учебный runtime-модуль
собран **с нашим заголовком** и исполняет настоящие вызовы Limbo/C, GC и исключения.

```sh
# Дополнительная сверка с эталоном; пути заданы явно и нужны только разработчику.
python3 compiler/limbo/frontend/tests/native_check.py \
  build/limbo-own/frontend/limbo_bindings \
  /полный/путь/classic/limbo-bootstrap /полный/путь/nc64/limbo-bootstrap
```

Сложные Sys/ADT/канальные интерфейсы пока этим профилем не заменяются. Согласованный
bootstrap остаётся временным полным компилятором модулей; его classic/NC64-кадры
нельзя смешивать. Расширять нужно семантическое разрешение типов и независимые
ABI-проверки, а не писать ещё один ручной парсер или угадывать структуры C.
