# Разрешение внешних алиасов — наш Limbo/Coco/R

У каталога интерфейсов появился отдельный неизменяемый проход связывания типов.
`limbo_interface_declared_type` получает прямой узел Type объявления алиаса,
функции или значения. `limbo_interface_resolve_type` следует внешним алиасам и
возвращает конечный узел Type. Обе функции доступны через C99-библиотеку
`limbo_interfaces`, отдельно от консольного драйвера.

NamedType теперь содержит точные узлы токенов `TypeIdentifier`, сформированные
Coco/R. Resolver использует эти узлы и поиск по каталогу. Повторного разбора
исходника, вычисления выражений и открытия файлов нет. Комментарии вокруг имени
типа и Unicode-идентификаторы сохраняют границы авторитетного парсера.

## Области видимости и время жизни

Неполное имя ищется сначала в текущем модуле, затем во внешних модулях и на уровне файла. Найденная
переменная или функция означает ошибку, а не переход к одноимённому файловому
алиасу. После перехода по алиасу используется **область его объявления**:
затенение в модуле не должно менять смысл тела файлового алиаса. Допустимы
опережающие ссылки внутри принятого интерфейса. Вложенные области поддержаны
запросами библиотеки; нативный C-профиль по-прежнему требует один верхний модуль.

Например, при файловых `A: type big; B: type A;` и модульном `A: type real;`
использование B внутри модуля остаётся big, а использование A даёт real.
Циклы обнаруживаются по идентичности объявлений. За один запрос итеративно
проходится максимум `LIMBO_ALIAS_MAX_DEPTH` (256) рёбер, без рекурсии C.

Выход меняется только при успехе. Диагностика: -1 неверный запрос, -2 ошибка
временного выделения имени, -10 ненайденное/не-алиасное либо неподдержанное
квалифицированное/обобщённое имя, -11 цикл или предел глубины. Координаты указывают
на ошибочный токен/конструкцию: строки считаются по LF, колонки и смещения —
**байты UTF-8**. Перед показом курсора IDE их нужно преобразовать в руны.

Каталог владеет деревом и исходником; возвращённые индексы заимствуются до его
уничтожения. Чтение неизменяемого каталога независимо, без globals парсера и без
сохранения временных имён. Уничтожение синхронизируется, выход/диагностика не должны
перекрываться с входами. Сам парсер Coco/R остаётся сериализованным.

## Точные границы прохода

Разрешаются **только внешние алиасы**. Алиас `array of big` возвращает узел массива;
вложенные алиасы в array/ref/function/tuple не обходятся. Имена модулей/ADT с
квалификаторами, обобщения, includes/imports пока не разрешаются. Это не полный
типизированный AST, проверка тел функций или понижение в FIR. Прежние JSON-виды
синтаксиса сохраняют исходные именованные типы.

Нативный C-профиль принимает byte/int/big/real/string и алиасы, заканчивающиеся
этими типами. Проверяются и неиспользуемые объявления алиасов. Затем выдаются
канонические кадры WORD/LONG/REAL/BYTE/String pointer, сигнатуры и карты GC.
C-typedef для исходного алиаса не создаётся: его имя не меняет ABI.
Составные алиасы этот backend отвергает до открытия выхода.

## Исполненные проверки

Проверены прямые/опережающие цепочки, затенение, файловая область, комментарии,
Unicode, внешние составные типы, циклы, неизвестные/квалифицированные/обобщённые
имена, точные байтовые координаты, сохранение выхода и граница 256/257 рёбер.
Принудительная ошибка malloc resolver не портит повторное чтение каталога.
ABI-тесты сравнивают алиасы и примитивы для classic32/NC64: независимые MD5/layout
расчёты и явно выбранные компиляторы Inferno дают те же метаданные.
[Учебный C-модуль](../../../disVM/examples/native-module/README.ru.md) использует
настоящие алиасы и исполняет вызовы, GC строк, ошибки и типизированные каналы в
DisVM. Выданный заголовок побайтно совпадает с прежним интерфейсом без алиасов.
