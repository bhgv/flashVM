# Исполняемый владелец жизненного цикла кооперативных задач

[English](ASINC-TASKS.md) · [Контракт языка](../ASINC.ru.md) ·
[Публикация захватов](ASINC-VIEWS.ru.md)

`asinctasks.dis` — обычный переносимый модуль Limbo. Единственный владелец
последовательно принимает типизированные запросы, а отдельные процессы Limbo
получают задания и выполняют работу. Кадры Flash не участвуют. Модуль работает
на нашем интерпретаторе и JIT, не использует Draw/Tk или нативный API потоков.

Это исполняемая основа жизненного цикла `asinc`, **не компиляция AS-замыканий**.
Вход, результат и ошибка представлены неизменяемыми строками. Изменяемые графы
объектов, AS-окружения, физические потоки AS, понижение задач в FIR и новый ABI
Dis64 этим модулем не реализованы.

## Запросы и порядок

`start(положительноеПоколение)` создаёт владельца; неверное поколение возвращает
nil. При замене владельца вызывающая сторона обязана выбрать новое поколение,
если ещё возможны старые сообщения. Каждый запрос содержит точное поколение и
канал ответа, который отправитель обязательно читает. Чужое поколение получает
Stale без изменений. Эти проверки защищают от устаревшей доставки, а не служат
проверкой полномочий недоверенного отправителя.

| Запрос | Поведение |
| --- | --- |
| Submit | Вход до 65536 символов; новый монотонный ID задачи |
| Claim | Обработчик с положительным ID получает первую задачу, вход и токен; без задач сразу Empty |
| Complete / Fail | Только правильные обработчик и токен завершают задачу результатом/ошибкой |
| Cancel ожидающей | Cancelled; вход владельца сразу освобождён |
| Cancel выполняемой | CancelRequested; вход сохраняется до подтверждения обработчика |
| Complete / Fail после Cancel | Подтверждает окончание работы; поздний результат отброшен, состояние Cancelled |
| AcknowledgeCancel | Явное подтверждение обработчиком запрошенной отмены |
| TakeResult | Однократная передача результата Completed/Failed; повторно Taken |
| Snapshot | Отдельный массив записей; его изменение не меняет владельца |
| Shutdown | Busy при Running/CancelRequested; иначе сброс оставшихся корней и выход |

Победителя определяет порядок получения запросов владельцем. Если первым пришло
завершение, поздняя отмена возвращает Terminal. Если первой пришла отмена, нужно
дождаться соответствующего завершения либо подтверждения. Пропавший обработчик
может бесконечно удерживать Busy: обнаружение смерти процессов, принудительная
отмена и автоматическая обработка их исключений здесь не реализованы. После
подтверждённого Shutdown посылать запросы нельзя: некому читать канал.

Доступно 32 слота за жизнь владельца. Они не переиспользуются даже после завершения.
Токен Claim равен уникальному ID задачи: повторных выдач, повторов и возврата в
очередь нет. При исчерпании Submit возвращает Full. Новый владелец требует нового
поколения и предварительного прекращения работ старого.

## Корни и владение

Владелец удерживает вход в Queued/Running/CancelRequested. Обработчик получает
собственную укоренённую копию скалярного значения. Подтверждённое окончание работы
очищает вход владельца; локальное значение обработчика живёт до его освобождения
самим обработчиком. Результат/ошибка удерживаются отдельно до TakeResult. Сначала
значение попадает в ответ, затем удаляется из слота владельца. Флаги inputHeld и
resultHeld отличают пустую строку от отсутствия значения.

Snapshot копирует записи; строки сохраняют обычную семантику значений/COW Limbo.
Снимок сам может удерживать значения после очистки владельца. Held-флаги показывают
владение слотом сервиса, а не число всех корней VM. Перед ожиданием следующего запроса сервис явно очищает временные payload-поля
запроса и ответа, чтобы не удерживать уже переданные значения в своём стеке.
Исключения выделения памяти
распространяются наружу; восстановление после OOM не реализовано. Эти проверки не
заменяют проверки реального GC и нативного окружения/результата в Inferno.

`asincviews` остаётся отдельным протоколом направленной публикации между кадрами.
Автоматические кадровые хуки и соединение обоих сервисов пока не добавлены.

## Проверка и пример

```sh
cmake -S disVM/runtime -B build/tasks -DDVM_RUNTIME_TESTS=ON
cmake --build build/tasks
ctest --test-dir build/tasks -R asinctasks --output-on-failure
(cd build/tasks && ./disvm --no-jit tasks-demo.dis)
(cd build/tasks && ./disvm --jit tasks-demo.dis)
```

При прямом запуске используйте штатный путь поиска модулей runtime, содержащий
собранные `.dis`. Установленный пакет содержит tasks-demo.dis, asinctasks.dis,
заголовок, исходник и оба руководства. Пример можно запускать штатным установленным
загрузчиком в режиме интерпретатора/JIT. Приложение в байткоде не требует Python.

[Подробно комментированный пример](../../disVM/examples/asinctasks/main.b)
создаёт владельца, посылает вход, запускает процесс Limbo, получает результат и
завершает сервис. [Приёмочный тест](../../ide/dis/tests/asinctasks_test.b) задаёт
оба порядка отмены/завершения каналами, без задержек; проверяет поколения,
токены, ошибочного обработчика, независимость снимка и записи символа строки,
дубликаты завершения, отмену ожидающей задачи, явное подтверждение, ошибки,
ёмкость и остановку при активной задаче.
