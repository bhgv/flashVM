# Исключения ресурсов и обработчики AVM1 (v0.8)

Реализованы стандартные инструкции SWF 7–8 `ActionTry` (0x8F) и `ActionThrow`
(0x2A). Используйте обычные конструкции ActionScript try/catch/finally.
Отдельная грамматика try:/except: не нужна. Компилятора исходного ActionScript
в проекте пока нет. Пример `examples/actionscript/resource_exceptions.as`
документирует использование; исполняемые тесты создают реальные инструкции.

Catch привязывает исключение к имени или регистру. Вложенные блоки используют
стек, регистры, пул констант и общий лимит инструкций своего кадра. Исключения
проходят через вызовы функций и нативных методов. Обычный finally сохраняет
ожидающее исключение или return; throw/return внутри finally заменяет его.
Прежняя локальная привязка имени catch восстанавливается. Исключение и значения,
сохраняемые для finally, включены в корни GC. Проверка вложенных блоков Try
выполняется до запуска верхнего потока инструкций. End внутри блоков не нужен.
Глубина ограничена 64. Переходы между блоками и DefineFunction2 с расширенными
регистрами не реализованы. Ошибочный байткод, нехватка памяти и неподдерживаемые
инструкции остаются статусами VM. Формат существующего DefineFunction пока
сохраняет прежние ограничения. Полная совместимость с Flash 8 не заявляется.

## Объект ResourceException

Ошибки AS-методов и свойств каналов/мутексов возвращают приложению FVM_EXCEPTION
и выбрасывают объект с полями name, code, message и context. Текст на английском
стабилен; для автоматического распознавания предпочтителен числовой код.

| Код | Префикс текста | Причина |
| --- | --- | --- |
| 1001 | resource.closed | Ресурс явно закрыт |
| 1002 | resource.stale | Устаревшая сессия сервиса или токен ресурса |
| 1003 | resource.disconnected | Разрыв установленного соединения, EOF, таймаут |
| 1004 | resource.unreachable | Соединение с сервисом не установлено |
| 1005 | resource.not_owner | Освобождение чужого захвата |
| 1006 | resource.recursive | Повторный захват нерекурсивного мутекса |
| 1007 | resource.cancelled | Отмена ожидания ресурса |
| 1008 | resource.io | Ошибка файлового ввода/вывода, включая блокирующее чтение EOF |
| 1009 | resource.failure | Другая ошибка ресурса |

context содержит resourceKind, resource, operation, threadId, originThreadId,
transport, flags, path, address, source, function, line, offset. Флаги могут
сочетаться: другой поток — 1, файл — 2, сеть — 4. Строка transport выбирает
сначала file, затем network, thread, иначе local. Неизвестный/удалённый ID
создавшего потока равен нулю. ID сетевого прокси локален, не является глобальным
идентификатором. Импорт через файл сохраняет путь на полученном ресурсе.
В C-снимках путь/адрес ограничены 511 байтами, источник/функция — 255.
Для связи с исходниками используются уже зарегистрированные карты инструкций;
без карты доступно смещение, остальные поля могут быть пустыми/нулевыми.

Сервис передаёт код причины в прежнем поле статуса ответа. Старые клиенты видят
общую ошибку; старые сервисы не передают подробную причину. Потерянный ответ на
set не вызывает автоматический повтор: захват мог состояться. Согласования
такого результата, аренд, восстановления после аварии и TLS пока нет.

## Встраивание и отладчик

Новый заголовок include/flashvm/exception.h предоставляет get/info/clear/raise.
После FVM_EXCEPTION получите ожидающее значение через fvm_exception_get и
обработайте его до clear. После clear корень исключения снимается: сохраняемый
объект нужно опубликовать в VM или закрепить. raise принимает любое значение
данного контекста и копирует строки. Для обычного скриптового throw функция info
возвращает NOT_FOUND. Низкоуровневые нативные API сохраняют контракт FVM_ERROR;
контекстную причину можно получить через info/get, AS-обёртка превращает её в
исключение. join передаёт статус FVM_EXCEPTION нативного рабочего callback,
но не переносит его объект из уничтожаемого контекста автоматически. Для
передачи данных обработайте/отправьте исключение внутри рабочего потока.

fvm_debug_exception_events возвращает до 64 копий событий ресурсов со всем
контекстом. При переполнении удаляется старейшее событие. Недостаточная ёмкость
возвращает NOT_FOUND и требуемый размер без очистки. Catch и clear не удаляют
события. Обычные скриптовые throw не входят в эту очередь событий ресурсов.
Прежний fvm_debug_resource_errors сохранён. Интерактивный интерфейс отладчика,
остановка исполнения и удалённый протокол замораживания очередей не реализованы.

Проверки: actionscript_exceptions.cpp проверяет именованный/регистровый catch,
вложенность, повторный throw, finally при return и его замену, прохождение через
нативные методы и функции, GC и неправильный формат блока. Два теста
resource_exception_network.c и resource_exception_file.c проверяют реальные TCP
разрывы, недоступный адрес, закрытый мутекс в файловой посылке, путь, URI,
идентификатор и снимок отладчика. Прежние тесты каналов, сервисов и потоков
проверяют новый AS-статус и сохранённые нативные статусы.

Изменение публичного API добавочное: новый статус и отдельный заголовок.
Существующие публичные структуры и FVM_ABI_VERSION не менялись.

Результаты проверки: [отчёт v0.8](EXCEPTIONS_REPORT.md).

## Интеграция Error в v0.9

Созданное ресурсное исключение поддерживает нативный Error.toString и без установки
стандартной библиотеки. При установленном Error оно наследует зарегистрированный
прототип. Диагностический граф и встроенный метод восстанавливаются из файла другим
процессом. Подробности: [STANDARD_ERROR.ru.md](STANDARD_ERROR.ru.md).
