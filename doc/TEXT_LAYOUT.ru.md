# Компоновка горизонтального текста с собственными контурами

API `flashvm/text_layout.h` строит блок текста из проверенного UTF-8 с одним
шрифтом. Используются статические FreeType/HarfBuzz/libunibreak/FriBidi,
включаемые ключом FONTS в DEFS.txt. Поиск системных шрифтов не выполняется.

Создайте шрифт через [fvm_font_read](../include/flashvm/font.h#L44), затем вызовите [fvm_text_layout_create](../include/flashvm/text_layout.h#L72).
При NULL options выбираются неограниченная ширина, естественный межстрочный
интервал, AUTO-направление абзаца и выравнивание START. Пример
examples/embedding/text_layout/main.c показывает переносы, смешанный текст
на латинице/иврите/арабском, измерения, экспорт контуров и рисование.

## Формирование строк

Сохраняются исходные границы UTF-8-байтов. CRLF считается одним разделителем;
CR, LF, VT, FF, NEL, LINE SEPARATOR и PARAGRAPH SEPARATOR также создают жёсткую
границу. Пустой вход даёт одну пустую строку. Повторные и завершающие разделители
сохраняют пустые строки. Каждая жёсткая строка начинает новый bidi-абзац.

FriBidi разрешает уровни всего абзаца до переноса. Для каждой предлагаемой строки
отдельно применяется правило L1 для завершающих пробелов и визуальный порядок
фрагментов. Фрагменты выделяются по уровню bidi и письменности Unicode.
Начальные общие/наследуемые символы получают следующую письменность, остальные —
предыдущую. HarfBuzz формирует логические фрагменты с контекстом строки; затем
фрагменты размещаются в визуальном порядке. Готовые глифы лигатур и диакритики
не переставляются по таблице визуальных кодовых точек. Default-ignorable символы
не создают глифов, но исходные байтовые позиции сохраняются.

Используется жадный выбор возможностей переноса libunibreak: кандидат формируется
и измеряется, при первом превышении выбирается последний помещающийся. Если
первое слово слишком длинное, применяются границы расширенных графем. Одна
неделимая графема может превышать ширину, но перенос всегда продвигается вперёд.
Окончательная строка формируется заново: лигатуры и арабские соединения учитывают
её реальные границы. Пробелы не удаляются, включая начальные и завершающие.
После первого превышения алгоритм не ищет более поздние кандидаты, которые
могли бы поместиться при немонотонном изменении ширины shaping.
Нулевая max_width отключает переносы.

| Значение | Смысл |
| --- | --- |
| metrics.advance_width | Максимальная длина продвижения строки без смещения выравнивания |
| metrics.height | ascent + descent + (число строк - 1) * расстояние базовых линий |
| metrics.ink | Точные границы размещённых кривых контуров без обводки |
| line.byte_start / byte_end | Диапазон исходных байтов без жёсткого разделителя |
| line.byte_next | Начало следующей строки, после разделителя/CRLF при наличии |
| line.x / baseline | Начало строки: x вправо, y вниз, пиксели |
| glyph.shaped.cluster | Исходная байтовая позиция UTF-8; у нескольких глифов может совпадать |
| glyph.x / y | Итоговое начало глифа с учётом смещений shaping |
| glyph.bidi_level | Уровень после сброса завершающих пробелов данной строки |

Первая базовая линия находится на высоте ascent. Явная line_height задаёт
расстояние базовых линий и допускает перекрывающиеся строки. LEFT/CENTER/RIGHT
работают внутри заданной ширины. START выбирает LEFT для LTR и RIGHT для RTL.
При превышении ширины начало равно x=0; при неограниченной ширине смещения
выравнивания равны нулю. Продвижение не равно границам рисунка: пробел имеет
ширину без контура, а глиф может выходить за собственное продвижение.

## Владение и преобразования

Компоновщик копирует контуры всех глифов и объединённый контур блока.
После успешного создания можно освобождать шрифт, вход, options и language.
Запросы результата их больше не используют. Результат допускает параллельное
чтение при отсутствии одновременного уничтожения; создание требует обычной
сериализации доступа к конкретному шрифтовому дескриптору.

[fvm_text_layout_path](../include/flashvm/text_layout.h#L85) возвращает независимый контур блока,
[fvm_text_layout_glyph_path](../include/flashvm/text_layout.h#L87) — независимый контур глифа в итоговой позиции.
Изменение контрольных точек и преобразования не затрагивают исходную компоновку
или другие копии. Для слова выберите глифы по исходному диапазону кластеров и
объедините их контуры. Лигатура — один неделимый контур: выделение отдельных
букв требует shaping без этой лигатуры, а не разрезания глифа по байтам.
Доступны преобразования, редактирование точек, заливка/обводка AGG/Cairo и маски
изображений через API path. NO_GRAPHICS сохраняет измерения и векторы;
отрисовка и маски возвращают UNSUPPORTED.

## Ограничения

Это горизонтальный текст с одним шрифтом и стилем. Полная реализация SWF
TextField/TextFormat ещё не завершена. Подстановка шрифтов, разные стили,
вертикальный текст, каретка/выделение и hit testing, редактирование с учётом
shaping, выключка по ширине, табуляция, условные дефисы и полный алгоритм
назначения письменности по Script_Extensions/парным скобкам остаются отдельными
задачами. Применённое простое наследование письменности описано явно.

Табуляция и SOFT HYPHEN возвращают UNSUPPORTED. Ограничения: 4096 кодовых точек,
16384 байта UTF-8, 65536 выходных глифов, миллион кодовых точек суммарно при
пробных формированиях строк. API path дополнительно ограничивает число команд
и координаты миллионом. Ошибочные входы/options дают INVALID_ARGUMENT,
неподдерживаемые возможности и превышение бюджета — UNSUPPORTED. При ошибке
выходной указатель обнуляется. Размеры должны быть конечными, неотрицательными
и в пределах ограничений. Ошибочные представления enum от C проверяются до
чтения как C++ enum.

Ограничения версий таблиц Unicode и шрифтов: FONT_LIBRARIES.ru.md.
Запуск на Windows/macOS/Android не подтверждается тестами Linux.
NO_FONTS сохраняет доступный API создания с UNSUPPORTED и NULL-результатом.
Подтверждающие проверки: TEXT_LAYOUT_CHECKPOINT.ru.md.
