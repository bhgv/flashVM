# Signed MovieClip depths / Знаковые глубины MovieClip

Development checkpoint v0.27; roadmap stage 3 remains open.

## English

MovieClip depth operations now accept integral depths from -16384 to 1048575.
An internal bias of 16384 maps signed depths to unsigned child-table keys.
Consequently authored negative depths sort below ordinary dynamic depths without
unsigned wraparound. getDepth reports the public depth; getInstanceAtDepth,
replacement, removal, duplicateMovieClip, attachMovie and swapDepths use the
parent's encoding. getNextHighestDepth ignores negative slots and reports the
next nonnegative depth, including 1048576 when the highest valid slot is occupied.

The supported numerical interval is not a claim that every reserved authoring
depth has identical Flash creation/removal rules. Timeline-specific removal and
depth ownership will accompany the placement engine. Full SWF-version coercion,
depth bias of the AVM1 CloneSprite opcode and all reference comparisons remain open.

Snapshots written before this change have no slot_bias field and retain their
unbiased nonnegative keys. Reads and nonnegative insertions use that encoding.
Before a negative insertion or a swap, a legacy table is rebuilt into biased
slots. Existing children are reused, preserving their identities, parents and
public depths. The new marker is published only after the replacement table is
allocated; the final table swap does not allocate. The public ABI and graph wire
version remain unchanged. Other readers may not understand the new private
encoding, so this is backward reading support, not forward compatibility.

[GC:] The table rebuild copies managed edges and does not clone children.
Native-call protection covers the unpublished temporary table. Existing GC
traversal and graph serialization retain biased tables and shared parent/child
cycles in the same way as earlier tables.

## Русский

Внутреннее смещение 16384 позволяет хранить отрицательные глубины без превращения
их в огромные unsigned-индексы. Публичные методы возвращают исходные знаковые
значения. Сортировка сцены размещает отрицательные глубины ниже положительных.
Следующая свободная верхняя глубина вычисляется только по неотрицательным слотам.

Старые снимки без slot_bias читаются как раньше. При первой отрицательной вставке
или перестановке таблица перестраивается, сохраняя те же экземпляры детей.
Выделение временной таблицы выполняется до публикации нового кодирования.
[GC:] При перестройке копируются управляемые связи, не сами клипы; нативный барьер
защищает временное состояние. Форматы ABI/графов не повышались.

Диапазон чисел ещё не подтверждает все правила Flash для зарезервированных
глубин. Владение клипами таймлайном и специальные правила удаления будут
реализованы вместе с тегами размещения. Этап 3 не закрыт.

## Tests / Тесты

`tests/movieclip_depths.cpp` covers negative/zero/highest depths, replacement,
numeric/object swap, removal, invalid bounds/fractions, GC and queue transport.
It also restores `tests/fixtures/movieclip-v026.fvg`, generated by the v0.26
portable library from a root and its child at depth 2. The binary fixture is test
input, not a generated validation log. The test inserts another positive child,
upgrades the legacy table with a negative child and verifies preserved identities.

The published [AS2 MovieClip reference](https://open-flash.github.io/mirrors/as2-language-reference/MovieClip.html)
documents the method depth intervals and reserved authoring ranges. Full player
conformance and non-Linux platform acceptance remain open.

## Validation v0.27 / Проверки v0.27

Strict C89/C++98 Linux runs passed: headless 175/175, bundled AGG 185/185,
bundled Cairo 185/185, portable/no-OS 166/166. The sanitizer driver completed
172 tests/examples. Heap/global ASan and UBSan were enabled; ASan stack checks
were explicitly disabled for the workspace exception/unwind environment,
LeakSanitizer was disabled because /proc is unavailable, and container exception
tests use UBSan only. No target-platform or complete-player certification follows.
