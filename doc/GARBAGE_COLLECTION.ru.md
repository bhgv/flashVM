# Трассирующий сборщик мусора FlashVM

## Принцип работы

Каждый `FVM_Context` владеет собственными объектами. Полный проход mark-and-sweep начинается с глобального объекта VM и объектов, закреплённых через `fvm_gc_pin`. Обходятся именованные и числовые поля, прототипы и метатаблицы. **Циклические ссылки** между недостижимыми объектами не препятствуют их освобождению.

Сборщик не является параллельным. Вызывайте его в потоке владельца контекста, в безопасной точке выполнения. Пока стек интерпретатора AVM1 и временные значения C не добавлены в корни GC автоматически, нельзя запускать сборку посреди исполнения инструкций или нативного callback. Доступные сейчас проходы запускаются явно через API.

## Методы

- `fvm_gc_pin` / `fvm_gc_unpin`: удержание внешних ссылок, допускается несколько закреплений.
- `fvm_gc_collect`: полный проход, даже если установлен `suspended`.
- `fvm_gc_mode`: число от -100 до 100, `FVM_GC_SUSPENDED` или `FVM_GC_FULL` (один полный проход без смены режима).
- `fvm_gc_state`: получение сохранённого режима, 0 — normal/default.
- `fvm_gc_step`: проверка порога и возможная сборка, не выполняется в suspended.
- `fvm_gc_object_count`: количество объектов для диагностики.

Порог проверок равен `1000 - 9*mode` новых объектов: от 1900 при -100 до 100 при +100. Это простая политика по количеству выделений, не инкрементальный GC.

## Метаметод `__gc`

Перед освобождением недостижимого объекта вызывается его нативный обработчик `__gc`, которому передаются `(объект, метатаблица, объект)` и контекст. Обработчик может восстановить достижимость, записав объект в глобальную таблицу. Перед удалением выполняется повторная маркировка. Повторный вызов `__gc` для того же объекта не допускается.

**Ограничения:** AS-функции в `__gc`, финализаторы C-only userdata и объект `gc` в ActionScript ещё не реализованы. Указатели C на объекты без `pin` не считаются корнями, после удаления они недействительны.
