# Проверки и незавершённые работы

## Повторение

Linux, Python 3, GCC/G++, ar и timeout:

```
python3 scripts/check.py
python3 scripts/check.py --sanitize
```

Скрипт собирает статическую библиотеку из всех исходников без внешних зависимостей
и Linux-адаптеров; затем собирает и запускает все тесты и embedding-примеры,
кроме опционального системного SQLite. Флаги C: `-std=c89`; C++: `-std=c++98`;
для обоих `-Wall -Wextra -pedantic-errors`. Таймаут каждого процесса — 30 секунд,
assert включены. В CMake assert-тесты теперь включены и для Release. Минимум
CMake — 3.1, соответствующий уже используемому target_sources.

Обычная CMake-сборка на машине с CMake:

```
cmake -S . -B build -DFVM_ENABLE_SQLITE=OFF
cmake --build build
ctest --test-dir build --output-on-failure
```

В текущем окружении CMake отсутствует: проверка выполнена напрямую компиляторами,
не через CMake/CTest. SQLite по умолчанию выключен; его опциональная системная
сборка не проверялась, исходники SQLite не включены. Новых внешних зависимостей
и загрузок стороннего исходного кода нет.

## Результаты

Строгая Linux-сборка: 89 тестов и примеров прошли. Санитайзеры: 88 проверены
AddressSanitizer + UndefinedBehaviorSanitizer; тест инъекции исключений
контейнеров — отдельно UBSan. Файлы validation/ содержат точный список тестов,
версию компилятора, флаги и исключения. Компилятор GCC 13.3.0. Исходники
thread-адаптеров macOS/Android также прошли компиляцию строгим C89 на Linux;
это проверка синтаксиса, не запуск на соответствующих платформах.

LeakSanitizer не может перечислять задачи из-за недоступного /proc и явно
отключён. ASan также сообщает невозможность определить верхнюю границу стека
при вложенном C++ rethrow; независимый пример без FlashVM воспроизводит это
предупреждение runtime. Тест исключения в конструкторе vector затем вызывает
сообщение внутри stack-unpoisoning ASan. Поэтому он компилируется и запускается
с UBSan, сохраняя проверки числа живых экземпляров и состояния контейнера.
Результат не доказывает отсутствие утечек или полную ASan-проверку исключений.

## Открытые работы и границы

- Нативная сборка и runtime CI для Windows/macOS/Android ещё не проверены.
- Строки VM живут до уничтожения контекста; реализован tracing GC **объектов**,
  сборка строкового arena остаётся отдельной работой.
- Инъекция отказов проверяет присваивания контейнеров, но не все выделения VM.
- Произвольные локальные переменные C и память userdata не сканируются: нужны
  root scopes, pin, захваченные корни или свойства трассируемых объектов.
- Нативный callback нельзя принудительно отменить. Destroy не должен гоняться
  с пользователями handle. Указатели объектов между контекстами запрещены.
- Worker переносит именованные определения функций, не замыкания и нативные
  регистрации. Интерпретатор остаётся подмножеством AVM1.
- Снимки каналов предназначены для одного процесса. TCP/UDP/TLS, нестандартные
  операторы каналов и полноценный компилятор ActionScript ещё не реализованы.
- Нативные ресурсы в снимках запрещены. Общие каналы передаются явно через
  удерживаемую обёртку/аргумент worker, без циклов handle внутри очередей.
- Опциональный SQLite, JIT, рендеринг/медиа и другие несвязанные заготовки
  исходного проекта в этом обновлении не завершались.

Заявления ограничены проверенными контрактами. Полная совместимость FlashVM/
Flash Player и готовность всех платформ к production не объявляются.
