# Function.apply — корни и семантика загруженного SWF

## v0.417: корни подготовки

В host и SWF4–8 упакованный получатель this удерживается во время чтения списка
аргументов. Инициализированный массив значений подключается к корням GC до первого
getter, поэтому уже полученные строки, объекты и циклы переживают сборку внутри
следующего getter. Корни действуют до завершения вызова целевой функции и снимаются
при успехе, ошибке, исключении и отказе памяти. Вспомогательный корень заимствует
существующий C++-массив без выделений и без изменения контекста вызова.

function_apply_gc получает свежую строку с NUL и циклический объект из script
getters. Третий getter действительно запускает GC и проверяет реестры живых
значений до обращения к данным. Проверены null/числовой this, ошибка, исключение
с NUL, отсутствие вызова цели после отказа getter, очистка и повторный вызов для
host/SWF4–8. Тест не проходил на исходной v0.416 до исправления.

Полные правила apply, длина списка, версии преобразований, большие количества
аргументов и платформенная приёмка ещё не подтверждены. Все девять стадий открыты;
цель остаётся SWF ≤8.

Validation v0.417 / Проверка: minimal Release 833/833; AGG Release 2/2 and
heap/global ASan+UBSan 2/2 apply/function tests. Generated native launchers restore
workspace executable modes; stack ASan/LSan disabled. Foreign runtime acceptance
and all nine stages remain open.

## v0.418: собственная длина загруженного списка

В SWF4–8 примитивный второй аргумент даёт пустой список. Для объекта берётся
собственная сохранённая длина, без прототипов и вызова getter: учитываются данные
addProperty и native Array. Имя length сопоставляется без учёта регистра в SWF4–6
и точно в SWF7–8. Значение преобразуется один раз через AVM1 Number/Int32 с
усечением и оборачиванием; undefined/NaN/бесконечность дают ноль. Объект длины
удерживается при самоустранении и GC внутри valueOf. Упаковка this предшествует
преобразованию длины. Host API сохраняет прежнюю политику.

function_apply_loaded проверяет примитивы, дробные/обёрнутые длины, addProperty,
наследование, регистр, Array, собирающий valueOf, исключения и восстановление.
Отрицательная signed длина и длина выше 65536 пока дают UNSUPPORTED до выделений;
это ограничение реализации, а не полное поведение Adobe для таких значений.
Источники сравнения закреплены в [EN](FUNCTION_APPLY.md). Все стадии открыты.

Validation v0.418 / Проверка: minimal Release 834/834; AGG Release 3/3 and
heap/global ASan+UBSan 3/3 apply/function tests. Native launchers restore workspace
executable modes; stack ASan/LSan disabled. Other-platform acceptance remains open.

## v0.419: обычные свойства аргументов

Загруженный apply читает числовые имена через обычный объектный путь для любого
типа источника. Собственные и наследуемые свойства/getters Number/Boolean/String/
Date больше не пропускаются сырым индексным API. Получатель getter — исходный
объект; отсутствующие элементы дают undefined. Уже полученные значения остаются
снимками, даже если следующий getter меняет исходный слот и запускает GC.
Host API сохраняет прежний индексный путь. function_apply_properties проверяет
SWF4–8, четыре native-класса, наследуемый script getter, NUL, мутацию и GC,
пропуски, ошибки/исключения, отсутствие вызова цели после отказа и восстановление.
Полная семантика __resolve/metatable, заимствование apply и большие списки ещё
не подтверждены; все стадии открыты.

Validation v0.419 / Проверка: minimal Release 835/835; AGG Release 4/4 and
heap/global ASan+UBSan 4/4 apply/function tests. Native mode-restoring launchers
used; stack ASan/LSan disabled. Other-platform runtime acceptance remains open.

## v0.420: постепенное заполнение и общий бюджет

Для положительной Int32-длины загруженного apply снят предел 65536. Массив
аргументов растёт по одному посещённому слоту; бюджет проверяется до чтения и
выделения. Упаковка this, преобразование длины, поиск имени, getters и целевой
вызов разделяют бюджет AVM1; вложенные вызовы его не сбрасывают. Учитывается
каждый кандидат имени length и каждый аргумент. Host сохраняет предел 65536
и прежний обход без такого бюджета. Отрицательная signed длина всё ещё даёт
UNSUPPORTED. Это заменяет ограничение загруженного режима из v0.418.

Проверены точные пороги, вложенный parseInt, насыщение счётчика, поиск имени и
восстановление. Список из 65537 значений передаётся C-функции и подготовленному
script body с реальной сборкой GC внутри; arguments.length и последний элемент
сохранены. Длина INT32_MAX при бюджете 4 прерывается до цели. Тест с запретом
выделений больше 4096 байт подтверждает отсутствие полного предварительного
массива в этом сценарии. Перебраны отказы памяти, проверены области вызова и
интерпретатор/два режима JIT с фактическими входами в машинный код.

Проверки локальные: большой RPC и другие физические платформы не заявляются.
Общая валидация, внутренности поиска и подготовка цели учитываются не полностью;
при отключённом лимите остаётся ограничение доступной памяти. Все стадии открыты.

Validation v0.420: Linux minimal 838/838; AGG 7/7; heap/global ASan+UBSan 7/7.
Generated native-mode launchers compensate for workspace executable-mode resets.
Stack ASan and LeakSanitizer are disabled in this environment. Other platforms
and completion of all nine stages remain unverified/open.

## v0.421 — заимствованные адаптеры и невызываемые цели

В загруженных SWF4–8 заимствованные Function.call/apply возвращают undefined,
если у цели нет callback вызова. Упаковка this и подготовка длины/индексов apply
выполняются раньше: ошибки getter, исключения со встроенным NUL и исчерпание
квоты продолжают передаваться вызывающему. Host API сохраняет UNSUPPORTED;
прямой публичный вызов и C/script/удалённые вызываемые интерфейсы не меняются.
Основание — закреплённая версия Ruffle function.rs по ссылке выше.

function_borrowed_adapters воспроизводит прежний сбой и проверяет версии SWF4–8,
host, настоящую сборку GC внутри script getter, исключения, повторный вызов,
вызываемую цель и порядок проверки бюджета. jit_function_apply дополнен обоими
адаптерами через интерпретатор и два режима JIT с входом в машинный код.
Полная семантика super и Function, как и все девять стадий, остаётся открытой.

Проверено v0.421: Linux minimal 839/839; AGG 9/9; heap/global ASan+UBSan
9/9, включая регрессию удалённых функций. Использованы генерируемые средства
восстановления права запуска; stack ASan/LeakSanitizer отключены. Другие ОС
не проверены; все стадии остаются открытыми.

## v0.422 — super требует прямой диспетчеризации

Загруженные Function.call/apply считают сохранённый объект super не функцией,
несмотря на внутренний callback для прямого вызова родителя. Подготовка аргументов
выполняется до undefined: script getter индекса запускается, может собирать GC,
передаёт ошибки и исключения со встроенным NUL. Заимствованный host-вызов и прямой
публичный вызов объекта super сохраняют прежнюю диспетчеризацию родителя.
Основание — явное разделение as_function и прямого super в закреплённом
function.rs Ruffle. Полная семантика super/Function не заявляется.

function_super_adapters воспроизвёл сбой на v0.421; проверены SWF5–8 и host,
оба адаптера, побочные эффекты родителя, GC в getter, ошибки/исключения, повторный
и прямой вызовы, восстановление корней и бюджета. Отрицательная signed длина
apply остаётся UNSUPPORTED: эталон переводит её в размер выделения, поэтому
считать её нулём по этому источнику нельзя. Все стадии остаются открытыми.

Проверено v0.422: Linux minimal 840/840; AGG 13/13; heap/global ASan+UBSan
13/13, включая прямой super, владельца/прототип и удалённые функции. Применены
генерируемые средства восстановления права запуска. Stack ASan/LeakSanitizer
отключены; дополнительные ОС и завершение стадий не подтверждены.

## v0.520: удалённая length нативного Array

После удаления собственного свойства length apply больше не использует
оставшуюся внутреннюю длину Array. Отсутствующее значение даёт ноль аргументов;
индексные getter не вызываются. Наследуемые length/getter игнорируются. Штатный
accessor, заново созданные данные и регистр собственного имени в SWF4–6
сохраняют прежнее поведение; NUL-суффикс остаётся отдельным свойством.
ABI, формат графа и host-политика не меняются.

Сравнение: Ruffle 2372a4e148a67d68efd796f4477b3cddd4f880cd, apply и
ScriptObject::length читают собственные сохранённые данные либо Undefined.
Это не проверка оригинальным Flash Player. Поведение удаления/виртуальной
length в остальных нативных методах Array и ненумерическая length ещё открыты.

function_apply_deleted_length проверяет SWF4–8, варианты length, C API,
интерпретатор, JIT и перенос графа. Вариант roots проверяет пропуск getter,
удаление связей, GC, исключения и ошибки целевой функции. Вариант allocation
перебирает отказы памяти, проверяет очистку, GC/повтор и сохранность элементов.
Исправленная матрица воспроизводит ошибку обработчика v0.519.

Проверено v0.520 на Linux x64 C++98: minimal 1070/1070, AGG 1089/1089,
Cairo 1090/1090, включая успешные повторы после восстановления прав запуска
20/18/26 файлов. Шесть целевых проверок ASan/UBSan успешны. Новый строгий
GNU readelf-аудит 1079 ELF успешен; прямые зависимости — только libc,
libgcc_s, libm и libstdc++. Транзитивные/dlopen-зависимости и реальная приёмка
Windows/macOS/Android этим не подтверждены.

В v0.521 чтение актуальной собственной length распространено на нативные методы
Array; [контракт и оставшиеся ограничения](ARRAY_LENGTH_STORAGE.md).
