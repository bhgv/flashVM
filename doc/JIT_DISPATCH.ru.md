# Нативная доставка URL и вызов кадров — v0.368

[English description](JIT_DISPATCH.md)

GetURL, GetURL2 и Call используют общие сервисы URL/кадров. VM сама не выполняет
сетевые запросы и навигацию: тесты регистрируют синхронный записывающий обработчик.
GetURL проверяет две терминированные строки и сохраняет соседнюю неизменную пару
констант. При исполнении обе строки усваиваются контекстом и удерживаются корнями;
в SWF4–5 не-ASCII литералы отклоняются до усвоения, как в интерпретаторе.
GetURL2 проверяет флаги при компиляции и удерживает оба операнда при преобразовании
сначала target, затем URL и при доставке. Операнды удаляются при успехе;
отсутствующие loaded-входы дополняются общим механизмом, host-входы ошибочны,
отсутствующий обработчик возвращает unsupported, ошибки обработчика передаются.

Call удерживает исходный операнд до завершения вложенного вызова кадра. Общий
сервис разрешает число/метку/clip:frame с выбранным таймлайном и восстановлением
root, не перемещая playhead. Сохранённые кадровые блоки теперь после проверки
ограниченного блока используют обычный автоматический режим исполнения:
поддерживаемые блоки входят в JIT с новым root-набором регистров/пулом, остальные
интерпретируются. Именной breakpoint кадра проверяется до выбора native, включая
наличие кэша. Существующие области восстанавливают target, пул, корни, debug cursor
и сохраняют общий счётчик инструкций.

| Проверка | Покрытие |
| --- | --- |
| `jit_dispatch` | Host/SWF4–8 и три режима, все допустимые флаги URL, встроенный NUL, литералы и legacy-байты, ошибки/исключения обработчика, отсутствующие входы/sink, строки после удаления кода и GC |
| `jit_frame_dispatch` | Число/метка/путь/NUL-путь, выбранный/отсутствующий target, неизменный playhead и нижний стек, отсутствующие кадры/входы, вложенные исключения и восстановление, ограниченная рекурсия и снятая активность кэша, fallback, именной breakpoint и возврат к кэшу, новый пул констант кадра, bounded-вход с неявным End, общий лимит 7/8 инструкций |
| `jit_dispatch_callbacks` | Target-first URL-преобразования с GC/исключением и traced-строками; строка target переживает преобразование URL; исходный receiver запроса кадра переживает GC во вложенном кадре |
| `jit_dispatch_allocation` | Литеральный/динамический URL, manual Call, автоматическая компиляция parent/child; отказы компиляции сохраняют handle; отказы вызова восстанавливают корни/глубины/активность; ошибки памяти host-sink передаются |
| `jit_invalid` | Неполные/повреждённые пары URL, неверные флаги/размер URL2 и непустой payload Call сохраняют прежний handle |

Счётчики различают native parent/кадр и interpreter/manual fallback; breakpoint
и неподдерживаемое тело подтверждаются счётчиками интерпретатора. По умолчанию
ошибки не повторяют эффекты; явный диагностический replay сохраняет прежнюю
политику повторных побочных действий. Это семантика FlashVM, а не полная
совместимость browser/FSCommand, потоков/событий кадров или эталонного Flash.
Реальная приёмка других платформ и все стадии остаются открытыми.

Linux Release: есть успешные результаты всех 754 проверок AGG, 754 Cairo и 735
minimal после восстановления прав ELF и повторных запусков. Пять проверок
dispatch/callback/allocation/frame/invalid проходят ограниченный heap/global
ASan+UBSan; stack ASan и LeakSanitizer отключены.
