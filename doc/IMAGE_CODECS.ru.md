# Встроенные библиотеки изображений

В корневом DEFS.txt по умолчанию выбран IMAGE_CODECS. Для отключения выберите
NO_IMAGE_CODECS. CMake собирает исходники из external без скачивания и поиска
системных библиотек. Подключение целевого проекта к flashvm автоматически даёт
пути заголовков и необходимые библиотеки.

| Формат | Библиотека | Чтение | Запись |
| --- | --- | --- | --- |
| PNG | libpng 1.6.59 + zlib 1.3.1 | libpng и потоковый API Cairo | libpng и потоковый API Cairo |
| GIF | giflib 5.2.2 | DGif, кадры и метаданные | EGif, кадры, палитры, расширения |
| JPEG | IJG libjpeg 9f | декомпрессор, источник в памяти | компрессор, результат в памяти |
| SVG | NanoSVG 239e102ec2c691f2902e20ace2ed36ee4a35cfe6; Cairo 1.16.0 | разбор фигур и растеризация NanoSVG | SVG-поверхность и потоковый API Cairo |

Cairo/Pixman собираются для экспорта SVG при IMAGE_CODECS независимо от выбора
GRAPHICS_AGG/GRAPHICS_CAIRO/NO_GRAPHICS. Этот выбор по-прежнему определяет
основной растеризатор FlashVM. NO_GRAPHICS отключает основной растеризатор,
но не отдельный SVG API. При NO_IMAGE_CODECS и GRAPHICS_CAIRO остаётся прежний
профиль Cairo: изображения в памяти, recording и пользовательские шрифты.

Из C89 доступны png.h, gif_lib.h, jpeglib.h, cairo.h, cairo-svg.h и flashvm/svg.h.
Для файлового JPEG API включайте stdio.h перед jpeglib.h. Исходные заголовки
NanoSVG доступны из C++98: анонимные объединения несовместимы со строгим C89.
Реализация уже включена в fvm_nanosvg; клиенту не нужно определять макросы
NANOSVG_IMPLEMENTATION и NANOSVGRAST_IMPLEMENTATION. Обёртка flashvm/svg.h
совместима с C89: read копирует и разбирает вход, size возвращает размеры,
rasterize записывает обычный RGBA8 в масштабе 1 с отсечением и сохранением
байтов заполнения строк, destroy освобождает документ.

Обёртка ограничивает вход 4 МиБ, размеры области 4096, координаты после
преобразований ±1 000 000, число точек путей 1 000 000. Это не полноценный
валидатор XML и не гарантия безопасной обработки произвольного вредоносного
входа. NanoSVG поддерживает ограниченный профиль статических фигур, путей и
заливок, а не весь стандарт SVG. Нельзя полагаться на поддержку текста/шрифтов,
встроенных изображений, фильтров, скриптов, внешних ресурсов и полного CSS.
Cairo может записать конструкции, которые NanoSVG не читает; обратное чтение
проверено на простых векторных фигурах. Для сохранения размеров в пикселях
при 96 dpi задавайте Cairo единицу CAIRO_SVG_UNIT_PX. NanoSVG может пропустить
неподдерживаемое содержимое; его API не сообщает обо всех отказах выделения
памяти при разборе и растеризации.

libpng собирается скалярно в C89 с готовой конфигурацией upstream. В giflib
bool заменён на однобайтовый GifBooleanType, перенесены объявления и добавлен
локальный реентерабельный токенизатор. JPEG использует ANSI-исходники и память
без временных файлов; приложение должно обработать ошибки через штатный API
(обычно setjmp/longjmp) и освободить результат jpeg_mem_dest через free.
NanoSVG разбирает дроби через double вместо C99 strtoll, сохраняя точность
на платформах с 32-битным long. Правки сохранены в flashvm.patch.
Резервные атомарные операции Cairo исправлены: статус и счётчики имеют размер
int, а не указателя. Передача ошибки записи SVG проверяется отдельным сценарием.

Тесты tests/image_codecs_* проверяют чтение/запись в памяти, прозрачность PNG,
кадры/локальные палитры/метаданные GIF, JPEG с допустимой погрешностью сжатия,
повреждённый вход, заголовки C++98, потоки PNG/SVG Cairo, ошибки записи, пиксели
и заполнение строк. tests/svg_facade.c проверяет включённую и отключённую
конфигурации. examples/embedding/image_codecs показывает SVG → RGBA → PNG
в памяти и запускается как тест. Это API нативного встраивания; объекты
ActionScript для изображений и завершённость SWF-движка этим не заявляются.
