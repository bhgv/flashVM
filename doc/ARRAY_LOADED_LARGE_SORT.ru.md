# Большая сортировка и бюджет захвата — v0.377

В загруженных SWF4–8 настоящие и заимствованные sort/sortOn больше не отклоняют
положительную длину только из-за превышения 65 536. Настоящий sort сначала
связывает пустой временный GC-корень, затем захватывает значения с учётом работы
перед каждым добавлением. Частичный снимок корректно освобождает корни при
ошибке памяти или бюджета. Построение элементов и quicksort продолжают учитывать
работу; теперь учитываются также разворот DESCENDING и запись массива индексов.
Незавершённый результат индексов укоренён. Стоимость прежних сортировок выросла.

Исторический порядок сравнений с левым pivot сохранён, включая квадратичный
худший случай. Большие упорядоченные/равные входы могут исчерпать бюджет;
нулевой лимит остаётся неограниченным. До успешного захвата и сравнений исходный
порядок не меняется. Побочные эффекты callback и частичная финальная запись
не откатываются. Незагруженные native/generic пути сохраняют отдельные пределы
65 536. Отрицательное знаковое хранение настоящего Array остаётся неподдержанным;
прежние правила отрицательной длины общего пути и no-op перегрузок сохранены.

Проверяются SWF4–8, четыре успешные сортировки 65 537 элементов/индексов,
неизменность источника RETURNINDEXEDARRAY, порядок вывода, корни/GC, прежние
C-пределы, отказы выделения памяти и повторные вызовы после сборки.
[Имена проверок](ARRAY_LOADED_LARGE_SORT.md). Все стадии остаются открытыми.

Подтверждены 777 AGG / 777 Cairo / 758 minimal Linux Release проверок после
исправления прав пяти ELF-файлов (2/2/1) и шести повторов, включая зависимый
профиль часовых поясов. Шесть проверок прошли ограниченный heap/global
ASan+UBSan; stack ASan и LSan отключены. Заголовок прошёл строгую проверку C89.
Исходные внешние SWF заново не сверялись; новых эталонных прохождений не заявлено.
