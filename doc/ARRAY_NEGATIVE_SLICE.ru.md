# Slice с отрицательной собственной длиной — v0.375

В загруженных SWF4–8 slice сохраняет знаковую собственную длину до преобразования
границ. При отрицательной длине без переполнения неотрицательная граница выбирает
эту длину, а отрицательная — ноль. Поэтому slice(0, -1) при length=-3 копирует
собственные ключи -3, -2, -1 в плотный массив длины три. Пропущенная правая
граница или undefined сохраняет захваченную длину и в этом примере даёт пустой
массив. Сначала преобразуется длина, затем начало и конец. Изменения длины при
преобразовании границ не меняют захваченный диапазон.

Чтение собственных хранимых данных не обходит прототипы и не вызывает геттеры;
пропуски и хранимые аксессоры следуют правилам положительного loaded slice.
Источник не меняется. Поддерживаются заимствованные объекты и настоящие Array
с unsigned-длиной, оборачивающейся в отрицательное число. Незавершённый результат
укоренён, копирование учитывает общий бюджет. Переполнение сложения границ и
длина результата выше максимального Int32 пока явно не поддерживаются.
Мутации отрицательной длины настоящего Array и все стадии остаются открытыми.
C-режим не изменён. [Источник сравнения и проверки](ARRAY_NEGATIVE_SLICE.md).

Подтверждены 773 AGG / 773 Cairo / 754 minimal Linux Release проверки:
AGG/Cairo после исправления прав ELF и повторов, minimal целиком сразу.
Пять проверок прошли ограниченный heap/global ASan+UBSan; stack ASan и LSan
отключены. Все стадии остаются открытыми.
