# Контракты сборщика и регрессионные проверки

Корни: глобальный граф, явные pin, стеки операндов AVM1, параметры, локальные
переменные и получатели, содержимое публичных `FVM_Stack`, захваченные таблицы
из `fvm_register_function_rooted`. Замена функции снимает её старый корень.
Одна захваченная таблица может удерживать несколько объектов. Произвольная
память userdata и локальные переменные C не сканируются. Внутри нативного
callback автоматическая сборка откладывается, явная рекурсивная запрещена.
Стеки и области корней должны завершаться до уничтожения контекста.

Маркировка итеративная, циклы свойств, индексов, прототипов и метатаблиц
обрабатываются. Уплотнение массива при освобождении линейное. Callback
вызываемого объекта теперь хранится в самом объекте: больше нет устаревших
записей и преобразования указателя в unsigned long, опасного на LLP64.

Перед финализацией фиксируется число объектов. Каждый подходящий объект
финализируется один раз. Созданные финализатором объекты и достижимые из
них графы переживают этот проход. Их финализация отложена до следующего
прохода; бесконечное создание финализируемых объектов не удлиняет текущий
список. После callback повторно проверяется достижимость и воскрешение.
Первая ошибка финализатора возвращается после завершения остальных callback
и освобождения; счётчик освобождённых объектов остаётся достоверным.

Нативный `__gc` имеет приоритет. Иначе строковое свойство `__gc` метатаблицы
задаёт имя AVM1-функции. Аргументы `(объект, метатаблица, объект)`, `this`
указывает на финализируемый объект. Это расширение для именованных функций;
замыкания и свойства со значением-функцией интерпретатор пока не поддерживает.

При уничтожении контекста повторное уничтожение и сборка запрещены. Создание
объекта возвращает `FVM_INVALID_ARGUMENT`, список финализаторов не растёт.
Воскрешение не продлевает жизнь уничтожаемого контекста. Void API уничтожения
не возвращает ошибки callback.

Новые тесты: `gc_finalizer_snapshot` — новые графы, ошибки, повторный вход;
`gc_api_stack_capture` — захваченные корни, замена, независимые стеки, время
жизни вызываемых объектов; `gc_script_finalizer` — AVM1-финализация и
воскрешение. Сохраняются существующие тесты циклов, областей корней и safe
points AVM1. Сборщик объектов останавливает VM, он не инкрементальный.
Строки пока живут до уничтожения контекста; сборка строк и инъекция отказов
выделения памяти остаются незавершёнными.

## Дополнительные API времени жизни

fvm_stack_register_rooted, fvm_callable_create_rooted и fvm_meta_register_rooted
трассируют захваченные таблицы. Глобальная стековая регистрация — безусловный
корень; захват вызываемого объекта/метатаблицы удерживается лишь при достижимом
владельце. Все три варианта проверяет gc_callback_captures.

flashvm/userdata.h присоединяет payload и release-callback к обычному объекту.
Сначала __gc может воскресить объект; release отложен до фактического освобождения.
Он вызывается один раз после решения о достижимости, пока объекты ещё существуют.
Выделение объектов и изменение pin в release запрещены. Release не должен
воскрешать объекты или обращаться к уже освобождённым. Исключения перехватываются,
сборка завершается с ошибкой. gc_userdata проверяет воскрешение, однократный release,
защиту повторного входа, диагностику и уничтожение контекста. Payload не сканируется;
захваченные объекты нужно хранить в трассируемых свойствах.
