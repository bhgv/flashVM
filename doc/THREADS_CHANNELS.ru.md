# Проект API потоков и каналов (спецификация, НЕ реализация)

## Состояние

На этом этапе реализован только вызов `__call` через `fvm_meta_call`. Описанные ниже синтаксические расширения ActionScript и функции ОС **не реализованы**. Этот документ фиксирует контракт для последующих этапов.

## Вызов `__call`

Метаметод получает `(owner, defining_metatable, args_table)`; пользовательские аргументы помещаются в числовые слоты таблицы начиная с 0. Вызов доступен из C через `fvm_meta_call`. Если `__call` — вызываемый C-объект, он вызывается через C stack bridge. Дополнительно поддерживается нативный обработчик, зарегистрированный `fvm_meta_register`. Функции AS как значения пока не поддерживаются.

## Потоки

Планируемый API: `thread.run(fn, copied_arg)`, `thread.run_suspended(fn, copied_arg)`, `thread.join(...)`, `thread.sleep(seconds)`, `thread.sleepms(ms)`, `thread.sleepus(us)`. Результат запуска — дескриптор с `start`, `stop`, `state`, `ret`. `stop` должен означать запрос кооперативной отмены, а не небезопасное принудительное убийство потока. `join` не должен блокировать сам себя. Каждый поток получает новый VM context; простые данные и таблицы копируются глубоко с сохранением общих ссылок внутри копии, но каналы остаются общими дескрипторами. Нативные функции, замыкания и userdata требуют явных правил переноса и по умолчанию не копируются.

## Каналы

Планируемые операции: `c <- value`, `value <- c`, `ready ?- c`. Каналы — двунаправленные и синхронизированные; внутренние сообщения типизированы, а сетевые требуют явно заданной сериализации и границ сообщений. Сетевые режимы TCP/UDP, DNS/IP, text/bin, TLS (при наличии криптобэкенда). `ready` сообщает только о наличии данных в момент проверки и не гарантирует, что следующий приём не заблокируется.

Для TCP необходимы фрейминг сообщений, частичные чтения/записи и обработка закрытия соединения. Для UDP — ограничения размера дейтаграммы. TLS требует проверки сертификатов и имени сервера. Нельзя пересылать сырые адреса объектов между процессами или контекстами.

## Формат данных

Суффиксы `::d8`, `::d16`, `::d32`, `::d64` (big endian) и `::8d`, `::16d`, `::32d`, `::64d` (little endian) — проект синтаксиса, пока не поддерживаемый парсером. Следует определить преобразования целых и вещественных чисел, переполнение, знаковость, Unicode и поведение при недопустимых размерах до реализации.

## Совместимость

Расширения `for (k, v in pairs(table))`, `for (k, v in threads)` и литералы `<...>` требуют изменения грамматики и компилятора ActionScript; стандартный AVM1-байткод их не содержит. Нужен отдельный компилятор расширенного языка либо C API, формирующий эквивалентные операции.
