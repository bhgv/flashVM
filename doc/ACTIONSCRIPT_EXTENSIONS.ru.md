# ActionScript: GC, потоки и каналы

## Установка и вызовы

Перед AVM1 вызвать `fvm_extensions_install(context)`. Он создаёт глобальные
объекты `gc`, `thread`, `channel`, `metatable`, `mutex`, принадлежащие контексту. Повторная установка
допустима, если все пять объекта сохранены. Конфликт или частичная замена
глобальных имён возвращает `FVM_INVALID_ARGUMENT`, пользовательские значения
не перезаписываются. Без установки поведение существующих контекстов прежнее.
C89 ABI: `flashvm/extensions.h`; реализация C++98 без STL.

Методы привязаны к объекту: одноимённая скриптовая или глобальная нативная
функция не перехватывает вызов. Текущий AVM1 использует именованные функции,
а не общие значения-функции и лексические замыкания. Поэтому worker принимает
**строку с именем функции**. Обычные dot-вызовы выполняются через CallMethod.
Операторы `<-`, `?-` и расширенные литералы не реализованы.

## Объект gc

| Вызов | Контракт |
| --- | --- |
| `gc.collect()` | Полный проход, число освобождённых объектов |
| `gc.step()` | Проход по порогу выделений, число освобождённых |
| `gc.mode(mode)` | -100..100; 101 — приостановка, 102 — один полный проход |
| `gc.state()` | Сохранённый режим; разовый полный проход его не меняет |
| `gc.count()` | Число живых объектов |

Только доверенные GC-методы могут собирать во время диспетчеризации метода;
получатель и аргументы зарегистрированы как корни. Для остальных нативных
callback защита повторного входа сохранена. GC внутри нативного callback или
финализатора запрещён либо отложен согласно C API. См. `GC_COMPLETION.ru.md`.

## Потоки и handle

| Вызов | Контракт |
| --- | --- |
| `thread.run(name, input?, sharedChannel?)` | Снимок именованных функций и входа, старт отдельной VM |
| `thread.run_suspended(...)` | Тот же снимок, ожидание start |
| `thread.join(handle, ...)` | Проверить уникальные handle и дождаться всех; один результат либо индексированная таблица |
| `thread.stopRequested()` | Запрошена ли отмена текущего worker; false в основной VM |
| `thread.sleep(seconds)`, `sleepms(ms)`, `sleepus(us)` | Неотрицательная задержка с проверкой отмены |
| `handle.start()` | Идемпотентный старт |
| `handle.stop()` | Кооперативная отмена; будит приостановленный worker |
| `handle.state()` | 0 suspended, 1 running, 2 finished, 3 joined |
| `handle.join()` | Ожидание и результат; автоматически запускает suspended |
| `handle.ret()` | Undefined до завершения; затем кэшированный результат |

Вход и результат — примитивы либо обычные объектные графы. Снимок сохраняет
циклы и общие ссылки; VM-объекты между потоками не разделяются. Изменение
входа после run_suspended не влияет на worker. Определения именованных функций
копируются при создании. Глобальные значения родителя, произвольные нативные
регистрации и замыкания не копируются. В worker устанавливаются стандартные
объекты. Необязательный канал доступен как `sharedChannel`: разные VM имеют
разные GC-обёртки с удержанием одного нативного handle.

join/ret кэшируют декодированный объектный результат в обёртке worker, GC
трассирует этот корень. Повторное получение сохраняет идентичность результата.
Удаление последней ссылки и GC освобождают граф результата, запрашивают stop,
выполняют join и освобождают нативные ресурсы. Уничтожение контекста делает
то же. Отмена AVM1 проверяется каждые 64 инструкции; ожидания встроенных
каналов и сон также проверяют отмену. Вложенные join скриптовых worker проверяют отмену и запрашивают stop дочернего
потока. Произвольный нативный callback нельзя принудительно прервать. Для предсказуемого времени
очистки выполнять явный join. Self-join запрещён.

Ошибка worker возвращается как FVM_Result из C-вызова или исполнения AVM1;
объектов исключений ActionScript в этом подмножестве нет. Undefined в ret
может означать и незавершённый worker, и реальный undefined-результат —
проверять state. Multi-join проверяет все handle до старта и ждёт остальных
даже при ошибке одного worker.

## Каналы

| Вызов | Контракт |
| --- | --- |
| `channel.create(capacity?)` | Создать обёртку; 0/по умолчанию — без ограничения |
| `ch.send(value)` | Дождаться места, передать снимок графа, вернуть true |
| `ch.trySend(value)` | True при отправке, false при полной открытой очереди |
| `ch.receive()` | Дождаться сообщения, скопировать в VM получателя |
| `ch.tryReceive()` | Undefined при пустой открытой очереди, иначе сообщение |
| `ch.ready()`, `ch.pending()` | Моментальный снимок готовности/размера |
| `ch.capacity(n)` | Изменить ёмкость, сохранить уже поставленные сообщения |
| `ch.close()` | Разбудить ожидающих; запретить отправку, разрешить чтение остатка |

Пустой закрытый канал и отправка в закрытый возвращают FVM_ERROR. При нескольких
потребителях ready не гарантирует немедленный receive. Undefined-сообщение и
пустой tryReceive выглядят одинаково; для различения использовать объект-конверт.

`fvm_extensions_wrap_channel(context, handle, &object)` удерживает нативный канал
и предоставляет обёртку для embedding. Глобальная ссылка или pin удерживает её;
GC снимает её ссылку на канал. Последний нативный release допустим после
завершения всех пользователей handle.

## Передача графов через C API

`flashvm/transfer.h`: fvm_channel_send_value / fvm_channel_receive_value.
Итеративно копируются именованные и индексированные свойства, прототипы и
метатаблицы. Сохраняются циклы и повторные ссылки. После успешной отправки
исходную VM можно собрать или уничтожить. Ограничения и поддержанные нативные кодеки описаны в
[FILE_CHANNELS.ru.md](FILE_CHANNELS.ru.md). С версии 0.3 снимок имеет ограниченный
версионированный бинарный формат без указателей и используется также файловыми
каналами. Есть кодеки Boolean, Math, TextFormat и созданного хостом TextField.
Пользовательским нативным callbacks нужны зарегистрированные устойчивые ID.
Дескрипторы mutex/channel передаются совместно в каналах памяти; другие живые ресурсы и произвольные замыкания пока не поддержаны. Примитивное чтение
оставляет граф в очереди; контекстное снимает запись и транзакционно восстанавливает
её, включая откат при ошибке. TCP/UDP/TLS остаются будущей работой.

`channel.create("file", path[, mode])` принимает `r`, `w`, `rw` (по умолчанию).
Конец файла, ёмкость и счётчик сообщений отличаются от очереди в памяти; см.
FILE_CHANNELS.ru.md. `metatable.attach(value, table)` возвращает значение с
метаданными, `metatable.get(value)` получает его таблицу. ABI 2 добавляет
метаданные примитивов и требует пересборки нативных клиентов.

## Проверки и границы

actionscript_extensions исполняет реальные AVM1-инструкции: диспетчеризация,
жизненный цикл, строки и графы результата, изоляция снимка, общий канал,
кэшированные корни, multi-join, отмена, очистка GC. channel_graph_transfer
проверяет циклы, уничтожение исходной VM, индексы и прототип, запрет callback.
gc_deep_graph собирает цикл из 12 000 объектов без рекурсивной маркировки.
channel_close_races проверяет гонки close с отправителями и получателями.

Команды и результаты — `VALIDATION.ru.md`. Это проверенное расширение указанного
подмножества AVM1, а не полная совместимость Flash Player или произвольного
ActionScript. Строки пока живут до уничтожения контекста. LeakSanitizer,
инъекция отказов памяти во всей VM и нативные проверки Windows/macOS/Android
остаются открытыми работами.

Shared mutex/channel transfer and debugger: [English](MUTEX_CHANNEL_DEBUG.md) / [Русский](MUTEX_CHANNEL_DEBUG.ru.md).
