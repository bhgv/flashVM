# Проверка платформ — v0.349

[English reference](PLATFORM_VALIDATION.md)

Стадия 9 требует настоящих сборок и запусков каждой ОС и приёмки стадий 1–8.
Добавлены повторяемые прогоны, а не доказательство готовности недоступных ОС.
Реализован только вывод HEADLESS. Архивы исходников/Git не создаются согласно
действующему указанию пользователя. Встроенные зависимости остаются статическими.

Для Windows, Linux или macOS нужны Python 3.8+, Git, CMake/CTest 3.26+ и нативный
компилятор. Из корня репозитория запустите:

```sh
python scripts/validate_platform.py --profile all --jobs 4
```

Профили `cmake/profiles/{agg,cairo,minimal}.defs` не меняют DEFS.txt. AGG/Cairo
включают шрифты, кодеки, SQLite, OS ports и render jobs; minimal отключает графику,
шрифты, кодеки и SQLite, сохраняя реальные потоки и сеть. Собираются Release,
все доступные тесты, примеры и reference runner. Assertions остаются включёнными.
Ошибка любой фазы останавливает прогон; отсутствие тестов считается ошибкой.
Существующая кросс-сборка не допускается к нативному запуску.

Параметры `--cmake`, `--ctest`, `--generator`, `--build-root` задают инструменты
и каталог результата. Поддержан Release для многоконфигурационных генераторов
Windows. Профили идут последовательно, `--jobs` задаёт параллелизм внутри профиля.
Каждая ОС требует собственного прогона.

В игнорируемом `build-platform/` сохраняются журналы фаз и JSON с версией,
коммитом, признаком незакоммиченных изменений, реальной ОС/CPU, путями компиляторов,
командами и результатами. Ошибка или прерывание не даёт общего статуса passed.
Журналы/JSON не коммитятся и не являются сертификатом завершения roadmap.

Для Android используйте NDK, SDK platform-tools с ADB shell-v2, устройство или
эмулятор API 24+ и совпадающий ABI. Полная команда приведена в английском
руководстве. Укажите `ANDROID_STL=c++_static` и задайте список
`CMAKE_CROSSCOMPILING_EMULATOR`: абсолютный путь Python, абсолютный путь
`scripts/android_test.py`, `--serial`, точный serial устройства, `--directory`,
`/data/local/tmp/flashvm-SESSION`, `--timeout`, `175`.

Затем выполните сборку и обычный CTest. Адаптер копирует каждый исполняемый файл,
переходит в выделенный каталог и запускает его на выбранном устройстве. Аргументы
экранируются, ошибки копирования/связи и код возврата программы передаются CTest.
Serial обязателен; устройство автоматически не выбирается. Для каждой сборки
нужен свой SESSION, общий для всех её тестов: это сохраняет файл между отдельными
writer/reader процессами. После прогона удалите только свой каталог SESSION.
После обрыва связи/таймаута проверьте оставшиеся процессы на устройстве.
CTest по-прежнему ограничивает обычный тест 30 секундами, отдельные — 180.

Python-сценарии нескольких процессов, сети, TZ и reference runner не регистрируются
при кросс-сборке: они запускают бинарники напрямую на хосте, обходя эмулятор CTest.
Их исполняемые компоненты доступны отдельно, но аналогичная оркестрация на Android
ещё нужна. CMake явно сообщает об исключении этих сценариев. Python на устройстве
не нужен. Кросс-сборка без адаптера запуска доказывает только сборку.

Локальные проверки ADB-адаптера используют имитацию транспорта; тест называется
`flashvm_android_adapter_host` и не считается запуском Android. Linux-подобные
ветки Android JIT сами по себе также не доказывают выполнение на устройстве.
Существующие ограничения JIT Windows/macOS сохраняются; interpreter fallback
не подтверждает наличие рабочего нативного backend этих ОС.

Приёмка: [RELEASE_ACCEPTANCE.md](RELEASE_ACCEPTANCE.md), [ROADMAP.md](ROADMAP.md).
Все стадии остаются открытыми до выполнения их реальных критериев.

## Локальные проверки v0.349

Linux x86-64 GCC/G++ 13.3, CMake/CTest 4.4.4 Release: в итоговых полных прогонах
AGG 701/701, Cairo 701/701, minimal 682/682, включая примеры и reference runner.
Первые/промежуточные прогоны получили BAD_COMMAND: у части созданных ELF отсутствовало
право исполнения. После восстановления прав прошли целевые проверки и полные
наборы. Прогон сохранил отказы; сам он права не меняет и тесты не повторяет.
Ошибок поведения, скрытых повторным запуском, не было. Пять проверок имитации
транспорта включены в host-тест адаптера. В кросс-конфигурации проверены 675 команд
и порядок файловой фикстуры; нативный прогон отверг такую сборку. Отдельно проверены
отсутствующий/устаревший инструмент. Это Linux и проверки хоста/конфигурации,
а не запуск Android, Windows или macOS.
