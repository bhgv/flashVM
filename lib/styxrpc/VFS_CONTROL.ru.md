# Отмена операций смонтированной VFS

[English](VFS_CONTROL.md) · [Руководство SDK](README.ru.md) · [Провайдеры обычных деревьев](reference/server_enable_mutations.ru.md)

Операция над обычным путём может пройти несколько компонентов, прочитать
метаданные, затем открыть, создать или удалить точный fid. Используйте вызовы
SDK с суффиксом `_until`, если вызывающий может остановиться на этих этапах.
Они отправляют штатные запросы Styx через существующее подключение и прерывают
ожидание обычным `Tflush` по тегу. Колбэк читает флаг остановки в потоке вызова,
в том числе при ожидании ответа на мультиплексоре.

| Операция | Вызов SDK |
| --- | --- |
| Метаданные пути или открытого файла | [stat](reference/vfs_stat_until.ru.md), [stat файла](reference/vfs_file_stat_until.ru.md) |
| Открытие файла или каталога | [файл](reference/vfs_open_until.ru.md), [каталог](reference/vfs_dir_open_until.ru.md) |
| Один шаг по каталогу | [следующая запись](reference/vfs_dir_next_until.ru.md) |
| Однократное изменение пространства имён | [создать новый файл](reference/vfs_create_until.ru.md), [mkdir](reference/vfs_mkdir_until.ru.md), [remove](reference/vfs_remove_until.ru.md) |
| Обмен через открытый файл | [чтение](reference/vfs_file_read_until.ru.md), [запись](reference/vfs_file_write_until.ru.md) |

Исходное подтверждение может успеть раньше завершения flush. В этом случае
SDK выдаёт подтверждённый результат. При отмене допуска сохраняются выходные
данные вызывающего и освобождаются временные fid. Отмена шага по каталогу
завершает его поток. Для продолжения закройте курсор и откройте путь заново.
При отмене stat открытого файла его заимствованный fid остаётся у вызывающего.

Остановка до отправки изменения возвращает `STYXRPC_IO_CANCELLED`. Отправленный
`Tcreate` либо `Tremove` без надёжного исходного ответа дают
`STYXRPC_IO_UNCERTAIN`. Провайдер мог применить изменение. SDK автоматически
его не повторяет. Если приложению важно текущее состояние, проверьте его
отдельным обходом.

На последовательном транспорте вызывающий может остановиться перед каждым
этапом. Уже начатый обмен использует настроенный срок ожидания.
Мультиплексному клиенту требуется ответ сервера на flush либо исходный запрос.
Синхронные колбэки провайдера определяют, когда сервер сможет обработать
следующие запросы.

## Проверка

Запустите `ctest --test-dir build-styxrpc -R styxrpc-vfs-control-wire --output-on-failure`.
[Тест протокола](tests/vfs_control_wire.c) удерживает выбранное подтверждение,
читает через соседний fid и посылает flush по нужному тегу. Сценарии изменений
проверяют возможный эффект и случаи, когда подтверждение выигрывает гонку.
Тест также удерживает второй фрагмент длинного обхода и проверяет, что
отменённый курсор каталога нельзя перемотать.

[Руководство по задачам AS2](https://github.com/bhgv/flashVM/blob/master/flashVM/doc/ASINC_VFS.ru.md)
запускает настоящую пару FlashVM–DisVM с тем же протоколом.
