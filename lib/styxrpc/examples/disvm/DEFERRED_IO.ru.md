# Запуск отменяемого файлового провайдера C и клиента Limbo

[English](DEFERRED_IO.md) · [Устройство провайдера](../../DEFERRED_IO.ru.md) · [Примеры](../README.ru.md)

1. Настройте SDK с `STYXRPC_EXAMPLES=ON`, `BUILD_TESTING=ON` и
   `CMAKE_PREFIX_PATH`, который указывает на установленные пакеты Styx
   и Unibus. Для клиента Limbo передайте `STYXRPC_DISVM_SOURCE` и
   `STYXRPC_DISVM_BUILD` для соответствующих исходников и сборки нативного
   DisVM с terminal launch. Нужны `disvm` и `bootstrap/limbo-bootstrap`.
2. Соберите и запустите хостовые проверки.

   ```sh
   cmake --build build-styxrpc
   ctest --test-dir build-styxrpc -R 'styxrpc-(disvm-)?deferred-' --output-on-failure
   ```

[Провайдер C](deferred_device.c) устанавливает выбор для байтового файла
`data` и писателя, выдаваемого при создании `new`. Каждое открытие получает
своё состояние. Чтение ждёт разрешения владельца, запись подтверждает один
байт и ждёт начиная со смещения один. Синхронный файл `gate` показывает
счётчики допуска и принимает команды продолжения чтения, остановки новых
чтений и выхода отменённых колбэков. Он доступен и при нескольких ожидающих
потоках.

[Клиент C](deferred_client.c) запускает чтение и двухбайтовую запись. Он
отменяет запись после подтверждения первого байта и закрывает fid до выхода
потока провайдера. Клиент проверяет завершение соседнего чтения, отменяет
другое чтение, открывает файл заново и создаёт новый файл с писателем в
нативном потоке. Последнее чтение остаётся в ожидании до разрыва. Проверка
нагрузки занимает все шестнадцать мест. Она подтверждает, что отменённый
поток сохраняет место до выхода, и использует это место для нового чтения.

[Клиент Limbo](deferred.b) работает с тем же провайдером C через обычные
`Sys.read` и `Sys.write` в монтировании `/device`. Родитель ждёт входа
обоих колбэков и вызывает `Processctl.cancelwait` для писателя. Он проверяет
сохранение подтверждённого байта, даёт второму потомку закончить, затем
отменяет нового читателя. После этого открывает файл заново и проверяет
писателя, выданного `Sys.create`.

[Сценарий запуска](deferred.py) передаёт концы пары Unix-сокетов либо
соединённого TCP-потока на loopback. Четыре теста DisVM выполняются в
интерпретаторе и JIT на обоих транспортах. Успешный клиент печатает `PASS`.
Перед завершением провайдер проверяет точные счётчики отмены и закрытие
всех состояний файлов.
