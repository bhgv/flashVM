# Изменяемое дерево 9P из C и Limbo

[English](MUTATIONS.md) · [Руководство SDK](../../README.ru.md) · [API изменения дерева](../../reference/server_enable_mutations.ru.md)

[Провайдер C](mutable_device.c) обслуживает небольшое дерево в памяти через унаследованный Unix-сокет. ID файлов соответствуют устойчивым ячейкам. При появлении или удалении потомка увеличивается ревизия каталога. Каждый читатель и писатель удерживает выбранную ячейку. Повторное создание имени не перенаправляет уже открытый файл.

1. Соберите хостовые пакеты Styx и libstyxrpc. В конфигурации libstyxrpc задайте `STYXRPC_EXAMPLES=ON` и `BUILD_TESTING=ON`. Передайте `STYXRPC_DISVM_SOURCE` и `STYXRPC_DISVM_BUILD`, чтобы включить тесты DisVM.
2. Запустите `ctest --test-dir build-styxrpc -R 'styxrpc-(mutable-tree|disvm-mutations)' --output-on-failure`. [Сценарий](mutations.py) создаёт новую пару сокетов для каждого прогона. Один конец получает провайдер, другой получает клиент C или DisVM.
3. [Клиент C](mutation_client.c) создаёт каталог и файл, записывает данные, проверяет отказ при создании дубликата и при удалении непустого каталога. Затем удаляет файл, читает прежние данные через удерживаемый fid и удаляет пустой каталог.
4. [Клиент Limbo](mutations.b) монтирует дерево C в `/device`. Он открывает запись через `Sys.create(path, Sys->OWRITE | Sys->OEXCL, 8r666)`, проверяет отказ для каталога только для чтения и служебного узла, затем создаёт то же имя после `Sys.remove`. Старый и новый читатели возвращают разные данные.
5. Каждый клиент печатает `PASS` после проверок. После закрытия сессии провайдер проверяет освобождение всех состояний fid и завершается. При ошибке тест выводит сообщение дочернего процесса.

Оба клиента посылают стандартные запросы Styx. Помимо операций с файлами SDK предоставляет функцию создания каталогов. В монтировании Limbo поддерживаются исключительное создание файла и удаление.
