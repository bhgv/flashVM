# Два канала одного C-модуля

[English](module_channels.md) · [libstyxrpc](../README.ru.md)

## Подготовка

Понадобятся Linux, C-компилятор, CMake, Python 3, установленный префикс Styx
и UniBus, двоичные файлы DisVM и `limbo-bootstrap` и каталог модулей Limbo
`disVM/upstream/module`. Из каталога `lib/styxrpc` соберите примеры с
`STYXRPC_EXAMPLES=ON`. Этот флаг добавляет хостовые библиотеки и программы
примера. Адаптер примера использует Linux `getrandom` для выдачи токенов.

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/prefix -DSTYXRPC_EXAMPLES=ON
cmake --build build
python3 examples/disvm/run.py --channels --runtime /path/to/disvm \
    --limbo /path/to/limbo-bootstrap --module /path/to/disVM/upstream/module \
    --device build/styxrpc-channel-device
```

`--channels` собирает канального клиента Limbo, подключает процессы одним
сокетом и монтирует модуль под `/device`. Повторите команду с `--jit`,
чтобы выполнить тот же сценарий в JIT, иначе используется интерпретатор.
Ожидаемый результат в обоих режимах — `PASS Limbo/C live channels over Styx`.

## Как устроен пример

1. В `channel_device.c` массив `leases` резервирует восемь одновременных
   выдач. `fill_entropy` заполняет запрошенный буфер полностью, продолжая
   после прерванного чтения. `main` инициализирует реестр до запуска сервера.
   На открытии `.unibus` диспетчер использует описатель реестра.
2. При вызове `port()` функция `publish_port` проверяет запрос и создаёт
   отдельный `DevicePort`. В `owned_port.c` планировщик получает одну очередь
   ёмкостью в одну строку. Токен связывает именно эту очередь с результатом
   вызова. Если после публикации не удаётся собрать ответ, код отзывает
   токен и освобождает порт. Клиент получает ошибку записи вызова.
3. `channel_client.b` дважды вызывает `port()` и удерживает оба результата.
   Два канала используют один ключ внутри своих выдач. Клиент записывает
   разные строки, проверяет готовую ветку `alt` первого канала и читает
   второй. Оба результата привязаны к своим fid функции.
4. При первой записи в операционный fid `.unibus` библиотека проверяет
   токен и вызывает открытие нужной очереди. При записи запроса библиотека
   вычитает 16 байтов токена из смещения. Приём или выбранный `alt`
   читается со смещения ноль. Место для следующей строки освобождается
   после успешного приёма.
5. Закрытие fid функции вызывает отзыв токена, отменяет её ожидающие
   операции и освобождает очередь. Другой токен продолжает обслуживаться.
   При выходе сценарий закрывает сокет и дожидается дочерних процессов.

Для проверки отказа при неверном токене, заполнения реестра и повторного
использования слота запустите:

```sh
ctest --test-dir build -R '^styxrpc-module-channels$' --output-on-failure
```
