# Общая ячейка между C и Limbo

[English](README.md) · [Каталог примеров](../README.ru.md) · [Устройство ячеек и список API](../../reference/named_cell.ru.md)

Пример передаёт записываемую ссылку через Styx. Процесс C обслуживает
`/.channels` и создаёт отдельное локальное подключение к тому же реестру.
Программа Limbo работает в DisVM и монтирует удалённый конец Unix-сокета.
Обе программы открывают собственные fid одной ячейки и видят
подтверждённые записи друг друга. Именованный канал передаёт ссылку
и упорядочивает шаги. После передачи ячейка остаётся доступной через аренду.

## Сборка и запуск

Нужны Linux64, компилятор C, CMake, Python 3 и установленные хостовые
пакеты Styx и Unibus. Для энтропии жетонов сервис C использует
`getrandom` Linux. Для запуска гостя нужны собранная DisVM,
bootstrap-компилятор Limbo, два каталога объявлений и исходники
`Styxnamed` и `Styxvalue`. Для сборки C достаточно отдельного каталога
libstyxrpc и префикса SDK.

```sh
cmake -S /path/to/styxrpc -B /path/to/rpc-build \
    -DCMAKE_PREFIX_PATH=/path/to/sdk -DSTYXRPC_HOSTED=ON -DSTYXRPC_EXAMPLES=ON
cmake --build /path/to/rpc-build --target styxrpc-shared-cell

python3 /path/to/styxrpc/examples/shared-cell/run.py \
    --host /path/to/rpc-build/styxrpc-shared-cell \
    --disvm /path/to/dis-build/disvm --limbo /path/to/dis-build/bootstrap/limbo-bootstrap \
    --system-modules /path/to/disVM/upstream/module --native-modules /path/to/disVM/module \
    --limbo-sources /path/to/disVM/limbo
```

| Параметр | Назначение |
| --- | --- |
| `--host` | Собранная программа сервиса C. |
| `--disvm` | DisVM с командами raw-монтирования Styx и запуска в нативном потоке. |
| `--limbo` | Bootstrap-компилятор Limbo для гостя и его библиотек. |
| `--system-modules` | Каталог со стандартными объявлениями, включая `sys.m`. |
| `--native-modules` | Каталог объявлений проекта, включая `styxnamed.m`. |
| `--limbo-sources` | Каталог с исходниками `styxvalue.b` и `styxnamed.b`. |
| `--jit` | Запуск через JIT DisVM. По умолчанию используется интерпретатор. |

[Скрипт](run.py) собирает три файла `.dis` во временный рабочий каталог.
Каждый процесс получает свой конец сокета. DisVM монтирует его с
`--raw` по пути `/device` и запускает гостя в нативном потоке.
Гость ставит смонтированную службу первой в своём корневом пространстве
имён, чтобы `Styxnamed` нашёл `/.channels`. Сервис задаёт срок уровня приложения восемь секунд.
Отдельно действуют сроки запросов Styx. Скрипт ограничивает ожидание
дочерних процессов и удаляет временные образы.

Ожидаемый вывод в обоих режимах.

```text
PASS C shared cell cancellation and token retirement
PASS Limbo observed both values through the same lease
PASS Dis application completed
```

## Как проходит обмен

| Шаг | Сервис C | Гость Limbo |
| --- | --- | --- |
| 1 | Создаёт ячейку с Boolean `true`. По `/settings` передаёт тег 8 и жетон из 24 байтов. | Принимает дескриптор и открывает собственную аренду до следующего обращения к каналу. Читает `true`. |
| 2 | Получает `a`, открывает вторую аренду C по тому же жетону, закрывает fid создателя. | Записывает Boolean `false` и посылает уведомление `a`. |
| 3 | Запрашивает остановку до записи. Читает `false` через временный fid. Затем подтверждённо записывает `true` и отправляет `r`. | После `r` читает `true` через ту же аренду Limbo. |
| 4 | Получает `c`, закрывает оставшуюся аренду C и ждёт отказа при присоединении по старому жетону. | Закрывает аренду ячейки и отправляет `c`. |
| 5 | Отправляет `d`, ждёт `e`, закрывает канал, дожидается потоков службы и освобождает реестр. | Принимает `d`, отправляет `e`, дожидается отключения сервиса и закрывает канал. |

[Код C](host.c) разделяет управляющую встречу и доступ к значению.
`exchange()` удерживает первую аренду во время передачи и закрывает
её после открытия обеих ссылок. `reads_disabled()` заимствует жетон,
сверяет тег и Boolean, затем освобождает буфер ответа. Колбэк
`deadline_reached()` использует монотонный срок вызывающего.
`already_stopped()` воспроизводит раннюю отмену.

[Код Limbo](guest.b) присоединяется к дескриптору, пока принявший его
канал удерживает временную ссылку. Собственная аренда переживает
последующие сообщения. Гость закрывает её перед уведомлением `c`.
Ответ `e` подтверждает, что Limbo прочитал полный кадр `d`. Limbo
удерживает подключение, пока C читает `e` перед остановкой сервиса.
Гость может освободить FD до того, как провайдер получит clunk.
`retired_token()` проверяет старый жетон через новые fid до первого отказа
или истечения срока. Каждый успешно открытый fid сразу закрывается.
После отказа последняя встреча подтверждает работоспособность подключения.


## Как развить пример

Ранняя отмена подходит, когда присваивание уже не нужно. В приложении
остановка может прийти после отправки части или всего значения. Запись
без положительного подтверждения может вернуть `STYXRPC_IO_UNCERTAIN`.
Если для следующего действия нужно текущее значение, прочитайте его
через живую аренду. Другие владельцы могли успеть записать новое значение.
[Тест протокола](../../tests/cell_stop_wire.c) проверяет отмену заголовка,
отправленное тело, короткий подтверждённый префикс и приоритет ответа.
[Парная проверка FlashVM](../../tests/flashvm/cancel-cell-setup_worker.as)
показывает отмену доступа к принятой ссылке из ActionScript.

При ошибке скрипт выводит сообщения обоих процессов. Ошибка монтирования
или отсутствующего модуля требует проверки путей к среде и объявлениям.
Сообщение `shared-cell exchange, deadline or retirement check failed`
означает, что не удалось подтвердить шаги ожидаемого обмена.
После истечения срока одна из сторон может завершиться. Скрипт
закрывает сокет и дожидается процессов. Сервис освобождает оставшиеся fid.
