# Образы модулей и файлы управления

[English](MODULES.md) · [Главная SDK](README.ru.md)

Для хостовых деревьев колбэков подключите `StyxRpc::serve`. Задайте каждому экспорту компилированную сигнатуру Dis, схему, если профиль её использует, обычный колбэк C и его контекст. [Создайте образ](reference/module_create.ru.md) и передайте его серверу Styx как контекст дерева `styxrpc_module_tree`. Образ содержит один `.interface`, файл каждого метода, маркеры выбранных профилей и необязательные живые знаковые целые ячейки в `.var`. Клиент Limbo может применить типизированный `load` к смонтированному каталогу. Другая хостовая программа C может [проверить интерфейс](reference/module_check.ru.md) перед привязкой вызываемых импортов.

Хост может опубликовать [файлы управления](reference/control_create.ru.md) программой или устройством. Опубликуйте `styxrpc_control_tree` самостоятельно или передайте описатель управления в спецификацию модуля для публикации обоих деревьев в одной сессии. `.upload` принимает беззнаковую длину payload из 32 бит в порядке big-endian, затем ровно столько байтов. Запись начинается со смещения ноль и идёт последовательно. Последняя запись успешна, только если владелец принял полную загрузку. Закрытие неполной загрузки отбрасывает её. Чтение `.state` даёт текстовый снимок на fid. Запись принимает `start`, `pause`, `restart` или `debug` со смещения ноль, с необязательным LF. Владелец определяет проверку загрузки, переходы, статистику и тактовый цикл. Используйте выданный транспорт. Сервер сам не выдаёт соединения и не проверяет учётные данные.

Прежде чем [освободить модуль](reference/module_destroy.ru.md) или [описатель управления](reference/control_destroy.ru.md), закройте сервер с открытыми fid. Колбэки выполняются синхронно в потоке владельца. Связь с какой-либо VM для этих деревьев не нужна.

Для [обычного клиента VFS](reference/vfs_stat.ru.md) подключите `StyxRpc::launch`. Он исключает `.prog` при выводе каждой страницы и отклоняет обычные пути с таким компонентом. [Типизированное открытие int](reference/vfs_int_open.ru.md) принимает явно выданную ячейку в `.var`. У существующих типизированных путей каналов и программ свои правила доступа.
