# Точные живые переменные VFS

[English](LIVE_VALUES.md) · [SDK C](README.ru.md) · [Парный пример](examples/disvm/LIVE_STAGE.ru.md) · [Справочник FlashVM](https://github.com/bhgv/flashVM/blob/master/flashVM/doc/STYX_RPC_LIVE_VARIABLES.ru.md)

Хостовое приложение C может работать с опубликованными скалярами, индексными коллекциями и именованными полями через действующий клиент Styx. Подключите `StyxRpc::launch` и `<styxrpc/live_client.h>`. Достаточно обычной смонтированной сессии. Обнаружение экспортов, вызовы и переменные используют одно соединение. Для допущенного пути VFS PID вызывающего не нужен.

## Контракт проекции для владельца

Пока доступен тот же объект, выдавайте постоянные Qid.path и тип файла. При публикации другого объекта под тем же именем назначайте новый Qid.path. Обход от удерживаемого fid должен оставаться в захваченной публикации. Для корня и потомков нужен обход без открытия, а также stat. Права доступа действуют для данных, `.type` и остальных метаданных.

| Узел | Тип и обмен |
| --- | --- |
| Файл Int32 в `.var` или поле типизированной записи | Обычный читаемый файл длиной 4 байта. Число знаковое, старшие байты идут первыми. |
| Фиксированный массив Int32 | `.type` содержит `array of int
`. `.len` хранит неотрицательное десятичное число и перевод строки. В `.idx` запишите четырёхбайтный беззнаковый индекс, затем работайте с `.val` как с Int32. |
| Вектор big | `.type` содержит `vector of big
`. Формат длины тот же. Селектор принимает восьмибайтный знаковый индекс в сетевом порядке. `.val` читает и пишет восьмибайтное знаковое значение. |
| Числовая часть гибридной таблицы | `.type` содержит `table of big
`. `.len` выдаёт длину плотной части. Селектор принимает нулевой байт и восьмибайтный знаковый ключ в сетевом порядке. Отрицательный индекс отсчитывается от конца плотной части. Формат `.val` совпадает с вектором. |
| Именованная запись | `.type` содержит `record
`. `.len` считает именованные поля. Каждое поле публикуется отдельным потомком со своим типом. |
| Строка или скаляр big | `.type` содержит `string
` или `big
`. `.val` хранит одну полную S-запись описанного ниже вида. |

В строковом `.val` идёт `STYXRPC_VALUE_STRING` (тег 7) до 1024 байт UTF-8 либо `STYXRPC_VALUE_NIL` (тег 9) без полезной нагрузки. Для скаляра big используется `STYXRPC_VALUE_BIG` (тег 2) со штатным знаковым кодированием. Одна полная запись со смещения ноль заменяет значение. Один fid чтения выдаёт один снимок, даже если потребовалось несколько чтений. Действуют обычный обмен Styx и кодек UniBus. Владелец должен принимать всё значение за одну запись при согласованном размере сообщения. [Общие константы](include/styxrpc/live_variable.h) · [Кодирование целого](reference/value_integer.ru.md).

Для индексной операции клиент удерживает селектор до конца обмена с `.val` и закрывает fid значения первым. DisVM закрепляет активный селектор за смонтированной сессией. Параллельный выбор в той же коллекции и сессии может вернуть занятость или отказ. Сериализуйте операции целиком.

## Владение и ожидание

Вызывающий владеет сессией и закрывает привязки перед её уничтожением. Привязка удерживает точный fid. Перед чтением, записью, запросом длины или захватом поля отдельный обход сверяет видимость и идентичность. Поле получает собственный fid. Чтение возвращает копию.

Синхронная операция может использовать `stop(state)` в вызывающем потоке. Остановка проверяется между запросами и во время прерываемого обмена. Последовательный транспорт может проверять её только перед отправкой запроса. Исходы имеют следующие значения.

| Исход | Значение |
| --- | --- |
| `STYXRPC_IO_OK` | Операция подтверждена. Доступны результат чтения, счётчик или захваченная привязка. |
| `STYXRPC_IO_NOT_OPEN` | Допуск отклонён. Примеры включают закрытую или устаревшую публикацию, неверный индекс и отказ режима. |
| `STYXRPC_IO_FAILED` | Подтверждённый сбой обмена или ошибка записи протокола. |
| `STYXRPC_IO_CANCELLED` | Вызывающий остановил операцию. Временный селектор освобождается. |
| `STYXRPC_IO_UNCERTAIN` | Нет надёжного подтверждения. Итоговая запись могла изменить значение. Проверьте состояние перед повтором. |

Кроме закрытия, операции используют временные fid и освобождают их перед возвратом или ставят освобождение в очередь при остановке. Удерживаемый fid никогда не переключается на другую публикацию. Используйте один контекст владельца для последовательных операций над сессией и её привязками.
