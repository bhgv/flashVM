# styxrpc_server_enable_deferred_io

[English](server_enable_deferred_io.md) · [Руководство провайдера](../DEFERRED_IO.ru.md) · [Создание сервера](server_create.ru.md)

## Синтаксис

```c
#include <styxrpc/serve.h>

typedef unsigned (*StyxRpcDeferFile)(void *context, uint64_t id);

int styxrpc_server_enable_deferred_io(StyxRpcServer *server, StyxRpcDeferFile select);
```

Хостовая сборка C99, цель `StyxRpc::serve`.

## Параметры и результат

| Параметр | Значение |
| --- | --- |
| `server` | Обычный сервер дерева колбэков. Вызовите у владельца до первого шага обслуживания. |
| `select` | Обязательный заимствованный колбэк. Код и контекст дерева действуют до уничтожения сервера. При открытии или создании файла владелец передаёт исходный `context` и точный `id` обычного файла. |

Функция выбора возвращает маску `STYXRPC_READ` и `STYXRPC_WRITE`. Сервер
пересекает её с разрешённым доступом fid и сохраняет для этого fid.
Ноль выбирает синхронные колбэки.

После регистрации возвращается `1`. Неверные аргументы, служебный адаптер,
повторная регистрация, начавшееся обслуживание или невозможность удержать
источник пробуждения владельца дают `0`.

## Владение и отмена

Выбранные `StyxRpcVfs.read` и `StyxRpcVfs.write` выполняются в нативных
потоках. Сервер удерживает состояние файла до завершения потока и владеет
буферами до кодирования ответа. На fid допускается одна работающая или
завершающаяся операция. Предел на сервер составляет шестнадцать операций.
Сверх предела выдаётся `Rerror`. Владелец выполняет выбор, открытие, закрытие,
метаданные, изменение дерева и синхронные передачи. Синхронизируйте общие
данные провайдера, если они доступны из нескольких колбэков одновременно.

В ожидающем колбэке проверяйте
[styxrpc_server_io_cancelled](server_io_cancelled.ru.md). Поздний результат
снятого запроса отбрасывается. Подтверждённое число байт относится к
результату провайдера. При уничтожении сервер сначала подаёт отмену, затем
ждёт потоки и закрывает оставшиеся состояния файлов.

## Пример

Для обычного сервера и одного потокобезопасного файла по ID установите
такой выбор.

```c
static unsigned select_file(void *context, uint64_t id)
{
    (void)context;
    return id == 2 ? STYXRPC_READ | STYXRPC_WRITE : 0;
}
```

Вызовите `styxrpc_server_enable_deferred_io(server, select_file)` перед
циклом обслуживания. [Рабочий провайдер](../examples/disvm/deferred_device.c)
включает такой выбор, ожидающие колбэки и синхронный управляющий файл.
Команды запуска приведены в [руководстве проверки](../examples/disvm/DEFERRED_IO.ru.md).
