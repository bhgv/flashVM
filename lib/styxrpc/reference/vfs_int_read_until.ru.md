# styxrpc_vfs_int_read_until

[English](vfs_int_read_until.md) · [Объявление](../include/styxrpc/vfs_client.h#L248) · [Реализация](../src/vfs_int.c#L78)

Прочитать одно знаковое значение Int32 из открытой переменной.

## Синтаксис

```c
#include <styxrpc/vfs_client.h>

StyxRpcIoOutcome styxrpc_vfs_int_read_until(StyxRpcVfsFile *file,
    int32_t *value, StyxRpcVfsStop stop, void *state);
```

## Доступность

Хостовый SDK C, библиотека `StyxRpc::launch`. Требуется подключённый клиент Styx и поддержка Int32-файлов `.var` со стороны владельца. Примеры проверены на Linux64 c DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `file` | Заимствованный открытый fid переменной с доступом на чтение. Сериализуйте операции и закрытие. |
| `value` | Обязательный выход для знакового результата. При отказе прежнее значение сохраняется. |
| `stop` | Необязательный колбэк. Выполняется в вызывающем потоке, ненулевой результат запрашивает остановку. NULL оставляет обычное ожидание. |
| `state` | Заимствованный контекст колбэка. Действует до возврата, NULL допустим по контракту колбэка. |

## Результат

| Исход | Условие |
| --- | --- |
| `STYXRPC_IO_OK` | В `value` записано целое число из полного ответа. |
| `STYXRPC_IO_NOT_OPEN` | Отсутствует файл или выходной указатель. |
| `STYXRPC_IO_FAILED` | Подтверждённый отказ или короткий ответ. |
| `STYXRPC_IO_CANCELLED` | Чтение прервано до получения исходных данных. |
| `STYXRPC_IO_UNCERTAIN` | Достоверный ответ не получен. Значение не выдано. |

## Поведение и время жизни

SDK отправляет один `Tread` на четыре байта со смещения ноль. Полный ответ содержит знаковое число в порядке от старшего байта к младшему. Короткий ответ означает ошибку. Полный исходный ответ, пришедший до `Rflush`, может завершить чтение успешно. Вызывающий владеет `file` и закрывает его. После отмены запроса в полёте или неопределённого исхода освободите fid, затем при необходимости откройте исходный описатель заново.

Колбэк должен быстро возвращать управление и избегать повторного входа в ту же сессию. Мультиплексированный клиент может отправить `Tflush` по тегу ожидающего запроса. Последовательный клиент проверяет флаг между обменами.

## Пример

```c
Use `value` only when the function returns `STYXRPC_IO_OK`.
```

Используйте `value` только при результате `STYXRPC_IO_OK`.
