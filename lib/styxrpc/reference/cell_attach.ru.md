# styxrpc_cell_attach

[English](cell_attach.md) · [Объявление](../include/styxrpc/named_cell.h#L51) · [Реализация](../src/named_channel_client.c#L296)

Открывает ещё одну аренду по действующему жетону.

## Синтаксис

```c
#include <styxrpc/named_cell.h>

StyxRpcVfsFile *styxrpc_cell_attach(struct StyxClient *session, const void *token);
```

## Доступность

Хостовый C SDK, цель `StyxRpc::launch`. Нужны подключённый клиент Styx и поддержка общих ячеек на `/.channels` у провайдера. Пример проверен с Linux64 и DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `session` | Заимствованный подключённый клиент службы `/.channels` выдавшей стороны. Удерживайте его до возврата. |
| `token` | Заимствованный жетон из `STYXRPC_CELL_TOKEN` байтов (24). До возврата удерживайте аренду или ссылку переданного дескриптора. |

## Возвращаемое значение

При успехе возвращает новый собственный fid. NULL означает неверный аргумент, чужой или отозванный жетон, недоступную службу либо отсутствие подтверждения.

## Поведение и время жизни

Присоединитесь до следующего запроса канала, который заменит ссылку принятого дескриптора. Собственный fid удерживает ячейку после закрытия канала. Закройте его через `styxrpc_vfs_close`. Отдельные fid используются независимо.

Вызов может ждать I/O по срокам смонтированной сессии.

## Пример

Передайте заимствованный жетон того же реестра. Удерживайте действующую аренду или ссылку принятого кадра.

```c
StyxRpcVfsFile *alias = styxrpc_cell_attach(session, token);
if (alias)
{
    styxrpc_vfs_close(alias, 0);
}
```

Используйте жетон этой сессии. Копия жетона сама по себе не продлевает жизнь ячейки.
