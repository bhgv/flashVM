# styxrpc_channel_pid_exchange

[English](channel_pid_exchange.md) · [Объявление](../include/styxrpc/channel_route.h#L128) · [Реализация](../src/channel_pid.c#L217)

```c
#include <styxrpc/channel_route.h>
StyxRpcStatus styxrpc_channel_pid_exchange(struct StyxClient *reverse,
    StyxRpcChannelRoutes *routes, size_t anchor, const StyxRpcSelection *selection,
    unsigned timeout_ms, void *scratch, size_t scratch_size,
    void *request, size_t request_capacity, void *reply, size_t reply_capacity,
    StyxRpcChannelResult *result);
```

Линкуйте `StyxRpc::launch`. Синхронная операция использует нативный профиль встречного Styx и UniBus. Она отправляет, принимает или выбирает одну из нескольких веток на одном PID и дополняет таблицу ключами каналов из принятого элемента.

## Подготовка обмена

- Передайте то же заимствованное монтирование `reverse` и таблицу вызывающего `routes`, которые использовались для [импорта PID](channel_pid_import.ru.md). Сохраняйте аренду результата и монтирование, пока возможны операции. Обращения к таблице и монтированию выполняйте последовательно. Начиная с нуля, `anchor` указывает индекс любого допущенного канала на нужном PID.
- В `selection` задайте одну или несколько типизированных веток с уже известными ключами этого PID. Установите `selection->policy` в NULL. Для одной ветки используйте `STYXRPC_CHANNEL_ONE`, для блокирующего выбора — `STYXRPC_CHANNEL_ALT`, для немедленного — `STYXRPC_CHANNEL_TRY`. Отправляемый элемент допускает nil и известные ключи каналов, закодированные обычными полями CURRENT на этом PID.
- В `timeout_ms` задайте бюджет от 1 до 60000 миллисекунд. Адаптер проверяет его между синхронными транзакциями Styx. Для каждой транзакции также действует таймаут монтирования.
- Передайте отдельный записываемый буфер `request` и его ёмкость в байтах для кодирования выбора. Отдельный записываемый буфер `reply` ёмкостью до `STYXRPC_MANAGED_LIMIT` байт хранит полный ответ. Для ALT и TRY передайте отдельный записываемый буфер `scratch` и его размер в байтах для подготовки веток. Для ONE передайте NULL и ноль. Храните буферы и данные выбора до возврата.
- Передайте записываемый `result`. При успехе `result->selected` содержит номер выбранной ветки от единицы или ноль при пустом TRY. Принятое значение указывает внутрь `reply` и доступно до его повторного использования.

## Результаты и время жизни

При `STYXRPC_OK` каждый дочерний CURRENT из принятого элемента сохраняется по PID и ключу со своей схемой и признаком ёмкости. Алиасы используют стабильные индексы. Таблица вмещает восемь записей суммарно, включая корневые и дочерние каналы всех допущенных PID. Внешний адрес, конфликт дочерних каналов или заполнение таблицы отклоняют всё обновление. Дочерний канал действует в течение жизни PID и доступен независимо от родительского индекса.

Временный fid операции закрывается через clunk до возврата. `STYXRPC_MORE` сообщает об исчерпании бюджета, `STYXRPC_REMOTE_ERROR` — о подтверждённой ошибке канала. `STYXRPC_INVALID` охватывает неверные аргументы, ключ за пределами выбранного PID, сбой транспорта, отозванный PID и неверный ответ. При ошибке `routes` и `result` сохраняют прежние значения. Удалённая операция может завершиться до таймаута или локального отказа. Автоматический повтор может выполнить её второй раз.

[Самостоятельная проверка на сокете](../tests/channel_socket.c) импортирует PID канала строк и принимает значение по допущенному ключу. Затем она пробует второй ключ, который обслуживается той же шиной. Адаптер отклоняет запрос, пока ключ не допущен. [Руководство по арендам](channel_leases.ru.md) описывает, как владелец получает кадр с PID.
