# styxrpc_channel_module_init

[English](channel_module_init.md) · [Объявление](../include/styxrpc/channel_module.h#L50) · [Реализация](../src/channel_module.c) · [Описание аренды](channel_leases.ru.md)

Подключите `StyxRpc::serve`.

```c
#include <styxrpc/channel_module.h>
StyxRpcStatus styxrpc_channel_module_init(StyxRpcChannelModule *module, const char *name,
    const StyxRpcChannelExport *exports, size_t count, StyxRpcModuleChannels *registry);
```

Подготовьте память `module` с базовым именем `name`, `count` различными компилированными описателями в `exports` и инициализированным `registry` для данного модуля и сессии. Каждый описатель принимает копируемые и графовые аргументы и выдаёт результат с типизированными каналами. Для заимствованных входных каналов используйте обработчики владельца. Колбэк может выдавать [группу очередей](channel_group_output.ru.md) с вложенными каналами в сообщениях. Передайте `module` как контекст `styxrpc_channel_module_tree`. Модуль публикует компилированное предложение, штатные маркеры и `.unibus` с проверкой полномочий.

`STYXRPC_OK` означает готовность модуля. Неверная настройка даёт `STYXRPC_INVALID`. Модуль, имена, описатели, реестр и его источник случайных байтов живут до уничтожения сервера. Диспетчер вызывает колбэки последовательно. Успешный колбэк возвращает положительный ключ и ресурс новой аренды либо ноль для nil. Если передан `release`, очистка вызывает его один раз при отказе публикации или отзыве. Отзыв закрывает ожидающие операции до очистки.

[Исполняемая проверка](../tests/module_channels.c)

Колбэк может передать в `StyxRpcChannelOutput.updates` собственный буфер `malloc` с дочерними записями позиционных обновлений и число байт в `update_size`. SDK поглощает буфер даже при отказе колбэка или невозможности опубликовать ответ. Когда изменений нет, оставьте оба поля нулевыми. Для подготовки изменившихся полей используйте [`styxrpc_graph_diff`](graph_diff.ru.md). SDK оборачивает обновления и проверяет их вместе с результатом. Пересоберите провайдер с текущим определением структуры.

### Составной ответ

Для прежнего единственного канала задайте `key` и `unbuffered`. Для составного ответа передайте в `result` собственный буфер `malloc` с одним закодированным потомком результата и его длину в `result_size`. В каждой живой позиции канала запишите ключ текущей группы через [`styxrpc_channel_route_value`](channel_route_value.ru.md) с `STYXRPC_ROUTE_CURRENT`. Настройте ресурс на точные ключи, типы и ёмкости. `key` равен первому живому ключу результата или нулю, когда везде nil. Буферы результата и обновлений принадлежат SDK после возврата колбэка и выделяются отдельно. Диспетчер подставляет свой токен, проверяет алиасы и обновления вместе, затем выдаёт ответ. При отказе подготовленный токен отзывается, ресурс освобождается. Потребители C пересобираются с текущим `StyxRpcChannelOutput`.
