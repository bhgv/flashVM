# styxrpc_server_enable_mutations

[English](server_enable_mutations.md) · [Руководство SDK](../README.ru.md) · [Создание сервера](server_create.ru.md)

## Синтаксис

```c
#include <styxrpc/serve.h>

int styxrpc_server_enable_mutations(StyxRpcServer *server,
    const StyxRpcMutations *mutations);
```

Доступна в хостовой сборке C99, цель `StyxRpc::serve`.

## Параметры и результат

| Параметр | Контракт |
| --- | --- |
| `server` | Обычный сервер дерева колбэков из [styxrpc_server_create](server_create.ru.md). Вызовите в потоке владельца до первого шага обслуживания. |
| `mutations` | Неизменяемая таблица, заимствованная до уничтожения сервера. Задайте одну или обе функции. При отсутствии колбэка соответствующая операция отключена. |

Функция возвращает `1` после установки. При неверных аргументах, повторной установке, начавшемся обслуживании или передаче служебного сервера возвращается `0`. Сетевого ввода-вывода нет.

## Протокол и владение

| Запрос 9P | Колбэк и результат |
| --- | --- |
| `Tcreate`, файл `0666`, `OWRITE` | `create(context, parent, name, 0, id, revision, cookie)` публикует файл и передаёт уже открытое состояние записи. Fid каталога становится fid файла со смещением ноль. Состоянием пользуются существующие колбэки записи и закрытия VFS. |
| `Tcreate`, каталог `DMDIR\|0777`, `OREAD` | `create(context, parent, name, 1, id, revision, NULL)` публикует пустой каталог. Тот же fid открывает курсор каталога с позиции ноль. |
| `Tremove` | `remove(context, id)` удаляет точный живой узел. Диспетчер поглощает fid запроса при успехе и при ошибке. Другие открытые состояния сохраняют своё время жизни. |

Все колбэки выполняются синхронно у владельца сервера с заимствованным `context` исходного дерева. `parent` и `id` обозначают устойчивые узлы, `name` передаёт один заимствованный компонент пути. Адаптер требует у родительского каталога права записи и прохода класса other. Удаление корня, изменение служебных узлов и создание дубликата отклоняются. В реализации колбэка также атомарно проверяйте отсутствие дубликата, запрещайте удаление непустых каталогов и при отказе возвращайте `0` без изменений.

При успешном создании верните `1` и выдайте свежий ненулевой ID обычного узла, начальную ревизию Qid и, для файла, открытое состояние. Сразу публикуйте потомка для stat и перечисления. При изменении состава каталога увеличивайте ревизию родителя. Не переиспользуйте ID в течение жизни сервера даже при повторном создании имени. После удаления сохраняйте данные, удерживаемые другими открытыми fid, до их закрытия.

Время работы колбэка определяет провайдер. Колбэк не должен повторно входить в диспетчер. При обрыве или flush подтверждение может потеряться после изменения дерева. Перед следующей операцией проверьте текущее состояние.

## Запуск примера

Настройте сборку с `-DSTYXRPC_EXAMPLES=ON -DBUILD_TESTING=ON` и готовым пакетом Styx. Провайдер хранит отдельные ID и данные удалённых узлов. Клиент C создаёт каталог, записывает и удаляет потомка, затем читает через уже открытый fid. Если настроена интеграция DisVM, клиент Limbo проверяет того же провайдера через `Sys.create` и `Sys.remove`.

```sh
ctest --test-dir build-styxrpc -R 'styxrpc-(mutable-tree|disvm-mutations)' --output-on-failure
```

Выбранные тесты печатают `PASS` и ждут, пока провайдер проверит закрытие всех fid. См. [разбор примера](../examples/disvm/MUTATIONS.ru.md), [заголовок](../include/styxrpc/serve.h) и [реализацию](../src/serve_mutations.inc).
