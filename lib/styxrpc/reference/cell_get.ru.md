# styxrpc_cell_get

[English](cell_get.md) · [Объявление](../include/styxrpc/named_cell.h#L55) · [Реализация](../src/named_channel_client.c#L328)

Читает снимок текущего значения через существующий fid ячейки.

## Синтаксис

```c
#include <styxrpc/named_cell.h>

StyxRpcIoOutcome styxrpc_cell_get(StyxRpcVfsFile *lease,
    unsigned char **frame, size_t *size);
```

## Доступность

Хостовый C SDK, цель `StyxRpc::launch`. Нужны подключённый клиент Styx и поддержка общих ячеек на `/.channels` у провайдера. Пример проверен с Linux64 и DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `lease` | Открытый fid ячейки на чтение и запись, удерживаемый вызывающим. Функция заимствует его. |
| `frame` | Записываемый указатель. При успехе получает буфер от `malloc`. Освободите его через `free`. |
| `size` | Записываемый выход для точной длины кадра в байтах вместе с тегом. |

## Возвращаемое значение

При `STYXRPC_IO_OK` вызывающий получает собственный кадр и его длину. При отказе оба выхода сохраняются. Неверные указатели дают `STYXRPC_IO_NOT_OPEN`. Повреждённый, пустой или неполный подтверждённый ответ даёт `STYXRPC_IO_FAILED`. Обмен без положительного подтверждения может дать `STYXRPC_IO_UNCERTAIN`.

## Поведение и время жизни

Согласуйте запросы и закрытие `lease`. После отказа с частично прочитанным ответом закройте этот fid перед новым обращением к ячейке. Удерживайте отдельную аренду, если приложению требуется сохранить жетон. Последовательные чтения могут наблюдать разные значения.

Вызов может ждать I/O по срокам смонтированной сессии.

## Пример

Передайте существующую аренду ячейки. При успешном чтении вызывающий получает отдельный буфер.

```c
unsigned char *frame = NULL;
size_t size = 0;
if (styxrpc_cell_get(lease, &frame, &size) == STYXRPC_IO_OK)
{
    free(frame);
}
```

Для `free` подключите `<stdlib.h>`. При необходимости декодируйте снимок до освобождения.
