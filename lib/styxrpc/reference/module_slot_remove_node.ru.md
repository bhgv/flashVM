# styxrpc_module_slot_remove_node

[English](module_slot_remove_node.md) · [Заголовок](../include/styxrpc/nodes.h) · [Реализация](../src/module_slot.c)

```c
#include <styxrpc/nodes.h>
StyxRpcStatus styxrpc_module_slot_remove_node(StyxRpcModuleSlot *slot,
    const char *path);
```

Слинкуйте hosted SDK. Вызывайте в потоке-владельце живого `slot`
вне колбэков передачи и освобождения узлов. `path` подчиняется правилам
[new_node](module_slot_new_node.ru.md), отсчитывается от корня и
содержит до 1024 байтов UTF-8 без учёта необязательной начальной
косой черты. Можно отозвать последовательный или
[позиционный](module_slot_new_node_at.ru.md) файл.

При `STYXRPC_OK` слот отзывает открытия этого идентификатора, удаляет
файл и опустевшие неявные каталоги. Затем он один раз вызывает функцию
освобождения, если она задана. Освобождение синхронное в потоке-владельце.
В колбэке освобождения менять слот нельзя. Fid, полученный через walk,
тоже истекает. Повторная публикация того же имени получает новый Qid.
Открытые соседние файлы продолжают работать.

`STYXRPC_INVALID` означает, что дерево не изменилось. Причины
включают нулевой слот, отсутствующее имя, каталог, неверный путь или
вызов во время передачи либо освобождения на том же слоте. Операция
не отправляет сообщений по сети. Новый вызов исполнения разрешает
путь после получения полного запроса.

Например, `styxrpc_module_slot_remove_node(slot, "/app/page")` отзывает
один файл. Для отзыва всех оставшихся узлов в конце фильма
используйте [clear_nodes](module_slot_clear_nodes.ru.md).
