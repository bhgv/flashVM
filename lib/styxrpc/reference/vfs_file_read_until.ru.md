# styxrpc_vfs_file_read_until

[English](vfs_file_read_until.md) · [Обзор VFS](../README.ru.md)

Прочитать подтверждённый префикс с байтового смещения открытого файла.
Вызывающий может запросить отмену во время ожидания данных.

```c
#include <styxrpc/vfs_client.h>

StyxRpcIoOutcome styxrpc_vfs_file_read_until(StyxRpcVfsFile *file, uint64_t offset,
    void *bytes, size_t size, size_t *used, StyxRpcVfsStop stop, void *state);
```

Подключите хостовую цель `StyxRpc::launch`.

| Параметр | Контракт |
| --- | --- |
| `file` | Fid, открытый для чтения, например через [styxrpc_vfs_open](vfs_open.ru.md). Сериализуйте передачи и закрытие на этом fid. |
| `offset` | Первый байт чтения. Весь диапазон должен помещаться в знаковое 64-битное смещение Styx. |
| `bytes`, `size` | Буфер для записи до 65 536 запрашиваемых байтов. При нулевой длине допустим NULL, запрос данных пропускается. |
| `used` | Обязательный выход для подтверждённой длины, в том числе при коротком чтении, ошибке или отмене. |
| `stop`, `state` | Необязательный [колбэк](../include/styxrpc/vfs_client.h#L38) и заимствованные данные. Для отмены верните ненулевое значение. Колбэк работает в вызывающем потоке, быстро завершается и оставляет этот fid вызывающему. |

Удерживайте аргументы до возврата. С NULL вместо колбэка действует
поведение [styxrpc_vfs_file_read](vfs_file_read.ru.md). С колбэком
проверка выполняется перед каждым фрагментом. Клиент с мультиплексором
проверяет отмену и при ожидании ответа, отправляя `Tflush` по тегу
ожидающего запроса. Последовательная сессия проверяет между фрагментами.

`STYXRPC_IO_OK` сообщает полный или короткий подтверждённый результат.
`Rread`, пришедший раньше `Rflush`, сохраняет свои байты. При отмене
следующего фрагмента функция возвращает `STYXRPC_IO_CANCELLED`, а
`used` сохраняет подтверждённую длину. Закройте отменённый fid через
[styxrpc_vfs_close](vfs_close.ru.md) перед новым открытием. Провайдер
мог уже потребить внешний ввод. Ожидание подтверждения flush зависит
от ответа другой стороны. Остальные fid мультиплексора могут работать
параллельно. Действуют и [обычные исходы I/O](vfs_read_at.ru.md).

## Пример

Проводной тест открывает файл, подтверждает первый байт и удерживает
второй. При ожидании второго чтения колбэк видит флаг отмены.
Ожидается `STYXRPC_IO_CANCELLED` с `used == 1`.
