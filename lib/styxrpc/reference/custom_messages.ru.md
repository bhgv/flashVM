# Пользовательские сообщения UniBus

[English](custom_messages.md) · [Сборка SDK](../README.ru.md#сборка)

Порт сообщений подходит для обмена типизированными событиями или двоичными
данными по инициативе любой стороны. Например, прибор может публиковать
замеры и принимать команды калибровки в той же сессии Styx, где доступны его
файлы и именованные методы. Сообщение содержит произвольные байты. Схема
регистрируется по имени с учётом регистра и ненулевой версии. Формат полезной
нагрузки и её кодек задаёт приложение.

Сервер может опубликовать `.messages` в корне рядом с существующим деревом.
Открытие на чтение и запись создаёт двусторонний поток с двумя независимыми
байтовыми смещениями и реестром каждого направления. Закрытие fid освобождает
этот поток. Клиент использует имеющийся `StyxClient`, в том числе на
двунаправленном соединении.

## Настройка порта

1. Установите SDK с `STYXRPC_HOSTED=ON`. Подключите `styxrpc/messages.h`.
   Серверу нужен `StyxRpc::serve`, клиенту — `StyxRpc::launch`.
2. Укажите типы на каждой стороне в `StyxRpcMessageSpec`. Согласуйте имя и
   версию схемы. Для каждого отправляемого типа выберите локальный уникальный
   ненулевой `send_tag`. Для каждого принимаемого типа задайте колбэк
   `receive`. Например, сервер отправляет `sensor.sample` версии 1 с тегом
   6 и обработчиком NULL. Клиент, который только принимает эту схему,
   регистрирует её с тегом 0 и обработчиком.
3. Вызовите [styxrpc_messages_enable](messages_enable.ru.md) до первого шага
   сервера. Сервер может отправлять сообщения из хука `opened`, колбэков
   приёма и между шагами диспетчера через порт, полученный в хуке.
4. Вызовите [styxrpc_messages_open](messages_open.ru.md) на смонтированном
   клиенте. [styxrpc_message_send](message_send.ru.md) ставит копию в очередь,
   а [styxrpc_messages_pump](messages_pump.ru.md) выполняет обмен в обе стороны
   в потоке владельца клиента. Входящие события поступают в зарегистрированные
   обработчики. Вызывайте pump при очередном опросе порта или наличии данных
   для отправки.
5. Закройте клиентский порт через [styxrpc_messages_close](messages_close.ru.md).
   Серверный хук `closed` завершает время жизни заимствованного порта.
   Он выполняется и при закрытии fid после обрыва связи.

Обработчик заимствует байты на время вызова и возвращает 1 для подтверждения
приёма. Из него можно вызвать `styxrpc_message_send` на том же порту.
Приложение планирует обмен и держит порт в потоке владельца I/O. Проверяйте
формат и ограничения самой полезной нагрузки в своих обработчиках.

## Протокол и обработка ошибок

Первая запись каждого направления содержит стандартное объявление привязок
UniBus с тегом 0. В нём отправитель перечисляет ненулевые теги, имена и
версии их схем. Каждая следующая запись использует один из этих тегов.
Получатель проверяет целую S-запись и находит обработчик по объявленной схеме.
Реестр фиксируется на время открытия порта. Объявлять незнакомые схемы можно.
Порт завершает работу при получении данных с неизвестным тегом,
неподдерживаемой схемой, ошибочной контрольной суммой или отказе обработчика.
Данные до объявления и повторное объявление также приводят к отказу.
Остальные fid сессии Styx могут продолжать работу.

Пустое чтение файла означает, что очередь временно пуста. Чтение и запись
используют следующее смещение каждого направления. Клиентский pump не
повторяет запись, исход которой неизвестен. Если в записи файла было
несколько сообщений, ошибка может возникнуть уже после доставки предыдущих.
Для подтверждений приложение может зарегистрировать схему ответа и передавать
идентификаторы запросов в полезной нагрузке.

Ограничения составляют 32 регистрации на сторону, 16 384 байта полезной
нагрузки в записи и восемь портов на сервер. Пример
[`tests/message_socket.c`](../tests/message_socket.c) монтирует настоящий
сокет, обменивается двоичным образцом максимального размера в нескольких
запросах Styx и вызывает `increment` через того же клиента. Запускайте пример из каталога исходников SDK.

```sh
cmake -S . -B build -DSTYXRPC_HOSTED=ON -DCMAKE_PREFIX_PATH=/path/to/prefix
cmake --build build
ctest --test-dir build -R styxrpc-custom-messages --output-on-failure
```
