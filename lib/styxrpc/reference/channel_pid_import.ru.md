# styxrpc_channel_pid_import

[English](channel_pid_import.md) · [Объявление](../include/styxrpc/channel_route.h#L104) · [Реализация](../src/channel_pid.c#L72)

```c
#include <styxrpc/channel_route.h>
StyxRpcStatus styxrpc_channel_pid_import(struct StyxClient *reverse, const char *shape,
    const void *bytes, size_t size, StyxRpcChannelRoutes *routes);
```

Линкуйте `StyxRpc::launch`.

Импортирует в потоке владельца полный типизированный элемент, принятый для выданного результата. `reverse` заимствует встречное монтирование Styx того же клиента. `shape` задаёт в скобках схему одного значения с каналами и завершающим NUL. Передайте кадр в `bytes` и длину в байтах в `size` до `STYXRPC_MANAGED_LIMIT`. Поля-каналы содержат nil или нативные PID каналов с элементами по значению. Обнулите `routes` перед первым вызовом и используйте эту таблицу для одного результата и монтирования.

SDK готовит отдельные PID со стабильными индексами, сохраняет точные алиасы и отклоняет несовместимые адреса, типы или признаки ёмкости. Для каждого PID он читает точный десятичный идентификатор и проверяет наличие `.unibus` в том же каталоге. Каждая операция Styx использует таймаут монтирования клиента. Связь сообщения с выданным результатом задаёт вызывающий. PID действует в нативном подключении с уникальными номерами выдачи.

`STYXRPC_OK` устанавливает таблицу. `STYXRPC_INVALID` сохраняет её при ошибках аргументов, отсутствии ресурса, сбое транспорта или заполнении таблицы. Последующие операции выполняются через [маршрутизированный обмен](channel_route_exchange.ru.md). Партнёр может отозвать PID после допуска. [Проверка на сокете](../tests/channel_socket.c)
