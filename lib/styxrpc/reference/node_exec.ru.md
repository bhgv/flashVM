# styxrpc_node_exec

[English](node_exec.md) · [Объявление](../include/styxrpc/nodes.h#L98) · [Клиент](../src/node_exec_client.c#L47) · [Провайдер](../src/node_service.c#L76)

```c
#include <styxrpc/nodes.h>
StyxRpcIoOutcome styxrpc_node_exec(struct StyxClient *session, const char *path,
    void *bytes, size_t size, size_t *used);
```

Подключите `StyxRpc::launch`. Провайдер публикует колбэк с правом исполнения
через [`styxrpc_module_slot_new_node`](module_slot_new_node.ru.md) в дереве
слота. Каждый вызов открывает отдельный fid в действующей сессии и ждёт
завершения колбэка или ошибки.

| Параметр | Назначение |
| --- | --- |
| `session` | Заимствованный подключённый клиент. Должен оставаться живым до возврата. |
| `path` | Непустой относительный путь от корня сессии, до 1024 байт. Служебные имена, пустые компоненты, `.` и `..` отклоняются. |
| `bytes` | Изменяемый буфер вызывающего с входными байтами. При успехе его первые `*used` байт занимают данные ответа. NULL допустим при нулевом `size`. |
| `size` | Длина входа и ёмкость ответа от 0 до `STYXRPC_NODE_BUFFER_MAX` байт включительно. |
| `used` | Обязательный выход. Длина результата при успехе, ноль при отказе. |

`STYXRPC_IO_OK` подтверждает результат, в том числе пустой.
`STYXRPC_IO_NOT_OPEN` означает неверные аргументы либо отказ открытия
службы. Остальные коды означают сбой или неопределённость. Ответ может
потеряться после исполнения колбэка. Клиент освобождает fid перед
возвратом и не повторяет вызов. При сбое `bytes` сохраняет исходное
содержимое. Параллельные вызовы используют разные fid. Провайдер вызывает
колбэки в потоке владельца, а закрытие незавершённого запроса его отменяет.

```c
unsigned char bytes[] = {38};
size_t used;
StyxRpcIoOutcome status = styxrpc_node_exec(session, "menu/invoke",
    bytes, sizeof(bytes), &used);
```

В [нативной проверке](https://github.com/bhgv/flashVM/blob/master/flashVM/tests/styxrpc/node-files.c) вызов
возвращает один байт со значением 42. Проверьте `status` перед чтением.

## Обмен по Styx

Пройдите от корня сессии к `/.exec`. Stat сообщает имя службы и
`STYXRPC_NODE_EXEC_QID` (3) файлового узла. Откройте его на чтение и запись.
При перечислении корня эта служба пропускается. Запрос начинается со
смещения ноль. Два беззнаковых счётчика по 32 бита в порядке от старшего
байта задают длины поля пути и аргумента. Путь с завершающим нулём идёт
перед аргументом. Аргумент может быть пустым. Последняя запись запускает
колбэк и подтверждает запрос при успехе. Читайте сохранённый ответ с
нулевого смещения. Его длина ограничена длиной аргумента. После
чтения закройте fid. Каждый fid принимает один запрос.

Адаптер собственного реестра использует кодек fid в `StyxRpc::rpc`. [open](node_service_open.ru.md), [write](node_service_write.ru.md), [read](node_service_read.ru.md), [close](node_service_close.ru.md).
