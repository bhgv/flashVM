# styxrpc_channel_element_routes

[English](channel_element_routes.md) · [libstyxrpc](../README.ru.md)

## Синтаксис

```c
#include <styxrpc/channel_route.h>
StyxRpcStatus styxrpc_channel_element_routes(const char *shape, const void *bytes, size_t size,
    StyxRpcChannelRoutes *routes);
```

Прочитайте один полный типизированный элемент с тегом 110. `shape` задаёт
объявленную схему в скобках, например `(c[i])` для элемента типа `chan of int`.
Передайте принятый буфер `bytes` и его точный размер `size`. Буфер живёт до
возврата. В `routes` копируется до восьми различных адресов каналов,
отличных от nil, в порядке первого появления.

Типы маршрутов CURRENT, PID и MODULE содержат положительный 31-битный ключ,
объявленную схему элемента и признак синхронного канала. У делегированного
PID установлен старший бит, а адрес модуля содержит ненулевой 16-байтовый
токен. Одинаковые алиасы объединяются. Несогласованный ключ, флаг ёмкости или
тип элемента для одного адреса приводят к отказу. Граф без каналов даёт
пустую таблицу.

При успехе возвращается `STYXRPC_OK`. При `STYXRPC_INVALID` содержимое `routes`
сохраняется. Причиной служит неполный, слишком большой или неверный кадр,
переполнение таблицы или конфликт адресов. Кодек выполняется без ввода-вывода,
результат владеет копиями данных. Полномочие связано с исходным проверенным
маршрутом и сроком его жизни. Подключите `StyxRpc::rpc`.
