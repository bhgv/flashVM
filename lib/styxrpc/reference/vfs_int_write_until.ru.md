# styxrpc_vfs_int_write_until

[English](vfs_int_write_until.md) · [Объявление](../include/styxrpc/vfs_client.h#L255) · [Реализация](../src/vfs_int.c#L109)

Записать знаковое значение Int32 в открытую переменную.

## Синтаксис

```c
#include <styxrpc/vfs_client.h>

StyxRpcIoOutcome styxrpc_vfs_int_write_until(StyxRpcVfsFile *file,
    int32_t value, StyxRpcVfsStop stop, void *state);
```

## Доступность

Хостовый SDK C, библиотека `StyxRpc::launch`. Требуется подключённый клиент Styx и поддержка Int32-файлов `.var` со стороны владельца. Примеры проверены на Linux64 c DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `file` | Заимствованный открытый fid с доступом на запись. Сериализуйте операции и закрытие. |
| `value` | Знаковое число от −2147483648 до 2147483647. |
| `stop` | Необязательный колбэк. Выполняется в вызывающем потоке, ненулевой результат запрашивает остановку. NULL оставляет обычное ожидание. |
| `state` | Заимствованный контекст колбэка. Действует до возврата, NULL допустим по контракту колбэка. |

## Результат

| Исход | Условие |
| --- | --- |
| `STYXRPC_IO_OK` | Подтверждены все четыре байта. |
| `STYXRPC_IO_NOT_OPEN` | Отсутствует файл. |
| `STYXRPC_IO_FAILED` | Подтверждённый отказ или короткое подтверждение. |
| `STYXRPC_IO_CANCELLED` | Остановка до отправки записи, способной изменить значение. |
| `STYXRPC_IO_UNCERTAIN` | Отправленная запись могла вступить в силу. Подтверждения недостаточно. |

## Поведение и время жизни

SDK отправляет один `Twrite` на четыре байта со смещения ноль. Знаковое число кодируется старшим байтом вперёд. Для успеха требуется подтверждение всех четырёх байтов. Полное исходное подтверждение до `Rflush` может завершить запись успешно. Вызывающий владеет `file` и закрывает его. После отмены запроса в полёте или неопределённого исхода освободите fid, затем при необходимости откройте исходный описатель заново. Избегайте автоматического повтора неопределённой записи.

Колбэк должен быстро возвращать управление и избегать повторного входа в ту же сессию. Мультиплексированный клиент может отправить `Tflush` по тегу ожидающего запроса. Последовательный клиент проверяет флаг между обменами.

## Пример

```c
After an uncertain write, a new exact open and a read can show the current value. Another writer may have updated it in the meantime.
```

После неопределённой записи новое открытие по исходному описателю и чтение показывают текущее значение. За это время значение мог изменить другой писатель.
