# styxrpc_module_ref_port_write_until

[English](module_ref_port_write_until.md) · [Объявление](../include/styxrpc/module_ref_port.h#L85) · [Реализация](../src/module_ref_port.c#L238)

Привязать позиционный порт ссылки или заменить его Int32 с колбэком остановки.

## Синтаксис

```c
#include <styxrpc/module_ref_port.h>

StyxRpcIoOutcome styxrpc_module_ref_port_write_until(StyxRpcModuleRefPort *port, uint64_t offset,
    const void *bytes, size_t size, StyxRpcVfsStop stop, void *state);
```

## Доступность

Хостовый SDK C с библиотекой `StyxRpc::launch`. Нужна подключённая сессия и действительный порт. Нативная пара Linux64 проверена с DisVM и FlashVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `port` | Заимствованный порт. Свободный порт принимает команду. Привязанный порт требует право записи для присваивания. |
| `offset` | Смещение в байтах. Ноль для команды и для присваивания. |
| `bytes` | Заимствованный буфер ввода. Для команды передайте её целиком за один вызов API. Для значения передайте четыре знаковых байта старшим вперёд. |
| `size` | Ненулевая длина в байтах. Для захвата это два байта плюс канонический относительный путь длиной 1–1024 байта без NUL. Для приёма это байт команды и полный именованный кадр описателя. Для привязанного порта ровно 4. |
| `stop` | Необязательный колбэк. Ненулевой результат запрашивает остановку. NULL использует обычные ожидания. |
| `state` | Заимствованный контекст колбэка до возврата. NULL допустим по контракту колбэка. |

## Результат

| Исход | Условие |
| --- | --- |
| `STYXRPC_IO_OK` | Принята целая команда или подтверждено присваивание. Порт владеет успешной привязкой. |
| `STYXRPC_IO_NOT_OPEN` | Неверная команда или аргумент, режим только чтения, недоступный владелец либо устаревший Qid. |
| `STYXRPC_IO_FAILED` | Подтверждённый сбой, например короткое подтверждение записи или ошибка проверки метаданных. |
| `STYXRPC_IO_CANCELLED` | Вызывающий остановил захват либо остановил присваивание до возможного эффекта. |
| `STYXRPC_IO_UNCERTAIN` | Запись могла вступить в силу, полное подтверждение потеряно. Порт сохраняет описатель. |

## Поведение и время жизни

До привязки команда `STYXRPC_REF_PORT_CAPTURE` открывает экспорт владельца и записывает его Qid. Команда `STYXRPC_REF_PORT_ADOPT` проверяет тегированный кадр и область подключения, откладывая открытие до первого доступа к значению. Команда `STYXRPC_REF_PORT_CAPTURE_LOCAL` вызывает колбэк локального захвата. После привязки присваивание отправляет одну запись из четырёх байтов со смещения ноль. Полное исходное подтверждение может опередить `Rflush`.

После отмены ожидающего удалённого доступа к значению или неподтверждённого исхода порт освобождает fid. Описатель и байты для пересылки остаются в порту. Следующее обращение сравнивает исходный полный Qid.path. Замена по тому же пути отклоняется. При отмене захвата порт остаётся свободным. При неопределённой записи перечитайте текущее значение отдельной операцией, если это нужно приложению. Избегайте автоматического повтора.

Сериализуйте операции и закрытие порта. Колбэк остановки работает в вызывающем потоке и должен быстро возвращать управление. Мультиплексированный клиент может отменить ожидающий запрос по тегу. Последовательный клиент проверяет флаг между обменами. Для локальных колбэков порта SDK проверяет флаг на границах вызова. Отмена внутри них зависит от провайдера.

## Пример

Порт уже удерживает записываемую ссылку. Эти байты кодируют −73.

```c
const unsigned char value[] = {0xff, 0xff, 0xff, 0xb7};
StyxRpcIoOutcome status = styxrpc_module_ref_port_write_until(port, 0,
    value, sizeof(value), deadline_reached, &deadline);
```
