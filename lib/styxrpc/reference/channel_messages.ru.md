# Схемы сообщений канала с разными типами

[English](channel_messages.md) · [Идентификаторы](../include/styxrpc/channel_messages.h) · [Пользовательские сообщения](custom_messages.ru.md)

Опубликуйте именованный обмен через [styxrpc_messages_publish](messages_publish.ru.md).
В реестре порта укажите схемы версии 1 из таблицы. Каждой исходящей схеме
назначьте отдельный ненулевой тег, для каждой принимаемой укажите
обработчик. В каждом направлении допустим свой набор тегов. Объявление
UniBus связывает их с точным именем и версией. Каждый открытый порт
держит собственный поток, в котором можно чередовать разные схемы.

| Схема | Данные |
| --- | --- |
| `styxrpc.int32` | Одна управляемая запись Int32. Используйте `styxrpc_value_integer` и `styxrpc_value_get_integer` с `STYXRPC_VALUE_INT`. |
| `styxrpc.real64` | Одна управляемая запись binary64. Используйте `styxrpc_value_real` и `styxrpc_value_get_real`. |
| `styxrpc.bool` | Ровно один байт, ноль или единица. |
| `styxrpc.text` | Байты UTF-8/WTF-8 с длиной. Встроенные нулевые байты входят в строку. |
| `styxrpc.null` | Пустые данные. |
| `styxrpc.ref.int32` | [Дескриптор ссылки Int32](int_variable_refs.ru.md) относительно сервера этой сессии обмена. |

[Управляемые кодеки](../include/styxrpc/managed.h) определяют кодирование
чисел. Приложение выбирает принимаемые схемы и их обработку. Сохраняйте
контексты обработчиков до закрытия и работайте в потоке владельца
диспетчера. Пересылайте дескриптор Int32 в пределах сессии его владельца.
Сервер может выдать ссылку через `styxrpc_int_ref_grant`.
Клиент отправляет без приёма через [messages_flush](messages_flush.ru.md).
