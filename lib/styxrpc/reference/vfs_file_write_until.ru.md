# styxrpc_vfs_file_write_until

[English](vfs_file_write_until.md) · [Обзор VFS](../README.ru.md)

Записать подтверждённый префикс в открытый файл с необязательной отменой.

```c
#include <styxrpc/vfs_client.h>

StyxRpcIoOutcome styxrpc_vfs_file_write_until(StyxRpcVfsFile *file, uint64_t offset,
    const void *bytes, size_t size, size_t *used, StyxRpcVfsStop stop, void *state);
```

Подключите хостовую цель `StyxRpc::launch`.

| Параметр | Контракт |
| --- | --- |
| `file` | Заимствованный fid, открытый на запись через [styxrpc_vfs_open](vfs_open.ru.md) или [styxrpc_vfs_create](vfs_create.ru.md). Сериализуйте передачи и закрытие на этом fid. |
| `offset` | Первый байт записи. Весь диапазон должен помещаться в знаковое 64-битное смещение Styx. |
| `bytes`, `size` | До 65 536 байтов для чтения вызываемой функцией. Храните буфер до возврата. При нулевой длине допустим NULL, запрос данных пропускается. |
| `used` | Обязательный выход для подтверждённой длины, в том числе при отмене или ошибке. |
| `stop`, `state` | Необязательный колбэк и заимствованный контекст. Для отмены быстро верните ненулевое значение. Колбэк работает в вызывающем потоке и оставляет этот fid вызывающему. |

SDK дописывает только неподтверждённый остаток. NULL вместо колбэка
даёт поведение [styxrpc_vfs_file_write](vfs_file_write.ru.md).
Колбэк проверяется перед каждым фрагментом и при ожидании ответа
мультиплексора. Последовательный клиент проверяет перед фрагментами.
Для отправленного ожидающего запроса мультиплексор использует штатный
`Tflush`. Ответ `Rwrite` до `Rflush` сохраняет подтверждённую длину.

При `STYXRPC_IO_CANCELLED` в `used` остаётся подтверждённый префикс.
Ожидающий фрагмент мог изменить файл, даже если подтверждение
потеряно. Закройте отменённый fid через [styxrpc_vfs_close](vfs_close.ru.md)
и выясните состояние файла перед новой записью. Если другая сторона
не отвечает, flush ждёт до срока сессии.
[Обычные исходы записи](vfs_write_at.ru.md)

[Проводной тест](../tests/channel_stop_wire.c#L211) отправляет два
байта и получает подтверждение первого. Отмена второго даёт
`STYXRPC_IO_CANCELLED` и `used == 1`. Сервер сверяет, что повторный
запрос содержит только остаток со смещения один.
