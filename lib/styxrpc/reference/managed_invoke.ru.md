# styxrpc_managed_invoke

[English](managed_invoke.md) · [Объявление и описатель](../include/styxrpc/managed_client.h) · [Реализация](../src/managed_client.c)

Подключите `styxrpc/managed_client.h` и хостовую цель `StyxRpc::launch`.

```c
StyxRpcOutcome styxrpc_managed_invoke(const StyxRpcManagedTarget *target,
    const void *arguments, size_t size, void *reply, size_t capacity,
    StyxRpcManagedReply *result);
```

В `target` укажите смонтированную сессию, относительный путь модуля, имя
экспорта, компилированную сигнатуру и точную схему аргументов и результата.
Передайте последовательность дочерних записей, её размер и отдельный буфер
ответа от 1 до 65536 байтов. Бюджет опроса готовности ответа составляет
1–60000 мс. У I/O сессии действуют собственные сроки. Профиль проверяется
тем же кодом, что и в DisVM. Для управляемого вызова с PID заранее опубликуйте
указанный ненулевой PID во встречном дереве и удерживайте публикацию до
возврата. Обычный управляемый профиль работает без встречного PID.

Функция передаёт один проверенный запрос через свежий fid, дописывая
только подтверждённый остаток, затем читает и проверяет результат.
Статусы имеют [тот же смысл, что у скалярного клиента](scalar_invoke.ru.md).
`result` выдаётся только при успехе и заимствует память ответа. Для плоских
`ref` приложение само применяет проверенную маску и записи изменений.
Здесь используется обычный управляемый профиль. Для графов, гибридных
таблиц и каналов предусмотрены свои API. Планирование, жизненный цикл
контекста и отмена сессии принадлежат приложению. Вызов синхронный, запрос
автоматически не повторяется. См. [клиент на C](../examples/client.c) и
[публикацию модуля](managed_module_init.ru.md).
