# styxrpc_cell_write_until

[English](cell_write_until.md) · [Объявление](../include/styxrpc/named_cell.h#L90) · [Реализация](../src/named_channel_client.c#L367)

Заменяет кадр ячейки по жетону через отменяемый временный fid.

## Синтаксис

```c
#include <styxrpc/named_cell.h>

StyxRpcIoOutcome styxrpc_cell_write_until(struct StyxClient *session,
    const void *token, const void *frame, size_t size, StyxRpcNamedStop stop, void *state);
```

## Доступность

Хостовый C SDK, цель `StyxRpc::launch`. Нужны подключённый клиент Styx и поддержка общих ячеек на `/.channels` у провайдера. Пример проверен с Linux64 и DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `session` | Заимствованный подключённый клиент службы `/.channels` выдавшей стороны. Удерживайте его до возврата. |
| `token` | Заимствованный жетон из `STYXRPC_CELL_TOKEN` байтов (24). До возврата удерживайте аренду или ссылку переданного дескриптора. |
| `frame` | Заимствованный кадр значения с тегом. Доступен для чтения до возврата. |
| `size` | Длина кадра вместе с тегом от 1 до `STYXRPC_NAMED_MAX` байтов. Дополнительные ограничения зависят от тега. |
| `stop` | Необязательный колбэк `StyxRpcNamedStop` в потоке вызова. Ненулевой результат запрашивает остановку. NULL оставляет обычное блокирующее ожидание. |
| `state` | Заимствованный контекст `stop`. Допустим NULL, если колбэк его принимает. Удерживайте до возврата. |

## Возвращаемое значение

| Результат | Условие |
| --- | --- |
| `STYXRPC_IO_OK` | Подтверждает полную замену. Исходный положительный ответ может опередить завершение отмены. |
| `STYXRPC_IO_NOT_OPEN` | Неверный аргумент, недопустимый локальный кадр либо недоступная служба. |
| `STYXRPC_IO_FAILED` | Определённый отказ подготовки или короткий подтверждённый обмен. |
| `STYXRPC_IO_CANCELLED` | Остановка до записи, которая могла применить значение. Сервер мог принять заголовок или часть подготовленного тела. |
| `STYXRPC_IO_UNCERTAIN` | Попытка команды или записи фрагмента осталась без положительного подтверждения. Если полное тело дошло до выдавшей стороны, замена может быть видна. |

## Поведение и время жизни

SDK использует отдельный fid операции и отправляет подтверждённые смещения без повтора. Неполный кадр не заменяет значение. Clunk сохраняет уже принятую замену. Чтение при восстановлении видит текущее значение и может совпасть с записью другого участника. Последовательность чтения, изменения и записи требует координации на уровне приложения.

Колбэк должен завершаться быстро и не обращаться к той же сессии. В мультиплексированной сессии ожидающий запрос можно отменить по тегу. В последовательной сессии флаг проверяется между обменами. Освобождение временного fid может продолжиться после возврата.

## Пример

Удерживайте аренду во время присваивания. Колбэк срока определён в полном примере.

```c
const unsigned char enabled[] = {STYXRPC_NAMED_BOOLEAN, 1};
StyxRpcIoOutcome result = styxrpc_cell_write_until(session, token,
    enabled, sizeof(enabled), deadline_reached, &end);
```

Удерживайте отдельную аренду до возврата. После `STYXRPC_IO_UNCERTAIN` используйте `styxrpc_cell_read_until` с новым действующим состоянием остановки, если приложению нужно видимое значение.
