# Встречные области аргументов-каналов

[English](channel_argument_scopes.md) · [SDK](../README.ru.md) · [Аренды результата](channel_leases.ru.md)

Прямой вызывающий владеет типизированным FIFO или синхронным каналом для каждого аргумента-канала. Одна встречная шина на соединение временно передаёт эти очереди нативному провайдеру Dis. Библиотека сериализует встречные операции и допускает только ключи активной области. Вызовы на одной шине выполняются последовательно на владельце приложения.

1. [Создайте](argument_bus_create.ru.md) шину для PID вызывающего. Опубликуйте её [ресурс](argument_bus_resource.ru.md) через [`styxrpc_program_unibus`](program_unibus.ru.md) до запуска встречного сервера. Его диспетчер работает и во время ожидания прямого ответа.
2. [Откройте](argument_scope_open.ru.md) область подготовки и соберите типизированные аргументы, [кодируя каждую очередь](argument_scope_value.ru.md) на соответствующей позиции. Сохраняйте память, ключи и кадры элементов, пока очередь заимствуется.
3. [Выполните](argument_scope_invoke.ru.md) вызов с точной схемой и PID. Библиотека проверяет предложение и публикует ключи перед первой записью. Область поглощается при любом исходе.
4. После возврата исходные очереди получают курсоры завершённых операций. Возвращённый канал использует независимую [аренду результата](channel_leases.ru.md). [Закрывайте](argument_scope_close.ru.md) отброшенные области и [уничтожайте](argument_bus_destroy.ru.md) шину после остановки сервера.

Собственный прямой транспорт может [активировать](argument_scope_activate.ru.md) и закрывать область вручную. [Проверка C](../tests/channel_arguments.c) подтверждает отмену ожидающего приёма, отсоединение его fid и отказ по старому ключу в последующих вызовах.
