# styxrpc_cell_read_until

[English](cell_read_until.md) · [Объявление](../include/styxrpc/named_cell.h#L82) · [Реализация](../src/named_channel_client.c#L346)

Читает полный кадр по жетону через временный fid.

## Синтаксис

```c
#include <styxrpc/named_cell.h>

StyxRpcIoOutcome styxrpc_cell_read_until(struct StyxClient *session,
    const void *token, unsigned char **bytes, size_t *size,
    StyxRpcNamedStop stop, void *state);
```

## Доступность

Хостовый C SDK, цель `StyxRpc::launch`. Нужны подключённый клиент Styx и поддержка общих ячеек на `/.channels` у провайдера. Пример проверен с Linux64 и DisVM.

## Параметры

| Имя | Описание |
| --- | --- |
| `session` | Заимствованный подключённый клиент службы `/.channels` выдавшей стороны. Удерживайте его до возврата. |
| `token` | Заимствованный жетон из `STYXRPC_CELL_TOKEN` байтов (24). До возврата удерживайте аренду или ссылку переданного дескриптора. |
| `bytes` | Записываемый указатель. При успехе получает буфер от `malloc`. Освободите его через `free`. |
| `size` | Записываемый выход для точной длины кадра в байтах вместе с тегом. |
| `stop` | Необязательный колбэк `StyxRpcNamedStop` в потоке вызова. Ненулевой результат запрашивает остановку. NULL оставляет обычное блокирующее ожидание. |
| `state` | Заимствованный контекст `stop`. Допустим NULL, если колбэк его принимает. Удерживайте до возврата. |

## Возвращаемое значение

| Результат | Условие |
| --- | --- |
| `STYXRPC_IO_OK` | Передаёт полный собственный кадр и его длину. |
| `STYXRPC_IO_NOT_OPEN` | Неверные указатели или недоступная служба. |
| `STYXRPC_IO_FAILED` | Определённый отказ подготовки либо неверный, неполный или пустой подтверждённый ответ. |
| `STYXRPC_IO_CANCELLED` | Остановка при присоединении, отправке команды чтения или получении ответа. |
| `STYXRPC_IO_UNCERTAIN` | Попытка команды или чтения осталась без надёжного положительного подтверждения. Выходы сохраняются. |

## Поведение и время жизни

SDK присоединяет и закрывает собственный fid. Удерживайте исходную аренду всё время. При отказе оба выхода сохраняются. После успеха полученный кадр можно декодировать независимо от последующих записей. Параллельные чтения используют раздельные выходы.

Колбэк должен завершаться быстро и не обращаться к той же сессии. В мультиплексированной сессии ожидающий запрос можно отменить по тегу. В последовательной сессии флаг проверяется между обменами. Освобождение временного fid может продолжиться после возврата.

## Пример

Исходная аренда должна оставаться доступной. Чтение по её жетону проверяет срок из полного примера.

```c
unsigned char *frame = NULL;
size_t size = 0;
if (styxrpc_cell_read_until(session, token, &frame, &size,
        deadline_reached, &end) == STYXRPC_IO_OK)
{
    free(frame);
}
```

Для `free` подключите `<stdlib.h>`. Полный пример сверяет оба байта Boolean перед освобождением.
