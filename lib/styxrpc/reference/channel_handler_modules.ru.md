# Хостовые функции с аргументами-каналами

[English](channel_handler_modules.md) · [SDK](../README.ru.md) · [Передача локальных очередей](channel_argument_scopes.ru.md) · [Публикация каналов результата](channel_leases.ru.md)

Хостовое приложение C принимает каналы-аргументы через нативный профиль вызова Dis. Канал и его память остаются у Dis. Переданные ключ и PID вызывающего дают обработчику маршрут к живой очереди или rendezvous на время вызова. Диспетчер обслуживает файлы функций. Владелец приложения может использовать встречное соединение в колбэке, пока диспетчер подтверждает запись и отвечает на опрос.

1. Опишите интерфейс в Limbo, например `relay: fn(port: chan of int): int;`. Возьмите точную компилированную сигнатуру из вывода Limbo с `-S`. Подготовьте `StyxRpcChannelFunction` с этим именем, сигнатурой, схемой `{"(c[i])", "(i)"}` и колбэком C. Для копируемого результата int запишите одну дочернюю запись [кодеком целых](../include/styxrpc/managed.h) с `STYXRPC_VALUE_INT`. Для void установите `*used = 0`.
2. [Создайте](channel_handlers_create.ru.md) модуль. Передайте `styxrpc_channel_handlers_tree` [серверу Styx](server_create.ru.md) на прямой стороне авторизованного двунаправленного соединения. Смонтируйте встречный клиент на второй стороне той же сессии.
3. Выполняйте [шаги](channel_handlers_step.ru.md) у владельца приложения. SDK проверяет кадр, PID и типы, объединяет алиасы и выполняет колбэк однократно на завершённый FID. В колбэке выберите ключ из `call->grants` и [выполните обмен](channel_exchange.ru.md) через встречный клиент для отправки, приёма или выбора ветки. SDK проверяет копируемый результат и публикует его на FID функции. Вызывающий опрашивает FID в ожидании ответа.
4. При остановке прямого сервера уничтожьте его и [остановите](channel_handlers_stop.ru.md) модуль, чтобы разбудить владельца. Дождитесь завершения обеих сторон и [уничтожьте](channel_handlers_destroy.ru.md) модуль. Освободите встречный клиент после возврата последнего активного колбэка.

Неполный вызов не выполняется. Закрытие ожидающего FID функции снимает его из очереди. Закрытие активного FID отбрасывает ответ и позволяет колбэку завершиться. Завершённая встречная операция уже могла изменить очередь вызывающего. Задайте конечное время ожидания встречных операций. Колбэк приложения может продолжать работу после отключения вызывающего.

Модуль допускает до восьми разных ключей на вызов, алиасы и nil. Элементы каналов и копируемые результаты используют типы по значению. Модуль публикует `.interface`, `.ref-fields` и `.unibus-version`. Модуль может также [публиковать отдельные каналы результата](channel_handlers_create_with_results.ru.md). Колбэк заполняет `StyxRpcChannelOutput`, диспетчер выдаёт токен на первой выдаче ответа и отзывает его по clunk функции. Дескрипторы с копируемым результатом и результатом-каналом можно разместить в одном модуле. Простой [синхронный модуль результата](channel_module_init.ru.md) подходит для колбэков с аргументами по значению.

[Автономная проверка C](../tests/channel_handlers.c) собирает фрагментированный запрос и проверяет параллельную работу диспетчера и владельца, отмену до запуска и правильный копируемый ответ. После [сборки хостового SDK](../README.ru.md) запустите:

```sh
ctest --test-dir build -R '^styxrpc-channel-handlers$' --output-on-failure
```
