# styxrpc_named_open_until

[English](named_open_until.md) · [Именованные каналы](named_channel.ru.md) ·
[Объявление](../include/styxrpc/named_channel.h) · [Реализация](../src/named_channel_client.c)

```c
#include <styxrpc/named_channel.h>

StyxRpcIoOutcome styxrpc_named_open_until(struct StyxClient *session,
    const char *path, StyxRpcVfsFile **out, StyxRpcNamedStop stop, void *state);
```

Подключите хостовую цель C `StyxRpc::launch`. Передайте подключённую
`session`, в которой другая сторона экспортирует `/.channels`.
Укажите канонический абсолютный путь `path` короче
`STYXRPC_VFS_PATH_MAX` байтов без служебных компонентов. Вызов
открывает независимое участие в существующем канале либо создаёт
канал по свободному имени.

При `STYXRPC_IO_OK` в `out` записывается собственный fid чтения и
записи. Закройте его через `styxrpc_vfs_close`. Согласуйте операции на
одном fid с его закрытием. У каждого участника свой fid. При любом отказе
`out` сохраняет прежнее значение.

| Результат | Значение |
| --- | --- |
| `STYXRPC_IO_NOT_OPEN` | Неверный аргумент либо служба не открылась. |
| `STYXRPC_IO_FAILED` | Служба отказала во входе, фрагмент неполон либо произошёл сбой подготовки. |
| `STYXRPC_IO_CANCELLED` | Вызывающий остановил подготовку или запись запроса на вход. |
| `STYXRPC_IO_UNCERTAIN` | Подтверждение записи потеряно без запроса остановки. |

Необязательный `stop(state)` исполняется в потоке вызова и возвращает
ненулевое значение для остановки. Колбэк должен быстро завершиться без
повторного входа в сессию. Держите `state` до возврата. NULL оставляет
обычное блокирующее ожидание. В мультиплексированной сессии обход,
открытие и запись отменяются по тегу. В последовательной сессии флаг
проверяется между обменами. Если полное подтверждение входа пришло до
завершения flush, вызов может вернуть успех. При отмене очистка может
продолжиться после возврата. Уже принятое имя может быть видно до
снятия fid. Провайдер освобождает имя после выхода последнего участника.

```c
StyxRpcVfsFile *port = NULL;
StyxRpcIoOutcome joined = styxrpc_named_open_until(session, "/jobs", &port,
    stop_requested, task);
if (joined == STYXRPC_IO_OK)
{
    styxrpc_vfs_close(port, 0);
}
```

Используйте парное подключение DisVM с доступным для записи родительским
каталогом `/jobs`. Здесь `stop_requested(task)` читает флаг задачи. Между
открытием и закрытием можно [отправить](named_send_until.ru.md) или
[принять](named_recv_until.ru.md) значение со встречным участником.
[Парный тест](../tests/flashvm/mixed_pair.py) с ключом
`--cancel-channel-setup` отменяет принятый DisVM вход, а затем снова
открывает это имя.
