# styxrpc_value_integer

[English](value_integer.md) · [libstyxrpc](../README.ru.md)

## Синтаксис

```c
#include <styxrpc/managed.h>

StyxRpcStatus styxrpc_value_integer(unsigned long tag, int64_t value,
    void *bytes, size_t capacity, size_t *used);
```

Соберите как C99 и подключите `StyxRpc::rpc`.

## Аргументы

| Параметр | Описание |
| --- | --- |
| `tag` | Тип вложенной записи из проверенной схемы. Используйте `STYXRPC_VALUE_INT` для знакового 32-битного целого, `STYXRPC_VALUE_BIG` для знакового 64-битного целого или `STYXRPC_VALUE_BYTE` для 0…255. |
| `value` | Знаковое значение в диапазоне выбранного типа. Для `STYXRPC_VALUE_BIG` допустим любой `int64_t`. |
| `bytes` | Записываемый буфер вызывающей стороны. |
| `capacity` | Размер буфера `bytes` в байтах. |
| `used` | Записываемый адрес для длины закодированной записи в байтах. |

## Результат

`STYXRPC_OK` означает, что первые `*used` байт содержат полную вложенную
запись. `STYXRPC_INVALID` означает неизвестный тип, значение вне диапазона,
неверный выходной аргумент или нехватку места. При допустимом `used`
ошибка устанавливает `*used` в ноль. Используйте данные буфера после успеха.

Кодек работает синхронно, без выделения памяти и ввода-вывода. Буфер
остаётся у вызывающей стороны. Для параллельных вызовов используйте
разные выходные буферы. Вложенную запись можно поместить в аргумент,
результат, массив, кортеж или сообщение типизированного канала в позиции,
в которой проверенная схема ожидает этот тип. DisVM и SDK для C используют
единое представление знаковых целых.
