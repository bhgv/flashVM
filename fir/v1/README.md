# FIR v1 toolchain

[Русский](README.ru.md). Implementation **0.46.0**, textual format **FIR 1.0**.
C99 throughout. All three parsers are generated by external
[bhgv/coco-r-C](https://github.com/bhgv/coco-r-C), the same generator used by
AS1/AS2/AS3/Limbo syntax frontends. Generated files stay in the build directory.

## Build from repository root

```sh
export TMPDIR="${TMPDIR:-$PWD/build/tmp}"
mkdir -p "$TMPDIR"
COCO_DIR="$TMPDIR/coco-r-C"
git clone https://github.com/bhgv/coco-r-C.git "$COCO_DIR"
make -C "$COCO_DIR/sources" -f unix.mk
cmake -S fir/v1 -B build/fir1 \
  -DCOCOR_ROOT="$COCO_DIR" \
  -DCOCOR_EXECUTABLE="$COCO_DIR/sources/cocor"
cmake --build build/fir1
ctest --test-dir build/fir1 --output-on-failure
```

Linux/Termux: install a C99 compiler, make, CMake and Python 3 for tests. No LLVM,
SDL or VM headers are needed to build the tools. On Windows use an available
C99 toolchain and the actual path to the external generator executable; this
release has not been tested on Windows or physical Android hardware.
A detached/renamed copy of v1 builds with the same flags and the root MIT LICENSE.

## Browse

```sh
python -m pip install -r flashVM/doku_viewer/requirements.txt
python fir/v1/view_docs.py --no-browser --port 8766
# Or: python view_docs.py
```

Both viewers list every FIR guide and tutorial. Local launchers also exist in
`fir/`, `doc/`, `compiler/`, `optimiser/` and `examples/`. They use the workspace
viewer and repository serving boundary so cross-links to existing FlashVM APIs
work. A detached tool build does not require a viewer; detached documentation
can be read as Markdown without the workspace engine.

## Backend migration in 0.4.1

`fir1 swf` and `fir1 actions` are removed. Use `fir1 object INPUT OUTPUT.swo`,
then [SWL](../../linker/README.md): `swl link OUTPUT.swf INPUT.swo`.
Historical direct-SWF commands are superseded by this two-stage pipeline.
Runtime tests require `FIR_SWL` together with `FIR_FLASHVM_RUNNER`.
