# FIR 1.0 structural parser

Frontend version 0.1.5; executable FIR tools version 0.57.0. This is an independent C99 parser
from [firsyn.atg](firsyn.atg), generated by external bhgv/coco-r-C. It recognizes
extended FIR structure; it does not build FirModule or validate types, SSA,
dominance, opcode identity/arity, effects or backend capabilities.

Supports multiple typed functions/results, block parameters and edge arguments,
if with two targets, jump/return, invoke with normal/catch, file/loc records,
source_language/source_semantics, versioned requires, type/global/import/export.
Types include 8/32/64-bit integers, f32/f64/bool/any/void, legacy string/channel,
as.string/limbo.string, as3.namespace/as3.multiname, ref<@Class>, array<T>,
chan<T>, tuple<T,...>, func(T,...)->T and named @Type. Operations have names and
structured operands; const.any has explicit number/string/bool/null/undefined
forms. Unknown operation names are syntactically legal and must be accepted or
rejected by a later verifier. Success here never authorizes optimization or SWO.

The first physical line is FIR 1.0 with LF/CRLF, optionally followed by whitespace and a // line comment. Bare trailing spaces, BOM and preceding comments remain rejected. The generated Coco/R parser still reads the whole input. Input is UTF-8 without NUL, at most 2 MiB. Comments are // and
/* ... */; string/escape spellings match the existing FIR reader. Coordinates
are bytes. No source-expression precedence is invented: FIR uses explicit operations.

## CLI and build

```sh
cmake -S . -B build -DCOCOR_ROOT=/host/coco-r-C \
  -DCOCOR_EXECUTABLE=/host/coco-r-C/sources/cocor
cmake --build build
ctest --test-dir build --output-on-failure
build/firsyn_parse INPUT.fir
```

This directory builds independently, including in a renamed copy. Building the
whole FIR project with cmake -S fir/v1 enables `fir1 syntax INPUT.fir` by default;
FIR_BUILD_SYNTAX_FRONTEND=OFF disables it. Commands check/print/opt/object retain
the existing strict executable profile. New constructs do not automatically lower
to SWO. Coco/R runs on the build host; parser executables run on the selected target.

## C API

CMake target: firsyn_frontend; public header: [firsyn.h](firsyn.h).
`firsyn_check(bytes,size,diagnostic)` and `firsyn_read(FILE*,diagnostic)` return
1 accepted / 0 rejected. diagnostic is optional. The caller owns bytes, FILE and
diagnostic storage. read starts at the current position, never rewinds or closes
the stream. Errors print nothing and never exit the process or create a VM.
Serialize calls to this library; it is not reentrant. Generated globals use the
firsyn prefix and do not overlap fir1/src1/AS/Limbo. Sequential calls recover
after errors. Code 1401 means invalid header; -1 input/encoding/size; -2 scanner
failure; -3/-4 nesting/work limits. Resource-failure coordinates may be zero.
Limits are 512 active guarded calls and 4,000,000 guarded production entries,
not a parenthesis count or a guarantee of complete verification.

0.1.2: generation removes previous outputs and checks exit status, diagnostics and files. The generator_failure test checks rejection of an invalid grammar.

The Coco/R resolver distinguishes block declarations after return/operand-free
operations from actual label operands, including comments and empty/typed parameters.
This is syntax recognition, not authorization to emit extended types or phi.

Version 0.1.4 admits bool.slot in the structural type grammar; initialization, dominance and nonescape remain verifier responsibilities. See [lazy numeric conditions](../doc/NUMERIC_LOGIC.md).

Version 0.1.5 recognizes i32.slot/f64.slot; dominance and nonescape remain executable verifier rules.
