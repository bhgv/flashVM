# Короткое замыкание и скалярные ячейки FIR — компилятор 0.24

[English](SHORT_CIRCUIT.md) · [Комментированный пример](../examples/tables/short-circuit.b) ·
[Сравнения-значения](COMPARISON_VALUES.ru.md) · [Терминальные ветви](TERMINAL_ARMS.ru.md)

Coco/R-профиль Limbo big/table реализует настоящее короткое замыкание `&&` и `||`.
Оба операнда должны иметь тип bool. Левый вычисляется один раз; `&&` вычисляет
правый только при истинном левом, `||` — только при ложном. Результат —
нормализованный bool для локальных переменных, явных cast и терминальных условий.

```limbo
present := "answer" in document;
valid := present && (document.answer == 42);
selected := valid || (delete document.answer);
```

Пропущенная правая часть не читает данные, не преобразует, не удаляет и не вызывает
исключений или обращений к владельцу. Выбранная часть сохраняет обычные эффекты,
даже если логический результат не использован. До оптимизации обе части проходят
разбор и проверку типов: пропущенная строка вместо bool всё равно ошибка.
Неявной истинности чисел/строк нет.

## Приоритеты и граф исполнения

Уровни соответствуют `limbo/limbo.y` Inferno: `&&` сильнее `||`; оба слабее
существующих побитовых операций и сравнений. Расширение `in` сильнее этих
логических операторов. Скобки меняют группировку; `!` остаётся унарным отрицанием.
Расширения исходного frontend остаются во FlashVM; язык/компилятор Inferno не меняется.

На операцию создаются три блока: пропуск, правая часть и соединение. Левое
значение инициализирует локальную bool-ячейку. Пропущенная ветвь сохраняет его,
выбранная записывает правое. В соединении читается новое неизменяемое SSA bool.
У вложенных операций свои метки и ячейки; оптимизатор не объединяет разные ячейки.
Инструкции RHS не размещаются перед защищающим переходом.

Добавлены три операции и один тип FIR в конец enum; прежние ID сохранены:

| Форма FIR | Контракт | Эффекты |
| --- | --- | --- |
| `%c: bool.slot = bool.local` | Скалярная локальная ячейка, исходно false | запись памяти |
| `bool.store %c, %b` | Запись нормализованного bool | запись памяти |
| `%v: bool = bool.load %c` | Копия содержимого в неизменяемое SSA bool | чтение памяти |

Текстовый формат остаётся FIR 1.0. C99 API использует те же проверяемые операции.
Саму ячейку нельзя копировать, выводить, преобразовывать, передавать как значение
или посылать по каналу. Все обращения проверяются на доминирование определения.
Это не указатель, GC-владелец, удалённая проекция или общий массив Limbo. Сразу
после определения ячейку можно читать — начальное значение детерминировано.

## Исполнение

Оба Dis-backend — скалярный и табличный — используют существующий MOVW.
Ячейка занимает скалярный слот кадра, без GC-бита указателя. Выделения в куче,
нового opcode VM, helper ABI и тега контейнера нет. Чистая числовая логика не
требует Bigtable; табличная сохраняет проверяемые импорты владельцев. Кучи VM
не смешиваются. Эталонный C runner исполняет те же чтения/записи по значению.

Эффекты памяти запрещают объединять инициализации разных ячеек и переиспользовать
чтения через запись. Известные условия позволяют удалить недостижимую RHS,
включая действительно пропущенные ошибки. Выбранные эффекты сохраняются.
Это не общий phi/слияние окружений, не удалённая атомарность и не исходные циклы.
SWF object backend отклоняет эти операции, сохраняя старый выходной файл.
Полное AS/SWF-lowering и панели Build/Run/Debug IDE остаются отдельной работой.

## Лимиты, диагностика и проверки

У терминальных и логических блоков один бюджет: 256 вместе со входным.
Отдельная плоская цепочка допускает 85 логических операций; терминальное решение
расходует ещё два блока. Пределы значений, имён и глубины сохранены. Ошибки типов
и лимитов сохраняют прежние FIR/sidecar. События логических переходов и записей
указывают на точные байты `&&`/`||`, включая смещения после UTF-8-префиксов.
Полный Dis SBL и подключение отладчика этим не добавляются.

Проверяются оба исхода, изменения владельцев, ошибочные cast/деление на ноль,
код до/после opt, вложенные приоритеты, независимость ячеек, запреты копирования,
выхода наружу и недоминирующих обращений, точные позиции и границы общего бюджета.
Настоящий Dis запускается в обоих режимах с квантами GC/планировщика по инструкции.

## Запуск

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/short-circuit.b build/lazy.fir -g build/lazy.json
build/fir/fir1 opt build/lazy.fir build/lazy-opt.fir
build/fir/fir1 dis build/lazy.fir build/lazy.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/lazy.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/lazy.dis
```

Значения: `42, 0`, затем флаги выполнения: `1, 0`. Перемещённые C99 SDK-клиенты
проверяют исходный и оптимизированный пример в обоих режимах VM. Аппаратное
исполнение ARM64 и полная загрузка ОС из этого не следуют.
