# Limbo: typeof и явные приведения big/string

В профиле Limbo с результатом big наш Coco/R-компилятор поддерживает
`typeof expression`, `big expression` и `string expression`. Операнд можно
ограничить скобками; в текущем прямолинейном профиле префиксы вкладываются
рекурсивно. `tobig` и `tostring` — AS-хелперы, а не новые ключевые слова Limbo.
Это описанное подмножество преобразований, а не полная реализация всех cast Limbo.

| Операнд | Результат typeof |
| --- | --- |
| big | `"big"` |
| string | `"string"` |
| table of big | `"table of big"` |
| Снимок keysof | `"keys"` |
| Ключ снимка | Реальный `"big"` или `"string"` при исполнении |

Для ключа проверяется вид данных в удерживаемом неизменяемом снимке, а не
возвращается внутреннее имя `table.key`. Отражение не преобразует данные и не
вызывает пользовательские методы. Сначала вычисляется операнд: `typeof t.bad`
сохраняет ошибку отсутствующего ключа. Ошибка вложенного cast также не исчезает.

```limbo
# Фрагмент тела value(): big; ссылка на полный модуль приведена выше.
t := table of big;
t[7] = big 10;      # Числовое пространство ключей.
t["7"] = big 20;    # Отдельное строковое пространство ключей.
keys := keysof t;
k := keys[0];       # Числовой ключ 7 удерживает неизменяемый снимок.
kind := typeof k;   # Во время исполнения получается "big".
text := string k;   # Явная копия "7" намеренно меняет пространство ключа.
value := t[text];   # Строковый ключ "7" даёт 20.
return big string value; # Точный десятичный круг с синтаксисом cast Limbo.
```

## Точные преобразования копий

`big` принимает big, строку и ключ снимка. Big сохраняется, числовой ключ копирует
точный индекс. Строка, включая строковый ключ, должна целиком задавать десятичное
целое: необязательный `+`/`-`, хотя бы одна ASCII-цифра, без пробелов, префикса
основания, дроби, экспоненты или нулевого байта. Ведущие нули десятичные.
Выход за [-9223372036854775808, 9223372036854775807] вызывает
`invalid big conversion`. Нет частичного результата, молчаливого нуля,
сужения или промежуточного числа с плавающей точкой.

`string` принимает те же виды операндов. Текст сохраняет точные байты/Unicode и
нулевые байты. Big и числовые ключи форматируются в каноничном десятичном виде;
знаковый ноль становится `"0"`. Это операции над копиями: cast не записывает
в исходную таблицу и не выполняет автоматическое обращение к прокси/каналу.

Таблицы, снимки и прочие виды отклоняются как операнды cast. Языковой any,
автоматические прокси, неоднородные таблицы, real/float/int-преобразования в этом
профиле и табличные CFG/циклы остаются отдельной работой.

## FIR, Dis и владение

Добавлены `value.type`, `value.big`, `value.text` без перенумерации прежних операций.
Результаты: string, i64, string. Проверяются типы, арность и доминирование.
Консервативные эффекты сохраняют ошибки неиспользованных преобразований при
оптимизации. FIRDBG1 запоминает точную позицию префикса, а не вложенного операнда;
полное соответствие исходник—Dis SBL пока не реализовано.

NC64-бэкенд использует прежние инструкции Dis и проверяемые импорты Bigtable.
Нужны согласованные runtime 0.19 и компилятор 0.16. Строковые результаты отмечены
в GC-карте кадра. Снимок удерживается во время выделения String; нативные адреса
не передаются между кучами/по каналам. Адаптеры common/table разбирают и форматируют
int64 без выделения памяти. Эталонный исполнитель явно хранит длину текста,
включая скопированный, и не обрезает его по нулевому байту.

Тестируются крайние значения, переполнение, ключи-копии, смена пространства ключей,
Unicode, бинарный текст на границе нативного модуля, ошибки неиспользованных
операций, точные позиции исходника, поддельные владельцы и GC между инструкциями.
