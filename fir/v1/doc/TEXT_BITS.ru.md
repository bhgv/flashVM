# Строковые выражения и точные биты int — компилятор 0.28

[English](TEXT_BITS.md) · [Комментированный пример](../examples/tables/text-bits.b) ·
[README примеров](../examples/tables/README.ru.md) · [Строки](UNICODE_STRINGS.ru.md) ·
[Int-арифметика](INT_ARITHMETIC.ru.md)

Coco/R big/table-профиль Limbo позволяет собирать подписи редактора и сравнивать
отражённые имена типов в общей цепочке исходник → FIR → Dis:

```limbo
mask := int 255;
mask &= int 63;
mask ^= int 21;
label := "line " + string mask;
old := label;
label += " 😀";
valid := (old == "line 42") && (label != old);
```

## Типы и порядок вычисления

| Операнды | Операции | Результат |
| --- | --- | --- |
| string/string | `+`, `+=` для строковой локальной | string |
| string/string | `==`, `!=` | bool |
| int/int | `&`, `|`, `^`, `&=`, `|=`, `^=` | int |
| int | `~` | int |

Каждый операнд вычисляется один раз, слева направо. Составное присваивание
запоминает старое значение, вычисляет RHS и меняет привязку только после успеха.
Это не удалённая атомарная транзакция. Смешение строки и числа либо int и big
требует явного преобразования. Упорядочивание строк, равенство таблиц и сдвиги
int пока отвергаются. Проверяемые сдвиги big сохранены. Отдельные однородный
int-профиль и числовые AS-профили не расширяются. Здесь используются cast Limbo;
расширения AS tobig/tostring имеют собственный синтаксис.

Равенство сравнивает содержимое Unicode, а не адреса. Нормализации, изменения
регистра и сегментации графем нет: `"é" != "é"`. Конкатенация сохраняет порядок,
принимает пустые строки и не меняет источники. Старые алиасы и срезы сохраняют
значения после `+=`. Результат можно использовать как текстовый ключ таблицы,
передавать len, индексировать и разрезать. Теперь работает непосредственное
сравнение `typeof value == "big"` для поддержанных типов.

## FIR, оптимизатор и исполнение

Две операции дописаны в конец enum без изменения прежних идентификаторов:

| FIR | Сигнатура | Эффекты |
| --- | --- | --- |
| `string.concat` | string/string → string | чтение, выделение, возможная ошибка |
| `string.eq` | string/string → bool | чтение |

Верификатор проверяет оба операнда и результат как для текста FIR, так и для
публичного C99 IR API. Неиспользуемая конкатенация сохраняется: ошибка выделения
наблюдаема. Равенство строковых констант сворачивается в bool, динамическое
сравнение остаётся чтением. Эталонный исполнитель копирует точные длины байтов,
включая срезы без завершающего NUL. Отдельный реестр владеет выделенными строками;
алиасы и срезы лишь заимствуют их, поэтому каждое выделение освобождается один раз.

NC64 Dis использует существующие ADDC и BEQC. Входные и выходные указатели
находятся в картах корней кадра при выделении и кванте GC/планировщика в одну
инструкцию. Используются готовые пути AMD64/ARM64 и их C fallback. Новых opcode
Dis, протокола каналов или ABI встроенного модуля нет.

Побитовые int сначала точно расширяются до big, проходят через чистые
big.and/or/xor/not, затем нормализуются по модулю 2^32. Знаковый результат
сохранён: `~int 0` равен -1. Преобразования через float и дополнительных RPC
владельцу таблицы нет; используются существующие оптимизатор и нативные ядра.

Живые string.concat/string.eq пока исполняются в Dis либо эталонном исполнителе.
SWF-бэкенд отвергает неподдержанные операции до замены выходного файла. Это
подготовка исходных сервисов IDE; подключение панелей Build/Run/Debug и полноценное
подключение отладчика остаются отдельной работой.

## Запуск и ожидаемый результат

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/text-bits.b build/text.fir
build/fir/fir1 check build/text.fir
build/fir/fir1 opt build/text.fir build/text-opt.fir
build/fir/fir1 dis build/text-opt.fir build/text.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/text.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/text.dis
```

Значения trace: 42, 0; флаги исполнения: 1, 0. Приёмка установленного SDK заново
линкует C99-клиенты source/FIR, компилирует исходный и оптимизированный пример
и проверяет оба режима VM. Проверка на физическом ARM64 остаётся отдельной
от проверки инструкций через эмуляцию.
