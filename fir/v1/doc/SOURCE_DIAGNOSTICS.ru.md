# Диагностика исходников: схема 1

[English](SOURCE_DIAGNOSTICS.md) · [C99 API](../compiler/API.ru.md) ·
[Синтаксис](SOURCE_SYNTAX.md) · [Пример](../examples/diagnostics/README.ru.md) ·
[IDE](../../../ide/README.ru.md)

FIR 0.5.4 добавляет `fir_source_ex` и необязательную JSON-диагностику числовых
адаптеров AS1/AS2/AS3 и Limbo. Авторитетный парсер — Coco/R
[src1.atg](../compiler/src1.atg). Текст FIR остаётся 1.0, объект — SWO1;
новых конструкций языка эта серия не добавляет. Независимые синтаксические
фронтенды не переводятся на новую схему автоматически.

## Владение и первая ошибка

`FirSourceDiagnostic` из [fir.h](../include/fir.h) содержит только скаляры.
`fir_source_ex` принимает прежние аргументы `fir_source` и дополнительный
указатель на результат. Возвращает 1 при успехе и 0 при ошибке.
Потоки и память сообщения/диагностики принадлежат вызывающему коду. Заимствованные
указатели не остаются после возврата. Вызовы всех generated-парсеров необходимо
сериализовать: новый интерфейс не делает компилятор реентерабельным.

Указатель диагностики может быть NULL. Отсутствие буфера сообщения либо ёмкость
0/1 не мешают возврату структурированной ошибки. Результат очищается при каждом
вызове, включая неверные аргументы. Успех: NONE и нулевые поля. Сохраняется
первая ошибка; последующее восстановление парсера не подменяет её позицию.
Старый `fir_source` остаётся совместимой обёрткой.

| kind | Причина | Позиция |
| --- | --- | --- |
| argument | Аргументы, профиль или имя модуля | Нет |
| input | Чтение/открытие входа | Нет |
| encoding | Неверный UTF-8 или NUL | Нет |
| limit | Вход больше 64 КиБ | Нет |
| resource | Память, временный поток или scanner | Нет |
| syntax | Синтаксис Coco/R | Lookahead-токен или точка EOF |
| semantic | Отклонение числового профиля/понижения | Захваченный токен, когда доступен |
| output | Ошибка записи/чтения промежуточного FIR | Нет |

Пределы токенов, имён, выражений и вложенности, обнаруженные при понижении,
считаются semantic; limit означает входной предел целого файла. `code` — номер
синтаксической ошибки Coco/R, у остальных видов 0. Номер может измениться с
грамматикой; текст semantic-сообщений не является машинным ABI.

## Единицы координат

`has_location` отличает отсутствие позиции от корректной точки длины 0.
`byte_offset` отсчитывается с 0 в исходных UTF-8 байтах, `byte_length` — длина
полуоткрытого диапазона. `line` и `column` отсчитываются с 1; column измерена
в байтах. Только LF начинает строку; табуляция и CR занимают по одному байту.
Без позиции все координаты нулевые. EOF: offset равен длине входа, length=0.
Координаты пересчитываются из исходных байтов, независимо от табуляции scanner.
Старый текст syntax-ошибок может показывать scanner-колонки: для канонических
координат используйте структуру либо JSON-поля.

В `/*中*/\ttrace(missing);` имя занимает байты [14,21), строку 1 и байтовую
колонку 15; символьное смещение — 12, символьная колонка — 13. Позиции экрана
и UTF-16 — другие единицы. Limbo-ядро использует символьные смещения и колонку
с 0, поэтому колонку host-диагностики нужно уменьшить на 1.

Проверки повторного объявления, const и присваивания запоминают имя до чтения
правой части. Ошибка бинарной операции привязана к оператору; неизвестное имя —
к месту его чтения. Прочие semantic-проверки используют текущий захваченный
токен. Это ещё не полная AST-карта исходников. Ошибка hash-комментария относится
ко всему pragma. Первая semantic-ошибка не заменяется поздней syntax-ошибкой.

## Командная строка

```sh
fir1_source as2 --input input.as output.fir --diagnostics-json --module example
```

Опции допускаются в обоих порядках. Повторные, неизвестные или незавершённые
опции дают usage и код 2. После корректного разбора CLI ошибка даёт одну JSON-
запись stderr с schema=1, kind, code, has_location, byte_offset, byte_length,
line, column, message. Успех: код 0, stdout/stderr пусты. Ошибки подготовки:
код 2; трансляции/выхода: код 1. Без опции остаётся человеческий текст.

FIR сначала пишется во временный поток. Неверный исходник не меняет выход;
CLI открывает назначение только после удачной трансляции. Сбой окончательного
копирования/закрытия может оставить префикс. Для атомарной замены SWF используйте
staging host-драйвера IDE. API не обещает откат произвольного файлового I/O.

## Приёмка в host IDE

`ide/build.py --structured-diagnostics` проверяет версию/типы, известный kind,
целые диапазоны, границы исходника, физические line/column, UTF-8 и границы
символов. Дубли JSON-ключей отвергаются. Неверная/чужая/непривязанная запись
остаётся исходным текстом без угаданных координат; regex из некорректного JSON
не применяется.

К принятой записи добавляются character_offset, character_length, символьные
line/column с 1, coordinate_units и source_sha256; байтовые поля сохранены.
Общий build-result тоже содержит SHA-256 точного снимка. Живой редактор должен
сравнить digest и захваченную ревизию перед применением позднего результата.
Host не владеет ревизией независимо редактируемого документа. Python здесь —
инструмент разработки на хосте, не runtime переносимой IDE.

[Проверки](TESTING.ru.md) отдельно покрывают C99 API, настоящий CLI и связку
host → компилятор. Это не доказательство полноты языков или встраивания Dis.
