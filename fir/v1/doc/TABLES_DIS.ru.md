# Наш Limbo → FIR → Dis: гибридные таблицы

[English](TABLES_DIS.md) · [Исходный язык и FIR](TABLES.ru.md) ·
[Пример Limbo](../examples/tables/main.b) · [Клиент C99 API](../examples/tables/compile.c)

`keys[i]` теперь возвращает проверенный ключ снимка для чтения и записи `t[keys[i]]`.
Выход за границы вызывает ошибку даже для неиспользованного результата. Ключ удерживает
неизменяемый снимок при замене локальных переменных и исходной таблицы; числовые и строковые
ключи не смешиваются. [Состояние расширений](EXTENSIONS.ru.md).

Компилятор FIR 0.14 сам создаёт NC64 Dis для поддерживаемого одноблочного профиля
таблиц big. Временный компилятор Limbo, ассемблер, Python и эталонный исполнитель
для генерации не нужны. Используются существующие импорты HASLDT и инструкции
load/mframe/mcall/lea, перемещения скаляров и ссылок.

Образ требует согласованного встроенного `$Bigtable` из runtime 0.17 с текущим ABI.
Загрузчик проверяет имена и сигнатуры каждой импортируемой функции. Несовместимый
модуль не позволяет вызвать другую нативную функцию по ошибочному индексу.
Inferno, контейнер Dis и набор инструкций не расширялись.

```sh
build/fir/fir1_source limbo --input fir/v1/examples/tables/main.b tables.fir -g tables.debug.json
build/fir/fir1 opt tables.fir tables.opt.fir
build/fir/fir1 dis tables.opt.fir tables.dis
build/runtime/disvm --no-jit --stats --inspect-words 0 2 tables.dis
build/runtime/disvm --jit --stats --inspect-words 0 2 tables.dis
```

В обоих режимах результат: DATA 0 42, DATA 8 1. Вторая ячейка — признак исполнения
trace, а не второе значение исходной программы. Эталонное C-исполнение остаётся
доступным отдельно. Генерация таблиц для SWO/SWF пока не поддерживается.

## Владение и карты GC

Смещения заданы явно для восьмибайтовых ячеек NC64 и не выводятся из размеров C.
Big передаётся без преобразования через double. Таблица и снимок ключей занимают
по одной ссылке. Ключ снимка — две ячейки: ссылка на снимок и скалярная позиция.
Местоположение с обычным ключом — две ячейки; со снимочным ключом — три:
таблица, снимок, позиция. Обе ссылки отмечены как корни GC. Строковый ключ
обычной позиции также является корнем. Диапазон — два скаляра. Копирование
сохраняет точную форму каждого значения.

Карта кадра отмечает модуль, строки, таблицы, снимки и ссылки в местоположениях.
Числовые ключи, диапазоны, статус/значение и сырой указатель подготовленного кадра
вызова не выдаются за heap-ссылки. В данных модуля отмечаются путь импорта и
строковые константы; числовые результаты остаются немаппированными. Кадры нативных
функций имеют проверенные загрузчиком дескрипторы, аргументы-ссылки удерживает MOVP.

После чтения/записи проверяется статус: отсутствие ключа не становится успешным
нулём. Индексы и диапазоны проверяются при создании, даже если результат далее
не используется. Ошибка внутри builtin указывает на PC вызывающей программы;
не выполняется вычитание указателей относительно отсутствующего нативного prog.

При ошибке проверки, покрытия или подготовки поток вывода не меняется. Ошибка
финальной записи может оставить префикс; CLI защищает прежний файл staging-потоком.
Пока нет таблиц в CFG/циклах, общих модулей, any и
адаптеров AS/SWF. FIRDBG1 хранится отдельно; полный SBL/перевод source→Dis PC ещё
не заявляется.

## Проверка на настоящей VM

`--quantum 1` заставляет планировщик и GC работать между инструкциями, включая
подготовку кадра и передачу аргументов. По умолчанию остаётся 2048; явный параметр
принимает 1..65536 без повторов. `--stats` показывает исполненные инструкции,
нативные операции, проходы/эпохи GC и живых владельцев таблиц/снимков. После
успешного выхода из кадра оба счётчика владельцев равны нулю.

Просмотр числовых результатов проверяет биты GC каждой запрошенной ячейки.
Наличие строк в другой части модуля не запрещает чтение числового диапазона;
попадание в ссылку или пересечение с ней запрещено. Данные удерживаются через
зарегистрированный нативный GC-корень до отчёта или обработки ошибки.

Исходный и оптимизированный FIR проверяются в интерпретаторе/JIT: Unicode,
границы big, разреженные индексы, алиасы, независимые срезы/снимки, копирование
типизированных пар, большие карты GC, неверные сигнатуры и позиции ошибок.
Счётчик native подтверждает нативные инструкции; C-функции таблиц остаются
обычными скомпилированными службами runtime.
