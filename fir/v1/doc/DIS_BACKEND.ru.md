# Прямой Dis-backend, реализация FIR 0.17.0

[Typed table Dis extension / Таблицы и нативные вызовы](TABLES_DIS.md) · [Русский](TABLES_DIS.ru.md). Ниже описан числовой путь. Hosted table backend также поддерживает
[исходные циклы и удерживаемые локальные ссылки](RETAINED_LOOPS.ru.md).


[English](DIS_BACKEND.md) · [Реализация C99](../compiler/dis.c) ·
[Библиотечный API](../compiler/API.ru.md) · [Подробный пример](../examples/dis/README.ru.md) ·
[Наш DisVM](../../../disVM/runtime/README.md).

Наш компилятор теперь непосредственно записывает исполняемый NC64 `.dis` из
проверенного FIR. Он не вызывает `limbo-native`, ассемблер Inferno, Python,
LLVM или внешнюю VM для генерации кода. Парсеры исходника и FIR по-прежнему
генерируются Coco/R в C99. Тракт SWO/SWL/SWF8 остаётся отдельной целью.

Скалярная цель теперь поддерживает проверенный многоблочный CFG: i32/bool/f64/i64
константы и copy, wrap-арифметику, signed less-than/equality, bool-ветвления,
безусловные переходы, захват скалярного trace и return. Прямые и обратные рёбра
переносятся из идентификаторов FIR-блоков в окончательные **PC инструкций Dis**,
включая оптимизацию и разные длины файловых операндов.

Наш Coco/R-профиль числового Limbo дополнительно принимает терминальные деревья
решений. После обычного пролога: `return expression;` либо
`if (expression relation expression) { result } else { result }`, рекурсивно.
Сравнения: `<`, `==`, `>`, `!=`, `<=`, `>=`. Каждая ветка возвращает значение;
компилятор 0.22 принимает объявления/присваивания внутри ветвей, но не продолжение
после решения. [Семантика областей](TERMINAL_ARMS.ru.md).
Phi и слияние окружений не подменяются эвристикой. Пределы: 64 КиБ, 1000 значений,
общая глубина 64 и до 127 решений/255 блоков. `-g DEBUG.json` отмечает байтовые
диапазоны операторов сравнения и ключевых слов `if`.

Числовые AS1/2/3 теперь также доходят до Dis через явные операции f64; профиль
исходного языка сохраняется. Динамические `as.add`/`as.to_number`, строки, каналы,
импорты и экспорты функций в этом числовом пути отклоняются до записи. Общие
функции Limbo, явные SSA phi и SBL остаются отдельной работой. Профиль big/table
уже поддерживает исходные while, трёхчастный for и for-in с типизированными
ячейками: [циклы](LOOPS.ru.md), [ссылочные переменные](RETAINED_LOOPS.ru.md).
Ручные FIR-циклы также исполняются с явным лимитом инструкций.

## Консольный запуск

Из корня репозитория, с нашим собранным Coco/R C:

```sh
cmake -S fir/v1 -B build/fir \
  -DCOCOR_ROOT="$PWD/tools/coco-r-C/upstream" \
  -DCOCOR_EXECUTABLE="$PWD/build/cocor/cocor"
cmake --build build/fir
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/main.b build/answer.fir
build/fir/fir1 check build/answer.fir
build/fir/fir1 dis build/answer.fir build/answer.dis
build/editor/disvm --stats --jit --inspect-words 0 1 build/answer.dis
build/editor/disvm --stats --no-jit --inspect-words 0 1 build/answer.dis
```

Runtime собирается отдельно как `disvm-editor` или `disvm-runtime`; путь
`build/editor` здесь пример. Ожидается `DATA 0 2147483647`. В stderr выводятся
настоящие счётчики исполнения, у интерпретатора native=0. Отказ guard с
переходом в интерпретатор не считается выполненным native-листом.

Оптимизация явная: сначала `fir1 opt INPUT.fir OPT.fir`, затем `fir1 dis OPT.fir
OUTPUT.dis`. Через API её также можно запросить FirRunOptions. CLI открывает
старый выходной файл лишь после успешной проверки/генерации во временном
потоке. Ошибка покрытия сохраняет старые байты. Финальная ошибка записи в
файловую систему может оставить префикс: транзакционный откат не заявляется.

## Точная цель и наблюдение результата

Используются существующие инструкции, инициализаторы и дескрипторы Dis с
экспериментальным **NC64 magic 819264**. Это контракт нашего Linux AMD64
runtime, не классический четырёхбайтовый Dis и не проект стандартного ABI64.
Новые теги, опкоды и контейнеры SWF/Dis не вводятся.

WORD в NC64 восьмибайтовый, а FIR i32 — знаковый 32-битный. После каждой
арифметической операции результат нормализуется:

```text
((native_result & 0xffffffff) ^ 0x80000000) - 0x80000000
```

Это относится и к промежуточным значениям. Произведение двух i32 помещается
в native 64-битный диапазон. Константы используют обычный big-endian DEFL,
операнды — обычное signed-30-bit кодирование Dis. Все размеры и смещения
ограничены проверенными пределами FIR. Карты локальных значений и данных
модуля не содержат указателей; заголовок и время жизни кадра обслуживает Dis.

Каждый **живой статический trace** получает слот в физическом порядке FIR.
Для N trace первые N восьмибайтовых ячеек содержат значения, следующие N —
флаги исполнения, изначально нулевые. Посещённый trace пишет значение и флаг 1;
непосещённый сохраняет значение 0 и флаг 0. Поэтому выполненный `trace 0`
отличается от пропущенной ветки. Повторное посещение сохраняет последнее значение;
это не хронологический журнал. После оптимизации N может измениться, поскольку
непосещаемые trace удаляются. Библиотечный клиент считает живые O_TRACE в
post-optimization модуле через существующий callback `after`; метаданные следует
публиковать только после успешного завершения компиляции.

Смещения первых N значений сохраняются для линейных клиентов. Для CFG нужно
читать и флаги. Далее расположен внутренний пул констант — это не trace-вывод.
Формат Dis, опкоды и ABI не расширены. Без инспекции значения не печатаются;
скрытого вызова Sys print нет.

`disvm --inspect-words OFFSET COUNT` запрашивает скалярный снимок. OFFSET —
десятичное байтовое смещение, кратное восьми; COUNT — 1..4096 native-слов.
До исполнения проверяются настоящие данные экземпляра и границы диапазона;
дескриптор с указателями отклоняется. Runtime удерживает именно исполняемый
экземпляр до отчёта или ошибки, а не читает исходные константы модуля либо
уже освобождённый кадр. Формат строки: `DATA byte_offset signed_word`.

## Ограничение исполнения, компонент 0.9.0

`disvm --max-instructions COUNT` принимает одно десятичное число 1..2147483647.
На полной границе инструкции после GC poll, до C/native-исполнения владелец
отклоняет следующий dispatch, если уже допущено COUNT инструкций. Fallback
считается один раз, native-счётчик увеличивается только после принятого листа.
Лимит суммарный по процессам и квантам; stdin/UI progress его не сбрасывает.
Это не тайм-аут по часам. Прежний busy-work guard также сохраняется.

Завершение ровно на лимите успешно. Превысивший его цикл завершается ошибкой
`instruction limit exceeded` с текущим, ещё не выполненным PC; `--stats` выдаёт
точное число допущенных инструкций. Незавершённый DATA-снимок не публикуется,
inspection-retain освобождается аварийным путём. Без опции действует прежняя
политика runtime. Это локальный CLI-лимит, не протокол breakpoint/удалённой отладки.

## Библиотека и сервис IDE

Свяжите `fir1_source_api` и `fir1_ir`, подключите `fir.h`. `fir_source` создаёт
промежуточный FIR из числового Limbo; после перемотки `fir_run(FIR_DIS, ...)`
выдаёт Dis. Уже проверенный модуль можно передать в `fir_dis`. Потоки и буфер
ошибки принадлежат вызывающему коду; библиотеки возвращают 1/0, не закрывают
потоки и не вызывают exit. NULL-диагностика допустима. Ошибка покрытия не
пишет ничего, ошибка I/O может оставить префикс непосредственно переданного
потока. [C99-пример](../examples/dis/main.c) показывает staging и очистку.

Компиляция исполняется в native build worker IDE; в Dis UI возвращаются
копируемые результаты по сервисному каналу. Парсеры требуют внешней
сериализации. Разные принадлежащие вызывающему коду FIR-модули проверяются
и генерируются без общего состояния backend.

## Проверки и следующие этапы

CTest компилятора проверяет детерминизм, C API/NULL/восстановление и сохранение
старого назначения при отказе. Необязательные runtime-тесты подключаются
путями DVM_FIR_COMPILER и DVM_FIR_SOURCE_COMPILER. Они проверяют 90 зависимых
операций независимым i32-эталоном, до/после peephole, в JIT/интерпретаторе и
с UBSan; отдельно прогоняют наш Limbo-парсер и lexical scopes, отказы неверных
диапазонов и запрет инспекции данных с указателями. Bootstrap не генерирует
проверяемые программы.

Далее нужны типизированные функции/сигнатуры/импорты, SSA joins/исходные циклы, f64/строки, исходные
каналы, более полное Limbo/AS lowering, линковка Dis и SBL/source-PC mapping.
Исходные `-g DEBUG.json` координаты сохраняются, но автоматически не становятся
`.sbl`. Полная IDE пока использует временный source-built bootstrap, пока наш
компилятор не покрывает её языковые конструкции.

[Пример терминального решения](../examples/dis/README.ru.md#терминальные-решения-и-флаги-исполнения)
показывает три статических слота. Дополнительно проверяются шесть сравнений
с обоими исходами, обратные физические рёбра, PC выше 8191, 255 блоков,
границы квоты и циклы. Verifier отвергает перемежающиеся живые блоки и скрытый
entry после удалённого префикса; это защищает оба emitter. Структурный Coco/R
фронтенд отличает следующую метку блока после return от настоящего операнда.

## Binary64: компилятор 0.9.0, runtime 0.10.0

Поддержаны const.f64, copy и f64.add/sub/mul/div через существующие MOVF и
real-инструкции Dis. Константы передаются точными IEEE-битами через uint64_t
в big-endian DEFL; знак нуля сохраняется. Исходные константы должны быть конечны,
но вычисления могут давать Inf/NaN. Деление — вещественное, включая деление на
знаковый ноль; идентичность payload NaN не обещается. Нормализация i32 не применяется.

`--inspect-reals OFFSET COUNT` читает однородный диапазон binary64 и печатает
`REAL смещение значение` с 17 значащими цифрами. Проверки границ, дескриптора,
удержания и ошибок общие с --inspect-words; совмещать эти опции нельзя. Флаги
исполнения остаются целыми 0/1 и читаются как words. Автоопределения типов нет:
клиент берёт типы trace из FIR. Для смешанных значений нужны отдельные диапазоны.
Это чтение битов, а не приведение целого к real. При ошибке VM или исчерпании
квоты частичный REAL-снимок не публикуется.

[Пример AS3 и SDK](../examples/dis/README.ru.md#binary64-из-as).

Our Coco/R Limbo adapter now additionally admits a homogeneous `value(): real`
profile: decimal real constants, typed/inferred real locals, lexical scopes,
assignments, + - * /, return and ordered terminal real comparisons/decisions. Mixed numeric casts and nonterminal real CFG remain outside this bounded profile. [Exact grammar coverage](SOURCE_SYNTAX.md#homogeneous-limbo-real-090).

Наш Limbo real — ограниченный однородный профиль с явными real-литералами;
обычные int-функции и их терминальные ветвления сохраняют прежнюю семантику.
[Комментированный пример](../examples/dis/README.ru.md#вещественный-limbo).
