# Расширения Limbo: что действительно исполняется

[English](EXTENSIONS.md) · [Исходный язык таблиц](TABLES.ru.md) ·
[ABI Dis](TABLES_DIS.ru.md) · [Интерфейс проекций IDE](../../../ide/dis/bridge/ideprojection.m)

Это граница текущей реализации, а не только принятого синтаксиса или целевой
архитектуры. Исходники расширенного профиля обрабатывает наш Coco/R-фронтенд.
Нативный bootstrap остаётся отдельным временным инструментом для обычного Limbo IDE.

| Возможность | Исходник → типизированный FIR → Dis | Граница |
| --- | --- | --- |
| `table of big` | Работает | Ациклический терминальный профиль `value(): big` |
| Проверяемые сдвиги big, явные int-счётчики | Работает | [64-битный/i32 контракт](BIG_SHIFTS.ru.md) |
| Арифметика big +, -, *, унарные знаки | Работает | [Modulo-64 и нативный код](BIG_ARITHMETIC.ru.md) |
| Числовые/строковые ключи, `t.k` | Работает | Ключи разных пространств, значения big |
| `len`, явные срезы, `keysof` | Работает | Независимые копии срезов и снимков |
| `keys[i]`, чтение/запись `t[keys[i]]` | Работает | Проверенный ключ неизменяемого снимка |
| `typeof`, приведения int/big/string | Работает | [Профиль и преобразования](TYPE_REFLECTION.ru.md) |
| Неоднородные таблицы | Предстоит | Значения остаются big |
| Языковой `any` | Предстоит | Само наличие FIR `T_ANY` ещё не означает реализации |
| Автоматические прокси-локальные/операторы | Предстоит | В IDE используется явный типизированный API |
| Проекции объектов и методов | Явный API IDE | Идентификатор владельца/эпоха, без адресов кучи |
| Общие сетевые удалённые ссылки | Предстоит | Общий реестр экспорта, аренды и GC не заявлен |

## Ключи снимков

```limbo
# Полный модуль находится в examples/tables/main.b.
# keysof копирует ключи, но не значения; тип снимка выводится компилятором.
t := table of big;
t["1"] = big 42;  # Строковый ключ отличается от числового 1.
keys := keysof t;
k := keys[0];     # Границы проверяются сейчас, даже если k потом не используется.
keys = keysof table of big; # k продолжает удерживать прежний снимок.
t[k] = big 43;    # Запись по прежнему строковому ключу.
return t[k];      # Читается текущее значение, а не значение на момент keysof.
```

В FIR добавлены `table.key` и `keys.at` без изменения номеров прежних перечислений.
Ключ хранит владельца снимка и позицию. Его внутреннее двухъячеечное представление
не передаётся по каналам или сети. Табличная позиция с таким ключом занимает три
ячейки и удерживает таблицу и снимок; только позиция является скаляром. Компилятор
создаёт точные GC-карты и вызовы `keycheck/getkey/setkey` с проверкой сигнатур.
Границы, отсутствие ключа и ошибки выделения памяти сохраняются при оптимизации.
Индексирование снимка не создаёт дополнительный объект ключа или String.

Эталонный C-исполнитель удерживает снимки до конца вызова; Dis использует реальные
корни кадров, RC и GC. Тесты заменяют владельцев при сборке между каждой инструкцией
и проверяют отсутствие живых нативных владельцев после успешного завершения.
C-ядро хранит скопированные ключи и big, но не адреса объектов Dis/Flash.

## Прокси и any

[Ideprojection](../../../ide/dis/bridge/ideprojection.m) и
[Idevalue](../../../ide/dis/bridge/idevalue.m) поддерживают явное типизированное
чтение, запись, преобразование копий, идентификаторы объектов/методов и вызов
в среде владельца. Это модули обычного Limbo с каналами запросов и ответов.
Они ещё не реализуют семантику автоматической локальной переменной `any`.
Поверхностный снимок значений IDE также отличается от изменяемой нативной таблицы.

Согласованный будущий `any` должен адаптировать типизированный канальный доступ:
запрашивать нужный тип при использовании, записывать у владельца и вызывать функции
в их среде. До прозрачного синтаксиса нужны типы возможностей/эффекты FIR, точная
позиция обращения в исходнике, эпоха владельца и управление жизненным циклом.
Составные атомарные изменения должны выполняться у владельца; отдельное клиентское
чтение и последующая запись атомарностью не обладают. Расширение таблиц в Inferno
из этой серии не переносится.
