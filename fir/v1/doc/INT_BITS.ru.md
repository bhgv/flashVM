# Точные signed32 побитовые операции — компилятор 0.52

[English](INT_BITS.md) · [Побитовый пример](../examples/dis/int-bits.b) · [Сдвиги](../examples/dis/int-shifts.b) · [API](../include/fir.h) · [Грамматика](../compiler/src1.atg)

Однородный профиль Limbo value(): int поддерживает &, |, ^, унарное ~, проверяемые << / >> и составные присваивания. Все операнды и результаты — signed32, в том числе на NC64. Псевдонимы типов сохраняют канонический int. Исходные AS и однородный real эти операторы отклоняют; неявных преобразований float/dynamic нет.

Приоритет: | ниже ^, затем &, сдвиги, суммы и произведения. Бинарные уровни левоассоциативны; дополнение вычисляет операнд один раз. Числовое условие остаётся одним явным сравнением с внутренним bool. Побитовое выражение нужно группировать: `if ((flags & mask) != 0)`. Несгруппированные смеси сравнения и битовых операторов отклоняются: в Limbo сравнение связывается сильнее &, а ограниченный профиль не приводит внутренний bool обратно к int.

## FIR и целевые ВМ

Добавлены три ID в конец перечисления: i32.and, i32.or, i32.xor. Сигнатура i32/i32 → i32, эффекты нулевые. Старые ID и FIR 1.0 не меняются. ~ понижается в xor с -1. Verifier отвергает смешанные типы до записи результата. Оптимизатор складывает константы через uint32_t и определённое восстановление signed32; неиспользуемые чистые операции удаляются. Эффекты производителей операндов сохраняются.

Побитовые int-операции типизированного big/table-профиля также используют новый примитив: одна инструкция вместо двух расширений, операции big и сужения. Проверяемый разбор строки/ключа перед получением int не исчезает. Полноразрядные big-операции сохраняют прежнюю семантику.

Оба Dis-бэкенда используют существующие ANDW/ORW/XORW с нормализацией signed32. Новых Dis-опкодов, ABI модулей или представлений кучи нет. SWF-объекты используют стандартные AVM1 BitAnd/BitOr/BitXor. SWL 0.3.12 проверяет BitXor и сохраняет его байты. Работает цепочка исходник → FIR → SWO → линкер → SWF.

Сдвиги используют прежние i32.shl.checked/i32.shr.checked. Счётчик int должен лежать в 0..31, правый сдвиг арифметический, левый оборачивается в signed32. Ошибочный счётчик вызывает исключение даже при неиспользуемом результате; пропущенная ветвь не исполняется. Живые проверяемые сдвиги предназначены для Dis/эталонного исполнения. SWF-бэкенд при отказе сохраняет прежний объект; полностью свёрнутые константы могут использовать обычный константный путь.

## Запуск

Из корня репозитория после сборки согласованных инструментов:

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/dis/int-bits.b build/bits.fir -g build/bits.json
build/fir/fir1 opt build/bits.fir build/bits.opt.fir
build/fir/fir1 dis build/bits.fir build/bits.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 2 build/bits.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 2 build/bits.dis
build/fir/fir1 object build/bits.fir build/bits.swo
build/swf-linker/swl link build/bits.swf build/bits.swo
```

Оба Dis-режима возвращают DATA 0 42 и DATA 8 1; второе слово подтверждает выполнение trace. Проверьте также оптимизированный вариант. SWF выдаёт 42 через trace в соответствующем хосте; открытое окно само по себе не проверяет результат. Для int-shifts.b повторите Dis-команды с отдельными именами файлов: результат тоже 42. Каждая непустая строка примеров прокомментирована. Установленный SDK компилирует оба примера, перелинковывает C99-клиент и исполняет исходный/оптимизированный Dis в обоих режимах.

Проверяются 192 сочетания границ/знаков/операторов, приоритеты, псевдонимы, составные операции, PC ветвлений, оба бэкенда Dis, загруженные табличные операнды, ошибки и пропуск сдвигов, границы профилей, позиции UTF-8 и сохранение выходных файлов. C API проверяет ID, эффекты и девять поддельных сигнатур. Счётчики подтверждают фактическую диспетчеризацию; физический ARM64 проверяется отдельно.
