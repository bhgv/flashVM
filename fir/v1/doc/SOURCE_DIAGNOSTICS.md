# Source diagnostics, schema 1

FIR 0.5.4 adds `fir_source_ex` and opt-in JSON output to the numeric AS1/AS2/AS3
and Limbo adapters. Parsers still come from authoritative
[src1.atg](../compiler/src1.atg), generated by external Coco/R. FIR text stays
1.0 and the object format stays SWO1; no new language constructs are added.
Broader syntax frontends have their own APIs and do not implicitly adopt this schema.

## C99 interface and ownership

[fir.h](../include/fir.h) defines `FirSourceDiagnostic`, an enum kind and copied
scalar fields. `fir_source_ex(input, output, language, name, message, capacity,
&diagnostic)` returns 1 on success, 0 on failure. Both streams and message/struct
storage belong to the caller. No pointers into source, streams or diagnostic
storage are retained on return. The generated parsers use globals: serialize
calls, including calls through the old API. This is not a reentrant compiler.

`diagnostic` may be NULL; message may be NULL or have capacity zero. Each call
clears its diagnostic before validating arguments. Success returns kind NONE and
all zero fields. The first failure wins, including when the text buffer is absent
or only one byte long. A later recovery error never replaces that location.
`fir_source` remains a wrapper that does not request the copied struct.

| Kind | Meaning | Location |
| --- | --- | --- |
| argument | Invalid stream, profile or module name | Absent |
| input | Failed input read/open | Absent |
| encoding | Invalid UTF-8 or embedded NUL | Absent |
| limit | Input exceeds 64 KiB | Absent |
| resource | Temporary stream/allocation or scanner failure | Absent |
| syntax | Coco/R syntax rejection | Original lookahead token or EOF point |
| semantic | Numeric profile/lowering rejection | Captured source token when available |
| output | Temporary/final FIR I/O failure | Absent |

Token/name/expression/nesting limits detected during lowering are semantic errors;
`limit` specifically denotes whole-input admission. Kind NONE is success only.
`code` retains Coco/R's syntax number for syntax errors; other kinds use zero.
Coco/R code numbers may change when the grammar changes; they are not frozen
language-independent error IDs. Semantic prose is for people, not a machine ABI.

## Coordinates

`has_location` distinguishes no position from a valid zero-length span:

- `byte_offset`: zero-based original UTF-8 byte offset.
- `byte_length`: number of original bytes; zero means an insertion/EOF point.
- `line`: one-based physical line; LF alone starts a new line.
- `column`: one-based byte column, with tab/CR counted as one byte each.

When no position is available, has_location and all four coordinates are zero.
EOF has offset equal to the admitted source size and length zero. Coordinates
are recomputed from original bytes, independent of scanner tab expansion.
The legacy text may still display scanner columns for syntax errors: consume the
copied struct or JSON fields for canonical positions.

The unresolved name in `/*中*/\ttrace(missing);` has byte span [14,21), line 1,
byte column 15, character offset 12 and character column 13. Screen cells and
UTF-16 code units are separate again. A client must decode byte boundaries before
converting to character indices. The Limbo core uses character offsets and
zero-based columns; its column is one less than the host diagnostic column.

Target-side duplicate/const/assignment checks capture the identifier before
parsing an initializer or RHS. Binary-operator errors capture the operator;
unknown-name errors retain the identifier where the read occurred. Other semantic
checks use their current token when available; this is not full AST source mapping.
Hash-comment errors refer to the complete pragma. Nested parser recovery does not
silently convert an earlier semantic error into a later syntax location.

## CLI

```sh
fir1_source as2 --input input.as output.fir --module example --diagnostics-json
```

`--module` and `--diagnostics-json` may occur in either order. Unknown, duplicate
and incomplete options fail with usage text and exit 2. Once CLI syntax is valid,
failed setup/compilation/output emits exactly one stderr record:

```json
{"schema":1,"kind":"semantic","code":0,"has_location":true,"byte_offset":14,"byte_length":7,"line":1,"column":15,"message":"source line 1: read before initialized declaration"}
```

Success has exit 0 and silent stderr/stdout; the FIR artifact goes to the selected
file. Setup failures use exit 2; translation/output failures use exit 1. JSON is
opt-in so callers of older tools keep working. Legacy error text is not JSON.
Error messages are escaped as JSON strings, not shell fragments.

The API stages FIR privately. Rejected input/translation does not write to output;
the CLI does not open the destination until compilation succeeds. Final stream copy
or close failure may leave partial output. Use the IDE host's staged publication
when replacing an existing SWF atomically. This API is not filesystem rollback
for arbitrary I/O faults, symlinks or aliases.

## Host IDE admission

`ide/build.py --structured-diagnostics` requests this schema and validates it
against the exact captured input: version/types, known kind, integer bounds,
span bounds, physical byte line/column, complete UTF-8 and code-point boundaries.
It rejects duplicate JSON keys. Malformed/foreign/unlocated records remain raw
text without guessed navigation coordinates; structured mode never mines a regex
location from an invalid JSON record.

Accepted diagnostics keep byte fields and add `character_offset`,
`character_length`, one-based character line/column, `coordinate_units` and
`source_sha256`. The overall result also identifies the exact snapshot by SHA-256.
The live editor must compare that digest and its captured revision before applying
a late result. The host cannot decide whether an independently edited document is
still current. Python is host tooling, not the deployed IDE runtime.
