# Точная арифметика big: Coco/R → FIR → Dis

[English](BIG_ARITHMETIC.md) · [Полный комментированный модуль](../examples/tables/arithmetic.b) ·
[Отражение и cast Limbo](TYPE_REFLECTION.ru.md) · [Состояние расширений](EXTENSIONS.ru.md)

Профиль Limbo с результатом big поддерживает бинарные `+`, `-`, `*`, унарные
`+`/`-`, скобки и арифметику в ключах, чтении, записи и границах среза.
Умножение сильнее суммы; оба бинарных уровня левоассоциативны. Приведения,
typeof, len и keysof принимают унарный операнд: `string (1 + 2)` даёт "3",
а `string 1 + 2` отклоняется как string-plus-big. Неявных преобразований нет.

Операнды должны иметь тип big. Операции сохраняют биты по модулю 2^64, как
unsigned-реализация интерпретатора Dis и нативные ALU AMD64/ARM64.
MAX+1 даёт MIN, MIN-1 даёт MAX, -MIN даёт MIN, MAX*2 даёт -2. Компилятор
и эталонный C-исполнитель не используют переполнение signed или промежуточный
real. Внедиапазонные литералы по-прежнему отклоняются; минимальное значение
записывается `-9223372036854775808` или `big -9223372036854775808`.

```limbo
# Тело value(): big; полный модуль приведён по ссылке выше.
maximum := big 9223372036854775807;
wrapped := maximum + 1; # Точный минимум, без округления в real.
flipped := -wrapped;    # Отрицание минимума сохраняет его битовый образ.
values := table of big;
key := string flipped; # Точный десятичный ключ, явное приведение Limbo.
values[key] = big 7;
values[key] = values[key] + 5 * values[key]; # Чтения вычисляются в исходном порядке.
return values[key];    # 42 в эталонном исполнителе, интерпретаторе и JIT.
```

## IR и нативный код

Добавлены чистые полные i64-операции `big.add`, `big.sub`, `big.mul`, `big.neg`
без изменения номеров прежних операций. Проверяются арность, типы и доминирование
SSA. Оптимизатор сворачивает константы через unsigned 64-bit и переносимое
толкование знаковых битов. Он объединяет одинаковые big-константы и выполняет
CSE в блоке над неизменяемыми SSA-входами. Чтения таблиц и преобразования сохраняют
консервативные эффекты: удаление неиспользованной арифметики не удаляет ошибку
отсутствующего ключа или неверного преобразования операнда.

NC64-эмиттер создаёт прежние IADDL (119), ISUBL (120), IMULL (123) со средним
операндом относительно кадра. Отрицание — ноль минус захваченный операнд.
Нет арифметического RPC, builtin-посредника или новой инструкции Dis. Исходные
и оптимизированные программы исполняются настоящей Dis VM с quantum=1. Тест
независимо декодирует образ, проверяет нативные ALU и отсутствие MFRAME/MCALL
в чистом арифметическом примере. Генерация арифметики не вызывает внешний ассемблер или bootstrap.

## Исходные позиции и ограничения

FIRDBG1 запоминает точный арифметический/префиксный токен. Позиция знакового
литерала охватывает минус и все цифры. Суммы/произведения разбираются циклом:
длинное плоское выражение не расходует стек рекурсии. Скобки, унарные операции
и вложенные индексы имеют общий предел глубины 64; сохраняются ограничения
входа, числа SSA и имён. Полное соответствие исходник—Dis SBL остаётся отдельно.

Деление, побитовые операторы, сравнения в этом профиле, табличные CFG/циклы,
неоднородные значения и автоматические канальные any/прокси предстоят.
Обычное чтение—вычисление—запись не является атомарным обновлением у удалённого
владельца. API ключей снимка остаётся явным; адреса куч по каналам не передаются.
