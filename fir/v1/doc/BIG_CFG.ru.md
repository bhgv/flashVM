# Полноразрядная арифметика big в прямом Dis CFG — FIR 0.17

[English](BIG_CFG.md) · [Полностью комментированный FIR](../examples/dis/big-cfg.fir) ·
[Скалярная цель](DIS_BACKEND.ru.md) · [Контракт арифметики](BIG_BITWISE.ru.md)

Прямой скалярный backend принимает i64-константы, copy, trace и операции big:
сложение, вычитание, умножение, деление, остаток, and/or/xor, отрицание и инверсию
во всём проверенном многоблочном FIR. Раньше любая операция big выбирала
одноблочный backend таблиц: корректный CFG отклонялся, а чистая арифметика
загружала Bigtable. Теперь этот backend выбирают настоящие операции таблиц,
ключей, диапазонов, отражения типов и преобразований.

FIR 0.18 расширяет эту основу: [точные терминальные решения исходного big](BIG_DECISIONS.ru.md).
Циклы таблиц, phi, смешанная типизация, сдвиги, прозрачный any/прокси и полная
компиляция функций/модулей Limbo остаются отдельной работой.

## Код, владение и ошибки

Используются существующие MOVL/ADDL/SUBL/DIVL/MODL/MULL/ANDL/ORL/XORL
(118–126), без импортов и heap-ссылок. Отрицание вычитает из заранее обнулённой
scratch-ячейки. Инверсия делает XOR с полной 64-битной маской в уже выделенной
скалярной MP-ячейке результата. Новых opcodes, глобальных масок, runtime helpers
и указателей между кучами нет.

До релокации учитывается точное число Dis-инструкций всех развёрток. Прямые и
обратные переходы используют PC инструкций, не байтовые смещения и не индексы
FIR. Арифметика сохраняет modulo 2^64; деление/остаток — zero divide и контракт
MIN/-1. Неиспользуемое деление всё ещё может выбросить ошибку после оптимизации.
Удалять ошибочную ветвь можно только тогда, когда она недостижима.

Захват: N восьмибайтовых значений, затем N флагов исполнения. У непройденной
ветви значение и флаг нулевые. После оптимизации надо пересчитать live trace:
недостижимые точки и их ячейки исчезают. Карты указателей обоих дескрипторов
пусты. Настоящие таблицы по-прежнему используют отдельный hosted-путь с
проверенными сигнатурами и точными GC-картами; ациклический CFG таблиц поддержан, циклы пока отклоняются. Обычная арифметика не является атомарным удалённым изменением.

## Запуск примера

Из корня репозитория после сборки нашего FIR и DisVM:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1 dis fir/v1/examples/dis/big-cfg.fir build/big-cfg.dis
build/runtime/disvm --jit --inspect-words 0 4 build/big-cfg.dis
build/runtime/disvm --no-jit --inspect-words 0 4 build/big-cfg.dis
```

Ожидаемые ячейки: `-9007199254740993, 0, 1, 0`. Первая ветвь точно восстановила
исходное число за пределами целочисленной точности binary64; вторая не исполнялась.
Явный `fir1 opt INPUT OUTPUT` удаляет константное решение и недостижимую ветвь.
Пример устанавливается вместе с SDK компилятора.

## Проверки

Runtime-тест проверяет оба решения, десять операций, знаковые границы, все
сочетания знаков деления/остатка, числа выше 2^53 и независимый Python oracle
со стабильным seed. Значения entry используются в других блоках; выходы из
ветвей прыгают назад. Исходный и оптимизированный код исполняются с quantum=1
интерпретатором и JIT. Декодер проверяет настоящие opcodes, отсутствие импортов
и пустые GC-карты. Ошибочная выбранная ветвь не публикует DATA; невыбранная
ошибочная ветвь не мешает успешному исполнению до и после оптимизации.
Это исполнение на AMD64. Эмуляция инструкций ARM64 проверяется отдельно и не
означает испытания на физическом ARM64.
