# Проверяемые сдвиги int32 в SWF — FIR 0.60

[English](SWF_INT_SHIFTS.md) · [Общий контракт](INT_SHIFTS.ru.md) ·
[Пример с комментариями](../examples/dis/int-shifts-swf.b) ·
[Проверка C99 API](../tests/swf_int_shifts_api.c)

SWO1 backend принимает `i32.shl.checked` и `i32.shr.checked`, когда живое
SSA-определение счётчика — `const.i32` в диапазоне **0…31**. Само значение
может оставаться динамическим. CLI `fir1 object` и библиотечные
`fir_object`/`fir_run(FIR_OBJECT)` используют одну проверку. Грамматика,
FIR opcode, версия SWO и Dis ABI не меняются.

AVM1 маскирует счётчик до пяти битов; FIR выдаёт ошибку при отрицательном
счётчике или значении выше 31. Поэтому неизвестный счётчик отвергается, даже
если некоторые запуски дали бы допустимое значение. Недопустимая константа
тоже отвергается: backend не заменяет ошибку FIR результатом Flash.
Проверка выполняется до записи байтов объекта. При отказе старый префикс
потока сохраняется; успешная запись по-прежнему требует обработки ошибок I/O.

| FIR | Допуск SWF |
| --- | --- |
| Динамическое x, счётчик-константа 0…31 | Принимается, точный signed32 |
| Константное x, неизвестный счётчик | Отказ, в том числе при x=0 |
| Счётчик -1, 32 или другая недопустимая константа | Отказ |
| Счётчик задан copy/add/другой операцией | Исходный backend отвергает; явная оптимизация может раскрыть константу |
| Сдвиги big | Прежние ограничения целевого backend |

Сдвиг влево сохраняет младшие 32 бита; вправо — арифметический, с продолжением
знака. Отрицательные значения и счётчик 31 совпадают с семантикой Dis.
После доказательства диапазона emitter использует стандартные AVM1
ShiftLeft/ShiftRight, не вычисляет выражения повторно и не добавляет runtime.

## Сборка примера

Из корня репозитория, после сборки FIR и SWL:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/int-shifts-swf.b build/shifts.fir
build/fir/fir1 object build/shifts.fir build/shifts.swo
build/linker/swl link build/shifts.swf build/shifts.swo
build/fir/fir1 dis build/shifts.fir build/shifts.dis
build/runtime/disvm --jit --stats --inspect-words 0 2 build/shifts.dis
build/runtime/disvm --no-jit --stats --inspect-words 0 2 build/shifts.dis
```

Цикл складывает -2, 2, 6, 10 и прибавляет 26: результат **42**. Dis показывает
payload 42 и executed flag 1; связанный SWF выводит 42 в FlashVM. Каждая строка
исходника объяснена. Для оптимизированного пути сначала выполните `fir1 opt`,
а затем подайте его результат любому backend. Установленный SDK содержит тот
же пример и библиотеки; C99-клиент пересобирается без дерева сборки.

## Проверки и границы

Проверяются восемь знаковых входов, включая MIN/MAX, и все 32 счётчика для
обоих направлений: 512 значений на исходный/оптимизированный вариант. Python
oracle сравнивается с настоящим выводом SWF в FlashVM и захватами Dis в
интерпретаторе/JIT; проверяются счётчики dispatch. Недопустимые/неизвестные
счётчики проверяют диагностику и сохранение старого файла. Тест C99 API
повторяет успешные вызовы, отказы и раскрытие счётчика оптимизатором.

Запуск SWF включают явные `FIR_SWL` и `FIR_FLASHVM_RUNNER`. Тест только
компилятора не доказывает работу плеера. Общие runtime-исключения AVM1 для
неизвестного счётчика, синтаксис сдвигов ActionScript, AS3/ABC output и новый
Dis64 int32/ref64 этой серией не добавляются.
