# Числовые ячейки и структурный Limbo CFG — FIR 0.58 / CLI 0.25

[English](NUMERIC_FLOW.md) · [Покрытие](COVERAGE.ru.md) · [Выражения](GROUPED_CONDITIONS.ru.md) · [Пример int](../examples/dis/numeric-flow-int.b) · [Пример real](../examples/dis/numeric-flow-real.b) · [Цикл FIR](../examples/dis/numeric-cells.fir) · [Снимки знакового нуля](../examples/dis/real-cells.fir)

Однородные функции Limbo int/real получили обычные структурные операторы:
нетерминальный if/else, необязательный else, else-if, while, счётный for, постфиксные обновления, break/continue для
ближайшего цикла и return из вложенного блока/цикла. Сохраняется ограниченный
вход value() и прежний trace-harness. Общий ABI функций/модулей этим не вводится.

## Семантика исходника

Числовые переменные по-прежнему инициализируются при объявлении и сохраняют тип.
Перед ветвлением/циклом активные значения помещаются в доминирующие приватные
ячейки. Присваивание меняет ячейку, чтение создаёт новый неизменяемый SSA-снимок.
Открытые ветви if сливаются через одну ячейку; завершившаяся return-ветвь не
создаёт ребро продолжения. Без else ложная ветвь сохраняет входное состояние.

Условие while вычисляется заново после каждого обратного ребра. Continue ведёт
к проверке ближайшего цикла, break — к его выходу. Локальные объявления и aliases
тела заканчиваются вместе с его областью и не читаются после цикла. Анализ консервативно допускает
ноль итераций даже при константно истинном тесте: return внутри тела не доказывает
полный возврат функции.
Каждый достижимый выход должен вернуть заявленный числовой тип. Недостижимый
суффикс после return/break/continue отвергается.

Именованные переходы, bool-переменные, смешанные int/real casts и
исходные вызовы функций пока не поддерживаются. Профиль big/table сохраняет свой
прежний for/while и ячейки удерживаемых владельцев. Повторения числовых и табличных
операторов имеют разные FIRST-множества Coco/R для конечной диагностики.
[Числовой for](NUMERIC_FOR.ru.md) использует область заголовка, вложенное тело
и отложенный шаг, к которому ведёт continue.

## Контракт FIR

Два типа и шесть операций добавлены в конец enum-каталогов, прежние номера
сохранены. Текстовый FIR остаётся 1.0; нужны согласованные инструменты и повторная
линковка C99-клиентов с соответствующими заголовками/библиотеками. Стабильный
бинарный ABI внутренних структур компилятора не обещается.

| Тип | Создание | Запись | Чтение | Начальное значение |
| --- | --- | --- | --- | --- |
| i32.slot | i32.local | i32.store cell, i32 | i32.load cell | точный signed32 ноль |
| f64.slot | f64.local | f64.store cell, f64 | f64.load cell | binary64 +0 |

Store не имеет результата, load создаёт неизменяемый SSA-payload. Handles ячеек
нельзя копировать, выводить, передавать в канал или преобразовывать. Создание
доминирует над каждым использованием. Сырой FIR разрешает чтение сразу после
создания и получает ноль; исходные объявления остаются строже. Разные ячейки
не alias. Поздняя запись не меняет старый load-снимок. Повторное выполнение
конструктора в теле цикла снова инициализирует его память.

Local/store имеют FIR_WRITES_MEMORY, load — FIR_READS_MEMORY. Выделения heap и
удержания owners нет. Оптимизатор пересылает известные значения только внутри
одного блока и удаляет перезаписанные store при прежних барьерах эффектов.
Факты не переносятся через обратное ребро; ошибки эффектных производителей
сохраняются. Verifier проверяет типы, arity, доминирование и запрет выхода handles
до публикации backend-результата.

## Исполнение, GC и отладка

Оба Dis-пути используют существующие MOVW/MOVF/MOVL и обычные scalar frame slots.
Даже рядом с таблицей numeric cells не получают биты pointer-map: NaN, signed32
и знаковый ноль не становятся GC-корнями. Новых Dis-инструкций, ABI кадров и общих
указателей между кучами нет. Счётчики доказывают исполнение выбранного режима,
а не аппаратную проверку другой CPU или все варианты native-операндов.

SWO использует приватные переменные объекта и стандартные AVM1 действия;
обратные переходы проходят прежние проверяемые fixups. SWL создаёт обычный SWF8.
Новых тегов/релокаций не требуется. C99-эталон исполняет отдельные числовые поля.
Прежние ограничения SWF для проверяемого int-деления/сдвигов сохраняются.

FIRDBG1 сохраняет UTF-8-позиции while, break, continue и return. Синтетические
ячейки относятся к управляющему if/while; прежнее имя события table-operation
сохранено для типизированных операций. Это provenance исходного/неоптимизированного
FIR, не окончательная карта Dis/SWF/JIT PC. C99-вызовы блокируют вызывающий поток
и сериализуются хостом; потоки принадлежат клиенту, результаты IDE передаются
копируемыми сообщениями служебных каналов.

## Примеры и команды

Все непустые строки четырёх учебных исходников подробно прокомментированы.

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/numeric-flow-real.b build/flow.fir -g build/flow.json
build/fir/fir1 opt build/flow.fir build/flow.opt.fir
build/fir/fir1 dis build/flow.fir build/flow.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 2 build/flow.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 2 build/flow.dis
build/fir/fir1 object build/flow.fir build/flow.swo
build/linker/swl link build/flow.swf build/flow.swo
```

Real-пример возвращает ровно 42.5: биты 4631178160564600832 и флаг 1. Int-пример
пропускает индекс 3, выходит на 9, получает сумму 33 и после слияния возвращает 42.
В сыром int два return: значения 0/42 и флаги 0/1; используйте --inspect-words 0 4.
После opt считайте оставшиеся trace. Для numeric-cells.fir пропустите source-стадию:
результат 42 после шести итераций. real-cells.fir даёт +0/-0: четыре слова равны
0, -9223372036854775808, 1, 1. SWF trace — отображение; точные биты проверяются Dis.

Приёмка охватывает CLI/C99 API, сырые/оптимизированные программы, матрицы числа
итераций, joins, вложенные циклы, shadowing, ранний return, строгие отказы и
сохранность прежнего output. Scalar/hosted GC проверяют int minimum, -0 и NaN;
позиции операторов проверены после Unicode-префикса. Перенесённые SDK заново
линкуют C99-клиент, сравнивают Dis с CLI и запускают real-цикл в interpreter/JIT.
Полные языки, AS3 ABC, общий Dis linker/calls, self-hosted IDE и панели
Build/Run/Debug остаются дальнейшей работой.
