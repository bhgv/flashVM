# Конструкторы гибридных таблиц — компилятор 0.31

[English](TABLE_LITERALS.md) · [Комментированный пример](../examples/tables/constructors.b) ·
[README примеров](../examples/tables/README.ru.md) · [Таблицы](TABLES.ru.md) ·
[Изменения](TABLE_MUTATION.ru.md) · [Строки и ключи](TEXT_VALUES.ru.md)

Coco/R big/table-профиль Limbo принимает необязательный инициализатор после
прежнего выражения выделения таблицы:

```limbo
settings := table of big {
    40, 2,
    font_size = 11,
    ["gutter-width"] = 4,
    [4] = 99,
};
```

`table of big` и `table of big {}` создают пустого владельца. Конструктор —
выражение, поэтому допускает последующую индексацию/срез и использование внутри
других выражений: `table of big {42}[0]` даёт 42. Это сахар по мотивам Lua над
нашими типизированными таблицами, а не общий Lua или полный фронтенд Limbo.

## Поля и коллизии

| Форма поля | Значение |
| --- | --- |
| `expression` | Запись по следующему позиционному числовому индексу, начиная с нуля |
| `name = expression` | Запись по скопированному строковому ключу `"name"` |
| `[key_expression] = expression` | Запись по явному big/string/ключу снимка |

Счётчик продвигают только позиционные поля. Явный числовой ключ не двигает его
и не ищет свободное место. Строковое и числовое пространства ключей различаются.
Повтор ключа разрешён; побеждает последняя выполненная запись, в том числе
коллизия явного и позиционного числового поля:

```limbo
a := table of big {[0] = 99, 42}; # a[0] равно 42.
b := table of big {42, [0] = 99}; # b[0] равно 99.
```

Все значения — big; int/bool требуют явного big-cast. Хранение вложенной таблицы,
строки или any в значении не добавляется. Вложенный конструктор можно использовать
в скалярном выражении: `len (table of big {1, 2})`. Имена полей следуют прежним
правилам ASCII-идентификаторов; пунктуацию, Unicode и ключевые слова задают через
строковый ключ в скобках. Идентификатор без присваивания остаётся позиционным
выражением, читающим обычную привязку. Инициализатор видит внешнюю затеняемую
переменную; новая локальная привязывается после успеха. Неявной ссылки на себя
и новой переменной для имени поля не создаётся.

Прежние правила сохранены: len считает непрерывный числовой префикс, countof —
все записи, keysof создаёт независимый снимок ключей, алиасы разделяют владельца,
числовые срезы копируются. Явные числовые ключи неотрицательны; строка с отрицательным
числом остаётся обычным текстовым ключом.

## Порядок и ошибки

Сначала выделяется владелец, затем поля выполняются один раз в порядке исходника.
Для каждого поля ключ вычисляется и адресуемая позиция проверяется до RHS.
Запись происходит только после успешного RHS. Как и в обычном присваивании,
`[-1] = 1/0` сначала сообщает ошибочный ключ. Уже выполненные операции владельцев
и внешние эффекты RHS не откатываются при более поздней ошибке; это не удалённая
атомарная транзакция канала.

После непустого списка допускается одна завершающая запятая. Пустые/повторные
поля, пропущенные разделители, присваивание/значение, неверные типы ключей и
не-big значения отвергаются. Вокруг присваивания и завершающей запятой допустимы
комментарии. Плоский список разбирается итеративно; вложенность использует прежний
лимит 64 уровней выражений, а лимиты байтов, имён и SSA сохранены. Ошибка исходника
не заменяет прежние FIR/debug файлы. Запись хранит точную позицию имени ключа,
открывающей скобки либо первого токена позиционного выражения в JSON отладки.

## FIR, runtime и C99-сервисы

Основная грамматика — src1.atg. Непотребляющие лексические предикаты различают
`name =` и обычное выражение с идентификатором, `=` и `==`, разделитель и одну
завершающую запятую после комментариев. Выражения разбирает Coco/R. Сгенерированные
файлы остаются только в каталогах сборки.

Понижение использует прежние table.new, точные const.i64/string, table.index и
table.store. Помощник позиционного индекса создаёт новую big-константу, не читая
устаревший текст токена. Новых ID операций/типов FIR, opcode Dis, ABI помощников
или представлений контейнеров нет. Прежние эффекты сохраняют проверки ключа,
ошибки RHS и записи при оптимизации. Интерпретатор и JIT используют готовые
сервисы таблиц и корни кадра.

C99-проверка многократно компилирует в одном процессе корректные конструкторы,
синтаксические ошибки и превышения SSA-лимита, затем проверяет восстановление
через разбор FIR, верификацию и Dis. Потоки и debug принадлежат вызывающему;
результаты сначала формируются во временных потоках. Вызовы парсера требуют внешней сериализации. Приёмка SDK
заново линкует source/FIR-клиенты и выполняет пример до/после оптимизации в обоих
режимах VM. Расширение языка остаётся только в FlashVM.

Живые операции таблиц пока не поддержаны SWF-бэкендом; при отказе старый выход
сохранён. Однородный int-профиль и AS-профили не меняются. Общие функции/циклы,
any-значения таблиц, полноценное подключение отладчика и панели IDE
Build/Run/Debug остаются отдельной работой.

## Запуск

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/constructors.b build/constructors.fir -g build/constructors.json
build/fir/fir1 check build/constructors.fir
build/fir/fir1 opt build/constructors.fir build/constructors-opt.fir
build/fir/fir1 dis build/constructors-opt.fir build/constructors.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/constructors.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/constructors.dis
```

Ожидаемые значения trace: 42, 0; флаги: 1, 0. Пример проверяет шесть гибридных
ключей, числовой префикс из двух элементов, независимый срез и неизменность полей
настроек после изменения через алиас. Доступность JIT AMD64/ARM64 сохраняет
166 быстрых путей и 173 полных decoded-входа; нового быстрого пути здесь нет.
