# Обход значений с одним именем — компилятор 0.47

[English](VALUE_ITERATION.md) · [Комментированный пример](../examples/tables/value-iteration.b) ·
[Парный обход](LOOPS.ru.md) · [Типизированный обход](TYPED_LOOPS.ru.md)

Coco/R-фронтенд профиля Limbo big/table теперь принимает `for (value in collection)`.
Единственное имя получает **значение**, а не ключ. Прежний вариант
`for (key, value in collection)` сохраняется. Это расширение профиля Limbo,
а не изменение смысла for-in в ActionScript.

| Получатель | Тип и значение единственной переменной |
| --- | --- |
| `table of big` | Копия big-значения по текущему захваченному ключу |
| `string` | Unicode-руна типа `int`, не байт UTF-8 |
| `keysof table` / снимок ключей | Ключ снимка, пригодный для `table[key]` |

```limbo
total := big 0;
for (amount in table of big {first=20, second=22}) {
    total += amount;
}
return total;
```

Для обхода ключей они запрашиваются явно: `for (key in keysof entries)`.
Произвольные массивы и tuple этим ещё не включены в профиль big/table.
Неподдерживаемые получатели отвергаются до публикации FIR.

## Захват, области имён и управление

Получатель один раз вычисляется во внешнем окружении. Только после этого имя
связывается в области тела. Поэтому `for (entries in entries)` захватывает внешнюю
таблицу и затеняет её имя big-значением внутри тела. После цикла внешнее имя
восстанавливается. Новое имя обхода нельзя читать после цикла; присваивание
скопированной переменной не меняет элемент таблицы.

Для таблицы захватывается независимый снимок ключей, но значения читаются живыми.
Добавленные в теле ключи не обходятся; изменение ещё не прочитанного значения
будет видно. Удаление ещё не прочитанного ключа сохраняет прежнюю проверяемую
ошибку отсутствующего ключа. Переназначение исходной таблицы/строки/снимка не
перенаправляет захваченного получателя. Строки и ключи сохраняют неизменяемый снимок.

Break, continue, ранний return, вложенные циклы, доказательства инициализации и
типизированные аренды присваивания используют прежнее понижение обхода.
Сокращённая форма не создаёт скрытого исходного имени ключа. Внутренние SSA-курсор
и ключ остаются там, где нужны для чтения, но не получают выдуманной пользовательской
переменной и debug-объявления. Значение сохраняет точный токен заголовка и область тела.

Оба заголовка разбирает Coco/R. Прежний непотребляющий lookahead теперь распознаёт
запятую либо целое ключевое слово `in` после имени, пропуская комментарии и пробелы.
Проверка границы идентификатора не принимает `inbox`, `in_foo` и `in1` за `in`.
Разбор обычного for не меняется; отдельного самописного парсера нет.

## FIR, владение и API

Обе формы используют прежние типизированные FIR-курсор, захваченного получателя
и загрузки значений. Новых операций FIR/Dis, публичных API и нативного ABI нет.
Корни получателя и снимка сохраняются при сборке после каждой инструкции;
оптимизатор удерживает эффекты памяти, границ и владения. Инициализация после
потенциально пустого цикла остаётся консервативной.

Последовательный C99-сервис и CLI используют общий сгенерированный парсер.
Ошибочный заголовок сохраняет прежние FIR/debug-файлы; C99-регрессия чередует
успешные сокращённые обходы с ошибками заголовков. Полные модули обычного Limbo
по-прежнему собираются отдельным удерживаемым bootstrap. Произвольные определения
модулей и автоматические значения `any` в Coco/R-профиль этим не добавлены.

## Запуск

Из корня репозитория после сборки:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/value-iteration.b values.fir -g values.json
build/fir/fir1 opt values.fir values.opt.fir
build/fir/fir1_table_run values.opt.fir
build/fir/fir1 dis values.opt.fir values.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 2 values.dis
build/runtime/disvm --no-jit --quantum 2048 --stats --inspect-words 0 2 values.dis
```

Пример возвращает 42; нативные захваты — `DATA 0 42`, `DATA 8 1`.
`fir1_value_iteration` и два runtime-варианта проверяют все получатели, пустые входы,
затенение, захват, живые изменения таблицы, вложенные/парные/обычные циклы,
переходы, комментарии и ошибочные/неоднозначные заголовки. Проверяются исходные
позиции и исполнение до/после оптимизации с обоими квантами и нулевым числом живых
владельцев таблиц/ключей. Оба установленных SDK компилируют и запускают пример
через заново скомпонованные C99-клиенты и перенесённые CLI-инструменты.
