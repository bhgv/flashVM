# Отрицательные индексы и срезы-копии — компилятор 0.32

Отрицательный индекс отсчитывается с конца: -1 — последний элемент, -2 —
предпоследний. Для гибридной таблицы берётся **только непрерывный числовой префикс
с нуля**. Строковые ключи и разреженные числовые записи не учитываются. У строки
считаются Unicode-скаляры, а не байты, единицы UTF-16 или графемы.

| Выражение при длине n | Смысл |
| --- | --- |
| `s[-1]` | элемент n-1 |
| `s[-n]` | элемент 0 |
| `s[0:-1]` | полная копия |
| `s[-2:-1]` | последние два элемента |
| `s[0:-2]` | всё, кроме последнего |
| `s[-1:-1]` | последний элемент как последовательность из одного элемента |

Положительная правая граница остаётся исключающей. **Отрицательная правая граница
включает указанный элемент**, чтобы `[0:-1]` был полной копией. Для пустой
последовательности `[0:-1]` допустим, а индекс -1 — нет. Выход за границы и обратный
нормализованный диапазон вызывают ошибку; автоматического обрезания нет.
INT64_MIN нормализуется через unsigned-модуль без переполнения знакового отрицания.

## Таблицы, FIR и фиксация записи

Отрицательные числовые позиции поддерживают чтение, запись, membership и delete.
Ключ фиксируется один раз на table.index **до RHS**. Изменение префикса внутри
RHS не перенаправляет уже захваченное составное присваивание:

```limbo
t := table of big {1, 2, 40};
t[-1] += big (delete t[0]); # Цель — индекс 2, хотя len становится 0.
```

Снимок хранит канонические неотрицательные ключи. Строка `"-1"` остаётся обычным
ключом словаря. Срез таблицы копирует и переиндексирует только числовой префикс.
Алиасы источника разделяют владельца, срез независим. Запись по -1 в пустую
таблицу вызывает ошибку, а не создаёт новый последний элемент.

C99-ядро предоставляет fht_resolve и fht_slice_relative. Прежняя unsigned-функция
fht_slice сохраняет положительный полуоткрытый API; get/set/delete принимают
отрицательные числовые ключи. В Bigtable дописан resolveindex, прежние экспорты
и сигнатуры сохранены. Прямой FIR table.index фиксирует позицию так же, как
исходный код. Проверка относительного диапазона зависит от длины получателя
и выполняется при применении. Границы строк в Coco/R-профиле остаются int.

## Массивы и строки Dis

Подготовленные хостом C-обработчики нормализуют индексы массивов/строк, запись
символа, границы срезов и смещение присваивания среза массива. Снимок Inferno
сохранён побайтно. Нативные guards отклоняют отрицательные операнды в эти
обработчики; полный JIT-dispatch сохраняет тот же fallback. Нового opcode нет.

**Срез Dis-массива с хотя бы одной отрицательной границей имеет независимое
хранилище элементов.** Сейчас сначала вызывается прежний GC-aware arraycpy,
затем сужается независимый владелец; частичная копия может выделить память для
всего источника. Поля mapped-записей удерживаются, а ref-объекты ADT сохраняют
идентичность. Положительные срезы Dis-массивов пока сохраняют прежнюю семантику
общего view. Строковые значения используют прежнюю copy-on-write семантику.

Нативный пример проверяет byte/int/big/real, mapped-записи, ссылки, отрицательную
запись, присваивание среза, Unicode и пустые копии с quantum 1. Массивный пример
компилируется сохранённым опорным компилятором Limbo: общий синтаксис array ещё
не реализован в ограниченном Coco/R-фронтенде. Его table/string пути проходят
через наши source/FIR-библиотеки и SDK. Семантика AS Array.slice и свойств здесь
не меняется: это расширение Dis/Limbo.

## Владение и многопоточность

Текущий хост Dis выполняет целую C-операцию одним владельцем VM, без переключения
Dis-процессов внутри копирования. C99-ядро требует внешней сериализации.
**Универсальный повторно входимый mutex записи на объекте пока не реализован.**
Mutex метаданных брокера не защищает содержимое. Отдельный связанный контракт
описывает токен владельца для длинных операций и будущего разделения по потокам.

## Запуск

```sh
build/fir/fir1_source limbo --input fir/v1/examples/tables/relative.b build/relative.fir
build/fir/fir1 opt build/relative.fir build/relative-opt.fir
build/fir/fir1 dis build/relative-opt.fir build/relative.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/relative.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/relative.dis
build/runtime/disvm --jit --quantum 1 build/runtime/relative-test.dis
```

Ожидаемые значения source-примера: 42,0; флаги: 1,0. Нативный модуль печатает PASS
после проверок владения. Ошибочные границы проверяются отдельными процессами
в обоих режимах, включая минимальный знаковый WORD, полученный во время исполнения.
