# Исполняемые while и for-in по таблицам — компилятор FIR 0.36

[English](LOOPS.md) · [Комментированный пример](../examples/tables/loops.b) ·
[Удержание таблиц](TABLE_LEASES.ru.md) · [Баланс владения](OWNERSHIP_FLOW.ru.md)

Наш Coco/R-профиль Limbo с результатом big теперь принимает циклы перед итоговым
return или терминальным ветвлением. CLI и C99 API для IDE используют одну грамматику.

```limbo
i := big 0;
sum := big 0;
while (i < 7) {
    sum += i;
    i += 1;
}

for (key, value in entries) {
    sum += value;
    entries[key] = value * 2;
}
```

Условие while вычисляется перед каждой итерацией, включая первую. Ноль итераций
сохраняет прежние значения. Инициализированные внешние big-локальные переводятся
в приватные ячейки кадра до начала теста. Чтения и присваивания используют текущие
значения ячеек: счётчики и накопители переживают обратные переходы и следующие
циклы. Вложенные циклы поддерживаются. Локальные объявления тела имеют отдельную
область видимости и не выходят наружу. До первого цикла сохраняется прежний SSA.

Условия используют типизированные сравнения, membership и ленивые &&/||.
Тело содержит объявления, присваивания, delete и вложенные while/for-in.
Компилятор 0.37 добавляет [if/else, break/continue и return](LOOP_CONTROL.ru.md).
Компилятор 0.38 добавляет [трёхчастный for и постфиксные обновления](COUNTED_FOR.ru.md).
В 0.39 добавлены [ячейки int/bool и обход строк/снимков](TYPED_LOOPS.ru.md).
В 0.40 добавлены [удерживаемые ссылочные ячейки](RETAINED_LOOPS.ru.md). Можно
как менять элементы таблицы, так и переназначать инициализированную ссылку.
Внешнее неинициализированное объявление не становится инициализированным только
из-за присваивания в теле: цикл может не выполнить ни одной итерации. Такой
код отклоняется, а не читает несуществующее SSA-значение после выхода.

`for (key, value in expression)` один раз вычисляет таблицу и снимает независимый
снимок keysof. key имеет тип capability ключа снимка с сохранением числового или
строкового пространства; доступны прежние typeof и приведения big/string.
value — копия big, прочитанная из живой захваченной таблицы в начале итерации.
Имена должны различаться, затеняют внешние только внутри тела и не выходят за
него. Слово value теперь разрешено как локальное имя, хотя также именует функцию
учебного профиля.

Посещаются ключи снимка в его порядке. Новые ключи, добавленные телом, в этот
обход не попадают. Значения можно обновлять; текущий ключ можно удалить после
чтения его значения. Если удалить ещё не прочитанный ключ, последующее чтение
вызовет обычную ошибку missing key. Это снимок ключей, не атомарный снимок всех
значений. Таблица не удерживается на весь обход: каждое присваивание использует
своё удержание, а между операциями работает планировщик и диагностика. Пока
обходятся table of big; массивы, строки и tuple — отдельное расширение.

В FIR добавлены i64.slot и big.local/load/store. Ячейка начинается с нуля,
не копируется и не выходит через cast; это скаляр, а не указатель. Чтение и запись
имеют эффекты памяти и сохраняются оптимизатором. NC64 использует обычные ячейки
кадра, MOVL и переходы Dis. Новых opcode Dis и форматов файла нет; прежние enum-ID
FIR сохранены. Явный API fir_acyclic по-прежнему проверяет DAG для нуждающихся в
этом клиентов; backend таблиц и исполнитель больше не требуют ацикличности.

Эталонный исполнитель ограничен миллионом инструкций. Поскольку он удерживает
выделения до конца вызова вместо GC, реестры таблиц, ключей и текстов ограничены
FIR_LIMIT каждый. При ошибке владельцы освобождаются, staged trace не публикуется.
В DisVM используются настоящий GC, планировщик и --max-instructions. Оба режима
проверяются с quantum 1/2048, включая сборку мусора на обратных переходах.

Команды сборки приведены в English-версии. Пример заполняет таблицу while-циклом,
затем суммирует и удваивает значения через for-in. Эталон печатает 42. В VM:
DATA 0 42, DATA 8 0, DATA 16 1, DATA 24 0; последняя пара отмечает выбранную ветвь.
Итоговые счётчики таблиц/ключей нулевые. SDK заново собирает C99-клиента и запускает
тот же исходник. Расширение языка остаётся в FlashVM и не переносится в Inferno.


Компилятор 0.40 добавляет удерживаемые ячейки инициализированных строк/таблиц/снимков/ключей. [Guide / Руководство](RETAINED_LOOPS.ru.md).
