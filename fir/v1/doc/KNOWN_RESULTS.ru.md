# Полностью известные целочисленные результаты — FIR 0.65

[English](KNOWN_RESULTS.md) · [Оптимизатор](../optimiser/peephole.c) ·
[Битовый анализ](../optimiser/integer_facts.c) · [Комментированный пример](../examples/dis/known-results.b) ·
[Матрица проверок](../tests/integer_known_results.py) · [Основы анализа](SHIFT_FACTS.ru.md)

Peephole заменяет битовую операцию int32 или big на литерал, когда известные
нулевые и единичные биты покрывают весь результат. Операнды могут оставаться
динамическими. Допущены AND, OR, XOR, big.not и проверяемые сдвиги, для которых
анализ полностью определяет успешный результат.

| Динамическое выражение | Точный результат |
| --- | --- |
| `(x & MAX) >> (width-1)` | 0 |
| `(x \| MIN) >> (width-1)` | -1 |
| `(x \| 1) << (width-1)` | MIN |
| `(x & -2) << (width-1)` | 0 |
| `((x \| 1) << (width-1)) ^ -1` | MAX |
| `((x \| 1) << (width-1)) \| 123` | MIN+123 |

Ширина равна32 или64. Правый сдвиг арифметический, левый сохраняет wraparound.
Это не правило для float или динамического AS. Неизвестные биты не считаются
нулями. При неизвестном/недопустимом счётчике сдвига сведения не выводятся,
даже для нулевого левого операнда: проверка счётчика остаётся.

Внутренний helper создания литерала принимает int64_t: новый полноширинный
путь не обрезает big MIN/MAX или MIN+123 через host int. Преобразование payload
использует прежние беззнаковые helpers; int32 сужается только из доказанного
signed32. Тип, SSA identity, блок и исходная строка сохраняются.

Анализ выполняется после локальной пересылки ячеек, перед материализацией.
Эквивалентные преобразования сохраняют доказательства успешных SSA-значений;
после CFG перед DCE анализ строится вновь. Удаляются операнды только самой
заменяемой операции. Ошибка производителя — деление на ноль, преобразование
или другой эффект — остаётся наблюдаемой. Таблица effects, барьеры памяти,
CSE, GC, владение и проверяемые канальные границы не ослаблены.

CLI, fir_run/fir_object и Dis-owned модуль компиляции IDE используют один код
при запрошенной оптимизации. Raw lowering сохраняет вычисления. Грамматики
Coco/R, FIR-инструкции, SWO/SWA/SWF и активный NC64 ABI не изменены; новый
Dis64 runtime и big SWF этим не включаются.

[Команды](KNOWN_RESULTS.md#source-and-target-commands) используют наш собственный
Coco/R frontend. Пример проходит восемь значений: очищенный знак после shift31
даёт0, установленный — -1; каждая итерация прибавляет1; добавление34 даёт **42**.
Работают raw/opt Dis/SWF и перелинкованные C99 SDK клиенты. Debug sidecars
сохраняют исходные spans; отладка native PC этим не добавляется.

Матрица проверяет192 исходных/оптимизированных результата: шесть форм, восемь
входов, обе ширины; MIN/MAX, знак и межблочные загрузки. Проверяются точные
литералы, отсутствие свёрнутых операторов, неподвижная точка, сохранение ошибок
производителей и проверок счётчиков. Реальный SWF требует переданных runner/SWL,
Dis — пути runtime с проверкой dispatch counters, capture flags и teardown.
Одни compiler-only проверки не доказывают исполнение нового ABI.
