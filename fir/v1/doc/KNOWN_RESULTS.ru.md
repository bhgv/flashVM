# Полностью известные целочисленные результаты — FIR 0.67

[English](KNOWN_RESULTS.md) · [Оптимизатор](../optimiser/peephole.c) ·
[Битовый анализ](../optimiser/integer_facts.c) · [Комментированный пример](../examples/dis/known-results.b) ·
[Матрица проверок](../tests/integer_known_results.py) · [Основы анализа](SHIFT_FACTS.ru.md)

Peephole заменяет битовую операцию int32 или big на литерал, когда известные
нулевые и единичные биты покрывают весь результат. Операнды могут оставаться
динамическими. Допущены AND, OR, XOR, big.not и проверяемые сдвиги, для которых
анализ полностью определяет успешный результат.

| Динамическое выражение | Точный результат |
| --- | --- |
| `(x & MAX) >> (width-1)` | 0 |
| `(x \| MIN) >> (width-1)` | -1 |
| `(x \| 1) << (width-1)` | MIN |
| `(x & -2) << (width-1)` | 0 |
| `((x \| 1) << (width-1)) ^ -1` | MAX |
| `((x \| 1) << (width-1)) \| 123` | MIN+123 |

Ширина равна32 или64. Правый сдвиг арифметический, левый сохраняет wraparound.
Это не правило для float или динамического AS. Неизвестные биты не считаются
нулями. При неизвестном/недопустимом счётчике сдвига сведения не выводятся,
даже для нулевого левого операнда: проверка счётчика остаётся.

Внутренний helper создания литерала принимает int64_t: новый полноширинный
путь не обрезает big MIN/MAX или MIN+123 через host int. Преобразование payload
использует прежние беззнаковые helpers; int32 сужается только из доказанного
signed32. Тип, SSA identity, блок и исходная строка сохраняются.

Анализ выполняется после локальной пересылки ячеек, перед материализацией.
Эквивалентные преобразования сохраняют доказательства успешных SSA-значений;
после CFG перед DCE анализ строится вновь. Удаляются операнды только самой
заменяемой операции. Ошибка производителя — деление на ноль, преобразование
или другой эффект — остаётся наблюдаемой. Таблица effects, барьеры памяти,
CSE, GC, владение и проверяемые канальные границы не ослаблены.

CLI, fir_run/fir_object и Dis-owned модуль компиляции IDE используют один код
при запрошенной оптимизации. Raw lowering сохраняет вычисления. Грамматики
Coco/R, FIR-инструкции, SWO/SWA/SWF и активный NC64 ABI не изменены; новый
Dis64 runtime и big SWF этим не включаются.

[Команды](KNOWN_RESULTS.md#source-and-target-commands) используют наш собственный
Coco/R frontend. Пример проходит восемь значений: очищенный знак после shift31
даёт0, установленный — -1; каждая итерация прибавляет1; добавление34 даёт **42**.
Работают raw/opt Dis/SWF и перелинкованные C99 SDK клиенты. Debug sidecars
сохраняют исходные spans; отладка native PC этим не добавляется.

Матрица проверяет384 исходных/оптимизированных результата:12 форм, восемь
входов, обе ширины; MIN/MAX, знак и межблочные загрузки. Проверяются точные
литералы, отсутствие свёрнутых операторов, неподвижная точка, сохранение ошибок
производителей и проверок счётчиков. Реальный SWF требует переданных runner/SWL,
Dis — пути runtime с проверкой dispatch counters, capture flags и teardown.
Одни compiler-only проверки не доказывают исполнение нового ABI.


## Переносы и заёмы FIR0.66

Анализ проходит32 или64 бита от младшего к старшему. Сложение начинается с
нулевого переноса. Вычитание вычисляется как `a + ~b + 1`: маски нулей и единиц
второго операнда меняются местами, начальный перенос равен единице. Бит суммы
известен, только если известны все три входных бита. Два известных нуля
гарантируют нулевой следующий перенос, две единицы — единичный. В остальных
случаях перенос неизвестен. Последний перенос отбрасывается, как требует
модульная арифметика FIR. Знаковое переполнение C не используется.

Корреляции между неизвестными битами не предполагаются. Анализ не доказывает
`x-x` через равенство неизвестных: для таких случаев есть отдельные правила
тождеств. Сложность одного переноса фактов ограничена шириной слова внутри
существующих монотонных проходов. Форматы, C99 API и владение не меняются.

| Динамическое выражение | Точный результат |
| --- | --- |
| `((x & -8) + 5) & 7` | 5 |
| `((x \| 7) + 1) & 7` | 0 |
| `((x & -8) - 1) & 7` | 7 |
| `((x \| 7) - 5) & 7` | 2 |
| `((x & -8) + (y & -8)) & 7` | 0 |

Те же факты используются в сыром SWF backend без предварительного opt.
Счётчик `(x & 15) + 16` допустим для int32-сдвига:16…31. Выражение
`(x & 31) + 32` даёт32…63 и отклоняется. У делителя `(x & -8) + 1`
младший бит всегда единичный, в том числе при отрицательных значениях и
переполнении. `(x & 7) - 1` может равняться нулю, поэтому не принимается.
Удаление внешней операции сохраняет ошибки вычисления её операндов.

Пример known-results.b дополнен переносом через три единицы и заёмом через
три нуля; результат остаётся42. Матрица расширена до384 raw/opt результатов
из12 форм, восьми входов и двух ширин. C99 fixture проверяет204800 случаев
масок/сдвигов и192512 дополнительных случаев сложения/вычитания по каждой
границе младших битов32/64. Проверяются непересекающиеся маски, сохранение
доказанных нулей и соответствие независимому беззнаковому вычислению.
CLI, C99 SDK и Dis-владелец компиляции IDE используют общий оптимизатор.

Независимый исчерпывающий oracle дополнительно перебирает81×81 пар
четырёхбитных троичных доменов и256 конкретных пар входов для каждой,
при обеих ширинах и двух операциях: **6 718 464 вычисления**. Сравниваются
точные пересечения нулей и единиц, включая знаковые биты вычитания и перенос
за пределы четырёхбитного домена. Oracle не повторяет алгоритм переносов.

FIR0.67 переносит известные биты через big.neg как беззнаковое модульное
вычитание из нуля. Сохраняются младшие биты и доказательство ненулевого
результата, включая MIN; ошибки операндов не исчезают.
[Полностью комментированный пример](../examples/dis/big-neg-facts.b) берёт
значение из typed table, делает его нечётным, меняет знак и возвращает42.
Добавлены10240 C99 проверок отрицания; target matrix теперь содержит384
raw/opt результата и исполняет этот собственный исходник через Dis.
