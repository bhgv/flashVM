# Операторы и области функции — компилятор 0.41

[English](FUNCTION_FLOW.md) · [Комментированный пример](../examples/tables/function-flow.b) ·
[Удерживаемые переменные](RETAINED_LOOPS.ru.md) · [Переходы циклов](LOOP_CONTROL.ru.md) ·
[Библиотека C99](../compiler/API.ru.md)

Профиль Limbo big/table с парсером Coco/R теперь использует одну грамматику
операторов на уровне функции, блока и цикла. Обычный `if` может менять локальные
переменные и продолжать функцию. `else` необязателен, цепочки `else if`
поддерживаются. Фигурные скобки вводят обычные лексические блоки. Return может
завершить любой путь функции; break/continue требуют охватывающий цикл.

```limbo
answer := big 40;
if (answer == 40) {
    answer += 2;
}
{
    answer := "local"; # Затеняет имя только внутри блока.
}
return answer;
```

Через объединения ветвей проходят типы локальных переменных из 0.39/0.40:
big, int, выведенный bool, string, table of big, снимки и отдельные ключи.
Присваивание сохраняет точный тип. Прежние правила затенения, удерживаемого
присваивания таблиц, неизменяемых строк, захваченного for-in, отрицательных
индексов и замены срезов сохранены.

## Пути, объединения и инициализация

Перед условием активные инициализированные переменные переводятся в приватные
типизированные ячейки. У каждой ветви собственная область и независимый снимок
идентификаторов компилятора. Только незавершённые достижимые пути направляются
в блок объединения. Когда обе ветви возвращают результат или делают переход,
лишнего объединения нет. Отсутствующий else — пустой продолжающийся ложный путь.
Break/continue адресуют внутренний цикл и через вложенные блоки/условия.

Ранее объявленная неинициализированная внешняя переменная может получить
значение на единственном продолжающемся пути, когда другая ветвь возвращает
результат. Её SSA-определение или ячейка доминирует над объединением. Первое
присваивание сохраняет исходное имя, идентификатор и область объявления,
не создавая случайного внутреннего затенения.

```limbo
answer: big;
if (failed) {
    return 0;
} else {
    answer = big 42;
}
return answer;
```

Здесь `failed` — уже инициализированный bool. Начиная с
[компилятора 0.42](JOIN_INITIALIZATION.ru.md), обе продолжающиеся ветви могут
инициализировать внешнее объявление с помощью типизированных ячеек и независимого
доказательства FIR. Частичное присваивание не разрешает позднее чтение.
Присваивание на возвращающем пути не инициализирует продолжающуюся соседнюю
ветвь. Потенциально пустой цикл также не доказывает инициализацию. Прежние
полностью терминальные деревья сохранены, включая
независимые локальные объявления и первые присваивания перед каждым return.

Каждый достижимый выход функции должен вернуть big. Один условный return без
возврата на продолжающемся пути отклоняется, даже при литеральном true в условии.
Само тело цикла не доказывает обязательный возврат. Оператор после return или
перехода на всех путях считается недостижимым. Проверка полноты возврата идёт
после закрывающей скобки функции: пропущенная скобка сохраняет синтаксическую
ошибку, а не маскируется поздней ошибкой отсутствия return. FIR и отладочные
данные до успешного окончания остаются во временных потоках.

## Пределы и свёртка констант

If сначала резервирует два блока; третий учитывается только при наличии
продолжающегося пути. Поэтому прежнее дерево из 127 решений, 128 листьев и
255 блоков принимается. Последовательность из 85 пустых сходящихся условий
вместе со входом занимает лимит 256 блоков; 86-е условие отклоняется.
Условия, блоки, группы выражений и циклы делят прежнюю глубину 64. Пределы
значений, имён и размера исходника сохранены.

Перевод неизменяемого скаляра в ячейку не должен скрывать литерал от пипхола.
Новый ограниченный проход подставляет чтение big/bool-ячейки только при одной
живой записи литерала в том же блоке, где создана ячейка. Чтение раньше записи
сохраняет начальный ноль. Доминирование ячейки гарантирует запись до чтений
в других блоках; литерал не меняется при повторном использовании SSA-слота циклом.

Несколько записей, запись из другого блока, нелитеральное значение и загрузки
ссылочных ячеек не подставляются. Проверка FIR идёт до и после оптимизации.
Независимые фикстуры проверяют начальный ноль, чтение после записи, изменяемые
и условные записи, нормализацию bool. Прежние матрицы знаковых сравнений и
полного терминального дерева продолжают проверять свёртку условий и ветвей.

## Владение, метаданные и цели

Используются существующие операции FIR/Dis. Снимки окружения содержат только
идентификаторы компилятора. Владельцы значений проходят объединения через
прежние помеченные ячейки кадра и удерживающий MOVP. Сигнатуры API C99 и формат
JSON отладки не меняются; оба парсера по-прежнему генерирует Coco/R.

Скобочные области сохраняют точные байтовые позиции и уникальные идентификаторы.
Общая область инициализатора/тела трёхчастного for привязана к ключевому слову
`for`. Условие сохраняет позицию `if`. Неинициализированное объявление теперь
имеет событие `declare` со значением `value=-1`; последующее присваивание сохраняет
тот же binding ID. Глобальные данные парсера обслуживают последовательные
запросы. Тест API чередует корректный поток с ошибками заголовка и объединения.

Неиспользуемые локальные строки профиля Limbo tables теперь корректно выбирают
hosted backend Dis и до удаления мёртвого кода. Отказы числового профиля для
неподдерживаемых строковых/динамических операций сохранены. Новых инструкций
Dis, ABI импортов, формата SWF и общего frontend Limbo/AS нет. Числовой профиль
Limbo int/real сохраняет документированную грамматику терминальных решений.

## Сборка и запуск

Из корня репозитория после сборки:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/function-flow.b flow.fir -g flow.json
build/fir/fir1 opt flow.fir flow.opt.fir
build/fir/fir1_table_run flow.opt.fir
build/fir/fir1 dis flow.opt.fir flow.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 10 flow.dis
build/runtime/disvm --no-jit --quantum 2048 --stats --inspect-words 0 10 flow.dis
```

Эталон печатает 42. В примере пять мест return: ровно одна ячейка результата
содержит 42 с установленным флагом; остальные значения/флаги равны нулю.
Счётчики владельцев таблиц/ключей в конце нулевые. Приёмка установленных SDK
отдельно считает места результата до/после оптимизации и проверяет каждое
значение, флаг и владельцев, включая прямой библиотечный компилятор исходника.

Тесты `fir1_function_flow` и `disvm_function_flow_{jit,interpreter}` покрывают
оба состояния FIR, два кванта, ранние возвраты, необязательный else и цепочки,
поддерживаемые типы переменных, единственный продолжающийся путь, вложенность,
области переходов, точные отладочные позиции и отказ при пропущенных return,
выходе локальных имён, несовместимых типах, сходящейся первой инициализации и
превышении глубины/числа блоков. Расширение остаётся в FlashVM и не переносится
в Inferno.
