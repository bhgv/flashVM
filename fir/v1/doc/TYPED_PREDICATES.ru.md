# Типизированные условия — FIR 0.53 / CLI исходников 0.20

[English](TYPED_PREDICATES.md) · [Построчно прокомментированный Limbo](../examples/dis/typed-predicates.b) · [Построчно прокомментированный FIR](../examples/dis/booleans.fir) · [Синтаксис сравнений](COMPARISON_VALUES.ru.md) · [Короткие логические операции](SHORT_CIRCUIT.ru.md) · [Покрытие](COVERAGE.ru.md)

В профиле Limbo с big и таблицами внутренний bool остаётся отдельным типом. Все шесть отношений между однотипными int теперь используют i32.eq или i32.lt.signed напрямую. Для > и <= переставляются уже вычисленные операнды; обратное отношение получается через bool.not. Расширение int в big для сравнения больше не нужно. Операнды вычисляются слева направо, каждый один раз. Сравнения big сохраняют полную ширину, строки сравниваются по содержимому; инверсия их результата тоже использует bool.not.

В конец списка операций FIR добавлены два номера:

| Операция | Аргументы | Результат | Эффекты |
| --- | --- | --- | --- |
| bool.not | bool | bool | нет |
| bool.eq | bool, bool | bool | нет |

Bool нормализован к 0/1. Неявное преобразование int, big, real, string или any здесь недопустимо. Упорядочивание bool и неявная «истинность» чисел остаются ошибками. Новое ключевое слово для объявления bool не вводится: тип выводится из сравнений и существующих операций владельцев. `big flag` явно преобразует значение. Парсеры по-прежнему генерируются из грамматик Coco/R.

Verifier проверяет число аргументов, доминирование определений, точные типы и нормализацию констант до записи результата. Неизвестная будущая операция сохраняет консервативные эффекты. Оптимизатор сворачивает константы, убирает двойное отрицание, упрощает равенство с true/false и самим собой, переиспользует одинаковые чистые операции внутри блока. Неиспользуемое условие можно удалить, но ошибка проверяемого преобразования и эффекты получения операндов сохраняются. Чтение и сравнение не становятся атомарной операцией для потоков и каналов.

Оба Dis-бэкенда используют существующий XORW с единицей для bool.not и BEQW с материализацией результата для bool.eq. Прямые сравнения int используют BLTW/BEQW над нормализованным signed32, в том числе на NC64. Новых Dis-opcode, изменений карты GC, ABI модулей и общих указателей между кучами нет. Логические ячейки и ленивые &&/|| продолжают работать.

Объектный бэкенд выдаёт стандартные AVM1 Not (0x12) и Equals2 (0x49). SWL 0.3.13 проверяет Not и сохраняет байты действий. Скалярный FIR проходит обычный путь FIR → SWO → линкер → SWF. Исходный пример с таблицей предназначен для Dis. Динамические преобразования AS и полная реализация AS этим не заявляются.

## Запуск и проверка

Из корня репозитория после сборки согласованных инструментов:

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/dis/typed-predicates.b build/predicates.fir -g build/predicates.json
build/fir/fir1 opt build/predicates.fir build/predicates.opt.fir
build/fir/fir1 dis build/predicates.fir build/predicates.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 2 build/predicates.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 2 build/predicates.dis
build/fir/fir1 object fir/v1/examples/dis/booleans.fir build/booleans.swo
build/swf-linker/swl link build/booleans.swf build/booleans.swo
```

Limbo-пример возвращает 42 и флаг выполнения 1. Повторите генерацию Dis и запуск для predicates.opt.fir. Локальная таблица должна освобождаться: в статистике tables_live=0 и keys_live=0. В исходном FIR видны прямые сравнения int, bool.not и bool.eq; в оптимизированном исчезает двойное отрицание. Скалярный FIR выводит true: хост trace может показать true или 1. Проверяйте вывод исполняющего SWF-хоста, а не только открытие окна.

Каждая непустая строка обоих примеров прокомментирована. Проверка установленного SDK компилирует Limbo через CLI и заново слинкованные C99-библиотеки, сравнивает байты Dis, запускает исходный и оптимизированный код в интерпретаторе и JIT. API исходного компилятора блокирующий и требует сериализации: IDE должна вызывать его в рабочем потоке сборки и передавать скопированные результаты по служебному каналу.

Проверяются 216 сравнений загруженных signed32, таблицы истинности bool, вложенные и ленивые условия, расположение слотов после свёртки ветвей, алгебраические упрощения, ошибки операндов, недопустимые типы и точные позиции операторов после UTF-8. Счётчики подтверждают JIT на текущем хосте; аппаратная проверка ARM64 и полнота компилятора/IDE остаются отдельными задачами.
