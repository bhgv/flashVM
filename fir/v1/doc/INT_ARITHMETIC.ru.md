# Точная int-арифметика и Unicode-границы — компилятор 0.27

[English](INT_ARITHMETIC.md) · [Комментированный пример](../examples/tables/int-arithmetic.b) ·
[Строки](UNICODE_STRINGS.ru.md) · [Составные операторы](COMPOUND_UPDATES.ru.md)

Coco/R big/table-профиль принимает однотипные int `+`, `-`, `*`, `/`, `%` и
унарные `+`/`-`. Литералы по умолчанию остаются big: пишите `index + int 1`,
а не `index + 1`. Смешение int/big отвергается. Значения таблиц остаются big:
перед записью нужен явный cast. Составные `+=`, `-=`, `*=`, `/=`, `%=` принимают
int RHS для int-локальной. В версии 0.28 поддержаны побитовые int; с версии 0.29 поддержаны проверяемые int-сдвиги;
big-версии сохранены.

Однородный `value(): int` также поддерживает знаковое деление/остаток, включая
/= и %=. Поведение деления real/AS не меняется; остаток real/AS отвергается.
Общие функции, исходные циклы, неявные преобразования и удалённая атомарность
не добавляются.

```limbo
length: int = len text;
first := length % int 2;
width := length / int 2;
end := first + width;
digits := text[first:end];
return big digits;
```

## Семантика и lowering

Каждый результат, включая промежуточный, нормализуется как signed i32 по модулю
2^32. Деление усекает к нулю; знак остатка соответствует делимому. MIN/-1
возвращает MIN, MIN%-1 — ноль. Нулевой делитель вызывает ошибку даже при
неиспользуемом результате. Правила одинаковы до/после opt и в обоих Dis-backend.

В конец enum добавлены `i32.div.signed` и `i32.mod.signed`: i32/i32 -> i32,
обе MAY_THROW. Старые операции/ID/типы сохранены. Peephole сворачивает только
известный ненулевой делитель через int64, исключая C-overflow MIN/-1. Нулевое
деление сохраняется до исполнения, если только ветвь действительно не пропущена.
Эталонный C runner независимо исполняет те же типизированные операции.

Dis использует существующие ADDW/SUBW/MULW/DIVW/MODW. WORD в NC64 шире int32,
поэтому каждый результат нормализуется до повторного использования:
`((word & 0xffffffff) ^ 0x80000000) - 0x80000000`.
Оба backend применяют одинаковые три шага. Нормализованные операнды позволяют
безопасно выполнить int MIN/-1 в WORD64 до приведения результата. Binary64,
новые opcode/helper/теги не нужны.

SWF object backend пока отклоняет живые проверяемые int div/mod, сохраняя старый
файл; свёрнутые константы могут использовать существующее покрытие. Полное AS/SWF-
деление int и все панели IDE/отладчика остаются отдельной работой.

## Проверки и SDK

Тестируются знаковые границы и комбинации знаков по точным Python-oracle, для
однородных скалярных и загружаемых из таблицы операндов. Проверены составные int,
унарные знаки, переполнение до повторного использования, вычисляемые Unicode-
границы, eager zero, lazy skip, типы, FIR-сигнатуры и сохранение неподдерживаемого
SWF-выхода. Настоящие VM-проверки контролируют native-счётчики и флаги capture
с квантами GC/планировщика по инструкции.

Параллельно из Inferno перенесены native buffered SEND/RECV для AMD64/ARM64:
геометрию проверяет чистый C-helper, копирование и commit кольца выполняет native-
код. Блокировка/очереди/pointer payload и неподдерживаемые случаи остаются в C.
Доступность — 166/173 команд, а не полная семантическая готовность. Обратный
патч readiness запрещает появление Python bytecode при --check.

## Запуск

После сборки FIR и runtime из корня репозитория:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/int-arithmetic.b build/int.fir -g build/int.json
build/fir/fir1 opt build/int.fir build/int-opt.fir
build/fir/fir1 dis build/int.fir build/int.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/int.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/int.dis
```

Значения: `42, 0`; флаги: `1, 0`. Свежие перемещённые in-process C99 source+FIR-
клиенты проверяют исходный/оптимизированный код и оба режима VM. Аппаратное
исполнение ARM64 и загрузка всей Inferno остаются отдельными проверками.

Версия 0.29: [проверяемые int-сдвиги и составные обновления](INT_SHIFTS.ru.md).
