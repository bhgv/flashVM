# Big: деление, остаток и полная побитовая арифметика

[English](BIG_BITWISE.md) · [Полный комментированный модуль](../examples/tables/bitwise.b) ·
[Основа арифметики](BIG_ARITHMETIC.ru.md) · [Матрица расширений](EXTENSIONS.ru.md)

Наш Coco/R-профиль Limbo с big поддерживает `/`, `%`, `&`, `|`, `^`, унарный `~`.
Все операнды/результаты — big; неявных int/real/string-преобразований нет.
Приоритет соответствует опорной грамматике Limbo: сначала унарные знаки,
приведения/отражение и дополнение, затем `* / %`, `+ -`, `&`, `^`, `|`.
Бинарные уровни левоассоциативны; скобки меняют порядок явно.

## Контракт деления

Частное усекается к нулю. Остаток имеет знак делимого либо равен нулю:
-7/3 = -2, -7%3 = -1, 7%-3 = 1. Нулевой делитель вызывает `zero divide`, как
в Dis, даже у неиспользуемого выражения после оптимизации. MIN/-1 возвращает
MIN, MIN%-1 — ноль. Компилятор и эталонный C-исполнитель проверяют эти случаи
до использования C-операторов / и %; свёртка не вызывает signed overflow
или аппаратную ошибку деления на хосте.

## Побитовый контракт

AND/OR/XOR/дополнение работают со всеми 64 битами. Результат — знаковое big
с теми же битами: ~MAX = MIN, ~MIN = MAX, ~-1 = 0. Используются unsigned-биты
и переносимое знаковое толкование, без сужения до AS/int и без real.

```limbo
# Тело value(): big; полный интерфейс и комментарии приведены по ссылке выше.
values := table of big;
values.input = big -123456789012345;
a := values.input;           # Исполняемое чтение не позволяет свести всё к константам.
q := a / 97;                # Усечение к нулю.
r := a % 97;                # Знак делимого.
restored := q * 97 + r;
values[string restored] = big 42;
toggled := restored ^ big -1;
back := ~toggled;            # Восстановление полного знакового битового образа.
return values[string ((back & big -1) | 0)]; # Ровно 42.
```

## FIR, оптимизатор и Dis

Добавлены big.div/mod/and/or/xor/not без перенумерации прежних операций.
Проверяются арность, типы и доминирование. Побитовые операции чистые/полные;
деление и остаток имеют MAY_THROW и не удаляются/CSE как чистые операции.
Ненулевые константные делители сворачиваются с отдельной обработкой MIN/-1.
Нулевые остаются исполняемыми ошибками. Сохраняются порядок вычисления и ошибки
операндов; промежуточные trace при ошибке не публикуются.

NC64 использует прежние DIVL (121), MODL (122), ANDL (124), ORL (125), XORL (126).
Дополнение — XOR с обычной ячейкой модульных данных из единичных битов; это не
владелец кучи и не сетевой указатель. Арифметических helper-вызовов нет.
Защищённый JIT может оставить исключительные входы проверяемому C-пути, но оба
режима имеют одинаковые результаты/ошибки. Испытан комплект: компилятор 0.16 и runtime 0.19.

Проверяются декодированные инструкции, независимые Python-оракулы знаковой/
модульной арифметики, знаки, крайние значения, числа выше 2^53, чтения таблиц,
точные позиции операторов, неиспользуемые ошибки и GC между инструкциями до/
после оптимизации. Исходный компилятор/оптимизатор/эталон проверены с UBSan.

Сдвиги, смешанная int/big-типизация, сравнения профиля, табличные CFG/циклы,
общий any и прозрачные прокси ещё предстоят. Чтение—вычисление—запись не
становится атомарным RPC владельца. Расширение в Inferno не переносится.
