# Парные целочисленные сокращения и поглощение — FIR 0.62

[English](INTEGER_PAIRS.md) · [Пример с комментариями](../examples/dis/integer-pairs.b) ·
[Проверки](../tests/integer_pairs.py) · [Прежние тождества](INTEGER_IDENTITIES.ru.md)

Проверяемый peephole упрощает пары операций i32/big по точным целочисленным
тождествам. Не добавляются opcode, грамматика, ABI или формат backend.
CLI и библиотечные `fir_optimise`/`fir_run` используют одну реализацию.

| Выражение | Результат |
| --- | --- |
| (x+y)-y, (y+x)-y | x |
| (x-y)+y, y+(x-y) | x |
| (x XOR y) XOR y и перестановки операндов | x |
| x AND (x OR y), (x OR y) AND x | x |
| x OR (x AND y), (x AND y) OR x | x |
| x AND (x AND y), (x AND y) AND x | x AND y |
| x OR (x OR y), (x OR y) OR x | x OR y |

Сложение/вычитание выполняется по модулю 2^32 или 2^64: сокращение верно
на MIN/MAX и при переполнении. Равенство означает один immutable SSA value
либо одинаковые целочисленные литералы одной разрядности. Это не сравнение
имён, исходного текста, float или предполагаемых runtime-диапазонов.
Разные третьи операнды не сокращаются.

Чистое доминирующее определение может находиться в предыдущем блоке.
Внешний результат превращается в copy, производители не переносятся и не
вычисляются повторно. Copy propagation/DCE удаляют мёртвые чистые операции;
новые факты о памяти не вводятся. Ошибка производителя y должна сохраниться,
даже если `(x XOR y) XOR y` заменено на x. Владение, приостановки, барьеры
памяти и локальный упорядоченный CSE остаются консервативными.

Для binary64 и динамических AS coercions правила не применяются.
`(1+1e300)-1e300` даёт ноль, а не один; регрессия исполняет этот контрпример.
Source/debug sidecars сохраняют прежний контракт исходного FIR; новая карта
Dis-PC/SBL и новый протокол отладки не добавлены.

## Сборка и запуск

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/integer-pairs.b build/pairs.fir
build/fir/fir1 opt build/pairs.fir build/pairs.opt.fir
build/fir/fir1 dis build/pairs.opt.fir build/pairs.dis
build/runtime/disvm --jit --stats --inspect-words 0 2 build/pairs.dis
build/runtime/disvm --no-jit --stats --inspect-words 0 2 build/pairs.dis
build/fir/fir1 object build/pairs.opt.fir build/pairs.swo
build/linker/swl link build/pairs.swf build/pairs.swo
```

Построчно прокомментированный пример перебирает i=0…3, восстанавливает три
копии i через add/sub, двойной XOR и поглощение, суммирует18 и прибавляет24.
Исходный/оптимизированный Dis и SWF возвращают42; Dis показывает payload42
и flag1. Raw SWF уже поддерживает эти операции; оптимизация убирает
вычисления, а не вводит новый формат.

SDK содержит исходник. Существующие C99-клиенты принимают его и используют
те же библиотеки; проверка переноса пересобирает клиентов, сверяет одинаковые
CLI/API pipelines и исполняет результат. Проверка Dis-владельца компилятора IDE
также содержит эти выражения в динамическом цикле и сравнивает24 artifacts.

## Проверки

Матрица:16 форм порядка операндов ×5 граничных пар ×2 разрядности =160
случаев до/после оптимизации. Дополнительно проверяются отдельные равные
литералы, доминирование через блоки, разные третьи операнды, ошибки
производителей, IEEE-контрпример, fixed point и исходная грамматика.
Настоящий Dis проверяет captures/flags, cleanup и native/JIT counters.
Запуск SWF требует явных FIR_SWL/FIR_FLASHVM_RUNNER; тест только компилятора
не доказывает исполнение плеером.

Полный Limbo/AS3, новый исполняемый Dis64 ABI, ref-result GC/unwind и
физическое исполнение ARM64 этой оптимизацией не объявляются готовыми.
