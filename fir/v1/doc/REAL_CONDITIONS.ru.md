# Упорядоченные условия real — FIR 0.54 / CLI исходников 0.21

[English](REAL_CONDITIONS.md) · [Limbo с комментарием каждой строки](../examples/dis/real-conditions.b) · [FIR с NaN и комментариями](../examples/dis/real-unordered.fir) · [Покрытие](COVERAGE.ru.md) · [Условия int/bool](TYPED_PREDICATES.ru.md)

Однородный профиль Limbo `value(): real` теперь поддерживает завершающие решения `if (...) { ... } else { ... }`, ограниченно вложенные решения, локальные псевдонимы и переменные внутри ветвей. Каждая ветвь по-прежнему возвращает результат. Все арифметические операнды — binary64. Неявного int-преобразования, числовой «истинности», присваивания real-сравнения отдельной локальной переменной, новых циклов/слияний и общего ABI вызова модулей этот профиль не получает. Грамматика Coco/R вызывает одинаковые C99-действия для CLI и библиотеки.

| Отношение | Условие FIR |
| --- | --- |
| a == b | f64.eq a, b |
| a != b | инверсия рёбер ветвления после f64.eq |
| a < b | f64.lt a, b |
| a > b | f64.lt b, a |
| a <= b | f64.le a, b |
| a >= b | f64.le b, a |

Операнды вычисляются один раз, слева направо. Переставляются только уже полученные SSA-значения. Три номера операций добавлены в конец списка FIR. Сигнатура каждой — f64/f64 → bool; результат нормализован к 0/1, операция чистая и определена для всех binary64. Любое упорядоченное отношение ложно при NaN хотя бы с одной стороны. Равенство принимает +0/-0 и одинаковые бесконечности; неравенство при NaN истинно. Поэтому <= нельзя получать инверсией >. Payload NaN и флаги состояния FPU этот ограниченный исходный профиль не предоставляет.

Литералы FIR остаются конечными. Представимые ненулевые субнормальные значения, включая минимальный binary64, принимаются даже при ERANGE от strtod. Переполнение и значения, целиком округляющиеся в ноль, отклоняются с сохранением прежнего вывода. Политика одинакова для исходных адаптеров и FIR-reader; исправление литералов действует и для AS, не добавляя ему синтаксис условий Limbo. NaN и бесконечности могут возникнуть при исполнении, например через 0.0/0.0 или переполнение умножения.

## Бэкенды и оптимизация

Verifier проверяет точные типы, число аргументов и нормализацию результата до записи файла. Подделанные неконечные литералы C API отклоняются. Константные отношения сворачиваются по binary64-семантике; одинаковые чистые условия внутри блока переиспользуются. Неиспользуемое условие можно удалить, сохранив проверяемые эффекты получения аргументов. Произвольное real-выражение `x == x` не заменяется на true: x может быть NaN. Порядок строгой арифметики сохраняется.

Оба Dis-бэкенда используют существующие BEQF/BLTF/BLEF и материализуют bool. Сырой FIR в hosted-пути также принимает константы, арифметику и копии binary64. Это простые скалярные ячейки, а не корни GC и не ссылки для retaining-копирования. C99-эталон выполняет те же значения независимо от Dis. Ограничение trace в hosted-пути сохраняется: выводите bool-сравнение, новый ABI вывода hosted real не вводится. Новых Dis-инструкций, ABI модулей, геометрии GC и общих указателей между кучами нет.

SWO сохраняет IEEE-сравнения несмотря на существующее правило равенства пары NaN в профиле загруженного AVM1. Less2 сохраняет неопределённость как undefined. Для `<` компилятор нормализует результат двумя Not; для `<=` сравнивает обратный Less2 с false, поэтому undefined остаётся ложным. Равенство объединяет оба упорядоченных направления через Boolean And. Повторно загружаются готовые SSA-значения, исходные выражения не вычисляются заново. Динамическое равенство AS сохраняется. SWL 0.3.14 проверяет стандартный And (0x10); форматы SWO1/SWF8 не меняются.

## Запуск примеров

Из корня репозитория с согласованными инструментами:

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/dis/real-conditions.b build/real-condition.fir -g build/real-condition.json
build/fir/fir1 opt build/real-condition.fir build/real-condition.opt.fir
build/fir/fir1 dis build/real-condition.fir build/real-condition.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 4 build/real-condition.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 4 build/real-condition.dis
build/runtime/disvm --jit --inspect-reals 0 2 build/real-condition.dis
build/fir/fir1 object build/real-condition.fir build/real-condition.swo
build/swf-linker/swl link build/real-condition.swf build/real-condition.swo
```

В исходном Limbo-примере два слота результата, затем два флага выполнения. Первый real равен точно 42.5, второй неисполненный слот — ноль, флаги — 1/0. `--inspect-words` показывает биты binary64; `--inspect-reals` в отдельном запуске показывает числа. Повторите генерацию и исполнение оптимизированного FIR, считая оставшиеся trace, а не предполагая прежнее число слотов. Живой результат остаётся 42.5.

Для `real-unordered.fir` выполняйте те же FIR/Dis/object/linker-команды без компиляции исходника. Три bool-слота равны 0/0/0, затем флаги 1/1/1; используйте `--inspect-words 0 6`. SWF-хост с trace должен показать три ложных значения; текст зависит от форматирования хоста. Открытие окна само по себе исполнение не проверяет. Каждая непустая строка обоих примеров прокомментирована. Исполняемый reader и структурный фронтенд принимают отделённый // комментарий после FIR 1.0. Числовой SWF trace — текст отображения и может округлить binary64; точные биты проверяются через Dis, а результаты SWF-условий — точно как bool.

Установленный SDK заново связывает C99-клиент, сравнивает Dis из библиотеки исходников и CLI, запускает исходные/оптимизированные решения в интерпретаторе и JIT, проверяет точные биты, флаги и счётчики. API исходников блокирующий и сериализованный: IDE должна вызывать его в рабочем потоке сборки и возвращать скопированные артефакты по служебному каналу. Проверяются unordered-значения, scalar/hosted-пути, 384 конечных исходных отношения, неконечные результаты, субнормальные литералы во всех AS-адаптерах, ленивые ветви, псевдонимы, сохранение файлов при отказе и UTF-8-позиции. Счётчики подтверждают текущий хост; аппаратная ARM64 и полнота компилятора/IDE — отдельные проверки.
