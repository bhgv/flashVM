# Unicode-операции строк — компилятор 0.26

[English](UNICODE_STRINGS.md) · [Комментированный пример](../examples/tables/unicode.b) ·
[README](../examples/tables/README.ru.md) · [Ленивые выражения](SHORT_CIRCUIT.ru.md)

Coco/R Limbo big/table-профиль поддерживает длину, индексирование символов и
полуоткрытые срезы строк. Типы соответствуют строковым операциям Inferno:

| Исходник | Вход | Результат |
| --- | --- | --- |
| `len text` | string | int, число Unicode-скаляров |
| `text[index]` | string, int | int, Unicode-скаляр |
| `text[first:end]` | string, int/int | string, полуоткрытый срез |

Числовые литералы этого профиля — big: для границы используйте `int 1`, int-
локальную либо int-выражение, например `len text`. Длины таблицы/снимка остаются
big; ключи таблицы сохраняют прежние big/string/key-правила. Неявное смешение
int/big и общая int-арифметика не добавляются — нужны явные cast. Полная
поддержка строк Limbo/AS не заявляется.

## Unicode и псевдонимы

Позиции измеряются Unicode-скалярами, а не UTF-8-байтами, UTF-16-единицами или
графемами. Emoji выше U+FFFF занимает одну позицию. `e` и U+0301 — две позиции;
нормализации и сегментации графем нет. Длина пустой строки — ноль; `[int 0:int 0]`
допустим, индексирование пустой строки завершается ошибкой.

Индекс: 0 <= index < length. Срез: 0 <= first <= end <= length. Неиспользуемый
некорректный индекс/срез вызывает ошибку до и после opt. Пропущенная ленивая
операция не выполняется. Срез не меняет исходник и его псевдонимы, включая полные,
префиксные, суффиксные и пустые срезы. Срез можно индексировать, использовать как
ключ таблицы или явно преобразовать в big. Эталонный срез не требует NUL после
последнего выбранного байта.

Для прямых C99-конструкторов IR закрыт пробел проверки UTF-8: некорректные живые
строковые константы отвергаются до публикации target-байтов. Проверяются одиночные
continuation-байты, overlong, суррогаты, значения выше U+10FFFF и обрывы последовательности.
Это исправление FIR API FlashVM, а не патч интерпретатора Inferno.

## FIR и исполнение

В конец enum добавлены три операции; прежние ID сохранены:

| FIR | Типы | Эффекты |
| --- | --- | --- |
| `string.len %s` | string -> i32 | чтение памяти |
| `string.at %s, %i` | string / i32 -> i32 | чтение, возможная ошибка |
| `string.slice %s, %range` | string / big.range -> string | чтение, выделение, возможная ошибка |

Исходные int-границы точно расширяются в существующий range. Dis-backend
использует LENC (84), INDC (82), SLICEC (113); средние операнды индекса/конца
читаются из кадра. Новых opcode VM, native helper Bigtable и тегов контейнера нет.
Строковый путь пока использует hosted backend с существующим Bigtable/range-check;
зависимость от него здесь не устраняется.

Перед SLICEC исходник удерживается MOVP в отдельном GC-корне назначения, поэтому
in-place shortcut не изменяет оригинал. Исполнение идёт через существующие
guarded JIT-пути либо C fallback; --jit не означает native для каждого среза.
Корни Dis не смешиваются с кучей FlashVM. C99 runner независимо декодирует
ограниченный UTF-8 и заимствует неизменяемые байты до завершения вызова, а не
повторяет внутренний byte/Rune-формат Dis.

## Диагностика и проверки

CLI/C99 используют одну Coco/R-грамматику. События сохраняют точный len либо
открывающую скобку с учётом UTF-8-префиксов; чтение получателя сохраняет свою
идентичность привязки. Ошибки типов сохраняют прежние FIR и
sidecar. Native nil/bounds сохраняют идентичности Inferno; текст ошибки reference
может отличаться. Полный Dis SBL/отладчик и GUI-панели компилятора остаются
отдельной работой. Прежние лимиты исходника/токенов/значений сохранены.

Проверяются ASCII, латиница/кириллица, emoji, комбинируемые знаки, escape-байты,
пустые/полные/вложенные срезы, псевдонимы, преобразование эталонных срезов без NUL,
ключи снимков, eager-ошибки, ленивые пропуски, типы и подложный UTF-8 C99 IR.

## Запуск

После сборки FIR и runtime из корня репозитория:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/unicode.b build/unicode.fir -g build/unicode.json
build/fir/fir1 opt build/unicode.fir build/unicode-opt.fir
build/fir/fir1 dis build/unicode.fir build/unicode.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/unicode.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/unicode.dis
```

Значения: `42, 0`, флаги выполнения: `1, 0`. Перемещённые C99-клиенты компилируют
исходник in-process, проверяют исходный/оптимизированный FIR и обе VM.
Аппаратное исполнение ARM64 и загрузка всей Inferno этим не подтверждаются.
