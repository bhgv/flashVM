# Ссылочные переменные в циклах — компилятор 0.40

[English](RETAINED_LOOPS.md) · [Комментированный пример](../examples/tables/retained-loops.b) ·
[Скалярные переменные](TYPED_LOOPS.ru.md) · [Захваченный обход](LOOPS.ru.md)

Профиль Limbo big/table с парсером Coco/R теперь допускает переназначение
инициализированных строк, `table of big`, последовательностей ключей и отдельных
ключей снимка через обратные переходы циклов и объединения loop-if. Консольный
компилятор и библиотека C99 используют один lowering. Тип переменной сохраняется.

```limbo
current := table of big {answer=40};
original := current;
for (index := int 0; index < int 2; index++) {
    current = table of big {answer=current.answer+1};
}
# current.answer равно 42; original.answer по-прежнему равно 40.
```

Алиас захватывает значение ссылки. Переназначение исходной переменной меняет
её приватную ячейку кадра и не перенаправляет существующие алиасы. Содержимое
таблицы остаётся общим и изменяемым: запись через алиас той же таблицы видна
остальным алиасам. Строки и снимки ключей сохраняют семантику неизменяемых
значений. Прежняя удерживаемая блокировка присваивания таблицы охватывает
захват получателя/ключа, вычисление RHS и публикацию записи.

В цикле теперь работает и запись в руну или срез строки: получившаяся
неизменяемая строка записывается обратно в переменную. Сохраняются прежние
рунные границы, отрицательные индексы, изменение длины и перекрытие со своим RHS.

```limbo
text := "xy";
while (len text < int 5) {
    text[int 0:int 1] = text; # 2 → 3 → 5 рун; RHS захвачен до замены.
}
```

## Контракт приватных ячеек FIR

В конец перечислений FIR добавлены четыре типа и три операции. Числовые значения
прежних типов/операций сохранены. Парсеры FIR и исходного языка генерируются
Coco/R. Новых инструкций Dis, ABI нативных указателей, импортов модулей и формата
SWF нет.

| Тип ячейки | Точный тип значения | Представление кадра NC64 |
| --- | --- | --- |
| `string.cell` | `string` | Одно слово владельца с отметкой GC |
| `table.cell` | `table.big` | Одно слово владельца с отметкой GC |
| `keys.cell` | `keys` | Одно отмеченное слово владельца снимка |
| `key.cell` | `table.key` | Отмеченный владелец + неотмеченная скалярная позиция |

```fir
%text: string = const.string "40"
%cell: string.cell = ref.local %text
%before: string = ref.load %cell
%replacement: string = const.string "42"
ref.store %cell, %replacement
%after: string = ref.load %cell
```

`ref.local` требует инициализированное значение точного типа. `ref.load`
возвращает обычное SSA-значение с независимым удержанием владельца. `ref.store`
принимает только значение типа этой ячейки. Сами ячейки нельзя копировать,
отражать через typeof, выводить trace, пересылать или возвращать: они приватны
кадру функции. Проверка доминирования требует инициализации до использования
на всех входящих путях.

Модель эффектов отмечает создание/запись как чтение+запись памяти с возможной
ошибкой, чтение — как чтение памяти с возможной ошибкой. Пипхол-оптимизатор
не объединяет чтения через запись и не удаляет публикацию владельца как
неиспользуемую чистую арифметику. Тест сохраняет чтения до и после записи в
оптимизированном модуле и сравнивает их независимые значения.

## Владение, циклы и GC

Перед условием цикла или структурированным loop-if компилятор переводит активные
локальные переменные в типизированные ячейки; недоступные объявления резервируют нулевое/nil-хранение. Вложенный цикл
использует уже доминирующую ячейку. Ячейка локальной переменной тела получает
начальное значение при каждом входе; соседние терминальные ветви восстанавливают
исходные идентификаторы ячеек. Запись в потенциально пустом цикле по-прежнему
не делает внешнее неинициализированное объявление гарантированно готовым к чтению.

Backend Dis помечает владельца каждой ячейки и каждого прочитанного значения
как отдельные корни GC. Используется существующий удерживающий `MOVP`: сначала
удерживается новый владелец, затем публикуется замена и освобождается прежний
владелец назначения. Для ключа снимка копируется ещё скалярная позиция; второе
слово никогда не помечается указателем. Повторная инициализация ячейки освобождает
прежнее удержание. Число корней ограничено скомпилированным кадром; backend пока
консервативно удерживает SSA-слоты до перезаписи или освобождения кадра.

Независимый эталонный исполнитель при публикации копирует байты строки, включая
срезы, U+0000 и строки из переиспользуемых буферов форматирования чисел. Реестр
владельцев одного запуска удерживает копии до очистки и сохраняет существующий
лимит. Он независим от нативных счётчиков ссылок и не моделирует расход памяти VM.

Ячейки — локальное хранение компилятора. Внешние проекции и каналы продолжают
использовать собственные контракты брокера и владения; адреса кадра наружу
не передаются, нового API объектного мьютекса здесь нет.

## Получатель обхода остаётся захваченным

`for-in` вычисляет получателя один раз. Переназначение исходной строки, таблицы
или последовательности ключей в теле не меняет захваченного получателя. Прямой
обход таблицы использует снимок ключей и живые значения именно захваченной
таблицы. Обход снимка не перечитывает вновь присвоенную переменную снимка.

```limbo
text := "A😀Я";
for (index, rune in text) {
    text = "changed"; # Всё равно три итерации по исходной строке.
}
```

Обычное условие цикла, напротив, читает актуальное значение на каждом проходе.
Шаг заголовка может переназначать ссылку; continue исполняет его один раз,
break и return пропускают. Прежние правила отбрасывания недостижимого шага
и его отладочных записей сохранены.

## Сборка, запуск и проверки

Из корня репозитория после сборки:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/retained-loops.b retained.fir -g retained.json
build/fir/fir1 opt retained.fir retained.opt.fir
build/fir/fir1_table_run retained.opt.fir
build/fir/fir1 dis retained.opt.fir retained.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 4 retained.dis
build/runtime/disvm --no-jit --quantum 2048 --stats --inspect-words 0 4 retained.dis
```

Эталон возвращает 42. VM показывает `42, 0, 1, 0`: два места результата и флаги
исполнения. Счётчики владельцев таблиц/ключей в конце равны нулю. Оба
устанавливаемых SDK компилируют этот пример через заново связанный клиент C99.

Тесты `fir1_retained_loops` и `disvm_retained_loops_{jit,interpreter}` проверяют
FIR до/после оптимизации, два кванта планировщика, алиасы, самоприсваивание,
пустых владельцев, Unicode/NUL, снимки числовых буферов, переназначение в шаге
и ветвях, захват получателей, копирование владельца/позиции ключа, вложенность
и ранний возврат. Отдельные FIR-фикстуры проверяют все четыре типа ячеек,
несовместимые загрузки/записи/инициализаторы, запрет копирования/выхода ячеек,
доминирование и сохранение старого SWF-объекта при неподдерживаемом lowering.
Повторные запросы C99 чередуют корректные ссылочные циклы с ошибками парсера
и семантики.

Расширение остаётся в FlashVM. Произвольные ADT, массивы/кортежи, динамический
`any`, выход ячеек за пределы кадра и полный компилятор Limbo/AS остаются вне
этого профиля. Backend NC64 Dis поддерживает эти ячейки; SWF отклоняет их
до замены выходного файла вызывающей стороны.

[Компилятор 0.42](JOIN_INITIALIZATION.ru.md) добавляет инициализацию на всех путях и независимо проверяемое `ref.nil`.

[Компилятор 0.43](LOOP_INITIALIZATION.ru.md) разрешает первые записи в теле цикла, сохраняя проверку чтений и входные факты на выходе.
