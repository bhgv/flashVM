# Лексические терминальные ветви — компилятор 0.22

Здесь описано исходное терминальное подмножество. FIR 0.57 также поддерживает [числовые слияния/while](NUMERIC_FLOW.ru.md); прежние примеры остаются корректными.

[English](TERMINAL_ARMS.md) · [Подробно комментированный пример](../examples/tables/arms.b) ·
[README примеров](../examples/tables/README.ru.md) · [Операции таблиц](TABLE_MUTATION.ru.md)

Авторитетная грамматика Limbo на Coco/R допускает объявления, присваивания и
обычные операторы профиля внутри обеих ветвей терминального решения. Это работает
для однородного `int` и точного `big`/table-профиля. Каждая ветвь заканчивается
`return` либо полным вложенным `if/else`, все пути которого возвращают значение.
Продолжения после дерева, SSA phi, исходных циклов и общих вызовов функций пока нет.

```limbo
x := big 41;
if (document.flag == 1) {
    x = big 100;             # Меняем внешнюю привязку только на выбранном пути.
    local := table of big;  # Локальный владелец принадлежит этой ветви.
    local.answer = x;
    return local.answer;
} else {
    return x + 1;           # Здесь по-прежнему входное x = 41.
}
```

## Инициализаторы и типы

В `x := x + 1` инициализатор сначала читает внешнее имя, затем создаётся локальное
затенение. Его тип может отличаться: `x := "42"` затеняет внешний big строкой,
после чего `return big x` делает явное преобразование. Обычное `x = ...` сохраняет
тип внешней привязки и отвергает запись строки в big. Повторное объявление в той
же области запрещено. Типизированное объявление без инициализатора нельзя читать
до присваивания. Локальные имена соседней ветви недоступны даже в заведомо
неисполняемой ветви: проверка типов предшествует оптимизации.

Ветви `int` используют существующие правила числовых операторов. В table-профиле
разрешены типизированные локальные переменные, владельцы и снимки ключей,
изменение/удаление элементов и явные преобразования.

Перед каждым решением frontend сохраняет входные SSA-привязки. Перед разбором
`else` он восстанавливает их и закрывает локальные имена первой ветви. Вложенные
снимки независимы; номера SSA и локальных привязок не переиспользуются. Это снимок
идентичностей компилятора, а не содержимого таблиц: реальные эффекты выполняет
только выбранная ветвь. Транзакции, мьютексы и удалённая атомарная модификация
этим не добавляются.

Новые операции FIR, opcode Dis, импорты Bigtable и изменения контейнеров не нужны.
Проверка CFG контролирует доминирование определений. Оптимизатор сохраняет эффекты
и проверяемые импорты. Карты владельцев удерживают локальные таблицы/ключи через
вызовы каналов и кванты GC/планировщика по одной инструкции. После завершения
модуля живых владельцев таблиц и ключей не остаётся.

## Отладочная информация и пределы

Source-sidecar содержит парные события входа/выхода области на точных байтах
скобок, уникальные номера областей, глубину и идентичность привязки. Доступ к
внешнему имени сохраняет область его объявления; затенение получает новую.
Смещения UTF-8 остаются байтовыми. Это не полное Dis SBL и не полное подключение
отладчика.

Ограничения сохранены: общая глубина синтаксиса 64, 127 решений/255 блоков,
1000 исходных значений, 256 идентичностей переменных за всю трансляцию. Закрытые
локальные имена тоже учитываются. Ошибки синтаксиса, типов и лимитов сохраняют
прежние файлы FIR и sidecar. Скрытого перехода на bootstrap-парсер нет.

## Запуск

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/arms.b build/arms.fir -g build/arms.json
build/fir/fir1 opt build/arms.fir build/arms-opt.fir
build/fir/fir1 dis build/arms.fir build/arms.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/arms.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/arms.dis
```

Две ячейки результата: `42, 0`; признаки выполнения: `1, 0`. Исходный и
оптимизированный примеры проверяются перемещёнными C99 SDK-клиентами в обоих
режимах VM. CLI и библиотека используют одни семантические действия и грамматику.
Для скалярных int-ветвей также проверена генерация объекта SWF. Аппаратное
исполнение ARM64 и полная реализация языков из этого не следуют.


Профиль int/real сохраняет эту терминальную грамматику. Профиль big/table в 0.41
также поддерживает [обычные операторы функции и объединения](FUNCTION_FLOW.ru.md).
