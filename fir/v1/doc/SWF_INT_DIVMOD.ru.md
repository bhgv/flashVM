# Знаковые деление и остаток int32 в SWF — FIR 0.61

FIR0.63: [known-bit proofs / доказательства по битам](INTEGER_FACTS.ru.md) additionally admit bounded dynamic counts/nonzero divisors and literal copies. The literal-only boundary below describes the original release.

[English](SWF_INT_DIVMOD.md) · [Исходник с комментариями](../examples/dis/int-divmod-swf.b) ·
[C99 API](../tests/swf_int_divmod_api.c) · [Арифметика int](INT_ARITHMETIC.ru.md) ·
[Сдвиги](SWF_INT_SHIFTS.ru.md)

SWO backend принимает `i32.div.signed` и `i32.mod.signed`, если живое
SSA-определение правого операнда — **ненулевой const.i32**. Числитель может
оставаться динамическим. Неизвестный делитель и ноль отвергаются до записи
байтов объекта. CLI, `fir_object` и `fir_run(FIR_OBJECT)` используют одну
проверку; явная оптимизация может раскрыть константу из copy/вычисления.
Грамматика, FIR opcode, версия SWO и действующий Dis ABI не меняются.

| Вход | Частное | Остаток |
| --- | ---: | ---: |
| -7 и 3 | -2 | -1 |
| 7 и -3 | -2 | 1 |
| MIN и -1 | MIN, с wrap | 0 |
| Любой числитель и неизвестный делитель | Отказ SWO | Отказ SWO |
| Любой числитель и ноль | Отказ SWO | Отказ SWO |

Частное усекается к нулю, остаток имеет знак числителя; это не Python floor
modulo. MIN/-1 даёт MIN по контракту FIR. После стандартного AVM1 Divide или
Modulo emitter выполняет BitOr с нулём: получается точный int32, а остаток -0
нормализуется в целочисленный ноль. Линкер принимает обычный однобайтовый
Modulo 0x3f, сохраняя байты действий и проверки записей/переходов. Дополнительный
extension flag и специальный opcode плеера не нужны.

## Точность промежуточного double

Каждый int32 точно представим как binary64. Если a/b нецелое, расстояние до
ближайшего целого не меньше 1/abs(b). При abs(a)<=2^31 ошибка округления
binary64 меньше 2^-21/abs(b), даже с запасом в полный ulp: границу усечения
перейти нельзя. Целые частные, включая +2^31 для MIN/-1, точно представимы.
ToInt32 завершает усечение и wrap. Этот аргумент относится к int32 и не
обосновывает перенос big в double. Modulo получает точные целые входы,
после чего результат также нормализуется.

## Удаление неиспользуемой проверяемой арифметики

Оптимизатор удаляет неиспользуемые деление/остаток i32 и big, если ненулевой
делитель доказан литералом того же типа. Сдвиг без пользователей удаляется
при доказанном int32-счётчике 0…31 или 0…63 для big. Это локальная проверка
DCE; публичная консервативная таблица `fir_effects` не меняется.

Производители операндов сохраняют собственные эффекты. Ошибочная конверсия,
отсутствующий ключ и внутреннее деление на ноль остаются наблюдаемыми, даже
если внешняя безопасная операция не используется. Неизвестные/недопустимые
делители и счётчики сохраняют проверки. Эффекты памяти, выделения, владения,
приостановки и управления не ослабляются; CSE и барьеры памяти остаются
консервативными.

## Сборка и запуск

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/int-divmod-swf.b build/divmod.fir
build/fir/fir1 object build/divmod.fir build/divmod.swo
build/linker/swl link build/divmod.swf build/divmod.swo
build/fir/fir1 dis build/divmod.fir build/divmod.dis
build/runtime/disvm --jit --stats --inspect-words 0 2 build/divmod.dis
build/runtime/disvm --no-jit --stats --inspect-words 0 2 build/divmod.dis
```

Пример с построчными комментариями перебирает -7…7, восстанавливает каждое i
через `(i/3)*3+i%3`, суммирует в ноль и возвращает **42**. Dis показывает 42
и flag 1; связанный SWF выводит 42 в FlashVM. Принимаются исходный и
оптимизированный FIR; для второго пути сначала выполните `fir1 opt`.
Установленный SDK содержит исходник, библиотеки и руководства; IDE использует
тот же API внутри процесса.

Прежний пример integer-identities теперь допускается в raw SWO: делители ±1
и нулевые счётчики сдвигов удовлетворяют доказательству. Оптимизация по-прежнему
убирает вычисления, но для допуска цели их предварительное удаление не требуется.

## Проверки и границы

Регрессия сравнивает 2688 исходных/оптимизированных результатов для 32
числителей и 21 делителя: MIN/MAX, оба знака, целые/дробные частные и
детерминированные значения всей разрядности. Python oracle использует
математические целые без переполнения host divide и без float. Настоящий SWF
в FlashVM и захваты Dis в интерпретаторе/JIT должны совпасть; проверяются
счётчики dispatch и флаги исполнения. Нулевые/неизвестные делители проверяют
ошибки и сохранение прежнего файла. C99 API повторяет успешные вызовы,
отказы и доказательства после оптимизации. Отдельные DCE-тесты проверяют
безопасные/ошибочные/неизвестные i32/big операции и ошибки производителей.
Линкер проверяется на точность object/archive и отказ при неверных записях.

Запуск SWF требует явных `FIR_SWL` и `FIR_FLASHVM_RUNNER`; тест только
компилятора не доказывает работу плеера. Общие проверки неизвестного делителя
во время исполнения SWF, произвольная big-арифметика SWF, AS3/ABC output и
исполняемые модули нового Dis64 остаются отдельными работами.
