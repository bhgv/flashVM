# Подсчёт, наличие ключа и удаление в таблицах Limbo

[English](TABLE_MUTATION.md) · [Подробно комментированный пример](../examples/tables/mutation.b) ·
[Таблицы](TABLES.ru.md) · [Компиляция Dis](TABLES_DIS.ru.md).

Компилятор 0.21.0 и runtime 0.24.0 добавляют законченный срез нашего ограниченного
Coco/R-профиля Limbo: countof, in и delete. Это расширение FlashVM/DisVM, которое
не переносится в язык/ABI Inferno. Грамматики src1.atg и fir1.atg остаются
авторитетными; сгенерированные парсеры хранятся только в результатах сборки.

## Синтаксис и типы

| Синтаксис | Тип FIR | Действие |
| --- | --- | --- |
| `countof entries` | i64 | Число всех числовых и строковых записей. |
| `key in entries` | bool | Проверка наличия, включая значение ноль. |
| `delete entries.name` | bool | Удаление буквального строкового ключа. |
| `delete entries[key]` | bool | Удаление числового, строкового или snapshot-ключа. |

Удаление бывает выражением или отдельным оператором. Оно не читает значение
отсутствующего ключа и не сдвигает числовые индексы. Приёмник/ключ вычисляются
однократно. in вычисляет сначала левый ключ, затем правую таблицу и связывает
слабее побитового OR. countof — ограниченный префиксный оператор. Точка по-прежнему
означает буквальный строковый ключ, а не чтение одноимённой переменной.

Логический результат можно вывести в локальную переменную и напрямую использовать
в if. Явные int/big/string дают нормализованные 0/1 либо строки "0"/"1".
По соглашению Limbo typeof сообщает int, хотя проверяемый FIR хранит отдельный
bool. Типизированное объявление: `flag: int = int (key in t)`. Значения таблицы
остаются big: `t.flag = big (key in t)`. Общая неявная динамическая конверсия,
прозрачный any и автоматические удалённые прокси этим изменением не вводятся.

## Семантика

Числовой 0 и строковый "0" — разные ключи. Числовой ключ имеет тип big; int-индекс преобразуется явно как `big index`. Нулевое значение существует в таблице.
Отсутствующий ключ даёт false для in/delete; обычное чтение отсутствующего ключа
по-прежнему вызывает ошибку. Отрицательный числовой ключ или недопустимый индекс
snapshot проверяется немедленно, даже если результат не используется и после
оптимизации. Неверные владельцы/статусы также не превращаются в обычное отсутствие.

len считает только непрерывный числовой префикс с нуля; countof — все записи.
После удаления нуля len может стать нулём, хотя последующие индексы сохраняются.
keysof остаётся независимым неизменяемым снимком. Старый snapshot-ключ можно
повторно проверить/удалить после удаления и вставки записи: используется его
исходная идентичность, а не порядковый номер в snapshot. Алиасы видят общую
мутацию. Нативные адреса не передаются ни в ключах, ни между кучами VM.

## FIR, оптимизация и Dis

В конец перечисления добавлены table.count, table.has и table.delete; старые ID
сохранены. Первые две операции читают память и могут выбрасывать исключение;
удаление также пишет память. Их нельзя выбросить или перенести через запись
только потому, что SSA-результат не используется. Проверяются типы, арность,
доминирование и сохранность выходного файла при отклонении IR/исходника.

Используются существующие LOAD/MFRAME/MCALL, без новых тегов контейнера и native-
инструкций. Старые программы сохраняют 21 именованный импорт; новые используют
26, добавляя count/delindex/deltext/delkey/present. Загрузчик проверяет сигнатуры.
Старые экспортируемые сигнатуры сохранены; новым программам нужен соответствующий
runtime. present переводит Ok/Missing в 1/0, остальные ошибки выбрасываются.
delkey разрешает проверенный snapshot-ключ. Владельцы таблиц/строк/снимков остаются
GC-корнями на границах вызовов, включая сборку на каждом шаге; скалярные результаты
не помечаются как указатели. Удалённые проекции используют явные канальные API.

## Запуск примера

Из корня репозитория после сборки fir и disvm-runtime:

```sh
build/fir/fir1_source limbo --input fir/v1/examples/tables/mutation.b mutation.fir
build/fir/fir1 opt mutation.fir mutation.opt.fir
build/fir/fir1_table_run mutation.opt.fir
build/fir/fir1 dis mutation.opt.fir mutation.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 mutation.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 mutation.dis
```

Эталон выводит 42; VM показывает 42,0,1,0 — два результата ветвей и два флага.
Исполнена только выбранная ветвь. Пример подробно комментирует ноль, алиас,
snapshot-удаление, повторное удаление и различие len/countof. Обе установки SDK
проверяют оригинальный/оптимизированный FIR через свежие C99-клиенты и оба режима
VM. table_mutation.py отдельно проверяет типы, rollback выхода и неиспользуемые
ошибочные операции; native boundary-тесты проверяют владельцев и статусы.
