# Группировка числовых условий — FIR 0.56 / CLI 0.23

[English](GROUPED_CONDITIONS.md) · [Ленивое вычисление](NUMERIC_LOGIC.ru.md) · [Покрытие](COVERAGE.ru.md) · [Пример real](../examples/dis/grouped-conditions.b) · [Пример int](../examples/dis/grouped-int.b)

Однородные профили Limbo int/real теперь используют общую Coco/R-иерархию
выражений для арифметики, отношений, скобок и логических операторов. Работают
обычные группы `(a < b || c < d) && e < f`, повторное `!!(a < b)` и сравнение
нормализованных условий `(a < b) == (c < d)` либо `!=`. Прежнее `!(...)` сохранено.
Скобки разбирает сама грамматика; отдельного символьного парсера или эвристики
выбора между числовой и булевой группой нет.

## Приоритеты и типы

От слабого связывания к сильному: `||`, `&&`, побитовое OR, `^`, `&`, равенство,
упорядоченные отношения, сдвиги, сумма/разность, произведение/деление/остаток,
унарные операции. Это порядок соответствующих операторов исходной грамматики
Limbo Inferno. Бинарные операции ассоциативны влево, унарные — вправо.
[Точная таблица](GROUPED_CONDITIONS.md#precedence-and-strict-types).

| Пример | Результат проверки типов |
| --- | --- |
| `(a < b) == (c < d)` | bool/bool, корректно |
| `!!(a < b)` | Два последовательных отрицания bool |
| `(1 < 2) == 1` | Отказ: нет неявного bool/int |
| `1 < 2 < 3` | Отказ: результат первого отношения не числовой операнд |
| `1 \| 2 == 3` | Отказ: равенство связывает сильнее побитового OR |
| `((1 \| 2) == 3)` | Корректное явное числовое группирование |
| `return +(1 < 2)` | Отказ: унарный плюс не преобразует bool в int |
| `flag := (1 < 2)` | Отказ: числовые локальные значения остаются int/real |

Все числовые SSA-производители записывают статический тип в существующий
ограниченный каталог. Арифметика, знаки, дополнение, сдвиги, identity-casts
псевдонимов, объявления/присваивания и return проверяют этот тип до публикации.
Промежуточные bool доступны условиям, логике и равенству, но не числовым
переменным/результатам. Преобразование обычного Limbo-отношения в int и полная
семантика языка ещё не реализованы. Числовые AS-профили сохраняют свою прежнюю
арифметику и отвергают эти Limbo-отношения.

## Исполнение, позиции и владение

Ленивые рёбра и приватные bool-ячейки используют прежние FIR-операции. Операнды
вычисляются однократно по порядку исходника. `(1 == 1 || (1 / 0 == 0)) && !!(2 < 3)`
не исполняет деление на ноль. При выборе ошибочной правой части ошибка сохраняется
и после оптимизации. Группировка не меняет IEEE-семантику NaN и знакового нуля;
отрицание не подменяется противоположным упорядоченным отношением.

FIRDBG1 хранит точные UTF-8-позиции отношений, ленивых операторов и каждого `!`,
включая повторные отрицания. Скобки не создают ложных событий. Комментарии с
несбалансированными скобками обрабатывает сгенерированный scanner. Общая глубина
групп/унарных операций/решений ограничена 64; бюджеты SSA и блоков сохранены.
После исчерпания SSA-бюджета проверка условия не индексирует каталог типов.
Отрицательные тесты требуют единственный структурированный compiler diagnostic,
поэтому авария sanitizer не считается корректным отказом. Семантический отказ
сохраняет прежние FIR/debug-потоки вызывающей стороны.
C99-вызовы остаются блокирующими и сериализуются хостом.

Новых FIR/Dis-инструкций, ABI кадров, GC-корней, контейнерных тегов и указателей
между кучами нет. Сырой и оптимизированный CFG исполняются существующими Dis и
SWO/SWL-бэкендами. Полные компиляторы, общие числовые for/calls, окончательные
карты Dis/SWF/JIT PC и панели Build/Run/Debug IDE остаются дальнейшей работой.

## Подробные примеры

Все непустые строки обоих примеров прокомментированы. Пример real сравнивает
два интервальных предиката и исключает NaN повторным отрицанием. Пример int
объединяет битовую маску с группированными ленивыми условиями.

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/grouped-conditions.b build/grouped.fir -g build/grouped.json
build/fir/fir1 opt build/grouped.fir build/grouped.opt.fir
build/fir/fir1 dis build/grouped.fir build/grouped.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 4 build/grouped.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 4 build/grouped.dis
build/fir/fir1 object build/grouped.fir build/grouped.swo
build/linker/swl link build/grouped.swf build/grouped.swo
```

Первый real-слот равен ровно 42.5 (биты 4631178160564600832), второй нулевой,
флаги 1/0. Для grouped-int.b первый слот равен 42 при тех же флагах. Повторите
backend-команды с grouped.opt.fir; число слотов определяйте по оставшимся trace.
Связанный SWF выводит 42.5 либо 42. Библиотечная компиляция использует тот же
публичный C99 API; перенесённый SDK сравнивает Dis библиотеки и CLI побайтно.

Приёмка включает 192 формы/тройки значений int/real, ленивые ошибки, NaN,
маскирование/приоритеты, комментарии, исходные позиции, отказы типов/лимитов и
сохранение output. C99-клиент чередует 16 успешных компиляций с 24 проверками
семантического отказа и rollback обоих потоков. Настоящий runtime проверяет
interpreter/native-счётчики, точные значения/флаги и освобождение owners.
Аппаратная ARM64/RV64 — отдельный этап.
