# Проверяемые знаковые сдвиги int — компилятор 0.29

[English](INT_SHIFTS.md) · [Комментированный пример](../examples/tables/int-shifts.b) ·
[README примеров](../examples/tables/README.ru.md) · [Арифметика](INT_ARITHMETIC.ru.md) ·
[Строки и биты](TEXT_BITS.ru.md) · [Сдвиги big](BIG_SHIFTS.ru.md)

Наш Coco/R big/table-профиль Limbo поддерживает `<<`, `>>`, `<<=` и `>>=` для
int-значения и int-счётчика. Результат остаётся int. Прежние big-сдвиги сохраняют
контракт big/int и диапазон 0..63; int-сдвиг требует **0..31**.

```limbo
packed := int packet.word;
sign := packed >> int 31;
value := packed & int 255;
value <<= int 1;
value >>= int 1;
return big value;
```

## Типы, ширина и ошибки

Операнды вычисляются один раз, слева направо. Счётчик не маскируется: отрицательное
значение и 32 либо больше вызывают `invalid argument`, даже для нулевого левого
операнда или неиспользуемого результата. Явный cast int сохраняет преобразование
по модулю 2^32; проверяется уже полученное типизированное значение счётчика.

Левый сдвиг сохраняет младшие 32 бита, затем трактует их как знаковое число.
Правый сдвиг арифметический, со знаковым заполнением. Нулевой сдвиг не меняет
вход; `int 1 << int 31` даёт -2147483648, `int -1 >> int 31` даёт -1.
Компилятор и эталонный исполнитель не сдвигают отрицательные знаковые C-числа.
Преобразования через binary64 и неявного смешения int/big нет.

Составное присваивание запоминает старый скаляр, вычисляет RHS и меняет привязку
лишь после успеха. Удалённая атомарная транзакция не добавляется. Сумма связывает
сильнее сдвига; сдвиги левоассоциативны, как в прежней big-грамматике. Отдельные
однородный int-профиль и числовые AS-профили в этой серии не расширяются.

## FIR и оптимизация

Две операции дописаны в конец enum без изменения прежних ID типов и операций:

| Операция | Сигнатура | Эффект |
| --- | --- | --- |
| `i32.shl.checked` | i32, i32 → i32 | возможная ошибка |
| `i32.shr.checked` | i32, i32 → i32 | возможная ошибка |

Текстовый FIR и публичный C99 IR проверяют точную сигнатуру. Константная свёртка
допускает только счётчики 0..31, работает с unsigned32 и явно восстанавливает
знак. Ошибочные константные сдвиги сохраняются даже при неиспользуемом результате.
Действительно невыбранную CFG-ветку можно удалить без вычисления её сдвига.
JSON отладки сохраняет точный диапазон оператора после префикса UTF-8.

## Исполнение NC64 Dis

Оба бэкенда — скалярный и hosted — разворачивают операцию в восемь существующих
инструкций: две проверки счётчика, big-сдвиг, три шага нормализации signed32,
переход через ошибочную ветку и саму ошибочную инструкцию. Корректные входы
используют SHLL/SHRL со счётчиком 0..31. Ошибочный счётчик достигает существующего
проверяемого big-сдвига с 64, вызывающего штатное исключение VM. Новые opcode,
ABI вспомогательных функций и зависимости от модулей не нужны. Ошибочная ветка
не публикует успешного результата.

Проверки учитывают порядок сравнения Dis: source сравнивается с middle;
арифметический сдвиг получает значение из middle, счётчик из source. Расчёт
размера скалярного кода и оба прохода hosted-эмиттера учитывают восемь инструкций,
сохраняя адреса переходов после развёрнутой операции. Используются существующие
ядра AMD64/ARM64 и C fallback. Новых нативных быстрых путей в этой серии нет.

## Проверки и ограничения

Проверяются константы и чтения таблиц на знаковых границах, счётчики
0/1/7/16/30/31, знаковое заполнение, составные обновления и ошибки для
-1/32/63/64/INT_MIN/INT_MAX при нуле и обоих знаках значения. Прямой скалярный FIR
проверяет переходы и trace после развёртывания. Исходный и оптимизированный код
сравниваются с Python-оракулом в эталонном исполнителе, настоящих интерпретаторе
и JIT. Подделанные типы C99 отвергаются до записи выходных байтов.

Сдвиги со счётчиком-константой 0…31 поддержаны SWF-бэкендом; неизвестные
счётчики отвергаются. [Точный контракт](SWF_INT_SHIFTS.ru.md). Общие
межмодульные функции и полный исходный Limbo остаются отдельными работами.
Расширение остаётся в FlashVM;
снимок Inferno ради новых операций компилятора не изменяется.

## Запуск

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/int-shifts.b build/shifts.fir -g build/shifts.json
build/fir/fir1 check build/shifts.fir
build/fir/fir1 opt build/shifts.fir build/shifts-opt.fir
build/fir/fir1 dis build/shifts-opt.fir build/shifts.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/shifts.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/shifts.dis
```

Значения trace: 42, 0; флаги исполнения: 1, 0. Приёмка установленного SDK заново
линкует C99-клиенты source/FIR и проверяет пример до/после оптимизации в обоих
режимах VM. Исполнение на физическом ARM64 остаётся отдельной проверкой от
эмуляции инструкций существующих нативных ядер.
