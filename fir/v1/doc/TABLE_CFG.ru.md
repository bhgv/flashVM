# Ациклический CFG таблиц — FIR 0.19 / runtime 0.22

[English](TABLE_CFG.md) · [Полный комментированный Limbo](../examples/tables/decisions.b) ·
[Типизированный исходник](TABLES.ru.md) · [Владение/ABI](TABLES_DIS.ru.md) · [Сравнения big](BIG_DECISIONS.ru.md)

Решения big-профиля Coco/R теперь могут переносить живые таблицы, снимки, ключи,
строки и захваченные locations в обе ветви. Нативные вызовы и преобразования
исполняются только на выбранном пути. Синтаксис исходника прежний: пролог
объявлений/присваиваний, затем return либо вложенный if/else, каждая ветвь
завершается. Устранён разрыв, когда корректный исходник/FIR с табличным решением
нельзя было получить как Dis или исполнить независимым reference runner.

## Граф и владение

Hosted Dis-backend и C reference runner требуют проверенный DAG. Публичная
`fir_acyclic(module, error, capacity)` проверяет заимствованный модуль, устраняет
повторные рёбра и делает ограниченный топологический обход. Модуль/парсер не
меняются, heap не выделяется. Обратное физическое направление перехода допустимо,
если логического цикла нет. Циклы отклоняются до публикации и создания владельцев.
Общий verifier FIR и скалярный pointer-free Dis backend по-прежнему допускают
циклы; их исполнение ограничивается существующим runtime instruction budget.

DAG исполняет каждую SSA-инструкцию не больше раза за вызов: реестры владельцев
reference runner ограничены FIR_LIMIT. Нативный frame сохраняет точные карты
всех потенциальных значений. Неисполненные owner-ячейки остаются корнями H;
bool, индексы/диапазоны и raw-адрес prepared-frame не помечены. Импорты загружаются
один раз перед entry. Указатели не передаются между кучами VM или по сети.

Ручной FIR допускает общий выход через доминирующий владелец/табличную location:
изменения таблицы остаются последовательными эффектами, без phi и без атомарного
удалённого read-modify-write. Одинаковые IF targets считаются одним ребром.
Сахар присваиваний/слияния окружений, phi, исходные циклы и циклические таблицы
здесь не добавлены.

## PC инструкций и ошибки

Первый приватный проход измеряет окончательный PC каждого блока с учётом
развёрток frame/argument/call и bool. Свежий второй поток разрешает прямые и
обратные IF/JMP. Длина файловых операндов не влияет на число инструкций; перед
публикацией оба счётчика должны совпасть. Placeholder-код первого прохода не
попадает в выход. HASLDT и opcodes прежние; IF сравнивает bool с immediate one,
затем выбирает существующий JMP.

Захват прежний: N значений, затем N флагов исполнения. После opt надо пересчитать
live trace. Выход C reference runner хронологический и публикуется только после
успешного return. Выбранные missing-key/conversion/zero ошибки не публикуют ни
reference trace, ни native DATA inspection. Невыбранная ошибочная ветвь не
исполняется. Финальная ошибка I/O всё ещё может оставить префикс; CLI использует
подготовку результата до замены назначения.

## Запуск

Из корня после независимой сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/decisions.b build/table-decision.fir
build/fir/fir1_table_run build/table-decision.fir
build/fir/fir1 dis build/table-decision.fir build/table-decision.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 6 build/table-decision.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 6 build/table-decision.dis
```

Reference: `42`. Нативные ячейки: `42, 0, 0, 1, 0, 0`: исполнен первый из трёх
статических возвратов. Оба переносимых SDK заново линкуют публичные C99-клиенты
компилятора/reference и запускают этот пример без bootstrap-компилятора.

Проверяются оба исхода решений, вложенные условия с сохранёнными ключами/cast,
невыполненные новые владельцы/ошибки, выбранные сбои, общие обратные выходы,
повторные рёбра и переходы через 8191 native-инструкцию. Оба режима собирают GC
между инструкциями и освобождают table/key владельцев. UBSan проверяет DAG,
компилятор и reference. Эмуляция ARM64 не означает испытаний физического ARM64.
