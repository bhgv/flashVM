# Присваивание срезам таблиц и строк с изменением длины

[English](SLICE_ASSIGNMENT.md) · [Отрицательные позиции](RELATIVE_SEQUENCES.ru.md) ·
[Запускаемый пример](../examples/tables/splice.b) · [C API](../../../common/table/SPLICE.ru.md)

Присваивания работают через наш Coco/R-компилятор, FIR, оптимизатор, независимый
C reference runner и нативный Dis backend в ограниченном Limbo-профиле таблиц.
Нужны инструменты FIR версии 0.33 и соответствующий hosted DisVM: сигнатуры
функций встроенного модуля проверяются перед исполнением.

```limbo
# Замена диапазона [1,3) со сдвигом хвоста.
t[1:3] = table of big {9};
# Вставка исходной плотной части таблицы в саму себя.
t[1:1] = t;
# Позиции строки — руны, а не байты UTF-8.
s[int 1:int -2] = "é";
# Замена последней руны на emoji.
s[int -1] = int 128512;
```

В этом source-профиле пока обязательны обе границы. Неотрицательный конец
исключается, отрицательный включается: `[0:-1]` охватывает всю последовательность.
Пустой диапазон вставляет, пустая замена удаляет, хвост сдвигается. Для таблицы
вставляется только плотная числовая часть правой стороны. Текстовые ключи назначения
сохраняются, разреженные числовые ключи остаются абсолютными. Если растущая плотная
часть пересекает такой ключ, операция завершается ошибкой без изменения таблицы.

Получатель и границы вычисляются один раз, отрицательные позиции нормализуются
до правой части. Изменение размера таблицы внутри RHS не перенаправляет
отрицательный индекс назначения: сохранённые абсолютные границы повторно
проверяются при замене. При самоприсваивании старые данные читаются до публикации
нового хранилища. Ошибка выделения сохраняет старое содержимое. Это не транзакция
над всеми побочными эффектами RHS: уже выполненное удаление или иное действие
правой части не откатывается, если последующая замена завершилась ошибкой.

Строки индексируются рунами Unicode; комбинируемые символы считаются отдельно.
Запись элемента требует int-код Unicode от U+0000 до U+10FFFF без суррогатов;
индекс за концом не дописывает символ. Замена среза требует string. Новая строка
привязывается к локальной переменной, прежние алиасы сохраняют старое значение.
ASCII-представление по возможности сохраняется; широкие строки копируются рунами.
Новое содержимое полностью готово до публикации. Составные присваивания срезам
и строковым элементам пока отклоняются.

FIR вводит типы возможностей `table.range` и `string.range`: владелец и две
абсолютные исключительные границы. Одноимённые операции захватывают нормализованный
диапазон; `string.char.range` — один существующий символ. `table.splice` не имеет
результата и сохраняет эффекты чтения/записи/выделения/ошибки. `string.splice`
возвращает новую строку, `rune.text` проверяет и кодирует Unicode scalar. При
копировании возможности сохраняются три ячейки, корень GC только первая.
Возможности строк и таблиц не взаимозаменяемы. Dis backend использует проверяемые
вызовы встроенного модуля, без новых upstream-опкодов.

Отладочные события указывают на исходную открывающую скобку. Тесты сравнивают
неоптимизированный и оптимизированный FIR, независимый Unicode/sequence oracle,
реальное исполнение в интерпретаторе/JIT с quantum 1 и освобождение владельцев.
Поддельные типы C API отклоняются до записи выходных файлов backend.

Общие массивы пока не охвачены: присваивание native Dis array с изменением длины
ещё предстоит. Интеграция объектных mutex с памятью VM и удалёнными проекциями
тоже не завершена. Сейчас отдельный C builtin исполняется целиком на одном потоке
владельца VM; атомарность всего исходного выражения между потоками/запросами
не заявляется. Regexp-срезы остаются отдельной работой. Расширения языка не
переносятся в Inferno.


## SDK tutorial / запуск примера

From the installed FIR package / из установленного каталога FIR:

```sh
./fir1_source limbo --input examples/tables/splice.b splice.fir
./fir1 opt splice.fir splice.opt.fir
./fir1 dis splice.opt.fir splice.dis
../disvm-runtime/disvm --jit --quantum 1 --inspect-words 0 4 splice.dis
```

Expected / ожидается: `DATA 0 42`, `DATA 8 0`, `DATA 16 1`, `DATA 24 0`.
The last two cells are execution flags; the failure arm is not executed.
Последние две ячейки — признаки исполнения; ветка ошибки не исполняется.
For in-process compilation / для встраивания:
[commented C99 client / комментированный клиент C99](../examples/dis/main.c).
