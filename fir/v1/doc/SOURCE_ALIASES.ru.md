# Псевдонимы исходника → канонический FIR (0.49)

[English](SOURCE_ALIASES.md) · [Исполняемый учебный пример](../examples/type-aliases/README.ru.md) · [Связывание интерфейсов](../../../compiler/limbo/frontend/ALIASES.ru.md)

Исполняемый адаптер использует [грамматику Coco/R](../compiler/src1.atg) и [библиотеку понижения](../compiler/lower.c). CLI и сериализованный C API принимают псевдонимы между implement и объявлением модуля, а также внутри реализуемого модуля перед экспортом value. Формы: `Name: type int;`, `Name: type real;`, `Name: type big;`, `Name: type string;`, `Name: type table of big;` либо ссылка на ранее объявленный псевдоним.

Связывание последовательное, с немедленным сохранением канонического типа в области объявления. Затенение исходного имени внутри модуля не меняет уже связанный файловый псевдоним. Тело видит псевдонимы модуля. Результат допускает int/real/big; числовые локальные переменные int/real остаются однородными. Профиль big/table допускает аннотации int, big, string и table of big. Возврат строки/таблицы и общие составные типы пока не поддержаны. Псевдонимы не порождают инструкций: тест требует побайтового совпадения FIR с прямыми аннотациями.

Предел — 128 псевдонимов на единицу трансляции и существующий буфер имени 255 байт. Дубликаты, самоссылки, неизвестные/опережающие имена и локальные значения, затеняющие псевдоним, дают семантическую ошибку. Локальные объявления типов, квалифицированные/обобщённые типы, include и приведения по имени псевдонима не реализованы. Отдельный механизм интерфейсов умеет опережающее связывание и диагностику циклов; эти возможности не следует приписывать исполняемому адаптеру. Полного компилятора типизированных тел здесь ещё нет.

Каждый запрос библиотеки сбрасывает состояние. При ошибке прежние FIR и отладочные файлы сохраняются. Ошибочные implement без имени и отсутствующий модуль завершаются диагностикой; повторение префикса требует токен идентификатора, исключая зависание на EOF. Отладочные позиции относятся к исходному снимку текста. Ключевое слово type не ломает одноимённые AS1/2/3 переменные и табличные поля t.type.

Тесты сравнивают канонический FIR, оптимизируют, создают настоящие Dis и исполняют в интерпретаторе/JIT с квантами 1 и 2048, проверяя результат и счётчики диспетчеризации. Дополнительный SWF-прогон проверяет числовую цепочку FIR → SWO → линкер → SWF через trace FlashVM. Таблицы остаются Dis-only. Используется существующий прямой Dis-бэкенд; новых опкодов, межкучевых указателей и ABI нативных модулей нет. value() в примере — учебная обёртка, а не общий интерфейс init Inferno.
