# Псевдонимы исходника → канонический FIR (0.50)

[English](SOURCE_ALIASES.md) · [Исполняемый учебный пример](../examples/type-aliases/README.ru.md) · [Связывание интерфейсов](../../../compiler/limbo/frontend/ALIASES.ru.md)

Исполняемый адаптер использует [грамматику Coco/R](../compiler/src1.atg) и [библиотеку понижения](../compiler/lower.c). CLI и сериализованный C API принимают псевдонимы между implement и объявлением модуля, а также внутри реализуемого модуля перед экспортом value. Формы: `Name: type int;`, `Name: type real;`, `Name: type big;`, `Name: type string;`, `Name: type table of big;` либо ссылка на другой псевдоним полного префикса объявлений.

Сначала сохраняются точные именные связи префикса, затем все объявления итеративно разрешаются до разбора экспорта value. Опережающие ссылки связываются в области своего объявления. Затенение исходного имени внутри модуля не меняет уже связанный файловый псевдоним. Тело видит псевдонимы модуля. Результат допускает int/real/big; числовые локальные переменные int/real остаются однородными. Профиль big/table допускает аннотации int, big, string и table of big. Возврат строки/таблицы и общие составные типы пока не поддержаны. Псевдонимы не порождают инструкций: тест требует побайтового совпадения FIR с прямыми аннотациями.

Предел — 128 псевдонимов на единицу трансляции и существующий буфер имени 255 байт. Дубликаты, циклы и неизвестные имена (даже в неиспользуемых объявлениях) и локальные значения, затеняющие псевдоним, дают семантическую ошибку. Локальные объявления типов, квалифицированные/обобщённые типы и include не реализованы. Отдельный механизм интерфейсов остаётся более широким сервисом AST; его каталог не подменяет ограниченный префикс исполняемого адаптера. Полного компилятора типизированных тел здесь ещё нет.

Каждый запрос библиотеки сбрасывает состояние. При ошибке прежние FIR и отладочные файлы сохраняются. Ошибочные implement без имени и отсутствующий модуль завершаются диагностикой; повторение префикса требует токен идентификатора, исключая зависание на EOF. Отладочные позиции относятся к исходному снимку текста. Ключевое слово type не ломает одноимённые AS1/2/3 переменные и табличные поля t.type.

Тесты сравнивают канонический FIR, оптимизируют, создают настоящие Dis и исполняют в интерпретаторе/JIT с квантами 1 и 2048, проверяя результат и счётчики диспетчеризации. Дополнительный SWF-прогон проверяет числовую цепочку FIR → SWO → линкер → SWF через trace FlashVM. Таблицы остаются Dis-only. Используется существующий прямой Dis-бэкенд; новых опкодов, межкучевых указателей и ABI нативных модулей нет. value() в примере — учебная обёртка, а не общий интерфейс init Inferno.

## Приведения и диагностика

Имя псевдонима в унарной позиции выбирается семантическим предикатом по точному токену предпросмотра Coco/R. Второго лексера или разбора исходного текста нет. Тип и позиция оператора сохраняются до разбора операнда. I text + big 1 преобразует только text; I (expression) — всю группу. Сохраняется общий предел вложенности 64.

В профиле big/table приведения int/big/string используют [проверяемый контракт](TEXT_VALUES.ru.md): разбор signed64 предшествует сужению signed32, ключи сохраняют снимок своего значения, ошибочный неиспользуемый разбор не удаляется оптимизатором. Цели real/table отклоняются до публикации результата. В однородных int/real-профилях разрешены только совпадающие тождественные приведения; смешанные преобразования пока не реализованы. Тождественное приведение не добавляет FIR-инструкций.

Каждая именная связь хранит байтовый диапазон правой части. Неизвестное имя или цикл указывает на этот диапазон с учётом префикса UTF-8. Успешный запрос восстанавливает позицию использования. Путь до 128 идентичностей и канонический кэш не используют выделения памяти или рекурсию C по глубине цепочки. Состояние сбрасывается после успешных и ошибочных запросов. Проверяются полная цепочка, цикл из 128 имён, неправильная область, неиспользуемые ошибки и повторное использование C API.

## Сверка с Inferno

Дополнительный [оракул](../tests/alias_oracle.py) сравнивает общие int/real-программы без затенения по явно переданным исходным сборкам компилятора Inferno. В classic32 и NC64 псевдонимы и прямые типы дают побайтово одинаковые Dis при одинаковом пути исходника. Это проверка компиляции, а не исполнения чужого ABI.

Затенение файлового псевдонима одноимённым модульным в одном исходнике — лексическое расширение FlashVM: выбранный компилятор Inferno отвергает повторное объявление. Гибридные таблицы также вне общего оракула; эти расширения в upstream не отправляются. Команда из корня после сборки опорных инструментов:

```sh
export TMPDIR="$PWD/build/tmp"
python3 fir/v1/tests/alias_oracle.py build/limbo-classic/limbo-bootstrap build/runtime/bootstrap/limbo-bootstrap
```
