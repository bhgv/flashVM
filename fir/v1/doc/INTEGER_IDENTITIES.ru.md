# Целочисленные тождества без потери ошибок — FIR 0.59

[English](INTEGER_IDENTITIES.md) · [Оптимизатор](../optimiser/peephole.c) ·
[Эффекты](../optimiser/effects.c) · [Пример](../examples/integer-identities/README.ru.md) ·
[C99 API](../tests/integer_identities_api.c)

Peephole упрощает проверенные i32/big, когда результат точен, а эффекты
производителей операндов сохраняются. Не добавлены новые команды FIR/Dis/SWF,
продукции парсера, синтаксис источника или ABI. CLI `fir1 opt` и библиотечные
`fir_optimise`/`fir_run` используют одну реализацию.

| Правило | Точный целочисленный результат |
| --- | --- |
| x+0, 0+x, x-0, x*1, 1*x | x |
| x-x, x*0, 0*x | 0 |
| x/1 | x |
| x/(-1) | Умножение с переполнением по модулю; MIN остаётся MIN |
| x%1, x%(-1) | 0, включая MIN%-1 |
| x AND -1, -1 AND x, x AND x | x |
| x AND 0, 0 AND x | 0 |
| x OR 0, 0 OR x, x OR x | x |
| x OR -1, -1 OR x | -1 |
| x XOR 0, 0 XOR x | x |
| x XOR x | 0 |
| Сдвиг x на доказанный int32 ноль | x |

Правила работают с готовыми SSA-значениями, а не переписывают исходный текст.
В `(a/b)*0` умножение можно заменить нулём, но деление остаётся: его ошибка
наблюдаема и при неиспользованном результате. Динамические преобразования big,
trace, каналы, владельцы и память сохраняют обработку по таблице эффектов.
Операнды не вычисляются повторно, производители не переносятся через ветвления.

При неизвестном делителе x/x, x%x и 0/x не упрощаются. Нулевое значение
сдвига не отменяет проверку неизвестного/неверного количества. Проверка
снимается только для доказанных ±1 или нулевого сдвига. Общие divide/mod/shift
по-прежнему имеют MAY_THROW. MIN/-1 не использует переполнение signed C.

Правила не относятся к binary64, динамическим AS-преобразованиям или ссылкам.
Например, замена `f64.add(-0,+0)` первым операндом превратила бы +0 в -0.
Прежние свёртки констант и упорядоченный floating CSE сохраняют свой контракт.

## Повторное использование и выдача результата

Локальный CSE теперь включает i32 AND/OR/XOR с одинаковыми операндами в том же
порядке. Переставленные операнды не канонизируются; границы базового блока не
пересекаются. Проверяемая арифметика с неизвестными входами не становится чистой.

Цикл с x/1, x%1 и x<<0 теперь может попасть в SWF **после явной оптимизации**,
поскольку эти операции исчезают. Исходный FIR по-прежнему получает отказ SWO
без замены существующего выходного файла там, где нет общего checked lowering.
Это не реализация динамического деления/остатка/сдвигов в SWF. Ограничения big
для backend сохраняются.

[Построчно объяснённый пример](../examples/integer-identities/main.b) возвращает
42 в raw/optimized NC64 Dis и после FIR → SWO → SWL → SWF → FlashVM. Переменная
цикла остаётся динамической на рёбрах CFG: результат не основан лишь на свёртке литералов.

## Владение, отладка и проверки

Проход синхронно меняет заимствованный проверенный FirModule, проверяет его
после fixed point и использует прежние отметки removed для печати/уплотнения.
FIRDBG1 описывает SSA до оптимизации; окончательная карта Dis/SWF PC не добавлена.
Нужно пересобрать согласованные библиотеки/заголовки и перелинковать сервисы.
Развёрнутая Dis IDE использует ту же библиотеку компилятора внутри процесса.

[Матрица](../tests/integer_identities.py) сравнивает raw/optimized Dis, MIN,
ошибки производителей/делителей/сдвигов, порядок и границы CSE, знак нуля.
Проверяются повторная оптимизация, сохранение выходного файла при отказе и
необязательное реальное исполнение связанного SWF. C99-проверка повторяет
компиляцию source/debug, снимки before/after, отказ raw и optimized object/Dis.
Счётчики подтверждают interpreter/JIT; владельцы таблиц/ключей должны освобождаться.
Linux и UBSan не подтверждают физическое исполнение ARM64/RV64 или других ОС.

Оптимизация в памяти сохраняет исходные SSA-идентификаторы. Печать и повторный
разбор убирают мёртвые определения и могут менять номера слотов и байты backend
без изменения поведения. Установленный C99-пример явно выполняет FIR_OPT →
канонический текст → backend, как CLI; побайтовое сравнение относится к этому
совпадающему пути. Прямой fir_run с optimise=1 проверяется отдельно, но не обязан
совпадать побайтно с текстовым round-trip.

## Целочисленные сравнения и удаление ветвей

Для одного вычисленного SSA-значения i32/big `x == x` превращается в true,
`x < x` — в false. Знаковые `x < MIN` и `MAX < x` дают false с учётом
разрядности. Сравнения с переставленными границами остаются динамическими.
Обычный проход CFG удаляет недостижимые ветви. Ошибки производителей
операндов сохраняются даже при константном результате сравнения. Анализ
диапазонов и рефлексивность float не добавлены: `NaN == NaN` остаётся false.

В [comparisons.b](../examples/integer-identities/comparisons.b) полностью
прокомментирован исходный пример с результатом 42. Проверки выполняют исходный
и оптимизированный Dis интерпретатором и JIT, а при подключённых тестовых
линкере и FlashVM — также оба варианта SWF. Отдельно проверяются MIN/MAX,
отрицательные значения, ноль, исключения производителей и IEEE NaN.
Это существующий NC64 backend, а не предлагаемый формат Dis64.

В этом примере счётчик выполнения уменьшился с 256 инструкций Dis
(255 native) до 160 (159 native), результат остался 42. Это число
инструкций, а не измерение ускорения по времени.
