# Управление циклом — компилятор FIR 0.37

[English](LOOP_CONTROL.md) · [Подробный пример](../examples/tables/loop-control.b) ·
[While и for-in](LOOPS.ru.md) · [Удержание присваиваний](TABLE_LEASES.ru.md)

Coco/R-профиль Limbo с результатом big теперь принимает внутри while/for-in
операторы if с необязательным else, цепочки else if, break, continue и ранний
return из функции. CLI и C99 API для IDE используют одну грамматику и lowering.

```limbo
sum := big 0;
for (key, value in entries) {
    if (typeof key == "string") {
        continue;
    } else if (value < 0) {
        break;
    }
    sum += value;
    if (sum == 42) {
        return sum;
    }
}
return sum;
```

Условия сохраняют типизированные сравнения, membership и ленивые &&/||. У каждой
ветки своя область имён. Видимые перед if инициализированные big-локальные
переводятся в доминирующие ячейки кадра. Исполняемая ветка изменяет эти ячейки,
последующие чтения видят актуальные значения. Локальные объявления ветки не
выходят наружу. Более поздние версии добавляют [типизированные ссылочные ячейки](RETAINED_LOOPS.ru.md),
[инициализацию через ветви](JOIN_INITIALIZATION.ru.md) и [первые записи в теле](LOOP_INITIALIZATION.ru.md).
Чтение без доказанной инициализации отклоняется. Изменять элементы таблиц можно;
присваивания сохраняют прежние удержания на вычисление RHS и запись.

Break выходит из ближайшего цикла. Continue возвращает к тесту ближайшего while
либо сначала продвигает курсор ближайшего for-in и затем проверяет следующий
ключ. У вложенных циклов независимые цели переходов. Return проверяет тип big
и выходит из функции, не продвигая курсор. В текущем исполняемом учебном формате
каждый return имеет собственную пару trace/признак исполнения.

Переход закрывает свой путь CFG. Если обе ветки завершаются переходом, лишний
недостижимый join не создаётся. Если одна ветка продолжается, продолжение связано
только с ней. For-in не создаёт ненужный шаг курсора, когда все пути тела выходят
без continue. Операторы после безусловного перехода, в том числе после if с двумя
закрытыми ветками, дают явную ошибку. Переход не может разорвать последовательность
lock/RHS/store/unlock одного исходного присваивания.

Вложенность управления использует общий лимит парсера в 64 уровня вместе со
скоупами и выражениями. Условие разбирается до занятия уровня тела. Смешанные
while/for/if не переполняют массивы отладочных областей и рекурсивный разбор.
События debug JSON break, continue, loop-if, loop-return указывают на конкретное
вхождение ключевого слова. Полная генерация SBL исходник—Dis остаётся отдельно.

Исправлено восстановление окружения между терминальными ветками функции:
теперь вместе с SSA-привязками сохраняются и восстанавливаются идентичности
big-ячеек. Раньше while в первой ветке мог заставить соседнюю ветку использовать
ячейку, определённую только на первом пути: FIR отклонял недоминирующий операнд.
Регрессия воспроизведена на прежнем компиляторе; оба выбора ветки теперь работают.
Это исправление расширенного frontend FlashVM, в Inferno оно не переносится.

Команды приведены в English-версии. Пример фильтрует таблицу, останавливается на
сумме 42 и проверяет while-переходы. Эталон печатает 42; VM показывает 42,0,1,0
и нулевые счётчики таблиц/ключей. Проверяются исходный/оптимизированный FIR,
интерпретатор/JIT, quantum 1/2048, закрытые ветки, продвижение курсора, ближайший
цикл, ранний return, скопы, позиции и ошибки без замены готового результата.
SDK компилирует тот же пример заново слинкованным C99-клиентом.

Новых типов FIR, opcode Dis и тегов файла нет. Вне циклов пока сохраняется прежний
синтаксис терминального ветвления функции; общие нетерминальные if на верхнем
уровне и именованные переходы пока отдельно.
[Компилятор 0.38](COUNTED_FOR.ru.md) добавляет трёхчастный for.


[Компилятор 0.41](FUNCTION_FLOW.ru.md) распространяет структурированные условия и блоки на уровень функции.
