# Счётные числовые циклы — FIR 0.58 / CLI 0.25

[English](NUMERIC_FOR.md) · [Числовой CFG](NUMERIC_FLOW.ru.md) · [Синтаксис](SOURCE_SYNTAX.ru.md) · [Пример int](../examples/dis/numeric-for-int.b) · [Пример real](../examples/dis/numeric-for-real.b) · [Вложенные области](../examples/dis/numeric-for-nested.b)

Однородные функции Limbo int/real поддерживают счётный for и постфиксные обновления
как отдельные операторы. CLI и библиотека используют одну грамматику Coco/R.
Сохраняется ограниченный вход value(); полный ABI функций/модулей и числовой
snapshot for-in этим не вводятся.

## Заголовок и порядок исполнения

```limbo
sum := 0; # Keep an outer accumulator across all loop edges.
for (i := 0; i < 10; i++) { # Initialize once, test before body, step after it.
    if (i == 3) { continue; } # Skip three, but execute the header step.
    if (i == 8) { break; } # Exit before summing eight or running the step.
    sum += i; # Sum precisely the seven contributing indices.
} # Retire header i while preserving outer sum.
return sum + 17; # Return twenty-five plus seventeen: forty-two.
```

Инициализатор выполняется один раз. Условие bool проверяется перед каждым входом
в тело, включая первый. Обычное завершение тела выполняет шаг один раз и снова
проверяет условие. Continue ведёт к шагу, break и return пропускают его. Во
вложенных while/for переход относится к ближайшему циклу. Пример складывает
0, 1, 2, 4, 5, 6, 7 и возвращает 42. Real использует тот же граф с binary64.

Каждую часть заголовка можно опустить, но обе точки с запятой и фигурные скобки
обязательны. Отсутствующее условие означает true. Анализ возврата остаётся
консервативным: открытое продолжение после цикла требует return даже при for(;;).
Недостижимый суффикс после break/continue/return отвергается.

| Позиция | Допустимая часть | Действие |
| --- | --- | --- |
| Инициализатор | Инициализированное явное/выводимое объявление, присваивание, составное или постфиксное обновление | Один раз перед тестом |
| Условие | Выражение существующего числового профиля, возвращающее нормализованный bool | Повторно на каждом обратном ребре |
| Шаг | Присваивание, составное или постфиксное обновление | Только после обычного тела/continue |
| Тело | Структурные числовые операторы, вложенные циклы и блоки | Вложенная лексическая область |

В инициализаторе и шаге допускается по одному оператору. Списки через запятую,
псевдонимы типов в заголовке, неинициализированные объявления, префиксные обновления
и обновления внутри выражений не поддерживаются. Обычные x++/x-- также допустимы
как отдельные операторы. Значения выражения они не создают. Прибавляется или
вычитается точная единица выбранного типа: int оборачивается по модулю 2^32,
real использует binary64, включая знаковый ноль и NaN. Неявных преобразований
целочисленных литералов в real не добавлено.

## Области видимости и отложенный шаг

Область заголовка видна условию, шагу и телу. У числового тела отдельная вложенная
область: локальный i может затенить i заголовка, но отложенный шаг продолжает
обновлять исходную переменную заголовка. После цикла обе локальные области
заканчиваются. Изменения внешних переменных сохраняются; пространства имён
псевдонимов и значений остаются раздельными.

Активные значения помещаются в приватные i32.slot/f64.slot согласно NUMERIC_FLOW.
Шаг разбирается один раз во временный поток. Перед разбором тела восстанавливаются
входные факты о переменных. Шаг публикуется в отдельном блоке, только если к нему
ведёт обычное завершение или continue. Полностью завершающееся break/return тело
не публикует недостижимые инструкции и debug-сайты шага. Вложенные циклы владеют
разными потоками; ошибки и следующий библиотечный вызов освобождают незавершённое
состояние. Прежние ограничения SSA, блоков и глубины сохраняются. Лексическая глубина
проверяется отдельно: заголовок и тело требуют две области при одном спуске
парсера. После ошибки вход/выход областей замораживается до сброса состояния,
чтобы восстановление не индексировало непринятого владельца.

Новых enum FIR, форматов кадров, опкодов Dis и действий SWF нет. Действуют прежние
проверки, эффекты и оптимизация числовых ячеек. Граф исполняется существующим Dis
интерпретатором/JIT и через AVM1 SWO/линкер. Ограничения backend сохраняются:
checked-деление, остаток и сдвиги int могут требовать Dis, в том числе в заголовке;
отказ SWF не заменяет уже существующий выходной файл.

FIRDBG1 сохраняет UTF-8 смещения. Историческое событие while-test обозначает тест
for, for-end — выход, binary для ++/-- указывает на двухбайтовый оператор.
Отложенные события шага следуют после событий тела в порядке испускаемого CFG.
Это позиции исходника/FIR; итоговые карты Dis/SWF/native PC остаются отдельным этапом.

## Примеры и библиотека

Команды сборки FIR, оптимизации, Dis, исполнения в двух режимах и линковки SWF
приведены в [English](NUMERIC_FOR.md#build-run-and-embed). Пример real возвращает
42.5: биты 4631178160564600832 и executed flag 1. Примеры int и nested возвращают
42. Для нескольких trace-сайтов нужно читать удвоенное число сайтов и проверять
ровно один выполненный флаг. Каждая непустая строка примеров подробно прокомментирована.

Перенесённый SDK заново линкует C99-клиент, сравнивает его Dis с CLI и исполняет
сырой/оптимизированный real for интерпретатором и JIT. Библиотечный путь прежний:
fir_source_debug, fir_parse/fir_verify, при необходимости fir_optimise, затем
fir_dis/fir_object. Библиотеки и заголовки следует пересобрать согласованно.
Тест numeric_for_api.c перемежает 16 успешных компиляций и 32 семантических отказа
с сохранением позиций FIR/debug-потоков. numeric_flow.py независимо проверяет
малые суммы, вложенность, затенение, int wrap, знаковый ноль, переходы и пропуск
ошибочного шага в Dis, а также точные runtime-capture до и после оптимизации.
