# Ленивые числовые условия — FIR 0.55 / CLI 0.22

[English](NUMERIC_LOGIC.md) · [Упорядоченный real](REAL_CONDITIONS.ru.md) · [Покрытие](COVERAGE.ru.md) · [Limbo с построчными комментариями](../examples/dis/numeric-logic.b) · [Bool-ячейки FIR](../examples/dis/numeric-logic.fir)

Однородные функции Limbo `value(): int` и `value(): real` принимают составные
условия завершающего `if/else`. Каждая ветвь по-прежнему обязана вернуть значение.
Парсер строится из читаемой грамматики Coco/R; CLI и библиотека вызывают одни
семантические действия. Профиль `big` сохраняет прежний расширенный синтаксис.

| Конструкция | Поведение |
| --- | --- |
| `a < b && c < d` | Правая часть исполняется только при истинной левой |
| `a == b || c == d` | Правая часть исполняется только при ложной левой |
| `!(a <= b)` | Отрицание уже нормализованного bool, включая unordered real |
| `a < b || c < d && e < f` | `&&` связывает сильнее `||` |
| `(a + b) < c` | Скобки внутри числового операнда сохраняют обычное значение |

У каждой арифметической стороны остаются прежние строгие типы. Числовой истинности,
присваивания bool числовой переменной, неявных преобразований int/real и общего
модульного ABI не добавлено. В этом ограниченном профиле отрицание условия пишется
именно `!(...)`; обычная булева группировка без `!` и отдельное `!a` пока не
поддерживаются. Это явно ограниченный исходный профиль, а не вся грамматика Limbo.

## Вычисление, ошибки и отладочные позиции

Операнды отношений вычисляются однократно слева направо. Ленивый оператор создаёт
ветвь до генерации правой части. Поэтому `1 == 1 || 1 / 0 == 0` возвращает истинное
условие без ошибки, а `0 == 1 || 1 / 0 == 0` исполняет проверяемое деление и завершается
ошибкой. Это проверяется C99-эталоном и настоящим Dis в обоих режимах, до и после
оптимизации. SWF-поддержка проверяемого целочисленного деления этой серией не расширена.

`!(NaN <= x)` истинно, хотя `NaN > x` ложно: отрицание не заменяется обратным
упорядоченным отношением. `&&`/`||` возвращают нормализованный bool. Каждая внутренняя
ячейка имеет тип `bool.slot`, инициализируется false и хранит только bool; handles
ячеек не копируются, не выводятся и не передаются по каналам. Скаляры не становятся
корнями GC. В SWF ячейка — переменная с объектным пространством имён; отдельного
heap-owner или нового тега контейнера нет.

FIRDBG1 сохраняет исходные UTF-8-диапазоны отношений и ленивых операторов. Синтетические
store/load относятся к исходному оператору. Это позиции исходного неоптимизированного
FIR, а не завершённая карта окончательных SWF/Dis/JIT PC. Общие бюджеты SSA, блоков
и глубины 64 ограничивают вложенность; отказ сохраняет прежние файлы. Несколько
компиляций через C API требуют сериализации вызывающей стороной; библиотека блокирует
свой вызывающий поток и не запускает отдельный worker IDE.

## Пример и воспроизведение

Из корня репозитория после сборки соответствующих инструментов:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/dis/numeric-logic.b build/logic.fir -g build/logic.json
build/fir/fir1 opt build/logic.fir build/logic.opt.fir
build/fir/fir1 dis build/logic.fir build/logic.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 4 build/logic.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 4 build/logic.dis
build/fir/fir1 object build/logic.fir build/logic.swo
build/linker/swl link build/logic.swf build/logic.swo
```

В исходном примере результат первой ветви равен точно 42.5: его binary64-биты
4631178160564600832, второй слот нулевой, флаги исполнения 1/0. После оптимизации
ориентируйтесь на число оставшихся trace. Для `numeric-logic.fir` пропустите source
стадию: три значения false/true/false и три флага 1/1/1. SWF trace может показывать
булевы значения словами; точные биты чисел проверяются через Dis. Построчные комментарии
объясняют все непустые строки обоих примеров.

## Приёмка

`numeric_logic.py` проверяет 64 тройки/формы условий для int/real, оба порядка приоритетов,
вложенное отрицание, ленивые ошибки, NaN, арифметические скобки, позиции операторов,
отказы типов/лимитов и сохранность output. Для каждого принятого случая проверяются
сырой и оптимизированный FIR. При явно переданных runtime/режиме проверяются реальные
счётчики interpreter/JIT, биты, флаги и освобождение owners. При FIR_SWL и
FIR_FLASHVM_RUNNER проверяется настоящий связанный SWF. Отдельный C99-клиент выполняет
16 компиляций библиотеками; перенесённый SDK сравнивает CLI/library Dis и запускает
этот учебник. Физическая ARM64, полный Limbo и панели Build/Run/Debug IDE остаются
отдельной работой.
