# Сравнения как значения и логическое отрицание — компилятор 0.23

[English](COMPARISON_VALUES.md) · [Комментированный пример](../examples/tables/comparisons.b) ·
[README примеров](../examples/tables/README.ru.md) · [Лексические ветви](TERMINAL_ARMS.ru.md)

Coco/R-профиль Limbo big/table принимает сравнения как выражения, а не только
условия терминальной ветви. Неявно объявленные переменные сохраняют тип bool:

```limbo
ascending := document.low < document.high;
descending := document.low >= document.high;
consistent := ascending == !descending;
return big consistent;
```

Представление runtime и теги контейнеров не меняются. CLI и C99 API используют
одни грамматику и семантические действия. Это расширение компилятора FlashVM;
изменения языка в Inferno не переносятся.

## Типы и порядок вычисления

| Операнды | Допустимые отношения | Результат |
| --- | --- | --- |
| big / big | `<`, `>`, `<=`, `>=`, `==`, `!=` | bool |
| int / int | `<`, `>`, `<=`, `>=`, `==`, `!=` | bool |
| bool / bool | `==`, `!=` | bool |

Смешанные типы, упорядочивание bool, равенство строк/таблиц и неявная истинность
отвергаются статически. `!` принимает только bool. Числовые типы согласовываются
явными cast. Ключевого слова объявления bool в этом ограниченном профиле пока
нет; результаты сравнений, membership и delete можно выводить, копировать и
преобразовывать существующими int/big/string. `typeof` называет bool `"int"`
по принятому соглашению Limbo; в FIR bool остаётся отдельным типом.

Операнды вычисляются ровно один раз, слева направо. Выражение
`big (delete t.a) != big (delete t.a)` наблюдает успешное удаление, затем отсутствие.
Атомарность операций с владельцем этим не добавляется. Ошибки остаются eager:
неиспользуемое `big "bad" < 1` всё равно вызывает ошибку до и после оптимизации.

## Приоритеты сверены с Inferno

Уровни сравнений соответствуют `limbo/limbo.y` ветки experiment. Выше в таблице —
более сильный приоритет.

| Уровень | Операции |
| --- | --- |
| Унарные/postfix | существующие cast, индексирование и `!` |
| Произведение, сумма | `* / %`, затем `+ -` |
| Сдвиг | `<< >>` |
| Упорядочивание | `< > <= >=` |
| Равенство | `== !=` |
| Побитовые | `&`, затем `^`, затем `|` |
| Расширение FlashVM | `in` |

`1 < 2 == 3 < 4` сравнивает два bool. `1 & 3 < 4` — ошибка типов, поскольку
сравнение сильнее `&`; нужная операция задаётся скобками или явным преобразованием.
Для отрицания membership пишите `!(key in table)`. Равенство ассоциируется слева;
цепочка упорядочивания отвергается при попытке сравнить bool с числом.
Короткозамкнутые `&&`/`||`, общие смешанные сравнения и исходные циклы пока
не реализованы. Полная поддержка выражений Limbo или AS не заявляется.

## FIR, Dis и диагностика

Используются существующие `big.lt.signed`, `big.eq`, скалярные преобразования
и константы. Однотипные int расширяются в big точно. Равенство bool расширяет
нормализованные значения; обратные отношения и `!` сравнивают их с нулём.
Новых номеров операций FIR, native opcode и импортов Bigtable нет. Dis BLTL/BEQL
материализуют bool без float, включая соседние целые выше 2^53 и знаковые границы.

Чистые сравнения можно сворачивать и переиспользовать. Проверяемые преобразования
и изменения памяти сохраняют эффекты и порядок. В sidecar остаются точные байты
исходных операторов, в том числе после UTF-8-префиксов. Вспомогательные операции
сохраняют позицию оператора. Исчерпание SSA-лимита не превращается в выход за
границу массива типов при материализации обратного сравнения. Ошибки сохраняют
старые файлы FIR и sidecar.

## Запуск

Из корня репозитория после сборки FIR и runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/comparisons.b build/comparisons.fir -g build/comparisons.json
build/fir/fir1 opt build/comparisons.fir build/comparisons-opt.fir
build/fir/fir1 dis build/comparisons.fir build/comparisons.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/comparisons.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/comparisons.dis
```

Значения: `42, 0`; признаки выполнения: `1, 0`. Перемещённые C99 SDK-клиенты
проверяют исходный/оптимизированный FIR в обоих режимах VM. Тестируются все шесть
отношений, границы, типы, приоритеты Inferno, порядок мутаций, eager-ошибки, лимиты
и UTF-8-позиции. Эмуляция ARM64 не заменяет аппаратные испытания и полную проверку
IDE/отладчика.
