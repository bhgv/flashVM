# Составные обновления с захватом назначения — компилятор 0.25

[English](COMPOUND_UPDATES.md) · [Комментированный пример](../examples/tables/compound.b) ·
[README примеров](../examples/tables/README.ru.md) · [Ленивые выражения](SHORT_CIRCUIT.ru.md)

Coco/R Limbo big/table-профиль принимает операторы `+=`, `-=`, `*=`, `/=`, `%=`,
`&=`, `|=`, `^=`, `<<=`, `>>=` для инициализированных big-локальных и элементов
таблицы. Работают точки, числовые/строковые индексы и ключи неизменяемых снимков.
Написание операторов сверено с Inferno; порядок захвата для гибридных таблиц
ниже — явный контракт расширения FlashVM.

```limbo
answer := big 40;
answer += 2;
entries[keys[0]] ^= big 3;
entries.answer <<= int 1;
```

## Типы и арифметика

Арифметические/побитовые формы требуют старое big и RHS big. Сдвиги требуют
старое big и явный RHS int в диапазоне 0..63. Литералы этого профиля — big,
поэтому `x <<= 1` является ошибкой типов; пишите `x <<= int 1`.
Отдельные однородный int- и AS-профили сохраняют прежнее покрытие операторов.
Конкатенация строк, составные bool, возведение в степень, ++/-- и присваивания
как значения выражений здесь не добавлены.

Сложение/вычитание/умножение/побитовые big работают по модулю 2^64. Деление
усекает к нулю; MIN/-1 возвращает MIN, MIN%-1 — ноль. Нулевой делитель вызывает
ошибку. Правый сдвиг арифметический. Преобразования через binary64 нет.
Арифметика использует прежние операции и типы. Для автоматического удержания
добавлены FIR table.lock/unlock и импорты Bigtable; opcode Dis и теги файлов прежние.

## Порядок захвата и записи

1. Один раз разрешаются локальная привязка либо владелец таблицы и ключ.
2. Для составного обновления старое big читается до вычисления RHS.
3. RHS вычисляется один раз с обычными вызовами, изменениями и ленивым CFG.
4. Новое big вычисляется и записывается только при успешном завершении.

Обычное `=` не читает старое значение и может вставлять отсутствующий ключ либо
инициализировать типизированную локальную. Составной оператор требует имеющееся
значение. Отсутствие старого ключа проверяется до ошибочного cast/деления RHS:
`t.missing += 1/0` сообщает missing key.

Захваченное место — capability владелец/ключ, а не адрес payload.
`t.answer += big (delete t.answer) + 1` сначала читает старое значение, удаляет
ключ в RHS, затем вставляет old+2. Получатель и ключ с побочными эффектами не
вычисляются повторно. Проверяемые карты корней удерживают владельцев/снимки
через выделения RHS и кванты GC/планировщика по инструкции. При ошибке финальная
запись не выполняется; уже совершённые независимые эффекты RHS не откатываются.

Таблица назначения теперь [удерживается локально](TABLE_LEASES.ru.md) на время
вычисления ключа, чтения старого значения, RHS и итоговой записи. Конкурирующие
операции над её данными не вклиниваются внутрь этого участка. Уже выполненные
эффекты не откатываются. Удалённый compare/exchange, транзакции нескольких
объектов и общие протоколы обновления проекций остаются отдельной работой.

## FIR, оптимизация и диагностика

Используются существующие table.index/load/store, арифметика и проверяемые сдвиги.
Локальные меняют текущую SSA-привязку. Место и старое значение захватываются до
инструкций RHS. Флаги MAY_THROW/памяти сохраняют порядок ошибок и мутаций;
оптимизатор не дублирует удаляющее выражение ключа. Ленивый RHS сохраняет свои
ветви/ячейки соединения до итоговой составной записи.

События арифметики/сдвигов указывают на точные байты составных операторов,
включая трёхбайтовые <<= и >>= после UTF-8-префиксов. Доступ к локальному имени
сохраняет его область-владельца. Ошибки типов/синтаксиса/лимитов сохраняют старые
FIR/sidecar. CLI и C99 API используют одну реализацию. Гибридная таблица остаётся
расширением FlashVM и не переносится в язык Inferno.

## Запуск

После сборки FIR и runtime из корня репозитория:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/compound.b build/compound.fir -g build/compound.json
build/fir/fir1 opt build/compound.fir build/compound-opt.fir
build/fir/fir1 dis build/compound.fir build/compound.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/compound.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/compound.dis
```

Значения: `42, 0`, затем флаги выполнения `1, 0`. Перемещённые свежие C99-клиенты
проверяют исходный/оптимизированный учебный код и оба настоящих режима VM.
Проверяются десять операторов, все виды ключей, знаковые границы, псевдонимы,
побочные эффекты ключа/RHS, ленивая RHS, приоритет ошибок, отказы типов и точные
UTF-8-позиции. Аппаратное исполнение ARM64 и полная интеграция IDE/отладчика
остаются отдельной работой.
