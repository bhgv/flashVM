# Трёхчастный for и постфиксные обновления — компилятор FIR 0.38

[English](COUNTED_FOR.md) · [Подробный пример](../examples/tables/counted-for.b) ·
[Переходы в цикле](LOOP_CONTROL.ru.md) · [Обход снимка](LOOPS.ru.md)

Coco/R-профиль Limbo с результатом big теперь принимает обычный for из трёх секций
наряду с for-in. CLI и библиотечный C99-компилятор используют общий lowering.

```limbo
sum := big 0;
for (index := big 0; index < 100; index++) {
    if (index % 2 != 0) { continue; }
    if (index == 14) { break; }
    sum += index;
}
return sum;
```

Инициализация выполняется один раз. Условие проверяется перед каждой итерацией.
Шаг выполняется после нормального завершения тела и при continue ближайшего
цикла — ровно один раз. Break и return обходят шаг. Любую секцию можно пропустить;
пустое условие означает типизированную истину. Вложенные while/for/for-in сохраняют
независимые цели переходов. Секция содержит одно присваивание/обновление или delete;
списки через запятую и объявления в секции шага пока не принимаются.

Инициализатор и тело имеют одну локальную область. Инициализатор может затенить
внешнее имя; внутреннее имя исчезает после цикла и не переобъявляется в его теле.
Присваивание ранее объявленной внешней big-переменной продолжает менять её.
Локальные объявления тела можно нормально переназначать; переносимые между
итерациями инициализированные big сохраняются в ячейках кадра. В [0.39](TYPED_LOOPS.ru.md) добавлены ячейки int/bool; для переносимых
ссылок по-прежнему нужны отдельные типизированные ячейки.

Операторы name++, name--, table[index]++, точечные поля и ключи снимка работают
с big. Receiver и ключ вычисляются один раз. Запись в таблицу удерживает блокировку
от чтения старого значения до точной модульной арифметики и store. Это отдельные
операторы, не выражения с возвращаемым старым/новым значением. Префиксные формы,
строки и диапазоны не добавлены. Обновления int появились в 0.39. Приведения Limbo остаются
big/int/string; команды to... относятся к отдельному расширению AS.

Шаг разбирается и проверяется в заголовке, но его FIR сохраняется во временном
потоке. После тела компилятор помещает его в отдельный блок шага с обратным
переходом к тесту. Если все пути тела выходят без continue, этот блок не достижим
и его FIR отбрасывается. Неиспользуемый шаг всё равно проверяется синтаксически
и по типам; компиляция не исполняет его арифметику.

Отладочные origins шага тоже откладываются. Публикуются только записи реально
выведенного FIR, в его порядке и с последовательными site-ID. У отброшенных
значений нет висячих событий. value=N обозначает имя %vN, а не индекс массива
внутри позже разобранного или оптимизированного модуля. Позиции остаются позициями
заголовка, хотя шаг исполняется после тела. При завершении запроса освобождаются
все потоки и копии origins, включая синтаксические/семантические ошибки.
C99-тест чередует успешные запросы с ошибками внутри захвата шага и проверяет
сохранность прежнего FIR/debug результата.

Новых типов FIR, native-импортов, opcode Dis и форматов файла нет. Расширение
остаётся в FlashVM и не переносится в Inferno. Полные компиляторы общего Limbo/AS
и окончательная релокация SBL исходник—Dis остаются отдельной работой.

Команды приведены в English-версии. Эталон печатает 42, VM показывает 42,0,1,0
и нулевые счётчики владельцев. Проверяются исходный/оптимизированный FIR,
интерпретатор/JIT с quantum 1/2048, пустые секции, вложенные виды циклов,
неисполняемые ошибочные шаги, большие и переполняющиеся big, однократное вычисление
ключа, области видимости и полнота debug-ID. SDK компилирует тот же пример
заново слинкованным C99-клиентом.


В [версии 0.39](TYPED_LOOPS.ru.md) добавлены ячейки int/bool, постфиксные
обновления int и обход строк/снимков ключей.
