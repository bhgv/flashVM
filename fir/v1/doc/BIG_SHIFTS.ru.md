# Типизированные int-cast и проверяемые сдвиги big — FIR 0.20 / runtime 0.23

[English](BIG_SHIFTS.md) · [Комментированный Limbo](../examples/tables/shifts.b) ·
[Арифметика big](BIG_ARITHMETIC.ru.md) · [Владельцы в CFG](TABLE_CFG.ru.md)

Наш big-профиль Coco/R принимает `<<`, `>>`, явный `int expr` и локальные int
для счётчиков. Big остаётся точным знаковым 64-битным значением; int сохраняет
установленный i32-контракт нашего компилятора, хотя NC64 хранит native WORD
в восьмибайтовой ячейке. ABI native WORD Inferno не меняется; полная зависимая
от цели семантика int Limbo здесь не заявляется.

Числовые литералы этого ограниченного профиля остаются big. Пишите `a << int 3`
либо объявляйте `n: int = int 3;` и используйте `a << n`. Big-счётчик без явного
преобразования отклоняется. Остальная арифметика требует big-операнды: для суммы
счётчика используйте `int (1 + 2)`, а не смешанное `int 1 + 2`.

## Точная семантика

`int expr` принимает int/big, сохраняет младшие 32 бита и интерпретирует их со
знаком. `int 4294967295` = -1, `int 4294967296` = 0. Преобразование полное и
чистое. Явный `big` расширяет знаковое int-значение; `string` форматирует его,
`typeof` возвращает `int`. Элементы таблиц и числовые ключи по-прежнему big:
для записи/индексации int надо явно расширить. Разбор text/real/key в int и
неявная смешанная арифметика здесь не добавляются.

Счётчик должен попасть в 0..63 **после** явного преобразования. Ошибка —
`invalid argument`, без маскирования modulo 64, включая неиспользуемый результат
после opt. Левый сдвиг работает над unsigned 64-битными битами с wrap; правый
арифметический, с распространением знака. Нулевой счётчик сохраняет значение.
MIN >> int 63 = -1, 1 << int 63 = MIN.

Приоритет совпадает с опорной грамматикой Limbo: unary/cast, произведения,
суммы, сдвиги, AND, XOR, OR. Сдвиги левоассоциативны; группы переопределяют
приоритет. Терминальные сравнения принимают полные big-выражения. Debug-origin
сдвига охватывает два байта оператора, int-cast — три байта префикса.

## FIR, оптимизация и нативный код

Без перенумерации добавлены `value.int` (i32/i64 → i32), `big.shl`/`big.shr`
(i64/i32 → i64). Verifier проверяет типы, арность и доминирование. Int-cast чист;
сдвиги сохраняют MAY_THROW, поэтому ошибочная неиспользуемая операция не исчезает
и не объединяется как pure CSE. Константный сдвиг сворачивается только при
допустимом счётчике. Правый сдвиг в folding/reference использует unsigned-биты
и явное заполнение знака: нет shift by 64 и undefined signed-left-shift.

Прямой скалярный CFG и hosted DAG таблиц используют прежние SHLL/SHRL (127/128).
Нормализация int: маска low bits, XOR знакового бита, вычитание. Константы
не помечены GC-указателями; скалярные копии не используют MOVP. Новых Dis opcodes
и runtime arithmetic helpers нет.

Hosted reflection добавляет kind 4 = int; значения 0..3 сохранены. Для нового
тега нужен соответствующий Bigtable; старая реализация отклонит неизвестный
kind. Сигнатуры функций и пространства ключей не меняются. Проверенная пара —
компилятор 0.20/runtime 0.23. Это расширение не переносится в Inferno.

## Запуск и проверки

Из корня после независимой сборки компилятора/runtime:

```sh
mkdir -p build/tmp
export TMPDIR="$PWD/build/tmp"
build/fir/fir1_source limbo --input fir/v1/examples/tables/shifts.b build/shifts.fir -g build/shifts.json
build/fir/fir1_table_run build/shifts.fir
build/fir/fir1 dis build/shifts.fir build/shifts.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 4 build/shifts.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 4 build/shifts.dis
```

Reference печатает 42; native-ячейки: `42, 0, 1, 0`. Вторая точка возврата не
исполнена. Оба переносимых SDK заново линкуют C99-клиенты и запускают пример.
Проверяются все счётчики 0..63 на runtime-loaded знаковых границах, числа выше
2^53, int-копии, настоящие opcodes, приоритеты, cast/reflection, ошибочные
счётчики до/после opt, неверные типы публичного FIR и сохранение старого output.
UBSan проверяет компилятор/folding/reference. Native AMD64 и эмуляция ARM64 не
означают испытаний физического ARM64.
