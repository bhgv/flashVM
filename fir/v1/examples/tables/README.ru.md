# Пример нативных гибридных таблиц

[English](README.md) · [Исходник Limbo](main.b) ·
[Контракт отражения/приведений](../../doc/TYPE_REFLECTION.ru.md) ·
[Владение в Dis](../../doc/TABLES_DIS.ru.md)

main.b — полный модуль для нашего Coco/R-профиля с результатом big. Все операторы
снабжены комментариями. Показаны плотные/разреженные числовые ключи, строковые поля,
псевдонимы, независимые срезы и снимки, удерживаемые ключи, typeof и стандартный
синтаксис приведений big/string Limbo. Результат равен 42.

Из корня рабочего пространства, после сборки компилятора 0.16/runtime 0.19:

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/tables/main.b tables.fir -g tables.debug.json
build/fir/fir1 check tables.fir
build/fir/fir1 opt tables.fir tables.opt.fir
build/fir/fir1_table_run tables.opt.fir
build/fir/fir1 dis tables.opt.fir tables.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 2 tables.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 2 tables.dis
```

Необязательный эталонный C-исполнитель печатает 42. Dis возвращает DATA 0 42 и
DATA 8 1; вторая ячейка отмечает исполнение trace. quantum=1 проверяет GC между
инструкциями. Генерация программы не использует старый компилятор. Сборка хоста
пока применяет явный bootstrap для ABI нативных модулей и обычных Limbo-сервисов.

compile.c — C99-клиент парсера/Dis-эмиттера, client.c встраивает эталонный исполнитель.
Они используют согласованные публичные заголовки/архивы и промежуточный вывод,
описанный в комментариях исходников. SDK содержит эти файлы и связанные руководства;
его тест компилирует/исполняет модуль и заново линкует отдельный C99-клиент.

Ключ снимка удерживает независимого владельца после замены локального снимка.
Приведение string явно копирует значение: числовой ключ 7 становится строковым
"7", то есть меняется пространство ключа. typeof не выполняет преобразования.
Десятичные приведения сохраняют все signed-64 биты и отклоняют неверный текст
или переполнение.

Не реализованы автоматические канальные any/прокси-локальные, общие модули Limbo,
произвольные типы элементов, табличные CFG/циклы и генерация SWF для таблиц.
AS-хелперы преобразований отделены от cast-синтаксиса Limbo. Debug JSON указывает
на исходные позиции FIR; полное соответствие исходник—Dis SBL остаётся отдельной работой.

[arithmetic.b](arithmetic.b) показывает знаковое оборачивание, отрицание и нативную арифметику big над чтениями таблицы. [Контракт](../../doc/BIG_ARITHMETIC.ru.md).

[bitwise.b](bitwise.b) проверяет знаковое деление/остаток и полные маски над чтениями во время исполнения. [Контракт](../../doc/BIG_BITWISE.ru.md).

## Точное деление и остаток

[division.b](division.b) читает операнды из изменяемой таблицы: MIN/-1 даёт MIN
с нулевым остатком; -17/5 усекается к -3, остаток равен -2. Выбранная ветвь
восстанавливает делимое и возвращает точно 42. Другая ветвь делит на ноль и
не должна исполняться. Все существенные строки подробно прокомментированы.
Проверка установленного SDK исполняет исходный и оптимизированный FIR в эталоне,
интерпретаторе и JIT, с разрешённой сборкой мусора на каждом шаге.
[Контракт арифметики big](../../doc/BIG_ARITHMETIC.ru.md).

## Наличие, удаление и число всех записей

[mutation.b](mutation.b) — построчно комментированный пример новых countof/in/delete.
Он сохраняет существующий ноль, создаёт алиас и независимый snapshot, удаляет
через snapshot-ключ и повторяет удаление. Возвращается 42; len видит дырку в
числовом префиксе, countof — две оставшиеся записи. Невыбранная ветвь намеренно
читает отсутствующее значение. [Полный контракт и команды](../../doc/TABLE_MUTATION.ru.md).
SDK проверяет исходный/оптимизированный FIR через свежие C99 API-клиенты и оба
режима VM; отдельно проверяются значения и флаги исполнения ветвей.

## Лексические терминальные ветви

[arms.b](arms.b) возвращает 42 в обеих ветвях. Пример показывает чтение внешнего
имени до затенения, отложенную типизированную инициализацию, локальные таблицы
и псевдонимы, переназначение внешнего владельца. Все ветви завершаются возвратом;
слияния SSA нет. [Семантика и команды запуска](../../doc/TERMINAL_ARMS.ru.md).

## Сравнения как значения

[comparisons.b](comparisons.b) возвращает 42: точные числа из таблицы выше 2^53,
сохранённые bool-сравнения, логическое отрицание, сравнение int и локальная ветвь.
Проверяются исходный/оптимизированный FIR и оба режима VM.
[Семантика, приоритеты и команды](../../doc/COMPARISON_VALUES.ru.md).

## Короткое замыкание

[short-circuit.b](short-circuit.b) возвращает 42, защищая чтение отсутствующего
ключа и пропуская удаляющую RHS. Временная таблица для логического соединения
не создаётся: используются скалярные ячейки кадра и обычный Dis MOVW.
[Семантика, FIR-ячейки и команды](../../doc/SHORT_CIRCUIT.ru.md).

## Составные обновления

[compound.b](compound.b) показывает десять составных операторов через псевдоним
таблицы, ключ снимка и локальное big; результат 42. Сдвиги требуют int-счётчик.
Место и старое значение захватываются до RHS; транзакции/атомарность не добавлены.
[Контракт и команды](../../doc/COMPOUND_UPDATES.ru.md).

## Unicode-операции строк

[unicode.b](unicode.b) проверяет семь Unicode-скаляров, срез с emoji и сохранение
исходного псевдонима, затем преобразует числовой срез в 42. Строковые длины/индексы
имеют тип int; длины таблиц/ключей — big. Комбинируемый знак считается отдельно.
[Подробная семантика и команды](../../doc/UNICODE_STRINGS.ru.md).

## Int-арифметика и вычисляемые границы

[int-arithmetic.b](int-arithmetic.b) вычисляет Unicode-окно пятью int-операторами
и превращает срез в 42. Все результаты нормализуются в int32 даже на NC64;
литералы этого профиля требуют явного int.
[Семантика и команды](../../doc/INT_ARITHMETIC.ru.md).

## Подписи редактора и точные маски int (0.28)

[text-bits.b](text-bits.b) собирает Unicode-подпись редактора. Три составные
побитовые int-операции получают 42, явный string cast создаёт число в подписи.
Добавление emoji сохраняет старый алиас `line 42`. Равенство строк и ленивое
условие защищают срез с Unicode-границами, возвращающий 42; ложная ветка даёт 0.
Ожидаемые trace: 42/0, флаги: 1/0. Каждый шаг исходника комментирован.

[Подробное руководство и команды](../../doc/TEXT_BITS.ru.md) описывает эффекты
выделения, корни GC, нормализацию int, запрет смешанных типов и ограничения SWF.
Приёмка SDK проверяет пример через заново слинкованные C99 API и CLI, до/после
оптимизации, в интерпретаторе и JIT.
