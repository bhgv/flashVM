# Исполняемые псевдонимы типов Limbo

[English](README.md) · [Контракт](../../doc/SOURCE_ALIASES.ru.md) · [Скалярный пример](main.b) · [Гибридная таблица](table.b)

Нужны согласованные FIR 0.51 и DisVM 0.32.1. Команды выполняются из корня репозитория после сборки инструментов. Каждая непустая строка примеров снабжена пояснением. main.b показывает связывание в области объявления: Count остаётся int, хотя модуль позднее объявляет Base как real.

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/type-aliases/main.b build/aliases.fir -g build/aliases.debug.json
build/fir/fir1 check build/aliases.fir
build/fir/fir1 opt build/aliases.fir build/aliases.opt.fir
build/fir/fir1 dis build/aliases.opt.fir build/aliases.dis
build/runtime/disvm --no-jit --quantum 1 --inspect-words 0 2 build/aliases.dis
build/runtime/disvm --jit --quantum 1 --inspect-words 0 2 build/aliases.dis
build/fir/fir1 object build/aliases.opt.fir build/aliases.swo
build/swf-linker/swl link build/aliases.swf build/aliases.swo
```

Оба запуска Dis выдают DATA 0 42 и DATA 8 1. Второе слово отмечает выполнение trace. SWF выводит число через trace в хосте, показывающем этот вывод; открытое окно само по себе не проверяет результат. Здесь действует цепочка исходник → FIR → SWO → линкер → SWF. Команда dis использует существующий прямой бэкенд.

Для table.b повторите первые шесть команд с отдельным именем выходных файлов. Проверяются псевдонимы big, string и гибридной таблицы; результат также 42. Табличный бэкенд предназначен для Dis, а не числового SWF-профиля. Учебная обёртка value() не является полным ABI Inferno init.

Псевдонимы разрешаются до генерации FIR и не меняют представление данных во время исполнения. Опережающие ссылки в полном файловом/модульном префиксе поддержаны. Отклоняются неизвестные имена, циклы (включая неиспользуемые), дубликаты, более 128 псевдонимов и локальные переменные, затеняющие псевдоним. В модуле псевдонимы идут до value. Произвольные тела функций и импорты пока вне этого адаптера. У компилятора интерфейсов есть отдельный более широкий механизм связывания. Отладочные позиции сохраняют байтовые смещения UTF-8 исходника.

[casts.b](casts.b) показывает опережающий псевдоним результата и приведения через модульные псевдонимы. Повторите Dis-команды для этого файла: оба режима возвращают 42. I digits сначала разбирает signed64 и сужает результат до -1; Result расширяет его перед сложением. Некорректное десятичное значение вызывает ошибку даже при неиспользуемом результате; оптимизация сохраняет этот эффект. В однородных числовых профилях int/real разрешены только тождественные приведения. Профиль big/table использует существующие проверяемые преобразования int/big/string; приведение по имени таблицы не клонирует объект.

Затенение модульного/файлового имени в main.b — лексическое расширение FlashVM: нативный Inferno отвергает такое повторное объявление. Общая скалярная сверка без затенения описана в контракте.

## Учебный пример времени жизни владельцев — runtime 0.32.1

[gc-owners.b](gc-owners.b) удерживает удалённый строковый ключ в независимом снимке. За 64 итерации создаются форматированные строки, выполняется сужение int, ключи копируются в таблицу и удаляются. Наблюдаемая сумма — 1952, сохранённый ключ преобразуется в 42. Проверка countof, в отличие от длины плотной части len, подтверждает отсутствие словарных записей. Каждая непустая строка прокомментирована.

```sh
export TMPDIR="$PWD/build/tmp"
mkdir -p "$TMPDIR"
build/fir/fir1_source limbo --input fir/v1/examples/type-aliases/gc-owners.b build/gc-owners.fir -g build/gc-owners.json
build/fir/fir1 opt build/gc-owners.fir build/gc-owners.opt.fir
build/fir/fir1 dis build/gc-owners.opt.fir build/gc-owners.dis
build/runtime/disvm --jit --quantum 1 --stats --inspect-words 0 4 build/gc-owners.dis
build/runtime/disvm --no-jit --quantum 1 --stats --inspect-words 0 4 build/gc-owners.dis
```

Ожидаемые DATA по смещениям 0/8/16/24: **42, 0, 1, 0**. Последние два слова — флаги выбранного/невыбранного возврата. Stats должен показать tables_live=0 keys_live=0. Тест дополнительно проверяет многократный GC при quantum 1 и фактические счётчики native. Проверяются исходный и оптимизированный FIR, затем quantum 2048. Установленный SDK повторяет проверки после переноса пакета. Табличный пример предназначен для Dis; числовой путь SWF проверяется предыдущими примерами. Счётчики подтверждают освобождение табличных/ключевых владельцев хоста, но не считают отдельно каждую нативную String-аллокацию.

## Локальные области типов — компилятор 0.51

[local.b](local.b) объявляет Number и Result внутри value(), затеняет Number типами int и string в соседних блоках и объявляет Step в теле цикла. Результат — 42. Используйте приведённые выше Dis-команды с отдельными именами выходных файлов. Ожидаются DATA 0 42 и DATA 8 1. Этот пример со смешанными табличными выражениями предназначен для Dis; числовые локальные псевдонимы дополнительно проверяются тестами через SWF.

Локальный псевдоним немедленно разрешается по уже видимым объявлениям. Неизвестная опережающая локальная ссылка отклоняется; файловые/модульные опережающие ссылки сохраняются. Выход из блока удаляет его псевдонимы и восстанавливает родительское окружение. Объявление не создаёт значения, слота кадра или FIR-инструкции: typedef тела цикла компилируется один раз. Тип и значение не могут занимать одно имя в одной области. Локальные значения по-прежнему не могут затенять псевдонимы в этом ограниченном профиле. Псевдонимы в init/step заголовка for отклоняются; обычные типизированные значения там работают как прежде.

Предел 128 учитывает все объявления единицы трансляции, включая вышедшие из области видимости. Состояние не переносится в следующий запрос библиотеки после успеха или ошибки. Имена тела недоступны в сигнатуре функции: префикс разрешается раньше неё.
