# Пример контейнера Dis64 на C99

[English](README.md) · [Построчно объяснённый исходник](main.c) ·
[Контракт сборки/API](../README.ru.md)

Программа пишет явно указанный файл общими заголовками Dis64 и string pool.
Она создаёт lossless Rune record, сохраняет одинаковые строки под разными ID,
проверяет чтение и порядок, собирает четыре секции и проверяет каталог до
открытия выходного файла. Каждая строка кода объясняет действие или владение.

Метки M/C/T не являются исполняемым модулем. Инспектор сообщает
`execution_supported:false`. Здесь проверяются воспроизводимые bytes и
работающий публичный C99 путь кодеков.

Полное руководство содержит команды для исходников и перенесённого SDK.
Буферы принадлежат стеку, views заканчивают жизнь до возврата, поток закрывается
при успехе и ошибке. Отказ кодека предшествует открытию файла; ошибка конечного
I/O возвращается вызывающему коду без обещания файлового rollback.

## pilot.c: настоящие metadata/types/code

[pilot.c](pilot.c) построчно поясняет сборку 180-байтового golden Pilot.
Descriptor0 задаёт data4/align4/map00, descriptor1 — frame64/align8/map00.
Metadata содержит условные data_type0 и executable entry0/frame_type1.
Имя Pilot хранится полными Rune в pool ID0. Code count2 содержит MOVW
с проверенными signed30 operands 42 и MP[0], затем EXIT без operands.
initializer_count0 означает стандартную инициализацию выделяемого data4.

Цель dis64_pilot_example принимает один явный выходной путь. После записи
используйте dis64inspect file --pilot или установленный run-dis64-pilot.sh.
Все буферы отдельные и принадлежат main; проверки выполняются до открытия
выхода. Ошибки fwrite/fclose возвращают отказ без обещания отката файла.
Набор SDK содержит pilot42.hex и все транзитивные заголовки. Выполнение новой
VM этим примером не заявляется: [команды и границы](../README.ru.md).

## Инициализированные данные и signatures

`pilot.c output --initialized` записывает общий initializer int32=40 по offset0,
затем ADDW immediate2 с AXNON (destination также lhs). Файл совпадает с общим
192-байтовым golden. Сам пример не применяет данные к native heap и не исполняет
код; без флага сохраняется180-байтовая форма.

[interfaces.c](interfaces.c) не принимает файлов: создаёт pool M/f, полную
signature version1 bool(int,big) и два ordinal import alias. Общий checker
принимает точные одинаковые signatures. Замена результата второго на int
делает пару конфликтной, сохраняя весь прежний выход и длину written.
Буферы отдельные, принадлежат main; resolver/callee/module не запускаются.
Цель сборки — dis64_interfaces_example; [руководство](../README.ru.md)
содержит команды независимой сборки из установленного SDK.
