# Обзор модулей Inferno: полезный код и реальные границы

[English](MODULE_AUDIT.md) · [Выбранные библиотеки](libraries/README.md) ·
[Runtime](runtime/README.md) · [Синхронизация](SYNC.ru.md)

Проверены удерживаемое ядро Dis, регистрация встроенных модулей, экспортируемые
операции Sys и выбранные библиотеки на обычном Limbo. Ниже разделены уже
исполняемый код и возможности, которым ещё нужен интерфейс хоста. Полный перенос
всех модулей Inferno не заявляется.

| Область | Полезный существующий код | Состояние FlashVM DisVM / следующее применение |
| --- | --- | --- |
| Ядро Dis, куча, стек, каналы | Корни RC/GC, кадры, отмена ALT, защищённые нативные пути | Уже удерживаются и исполняются; адаптеры NC64 отделены от стандартного ABI. |
| `$Sys` | Форматирование, UTF и контракты нативного I/O | Работают read/write/create/seek и стандартные дескрипторы. Метаданные, dirread, процессы, namespace и сетевые экспорты ещё имеют явные неподдерживаемые пути. |
| `$Loader` | Инструкции, типы и связи загруженного модуля | Уже зарегистрирован и проверяется; полезен для дизассемблера IDE. Динамическое создание модулей требует более широких проверок. |
| `Dis` | Декодер объектов, имена операций и пути исходников | Уже собирается из исходников. Декодер рассчитан на классический формат; NC64 нельзя выдавать ему как совместимый объект. |
| `Debug`, `Exception`, `Profile` | Символы, протоколы стека/управления и модели профилирования | Debug поставляется; основная работа — `/prog`, управление процессами и устройства профилирования. Одних объявлений недостаточно для работающего отладчика. |
| `Bufio`, `String`, `Arg` | Рунные буферы, разбор текста/чисел и аргументов | Уже поставляются и исполняются; подходят для повторного использования в сервисах IDE. |
| `Readdir` | Сортировка и фильтрация каталога | Библиотека есть; реальный обход требует недостающего интерфейса каталогов Sys. |
| `Regex` | Разбор regexp и исполнение автомата на обычном Limbo | Добавлен к исходным библиотекам этой серии; рунные захваты проверяются на DisVM. Полезен для поиска IDE и будущего понижения regexp-срезов. |
| `Lock` | Семафор на канале | Полезный образец сериализации сервиса. Это не объектный reentrant-мутекс с владельцем; он не заменяет автоматически существующий протокол аренды таблиц. |
| `Styx`, `Styxservers` | Кодек 9P2000 и серверные помощники | Уже поставляются. Кодек не равен смонтированному namespace, отменяемому транспорту или реестру времени жизни удалённых объектов. |
| `$Srv`, `$Math` | Разрешение имён, скаляры/векторы и преобразования | Уже зарегистрированы. Resolver может блокировать единственного владельца; математика использует проверяемые адаптации хоста. |
| `$Draw`, `$Tk`, `$Prefab`, `$Freetype` | UI-реализации Inferno | Отдельны от нашего графического фронтенда FlashVM; для отображения IDE их импорт не нужен. |
| `$IPints`, `$Crypt`, `$Keyring` | Большие целые и криптография | Этим обзором не добавлялись: нужны отдельные проверки ABI, владения и безопасности. |

## Подтверждённый полезный перенос: Unicode Regex

Прежние теги Regex начинались с `1<<16`, совпадая с допустимыми символами
U+10000…U+1000B. Настоящий запуск неизменённой библиотеки на DisVM отвергал
U+10000 как ошибочное выражение. Исправленная база — `1<<21`; маркер конца ввода
выводится из неё. Публичные сигнатуры compile/execute не меняются.

Исправление опубликовано обратно в Inferno experiment коммитом
**320e6581e425c014f8a9ba313352b664925a709f**, затем импортировано побайтно.
Regex включён в нативную и отдельную сборки библиотек; runtime/editor-пакеты
получают исходник, интерфейс, байткод и символы. Проверка установленного SDK
заново компилирует библиотеку и клиента только из перенесённых исходников/заголовков
и исполняет оба режима с квантами 1 и 2048.

Матрица из 85 случаев охватывает все 12 прежних коллизий, ASCII/BMP, emoji и
U+10FFFF: литералы, экранирование, классы, альтернативы и повторные захваты.
Смещения считаются в рунах, а не байтах UTF-8. Старые исходники/интерфейс падают
на активной проверке результата compile; исправленная пара проходит четыре запуска.
[Регрессия Inferno](upstream/appl/lib/tests/README.regex-unicode.md).

Это существующая библиотека Limbo, исполняемая на DisVM. Поиск regexp в UI редактора,
синтаксис regexp-срезов в нашем Coco/R-фронтенде и отдельный машинный regexp-JIT
здесь не добавлены. Полный исходник Regex пока собирается удерживаемым bootstrap
обычного Limbo; наш Coco/R-компилятор big/table остаётся более узким профилем.

## Приоритет после обзора

Сначала полезно подключать конкретные операции метаданных/каталогов Sys и
отладочные сервисы `/prog` к существующим переносимым границам хоста. Это откроет
реальный обзор файлов, чтение метаданных классических Dis и отладочные окна без
второго графического стека. Декодирование формата должно быть явным: NC64 и
классический Dis требуют разных допустимых раскладок.

Для поиска теперь есть проверенный Regex API: его можно поставить за типизированным
сервисом запрос/ответ IDE с ограничением работы и исходными позициями диагностики.
Нужно явно задать отмену и планирование владельца. Долгое вычисление на чистом
Limbo прерывается квантами VM, но будущий блокирующий нативный вызов не должен
останавливать брокер. Замены с захватами, regexp-срезы и автоматические операторы
`any`/прокси всё ещё требуют отдельных контрактов языка и FIR.
