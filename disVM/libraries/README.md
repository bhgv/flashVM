# Selected Inferno modules / Выбранные модули Inferno

[Runtime](../runtime/README.md) · [Runnable tutorial](../examples/standard-modules/README.md) ·
[Exact source selection](../UPSTREAM.json) · [Preparation](prepare.py)

The runtime packages selected source-built libraries, not a whole Inferno OS.
Sources come from bhgv/Inferno-OS-bhgv, experiment; UPSTREAM.json records exact
revision/hashes. Imported sources remain unchanged, including original notices.
Private build views contain reviewed NC64/host adaptations and explicit bug fixes.

| Module | Current executed coverage | Remaining boundary |
| --- | --- | --- |
| Sys | Existing actual I/O plus new fprint with checked result | Complete metadata, directory I/O, process/namespace/network services remain incomplete. |
| Srv | Real numeric forward lookup, service-port lookup, invalid inputs, repeated result ownership; production rollback fixtures | DNS may block the owner; no cancellable resolver worker yet. Reverse lookup depends on native host/DNS data. |
| Math | Scalar sqrt, binary64 conversion, dot, sort, wire int32 import, module-local arrays; independent compiler binary64 constants | Scalar functions use host libm, not an imported fdlibm. Full Math/FP/platform differential acceptance is not claimed. |
| Loader | Actual instruction, type-descriptor and link snapshots of a loaded module | Dynamic newmod/ext/dnew/compile exports are retained but not comprehensively accepted by this series. |
| Bufio | In-memory Unicode/non-BMP read, pushback, newline and EOF | Full file/filler/stream matrix remains open. |
| String | Case conversion, Unicode prefix and numeric parsing | Full language/string conformance is not claimed. |
| Arg | Real option/argument parsing and consuming argv ownership | No shell or command-process runner is implied. |
| Styx | Actual 9P2000 Read pack/unpack with offset above 2 GiB; truncation, NOFID/Qid version widths and impossible-header rejection | This codec is not a mounted namespace or live distributed filesystem. |
| Styxservers | Initialization and bounded readbytes/EOF helper | Live server lifecycle needs Sys process/FD/namespace and transport work. |
| Readdir | Loaded library and pure empty ordering | Actual enumeration awaits Sys.dirread; no fake directory entries are returned. |
| Debug | Loaded library, init and NC64 primitive-width adaptation | /prog control, stack/heap views, full symbols and stepping are not wired. |
| Dis | Source-built reference parser/opcode interface; opcode identities used by the Loader tutorial | loadobj needs Sys.fstat and its classic-format parser must not be advertised as NC64 decoding. |

Draw.m is a retained declaration needed by Debug's historical Command context;
no Draw, Tk or Prefab implementation is imported or required. $Loader uses the
retained production loader.c with declarations/maps regenerated by the matching
compiler. Sys descriptor initialization is idempotent across builtin registration.
$Srv uses the fresh production result construction/cleanup and real shared
[resolver port](../../flashVM/ports/network/resolver.h), with a real native lock.
This runner still has one OS owner; its synchronous I/O can block other Dis work.

NC64 numeric tables have eight-byte cells. The updated upstream fixed-width
classic ICASE/ICASEL/IGOTO leaves cannot consume those rows. The NC64 runner
explicitly declines those native leaves and uses separately checked C table
adapters; ordinary upstream/native-emitter tests retain the standard layout.
The tutorial verifies its actual emitted bytecode contains all three forms,
executes their branches and also checks interpreter/JIT dispatch counters.
Native opcode availability is not equivalent to executing every opcode natively
inside this experimental ABI.

## Build and run

Run `python3 build_menu.py`, select `all` or `disvm-runtime`, accept defaults.
Post-build **7** runs the module tutorial; **5** opens the existing editor.
The installed `run-checks.sh` also executes the module tutorial when present.
The runtime package includes matching modules/.sbl, selected prepared Limbo
sources, headers, this guide and the heavily commented tutorial.

Standalone library-only builds use this directory's CMakeLists.txt with explicit
LIMBO_EXECUTABLE, DVM_LIBRARY_SOURCE_ROOT and matching DVM_LIBRARY_CELL_BYTES
(4 classic or 8 NC64). Target disvm_libraries produces the eight libraries and
symbols. No emu, C compiler, UI SDK or sibling source checkout is assumed by
that project. Choosing a compiler with a different ABI is unsupported; ordinary
menu builds choose the matching native compiler automatically.

## Bugs found during transfer

Math interface compilation exposed dtoa's assumed 32-bit long limbs on LP64:
reading/writing halves of a double exceeded its storage. The bootstrap derives
32-bit int limbs with a compile-time width check, and packs negative subtraction
halves through unsigned shifts. Both CMake and direct builds use that view;
134 independent binary64 constants include overflow, subnormal and signed-zero
boundaries. UBSan runs actual compilation and module execution.

Both Styx decoders previously sliced a buffer to an advertised size below the
seven-byte fixed header, then indexed that removed header. Prepared sources now
reject size < H before trimming. Tests cover every impossible size 0..6 and
every prefix of a real Read request. The NC64 codec separately sign-extends wire int32 values, preserving NOFID and Qid versions instead of changing the protocol with host cell width. Separate upstream patches are retained;
these fixes were still absent at the checked experiment revision.

## По-русски

Перенесены выборочные модули, а не вся ОС. В меню запуска **7** — настоящая
проверочная программа на Dis; **5** — редактор. Srv/Math/Loader зарегистрированы
как встроенные модули, восемь Limbo-библиотек собираются из закреплённых исходников.
В таблице выше явно разделены исполненные функции и ещё не готовые службы.
Наличие debug.dis не означает работающий отладчик: устройство /prog пока отсутствует.
Наличие Styx-кодека не означает готовые mount/export, namespace либо сетевой сервер.

При переносе исправлены обнаруженные ошибки dtoa и двух декодеров Styx. Исходные
снимки не редактируются: изменения применяются в отдельных производных файлах
при сборке, патчи для исходного Inferno хранятся отдельно. Сборщик проверяет
ожидаемые места изменений и останавливается при неожиданном обновлении upstream.
