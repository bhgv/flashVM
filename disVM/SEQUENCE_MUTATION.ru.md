# Замена срезов и регулярные выражения: контракт реализации

Статус: согласуемая семантика; приведённый синтаксис ещё не реализован.
[Блокировки](OWNED_OPERATIONS.ru.md) · [Существующие относительные индексы](../fir/v1/doc/RELATIVE_SEQUENCES.ru.md)

Запись `target[first:end] = replacement` заменяет выбранный диапазон, а не
перезаписывает только столько элементов, сколько помещается. Хвост сдвигается;
новая длина равна старой длине минус длина диапазона плюс длина замены.
Пустой диапазон вставляет, пустая замена удаляет. Для таблицы меняется плотная
числовая часть; текстовые ключи не становятся элементами последовательности.
Взаимодействие растущего префикса с уже занятыми разреженными числовыми ключами
нужно определить до реализации: молчаливое уничтожение таких ключей недопустимо.

Индексы строк измеряются рунами Unicode, не байтами UTF-8 и не графемами.
Отрицательный конец остаётся включительным согласно принятому расширению:
`[0:-1]` охватывает всю последовательность. Положительный конец исключительный.
Индексация на чтение и запись также должна работать по рунам.

Для самоприсваивания сначала нужен устойчивый снимок правой части. Вычисления
размеров проверяются на переполнение, выделение новой памяти завершается до
публикации изменения. Ошибка выделения не должна оставлять частично сдвинутый
хвост. Блокировка принадлежит общей памяти представлений, а не временному срезу.
Передача сетевых данных может идти в промежуточный буфер до захвата объекта;
затем нужно проверить сохранённую версию либо выполнить заранее выбранную
семантику применения к текущему состоянию. Нельзя выдавать это за атомарность
выражения, если блокировка не охватывала вычисление его входных значений.

Предложенный поиск `str[/pattern/]` возвращает nil при отсутствии совпадения;
иначе array of string: полное первое совпадение, затем группы по порядку
открывающих скобок. Требуется определить представление неучаствовавших групп
отдельно от участвовавших пустых групп. Глобальный поиск не подразумевается.

Присваивание `str[/pattern/] = replacement` заменяет первое совпадение.
В шаблоне замены `\0` обозначает полное совпадение, `\1` и следующие — группы.
Лексер строк и обработчик замены должны согласовать экранирование, чтобы
пользовательский `\1` не исчезал до исполнения. Обратная косая черта, ссылка на
несуществующую группу, многозначные номера и отсутствие совпадения требуют
явно задокументированных правил и отрицательных тестов до включения синтаксиса.

Парсер Coco/R должен различать regexp-литерал в индексном выражении и оператор
деления; FIR хранит отдельную операцию поиска/замены с координатами источника.
Скомпилированный regexp можно кэшировать как программу сопоставителя. Машинный
JIT необязателен для первого рабочего варианта: сначала захваты, Unicode,
ограничения времени/памяти и предсказуемая отмена. Существующий FlashVM regex API
возвращает только диапазон совпадения и не реализует этот контракт групп.
