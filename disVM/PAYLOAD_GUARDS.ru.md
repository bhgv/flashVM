# Владение данными native-таблиц и обработка исключений

[English](PAYLOAD_GUARDS.md) · [Локальный C API](../common/owned/REQUESTS.ru.md) ·
[Запускаемый пример Limbo](examples/table-guards/main.b)

Приватный неподвижный GC-владелец Bigtable содержит `FvmTableOwner` с повторно
входимой блокировкой по токену операции. Защищены чтение/запись, длина/число ключей,
захват относительных индексов и диапазонов, срезы и построение снимка ключей.
Splice захватывает источник и назначение в едином порядке; для self-splice
достаточно одного владельца. Алиасы handle разделяют ту же блокировку. При
конструировании новый снимок принимается целиком до возврата программе.

Под блокировкой используются только scalar C-хранилище и Fht-статусы. Механизм
ошибок VM, GC и код приложения не вызываются. Проверка handle и преобразование
строк/ключей-снимков идут до входа, исключения VM — после выхода. Кадр удерживает
живые handle всё время. GC уничтожает только освобождённую блокировку, затем
C-хранилище. Финализация занятого владельца — нарушение инварианта, а не повод
принудительно снять защиту продолжающейся операции.

`Bigtable.guardstate(handle)` возвращает `(owner, depth, waiters)` под коротким
mutex метаданных. Данные объекта не захватываются, native-указатель не выдаётся,
доверенный токен от программы не принимается, сообщения об успешном обмене не
генерируются. Это интерфейс для диагностики, ещё не полная привязка к RPC-брокеру.

Планировщик runtime теперь подключает сохранённый обработчик исключений Inferno.
Limbo-блоки `exception` продолжают исполнение в интерпретаторе и leaf-JIT; native
и вызывающие кадры очищаются по точным картам корней. Ограниченная резервная
строка ошибки закреплена штатной таблицей native-корней на время жизни runtime.
Сохраняется fallback при нехватке памяти. Native thread cancellation не является
исключением программы. Диагностика последнего исключения и типизированное значение
освобождаются при нормальном завершении процесса планировщиком. Ошибки instruction-boundary бюджета остаются
терминальными: обработчик не должен обходить лимит или считать невыбранную
инструкцию исполненной.

Общее исправление Inferno проверяет PC перед выбором обработчика, включая builtin
без bytecode. Родительский код ошибочно принимал PC посреди инструкции. Дополнительное
исправление LP64 согласует sentinel отсутствующего обработчика с native-шириной
ulong в loader, не допуская перехода перед образом при несовпавшем шаблоне. Регрессия
проходит для emu/os и native/WORD32. Снимки сохранены побайтно; генерируемая view
адаптирует только TLS-регистры, регистрацию корня и диагностические функции host.

Защищены отдельные примитивы таблицы. Удержание на всё составное исходное выражение
через RHS, ожидания сети/канала, массивы, mutable String-ячейки и общие leases
удалённых проекций пока не реализованы. Строки заменяются по значению. VM всё ещё
имеет один executor; native-клиенты могут работать с scalar owner API вне GC-кучи,
но сырые GC-владельцы не передаются чужому executor-потоку. Для async-удержания
нужны очередь планировщика, pinning и подтверждение отмены. Mutex метаданных
брокера остаётся независимым и не заменяет защиту данных.
