## Реализованный участок

Один `DVM_UIBridge` владеет двумя настоящими каналами FlashVM: UI → Dis и Dis → UI.
Стороны не могут случайно прочитать собственное отправление. Оба направления
имеют ограничение в 32 сообщения. Создание с `rendezvous=1` включает штатное
ожидание фактического приёма; с нулём используются ограниченные буферные очереди.
Снимки ожидающих отправителей/получателей доступны через исходный API FlashVM.

AS получает два обычных `fvm_extensions_wrap_channel`-объекта. Их `trySend` и
`tryReceive` совместимы с нативным кодеком: строки-примитивы проходят через
существующий primitive fast path FlashVM. Вторая реализация очереди, mutex,
платформенного ввода или графической системы не добавляется.

На стороне Dis `dvm_ui_dis_offer` копирует запись в настоящий `Array` с `Tbyte`
и передаёт его штатным `csendalt`/`movp`. Входной канал должен быть заранее
зарегистрирован хостом с точным Limbo-типом `chan of array of byte`. Проверка
mover подтверждает только указательный класс, не статический тип элемента.
`len=-1` запрещает `csendalt` самостоятельно создавать буфер. Если нет приёмника
или места, временная ссылка освобождается и возвращается `FVM_NOT_FOUND`.

`dvm_ui_dis_export` принимает уже полученный и удерживаемый Dis byte array,
проверяет тип/длину/протокол и копирует сообщение в UI-направление. Эти функции
вызываются владельцем исполнения Dis под его защитой памяти и внешней границей
ошибок. Они не разрешают произвольному UI-потоку менять Dis-кучу. Ошибки выделения
Dis распространяются через штатный error/kprotect, а не маскируются под успех.

Модуль `uibridge` реализует тот же кодек на Limbo без Sys/Draw/Tk. Учебный
`uiecho` получает и отправляет **обычные блокирующие каналы Dis**. Внутренние
очереди Limbo, `alt` и приостановка процессов сохраняются; их структуры не
подменяются очередями потоков ОС. Общая часть — формат значений и адаптеры
на границе двух владельцев. Этот локальный протокол не является 9P/Styx wire format.

## Ввод только из FlashVM

Хост сначала выполняет обычную доставку события FlashVM. Затем на том же
потоке владельца `dvm_ui_pointer` читает `fvm_input_get_pointer`, а
`dvm_ui_keyboard` — `fvm_input_get_keyboard`. Событие повторно не доставляется,
существующие обработчики не заменяются. Клавиатурная функция получает код
именно текущего перехода, а не выводит key-up из последнего key-down.

Обе функции возвращают точную скопированную запись через `captured` перед
попыткой отправки. При переполнении вызывающий код удерживает её и повторяет
`dvm_ui_send`, а не повторяет ввод и не считывает уже изменившиеся координаты.
Порядок событий и политика остановки при переполнении принадлежат хосту;
нельзя обгонять отложенный key-up или незаметно терять событие.

Это явные точки подключения **после** dispatch, не автоматически установленные
глобальные перехватчики каждого frontend. Для текста/IME предусмотрен класс Text:
передаётся уже подтверждённый текст из пути ввода FlashVM, не текст, синтезированный
из ASCII клавиш. Автоматическая разводка frontend text/IME/focus ещё не выполнена.
MovieClip и TextField меняются только AS-клиентом в потоке владельца интерфейса.
Ожидать блокирующий receive или Dis-сервис в цикле отрисовки нельзя.

## Формат одной атомарной записи

Строка `fvd1:` + шесть восьмизначных lowercase hex-полей + UTF-8 payload.
Полный заголовок — 53 ASCII-байта. Поля по порядку:

| Поле | Представление | Назначение |
| --- | --- | --- |
| kind | uint32, значения 1–6 | Request, Reply, Pointer, Key, Text, Focus |
| id | uint32 | Ненулевой ID запроса/ответа; ноль для ввода |
| code | uint32 | Операция, статус, кнопка мыши или виртуальная клавиша |
| flags | uint32 | Pointer: фаза; Key: нажатие 0/1; прочие — контракт сервиса |
| first | int32, two's complement | Pointer X в twips; Key ASCII; аргумент операции |
| second | int32, two's complement | Pointer Y в twips; второй аргумент |
| payload | До 1024 байт canonical UTF-8 | Текст, включая NUL, переводы строк и supplementary Unicode |

Координаты: 20 twips на пиксель, усечение к нулю, диапазон int32.
Суррогаты без пары, overlong UTF-8 и значения выше U+10FFFF не входят в общий
профиль AS/Limbo и отвергаются. Нативные указатели, double ABI, struct padding и
дескрипторы GC не сериализуются. На стороне Limbo unsigned-поля сохраняются как
32-битные `int` bit patterns. Классы сообщений проверяются общим кодеком, смысл
операции/разрешения/ревизии — соответствующим сервисом.

Порядок FIFO гарантируется отдельно в каждом направлении. id коррелирует ответ,
но не обеспечивает дедупликацию или «ровно один раз». Успешная отправка означает
принятие транспортом, не выполнение операции. Невалидный входной пакет потребляется
и освобождается, результат при ошибке не изменяется. Хост должен обработать ошибку.
При close ожидающие операции просыпаются; принятые буферные записи можно дочитать.
Сначала close, затем join/остановка пользователей, затем освобождение оболочек и destroy.

## Проверки и оставшаяся интеграция

На Linux AMD64 с CMake 3.10.2 собран набор из 42 тестов, прошедший полностью.
После уточнения Unicode/сохранения ввода повторно проверены изменённые мостовые
тесты. Есть реальная передача через AS channel wrappers, ввод FlashVM, bounded FIFO,
rendezvous и close. Отдельная фикстура использует production heaparray/freeptrs,
csendalt/isend/irecv/movp и настоящий FlashVM transport; её планировщик, pool allocator
и границы ошибок — тестовые, это не запуск целого Limbo-приложения.

Оба Limbo-модуля компилируются исходным bootstrap из tools; AS2 разбирается нашим
Coco/R-фронтендом. Алгоритм AS-кодека дополнительно проверен Node, что не является
доказательством исполнения всей AS-программы в FlashVM. Node — необязательная
проверка разработчика, не зависимость сборки или поставляемой IDE.

Полный Dis-хост ещё должен связать загрузку модулей, scheduler/lifecycle, корни GC,
регистрацию точных типов каналов и owner-pump с сохранением отложенных сообщений.
Мостовые операции не заменяют эту работу и не создают незаявленный эмулятор.
Ещё предстоят автоматическое подключение ввода frontend и AS-виджеты редактора.
Запуск `uiecho`/`idecore` целиком в нашем DisVM пока не объявляется проверенным.
