# styxheldexport

[English](HELD-EXPORT.md) · [Заголовок](held_export.h) · [Реализация](held_export.c) · [Время жизни открытого fid](OPEN-FID-LIFETIME.ru.md) · [Styx для одного файла](SINGLE-FILE.md)

```c
#include "held_export.h"

DVM_Provider *styxheldexport(DVM_VfsHandle *source, unsigned access);
```

Функция из native POSIX SDK `styx_vfs` превращает уже открытый файл в провайдер
с одним корневым файлом (`.`). Хост вызывает её после завершения всех
заимствований `source`. В `access` передаётся непустая комбинация
`FVM_ACCESS_READ` и `FVM_ACCESS_WRITE` из действительных прав открытого файла.
При каждой попытке открытия провайдер отдельно проверяет этот предел прав.

При успехе функция возвращает ссылку во владение вызывающему и очищает
`source`. При возврате `NULL` файл остаётся у вызывающего. Причинами отказа
могут быть недопустимые права, каталог, отсутствие метаданных или операций
ввода-вывода и ошибка подготовки. Сбор метаданных может ждать, поэтому
вызывайте функцию вне блокировок VM и пространства имён. Полученную ссылку
освобождает `dvm_provider_release`.

Первое разрешённое открытие получает исходный объект и его текущую позицию.
Поддерживаются режимы `r`, `wo` и `rw`. Отказ из-за режима оставляет выдачу
доступной. Среди параллельных открытий успешным может быть только одно.
После его закрытия повторное открытие невозможно. Поток поддерживает
последовательный ввод-вывод. Смещение в Styx начинается с нуля и растёт на
подтверждённое число байтов от исходной позиции. Режим и размер фиксируются
на момент публикации. Размер относится ко всему файлу, а EOF определяется
чтением с текущей позиции.

Хост может передать провайдер в `styxbacking` для обслуживания файла
существующими обработчиками Styx. Хост контролирует доступ к опубликованному
маршруту. Удалённая сторона открывает его и получает свой fid. Открытый fid
продолжает работать после снятия публикации и отвечает за окончательное
закрытие. Если файл так и не открыли, последняя ссылка на провайдер передаёт
закрытие отделённому worker. Каждая выдача использует одного такого worker.
Интерфейс принимает native handles, которыми уже владеет хост.
