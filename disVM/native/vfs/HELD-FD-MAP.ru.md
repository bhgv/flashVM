# styxheldfdmap

[English](HELD-FD-MAP.md) · [Заголовок](held_export.h) · [Реализация](held_export.c) · [Экспорт открытого файла](HELD-EXPORT.ru.md) · [CLI запуска](../../runtime/TERMINAL-LAUNCH-CLI.md)

```c
#include "held_export.h"

int styxheldfdmap(DVM_View *view, unsigned number, DVM_Provider *grant, unsigned access);
```

Функция native POSIX SDK `styx_vfs` помещает подготовленную выдачу файла в
частное дерево запуска по пути `/.fd/NUMBER`. Номер десятичный, от 0 до 31.
Передайте изменяемый view builder и живой корневой файловый провайдер от
[`styxheldexport`](HELD-EXPORT.ru.md). `access` задаёт непустое сочетание
`FVM_ACCESS_READ` и `FVM_ACCESS_WRITE` из разрешённых прав. Каталог создаётся
как часть представления VFS. Собирайте отдельное представление для каждого
запуска и публикуйте его для нужной удалённой стороны.

Функция возвращает 1, когда view удерживает mapping, и 0 при отказе или
нехватке памяти. Вызывающий сохраняет свои ссылки на view и grant. Повторное
успешное добавление того же пути заменяет его по правилам view. Функция
проверяет доступ без открытия файла. Меняйте builder при исключительном
владении и зафиксируйте его перед передачей серверу Styx.

Например, опубликуйте файл для чтения под номером 0. Принимающая сторона
обнаружит его при запуске по `/.fd/0`, а Limbo получит локальную ссылку
через `sys->fildes(0)`.
