# styxunibusserverstartmounted

[English](SCALAR-FUNCTION-MOUNTED.md) · [Заголовок](unibus_server.h) · [Пример запуска](tests/scalar/pair.c)

```c
StyxUnibusServer *styxunibusserverstartmounted(
    RemotePhy *channel, const StyxMountedScalar *entries, size_t count);
DVM_Provider *styxunibusservermailbox(
    StyxUnibusServer *server, size_t index, int reply);
```

Подключите `unibus_server.h` и библиотеку `styx_unibus_server`.
Конструктор принимает подключённый канал во владение при любом исходе.
Передайте от 1 до 64 записей с уникальными именами каталогов модулей.
В каждой записи указывается одна функция. Имена задаются одним
элементом пути, имя `.interface` зарезервировано. Таблица заимствуется
на время запуска, состояние нативного обработчика — до завершения сервера.
При неверных параметрах или сбое запуска функция возвращает NULL.

Если поле `native` равно NULL, запись получает отдельные приёмники запросов
и ответов для сервиса Dis. Индекс начинается с нуля. Передайте 0 для чтения
запросов или 1 для записи ответов. Провайдер заимствуется до завершения
сервера. Для нативной записи, отсутствующего сервера или индекса вне
таблицы возвращается NULL. Пути и теги для владельца описаны в
[настройке сервиса](SCALAR-FUNCTION-DIS.ru.md).

В корне Styx появляется один каталог `mounted`. У каждого модуля свой
файл функции, а у типизированной записи — свой доступный только для чтения
`.interface`. Общий диспетчер принимает вызовы последовательно. Каждый
открытый fid сохраняет свой ответ. При закрытии соединения сервер закрывает
все приёмники запросов Dis. После этого вызовите `styxunibusserverjoin`.

В SDK с настроенными DisVM и компилятором Limbo запустите
`ctest -R '^terminal-scalar-owner-guest$' -V`. Пример монтирует один Styx-корень
для нативной функции и экспорта исходного Dis. Он проверяет оба результата
и отказ при попытке загрузить каждый каталог с импортом другого.
