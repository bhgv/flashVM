# styxlaunchpublicationresultrecord

[English](LAUNCH-RESULT-RECORD.md) · [API](launch_publication.h) · [Публикация](LAUNCH-PUBLICATION.ru.md) · [TCP-пример](../../examples/vfs-run/TUTORIAL.ru.md) · [Встречная доставка Styx](LAUNCH-DELIVER.ru.md)

`int styxlaunchpublicationresultrecord(StyxLaunchPublication *publication, int wait, const FVM_SOrdinal *ordinal, unsigned long tag, void *bytes, size_t capacity, size_t *used);`

Подключите `styx_terminal`. Передайте живую публикацию, следующий порядковый
номер ответного тега получателя, ненулевой 32-битный тег, буфер вызывающего
с ёмкостью в байтах и указатель для записи длины. При `wait = 0` незавершённая
команда даёт статус ожидания без блокирующего waitpid. При ненулевом `wait` вызов может ждать
процесс. Публикация сериализует получение статуса.

Результат 1 даёт упорядоченный пакет с одной S-записью. Данные записи —
десятичный код выхода с переводом строки. Результат 0 означает, что статус
ещё недоступен. Результат -1 означает неверные аргументы, ошибку ожидания
или кодирования, в том числе недостаточный размер буфера. Вызывающий назначает
порядковый номер и публикует пакет на своей разрешённой линии.

TCP-тест резервирует тег ответа 17 с порядковым номером 0 и выдаёт получателю
файл `/launch-exit`. Клиент читает результат вместе с обычными записями Unibus.
Отдельный файл результата также проверяется.
