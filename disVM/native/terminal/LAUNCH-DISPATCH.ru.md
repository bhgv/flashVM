# styxlaunchpublicationdispatch

[English](LAUNCH-DISPATCH.md) · [API](launch_publication.h) · [Публикация](LAUNCH-PUBLICATION.ru.md) · [TCP-пример](../../examples/vfs-run/TUTORIAL.ru.md)

`int styxlaunchpublicationdispatch(StyxLaunchPublication *publication, uint64_t offset, const void *bytes, size_t size);`

Подключите `styx_terminal`. Вызывайте из обработчика записи Styx перед передачей
байтов существующему потоку Unibus. Передайте инициализированную публикацию,
смещение в байтах для этого fid и буфер записи с размером в байтах. Тег запуска
резервируется отдельно от тегов обычных записей Unibus.

Маршрут запуска выбирает полная S-запись в первой записи нового fid. Результат 1
подтверждает её приём, -1 означает отказ для совпавшего маршрута, 0 передаёт
запись обычному потоку. Последующие фрагменты обрабатывает поток. Запрос запуска
отправляется одной записью, поэтому действует предел записи транспорта.
Публикация сериализует приём. Владелец разрешает доступ к узлу Styx и удерживает
публикацию на время обработки.

В TCP-примере `runargs("/routed.dis", payload)` отправляет запрос через
смонтированный `.unibus`. После `init` у владельца клиент читает статус из
`/run-result` и продолжает обычный обмен через тот же узел `.unibus`.
