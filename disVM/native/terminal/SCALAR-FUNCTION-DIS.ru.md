# styxunibusserverstartdis

[English](SCALAR-FUNCTION-DIS.md) · [Заголовок](unibus_server.h) · [Пример запуска](tests/scalar/pair.c)

```c
StyxUnibusServer *styxunibusserverstartdis(
    RemotePhy *channel, const char *module, const char *name);
```

Подключите `unibus_server.h` и библиотеку `styx_unibus_server`.
Конструктор принимает подключённый канал Styx во владение при любом
исходе и возвращает сервер или NULL. Оба имени задаются одним элементом
пути каждое. Сервер публикует под `mounted` один каталог модуля
с доступным только для чтения `.interface` и файлом функции
`fn(int): int`. Имя экспорта должно совпадать с настройкой сервиса владельца.

`styxunibusserverinbox(server)` даёт провайдер чтения запросов,
`styxunibusserverreply(server)` — провайдер записи ответов. Они
заимствуются до завершения сервера. Смонтируйте их в пространстве владельца
и запустите [общий скалярный сервис](../../runtime/SCALAR-OWNER-SERVICE.ru.md),
передав эти пути, теги 72 и 73, путь исходного Dis-модуля и имя экспорта.
При нулевом счётчике вызовов сервис работает до закрытия соединения.
Клиент монтирует корень Styx и использует обычный типизированный `load`
по пути `mounted/<модуль>` относительно точки монта.

Диспетчер передаёт сервису по одному вызову и сохраняет каждый готовый
ответ в его открытом Styx fid. Диспетчер ждёт ответа владельца до трёх
секунд. Если исход обмена неизвестен, он прекращает приём запросов по
маршруту и возвращает ошибку Styx без повторной отправки. При закрытии
соединения диспетчер закрывает приёмник запросов, чтобы ожидающий
владелец мог завершиться. Перед `styxunibusserverjoin` закройте соединение.

В SDK с настроенными DisVM и компилятором Limbo запустите
`ctest -R '^terminal-scalar-owner-guest$' -V`.
[Клиент на Limbo](../../examples/remote-scalar/styx-mounted.b) и общий
сервис запускаются в отдельных DisVM. В режимах интерпретатора и JIT
ожидается `PASS mounted Styx original Dis`. Результат зависит от
приватного файла и состояния владельца. Пример также проверяет
передачу исключения.
