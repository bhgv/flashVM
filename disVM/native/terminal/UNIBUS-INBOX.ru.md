# styxunibusinbox

[English](UNIBUS-INBOX.md) · [API](unibus_inbox.h) · [Отправитель](LAUNCH-DELIVER.ru.md) · [Пример](../../examples/vfs-run/TUTORIAL.ru.md)

`DVM_Provider *styxunibusinbox(unsigned long tag);`

Подключите `styx_terminal`. Передайте выделенный для ответа ненулевой
32-битный тег. Результат — владеющая ссылка на провайдер одного файла либо
NULL при неверном теге или ошибке выделения. Освобождайте ссылку обычной
операцией для провайдера. Открытые fid удерживают собственные ссылки.

Опубликуйте для встречной стороны право записи в `.unibus`, а в пространстве
имён Limbo выдайте право чтения. Провайдер принимает одну полную S-запись
длиной до 64 байт в кодированном виде. Чужой тег, неполный кадр и повторная
запись отклоняются. Поддерживаются режимы `r` и `wo`. У каждого читателя своя
последовательная позиция. До появления записи непустое чтение сообщает
об ожидании ошибкой I/O. После появления отдаёт байты записи, затем EOF.
Провайдер не ждёт будущую запись. Запись сериализована, отмена может
отклонить допуск операции.

В TCP-примере локальный приёмник виден как `/reverse-exit`. Владелец пишет
в `.unibus` клиента по встречному каналу Styx. Limbo читает ту же запись
через `Sys->read` по имени, выданному для чтения.
