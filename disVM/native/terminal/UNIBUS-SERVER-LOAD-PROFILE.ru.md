# styxunibusserverloadprofile

[English](UNIBUS-SERVER-LOAD-PROFILE.md) · [Заголовок](unibus_server.h) · [Реализация](unibus_loaded.c)

```c
DVM_Provider *styxunibusserverloadprofile(StyxUnibusServer *server);
```

Подключите `unibus_server.h` и библиотеку `styx_unibus_server`.
Передайте работающий сервер из
[styxunibusserverstartloaded](UNIBUS-SERVER-LOADED.ru.md). Вызов немедленно
возвращает заимствованный провайдер, действительный до join. Для других
режимов сервера и NULL возвращается NULL.

Выдайте в VFS владельца только запись в корневой узел провайдера. Передайте
его путь в поле `offer` конфигурации `loaded`. Владелец записывает одну
полную S-запись после связывания экспорта. Диспетчер сверяет имя и
сигнатуру и закрывает приёмник после чтения записи. Удалённый клиент
читает принятый профиль из `.interface` смонтированного каталога.

## Скомпилированные типы

Если загруженный образ содержит
[таблицу типов компилятора](../../../tools/limbo-bootstrap/STYX-TYPE-TABLE.ru.md),
сервис включает в предложение типы выбранного экспорта. S-запись с тегом
88 содержит прежний вид записи и 32-битную сигнатуру, однобайтовые длины
имени, аргументов и результата, затем три строки этих длин. Оба описания
типов оформлены внешними списками. Внутри `i` и `b` обозначают `int`
и `big`. Токен `f` обозначает `real`, скобки создают вложенный кортеж, а `r[ib]` обозначает ссылку
на ADT с такими полями.

Владелец сверяет схему с поддерживаемым шлюзом. Клиентский `load`
проверяет схему, имя и скомпилированную сигнатуру до связывания. Шлюз
с тремя аргументами упаковывает вызов и читает результат по полученным
спискам. Для образов без таблицы используется прежний тег 71 с именем
и сигнатурой для шести фиксированных профилей. Для дополнительных
[скалярных схем](SCALAR-FUNCTION.ru.md#вызов-по-скомпилированным-скалярным-типам)
и [раскладок ref](SCALAR-FUNCTION.ru.md#вызов-по-скомпилированным-типам-ref)
требуются метаданные типов в обоих образах.
