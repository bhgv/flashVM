# styxunibusserverstartloadedset

[English](UNIBUS-SERVER-LOADED-SET.md) · [Заголовок](unibus_server.h) · [Реализация](unibus_loaded.c)

```c
StyxUnibusServer *styxunibusserverstartloadedset(
    RemotePhy *channel, const char *module, const char *const *names, size_t count);
```

Подключите `unibus_server.h` и библиотеку `styx_unibus_server`.
Передайте свой соединённый канал Styx, заимствованное имя каталога в
`mounted` и упорядоченный список из одного–восьми разных имён экспортов.
Каждое имя занимает до 48 байтов UTF-8 и задаёт один компонент VFS.
Имя `.interface` зарезервировано. Массив и строки должны быть доступны
до возврата. Конструктор принимает канал во владение и возвращает сервер
либо NULL при неверных входных данных или ошибке запуска.

Выдайте VM владельца чтение запросов, запись ответов и
[запись профиля](UNIBUS-SERVER-LOAD-PROFILE-AT.ru.md) для каждого индекса.
Запустите [общий сервис](../../runtime/SCALAR-OWNER-SERVICE.ru.md#один-load-для-нескольких-экспортов)
в том же порядке. Сервис берёт типы и сигнатуры из исходного модуля.
Файлы функций и `.interface` открываются после проверки всех профилей.
Отказ одного экспорта отклоняет всю публикацию. Открытие ждёт набор
до трёх секунд. После истечения срока можно повторить попытку.
Принятые профили сохраняют порядок и остаются неизменными до конца сессии.

После закрытия канала вызовите `styxunibusserverjoin`. Подготовку,
результаты и проверку отказа показывает
[пример с двумя VM](../../examples/remote-scalar/STYX.ru.md#загрузка-шести-экспортов-с-общим-состоянием).
