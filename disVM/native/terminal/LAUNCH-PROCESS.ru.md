# Исполнение команды у владельца Styx

[English](LAUNCH-PROCESS.md) · [API](launch_process.h) · [Приём](LAUNCH-RECEIVE.ru.md)

Библиотека POSIX `styx_terminal` предоставляет `StyxLaunchProcess` для
одноразовой опубликованной команды. Хост разрешает запись Styx и выбирает
исполняемый файл, рабочий каталог и аргументы.

## styxlaunchprocessinit

Передайте `styxlaunchprocessinit(&process, tag, directory, argv)` неиспользуемое
состояние, ненулевой 32-битный тег, рабочий каталог и массив аргументов с
завершающим NULL. Первый аргумент содержит абсолютный путь. Удерживайте массив
и строки до приёма запроса, а состояние по стабильному адресу до завершения
работы. Функция возвращает 1 при успехе или 0 при неверных аргументах.
Инициализация не запускает процесс.

Передайте запись в `styxterminallaunchreceive(&process.receiver, offset, bytes,
size)`. Принятый кадр создаёт дочерний процесс и подтверждает постановку
на исполнение. Процесс наследует окружение владельца. Частные FD хоста нужно
пометить close-on-exec. Вызовы для одного состояния выполняются последовательно.

## styxlaunchprocessstatus

После подачи запроса вызовите `styxlaunchprocessstatus(&process, wait, &status)`.
При нуле в `wait` вызов проверяет статус без ожидания, при ненулевом значении
ожидает. Возвращается 1 с сохранённым статусом, 0 до завершения или запуска
либо -1 при неверных аргументах или ошибке ожидания. При обычном завершении
статус равен 0–255, при сигнале — 128 плюс номер сигнала. Ошибка смены каталога
даёт 126, ошибка запуска исполняемого файла — 127. Дождитесь завершения
процесса до освобождения состояния.
