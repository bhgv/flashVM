# Последовательная сессия скалярных вызовов

[English](SCALAR-SESSION.md) · [Заголовок](unibus_server.h) · [Запуск двух DisVM](../../examples/remote-scalar/STYX.ru.md)

`styxunibusserverstartsession(channel, tag, original, profile)` публикует
файлы как `styxunibusserverstartmodule`, но приёмник `.unibus` допускает
следующую запись после чтения предыдущей. Заполненный слот отклоняет запись.
Чтение с недостаточным буфером отклоняется, запись остаётся доступной.

Хост выдаёт пару эксклюзивно для одной последовательности вызовов. Владелец
удерживает один загруженный модуль до конца последовательности. Нативная
точка входа клиента допускает один вызов одновременно для своего экземпляра.
После подтверждённого результата или ошибки метода можно вызвать снова.
Если достоверного ответа нет, точка входа перестаёт принимать запросы.
Для восстановления хост выдаёт новую пару файлов. Старый ответ не
переносится на новый маршрут. Параллельные независимые экземпляры одного
маршрута этот режим не поддерживает.


После получения последнего ответа клиентский хост может вызвать
`styxscalarclosefile(request, tag)`. Функция отправляет одну S-запись
завершения с тегом запросов. Владелец в режиме с нулевым счётчиком выходит
после этой записи или EOF. При обрыве соединения приёмник сначала отдаёт
подтверждённую запись, если она есть, затем сообщает EOF. Ожидание нового
запроса владельцем не ограничено трёхсекундным сроком ожидания ответа
клиентом.

Тест двух DisVM также обрывает TCP после подтверждённого результата без
записи завершения. Он проверяет, что владелец выходит из ожидания, а обе
VM завершаются без открытых файлов, отложенных закрытий и активных задач
диспетчера.
