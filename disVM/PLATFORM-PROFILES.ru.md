# Выбранные профили инструментов native64

[English](PLATFORM-PROFILES.md) · [Синхронизация](SYNC.md) ·
[Руководство Inferno](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/build-native64.md)

Коммит Inferno daa205685c1e55acf9614dd05b603ae540d39a16 добавляет пять mk-профилей.
FlashVM сохраняет их точные исходники, проверки целевого компилятора и небольшое
замыкание host-тестов. Это описание инструментов сборки ядра/библиотек. Полные
платформенные порты эмулятора Inferno и приёмка Android APK остаются отдельной работой.

| Профиль | Выбор цели |
| --- | --- |
| Linux-amd64 | Нативный/кросс GCC, x86-64 LP64, `-m64` |
| Linux-arm64 | Нативный/кросс GCC, AArch64 LP64 |
| Linux-riscv64 | Нативный/кросс GCC, RV64GC, LP64D |
| Android-amd64 | NDK LLVM для x86-64, API 21 по умолчанию |
| Android-arm64 | NDK LLVM для AArch64, API 21 по умолчанию |

`native64-target.h` отказывает при несовпадении архитектуры компилятора или модели
LP64. Небольшие lib9-заголовки подключают общие объявления; машинный контекст
сигналов/FPU, cache flush и ассемблер они не реализуют. 64-битная цель сама по себе
не включает новую файловую модель Dis. Необязательный DISMODELFLAGS должен
совпадать у всех связанных объектов runtime и сгенерированных заголовков.

## Повторение проверок

Соберите наш mk из выбранных исходников и передайте его явно:

```sh
sh tools/mk/bootstrap.sh build/mk
NATIVE_MK="$PWD/build/mk/mk" python3 disVM/upstream/utils/tests/native64-mkfiles.py
python3 disVM/upstream/emu/Android/tests/storage.py
cmake -S disVM -B build/core -DDVM_MK_EXECUTABLE="$PWD/build/mk/mk"
cmake --build build/core
ctest --test-dir build/core -R 'native64_mkfiles|android_storage' --output-on-failure
```

У независимого ядра нет скрытой зависимости от соседней сборки mk. Необязательный
DVM_MK_EXECUTABLE включает проверку реальным mk. Драйвер upstream также понимает
NATIVE_MK; его автоматическая сборка mk из полного дерева Inferno не входит в наш
выбранный снимок DisVM. Передавайте явный путь при запуске этого драйвера или
выбранного агрегатного набора проверок.

Проверка разбирает все пять профилей настоящим mk, затем собирает, линкует и
запускает соответствующие host-модели WORD64/WORD32 и отказывает при намеренно
неверном выборе архитектуры. Фактический host этой серии — Linux x86-64.
Раскрытие профиля не доказывает сборку/исполнение ARM64/RV64/NDK или работу устройства.

## Граница Android-проверки

Текущий независимый POSIX-модуль storage.c/.h выбирает только /sdcard/Inferno.
Предыдущее предложение приватного каталога/fallback отозвано upstream. Каталог
не создаётся; отсутствующее, не являющееся каталогом или недоступное хранилище
даёт отказ. Размер выхода проверяется до файловых вызовов; при ошибке выход
сохраняется. Настройка приватных каталогов больше не входит в интерфейс helper.

Обновлённый host-тест оборачивает stat/access ограниченными заглушками и проверяет
точный общий путь, маску доступа, output/errno, отсутствие доступа и игнорирование
приватных/env-альтернатив. Реальная /sdcard не используется, выдача разрешений
Android не доказывается. Применяется строгий UBSan; SDK, Draw/Tk, JNI и полный
эмулятор в runtime DisVM не добавляются.

В Android-профилях EXTWINFLAGS явно выбирает ABI-флаги GLES/Clutter; для framebuffer
он пуст. SYSLIBS включает libm. Это параметры сборки, а не проверка устройства/NDK.

Интеграция startup/trace/mkfile Android и отдельный патч APK описаны в руководстве
Inferno. Они вне выбранного замыкания helper-модуля; host-проверки путей не доказывают
запуск APK или предоставление доступа к хранилищу на устройстве.
