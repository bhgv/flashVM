# Независимые проверки владения native64

[English](NATIVE64-REVIEW.md)

Экспериментальный WORD32/native64 ABI из выбранных исходников Inferno отличается
от исполняемого NC64 рантайма IDE. Импорт исходников не включает новый профиль
файлов Dis64 и не переключает установленный SDK на другой ABI.

## Две явные группы проверок

Для GNU/Clang на Linux64 с поддержкой строгого UBSan добавьте к обычной
конфигурации рантайма следующие параметры:

```sh
cmake -S disVM/runtime -B build/editor-review \
    -DDVM_RUNTIME_TESTS=ON -DDVM_RUNTIME_NATIVE64_REVIEW_TESTS=ON
cmake --build build/editor-review --parallel 4
ctest --test-dir build/editor-review -R disvm_native64_review --output-on-failure
```

`disvm_native64_review_module_sets` проверяет реальные сгенерированные описания,
создание модулей/Type/связей, освобождение при отказах и атомарную публикацию.
Независимый тест FlashVM перебирает 72 сочетания порядка запросов и удаления
для каждой совместимой модели. После удаления проверяются оставшаяся цепочка,
владение и вызовы настоящих C-функций. Выходные указатели заимствованы: после
выгрузки соответствующего модуля пользоваться ими нельзя. Пустая транзакция
не должна читать неиспользуемые указатели или менять существующий реестр.

`disvm_native64_review_typed_sys` проверяет собственные снимки аргументов,
полные карты map8, настоящий форматтер, ограниченный рост буфера и четыре
доверенных C-шлюза Sys. Используются реальные тела heap/GC, преобразования и
защиты ошибок emu/os; выделение памяти, планировщик и вывод ограничены тестовыми
сервисами. Специальные сборки с удалённой защитой обязаны завершиться ошибкой
на активной проверке владения или состояния планировщика.

Отказ публикации результата после записи не отменяет уже выведенные байты.
Автоматически повторять такую операцию нельзя. Проверки указателей не доказывают
происхождение памяти: вызывающий обязан обеспечить текущую отображённую ячейку,
сериализацию и корни входных объектов.

Обе группы используют собранный из исходников `limbo-bootstrap` только для
генерации native64 C-описаний. Его NC64 байткод не выдаётся за Dis64.
Санитайзер нужен этим необязательным проверкам разработки; установленному
проигрывателю он не требуется.

## Полное замыкание проверок

```sh
NATIVE64_LIMBO=/absolute/path/to/fresh/limbo \
NATIVE64_MATH_LIBDIR=/absolute/path/to/source-built/native/lib \
NATIVE64_CFLAGS='-O3 -g -DNDEBUG -fno-strict-aliasing -fsanitize=undefined -fno-sanitize-recover=all' \
python3 disVM/upstream/utils/tests/native64-layout.py
```

В явном каталоге библиотек должны лежать собранные classic-mk `lib9.a` и
`libmath.a`. Без них группа полной регистрации Math сообщает пропуск.
Проверяются все 68 экспортов Math, layout/GC/результаты, типизированные Sys и
наборы модулей. Предварительно собранные численные архивы не дают покрытия
санитайзером всей библиотеки. Это проверки на хосте, не исполнение на физических
ARM64/RV64 и не полная загрузка ОС.

## Согласование

Рабочие журналы: [Inferno](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-inferno-journal.md)
и [FlashVM](https://github.com/bhgv/Inferno-OS-bhgv/blob/experiment/doc/dis64-flashvm-journal.md).
Четыре отказа упакованных variadic-входов Sys и защита полной загрузки остаются.
Frame64/map8, профиль допуска 43-op np0, `execution_supported=false` и настройки
NC64/SDK не меняются. Частные C-теги не являются идентификаторами wire-формата.
Прежние результаты ASan для оптимизированного UTF и инъекции unwind остаются
открытыми. Атомарность графа модулей не откатывает эффекты их инициализаторов.

CTest размещает временные файлы проверок в каталоге сборки через
`NATIVE64_TMPDIR`. При прямом запуске драйверов можно указать существующий
доступный для записи каталог той же переменной. Выбор исходников и ABI не меняются.
