# Контракт блокировки длинной операции с владельцем

[English](OWNED_OPERATIONS.md) · [Брокер](broker/README.ru.md) ·
[Отрицательные позиции](../fir/v1/doc/RELATIVE_SEQUENCES.ru.md)

Статус: **контракт проектирования, не готовый mutex каждого объекта**.
Сейчас VM имеет один поток-владелец, а внутри C-копирования массива/таблицы
Dis-процессы не переключаются. C99-API таблиц требует сериализации у владельца.
Mutex брокера защищает только метаданные диагностики.

Длинная изменяющая операция должна получать устойчивый токен. Блокировка записи
хранит токен и глубину повторного входа. Вложенные чтения/записи той же операции
допускаются, чужой писатель ждёт. Одного ID нативного потока недостаточно:
несколько VM-задач могут исполняться в одном потоке. Удалённый ID переменной
или объекта не даёт права подделать токен.

Длина, отрицательные индексы и диапазон фиксируются после захвата защиты.
Она удерживается при перемещении/перестановке и публикации результата. Внутренние
записи владельца проходят по тому же токену; mutex не открывается для всех.
Читателю нужен shared guard либо устойчивый снимок, пока структура меняется.
Копирование обычно требует read-защиты источника и write-защиты назначения;
перестановка на месте — исключительного владения.

Несколько владельцев захватываются в устойчивом глобальном порядке; одинаковые
владельцы предварительно объединяются. Повторный вход не означает произвольного
повышения shared lock. Уровни освобождаются ровно один раз при успехе, исключении
VM и ошибке выделения. Таймаут/обрыв канала не доказывает остановку исполняющего
владельца: корень и блокировка сохраняются до подтверждения завершения/отмены.

Короткий spin допустим для метаданных замка. Ожидание канала, планировщика,
диска или сети требует очереди VM либо нативного ожидающего примитива.
Нельзя удерживать spinlock через GC/переключение. Длинные операции позднее можно
делить на порции, сохраняя lease операции и публикуя согласованные состояния.

Независимый mutex брокера не заменяет объектную защиту. Диагностика/отладчик
сообщают ожидание замка или остановку владельца без захвата его payload-lock.
Debug-пауза не снимает защиту незавершённой операции. Подключение этих токенов
к массивам/таблицам/проекциям и проверки реальной конкуренции потоков ещё нужны.
