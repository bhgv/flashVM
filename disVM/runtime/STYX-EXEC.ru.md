# Вызов исполняемых узлов VFS из Limbo

[Публикация обработчиков из Limbo](STYX-EXEC-PUBLISH.ru.md)

[English](STYX-EXEC.md) · [Публикация](../../flashVM/doc/STYX_RPC_NEWNODE.ru.md) · [SDK C и обмен по Styx](../../lib/styxrpc/reference/node_exec.ru.md)

`Styxexec` вызывает функции, опубликованные в VFS другой программы.
FlashVM регистрирует обычную функцию AS через
`vfs.newnode(path, "x", callback)`. Связанные функции можно разместить в
одном каталоге. Вызов использует уже подключённое монтирование, например
`/peer`, и разрешает путь от его корня. Текущий рабочий каталог обеих
программ на этот путь не влияет.

## Запуск парного сценария

1. Возьмите [команду сборки и прогона](STYX-CHANNEL.md#acceptance)
   парного теста и добавьте `--execute`.
2. Скрипт компилирует [приложение Limbo](../../lib/styxrpc/tests/flashvm/execute_pair.b)
   и три исходника AS. [Метод кадра](../../lib/styxrpc/tests/flashvm/execute_pair.as)
   публикует два исполняемых узла и один узел только для чтения.
3. [Обработчик](../../lib/styxrpc/tests/flashvm/execute_apply.as) получает
   `"x"`, массив байтов и его длину. Он записывает в начало массива
   номер вызова и крайние байты входа, затем возвращает длину ответа.
   Тест проверяет отказы, пустой запрос и запрос из нескольких записей.
   Ожидаемая строка `PASS native execute RPC paired VMs`.

Передайте `--tcp` для пары по TCP и `--jit` для режима JIT. Колбэк
выполняется в потоке владельца фильма после получения всех входных
байтов. Ответ помещается во входной буфер. Служебный файл скрыт в списке
каталога. Исполняемый узел виден по опубликованному пути.

Вызовите [init](styx-exec-init.ru.md), чтобы загрузить Sys, затем
[call](styx-exec-call.ru.md) для обращения к узлу.
