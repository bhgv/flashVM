
## Двусторонний маунт для локальной программы

В сборке DisVM с нативным SDK можно передать подключённый поток и
запустить локальную программу, которая загружает библиотеки у провайдера.

```sh
disvm --styx-mount-fd 3 -- --no-jit caller.dis
```

Команда монтирует сторону провайдера в `/peer` гостевой VFS. Каталог
`peer` на хосте не требуется. Канал 0 мультиплексированного транспорта
несёт прямой маунт Styx, канал 1 обслуживает виртуальный контекст клиента.
Провайдер монтирует канал 1 и передаёт корень обработчику с контекстом.
Обычный типизированный `load` и вызов функции автоматически публикуют
контекст активного процесса. Провайдер определяется выданным соединением.

[Пример Limbo](../examples/remote-scalar/styx-cli.b) и тест
`terminal-caller-mount-cli` проверяют команду в двух процессах ОС с JIT и
без него. Укажите в настройке тестовой сборки SDK
`INFERNO_DISVM_TERMINAL_CLI` со ссылкой на исполняемый DisVM с этим SDK.

Для отправки запуска по тому же маунту укажите путь программы, файл
запросов на запись и тег S-записи.

```sh
disvm --styx-mount-fd 3 --launch app.dis submit 17 -- caller.dis
```

Оба пути относятся к корню подключения. Маунт удерживает точные узлы.
Программа вызывает `Vfsnative.run` или `Vfsnative.runargs` для
`/peer/app.dis` либо его bind-имени. Провайдер обслуживает файл запросов
и принимает выбранный тег. Положительный результат подтверждает
доставку запроса провайдеру. В этом профиле передаются исходные
стартовые байты.

[Пример отправки запуска](../examples/remote-scalar/styx-run.b)
проверяет двоичные аргументы через bind и отказ для соседнего файла
без маршрута. Пример входит в тест `terminal-caller-mount-cli`.
