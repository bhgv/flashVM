# Целочисленная переменная в VFS

[English](VFS-INT-VARIABLE.md) · [Интерфейс Limbo](../module/vfsexport.m) · [Пример](fixtures/vfs-publication/main.b)

```limbo
intvar: fn(initial: int): ref Root;
intget: fn(root: ref Root): (int, int);
intset: fn(root: ref Root, value: int): int;
```

Загрузите `Vfsexport` по `Vfsexport->PATH`. `intvar` создаёт общую
атомарную ячейку со знаковым 32-битным начальным значением и возвращает
точную ссылку `Root` или `nil` при отказе. Передайте ссылку другому
Limbo-процессу или опубликуйте как обычный файл через `overlay`.
`intget` возвращает `(1, значение)` при успехе и `(0, 0)` для другого
корня. `intset` возвращает 1 после записи либо 0 при отказе. Типизированные
операции требуют исходную ссылку на ячейку. Файловая проекция может задавать
свои ограничения чтения и записи.

Файл содержит четыре байта со старшим байтом вперёд. Каждое открытие имеет
свою позицию. Читайте или записывайте целиком с нулевого смещения.
Частичная запись отклоняется. Типизированные и файловые операции работают
с одним значением без управляемых указателей внутри файловых обработчиков.
Корень и открытые дескрипторы удерживают ячейку.

Запустите `ctest -R '^disvm_native_vfs_publication$' -V`. Пример создаёт
ячейку из Limbo, помещает её в `/.var/count`, передаёт ссылку потомку и
проверяет изменения через типизированные и файловые операции. Этот пример
проверяет локальную публикацию VFS.

## Публикация по Styx

Нативный лаунчер может передать точный файл ячейки в
`styxvariableserverstart` из библиотеки `styx_unibus_server`.
Сервер принимает подключённый канал во владение, удерживает файловую
ссылку и публикует `.var/<имя>` с исходными правами чтения и записи.
Каждый открытый fid получает отдельную позицию. После закрытия канала
вызовите `styxvariableserverjoin`.

[Пример](../examples/remote-scalar/styx-variable.b) создаёт ячейку в Limbo
и меняет значение на `-2`. С удалённой стороны обычный Styx-клиент читает
это значение и пишет `65539` обратно. Владелец видит результат через
`intget`. Нативный стенд передаёт серверу ту же файловую ссылку, которую
выбрал пример. Запуск проверки в настроенном SDK
`ctest -R '^terminal-managed-variable-guest$' -V`.

Для каталога выбранной загрузки используйте `styxvariableserverstartprogram`.
Конструктор принимает имя загрузки и ненулевой PID от доверенного
лаунчера и публикует `<загрузка>/.prog/<pid>/.var/<имя>` и файл `.pid`
только для чтения. В проверке PID берётся из `Processctl.pid()`.
Принимающая сторона захватывает каталог загрузки и открывает ячейку
через своё `/.prog/.self/.var/count`. Этот же тест отдельно проверяет
прежний путь `.var/count`. [Контекст процесса](LAUNCH-PROGRAM-ROUTE.ru.md)

`styxvariableserverstartprogramfiles` публикует в одном `.var` от 1 до
64 явно выданных файлов. Каждый элемент `StyxPublishedVariable` задаёт имя
и точный провайдер. Конструктор удерживает файлы до завершения сервера.
Повтор имени или непригодный файл отклоняет всю публикацию до запуска
диспетчера. Права чтения и записи берутся у каждого файла отдельно.

В сквозном примере `count` доступен на чтение и запись, а `limit` выдан
только на чтение. Клиент открывает оба через один Styx-монт. Владелец
проверяет, что обновление `count` сохранило значение `limit`.
