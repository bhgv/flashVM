# Vfsexport.table

[English](VFS-HYBRID-TABLE.md) · [Интерфейс](../module/vfsexport.m) · [Реализация](vfs/cap_bigtable.c)

```limbo
table: fn(source: ref Root): ref Root;
```

Загрузите `Vfsexport` и передайте живой дескриптор из `Bigtable`.
Каталог удерживает то же нативное хранилище. При недопустимом дескрипторе
или нехватке памяти возвращается nil. Смонтируйте каталог или добавьте
его под `.var`. У таблицы остаются плотная последовательность,
разреженные числовые и строковые ключи.

| Файл | Доступ и данные |
| --- | --- |
| `.type` | Текст `table of big\n` только для чтения. |
| `.len` | Плотная длина десятичным числом и перевод строки. |
| `.count` | Число всех пар десятичным числом и перевод строки. |
| `.ins` | Записать знаковые 64-битные позицию и значение. |
| `.push` | Записать одно знаковое 64-битное значение. |
| `.pop` | Прочитать последнее значение плотной части как знаковое 64-битное слово. Пустая часть даёт ошибку чтения. |
| `.add` | Записать байт 0 и восьмибайтовый числовой ключ либо байт 1 и от 0 до 255 байт текста. После ключа записать восьмибайтовое знаковое значение. |

Все слова передаются старшим байтом вперёд. Для каждой изменяющей
операции откройте отдельный FD. Успешная запись завершает операцию.
Первое непустое чтение `.pop` извлекает значение. Короткие чтения
возвращают остаток того же значения. Вставка и извлечение сохраняют
разреженные и строковые ключи. Повторное добавление ключа даёт отказ.
Удерживаемая блокировка таблицы может отложить операцию VFS.
[Пример Styx](../examples/remote-scalar/styx-scoped-calls.b) сверяет удалённые
изменения обеих частей с локальным чтением через Bigtable.
