# Файлы и каталоги по платформам — v0.1650

[English](FILESYSTEM.md) · [Рантайм](README.md) · [Исполняемый пример](../examples/filesystem/README.ru.md)

`Sys.stat`, `Sys.fstat`, `Sys.dirread` работают через C89
[интерфейс ports](../../flashVM/ports/filesystem_port.h). В DisVM остались проверка
аргументов, перевод в `Sys.Dir` и управление корнями GC. Заголовки и дескрипторы
операционной системы не выходят из ports. Выбор действует и для отдельного
DisVM, и для связанного с FlashVM редактора.

| ОС | Реализация | Особенности |
| --- | --- | --- |
| Linux | [linux](../../flashVM/ports/linux/filesystem.c) | stat/fstat, обход относительно открытого дескриптора каталога |
| macOS | [mac](../../flashVM/ports/mac/filesystem.c) | Отдельный выбор общей POSIX-реализации |
| Android | [android](../../flashVM/ports/android/filesystem.c) | Разрешённые обычные пути приложения; SAF/content provider пока не подключён |
| Windows | [windows](../../flashVM/ports/windows/filesystem.c) | UTF-16, CRT-потоки, отдельные handles метаданных и FindFirst/Next |

Linux/macOS/Android используют общую [POSIX-механику](../../flashVM/ports/filesystem_posix.inc)
внутри ports. [file_port.c](../../flashVM/ports/file_port.c) передаёт выбранному
порту открытие и проверку пути. URI, включая `content://`, отвергаются до открытия,
также в режиме записи с усечением. Имена должны быть корректным UTF-8; замены
невалидных байтов и усечения нет. Максимум имени — 4095 байтов. Windows пока тоже
отвергает `://`: нужен обычный путь диска/UNC, не `C://...`.

## Контракты Limbo

- `stat(path)` возвращает `(0, запись)` либо `(-1, пустая запись)` и текст ошибки.
  Встроенный NUL в пути отвергается до вызова ОС.
- `fstat(fd)` запрашивает открытый файл/каталог, сохраняя обе логические позиции
  файла. Имя, сохранённое при открытии, служит для отображения. В POSIX запрос
  сохраняет идентичность после переименования/удаления имени. В Windows сама
  возможность такого удаления зависит от политики совместного доступа CRT.
  Метаданные стандартных дескрипторов 0–2 пока не поддержаны.
- Каталог открывается `open(path, Sys->OREAD)`. `dirread` выдаёт `(n, массив)` не
  более 32 записей, `(0, nil)` в конце, `(-1, nil)` при ошибке. `.` и `..`
  исключаются. Обычные `read`/`seek` каталога отвергаются. Общая квота файлов и
  каталогов — 29 слотов.
- Последний `ref Sys->FD` закрывает ресурс. Массивы и строки записей принадлежат
  VM независимо от курсора. Старые корни очищаются до освобождения; защищённая
  сборка результата освобождает нативную порцию при исключении выделения VM.
- Настоящий Inferno `Readdir` теперь выполняет обход и сортировку через эти
  вызовы. Обход не является атомарным снимком. Невалидное UTF-8 имя, исчезнувший
  элемент или оборванная символическая ссылка могут завершить ошибкой всю
  порцию. После этого курсор постоянно ошибочный: нужен явный повторный open.

Размер передаётся точно как `big`; превышение знаковых 64 бит отвергается.
Идентификаторы inode/file index и device/volume берутся у ОС; `qid.vers` зависит
от секунд mtime и не является уникальной версией. Времена — знаковые Unix-секунды;
права — младшие девять бит и DMDIR. POSIX uid/gid — десятичные ID. В Windows
uid/gid пусты, права отражают атрибут read-only, а не ACL. `muid` пуст.

## Владение в переносимом API

Объявления — [filesystem_port.h](../../flashVM/ports/filesystem_port.h). Пути и
указатели результатов заимствованы; метаданные меняются лишь при успехе. Вызовы
требуют внешней синхронизации и могут блокировать вызывающий поток.

| Функция | Результат и освобождение |
| --- | --- |
| [`fvm_port_path_info`](../../flashVM/ports/filesystem_port.h#L48) | Копирует метаданные пути, следует ссылкам, ресурс не передаёт. |
| [`fvm_port_file_info`](../../flashVM/ports/filesystem_port.h#L43) | Копирует данные открытого потока, не меняет позиции. |
| [`fvm_port_directory_open`](../../flashVM/ports/filesystem_port.h#L53) | При успехе передаёт один курсор; при ошибке output неизменён. |
| [`fvm_port_directory_info`](../../flashVM/ports/filesystem_port.h#L57) | Запрашивает сохранённый handle каталога. |
| [`fvm_port_directory_read`](../../flashVM/ports/filesystem_port.h#L63) | Передаёт порцию; NULL/0 в конце. Ошибка сохраняет output и делает курсор ошибочным. |
| [`fvm_port_directory_entries_free`](../../flashVM/ports/filesystem_port.h#L67) | Освобождает только нативную порцию, допускает NULL. |
| [`fvm_port_directory_abort`](../../flashVM/ports/filesystem_port.h#L71) | Запрещает продолжение после ошибки публикации результата. |
| [`fvm_port_directory_close`](../../flashVM/ports/filesystem_port.h#L75) | Закрывает курсор, допускает NULL. |

`FVM_FileNumber64` хранит точные 64 бита двумя словами high/low по 32 бита,
сохраняя C89 ABI. Типы ОС и извлечение дескрипторов скрыты внутри ports.

Пример проверяет Unicode, двоичный NUL, разреженный файл 4294967303 байта,
три порции каталога, Readdir, EOF, ошибки и повторное использование дескрипторов.
Оба режима исполнения проверяются с quantum 1/2048. Отдельный C89-тест проверяет
fstat после rename/unlink и остановку после частичной ошибки; на Linux он также
запускается с ASan/UBSan. Нативная проверка Windows/macOS/Android ещё предстоит.

Файловые вызовы пока блокируют единственного владельца VM. Фоновое I/O,
отмена, SAF/JNI, namespace и `/prog` для отладчика в эту серию не входят и остаются
отдельными задачами для отзывчивой IDE и брокера.
