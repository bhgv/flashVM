# Публикация файловых колбэков VFS из Limbo

[English](STYX-NODES.md) · [API только для исполнения](STYX-EXEC-PUBLISH.ru.md) · [Файловый API ActionScript](../../flashVM/doc/STYX_RPC_OS.ru.md)

Приложение на Limbo в парной DisVM может опубликовать колбэк как
обычную запись в своём живом пространстве имён. Файл виден в каталоге
вместе с остальными записями. Его имя и права видны через stat.
Обычные чтение и запись по Styx доходят до владельца в Limbo.
Для исполнения используется существующая служба libstyxrpc в той же сессии.

## Интерфейс

| Функция | Назначение |
| --- | --- |
| [`init`](styx-nodes-init.ru.md) | Загрузить системный модуль перед публикацией. |
| [`publish`](styx-nodes-publish.ru.md) | Занять свободный абсолютный путь с любым непустым подмножеством `rwx`. |
| [`Node.dispatch`](styx-nodes-dispatch.ru.md) | Обработать один запрос через загруженный модуль Limbo. |
| [`StyxnodeHandler.transfer`](styx-nodes-transfer.ru.md) | Заполнить буфер или подтвердить обработанный префикс входа. |
| [`Node.recv`](styx-nodes-recv.ru.md), [`Node.reply`](styx-nodes-reply.ru.md), [`Node.refuse`](styx-nodes-refuse.ru.md) | Явно принять или завершить запрос. |
| [`Node.close`](styx-nodes-close.ru.md) | Освободить регистрацию. |

Для фиксированной длины и смещений используйте
[позиционную публикацию](STYX-NODE-OFFSETS.ru.md). Исходный `publish`
создаёт последовательный поток.

Чтение и запись последовательные. За один вызов колбэк получает
один фрагмент транспорта и может обработать меньше байтов.
Ноль при чтении означает EOF. Следующее чтение может запросить новые
данные. Положительный короткий результат позволяет библиотеке запросить
оставшиеся байты. Размер фрагмента до 65 536 байтов. Обычный удалённый
ввод-вывод дополнительно ограничен согласованным размером сообщения Styx.
Файл сообщает длину ноль. Колбэк не получает смещение, поэтому операция
с изменённой позицией завершается ошибкой. Новое открытие начинает
новый курсор транспорта. Состояние приложения принадлежит обработчику
Limbo и может быть общим для разных открытий.

Нативный код ждёт каждый фрагмент не более пяти секунд с учётом
ожидания предыдущего фрагмента. Удалённая сторона может завершить
ожидание раньше. Ошибка у вызывающей стороны возможна даже после
изменения состояния приложения. Владелец должен ответить прежде, чем
синхронно обратиться назад к той же ожидающей стороне. Локальный
управляющий fid и удалённая служба исполнения зарезервированы.
Путь прикладного файла разрешается по обычным правилам VFS.
Открытый файл сохраняет исходного провайдера при изменении пространства
имён и возвращает ошибку после снятия публикации владельцем.

## Проверка в паре

1. Выполните [команду парной проверки](STYX-CHANNEL.ru.md#проверка)
   с `--nodes`. Добавьте `--tcp` для TCP или `--jit` для JIT.
2. [Модуль запуска на Limbo](../../lib/styxrpc/tests/flashvm/nodes_pair.b)
   загружает `styxnodes.dis`, инициализирует модуль, публикует
   `/tools/mail` с `"rwx"` и запускает собранный SWF через файлы
   загрузки и состояния плеера. На каждый запрос транспорта он вызывает
   `node.dispatch(handler)`.
3. [SWF на AS](../../lib/styxrpc/tests/flashvm/nodes_pair.as) находит
   запись через `os.opendir`, открывает её через `vfs.open`, отправляет
   четыре байта, читает два двоичных байта и вызывает `os.exec`.
   [Обработчик](../../lib/styxrpc/tests/flashvm/nodes_handler.b)
   подтверждает запись по два байта, заполняет буфер чтения и возвращает
   короткий ответ исполнения. SWF проверяет результаты и сообщает о завершении.
4. Модуль Limbo проверяет отказ и отзыв открытого файла, закрывает все
   регистрации и печатает `PASS native nodes RPC paired VMs`.

Проверка использует компиляторы Limbo и AS, инструменты FIR и линкер SWL
из проекта. Оба приложения работают в штатной паре под Linux.
