# Vfsctl.run

[English](VFS-RUN.md) · [Обзор](VFS-LAUNCH.ru.md) · [Руководство](../examples/vfs-run/TUTORIAL.ru.md) · [Реализация](vfs/vfsnative.c)

## Синтаксис

```limbo
include "vfsctl.m";
# Загрузите Vfsctl и вызовите init() перед run.
run: fn(path: string): int;
```

Доступно в hosted DisVM с модулем [Vfsctl](../module/vfsctl.m) и встроенным
`$Vfsnative`. Обязательный параметр `path` задаёт непустое имя VFS длиной до
4095 байт UTF-8. Можно использовать абсолютный или относительный путь и имя,
созданное через bind. Относительный путь использует пространство имён и
рабочий каталог вызывающего процесса.

## Результат и эффекты

| Результат | Значение |
| --- | --- |
| `1` | Владелец подтвердил успешное выполнение либо маршрут без результата подтвердил доставку. |
| `0` | Неверный путь, недоступный маршрут или отказ до подтверждения доставки. |
| `-1` | Доставка или результат выполнения неизвестны. |
| `-2` | Владелец подтвердил ошибку выполнения. |

Маршрут даёт выбранный VFS-провайдер. Вызов отправляет один пустой пакет и при
возврате освобождает временные ссылки на маршрут и пространство имён. Вызов
может ждать I/O провайдера. Runtime передаёт сигнал отмены и сохраняет
результат доставки, если отмена произошла одновременно с записью.
Автоматического повтора нет. Исполнением и временем жизни файла результата
управляет хост.

Маршрут Styx с контекстом открывает `.unibus` для чтения и записи и
держит тот же fid до результата. Отдельно открывать `.exit` не нужно.

## Пример

```limbo
delivery := vfs->run("/routed.dis");
```

При результате 1 клиент может перейти к отдельно опубликованному файлу
результата. См. [TCP-пример](../examples/vfs-run/runexample.b) и
[`runargs`](VFS-RUNARGS.ru.md).
