# Общий скалярный сервис владельца

[English](SCALAR-OWNER-SERVICE.md) · [Исходник](../limbo/scalarowner.b) · [Запуск двух DisVM](../examples/remote-scalar/STYX.ru.md)

Сборка нативных модулей включает `scalarowner.dis`, общий сервис для одного
опубликованного экспорта `fn(int): int`. Он работает в VFS владельца.
[Vfsnative.scalarload](VFS-SCALAR-LOAD.ru.md) связывает реализацию, а сервис
вызывает связанный слот обычной инструкцией Dis. Запрос и ответ передаёт
общий встроенный код на C.

Лаунчер передаёт через `Launchcontext.arguments()` шесть или семь полей UTF-8,
разделённых табуляцией. Вся строка ограничена 4096 байтами.

| Поле | Значение |
| --- | --- |
| Реализация | Путь исходной библиотеки Dis в пространстве владельца |
| Экспорт | Имя функции в компилированной таблице экспортов |
| Запрос | Читаемый путь выданного приёмника |
| Ответ | Записываемый путь встречного файла Styx |
| Тег запроса | Десятичный ненулевой 32-битный тег маршрута |
| Тег ответа | Десятичный ненулевой 32-битный тег встречного маршрута |
| Число вызовов | Необязательное десятичное число 0–65536, по умолчанию 1. Ноль ждёт закрытия сессии |

Сервис загружает реализацию один раз и обрабатывает заданное число запросов.
Каждый запрос получает отдельную запись результата или ошибки.
Исключение реализации даёт код ошибки владельца 1. Пути и теги задаются
хостом при выдаче маршрута. Сервис не устанавливает соединение, не монтирует
удалённую сторону и не выбирает реализацию по сетевым данным.

С нулевым счётчиком владелец ждёт вызовы до записи завершения или EOF.
Фиксированный счётчик сохраняет прежний ограниченный режим.

## Несколько экспортов одной реализации

Запустите тот же сервис со следующими полями, разделёнными табуляцией:

```text
set  реализация  экспорт  запрос  ответ  [экспорт запрос ответ ...]
```

Укажите от одной до восьми троек. Пути запроса и ответа ведут к локальным
приёмникам соответствующего экспорта [смонтированного сервера](../native/terminal/SCALAR-FUNCTION-MOUNTED.ru.md).
Все тройки используют тег запроса 72 и ответа 73. Сервис связывает все
имена в одном экземпляре до чтения запросов. Глобальные переменные модуля
общие для его экспортов. Сервис проверяет маршруты в порядке конфигурации,
кратко ждёт, когда в активных приёмниках нет запросов, и завершается после
EOF на каждом пути запроса. Прежний формат запуска одного экспорта также
доступен.

В примере с двумя DisVM функции `compute` и `adjust` обслуживает одна
реализация. Чередование функций, включая вызов с исключением, проверяет
общий счётчик. См. [запускаемый пример](../native/terminal/SCALAR-FUNCTION-MOUNTED.ru.md).

## Один экспорт с ADT по ссылке

Для экспорта с [профилем скалярного ref](../native/terminal/SCALAR-FUNCTION.ru.md#возврат-полей-adt-по-ссылке)
публикатор задаёт `dis_ref` в записи `StyxMountedScalar`. При запуске общего
сервиса передайте пять полей через табуляцию.

```text
ref  implementation  export  request  reply
```

Сервис связывает именованный экспорт один раз и принимает запросы до EOF.
На каждый запрос он создаёт локальный ADT из входного снимка и вызывает
связанный экспорт. При успехе он отправляет возвращённый кортеж и итоговые
скалярные поля ADT. При исключении сервис отправляет запись ошибки,
а поля объекта клиента сохраняют свои значения. Формат запуска использует
запрос без PID. См. [запускаемый пример](../examples/remote-scalar/STYX.ru.md#возврат-полей-из-исходного-dis).

## Один экспорт со списком аргументов

Для [профиля со списком аргументов](../native/terminal/SCALAR-FUNCTION.ru.md#список-аргументов-и-вложенный-результат)
опубликуйте запись `StyxMountedScalar` с флагом `dis_call`. Передайте общему
сервису пять полей через табуляцию.

```text
list  implementation  export  request  reply
```

Сервис сверяет компилированную сигнатуру при связывании исходного Dis.
Для каждого запроса он вызывает экспорт с тремя обычными аргументами
Limbo и отправляет вложенный результат либо ошибку. Сервис работает
до EOF приёмника запросов.

## Один экспорт с двумя ссылками

Для [профиля с двумя ref](../native/terminal/SCALAR-FUNCTION.ru.md#две-ссылки-в-одном-вызове)
опубликуйте запись `StyxMountedScalar` с флагом `dis_ref_pair`. Передайте
общему сервису пять полей через табуляцию.

```text
refpair  implementation  export  request  reply
```

Сервис связывает исходный экспорт один раз. На каждый запрос он создаёт
один локальный ADT на номер объекта. Если оба номера совпадают, обычному
вызову Dis передаётся одна и та же ссылка. При успехе сервис отправляет
результат и итоговые поля каждого объекта по одному разу. При исключении
он отправляет ошибку через приёмник ответов. EOF приёмника запросов
завершает работу сервиса.

## Профиль из исходного load

Используйте [styxunibusserverstartloaded](../native/terminal/UNIBUS-SERVER-LOADED.ru.md),
чтобы зарезервировать один экспорт до запуска VM владельца. Передайте
общему сервису шесть полей через табуляцию.

```text
loaded  implementation  export  request  reply  offer
```

`implementation` и `export` выбирают исходный файл Dis и именованную
функцию. `request` открывает чтение из локального приёмника запросов.
`reply` открывает запись в локальный приёмник ответов. `offer` открывает
запись в [служебный приёмник профиля](../native/terminal/UNIBUS-SERVER-LOAD-PROFILE.ru.md).

Обычный загрузчик Dis читает локальный образ, а линкер создаёт экземпляр
модуля для выбранного экспорта. Общий сервис использует тот же экземпляр
и отправляет диспетчеру C скомпилированные имя и сигнатуру через `offer`.
Диспетчер выбирает совместимый шлюз и выдаёт ту же S-запись из `.interface`.
Обычный клиентский `load` сверяет её со скомпилированным импортом без
чтения исходного `.m` по сети. Режим обслуживает один экспорт и шесть
существующих профилей шлюза. Другие режимы сервиса обслуживают наборы
экспортов.

## Один load для нескольких экспортов

Вызовите [styxunibusserverstartloadedset](../native/terminal/UNIBUS-SERVER-LOADED-SET.ru.md),
чтобы зарезервировать каталог выбранных экспортов. Передайте поля через
табуляцию в том же порядке, что и имена в массиве.

```text
loaded-set  implementation  export  request  reply  offer  [export request reply offer ...]
```

Передайте от одной до восьми групп экспортов. Для каждой группы
действуют те же разрешения, что и в режиме `loaded` для одного экспорта.
Сервис загружает исходный образ один раз и создаёт один локальный
экземпляр данных. Все однослотовые типизированные представления удерживают
одни и те же данные модуля. Циклы обработки запускаются после связывания
всех представлений. Отсутствующий или неподдерживаемый экспорт отклоняет
каталог до любого вызова. Диспетчер Styx обслуживает запросы на одном
сервере последовательно. Сервис завершается после EOF всех приёмников.

В [примере с двумя VM](../examples/remote-scalar/STYX.ru.md#загрузка-шести-экспортов-с-общим-состоянием)
проверяются все шесть поддерживаемых профилей в одном каталоге.
