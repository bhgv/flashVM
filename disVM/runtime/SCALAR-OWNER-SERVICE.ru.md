# Общий скалярный сервис владельца

[English](SCALAR-OWNER-SERVICE.md) · [Исходник](../limbo/scalarowner.b) · [Запуск двух DisVM](../examples/remote-scalar/STYX.ru.md)

Сборка нативных модулей включает `scalarowner.dis`, общий сервис для одного
опубликованного экспорта `fn(int): int`. Он работает в VFS владельца.
[Vfsnative.scalarload](VFS-SCALAR-LOAD.ru.md) связывает реализацию, а сервис
вызывает связанный слот обычной инструкцией Dis. Запрос и ответ передаёт
общий встроенный код на C.

Лаунчер передаёт через `Launchcontext.arguments()` шесть или семь полей UTF-8,
разделённых табуляцией. Вся строка ограничена 4096 байтами.

| Поле | Значение |
| --- | --- |
| Реализация | Путь исходной библиотеки Dis в пространстве владельца |
| Экспорт | Имя функции в компилированной таблице экспортов |
| Запрос | Читаемый путь выданного приёмника |
| Ответ | Записываемый путь встречного файла Styx |
| Тег запроса | Десятичный ненулевой 32-битный тег маршрута |
| Тег ответа | Десятичный ненулевой 32-битный тег встречного маршрута |
| Число вызовов | Необязательное десятичное число 0–65536, по умолчанию 1. Ноль ждёт закрытия сессии |

Сервис загружает реализацию один раз и обрабатывает заданное число запросов.
Каждый запрос получает отдельную запись результата или ошибки.
Исключение реализации даёт код ошибки владельца 1. Пути и теги задаются
хостом при выдаче маршрута. Сервис не устанавливает соединение, не монтирует
удалённую сторону и не выбирает реализацию по сетевым данным.

С нулевым счётчиком владелец ждёт вызовы до записи завершения или EOF.
Фиксированный счётчик сохраняет прежний ограниченный режим.

## Несколько экспортов одной реализации

Запустите тот же сервис со следующими полями, разделёнными табуляцией:

```text
set  реализация  экспорт  запрос  ответ  [экспорт запрос ответ ...]
```

Укажите от одной до восьми троек. Пути запроса и ответа ведут к локальным
приёмникам соответствующего экспорта [смонтированного сервера](../native/terminal/SCALAR-FUNCTION-MOUNTED.ru.md).
Все тройки используют тег запроса 72 и ответа 73. Сервис связывает все
имена в одном экземпляре до чтения запросов. Глобальные переменные модуля
общие для его экспортов. Сервис проверяет маршруты в порядке конфигурации,
кратко ждёт, когда в активных приёмниках нет запросов, и завершается после
EOF на каждом пути запроса. Прежний формат запуска одного экспорта также
доступен.

В примере с двумя DisVM функции `compute` и `adjust` обслуживает одна
реализация. Чередование функций, включая вызов с исключением, проверяет
общий счётчик. См. [запускаемый пример](../native/terminal/SCALAR-FUNCTION-MOUNTED.ru.md).
