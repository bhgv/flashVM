# Файлы VFS с колбэками и смещениями

[English](STYX-NODE-OFFSETS.md) · [Публикация из Limbo](STYX-NODES.ru.md) · [Публикация из ActionScript](../../flashVM/doc/STYX_RPC_NEWNODE.ru.md) · [SDK на C](../../lib/styxrpc/reference/module_slot_new_node_at.ru.md)

Используйте этот режим, если колбэк обращается к байтам по известным
позициям в объекте фиксированной длины. Длина задаётся в байтах от нуля
до 2⁵³−1 и видна через обычный stat VFS. Публикация не выделяет память
пропорционально длине. Данные принадлежат колбэку, поэтому файл может
быть разреженным. Каждое открытие начинает курсор с нуля. Можно
установить позицию от начала, текущего смещения или конца файла.
Следующее чтение или запись передаст абсолютную позицию обработчику.

| Среда публикации | Объявление | Обработчик |
| --- | --- | --- |
| Limbo | [`nodes->publishat(path, permissions, length)`](styx-nodes-publishat.ru.md) | [`transfer(path, operation, buffer, offset)`](styx-nodes-transfer-at.ru.md) |
| ActionScript | [`vfs.newnode(path, permissions, callback, length)`](../../flashVM/doc/STYX_RPC_NEWNODE.ru.md) | `callback(operation, buffer, len, offset)` |
| SDK на C | [`styxrpc_module_slot_new_node_at`](../../lib/styxrpc/reference/module_slot_new_node_at.ru.md) | `transfer(context, access, offset, bytes, size, used)` |

Буфер чтения ограничен числом байтов до конца файла. На конце и за
пределами файла чтение возвращает ноль без вызова колбэка. Фрагмент
записи, выходящий за конец файла, отклоняется до вызова обработчика.
Если транспорт разбил запрос, предыдущие фрагменты могли быть
подтверждены. Короткий успешный результат продвигает курсор только на
подтверждённое число байтов. Исполнение требует права `x`, получает
весь исходный буфер независимо от длины файла и имеет смещение ноль.
В AS смещение имеет тип Number, в Limbo — `big`. Локальный seek DisVM
также ограничен диапазоном нативного знакового `long`. Удалённый seek
может сразу изменить позицию клиента. Сервер получит её в следующем
запросе чтения или записи.

Позиционный файл Limbo с правами на чтение и исполнение может выдавать
точные байты образа Dis. При локальном нативном чтении или записи очередь
проверяет отмену между ожиданиями. Билет без ответа становится
недействительным после отмены. Если владелец уже получил операцию, её
прикладные эффекты могли произойти. Открытый курсор отклоняет следующие
операции с данными. Отдельное открытие использует свой курсор.
См. [живую загрузку Dis](../../flashVM/doc/STYX_RPC_LIVE_DIS.ru.md).

Парный встречный сервер Styx также откладывает обычные чтения байтов
таких файлов. Нативный поток удерживает активный курсор, пока диспетчер
обслуживает другие fid. `Tflush` снимает ожидающий билет Limbo,
а `Node.reply` отклоняет поздний ответ на этот билет. Отдельно открытый
fid может продолжать читать публикацию. Сервер ограничивает количество
отложенных чтений и сериализует доступ к каждому занятому курсору.
См. [реализацию диспетчера](../native/terminal/caller_read.c)
и [отмену в задачах FlashVM](../../flashVM/doc/ASINC_VFS.ru.md).

Данные и позиции передаются обычными сообщениями Styx в существующей
сессии libstyxrpc. Колбэк работает в VM владельца. Для данных, которые
обрабатываются по мере поступления, подходит
[последовательная публикация](STYX-NODES.ru.md).

## Проверка в паре

Добавьте `--positioned` к [команде парной проверки](STYX-CHANNEL.ru.md#проверка).
[Модуль Limbo](../../lib/styxrpc/tests/flashvm/positioned_pair.b) публикует
файл и запускает [SWF на AS](../../lib/styxrpc/tests/flashvm/positioned_pair.as).
SWF публикует второй файл с
[колбэком AS](../../lib/styxrpc/tests/flashvm/positioned_transfer.as) и
записывает данные в конец первого.
[Обработчик Limbo](../../lib/styxrpc/tests/flashvm/positioned_handler.b)
проверяет смещения выше 4 ГиБ, возвращает сохранённые двоичные байты
и обслуживает исполнение. Затем модуль Limbo выполняет те же операции
с файлом FlashVM через `Sys`. Проверка печатает
`PASS native positioned RPC paired VMs`. Для TCP и JIT добавьте `--tcp` и `--jit`.
