# Pointer-constructor C tail entry — runtime0.77

Hosted SysV x64 pointer-cons now has a generated native entry again. The entry
keeps REG in rdi, loads the shared C target into volatile rax and JMPs to it.
The C constructor still performs every checked Heap/Type acquisition, root,
allocation, marking, publication and rollback operation. No ordinary machine
Heap/Type add/load/store sequence has been restored.

The original C caller's stack and return address remain intact. Unlike CALL,
JMP leaves no return PC inside the module-owned JIT mapping. The shared target
can therefore return or raise through ordinary C VM exception frames after that
mapping is freed. Neither target nor C dispatch reads Jit/module cache storage
after callbacks that may retire it. This follows the existing complete-dispatch
tail bridge pattern without adding a field to LeafLayout or changing any opcode.

The target accepts only the exact current TLS REG address. Foreign REG declines
before reading operands. Normal C dispatch has already decoded the instruction
and advanced PC; caller's complete VM roots and serialized managed admission
remain prerequisites. Return1 means committed construction. An acquisition or
allocation error rolls back and propagates as a VM error, never as a false return
that could retry an opcode after partial work. No asynchronous cancellation or
arbitrary native-thread managed access is added.

| Backend | Hosted pointer-cons path | Evidence here |
| --- | --- | --- |
| SysV x64 | Generated JMP to checked C constructor | Actual code execution and ABI controls |
| ARM64 | Existing C fallback | No new target execution claim |
| RV64 | Existing C path, no new lowering | No new target execution claim |

Source adaptation pins the reviewed old x64 emitter body and rejects drift or
double adaptation. The common unchecked-layout decline remains for other targets.
Code cache sizing and validation use the new generated bytes/address in the same
process; no native address is serialized into Dis64. Owning upstream snapshots
and standalone raw-emitter fixtures stay untouched.

`test_jit_counts.py` verifies64 successful checked Tptr acquisitions and64 actual
shared-target calls in JIT, zero target calls in C, correct payloads and both poll
modes. Restoring the original private x64 emitter/validator must detect bypassed
owners. A native-entry success statistic describes accepted JIT dispatch, not
inline arithmetic or a benchmark result.

`test_pointer_tail.py` executes three complete guest/shutdown positives: unmap
current JIT before the constructor; inject a monitor error and verify unchanged
REG/PC/operands/owners before a clean test-only retry; combine unmap and error.
It also checks foreign REG refusal. A separate private compiler replaces JMP
with an ABI-aligned CALL. The shared target must detect a module-owned return
address at semantic status10 BEFORE unmapping, rather than treating a crash or
timeout as a successful control. Production objects remain unchanged.

Use --positive-only for joined TSan runs; bad-CALL/old-emitter controls are
excluded there. C code is instrumented, generated machine bytes are not. These
are focused x64 ABI/lifetime proofs, not certification of every callback, backend,
allocator or collector. General managed admission remains serialized.
