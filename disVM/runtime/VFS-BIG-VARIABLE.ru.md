# Vfsexport.bigvar

[English](VFS-BIG-VARIABLE.md) · [Интерфейс Limbo](../module/vfsexport.m#L44) · [Реализация](vfs/cap_live_value.c#L274) · [Парный пример](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md)

## Синтаксис

```limbo
include "vfsexport.m";
bigvar: fn(initial: big): ref Root;
```

Загрузите `Vfsexport` из `Vfsexport->PATH` в нативной DisVM. Передайте любое знаковое значение Limbo `big` в `initial`. Возвращает собственный `Root`, удерживающий значение, или `nil` при невозможности выделить хранилище или файловую проекцию. Ячейка охватывает весь знаковый 64-битный диапазон.

## Файлы и время жизни

| Файл | Контракт |
| --- | --- |
| `.type` | `big
`, только чтение. |
| `.val` | Одна полная скалярная запись `big` с тегом 2. Используйте [формат целого SDK](../../lib/styxrpc/reference/value_integer.ru.md). |

Первый запрос чтения ненулевой длины фиксирует значение для открытого fid. Для следующего снимка откройте новый fid. Ячейка принимает полную запись знакового значения со смещения ноль. Неверный тег, запись другого вида, неполный кадр или неверное смещение отклоняются. Чтение видит прежнее или новое значение целиком. После монтирования провайдер и открытые fid удерживают нативное хранилище. Для публикации вместе с другими полями используйте [составление записи](VFS-VARIABLE-RECORD.ru.md).

## Пример

```limbo
# Храним точное начальное значение для удалённого клиента.
caps := load Vfsexport Vfsexport->PATH;
magnitude := caps->bigvar(big "-9223372036854775808");
```

Проверьте `magnitude` перед монтированием или добавлением поля. Клиент C получает `int64_t` через [API живого чтения](../../lib/styxrpc/reference/live_read_until.ru.md). FlashVM получает этот минимум как десятичный текст через [`binding.get()`](../../flashVM/doc/STYX_RPC_LIVE_GET.ru.md). Целые в точном диапазоне декодируются как Number.
