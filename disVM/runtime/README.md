# Experimental runnable Dis and IDE services (NC64)

Use `python3 build_menu.py`, select `all` or `disvm-runtime`, and accept the
defaults. After building, choose **4** for the Dis channel example or **5** for
IDE workspace services. Installed commands also work independently:

```sh
bash out/disvm-runtime/run-console.sh
bash out/disvm-runtime/run-ide.sh
```

This is an actual native executable loading and executing compiled Limbo modules:
production Dis decoding, instructions, AMD64 guarded native leaves, stacks,
module linking, reference counting and cycle collector are retained. `up` and its
named `R` subobject use the existing OS TLS context. Blocking Dis channels and
spawned Limbo processes run above one native owner using a FIFO scheduler. This
initial executable does not yet run multiple VM owners concurrently.

The IDE example executes production idecore/ideworkspace modules and the callable
workspace tutorial: it creates document owners, takes a revision-bound build
snapshot and stops all services through channels. It does not fabricate compiler
output. The graphical editor is not connected to this executable yet. The FlashVM
windowed examples remain separately launchable from the same build menu.

## Explicit experimental ABI

Classic bootstrap output uses four-byte cells; native host pointers and legacy
WORD are eight bytes on this AMD64 build. Silently mixing them corrupts frames,
pointer maps, alt tables and Sys arguments. This runner therefore uses a separate
**NC64** experimental cell target with magic **819264** (classic **819248**).
Native cells, int slots and pointer-map slots are eight bytes. Sys frames and
maps are generated by the matching compiler. This is not the proposed standard
Dis ABI64 with 32-bit int, nor a claim of complete classic Limbo integer-overflow
semantics. Classic modules are rejected, not reinterpreted. Existing compiler,
SDK and IDE packages keep their classic format unchanged.

`limbo-native` is installed beside `disvm` solely for this target. Example:

```sh
./limbo-native -g -I include/limbo -o console-check.dis examples/console-check/main.b
./disvm console-check.dis
```

The project's own Coco/R-to-FIR compiler remains the intended compiler path.
This selected upstream bootstrap enables runnable integration now. Debug symbols
are shipped beside native modules; a runtime debugger connection is still pending.

## Host boundary

Acceptance is native Linux AMD64. Normal Sys support includes production string
formatting/tokenization/UTF helpers, stdout printing and read-only module/file
opening plus read/readn through FlashVM's file port. Unavailable Sys functions throw explicit
errors. One stdout message is bounded to a 4096-byte formatting buffer.
No successful empty Sys service, external emu, Inferno Draw or full
Inferno filesystem is substituted. General writes, network namespaces, Styx,
process control and Dis exception-handler propagation remain to be connected.

The standalone executable owns one bounded 64 MiB arena. Stable block headers
allow the retained Inferno RC and cycle collector to traverse it; first-fit
allocation currently splits blocks without coalescing, so fragmentation can hit
the limit. The allocator is private to this experimental host and can be replaced.
Cycle collection runs between scheduler slices on the owner, not concurrently;
existing collector-worker/safepoint APIs remain the future shared-owner path.
The runner bounds simultaneous processes and total scheduler slices, diagnoses
blocked-process deadlock, and relies on OS process teardown for its final native
resources. It is not yet a reusable independently destructible embedding object.

`--jit` and `--no-jit` select guarded leaves or interpretation. `--test-control`
explicitly enables an isolated `/dev/sysctl` halt node for unchanged IDE regression
clients. It is disabled during normal examples. Test automation checks exit
status and PASS/FAIL text because those existing tests intentionally halt on both
successful and failed assertions.

Local source-view adaptations are kept in `prepare.py`; imported files retain
manifest hashes. The byte-array descriptor fix is also supplied as an upstream
patch: legal byte arrays have module-local descriptors, so pointer identity with
`Tbyte` cannot be required. Alt headers are adapted only for NC64, with checked
narrowing to internal native counters.


The normal and native-cell bootstrap builds reserve a real sentinel slot in the
old generated yacc parser stack. This avoids forming `&yys[-1]`, which UBSan
identified during Sys-interface compilation. The adaptation runs after either
the pinned parser or a fresh iyacc generation; no grammar action is changed.
