# Vfsexport.recordpipe

[English](RECORD-PIPE.md)

Канал записей связывает процесс Limbo с участником, которому выдали
поддерево по Styx. Оба файла виртуальные. Файловые операции передают
целые S-записи и читают подтверждения. Приложение может отправить
разобранное значение в локальный канал Limbo до подтверждения доставки.

## Интерфейс

```limbo
include "vfsexport.m";
export := load Vfsexport Vfsexport->PATH;
pipe := export->recordpipe();
```

`recordpipe()` не принимает аргументов. Возвращает собственный
`ref Vfsexport->Root` или `nil` при ошибке выделения. Локально откройте
конец из полномочия через `Vfsexport->open`. Участник, смонтировавший
дерево, открывает его через `Sys->open`. Оба конца требуют `Sys->ORDWR`.
Чтобы выдать только один конец, скройте второй через `Vfsexport->overlay`
перед публикацией дерева. Каталогу нужны права поиска.

| Открытый файл | Запись | Чтение |
| --- | --- | --- |
| `send` | Одна целая S-запись размером 1–1024 байта вместе с заголовком | Один байт подтверждения после ответа получателя |
| `recv` | Один байт подтверждения на том же fid, который прочитал запись | Целая ожидающая S-запись |

Отправитель записывает сообщение и удерживает fid до чтения
подтверждения. Один канал обслуживает одну операцию одновременно.
Запись в занятый канал завершается отказом. Ошибка формата не занимает
канал. Буфер чтения должен вмещать целую S-запись. Короткий буфер
получает отказ без потребления байтов. Пока на конце ничего не готово,
чтение возвращает ноль. Файловые операции не ждут другую сторону.

Получатель пишет байт `1` при доставке или `0` при отказе. Если он прочитал
запись и закрыл fid до подтверждения, отправитель получает байт `2`.
Исход неизвестен. Запись повторно не выдаётся. Закрытие fid отправителя
снимает его операцию. Если получатель успел прочитать запись, подтвердить
эту операцию уже нельзя. Канал освобождается после чтения подтверждения
отправителем либо закрытия его fid.

Провайдер проверяет обрамление и контрольную сумму S-записи.
Тип и содержимое проверяет код, который разбирает значение. Файловой
конец подключается к обработчику Limbo явно. Интерфейс работает локально
и через встречный Styx с контекстом вызова в сборке со Styx SDK.

## Пример

Стенд с тремя DisVM выдаёт по одному концу на каждое направление
в клиентском `.vfs`. Локальный обработчик принимает сообщение в
`chan of int` через `alt`, подтверждает доставку и отправляет типизированный
ответ через второй канал записей. Проверки охватывают повреждённую
запись, неверный режим открытия, скрытый конец и подтверждение с чужого fid.
