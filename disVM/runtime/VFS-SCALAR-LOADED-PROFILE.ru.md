# Vfsnative.scalarloadedprofile

[English](VFS-SCALAR-LOADED-PROFILE.md) · [Имена каталога](VFS-SCALAR-LOADED-EXPORTS.ru.md) ·
[Объявление Limbo](../module/vfsnative.m) · [Реализация](vfs/loaded_catalogue.inc)

```limbo
scalarloadedprofile: fn(anchor: Scalarloadedanchor): array of byte;
```

Загрузите встроенный модуль `Vfsnative` в работающем процессе DisVM и
получите `anchor` через `scalarloadanchor(path)`. Например:

```limbo
anchor := routes->scalarloadanchor("library.dis");
profile := routes->scalarloadedprofile(anchor);
```

При успехе метод возвращает новый массив байтов с одной частной записью
S-record на каждый вызываемый экспорт. Порядок компиляции совпадает с
`scalarloadedexports(anchor)`. В записи содержатся имя и скомпилированная
сигнатура, а также схемы аргументов и результата, когда они есть. Используются
те же проверки шлюза, что и в `scalarloadedslot`. При nil в `anchor`, пустом
каталоге, числе вызываемых экспортов больше восьми или ошибке кодирования
метод возвращает nil. Неполный профиль не выдаётся.

Метод читает загруженный экземпляр без файлового ввода-вывода и вызовов
методов гостя. Массив принадлежит вызывающему, его изменение не влияет на
последующие вызовы. Сохраните anchor для связывания представлений того же
экземпляра после замены файла по старому пути.

Владелец Styx может использовать записи при подготовке публикации. Частные
предложения описывают скомпилированные методы. Область сессии, маршруты
вызовов и открытый `.interface` формируются при публикации.

Нативная [проверка публикации](../native/terminal/publish_profile.h)
проверяет всю последовательность и подготавливает открытый профиль. Она
отклоняет повреждённые записи, повторы и служебные имена. Если у сессии есть
встречный корень, вызовы со схемой получают соответствующие теги области.
