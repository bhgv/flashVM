# Смешанные каналы UniBus в Limbo

[English](STYX-CHANNEL.md) · [Интерфейс](../module/styxchannel.m) · [Реализация на Limbo](../limbo/styxchannel.b) · [Сервер FlashVM](../../flashVM/doc/STYX_RPC_DEFAULT.ru.md)

Именованный блокирующий канал открывается через [Styxnamed](../../lib/styxrpc/reference/named_channel.ru.md).


Загрузите модуль `Styxchannel` из `styxchannel.dis` и вызовите `init()`
до работы с ним. Инициализация подключает Unibus смонтированной сессии,
побитовые преобразования Math и адаптер ссылок Int32. Сборка штатной
DisVM включает библиотеку Limbo. Для нативных операций нужна двунаправленная
сессия `--styx-mount-fd`, `--styx-mount-tcp` или `--styx-local-pair`.
Обмен работает через ту же сессию, что и встречный маунт.

| Метод | Контракт |
| --- | --- |
| `newchan(address, root)` | Открывает именованный обмен от корня сессии. Укажите один непустой компонент до 255 байт UTF-8, допускается начальная косая черта. При получении ссылок абсолютный `root` должен быть точкой монтирования их владельца. Возвращает собственный `ref Port`, при отказе выдаёт исключение. |
| `port.send(message)` | Отправляет `ref Message`. Возвращает 1 после подтверждения записи Styx либо 0, если передача ещё не началась из-за занятости очереди. Неверное сообщение и ошибка транспорта дают исключение. При ошибке записи результат на другой стороне может быть неизвестен. |
| `port.recv()` | Возвращает старейшее полное сообщение `ref Message` либо nil после опроса пустой очереди. Ошибки чтения дают исключение. Фрагментированное сообщение может потребовать нескольких опросов. |
| `port.close()` | Закрывает порт и удаляет непрочитанные записи. Повтор допустим. У исходного процесса до восьми открытых портов, при завершении запуска они закрываются. |

Работайте в исходном процессе смонтированного запуска. Хост копирует
данные сообщений и выполняет Styx I/O вне допуска к управляемой куче.
Вызовы могут ждать до истечения срока запроса Styx.

`Message` — типизированный ADT с pick-вариантами. `Integer`, `Floating`,
`Boolean`, `Text` и `Null` передают снимки. У варианта `Variable` есть
поле `cell` типа `ref Styxintref->Cell`, открытое в маунте владельца.
Для доступа используйте `cell.read()` и `cell.write(value)`. Пересылайте
ссылку только в исходной сессии и держите точку монтирования связанной с
ней. Файл ссылки удерживается отдельно от порта. Провайдер должен заранее
выдать живую ссылку Int32. SWF, обслуживающий `.rpc` на стороне FlashVM,
в этой версии обменивается снимками.

## Проверка

[Клиент Limbo](../../lib/styxrpc/tests/flashvm/mixed_pair.b) загружает и
запускает [сценарий AS](../../lib/styxrpc/tests/flashvm/mixed_pair.as)
через службу плеера. Затем проверяет эхо пяти видов сообщений на одном
порту, скрытие корня в обычной VFS, отказ при повторном открытии занятого
порта и открытие после закрытия.

В корне репозитория укажите в `build` каталог полной парной сборки.
Скрипт компилирует оба приложения штатными Limbo, AS2 View, FIR и SWL
и запускает обычные DisVM и FlashVM. Для приложений достаточно Limbo
и ActionScript.

```sh
python3 lib/styxrpc/tests/flashvm/mixed_pair.py --source disVM \
  --runtime "$build/disvm-editor/disvm" \
  --player "$build/paired-flashvm/flashvm_styx_player" \
  --limbo "$build/disvm-editor/bootstrap/limbo-bootstrap" \
  --as2 "$build/as2/view/as2_viewc" --fir "$build/fir/fir1" \
  --fir-opt "$build/fir/fir1_opt" --swl "$build/linker/swl"
```

Ожидаемый результат `PASS native mixed RPC paired VMs`. Ключ `--tcp`
использует штатное TCP-соединение, `--jit` включает JIT на обеих VM.
Тесты SDK `styxrpc-mixed-ref-disvm-interpreter` и
`styxrpc-mixed-ref-disvm-jit` запускают
[приёмник типизированной ссылки](../../lib/styxrpc/tests/flashvm/mixed_ref.b)
и проверяют изменение значения у владельца.

[Типизированные значения и живые ячейки именованного канала](STYX-NAMED-VALUES.ru.md) работают в том же парном пространстве имён.
