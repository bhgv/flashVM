# Vfsexport.stringvar

[English](VFS-STRING-VARIABLE.md) · [Интерфейс Limbo](../module/vfsexport.m#L41) · [Реализация](vfs/cap_live_value.c#L255) · [Парный пример](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md)

## Синтаксис

```limbo
include "vfsexport.m";
stringvar: fn(initial: string): ref Root;
```

Загрузите `Vfsexport` из `Vfsexport->PATH` в нативной DisVM. Передайте исходную строку или `nil`. Начальное значение копируется в нативное хранилище. Возвращает собственный `Root` живой строковой ячейки. При нехватке памяти, повреждённой кодировке или размере более 1024 байт UTF-8 возвращает `nil`. Пустая строка и nil имеют разные представления. Строка с длиной может содержать нулевой символ.

## Файлы и время жизни

| Файл | Контракт |
| --- | --- |
| `.type` | `string
`, только чтение. |
| `.val` | Полная строковая запись UniBus с тегом 7 и длиной UTF-8 либо nil с тегом 9 и пустой нагрузкой. Откройте новый fid для нового снимка. Пишите полный кадр со смещения ноль. |

При первом запросе чтения ненулевой длины открытый fid фиксирует снимок. Части с того же fid относятся к этому снимку. Полная проверенная запись заменяет значение под блокировкой ячейки. Неполная или неверная запись и запись со смещения, отличного от нуля, отклоняются. Удерживайте возможность в корнях при составлении или монтировании. Опубликованный провайдер и открытые fid удерживают хранилище во время использования. Отказ доступа к пути не влияет на создание ячейки.

## Пример

```limbo
# Составляем запись с этим полем перед публикацией в VFS.
caps := load Vfsexport Vfsexport->PATH;
label := caps->stringvar("sun");
r := caps->record(("label", label) :: nil);
```

Перед монтированием `r` проверьте результаты конструкторов. Откройте `label` через [живую привязку FlashVM](../../flashVM/doc/STYX_RPC_LIVE_GET.ru.md) или [SDK для C](../../lib/styxrpc/reference/live_read_until.ru.md). Для чтения в Limbo откройте `.val` через `Vfsexport.open` и декодируйте запись с длиной.
