# Публикация исполняемых узлов VFS из Limbo

[English](STYX-EXEC-PUBLISH.md) · [Вызов из Limbo](STYX-EXEC.ru.md) · [Вызов из FlashVM](../../flashVM/doc/STYX_VFS_EXEC.ru.md)

Двунаправленный запуск DisVM позволяет опубликовать обработчик Limbo по
пути в живом пространстве имён. Загрузите и инициализируйте
`styxexec.dis`, затем вызовите [`publish`](styx-exec-publish.ru.md)
со свободным путём под существующим доступным для записи каталогом.
Узел объявляет право исполнения. В потоке владельца
[`dispatch`](styx-exec-dispatch.ru.md) вызывает обработчик модуля
[`StyxexecHandler.invoke`](styx-exec-invoke.ru.md). Один экземпляр модуля
может обслуживать несколько путей.

Клиент посылает запрос по протоколу исполнения libstyxrpc через уже
подключённую сессию. Диспетчер собирает фрагменты запроса и передаёт
копию входа потоку владельца. У каждого запроса свой билет ответа.
Для своей очереди обработки используйте [`recv`](styx-exec-recv.ru.md),
[`reply`](styx-exec-reply.ru.md) и [`refuse`](styx-exec-refuse.ru.md).
Диспетчер ждёт ответ до пяти секунд после получения полного запроса.
У клиента может быть меньший срок ожидания. Работа с кучей Limbo
остаётся в потоке владельца.

Служебный `/.execctl` доступен локальному владельцу. Клиент использует
скрытый `/.exec` в корне подключения. В обычном списке VFS виден
опубликованный прикладной путь. При каждом вызове проверяется текущий
выбранный слой. Если другой bind перекрывает узел, обработчик снова
станет доступен, когда его слой вернётся в видимую часть VFS.
[`close`](styx-exec-close.ru.md) удаляет точную привязку владельца,
сохраняя замену по тому же пути. Сериализуйте операции на одном Node.
Для параллельной работы с приложением выделите отдельный поток Limbo.

## Запуск парной проверки

1. Добавьте `--publish` к [команде парного прогона](STYX-CHANNEL.md#acceptance).
   Ключи `--jit` и `--tcp` выбирают соответствующие режимы.
2. [Приложение Limbo](../../lib/styxrpc/tests/flashvm/publish_pair.b)
   публикует два узла и загружает [фильм AS](../../lib/styxrpc/tests/flashvm/publish_pair.as).
   Фильм делает вызовы от рабочего каталога и по абсолютному пути.
3. [Собранный обработчик](../../lib/styxrpc/tests/flashvm/publish_handler.b)
   преобразует короткий запрос и запрос на 16 КиБ. Получив оба ответа,
   фильм вызывает второй узел. Приложение Limbo закрывает публикации
   и печатает `PASS native publish RPC paired VMs`.

Драйвер собирает приложение и обработчик из Limbo, фильм из AS.
Проверка использует штатный двунаправленный Linux-профиль DisVM.
