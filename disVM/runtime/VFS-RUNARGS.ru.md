# Vfsctl.runargs

[English](VFS-RUNARGS.md) · [Обзор](VFS-LAUNCH.ru.md) · [Руководство](../examples/vfs-run/TUTORIAL.ru.md) · [Реализация](vfs/vfsnative.c)

## Синтаксис

```limbo
include "vfsctl.m";
# Загрузите Vfsctl и вызовите init() перед runargs.
runargs: fn(path: string, arguments: array of byte): int;
```

Доступно в hosted DisVM с модулем [Vfsctl](../module/vfsctl.m) и `$Vfsnative`.
Параметр `path` обязателен и подчиняется тем же правилам абсолютных,
относительных и забинженных путей, что и [`run`](VFS-RUN.ru.md). Предел —
4095 байт UTF-8. `arguments` содержит от 0 до 65 536 байт. `nil` и пустой
массив отправляют пустые данные. Нулевые байты сохраняются. Callback владельца
и транспорт могут задать меньший предел. Публикация команды по умолчанию принимает пустые данные.
[Владелец может разрешить передачу](../native/terminal/LAUNCH-PROCESS-PAYLOAD.ru.md)
в `Launchcontext.arguments()` команды.

## Результат и эффекты

| Результат | Значение |
| --- | --- |
| `1` | Владелец подтвердил успешное выполнение либо маршрут без результата подтвердил доставку. |
| `0` | Неверные данные, недоступный маршрут или определённый отказ. |
| `-1` | Доставка или результат выполнения неизвестны. |
| `-2` | Владелец подтвердил ошибку выполнения. |

Runtime копирует массив до ожидания I/O, а вызывающий сохраняет владение им.
Callback владельца заимствует принятые байты на время вызова. Для дальнейшего
использования владелец должен их скопировать. Отмена действует на ожидание
транспорта и не вызывает повтора. Смысл принятых данных задаёт callback.

Маршрут Styx с контекстом открывает `.unibus` для чтения и записи и
держит тот же fid до результата. Отдельно открывать `.exit` не нужно.

## Пример

```limbo
data := array[] of {byte 'x', byte 0, byte 'y'};
delivery := vfs->runargs("/payload.dis", data);
```

[обработчик владельца](../native/terminal/LAUNCH-RECEIVE.ru.md).
