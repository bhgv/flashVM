# Карантин функции после подтверждённой ошибки JIT

Единица переключения — **вся функция**, а не одна инструкция и не вся VM.
После публикации карантина её следующие JIT dispatch идут в обычный интерпретатор.
Остальные функции и модули сохраняют JIT. Уже допущенная инструкция может
закончиться; её не прерывают и не повторяют. Глобального эксклюзива нет.

Hosted leaf backend сохраняет исходные Dis-инструкции и PC. Границы функций
определяются по entry модуля, exports и исправленным local CALL/SPAWN targets.
Установленные symbol files, disassembler или debugger libraries не нужны.
У встроенной компилятором исходной функции нет отдельного runtime-кадра: единицей
карантина становится окружающая испущенная функция. Интервал `[start,end)`
выражен в исходных Dis PC.

Монотонная generation до публикации JIT отличает выгрузку/повторную загрузку даже
при совпадении адресов. Записи карантина содержат только native scalars и
публикуются immutable-префиксом с release/acquire. Читатели не берут замок
исполнения; редкие изменения защищены mutex метаданных. Уже исполняющаяся
инструкция другого потока может завершиться; его следующий проверенный выбор
JIT увидит опубликованный карантин.

Сейчас автоматический классификатор обрабатывает явный `exCompile`, возникший
внутри выбранного native callback. Обычные Limbo nil/bounds/divide errors,
отказ fast path и штатные ненулевые return values не являются основанием
карантина. Внутренний API `dvm_jit_report_failure` позволяет сообщить независимо
подтверждённый backend defect до unwind. Это не произвольная команда клиента
и не API повторного исполнения инструкции.

Ограниченный лог `JITFAULT` содержит generation загруженного code, путь модуля,
интервал функции, точный исходный Dis PC/opcode, backend, причину,
`action=interpret-function` и `replay=0`. Сбойная операция проходит обычный
exception handler либо останавливается до него встроенным debugger. Она не
перезапускается с начала функции: предыдущие I/O/shared writes могли состояться.

Таблица содержит128 исключительных записей на lifetime VM. При заполнении
последующий JIT целиком уступает интерпретатору с `capacity_exhausted=1` в логе:
известная сбойная функция не начинает незаметно исполняться нативно снова.
Исчерпание generation также запрещает новый JIT. Записи не удерживают
Module/Jit/heap. Перезапуск сбрасывает карантин; сохранения на диск пока нет.
Отсутствующие symbol names не выдумываются.

Регрессия настоящей VM вводит безопасную явную backend exception перед реальным
нативным сложением. Проверяются пойманное исходное исключение, корректные
следующие результаты, отсутствие **любых native entries во всём интервале
сбойной функции**, продолжение настоящего JIT вне него и оба poll backend.
Инъекция существует только в test-linked probe, отсутствует в production.

Допущенные synchronous integer scalar RX faults теперь используют этот же
карантин всей функции: [контракт захвата](JIT-SIGNALS.ru.md). Это ограниченная
гарантия восстановления, не детектор произвольного повреждения native memory
и не повторное исполнение инструкции. GDB необязателен:
[встроенный отладчик](DEBUGGER.ru.md).

The missing-classification control preserves original caught-error behavior and
correct results, but requires precise DETECTED for absent quarantine. Eight real
native owners exercise the shared fallback after publication. / Контроль пропуска
классификации сохраняет пойманную ошибку и верные результаты, но требует точного
DETECTED при отсутствии карантина. Общий fallback проверяют восемь native owners.
