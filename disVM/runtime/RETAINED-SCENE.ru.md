# Сохраняемые битмапы объектов IDE

[English](RETAINED-SCENE.md) · [Владельцы рисования](../../ide/RENDER_OWNERS.ru.md) ·
[Жесты рабочего стола](../../ide/DESKTOP-WORKSPACE.ru.md)

Теперь каждому окну/виджету в протоколе рабочего стола соответствует локальный
RGBA-буфер. Содержимое, преобразование/прозрачность и композиция потомков имеют
отдельные флаги. Родитель кэширует собственный рисунок; дети остаются отдельными
слоями в порядке наложения. Это исключает повторный захват детей MDI в родитель.
Итоговый экран — корень композиции. Отдельный битмап каждому символу не выделяется.

Владелец FlashVM подготавливает копии локальных команд и модификаторов. Потоки
растеризации не получают VM, шрифтов или управляемых объектов. Неизменённые
изображения разделяются с последним действительно показанным кадром. Короткий
mutex защищает только счётчик ссылок на изображение, не работу с пикселями.

До четырёх работников рисуют только изменённые локальные буферы. Затем работники
компонуют повреждённые плитки экрана64×64. Сдвиг, зум, поворот и прозрачность не
требуют повторной растеризации содержимого. Для целого сдвига есть прямой путь
копирования, для остальных преобразований — билинейная фильтрация с учётом alpha.
Прозрачность задаётся в тысячных:900 означает ровно90 процентов.

Изменение ребёнка поднимает флаг композиции всем родителям. Старое/новое положение,
удаление и изменение порядка слоёв повреждают соответствующие области экрана.
В них снова блитятся и неизменённые пересекающиеся слои: иначе нельзя восстановить
открывшийся фон и прозрачные перекрытия. Флаги узлов сбрасываются после успешной
композиции; флаги загрузки текстуры сохраняются до передачи владельцу SDL.
Неуспешный или отменённый снимок не меняет уже показанные изображения.

При редактировании текста вычисляется локальная область изменённых полных
контуров. Работник берёт копию предыдущего битмапа, очищает только эту область и
рисует пересекающий её локальный рисунок. Целое окно заново не растеризуется.
Однако выделение/копирование целого изменённого битмапа пока возможно: плиточного
COW для пикселей ещё нет.

Для целиком находящихся в пределах canvas обычных окон исходников/Help/консоли
точный ключ содержимого позволяет пропускать и повторные MovieClip-действия на
владельце. Меняется преобразование; ссылки удерживают готовое изображение и его неизменяемые
локальные команды. Повторного копирования/сравнения контуров глифов нет. Цепочка
команд копируется только при построении нового изменённого изображения.
Миниатюры, графические и обрезанные окна, активные анимации пока проходят подготовку
команд владельцем, но их растровые изображения тоже переиспользуются, если локальный
рисунок совпадает. Геометрия приводится к сетке1/4096 пикселя против шума обратных
матриц; сравнение этой формы точное, без хеш-коллизий.

Продолжение уже захваченного мышью заголовка больше не ждёт растеризации. Новое
попадание по объекту, фокус, жизненный цикл и воспроизведение записи сохраняют барьер
соответствия геометрии пикселям. Очередь не переупорядочивается. Для остальных
жестов touch/выделения старый барьер пока сохранён. Ввод клавиатуры остаётся внекадровым.

SDL сначала пробует ускоренный renderer, затем программный. Композиция объектов пока
идёт на CPU; это не GPU-сцена. Загрузка текстуры — только повреждёнными плитками.
Полные копии экранного буфера ещё остаются. GC теперь запускается по обычному порогу
выделений в безопасной точке, а не принудительно целиком на каждом перемещении.

Лимит связанных битмапов —64MiB на снимок. При его превышении IDE повторяет подготовку
обычным векторным путём, сохраняя прозрачность. Неверное дерево таким успехом не
маскируется. ID1..63, отсутствие циклов, размеры и преобразования проверяются.
Отмена очереди, завершение и уничтожение предыдущего кадра освобождают ссылки;
после закрытия всех владельцев физических битмапов должно остаться0.

Для наблюдения за настоящей работой:

```sh
DVM_EDITOR_RENDER_STATS=1 ./run-desktop-ide.sh
```

`SCENECACHE ticket built reused dirty local_pixels` — построенные/повторно
использованные буферы, изменённые узлы и локально перерисованные пиксели.
`ROOTDAMAGE ticket tiles pixels` — область композиции/загрузки экрана.
Это счётчики работы, а не измерение FPS. При replay они выводятся автоматически;
`NODECACHE` показывает пропуск пересоздания объекта на владельце.
Для сравнения разработчика: `DVM_EDITOR_RETAINED=0` включает векторный путь.

В проверках: побайтовое сравнение полной/инкрементальной композиции, нулевая
растеризация при модификаторах, локальное обновление контуров текста, флаги предков,
освобождение изображений, отмена очереди, циклы и лимит памяти. Отдельно проверены
настоящий IDE replay и SDL FIFO. Dummy driver проверяет программный запасной путь,
но не скорость GPU на пользовательском устройстве.

Отдельные готовые текстуры поддеревьев, узлы на каждый графический примитив,
внешняя карта прозрачности, плиточный COW пикселей, повышение разрешения буфера
после сильного зума и GPU-композиция остаются следующими этапами. Билинейный зум
не добавляет векторной детализации. Владельцы документов и форматы Dis/SWF не меняются.
