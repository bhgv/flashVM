# Запустить смонтированную команду и прочитать код завершения

[English](TUTORIAL.md) · [Сборка и запуск](README.ru.md) · [Обзор](../../runtime/VFS-LAUNCH.ru.md)

1. Соберите и запустите TCP-тест [командами из README](README.ru.md). Тест
   создаёт временный каталог, компилирует модули Limbo и публикует команду
   и файл результата через Styx-сервер.
2. Откройте [`runexample.b`](runexample.b). `execute` загружает `Sys` для
   файловых операций и `Vfsctl` для отправки по маршруту. `vfs->init()`
   подключает встроенный модуль. `vfs->run(command)` разрешает имя в
   пространстве вызывающего и отправляет владельцу один пустой запрос.
3. Передайте путь команды и как `payloadroute`. В этом случае клиент вызывает
   `vfs->runargs(command, payload)` один раз. Команда читает `x\0y` в своём
   `init` через `Launchcontext.arguments()`. Отдельный маршрут получает данные
   через свой callback. При `nil` команда запускается с пустыми данными.
4. `delivered` поднимает исключение при отказе или неизвестном исходе.
   Решение о повторе остаётся за вызывающим, потому что подтверждение
   может потеряться уже после принятия запроса.
5. `exitstatus` открывает поток результата для чтения и собирает десятичные
   цифры до перевода строки. Недоступный файл, ранний EOF и неверная запись
   вызывают исключение. Локальная ссылка на FD освобождается при возврате
   или выходе из функции по исключению.

Владелец печатает `PASS owner Dis init` после чтения файла из своего рабочего
каталога. Клиент ожидает код выхода 0 и печатает
`PASS path-only Styx command submission`. CTest требует успеха в интерпретаторе
и JIT. Тест закрывает соединения, дожидается процессов и удаляет временные файлы.

Полный контракт результатов приведён в справочнике
[`run`](../../runtime/VFS-RUN.ru.md) и [`runargs`](../../runtime/VFS-RUNARGS.ru.md).
