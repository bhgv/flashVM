# Закреплённые нативные владельцы Dis

[English](README.md) · [Исходник](main.b) · [Меню](../../../ide/ENTRYPOINTS.md)

Консольный пример запускает четыре дочерних процесса Dis. У каждого свой
закреплённый нативный поток, личный scratch-массив и состояние ошибки. Дочерний
процесс передаёт копию `(lane, sum)`, родитель проверяет четыре результата.
Возврат из точки входа позволяет runtime штатно присоединить владельцев.
Контекст дисплея/FlashVM не нужен; унаследованные стандартные FD доступны.

Запуск: пункт меню **19** или:

```sh
sh out/disvm-editor/run-resident-owners.sh --jit
sh out/disvm-editor/run-resident-owners.sh --no-jit
```

Команда также поставляется в `disvm-runtime`. Аргументы передаются как отдельные
опции runtime: `--jit` выбирает JIT, `--no-jit` — интерпретатор. Launcher включает
обязательную модель закреплённых нативных владельцев и статистику. Настройки числа
исполнителей и миграции процессов нет. Удалённую опцию `--managed-workers` VM
отвергает; установщик убирает её старую команду и байткод из существующего пакета.

Ожидаемый вывод приложения:

```text
PASS resident owners: children=4 sums=ok private-state=ok channels=ok
```

Начните с [`calculate`](main.b): `lane` выбирает сумму, `replies` заимствован до
единственной отправки. Scratch личный, по каналу идут лишь два скаляра.
[`init`](main.b) удерживает канал ответов, запускает процессы и проверяет каждую
дорожку один раз. Любая неудачная проверка вызывает исключение.

[Приёмка](../../runtime/test_resident_owners.py) независимо проверяет пять нативных
владельцев (родитель и четыре дочерних), join, отсутствие миграций и активных
владельцев после завершения, пустую очередь исполнения и нужные счётчики JIT.
Это не замер масштабирования CPU и не демонстрация миграции потоков.
