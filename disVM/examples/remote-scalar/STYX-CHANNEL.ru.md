# Передача канала Limbo через Styx

[English](STYX-CHANNEL.md) · [Руководство по загрузке библиотек](STYX.ru.md)

Обычный `load` связывает экспорт библиотеки, который принимает живой
`chan of int`. Клиент открывает файл смонтированной функции как обычно.
DisVM публикует виртуальный файл `.prog/<pid>/.unibus` во встречном
контексте Styx клиента и отправляет по одному ключу на каждый отличный от
`nil` канал. Если один канал передан дважды, провайдер получает две ссылки
на один прокси. Исходная функция Dis работает со штатными инструкциями канала.

## Запуск примера

Соберите SDK и DisVM с его поддержкой по
[руководству по загрузке библиотек](STYX.ru.md#подготовка-и-проверка-публикации).
Из корня репозитория запустите сценарий с путями к собранным DisVM и Limbo.

```sh
python3 disVM/examples/remote-scalar/run_channel.py \
    --runtime build/scalar-runtime/disvm \
    --limbo build/scalar-runtime/bootstrap/limbo-bootstrap
```

Опция `--jit` запускает обе VM в режиме JIT. Сценарий компилирует клиент и
провайдер с `-D RG`, запускает два процесса DisVM в отдельных временных
каталогах и связывает их через TCP loopback. Он проверяет вывод
`PASS automatic Limbo channels over UniBus` и удаляет образы при выходе.

| Исходник | Что показывает |
| --- | --- |
| [Интерфейс](chain-channel.m) | Типизированный экспорт с обычными параметрами Limbo. |
| [Клиент](styx-channel-client.b) | Обычный `load`, обмен без буфера с локальным `alt`, буферизованная отправка и отмена с повторным успешным вызовом. |
| [Провайдер](styx-channel-owner.b) | Штатные `send`, `recv` и `alt`, в том числе выбор из двух прокси и ветка по умолчанию. |

## Операции с каналом

VM, которая ждёт ответа функции, обслуживает запросы UniBus через очереди
исходного канала. Отправка завершается, когда получатель принял значение
или когда оно помещено в буфер. Приём берёт значение из исходного буфера
либо у ожидающего отправителя. `alt` провайдера передаёт все ветки одним
запросом и выполняет одну. Для `alt` с веткой по умолчанию исходная VM
проверяет готовность один раз.

Для каждой операции шлюз открывает новый fid на чтение и запись в
существующей встречной сессии Styx. Запрос и ответ идут через этот fid.
При отмене или возврате клиент закрывает приём запросов на UniBus и отзывает
выдачу. Если соединение рвётся после выполнения операции, провайдер получает
ошибку, а VM не повторяет операцию.

Поддерживаются аргументы `chan of int`, включая позиции кортежа. Их ключи
действуют до конца вызова. В `alt` провайдера допускается до восьми прямых
прокси-веток одного вызова. Осталось добавить другие типы элементов, возврат
каналов, использование прокси из отдельного потока провайдера и выбор между
локальными и удалёнными ветками или массивами каналов.

## Записи протокола

| Тег | Запись |
| --- | --- |
| 24 | Ключ аргумента как положительное 32-битное число в сетевом порядке. Тег 9 представляет `nil`. |
| 25 | Отправка с четырёхбайтовым ключом и одной типизированной S-записью int. |
| 26 | Приём с четырёхбайтовым ключом. |
| 27 | Ответ в форме [скалярной записи UniBus](../../native/terminal/scalar_record.h). Ответ `alt` содержит порядковый номер ветки с единицы в старших 32 битах и биты значения в младших. Ноль означает ветку по умолчанию. |
| 28, 29 | Блокирующий выбор и выбор с веткой по умолчанию. Содержат упорядоченные записи отправки и приёма. |
