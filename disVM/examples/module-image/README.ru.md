# Получение модуля и передача через FlashVM

[English](README.md) · [Сборка и API хоста](../../host/README.ru.md) ·
[Полностью комментированный код](main.c)

Нативный пример читает существующий `.dis` через файловый адаптер FlashVM,
передаёт произвольные байты настоящим каналом FlashVM, получает независимую копию
и сравнивает каждый байт. NUL и байты вне WTF-8 сохраняются через явную оболочку
`dis-hex:`. Модуль не запускается: это проверка транспорта, не исполнения Dis/JIT.

Соберите общий хост с настоящей библиотекой FlashVM и её зависимостями по инструкции.
При заданном `DVM_FLASHVM_LIBRARIES` доступна цель `disvm_module_image_example`,
вместе с тестом настоящего канала. Передайте существующий скомпилированный модуль
и точный размер файла:

```sh
build/disvm-host/disvm_module_image_example build/workspace/ide/idecore.dis BYTE_COUNT
```

Замените `BYTE_COUNT` размером в байтах из файлового менеджера или метаданных
ресурса. Успех: `PASS acquired and transferred ... module bytes; no VM execution`.
Ошибка файла, усечение, квота, нехватка памяти или ошибка канала дают ненулевой код.
Размер задаёт один кадр образа, последующие байты не читаются. Это входная граница
для файла, буфера IDE или встроенного ресурса, а не готовый резолвер пространства имён.

Оба образа владеют нативной памятью; указатели куч VM не передаются. Канал здесь
буферизированный: один поток сначала отправляет, затем принимает. Для rendezvous
нужны отдельные нативные потоки отправителя и получателя и явный
`fvm_channel_set_rendezvous`. Общий cleanup освобождает оба образа и канал на любом
пути. Рабочая IDE будет Limbo/AS-байткодом, не этим нативным примером.
