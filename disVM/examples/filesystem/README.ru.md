# Реальные метаданные и обход каталогов

[English](README.md) · [Контракт](../../runtime/FILESYSTEM.ru.md) · [Код](main.b)

Исполняемый пример Limbo проверяет файловую основу для браузера IDE. Используются
настоящие Sys и исходная библиотека Readdir, без подмены файловых операций.
Нужны согласованные по ABI компилятор Limbo, DisVM, sys.m/readdir.m и readdir.dis.

`main.b` — шаблон с `FIXTURE_ROOT`. [Драйвер](../../runtime/test_filesystem.py)
создаёт собственный временный каталог, подставляет корректно экранированный путь,
компилирует пример, запускает его и удаляет только свои файлы. Прямо компилировать
шаблон без подстановки не следует.

После сборки, из корня репозитория:

```sh
ctest --test-dir build/runtime -R 'sys_filesystem|shared_filesystem' --output-on-failure
```

Для ручного запуска драйвера см. [английский README](README.md); пути компилятора,
VM, include, примера и Readdir передаются явно. В установленном runtime SDK:

```sh
python3 examples/filesystem/run.py ./limbo-native ./disvm ./include/limbo \
  ./examples/filesystem/main.b ./readdir.dis jit
```

Повторите с `interpreter`. Ожидается `PASS hosted Sys filesystem jit`; драйвер
обязательно проверяет маркер самого Limbo-примера в запусках quantum 1 и 2048.
Создаются 73 элемента, включая Unicode-имя, двоичный NUL и разреженный файл
4294967303 байта. Файловая система должна поддерживать разреженные файлы и иметь
место для метаданных.

Проверяются точность размера/идентичности, сохранение позиции после fstat,
три порции dirread, EOF, реальная сортировка Readdir и повторное использование
слотов после освобождения FD. Ошибочные пути очищают старые владельцы результата;
NUL и content:// отвергаются. Строки кода снабжены комментариями.

| API | Назначение и владение |
| --- | --- |
| stat/fstat | Копии метаданных принадлежат VM; fstat сохраняет позиции. |
| open/read/seek | FD владеет ресурсом; чтение проверяет байты, каталог не является байтовым потоком. |
| dirread | Порция VM-записей; count различает EOF и ошибку. |
| Readdir.init | Обход и сортировка через Sys; записи живут независимо от FD. |

Последняя ссылка FD закрывает нативный ресурс. Присваивание nil освобождает
массивы; временные файлы принадлежат только драйверу. Все C-функции, ошибки,
блокировки и освобождение описаны в [контракте](../../runtime/FILESYSTEM.ru.md#владение-в-переносимом-api)
и [заголовке](../../../flashVM/ports/filesystem_port.h).

Нативные проверки выполнены на Linux; Windows/macOS/Android ещё требуют запуска
на своих платформах. Фоновое I/O, namespace, SAF и /prog здесь не реализованы.
