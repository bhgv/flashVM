# Как написать C-модуль для нашего DisVM

В .m используются скалярные алиасы Value/Text. Наш проход связывания Coco/R
разрешает их в big/string и выдаёт тот же ABI, без ручных C typedef.
[Семантика и API](../../../compiler/limbo/frontend/ALIASES.ru.md).

Это настоящий встроенный модуль хоста, загружаемый через `load Nativedemo
Nativedemo->PATH`. Реализация написана на C, клиент и канальный сервис — на Limbo.
Кадры вызовов, структурные сигнатуры, размеры и карты GC генерирует **наш
Limbo-компилятор на Coco/R**. Они не скопированы из старого заголовка. Временный
bootstrap пока компилирует исполняемый Limbo-клиент, но C-интерфейс этого модуля
генерирует уже наш инструмент.

## Ответственность файлов

`nativedemo.m` — единственный контракт. `native.c` реализует функции и регистрирует
сгенерированную таблицу. `main.b` управляет загрузкой, запросами, частными каналами
ответа, исключением и завершением процесса. Каждая непустая строка примеров
прокомментирована, включая ABI и владение. Сгенерированный заголовок находится
в build и никогда не редактируется вручную.

| Функция | Результат и владение |
| --- | --- |
| `add(big, big): big` | Копирует числа; беззнаковая арифметика C сохраняет точное переполнение по модулю 2^64. |
| `greeting(): string` | Создаёт обычную строку Dis через `retstr`; результат удерживает вызывающий. |
| `check(int)` | Для ненулевого значения возвращает void, для нуля поднимает `native demo: rejected`. |

Адреса C, файловые дескрипторы и объекты дисплея не становятся содержимым канала.
Сервис получает числа и частный канал ответа, вызывает C и отвечает из Limbo.
Остановка подтверждается до освобождения времени жизни сервиса. Это локальная
типизированная обёртка, не протокол сетевых lease или исполнения ровно один раз.

## Сборка из корня репозитория

```sh
# Собираем наш компилятор интерфейсов с явно выбранным Coco/R.
cmake -S compiler/limbo -B build/limbo-own \
  -DCOCOR_ROOT="$PWD/tools/coco-r-C/upstream" \
  -DCOCOR_EXECUTABLE="$PWD/build/cocor/cocor"
cmake --build build/limbo-own -j4
# Этот заголовок выдаёт наш парсер/каталог и backend нативного ABI.
build/limbo-own/frontend/limbo_bindings --format native-c-nc64 \
  disVM/examples/native-module/nativedemo.m build/nativedemo_native.h
# Учебный builtin включается явно, обычная сборка может его не содержать.
cmake -S disVM/runtime -B build/native-module \
  -DDVM_RUNTIME_NATIVE_DEMO=ON \
  -DDVM_LIMBO_BINDINGS="$PWD/build/limbo-own/frontend/limbo_bindings"
cmake --build build/native-module -j4
ctest --test-dir build/native-module -R native_module --output-on-failure
build/native-module/disvm --jit --stats --quantum 1 \
  --max-instructions 1000000 build/native-module/native-demo.dis
```

CMake генерирует `native/nativedemo_native.h` из `.m`, компилирует `native.c`
в хост и собирает согласованные `native-demo.dis/.sbl`. При включённой графической
цели тот же модуль попадает в `disvm-editor`. При исполнении компилятор, Python и
генерация заголовков не нужны. Если `$Nativedemo` не загружается, проверьте опцию
и пересоберите хост: копирование одного `.m` или `.dis` не регистрирует C-модуль.

Ожидаемая последняя строка:

```text
PASS native module: wrap=ok sum=42 strings=2048 caught=1 shutdown=ok
```

Проверки запускают интерпретатор/JIT с квантами 1 и 2048, контролируют настоящие
счётчики исполнения и активность GC при кванте 1. Клиент проверяет
`MAX_BIG+1 == MIN_BIG`, сумму 42 через канал, 2048 возвратов строки, перехваченную
C-ошибку, следующий успешный вызов и подтверждённую остановку. Ошибка любого
шага меняет код завершения процесса.

## Порядок чтения

1. Начните с `.m` и полученного заголовка. `F_Nativedemo_*` — сгенерированный
   ABI, не приблизительные структуры C. Возвратные ячейки и карты управляемых
   аргументов принадлежат VM.
2. В `dvm_nativedemo_initialize` таблица регистрируется после allocator/Sys,
   на потоке владельца VM. Лишь затем работает типизированный `load`.
3. В `add` используется `memmove` без предположений о выравнивании и unsigned
   без неопределённого знакового переполнения C. Возвращаются биты значения.
4. В `greeting` стандартный `retstr` создаёт и публикует строку Dis. `char *`
   из `malloc` не является `String *`; адрес стека C не является объектом GC.
5. В `check` и обработчике Limbo показана ошибка VM. `error()` нельзя вызывать
   из произвольного pthread или с незавершённой обязательной очисткой C-ресурсов.
6. В сервисе Limbo остаются конкурентность, блокировка канала и владение ответом.

## Расширение примера

Короткие вычисления выполняйте синхронно. Для колоризатора или тяжёлой отрисовки
копируйте проверенные данные в собственное хранилище задания C, выполняйте работу
независимо и возвращайте копии через владельца. Worker не должен удерживать
неукоренённые кадры VM, `String *`, `Array *` или изменяемый MovieClip. Перед
обещанием асинхронного вызова хост должен реализовать корни ожидающего вызова,
отмену и доставку завершения. Этот скалярный пример их не изображает готовыми.

Нативный генератор сейчас поддерживает прямые byte/int/big/real/string, скалярный
или void результат, один модуль, до 128 функций/16 параметров и явные classic32/NC64.
ADT, массивы, каналы, алиасы, импорты, varargs, полиморфизм и raises-сигнатуры
отвергаются. Более общие C/AS scaffold’ы внешних модулей остаются отдельным
интерфейсом, не нативным ABI кадров.
