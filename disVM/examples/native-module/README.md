# Writing a C module for our DisVM

The .m now uses Value/Text scalar aliases. Our Coco/R binding pass resolves them
to big/string and emits the same native ABI, with no handwritten C typedefs.
[Semantics and API](../../../compiler/limbo/frontend/ALIASES.md).

This example is an actual host builtin loaded through `load Nativedemo
Nativedemo->PATH`. The implementation is C; its caller and channel service are
Limbo bytecode. The frames, structural signatures, descriptor sizes and GC maps
are generated by **our Coco/R Limbo compiler**, not copied from a legacy header.
The temporary native bootstrap currently compiles the executable Limbo client;
that does not make it the generator of this module's C interface.

## What each file owns

`nativedemo.m` is the sole interface contract. `native.c` implements exports and
registers their generated table. `main.b` owns loading, requests, private reply
channels, exception recovery, process shutdown and successful-test reporting.
Every nonblank example code line has a comment, including ownership/ABI decisions.
The generated header lives in the build directory and must never be edited.

Exports are intentionally small:

| Export | Result and ownership |
| --- | --- |
| `add(big, big): big` | Copies scalars; unsigned C arithmetic provides exact modulo-2^64 wrap. |
| `greeting(): string` | Allocates an ordinary Dis-owned string using `retstr`; the caller roots the result. |
| `check(int)` | Returns void for nonzero; raises `native demo: rejected` for zero. |

No native pointers, OS file handles or display objects are channel payloads. The
service receives scalar requests and a private reply channel. It computes through
C and replies from Limbo. Stop is acknowledged before the caller releases service
lifetime. This is a local typed wrapper, not a network lease/exactly-once protocol.

## Build from the repository root

First build our own interface tools with the selected Coco/R SDK:

```sh
cmake -S compiler/limbo -B build/limbo-own \
  -DCOCOR_ROOT="$PWD/tools/coco-r-C/upstream" \
  -DCOCOR_EXECUTABLE="$PWD/build/cocor/cocor"
cmake --build build/limbo-own -j4
# This product is generated by our parser/catalog and native ABI backend alone.
build/limbo-own/frontend/limbo_bindings --format native-c-nc64 \
  disVM/examples/native-module/nativedemo.m build/nativedemo_native.h
# Enable the teaching builtin explicitly; ordinary runtimes may omit it.
cmake -S disVM/runtime -B build/native-module \
  -DDVM_RUNTIME_NATIVE_DEMO=ON \
  -DDVM_LIMBO_BINDINGS="$PWD/build/limbo-own/frontend/limbo_bindings"
cmake --build build/native-module -j4
ctest --test-dir build/native-module -R native_module --output-on-failure
build/native-module/disvm --jit --stats --quantum 1 \
  --max-instructions 1000000 build/native-module/native-demo.dis
```

CMake generates `native/nativedemo_native.h` from the `.m`, compiles `native.c`
into the host, and builds matching `native-demo.dis/.sbl`. The same optional source
is included by `disvm-editor` when the graphical target is enabled. No compiler,
Python or header generation occurs in the running example. If `$Nativedemo` cannot
be loaded, confirm that the runtime was rebuilt with the option enabled; installing
only a `.m` or `.dis` does not register a C module.

Expected final output:

```text
PASS native module: wrap=ok sum=42 strings=2048 caught=1 shutdown=ok
```

Tests run interpreter/JIT at quanta 1 and 2048. They check actual dispatch counters
and require GC activity at quantum 1. The client tests `MAX_BIG+1 == MIN_BIG`,
request/reply sum 42, 2048 string returns, caught C error, another successful call
and acknowledged stop. A failed check changes the process exit status.

## Read the code in this order

1. Read the `.m` and the generated header. `F_Nativedemo_*` is a generated ABI,
   not a guessed C struct. Return slots and managed input maps belong to the VM.
2. Read `dvm_nativedemo_initialize`: registration happens after allocator/Sys setup,
   on the bound VM owner. `builtinmod` must succeed before a later typed load.
3. Read `add`: `memmove` avoids alignment assumptions; unsigned addition avoids
   undefined signed C overflow; only the resulting bits are returned.
4. Read `greeting`: `retstr` constructs and publishes a Dis string. A `malloc`ed
   `char *` is not a Dis `String *`, and a native stack address is never a GC object.
5. Read `check` and its Limbo handler: `error()` is an owner-thread VM operation.
   It must not be called from an arbitrary pthread or while C cleanup is missing.
6. Read the service: concurrency and blocking communication remain with Limbo.

## Extending the example

Keep short scalar work synchronous. For a colorizer or expensive renderer, copy
validated input into native-owned job storage, process it independently, and return
copied results through the owner. Never let a worker retain an unrooted VM frame,
`String *`, `Array *` or mutable MovieClip. The host must implement pending-call
roots, cancellation and completion delivery before a blocking asynchronous export
is promised. Those mechanisms are not demonstrated by this scalar builtin.

The native generator currently supports direct byte/int/big/real/string arguments
and scalar/void results, one module, at most 128 exports/16 arguments, explicit
classic32 or NC64 targets. Composite ADTs, arrays, channels, aliases, imports,
varargs, polymorphism and raises-qualified signatures are rejected. The broader
C/AS external-module scaffolds remain separate interfaces, not native frame ABI.
