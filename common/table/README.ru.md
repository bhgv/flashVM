# C-ядро гибридных таблиц

[English](README.md)

Самостоятельная библиотека C99 хранит значения `big`/int64 по неотрицательным
числовым индексам и строковым ключам с явной длиной в байтах. Ключи `1` и `"1"`
различаются. Контейнер растёт динамически; нехватка памяти возвращается как ошибка.

Плотная часть — массив со знаком присутствия каждого элемента. Разреженные
числовые и строковые ключи хранятся в растущей хеш-таблице. При росте плотной части
покрытые ею числовые элементы переносятся из хеш-части без изменения семантики.
Длина последовательности — первый отсутствующий индекс от нуля. Полное число
пар запрашивается отдельно. Удаление элемента не сдвигает остальные ключи.

Снимок ключей независим от исходной таблицы: сначала числовые по возрастанию,
затем строковые в порядке добавления. Замена значения не меняет порядок,
удаление с последующим добавлением переносит ключ в конец. Срез `[first,end)`
копирует только последовательность, перенумеровывает её от нуля и не захватывает
словарную часть. Изменение среза не меняет исходные слоты.

Аллокатор можно подменить. При ошибке выделения логическое содержимое исходной
таблицы не меняется, частичный результат наружу не выдаётся. Блокировки и вызовы
пользовательского кода отсутствуют: операции сериализует владелец VM. В C-ядре
нет ссылок на кучи Dis/FlashVM. Пока реализованы только скалярные `big`, а не
объектные ключи или произвольные значения с обходом GC.

Самостоятельная сборка:

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Проверки сравнивают 12 000 операций с независимой моделью, проверяют границы big,
дырки, строковые ключи с нулевыми байтами, независимые снимки/срезы и отказы
аллокатора с подсчётом всех незакрытых выделений. Код под MIT из корня репозитория;
он не скопирован из Lua и не меняет Inferno или формат Dis.

## Точные скалярные адаптеры

`fht_big_parse(text, size, result)` принимает полное десятичное целое с явной
длиной байтов и необязательным +/-. Неверный текст, нулевой байт или переполнение
signed-64 дают FHT_INVALID без изменения результата. `fht_big_format(value, text,
capacity)` требует не менее 21 байта, возвращает длину без NUL и ничего не меняет
при неверном буфере. Обе функции заимствуют аргументы, не выделяют память и не
используют числа с плавающей точкой. C-тест сравнивает 20 005 форматирований со
snprintf и проверяет крайние значения/ошибки разбора. [Контракт приведений Limbo](../../fir/v1/doc/TYPE_REFLECTION.ru.md).
