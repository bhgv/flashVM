# Транзакционная замена плотного диапазона

[English](SPLICE.md) · [Владелец с блокировкой](../owned/README.ru.md)

C API `fht_splice(destination, first, end, replacement)` заменяет диапазон всей
плотной частью replacement. Отрицательный конец включается: `[0:-1]` означает
всю плотную часть. Положительный конец исключается. Подключение синтаксиса
присваивания срезу в Limbo/FIR ещё требуется; поведение штатного Dis array store
этим изменением не переопределяется.

Пример: `[1, 2, 3, 4]`, замена `[1:3]` на `[9]`, результат `[1, 9, 4]`.
Вставка результата в самого себя на `[1:1]` даёт `[1, 1, 9, 4, 9, 4]`.
Чтение старого содержимого завершается до публикации нового; самоприсваивание
безопасно. Пустой replacement удаляет диапазон. В пустую таблицу можно вставить
на `[0:0]`, либо заменить всю пустую часть через `[0:-1]`.

Текстовые ключи и их порядок сохраняются. Разреженные числовые ключи остаются
по абсолютным позициям. Рост с пересечением такого ключа возвращает FHT_INVALID
без изменений. Некорректные границы и переполнение тоже отклоняются; нехватка
памяти возвращает FHT_NOMEM с сохранением исходных данных. Текстовые и разреженные
ключи replacement не включаются во вставляемую последовательность.

Сначала строится полная новая таблица, затем обменивается внутреннее хранилище.
Временная память пропорциональна числу ключей назначения и длине вставки.
Идентичность внешнего Fht сохраняется. Это реализация с откатом; оптимизация
перемещением на месте пока не выполнена.

Plain Fht требует внешней сериализации всех обращений, включая чтение. Блокировки
скрыто не добавляются. Для host-транзакций есть адаптер common/owned; два владельца
захватываются в стабильном порядке, для самоприсваивания достаточно одного.
Контекст allocator должен оставаться живым, заимствованные указатели нельзя
сохранять за пределами защищённой операции.
