# Защищённые операции с таблицами

[English](REQUESTS.md) · [Контракт владельца](README.ru.md) ·
[Интеграция с VM](../../disVM/PAYLOAD_GUARDS.ru.md)

`table_request.h` используется нативным Bigtable DisVM и доступен доверенным
host-адаптерам. Это локальный C API, не wire-формат RPC. Заимствованные указатели
не должны пересекать границы куч, процессов или сети. Время жизни владельцев
гарантируется снаружи; native cancellation отключается до исполнения и остаётся
отключённым до принятия или освобождения результата.

`fvm_owned_token` выдаёт ненулевые process-local токены операции под коротким mutex
метаданных. Переполнение возвращает EOVERFLOW, повторного использования нет.
Удалённая сторона не выбирает доверенный токен. Вложенный последовательный вызов
использует тот же токен; два одновременно исполняемых native-потока — разные.

`fvm_table_request` отдельно возвращает ошибку native-блокировки и Fht-статус.
GET, SET, DELETE, LENGTH, COUNT, RESOLVE, RANGE, SLICE, KEYS целиком выполняются
под объектной блокировкой. RANGE нормализует границы, не отпуская её. SLICE/KEYS
при успехе передают независимо владеющий снимок. SPLICE захватывает источник
и назначение на всё чтение, выделение, замену хвоста и публикацию. C allocator
должен возвращать управление обычным образом, без исключения VM и longjmp.

Пара захватывается в едином порядке native-адресов; одинаковые владельцы
объединяются в один повторный вход. Ошибка освобождает только новые уровни входа.
Захваченный старший владелец без младшего при попытке захвата пары приводит к
EDEADLK. Уже удерживаемые посторонние блокировки тоже должны соблюдать глобальный
порядок. Это не механизм произвольного повышения shared/write-блокировок.
Выход предварительно проверяет обоих владельцев: чужой токен не освобождает
половину пары.

Тесты выполняют 8000 встречных копирований четырьмя pthread, проверяют рекурсию,
чужой токен, нарушение порядка, откат self-copy при нехватке памяти и уничтожение
освобождённых владельцев. Другие проверки читают диагностику при четырёх ожидающих
потоках и выполняют 40000 вложенных изменений таблицы. Баланс allocator проверяет
владеющие блоки независимо от LSan.

Native VM проверяет приватный GC-handle, отключает cancellation, получает свой
токен и вызывает этот слой. Исключение VM возникает после освобождения блокировок.
Неизменяемые снимки ключей после создания не требуют блокировки исходной таблицы.
Mutex может ждать на native-потоке: нельзя держать его через yield единственного
владельца VM, если ожидаемое продолжение само требует того же потока. Удержание
на всё исходное выражение, подтверждение сетевой отмены и интеграция удалённых
проекций с планировщиком остаются отдельными задачами.
