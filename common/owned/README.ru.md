# Блокировка с владельцем операции

[English](README.md) · [Контракт интеграции](../../disVM/OWNED_OPERATIONS.ru.md)

Реализован отдельный C99/POSIX механизм: исключительная блокировка с повторным
входом по ненулевому токену операции. Конкуренты спят на условной переменной.
Короткий mutex метаданных не удерживается во время работы с данными.
**Подключения к массивам, строкам и таблицам DisVM пока нет.** Для Windows
нужна отдельная реализация примитивов ожидания.

Блокировка принадлежит владельцу памяти. Представления одного массива обязаны
разделять одну блокировку. Инициализированную структуру нельзя копировать.
Runtime отвечает за выдачу токенов, корни GC, время жизни и порядок захвата
нескольких объектов. Удалённая сторона не должна выбирать доверенный токен.
Один токен обозначает одно последовательное исполнение: одновременно выполнять
его из двух native-потоков запрещено. Вложенный последовательный вход разрешён.

Перед входом надо отключить pthread cancellation и оставить отключённым до
последнего выхода; иначе enter возвращает EINVAL. После освобождения восстанавливают
старое состояние cancellation. Каждый успешный вход требует отдельного выхода,
включая ошибки и исключения. Пример с комментариями приведён в English README.
Таймаут сети не доказывает завершение операции: отмена должна быть кооперативной.
Нельзя снимать блокировку по обрыву канала, пока исполнитель продолжает работу.

Читатели тоже должны захватывать блокировку. Проверять длину, нормализовать
индексы и снимать копию исходного диапазона следует после захвата. Для работы с
самим собой вложенные вызовы используют тот же токен, не открывая данные другим.

inspect читает только owner/depth/waiters под коротким mutex метаданных.
Диагностика остаётся доступной при остановленном владельце; она не разрешает
запуск второго исполнения с его токеном. destroy требует внешней гарантии:
прекратить публикацию объекта, дождаться всех пользователей, затем уничтожать.
Проверка EBUSY сама по себе не решает задачу времени жизни.

Порядок пробуждения не гарантирован. Нельзя блокировать единственный поток VM,
если ожидаемая операция сама требует исполнения на нём: при интеграции нужен
переход к ожиданию через планировщик.

Тест запускает четыре native-потока, проверяет ожидание, рекурсию, диагностику,
отказ чужому токену и 40 000 защищённых изменений. Команды сборки приведены в
English README; CTest ограничивает зависание двадцатью секундами.

## Владелец таблицы и замена среза

`FvmTableOwner` связывает настоящую Fht-таблицу и блокировку общим временем жизни.
`fvm_table_owner_apply` защищает весь callback: чтение, проверку длины и запись.
Вложенный callback повторно входит с тем же токеном. Код ошибки приложения
возвращается отдельно от ошибки mutex. Callback не должен выбрасывать исключение
VM или делать longjmp через освобождение блокировки. Этот API пока не подключён
к нативному Bigtable-модулю DisVM или памяти массивов и строк.

`fht_splice(table, first, end, replacement)` заменяет диапазон плотной части всей
плотной частью replacement. Есть вставка, сжатие, удаление и безопасная вставка
таблицы в себя. Для части replacement предварительно создают срез. Текстовые
ключи сохраняют порядок, разреженные числовые ключи — абсолютные позиции.
Если рост пересекает существующий разреженный ключ, операция возвращает
FHT_INVALID без изменения таблицы. Ошибки выделения памяти также откатываются.
Для двух владельцев обе блокировки нужно захватывать в едином стабильном порядке.
Для операции над самой собой достаточно собственной блокировки.

Дополнительный тест выполняет 40 000 read-modify-write транзакций над таблицей
четырьмя native-потоками с вложенными callback. Тесты ядра внедряют ошибки
выделения памяти при вставке в себя, проверяя содержимое и отсутствие утечек.

## Запускаемый пример

`example_splice.c` подробно комментирует создание владельца, защищённую
инициализацию, вставку таблицы в себя и очистку на ошибках. После сборки
запустите `build/owned/owned_splice_example`: `[1, 9, 4]` превращается в
`[1, 1, 9, 4, 9, 4]`, каждый элемент проверяется. Пример включён в CTest.
Он показывает C host API; это ещё не синтаксис Limbo. Native cancellation
восстанавливается только после освобождения таблицы.
