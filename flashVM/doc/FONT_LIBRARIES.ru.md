# Статические шрифтовые библиотеки и редактируемые контуры

В DEFS.txt по умолчанию включён FONTS; NO_FONTS отключает шрифтовые библиотеки
и их программы. Все включённые библиотеки external объявлены целями STATIC,
включая AGG/Cairo, кодеки, zlib и SQLite. Даже BUILD_SHARED_LIBS=ON не превращает
их в динамические: CMake проверяет тип каждой цели. Системная библиотека языка,
потоки и платформенные SDK не являются встроенными зависимостями external.
Сборка не скачивает библиотеки и не подменяет их системными установками.

| Библиотека | Версия | Профиль |
| --- | --- | --- |
| FreeType | 2.14.3 | C89, переносимый stdio/malloc, встроенный zlib |
| HarfBuzz | 1.8.8 с патчем C++98 | OpenType, fallback, UCDN, адаптер FreeType |
| libunibreak | 6.1 с патчем C89 | границы строк, слов и графем |
| FriBidi | 1.0.16 с патчем C89 | bidi Unicode 16.0, готовые таблицы релиза |

HarfBuzz 10.4.0 требует C++11 в upstream meson.build, а для некоторых
компиляторов — C++14. Поэтому выбран 1.8.8. Этот выбор обеспечивает проверяемую
совместимость языка, но не заявляет актуальные данные Unicode или полный аудит
upstream. Алгоритмы и таблицы HarfBuzz сохраняют поведение исторической версии.
libunibreak 6.1 заявляет Unicode 15.0 для строк и 15.1 для слов/графем, с неполной
поддержкой правил строк 15.1. Таблицы этих библиотек не образуют единую новейшую
реализацию Unicode.

Нативное приложение подключает цель flashvm и получает пути заголовков и
статические зависимости: ft2build.h, hb.h/hb-ot.h/hb-ft.h, linebreak.h,
wordbreak.h, graphemebreak.h и fribidi.h. При GRAPHICS_AGG+FONTS включён адаптер
FreeType для AGG; при сборке Cairo с FONTS включён его FreeType backend.
Fontconfig и автоматический поиск системных шрифтов отключены: приложение
передаёт байты шрифта или собственный FT_Face. PNG, bzip2 и Brotli FreeType
отключены. HarfBuzz вызывает FreeType, обратной зависимости нет, поэтому
цикла статической линковки не возникает.

## C89 API FlashVM

flashvm/font.h владеет копией байтов шрифта, face и размером без hinting.
Вход ограничен 32 МиБ, размер — (0,4096] пикселей. Один изменяемый шрифтовый
объект нельзя использовать одновременно из нескольких потоков. Для каждого
потока создавайте отдельный объект. HarfBuzz использует pthread mutex на POSIX
и нативные блокировки на Windows. Обёртке нужна Unicode charmap; она извлекает
контуры, а не рисует встроенные bitmap/SVG/цветные глифы. Специальные операции
можно выполнять через исходный API библиотек.

| Операция | API |
| --- | --- |
| Метрики и Unicode → глиф | [fvm_font_metrics](../include/flashvm/font.h#L58) / [fvm_font_char](../include/flashvm/font.h#L66); отсутствующий символ даёт glyph 0 |
| Независимый контур глифа | [fvm_font_glyph](../include/flashvm/font.h#L70): прямые, квадратичные/кубические Безье, закрытые контуры |
| OpenType shaping | [fvm_font_shape](../include/flashvm/font.h#L76): глифы, продвижения, смещения, кластеры UTF-8 |
| Контуры размещённого текста | [fvm_text_run_path](../include/flashvm/font.h#L98): объединение расположенных глифов |
| Допустимые переносы | [fvm_text_breaks](../include/flashvm/font.h#L104): классификации libunibreak на каждый входной байт |
| Bidi одной строки | [fvm_text_bidi](../include/flashvm/font.h#L119): направление, логические уровни, карта визуальных индексов |

Координаты — пиксели, x вправо/y вниз. Масштабированные контуры FreeType имеют
точность 26.6; double в экспортированных точках не создаёт дополнительную
точность. Ascent/descent/line-height берутся из метрик размера FreeType с их
округлением. FreeType ограничивает запросы размера снизу одним пикселем;
для меньшей геометрии применяйте матрицу к экспортированным векторам.
Продвижение текста и геометрические границы видимых контуров —
разные величины.

[fvm_font_shape](../include/flashvm/font.h#L76) принимает однородный по письменности/направлению фрагмент
корректного UTF-8, максимум 4 МиБ. AUTO определяет свойства фрагмента, но не
выполняет раскладку многоязычного абзаца. Bidi принимает UTF-32, максимум
1 000 000 скалярных Unicode-значений; визуальный массив только переставляется,
без зеркальной замены символов и арабских presentation forms. HarfBuzz должен
получать логические фрагменты, затем приложение размещает их визуально;
нельзя просто передать переставленные символы на shaping. Уровни сохраняются
в логическом порядке абзаца. Для отдельных строк после переноса и зеркальных
замен используйте исходный API FriBidi. Результат shaping хранит скопированные
позиции после закрытия шрифта; для экспорта его контуров нужен тот же шрифт,
face и размер. Частичное перекрытие входных/выходных массивов не поддерживается.

libunibreak определяет места возможных переносов. Выбор строк по доступной
ширине, резервные шрифты, выравнивание, межстрочные интервалы, выключка и
группировка блоков остаются политикой приложения. Лигатура или комбинируемый
знак не обязаны соответствовать одной букве: при редактировании сохраняйте
связь с кластерами. Завершённость TextField/ActionScript и всей SWF-раскладки
этим этапом не заявляется.

## Собственная векторная модель

flashvm/path.h хранит команды MOVE, LINE, QUADRATIC, CUBIC, CLOSE в контейнере
FlashVM без STL. Контур живёт независимо от шрифта. Число точек команд —
1/1/2/3/0; квадратичная кривая хранит контрольную/конечную точки, кубическая —
две контрольные/конечную. Инициализировать нужно только эти координаты.
Путь начинается с MOVE, CLOSE требует открытого контура; после CLOSE начните
новый MOVE.

Матрица задаёт перенос, масштабирование, вращение, отражение и наклон.
Преобразование и добавление контуров транзакционны: при недопустимом результате
исходный объект сохраняется. Для индивидуальных букв/слов храните отдельные
контуры, для строки/блока объединяйте копии. Изменение узлов и контрольных
точек позволяет искажать фигуры; отдельного API нелинейной деформации пока нет.
[fvm_path_bounds](../include/flashvm/path.h#L71) вычисляет экстремумы Безье в double, а не прямоугольник
контрольных точек; учитывает MOVE и не включает толщину обводки. Пределы:
±1 000 000 для координат и 1 000 000 команд.

[fvm_path_draw](../include/flashvm/path.h#L81) рисует через выбранный AGG/Cairo: заливку nonzero/even-odd или
обводку положительной ширины с круглыми соединениями и окончаниями. Для Cairo
квадратичная кривая точно переводится в кубические контрольные точки; AGG
сохраняет квадратичный тип. Размеры поверхности и координаты рисования
ограничены 4096, как в raster.h. Растеризация аппроксимирует кривые; округление
при малой прозрачности может различаться. NO_GRAPHICS сохраняет шрифты и
геометрию, но рисование возвращает UNSUPPORTED.

[fvm_path_mask](../include/flashvm/path.h#L86) использует заполненный контур как сглаженную маску покрытия
RGBA8-изображения такого же размера и накладывает его source-over на результат.
Для маски векторной сцены сначала отрисуйте сцену в исходное изображение.
Совпадающие отображения пикселей источника/результата допустимы; другие
перекрывающиеся буферы не поддерживаются. Заполнение строк сохраняется.
Эти API не являются декодером SWF-фигур.

## Пример, лицензии и проверки

examples/embedding/font_libraries показывает shaping → контуры → наклон →
правку точки → заливку/обводку/маску. Встроенный геометрический тестовый TTF
(CC0) содержит отверстие, квадратичную кривую, составной глиф, лигатуру fi,
кернинг AV GPOS и отображения/формы иврита и арабского. Системные шрифты и
fontTools для сборки не нужны. fontTools нужен только разработчику для
повторного создания данных scripts/generate_test_font.py.

Сохранены исходные лицензии. FreeType: FTL или GPL; HarfBuzz: Old MIT,
UCDN ISC; libunibreak: zlib/libpng и условия Unicode; FriBidi: LGPL-2.1-or-later.
Portions of this software are copyright © 2026 The FreeType Project
(https://freetype.org). All rights reserved.
В HarfBuzz исправлен вызов memset с нулевым указателем для пустого буфера;
прямой тест hb_buffer_get_glyph_positions подтверждает этот случай.
PROVENANCE.json содержит источники и SHA-256 архивов, flashvm.patch — все
локальные правки. Строгие C89/C++98 сохранены; внутренние реализации требуют
поддерживаемых нативных типов/возможностей компилятора. См.
[отчёт проверок](FONT_LIBRARIES_CHECKPOINT.ru.md).

Компоновка строк и абзацев с собственными контурами: [TEXT_LAYOUT.ru.md](TEXT_LAYOUT.ru.md).

## Проверка входа bidi и срок жизни результатов (v0.827)

[`fvm_text_bidi`](../include/flashvm/font.h#L119) принимает заимствованный UTF-32 абзац до 1 000 000 Unicode-скаляров
и направление AUTO/LTR/RTL. Представление enum из C проверяется до чтения
значения C++ enum. Суррогаты, неверные скаляры, отсутствующие обязательные массивы
и превышение длины дают INVALID_ARGUMENT до изменения результатов.
NO_FONTS проверяет тот же вход, затем возвращает UNSUPPORTED.

Направление, визуальный текст, индексы visual-to-logical и логические уровни
публикуются только при успехе. Для пустого входа разрешены нулевые массивы;
с поддержкой шрифтов AUTO становится LTR. Вход и визуальный массив могут
совпадать; остальные выходные массивы должны быть раздельными. Память не
удерживается; независимые буферы не требуют VM, корней GC или общего шрифта.
Границы проверяет `text_bidi_admission.c`. Полная приёмка Unicode/SWF остаётся открытой.

v0.828: `text_bidi_allocation.cpp` перебирает отказы C++-выделений, проверяет неизменность входа на месте и всех результатов при OOM, затем повторяет вызов с явным эталоном RTL-порядка, индексов и логических уровней. Отказы памяти проверяются в обычной сборке.

v0.829: `text_bidi_os_ports.cpp` запускает четыре настоящих OS-потока по 256 абзацев с независимыми буферами и явными эталонами LTR/RTL-индексов и логических уровней. Общие изменяемые шрифты и VM не нужны. Это нативная проверка конкурентности, а не приёмка устройств и платформ.
