# Именованные размеры MovieClip

[English](MOVIECLIP_NAMED_PROPERTIES.md) · [Изображения](IMAGE_LOADING.ru.md) ·
[Источники](PLAYER_SOURCES.ru.md) · [Состояние этапов](ROADMAP_STATUS.md).

С v0.704 свойства `_width` и `_height` экземпляра MovieClip читают и меняют ту же
нативную геометрию, что числовые свойства AVM1 8 и 9. Учитываются загруженные
картинки, рисунки и дочерние клипы. Перенос и масштаб родителей не меняют размер
в координатах родителя; собственные масштаб и поворот клипа учитываются.
Значение не кешируется в обычном поле, поэтому загрузка, рисование и выгрузка
сразу отражаются в следующем чтении.

```actionscript
// Эскиз: выполняется после завершения загрузки дочерней картинки.
trace(picture._width); // Габарит нарисованного содержимого в координатах родителя.
picture._width = 160; // Меняет нативные масштабы по существующему правилу AVM1.
picture._height = 90; // Чтение и рендер используют одну геометрию.
```

Преобразование аргумента использует текущий профиль AVM1. Объект может вызвать
пользовательские `valueOf`/`toString`; ошибка возвращается до публикации масштаба.
Отсутствующий аргумент, null и undefined игнорируются. NaN не меняет размер.
Отрицательные и предельные размеры, поворот и вырожденная геометрия обрабатываются
существующей числовой реализацией; новый алгоритм геометрии не добавлен.
Пустой клип возвращает ноль. Прототип класса возвращает undefined и игнорирует
запись. Аксессоры прототипа неперечисляемые и неудаляемые; пользовательские
дескрипторы могут их затенять. Числовые инструкции обходят именованное затенение.

C-приложение использует [`fvm_object_get`](../include/flashvm/value.h#L72) / [`fvm_object_set`](../include/flashvm/value.h#L74) без консоли и плеера.
Действуют обычные проверки контекста, ошибки и правила заимствования результата.
Контекст и экземпляр должны оставаться живы; для хранения указателя через
последующий собирающий вызов используйте [`fvm_gc_pin`](../include/flashvm/gc.h#L48). Вызов аксессора удерживает
операнды во время преобразования. Нативные снимки геометрии защищены от сборки
при обращении к преобразованиям потомков; явная повторная сборка ограничена
обычными правилами нативного вызова.

Четыре функции имеют отдельные стабильные идентификаторы сериализации без
указателей userdata. После сериализации или передачи через канал функции
восстанавливаются в принимающем контексте; изменение копии не меняет оригинал.
Идентификаторы прежних методов и публичный ABI дескрипторов сохранены.

## Проверки

`tests/movieclip_named_dimensions.cpp` проверяет профили SWF5–8 в режимах
интерпретатора/JIT: согласованность числового и именованного доступа, настоящие
GetMember/SetMember, масштаб родителя, поворот, пустой клип, null/undefined/NaN,
ошибки преобразования, GC, прототип и независимые сериализованные графы.
Тесты качества и загрузки изображений служат регрессионным контролем. Отдельный
перебор отказов C++ new/new[] проверяет сохранение обоих масштабов и размеров
после каждой неудачной установки размера. Это
ограниченные сценарии, а не полная приёмка совместимости с оригинальным Flash
Player или реальных устройств.

```sh
cmake -S flashVM -B build-named
cmake --build build-named --target flashvm_tests_movieclip_named_dimensions
ctest --test-dir build-named -R '^flashvm_tests_movieclip_named_dimensions$' --output-on-failure
```

SDL, сеть и кодеки для этого теста не требуются. Связанные примеры изображений
содержат команды сборки необязательного плеера для своей и других платформ.

## Адрес содержимого с v0.705

Свойство `_url` только для чтения использует ближайший сохранённый нативный
источник, как ActionGetProperty с индексом 15. Плеер сохраняет абсолютный путь
локального файла или конечный сетевой URL после перенаправлений. Для запуска
из памяти используется явно заданный хостом источник. Нативный клип без
источника возвращает пустую строку; прототип класса — undefined. Чтение не
создаёт сетевой запрос; `_lockroot` не становится границей поиска источника.

[`fvm_movieclip_set_source`](../include/flashvm/movieclip.h#L103) копирует строку. Геттер возвращает заимствованное
управляемое хранилище по обычным правилам object API. Выгрузка сохраняет адрес,
отсоединённые потомки удерживают прежний адрес, успешная замена содержимого
атомарно публикует новый. Ошибка замены сохраняет прежний источник. Сериализация
сохраняет адреса и восстанавливает геттер в принимающем контексте.

Именованная запись и ActionSetProperty с индексом 15 игнорируются без
преобразования аргумента. Они не меняют внутреннюю базу загрузчика. Явное
затенение обычным пользовательским полем влияет только на именованный доступ;
числовая инструкция читает нативный источник. Чужой или повреждённый граф
возвращает прежнюю ошибку проверки источника. Полная историческая совместимость
написания/экранирования `_url` и всех поставщиков ресурсов пока не заявлена.

`tests/movieclip_location.cpp` проверяет SWF5–8, интерпретатор/JIT, GetMember,
запрет преобразования при записи, наследование и отсоединение источника,
выгрузку/ошибку перезагрузки, независимые сериализованные контексты и GC.
