# Составные результаты с арендой и локальный конец ActionScript

[English](STYX_RPC_RESULT_CHANNELS.md) · [Каналы](STYX_RPC_CHANNELS.ru.md) · [Запускаемый пример AS2, Limbo и C](../../lib/styxrpc/examples/disvm/CHANNEL_RESULTS.ru.md)


Провайдер может вернуть типизированный кортеж или массив с живыми каналами. Тот же ответ может вернуть ref аргумента и применить его изменения. Ключи результата используют один токен сервера. В Limbo работают обычные `load`, приём, отправка и `alt` на полученных каналах.

## Возврат графа и группы каналов

Опубликуйте метод `"channel"` с сигнатурой компилятора и полной схемой результата. Для `fn(box: ref Box): (ref Box, chan of int, chan of int)`, где `Box` содержит одно поле int, аргументы имеют схему `(r[i])`, а результат `((r[i]c[i]c[i]))`.

```actionscript
function compose(box) {
    box[0] = box[0] + 5;
    var queue = [1, [71]];           // Один слот со значением Int32.
    return [box, queue, queue];      // Один описатель сохраняет идентичность канала.
}
```

Здесь обычный синтаксис AS2. Запускаемый пример создаёт те же массивы через `split` и `push` для фронтенда View.

Позиция канала в составном результате принимает описатель `[ёмкость, элементы]` или `null`. Ёмкость от 0 до 8, начальные элементы хранятся в плотном Array. При нулевой ёмкости нужен пустой Array. Повтор того же описателя и типа даёт тот же ключ. Несовпадение типов отклоняется. Под одним токеном можно выдать до восьми разных очередей, включая каналы в начальных сообщениях. Результат и разреженная обратная запись сверяются вместе до выдачи ответа. Если все позиции каналов nil, обычные значения и изменения передаются без токена. [Публикация объекта](STYX_RPC_PUBLISH_OBJECT.ru.md) · [Контракт провайдера C](../../lib/styxrpc/reference/channel_module_init.ru.md).

## Локальный конец канала результата

Для метода с единственным результатом `c[T]` создайте конец владельца через [`vfs.resultChannel`](STYX_RPC_RESULT_CHANNEL.ru.md). Верните этот объект из метода и сохраните его в коде AS2.

```actionscript
function buffered(seed) {
    ownerPort = vfs.resultChannel("s", 1);
    ownerPort.trySend(seed);         // До публикации можно заполнить исходящий буфер.
    return ownerPort;                // Право на публикацию переходит результату.
}
```

Партнёр принимает исходящее значение, а его отправка попадает в отдельную входящую очередь. Код AS2 опрашивает `tryReceive()` и `trySend()` между вызовами или кадрами. При нуле слотов методы сразу сопоставляют уже ожидающую встречную операцию. Когда отправка вернула false, сохраните исходное значение, если собираетесь повторить попытку. Инициализатор с одним результатом также может вернуть начальное значение с ёмкостью из описателя метода.

Конец возвращается один раз в позиции единственного канала с точным типом элемента. Составные результаты используют собственные описатели очередей. Для сообщений со встречными каналами PID используйте [API очереди PID](STYX_RPC_PID_MAILBOX_EXPORT.ru.md). Локальный конец поддерживает копируемые числа, строки, плотные массивы, кортежи и списки, допустимые в скомпилированном типе.

После clunk fid результата `active()` возвращает false. Объект AS хранит отдельную нативную ссылку. `close()` освобождает её и непереданный ресурс. Опубликованный маршрут принадлежит удалённой аренде. [Время жизни и методы](STYX_RPC_RESULT_CHANNEL.ru.md) · [Нативный пример](../../lib/styxrpc/examples/disvm/CHANNEL_RESULTS.ru.md).
