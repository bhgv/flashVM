# Штатный парный плеер Styx

[English](STYX_RPC_PLAYER.md) · [Протокол плеера](STYX_RPC_MODULES.ru.md) · [Файлы и модули](STYX_RPC.ru.md)

Программа `flashvm_styx_player` запускает владельца FlashVM с монотонным тактовым циклом. Она принимает уже подключённый двусторонний поток на дескрипторе от 3 или открывает указанный TCP-адрес. Команда ActionScript `trace` пишет в stdout плеера. Для сборки установите хостовые SDK Styx и libstyxrpc.

```sh
cmake -S flashVM -B build/flash -DFVM_ENABLE_STYXRPC=ON -DCMAKE_PREFIX_PATH=/path/to/sdk
cmake --build build/flash --target flashvm_styx_player
```

## Запуск владельцев

Создайте связанную пару сокетов в запускающей программе и передайте по одному концу каждой команде. Числа обозначают унаследованные дескрипторы в соответствующих процессах. После запуска закройте копии дескрипторов в запускающей программе.

```sh
flashvm_styx_player --fd 3 --no-jit
disvm --styx-mount-fd 4 --at /flash -- \
    --native-spawn --no-jit controller.dis
```

Программа `controller.dis` управляет FlashVM через `/flash/.upload` и `/flash/.state`. Обычные пути FlashVM разрешаются в VFS работающей программы Dis от её корня. Каждый новый поиск учитывает текущие привязки и их порядок. Начальный корень определяется рабочим каталогом запуска DisVM. Доступ, включая запись, зависит от фактических прав выбранного провайдера.

Программа управления записывает в `/flash/.upload` длину стартового SWF четырьмя байтами big-endian и сам SWF. Затем достаточно один раз записать `start` в `/flash/.state`. Плеер берёт частоту из заголовка SWF. При нулевой частоте используется 12 кадров в секунду. Плеер ждёт следующего кадра или запроса Styx. `pause` останавливает кадры и оставляет файлы управления доступными. `restart` запускает сохранённый стартовый SWF заново. В этой программе `debug` приостанавливает фильм и выбирает интерпретатор. Встраиваемый API также поддерживает подключаемый отладчик. Для каждой VM можно выбрать `--jit`, если он доступен в этой сборке.

По умолчанию плеер запускается без окна. Для окна соберите его с растером
и штатным SDL2-фронтендом. Например, из корня репозитория:

```sh
cmake -S flashVM -B build/flash-window \
  -DFVM_ENABLE_STYXRPC=ON -DFVM_BUILD_DESKTOP_FRONTEND=ON \
  -DFVM_DEFS_FILE="$PWD/flashVM/cmake/profiles/player-jit.defs" \
  -DCMAKE_PREFIX_PATH=/path/to/sdk
cmake --build build/flash-window --target flashvm_styx_player
```

Передайте `--window` при запуске. Окно открывается после загрузки SWF и
подаёт события клавиатуры и мыши в его обычные обработчики. Отрисовка
работает и в паузе, поэтому вызов метода объекта из DisVM может изменить
кадр без продвижения шкалы времени. Закрытие окна завершает соединение.
С `--capture frame.ppm` сборка с растером записывает последний кадр при
штатном завершении. Снимок можно записать и в режиме без окна.

Фильм, передающий ввод другому владельцу, может включить
[очередь оконного ввода](STYX_RPC_HOST_INPUT.ru.md) вызовом `hostInput.enable()`.

Профиль `text-jit.defs` добавляет штатную отрисовку TextField. При загрузке
фильма плеер открывает `fonts/NotoSansMono-Regular.ttf` через ту же сессию VFS
DisVM. При отсутствии файла текстовая библиотека недоступна. Если файл есть,
он должен содержать корректный TTF размером до 4 МиБ. Своя копия шрифта
принадлежит каждому фильму.

## Сессия в ActionScript

В загруженном SWF доступны `styxrpc` и `styxChannel`. Объект `styxrpc`
использует уже подключённую сессию DisVM. Например,
`styxrpc.read("project.txt", 0, 32)` возвращает пару из статуса и массива
байтов. `styxChannel("(i)", 1)` создаёт локальную типизированную очередь.
Каждый новый фильм получает собственный объект сессии. При замене фильма
плеер закрывает его старые дескрипторы запуска.

## Запуск через TCP

Запустите слушатель на машине с FlashVM. `HOST` — адрес местного интерфейса,
`PORT` — десятичный порт. Loopback подходит, если оба процесса работают на
одной машине. Для связки по сети укажите доступный второй стороне интерфейс.

```sh
flashvm_styx_player --listen 127.0.0.1 7474 --jit --window
disvm --styx-mount-tcp 127.0.0.1 7474 --at /rpc -- --native-spawn --jit desktop-paired.dis
```

`--listen HOST PORT` принимает одно соединение и закрывает слушающий сокет.
При порте `0` номер выбирает ОС. Фактический номер появляется первой строкой
в виде `styx listening PORT`. `--connect HOST PORT` подключается к слушателю.
После разрешения имени на подключение даётся до пяти секунд. `--fd FD`
принимает уже подключённый поток. Во всех случаях используется одна и та же
сессия StyxRPC. Прямой TCP передаёт данные открытым текстом и рассчитан на
доверенную сеть или отдельно защищённое соединение.

Расположение модулей и ресурсов описано в [руководстве IDE](../../ide/DESKTOP-PAIRED.ru.md).
Публикация удалённых программ и библиотек описана в [справке DisVM](../../disVM/runtime/TERMINAL-LAUNCH-CLI.ru.md#подключение-по-tcp).

## Соединение двух FlashVM

Выберите встречные роли, чтобы каждый клиент монтировал дерево сервера
второй FlashVM. И слушатель, и подключающийся могут выбрать любую роль.

```sh
flashvm_styx_player --listen 127.0.0.1 7474 --peer forward --movie view-a.swf --jit
flashvm_styx_player --connect 127.0.0.1 7474 --peer reverse --movie view-b.swf --jit
```

Роль `forward` обслуживает канал 0 и монтирует канал 1. Роль `reverse`
обслуживает канал 1 и монтирует канал 0. Пока идёт встречное монтирование,
каждая сторона отвечает на запросы версии и attach. В режиме `--peer`
параметр `--movie FILE` загружает локальный стартовый SWF и запускает его
на первом такте после подключения. Без `--movie` плеер ждёт загрузки через
встречное соединение. Закрытие потока завершает сессию. Чтобы выдать плеерам
готовые потоки извне, используйте `--fd FD` на каждом конце.

Каждый фильм может [опубликовать объект](#публикация-объекта-фильма) и вызвать
Int32-метод второго фильма через [`styxrpc.callInt`](STYX_RPC_SESSION_CALL_INT.ru.md).
Фильмы работают в отдельных кучах. На сессии видны управление встречным
плеером и опубликованный им образ. Загрузка шрифта из VFS Dis применяется
при запуске в паре с DisVM.

## Терминал Unibus

[Обмен приложения через штатный объект vfs](STYX_RPC_DEFAULT.ru.md) доступен [типизированным клиентам Limbo](../../disVM/runtime/STYX-CHANNEL.ru.md).

При двунаправленном запуске Limbo-программа подключает свои
`chan of array of byte` через `$Unibus.attach(input, output)` и завершает
обмен через `detach()`. SWF получает глобальный объект `styxTerminal` с
`bidir == true`. `trySendFrame(frame)` принимает одну посчитанную строку
fvd1 и возвращает true, когда кадр поставлен в очередь. false означает,
что кадр ещё можно отправить позднее. `tryReceiveFrame()` возвращает
следующую строку либо undefined. Например, эти методы можно вызывать в
`onEnterFrame`. Для каждого направления в пути есть место для одного
кадра. Разрешение на следующий кадр выдаётся после приёма предыдущего.

Объявите у корня метод `onTerminalFrame()` и вызовите
`styxTerminal.enableNotifications()`. Плеер вызывает метод без аргументов
между обработками Styx, когда входящий кадр уже скопирован и фильм запущен.
Заберите кадр через `tryReceiveFrame()`, чтобы вернуть разрешение на следующий.
Ожидающий кадр может вызвать повторное уведомление. Метод исполняется в
потоке владельца FlashVM вместе с обработчиками фильма.

[Контракт терминала IDE](../../ide/TERMINAL-BIDIR.md) описывает, как
передать этот объект существующему адаптеру ActionScript.

## Системные файловые дескрипторы

Фильмы с подключённой VFS используют [файловые методы vfs и os](STYX_RPC_OS.ru.md).

## Публикация и использование модулей фильма

Один фильм может выдать несколько типизированных колбэков и живых свойств
Int32 через образ модуля Dis. См. [publishObject](STYX_RPC_PUBLISH_OBJECT.ru.md).
Используйте [loadModule](STYX_RPC_LOAD_MODULE.ru.md) и
[intVariable](STYX_RPC_INT_VARIABLE.ru.md) на подключённой сессии. Для
пользовательского обмена UniBus есть [openMessages](STYX_RPC_OPEN_MESSAGES.ru.md).

Хост передаёт `fvm_styxrpc_playback_slot(playback)` как контекст
`styxrpc_module_slot_tree`.

## Нативная проверка

При настройке тестов SDK укажите исходники и сборку DisVM, а также `-DSTYXRPC_FLASHVM_PLAYER=/path/to/flashvm_styx_player`. Тесты запускают штатные двоичные файлы, проверяют тактовый цикл, паузу, вложенные SWF, поздние привязки VFS, вызовы методов объекта фильма и отзыв старых fid.

```sh
ctest --test-dir build/styxrpc -R 'styxrpc-native-player' --output-on-failure
```

Для оконной сборки задайте `STYXRPC_FLASHVM_WINDOW_PLAYER`. Проверки
`styxrpc-native-window-*` используют SDL dummy driver и сравнивают пиксели
до и после перемещения фигуры вызовом из DisVM.

Проверки `styxrpc-native-terminal-*` запускают `.dis` и `.swf` на
штатной паре. Кадр клавиши идёт в канал Limbo, ответ с Unicode
возвращается в SWF и меняет итоговый растр в оконном прогоне.

Проверка двух плееров собирает SWF вызывающего и провайдера компилятором AS2,
FIR и линкером SWL из проекта. Она проверяет обе роли в JIT и интерпретаторе,
ожидает ответ и завершение второй стороны при разрыве. `--tcp` выбирает прямое
соединение TCP loopback. По умолчанию используется локальная пара сокетов.

```sh
python3 ide/tests/check_flash_peers.py --tcp \
  --player build/flash/flashvm_styx_player --as2 build/as2/view/as2_viewc \
  --fir build/fir --swl build/linker/swl
```

Вызовы исполняемых узлов описаны в [vfs.exec](STYX_VFS_EXEC.ru.md).

[Проверка парной IDE](../../ide/DESKTOP-PAIRED.ru.md) тоже принимает `--tcp`.
