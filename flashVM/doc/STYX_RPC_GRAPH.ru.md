# Позиционные графы ссылок через Styx RPC

[English](STYX_RPC_GRAPH.md) · [Мост](STYX_RPC.ru.md) · [Обычные ref](STYX_RPC_REFS.ru.md)

Привязка графов нужна для вложенных и возвращаемых ref Limbo. Модуль публикует компилированные схемы в `.interface` и штатный маркер Dis `v00009\n` в `.ref-fields`. Клиент проверяет обе записи по одному удерживаемому каталогу модуля до отправки вызова. Для каждого вызова открывается новый fid функции. Через него идут позиционный запрос (тег 112) и разреженный список изменений (тег 19). FlashVM и независимые программы на C используют один кодек и транспорт libstyxrpc.

| Значение Limbo | Представление ActionScript |
| --- | --- |
| `ref ADT` | Плотный нативный Array в порядке полей объявления или `null` для nil. |
| `array of ref ADT` | Массив из Array для ADT и элементов nil. |
| Поля-кортежи | Array в порядке элементов кортежа. При обновлении кортеж на изменённом пути заменяется. |
| Скаляры и массивы значений | [Отображение управляемых значений](STYX_RPC_IMPORT_MANAGED.ru.md). |

У аргументов, результата и изменений общая таблица идентификаторов в пределах вызова. Повторная ссылка указывает на тот же локальный Array. Новый ref может одновременно появиться в результате и изменённом поле. Неизменившееся поле сохраняет значение, в том числе идентичность массива. Клиент проверяет и подготавливает весь ответ до записи в доступные нативные слоты. При удалённом исключении или локальном отказе участвующие поля вызывающего сохраняются. Локальный отказ возможен после исполнения удалённой функции.

Изменённое поле типа `big` преобразуется по [правилам для знаковых 64-битных целых](STYX_RPC_VALUE_TYPES.ru.md#передача-знакового-64-битного-целого). Исходный Array ссылки получает Number или десятичный String по тем же правилам, что и обычный результат.

## Вызов Dis из FlashVM

1. Скомпилируйте модуль Limbo и возьмите имя экспорта, подпись и полные схемы аргументов и результата.
2. Смонтируйте пространство имён Dis через libstyxrpc и заполните [управляемую цель](../../lib/styxrpc/include/styxrpc/managed_client.h). Для экспорта с контекстом вызова задайте PID, делегированный хостом.
3. Зарегистрируйте [`fvm_styxrpc_import_graph`](STYX_RPC_IMPORT_GRAPH.ru.md) на владельце FlashVM и вызовите глобальную функцию из ActionScript. Для обычного профиля используйте [управляемую привязку](STYX_RPC_IMPORT_MANAGED.ru.md).

## Вызов FlashVM из Dis

1. Определите функцию AS на владельце сервера и создайте [дескриптор графового экспорта](STYX_RPC_EXPORT_GRAPH.ru.md) по соответствующему интерфейсу Limbo.
2. Опубликуйте дескриптор через [`styxrpc_graph_module_init`](../../lib/styxrpc/reference/graph_module_init.ru.md) и подключите дерево к серверу Styx.
3. Выполните обычный типизированный `load` Limbo по смонтированному пути модуля и вызовите экспорт.

Мост принимает кадры до 64 КиБ, до 256 идентификаторов ref на вызов и до восьми полей после разворачивания кортежей в одной разреженной записи. У Array для ref в AS до восьми непосредственных полей. Как и в кодеке Dis, ссылка на ещё не завершённое определение отклоняется. В этом же графе доступны [гибридные таблицы и патчи ключей](STYX_RPC_HYBRID.ru.md). Для результатов с живыми каналами используйте [контекстную привязку](STYX_RPC_CHANNELS.ru.md).
