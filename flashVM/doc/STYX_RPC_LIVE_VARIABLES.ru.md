# Живые переменные через Styx VFS

[English](STYX_RPC_LIVE_VARIABLES.md) · [Мост](STYX_RPC.ru.md) · [SDK C](../../lib/styxrpc/LIVE_VALUES.ru.md) · [Запускаемый пример](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md)

Живая привязка позволяет читать и менять переменную, опубликованную другим процессом. Одна операция обращается к скаляру или выбранному элементу. Хранилищем владеет другая сторона. Используйте [типизированные значения RPC](STYX_RPC_VALUE_TYPES.ru.md) для копии целого массива или строки и для обратной записи ref после вызова.

## Выбор проекции

| Публикация | Чтение и запись | Дополнительные методы |
| --- | --- | --- |
| [Ячейка Int32](../../disVM/runtime/VFS-INT-VARIABLE.ru.md) внутри `.var` | `get()`, `set(number)` | `close()` |
| [Массив Int32](../../disVM/runtime/VFS-INT-ARRAY.ru.md) | `get(index)`, `set(index, number)` | `length()`, `close()` |
| [Скаляр big](../../disVM/runtime/VFS-BIG-VARIABLE.ru.md) | `get()`, `set(numberOrDecimal)` | `close()` |
| [Вектор big](../../disVM/runtime/VFS-BIG-VECTOR.ru.md) | `get(index)`, `set(index, numberOrDecimal)`. Для отрицательных индексов отсчёт идёт с конца. | `length()`, `close()` |
| [Гибридная таблица](../../disVM/runtime/VFS-HYBRID-TABLE.ru.md) | Те же методы с точными числовыми ключами и относительными отрицательными индексами. Для строковых ключей и операций над структурой используйте [bindHybrid](STYX_RPC_HYBRID_BIND.ru.md). | `length()` для плотной части, `close()` |
| [Строковая ячейка](../../disVM/runtime/VFS-STRING-VARIABLE.ru.md) | `get()`, `set(stringOrNull)`. До 1024 байт UTF-8 на значение. | `close()` |
| [Запись опубликованных полей](../../disVM/runtime/VFS-VARIABLE-RECORD.ru.md) | Сначала откройте поле, затем вызовите его методы. | `field(name)`, `length()`, `close()` |

Обычные живые привязки локальны для смонтированной сессии. `binding[0]` и присваивание `binding.name` обращаются к свойствам объекта AS. К удалённым данным ведут `get`, `set` и `field`. Запись содержит явно перечисленные владельцем возможности. Вложенная запись открывается как отдельное поле. Через специализированный API Int32 ссылку на ячейку модуля можно [передать уполномоченному процессу](STYX_RPC_INT_VARIABLE_BIND.ru.md).

## Чтение поля и изменение элемента

На записи из [парного примера](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md) откройте доступ на запись, получите массив Int32 и освободите fid родителя. В примере позиции 0 и 2 указывают на одну нативную ячейку Int32. После записи в позицию 0 результат виден в позиции 2 и владельцу в Limbo.

```actionscript
var record = vfs.liveVariable("/live/.var", true); // Разрешаем выданную запись.
var numbers = record.field("numbers");           // Независимый fid поля.
var parentClosed = record.close();
var before = numbers.get(2);                      // -17 в парном примере.
var updated = numbers.set(0, 42);                 // Одна подтверждённая запись.
var aliased = numbers.get(2);                     // 42 из той же ячейки.
var released = numbers.close();
```

При чтении, записи, запросе длины и захвате поля сверяется путь и Qid.path. При изменении содержимого Qid.path сохраняется. Публикация другого узла под тем же именем делает старый прокси устаревшим. Обмен всегда идёт через исходный fid. Если имя заменилось во время вызова, вызов может завершиться на старом узле или вернуть ошибку. Для доступа к новой публикации явно откройте её заново. Освободите прежние прокси и закрывайте сессию после привязок.

## Работа в фильме и задании

Сессия фильма и смонтированная сессия `asinc` предоставляют одинаковые методы. Операции синхронны в контексте владельца. Остановка задания прерывает обход, чтение метаданных или обмен значением, если транспорт позволяет отменить запрос. Неподтверждённая запись могла исполниться. Проверьте действующую привязку или состояние владельца перед повтором. Селектор отменённой операции освобождается отдельно. Выполняйте индексные операции последовательно в контексте владельца сессии.
