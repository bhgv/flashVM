# Доказательства нативной приёмки

v0.644. [English](RELEASE_EVIDENCE.md). Этап 9 остаётся открытым.

[validate_platform.py](../scripts/validate_platform.py) записывает schema 2 в
platform-evidence.json. Каждый профиль сохраняет команды, данные компиляторов,
идентичность исходников и точный результат полного CTest. Старые отчёты schema 1
остаются историческими; смена цифры схемы не добавляет отсутствующих проверок.

[inventory](../scripts/ctest_evidence.py) читает JSON CTest после сборки;
[results](../scripts/ctest_evidence.py) требует ровно один JUnit-результат для
каждого имени, без дублей, ошибок, отключённых тестов и неизвестных состояний.
Повторный список после выполнения должен совпадать. Старый XML удаляется до
запуска. Отсутствующий, повреждённый, слишком большой или неполный результат
означает отказ даже при нулевом коде CTest. Это локальная проверка происхождения,
а не криптографическое удостоверение.

Пропуск допускается только повторяемым `--allow-skip ТОЧНОЕ_ИМЯ_ТЕСТА`, без
шаблонов. Фактические пропуски сохраняются поимённо и не считаются успешным
исполнением. Ноль исполненных успешных тестов запрещён. Проверка намеренно
строже прежней: сначала изучите реальные пропуски конкретной платформы,
затем явно подтвердите ограничение. Это не подтверждает саму возможность.

Из папки компонента:

```sh
python3 scripts/validate_platform.py --profile minimal --jobs 2
```

Если инструменты отсутствуют в PATH, задайте `--cmake` и `--ctest`. Запуск
собирает все настроенные цели; фильтра выборки для приёмки нет. Логи, JUnit и
JSON остаются в игнорируемой build-platform. Изменение исходников или состава
тестов во время проверки делает результат недействительным. Генерируемые
результаты не коммитятся. Статические зависимости и нативный запуск на каждой
платформе требуют отдельных подтверждений.

Девять тестов CTest-evidence включают настоящие запуски CTest с фильтром,
пропуском и отключённым тестом. Семь source-identity тестов проверяют изменение
исходников и замену прежнего успешного отчёта неуспешным. Это Linux-проверки
инструментов, без заявления приёмки Windows/macOS/Android или полного Flash.

## Нативная цель и ABI — v0.642

[native_target.py](../scripts/native_target.py) читает только активную папку
версии CMake; устаревшая CMakeSystem.cmake не подменяет и не блокирует результат.
Требуются буквальные, полные, непротиворечивые host/target поля и FALSE для
CMAKE_CROSSCOMPILING. ОС, нормализованная архитектура и ширина указателя обоих
компиляторов должны совпадать с исполняющим отчёт процессом. Подмена цели Android
или ARM на Linux x64 отвергается до сборки/тестов. Сборка 32-bit из 64-bit Python
требует отдельного согласованного окружения проверки. Native reporter покрывает
Linux/Windows/macOS; Android требует отдельной приёмки на устройстве.

Семь тестов проверяют контракты на метаданных; Windows/macOS/RISC-V в этих тестах
являются fixtures, а не запуском на соответствующей платформе. Реальная активная
Linux x86-64/GNU C/C++ конфигурация отдельно прошла проверку идентичности.

## Сводная матрица — v0.643

[release_matrix.py](../scripts/release_matrix.py) читает переносимые папки отчётов:
platform-evidence.json и подпапки профилей с test-inventory.log,
test-inventory-after.log, ctest-results.xml. Нужны все четыре файла; одного JSON
недостаточно. Записанные абсолютные пути чужого компьютера не исполняются.
Артефакты не могут выходить из папки отчёта, в том числе через symlink.

Обязательны одна версия, полный commit ID, чистое дерево и одинаковые начальный/
конечный fingerprints внутри каждого отчёта. Fingerprints разных ОС не обязаны
совпадать: файловые режимы отличаются. Пересчитываются список тестов, JUnit,
контрольные суммы и числа; проверяются последовательность команд и ABI.
Дубли ячеек, изменённые артефакты, иной commit, schema 1 и грязное дерево запрещены.
Пропуски независимо подтверждаются для конкретной ОС/архитектуры/профиля/имени.

```sh
python3 scripts/release_matrix.py --commit FULL_COMMIT_ID --version 0.643 \
  --report /evidence/linux/platform-evidence.json \
  --report /evidence/windows/platform-evidence.json \
  --output /results/release-matrix.json
```

По умолчанию нужны 16 ячеек: agg/cairo/minimal/minimal-jit для Linux x86_64,
Windows x86_64, macOS aarch64 и Android aarch64. Последний пока не принимается
настольным reporter и остаётся открытым устройственным требованием. Неполная
матрица возвращает 1/blocked, повреждённый ввод — 2/invalid. Явный
`--require Linux:x86_64:minimal` проверяет только выбранное подмножество; успешный
код 0 не закрывает этап 9. Сводка содержит scope, точный список ячеек и ограничения.
`--allow-skip Linux:x86_64:minimal:ТОЧНОЕ_ИМЯ` подтверждает только один пропуск.
Выходной файл размещать вне всех папок входных отчётов. JSON публикуется атомарно.
Локальные отчёты не подписаны: намеренную подделку всех согласованных файлов
этот инструмент не обнаруживает и не заменяет доверенный CI/нативный запуск.

11 тестов проверяют матрицу, перенос папки, неверные ABI/версии/commit, пропуски,
изменения JUnit, дубли, выход symlink и замену прежнего pass состоянием blocked
или invalid. Эти fixtures не считаются исполнением на других ОС.

## Переносимый архив доказательств — v0.644

[release_bundle.py](../scripts/release_bundle.py) экспортирует только отчёт,
два списка CTest и JUnit каждого профиля плюс manifest.json с размерами/SHA-256.
Бинарники, произвольные логи, исходники и Git-история не включаются. Перед записью
проверяется отдельный снимок файлов, поэтому изменение между первой проверкой и
копированием не публикует некорректный архив. Порядок записей, timestamp 1980,
права 0644 и ZIP_STORED фиксированы: повторный экспорт одних байтов идентичен.
Идентичность разных нативных запусков не обещается — их времена/пути различны.

```sh
python3 scripts/release_bundle.py --commit FULL_COMMIT_ID --version 0.644 \
  --report /evidence/linux/platform-evidence.json \
  --output /exports/native-linux-v0.644.zip
```

Для фактических пропусков нужны те же точные --allow-skip правила, что в матрице.
Выход находится вне входной папки. Архив публикуется атомарно; при ошибке старый
архив сохраняется, код возврата обязателен к проверке. Распакуйте свой доверенный
архив в отдельную папку и передайте platform-evidence.json инструменту матрицы.
Хэши manifest — контроль целостности, без электронной подписи/удостоверения ОС.

Пять тестов проверяют байтовую воспроизводимость, manifest, перенос, исключение
лишних файлов, изменение во время экспорта и сохранение старого архива при ошибке.
Отдельный настоящий CMake/C89/C++98/CTest pipeline собирает изолированный проект,
доказывает отказ при нулевом CTest с неподтверждённым skip, успешный повтор,
пересчёт матрицы, экспорт и восстановление после следующего отказа. Это тест
инфраструктуры с маленьким fixture, а не полный прогон VM.
