# Доказательства нативной приёмки

v0.642. [English](RELEASE_EVIDENCE.md). Этап 9 остаётся открытым.

[validate_platform.py](../scripts/validate_platform.py) записывает schema 2 в
platform-evidence.json. Каждый профиль сохраняет команды, данные компиляторов,
идентичность исходников и точный результат полного CTest. Старые отчёты schema 1
остаются историческими; смена цифры схемы не добавляет отсутствующих проверок.

[inventory](../scripts/ctest_evidence.py) читает JSON CTest после сборки;
[results](../scripts/ctest_evidence.py) требует ровно один JUnit-результат для
каждого имени, без дублей, ошибок, отключённых тестов и неизвестных состояний.
Повторный список после выполнения должен совпадать. Старый XML удаляется до
запуска. Отсутствующий, повреждённый, слишком большой или неполный результат
означает отказ даже при нулевом коде CTest. Это локальная проверка происхождения,
а не криптографическое удостоверение.

Пропуск допускается только повторяемым `--allow-skip ТОЧНОЕ_ИМЯ_ТЕСТА`, без
шаблонов. Фактические пропуски сохраняются поимённо и не считаются успешным
исполнением. Ноль исполненных успешных тестов запрещён. Проверка намеренно
строже прежней: сначала изучите реальные пропуски конкретной платформы,
затем явно подтвердите ограничение. Это не подтверждает саму возможность.

Из папки компонента:

```sh
python3 scripts/validate_platform.py --profile minimal --jobs 2
```

Если инструменты отсутствуют в PATH, задайте `--cmake` и `--ctest`. Запуск
собирает все настроенные цели; фильтра выборки для приёмки нет. Логи, JUnit и
JSON остаются в игнорируемой build-platform. Изменение исходников или состава
тестов во время проверки делает результат недействительным. Генерируемые
результаты не коммитятся. Статические зависимости и нативный запуск на каждой
платформе требуют отдельных подтверждений.

Девять тестов CTest-evidence включают настоящие запуски CTest с фильтром,
пропуском и отключённым тестом. Семь source-identity тестов проверяют изменение
исходников и замену прежнего успешного отчёта неуспешным. Это Linux-проверки
инструментов, без заявления приёмки Windows/macOS/Android или полного Flash.

## Нативная цель и ABI — v0.642

[native_target.py](../scripts/native_target.py) читает только активную папку
версии CMake; устаревшая CMakeSystem.cmake не подменяет и не блокирует результат.
Требуются буквальные, полные, непротиворечивые host/target поля и FALSE для
CMAKE_CROSSCOMPILING. ОС, нормализованная архитектура и ширина указателя обоих
компиляторов должны совпадать с исполняющим отчёт процессом. Подмена цели Android
или ARM на Linux x64 отвергается до сборки/тестов. Сборка 32-bit из 64-bit Python
требует отдельного согласованного окружения проверки. Native reporter покрывает
Linux/Windows/macOS; Android требует отдельной приёмки на устройстве.

Семь тестов проверяют контракты на метаданных; Windows/macOS/RISC-V в этих тестах
являются fixtures, а не запуском на соответствующей платформе. Реальная активная
Linux x86-64/GNU C/C++ конфигурация отдельно прошла проверку идентичности.
