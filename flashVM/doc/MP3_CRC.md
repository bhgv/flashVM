# Protected MPEG Layer-III packets

[Русский](MP3_CRC.ru.md).

## Native CRC foundation (v0.813)

The private [fvm_swf_mp3_verify_crc](../src/swf/sound_mp3.cpp#L58) checks one exact MPEG packet without allocation,
VM access, decoder mutation or callbacks. The MPEG protection bit selects CRC
validation: the last sixteen header bits and version/channel-dependent side
information feed the MPEG CRC-16 register. The transmitted checksum is big-endian.
MPEG-1 mono/stereo side information is 17/32 bytes; MPEG-2/2.5 uses 9/17 bytes.
CRC mismatch or a short protected region returns INVALID_ARGUMENT. Unprotected
packets retain their existing behavior. Main audio data is outside this checksum;
this is neither whole-packet integrity nor Huffman validation.

Eight original LAME 3.100 analytical vectors cover all three MPEG versions,
mono/stereo and standard/free-format bitrate. Their transmitted CRC bytes are
encoder output, not generated by FlashVM. Independent mpg123 provides sampled
PCM goldens. Every protected bit and short prefix is tested; main-data flips
explicitly demonstrate checksum coverage limits. Normal builds need no external
encoder or decoder. scripts/generate_crc_mp3_test_fixture.py --check reproduces
the complete fixture on the validation Linux host.


## Decode admission (v0.814)

Every protected packet now passes CRC validation before decoder state or PCM can
change. A failed checksum preserves packet metadata, native reservoir/history and
the previous PCM buffer, so a caller may retry the intact packet. This extra atomic
retry guarantee applies to pre-decode CRC rejection; failures inside the codec remain
terminal as before. DefineSound full-source validation rejects a damaged final CRC
even for an early or zero-length selected read, without publishing partial PCM.


## Counted-block preparation (v0.815)

Free-format block geometry is committed only after every candidate packet has a
valid protected-region CRC. Failure preserves the fresh decoder even when the
bad checksum is at the end of a multi-packet first block. Ordinary and free-format
stream normalization reject damaged late packets without publishing a snapshot.
Peak-budget bounds and allocation counts remain unchanged. Allocation failures
are recoverable; normalized readers survive VM teardown without allocating.


## Player admission (v0.816)

Unmuted desktop playback now fully validates each MP3 referenced by a root
StartSound before window/audio acquisition. A fixed 8192-byte owner-stack bitmap
deduplicates UI16 sound IDs; a zero-length public PCM read validates every packet
without retaining PCM. Stop-only events do not require a source decode. This checks
all statically referenced root MP3, including later or otherwise unreached frames.
Muted playback and metadata inspection do not decode the sound. Playback-time
voice preparation remains separately bounded and outside the native worker mutex.


## Actual player oracle (v0.817)

The independent mpg123 oracle compares every S16 value accepted by dummy SDL for
128 protected-stream and MP3/PCM/ADPCM mixed-event cases: eight encodings, grouped
packets, FWS/CWS and interpreter/native JIT. All pass within three S16 units.
Another 128 first/last-checksum failures are rejected before audio acquisition
and leave a preexisting trace destination unchanged. Sixty-four muted cases pass
without opening an audio device. These are native software/queue checks, not
physical-device acceptance. Header/side CRC does not cover audio main data.


## Bounded C89 verification (v0.818)

The annotated [C89 example](../examples/multimedia/swf_stream_mp3/README.md) adds
`--verify INPUT.swf`: bounded input, complete first-segment normalization and
post-VM native reads, with no output file. Export and verification share the same
CRC/error admission. The protected fixture oracle covers 72 grouped FWS/CWS cases
with independent sampled PCM, plus rejection without replacing an existing output.
This command checks one audio segment, not every movie resource or AVM1 behavior.


## Concurrent native decoding and acceptance (v0.819)

Four real OS workers independently decode all eight shared immutable fixtures
for eight passes each. The host creates workers/gate before disabling C++ new/new[],
releases the gate with proper mutex ordering, then joins all workers before cleanup.
Each instance rejects a damaged checksum without changing history, retries the intact
packet and compares independent PCM positions. No VM or GC state is shared or needed.
This workload passes ordinary native and full-core ASan/UBSan builds; it is not TSan
or native Windows/macOS/Android acceptance.

Final evidence: 93 native audio tests, six CRC/worker ASan/UBSan cases, 128 valid
protected SDL cases, 128 rejected first/last-checksum cases, 64 muted bypass cases,
the distinct-ID preflight unit and C89 verification/export pass. LAME/mpg123 regenerate
all protected and prior free-format fixtures exactly on the validation host.
Native injected allocation failures use the ordinary build. Header/side CRC does
not establish whole-audio integrity, full SWF support, A/V timing or device quality.


The global multimedia comment checker still reports two unchanged baseline Windows
speech files; the changed annotated C89 tutorial and frontend catalog checks pass.
