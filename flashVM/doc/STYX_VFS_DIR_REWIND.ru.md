# Directory.rewind

[English](STYX_VFS_DIR_REWIND.md) · [Файловые методы](STYX_RPC_OS.ru.md) · [SDK на C](../../lib/styxrpc/reference/vfs_dir_rewind.ru.md) · [Реализация](../src/styxrpc/os.c#L385)

```actionscript
directory = vfs.opendir(path)
directory.rewind()
entry = directory.next_file()
```

Начать заново обход каталога, уже открытого через `vfs.opendir` или
`os.opendir`. Метод не принимает аргументов. Он удаляет записи из
буфера, сбрасывает EOF или ошибку прежнего обхода и возвращает `true`.
Следующий вызов `next_file()` прочитает Styx с нулевого смещения и
может ждать ввода-вывода. Если сервер больше не узнаёт исходный
идентификатор каталога, чтение завершится ошибкой. Чтобы разрешить
путь заново и открыть каталог, который находится там сейчас, вызовите
`opendir(path)`. Вызов `rewind()` после закрытия даёт ошибку.

В дереве файлов с колбэками у каждого каталога своя ревизия. Публикация
или отзыв непосредственного потомка меняют эту ревизию. Если при обходе
сервер обнаруживает смену ревизии, чтение прерывается с ошибкой.
Изменение в другом каталоге позволяет продолжить обход. Итератор может
успеть выдать записи из буфера прежнего чтения до обнаружения изменений.
Для актуального списка начните обход с начала.

В Limbo для открытого каталога в парном монтировании Styx вызовите
`sys->seek(fd, big 0, Sys->SEEKSTART)`, затем `sys->dirread(fd)`.
Для каталога поддерживается только нулевое смещение от начала.
Исходный fid сохраняется.

Добавьте `--dirlive` к [парной проверке](../../disVM/runtime/STYX-CHANNEL.ru.md#проверка).
[SWF на AS](../../lib/styxrpc/tests/flashvm/dirlive_pair.as) удерживает
один каталог DisVM во время публикации и отзыва.
[Клиент на Limbo](../../lib/styxrpc/tests/flashvm/dirlive_pair.b)
читает каталог в несколько сообщений и проверяет продолжение обхода
при изменении соседнего каталога. После изменения состава открытого
каталога клиент перематывает его. Оба приложения работают в штатной паре.
