# Делегирование каналов UniBus на отдельных маршрутах

[English](STYX_RPC_CHANNEL_DELEGATION.md) · [Вложенные каналы](STYX_RPC_NESTED_CHANNELS.ru.md) · [Самостоятельный C SDK](../../lib/styxrpc/reference/channel_leases.ru.md)

Типизированное сообщение UniBus может нести маршрут за пределами текущей шины. Встречный PID задаёт ресурс, опубликованный хостом на второй половине того же соединения Styx. Токен модуля задаёт отдельную публикацию на удерживаемом модуле DisVM. Нативный провайдер Dis использует оба адреса для обмена рекурсивными каналами.

## Опубликуйте очередь ActionScript

1. Инициализируйте встречный реестр программ и создайте [сервер программ](../../lib/styxrpc/reference/program_server_create.ru.md) на встречной половине того же двунаправленного соединения Styx, по которому вызывается DisVM. Запустите диспетчер в отдельном потоке. У владельца FlashVM установите [фабрику локальных каналов](STYX_RPC_CHANNEL_FACTORY.ru.md) под именем `newRpcChannel` и [функцию публикации](STYX_RPC_CHANNEL_PUBLISHER.ru.md) под именем `publishPort`.
2. Вызовите функцию Dis и оставьте открытым арендованный канал, принимающий в сообщении канал целых чисел. В примере этот канал называется `outgoing`. В очередь ActionScript со слотами можно записать начальное значение до публикации.

   ```actionscript
   var queue = newRpcChannel("i", 2);
   queue.trySend(81);
   var port = publishPort(outgoing, queue);
   outgoing.send(port);
   ```

3. Dis открывает `.prog/<pid>/.unibus` через существующее встречное монтирование и работает с исходной очередью. Во время публикации локальные методы очереди сообщают, что канал занят. После обмена закройте или освободите каналы результата и уберите ссылки на непрозрачные значения PID этого семейства. Последнее освобождение отзовёт PID, отменит ожидающие fid и вернёт доступ к очереди с оставшимися значениями. Сохраняйте встречный сервер до окончания отзыва.

[Нативный API хоста](STYX_RPC_CHANNEL_DELEGATE_LOCAL.ru.md) также публикует очередь явно. [Ресурс C SDK](../../lib/styxrpc/reference/channel_group_reverse_borrow_graph.ru.md) доступен независимо от обеих VM.

### Опубликуйте каналы внутри сообщений

Если элемент очереди содержит локальный канал, функция публикации обходит каналы, ссылки на которые уже стоят в FIFO. Все достижимые очереди передаются под одним PID. Каждая отдельная очередь получает свой ключ на этой шине. Повторная ссылка на канал в другом слоте или позиции сообщения сохраняет его идентичность. Партнёр может обмениваться данными через дочерние каналы и возвращать опубликованные каналы в совместимые очереди той же шины. Граф вмещает до восьми очередей вместе с корневой. Закрытый или уже переданный потомок приводит к отклонению всей публикации.

После отзыва данные FIFO возвращаются в исходные очереди. При следующем локальном обращении FlashVM восстанавливает точные ссылки из возвращённых записей. Трассируемый граф удерживает объекты при сборке мусора до этого обращения. В [нативной проверке Limbo](../../lib/styxrpc/tests/flashvm/channel_pid_graph.b) Dis переносит rendezvous из одного FIFO в другой. [Хост FlashVM](../tests/styxrpc/channel-pid-graph.c) проверяет оба алиаса и оставшиеся данные после GC.

## Отправьте PID, уже зарегистрированный хостом

1. Подготовьте [встречный ресурс очередей](../../lib/styxrpc/reference/channel_group_reverse_output.ru.md) либо эквивалентные колбэки. Зарегистрируйте ресурс через [публикацию PID](../../lib/styxrpc/reference/program_unibus_grant.ru.md) у встречного диспетчера Styx. Сохраняйте регистрацию, пока партнёр использует канал.
2. Вызовите компилированную функцию DisVM на прямой половине этого же соединения. Сохраните открытый канал результата. У владельца FlashVM [свяжите встречный PID с этой арендой](STYX_RPC_CHANNEL_DELEGATE_PID.ru.md) и передайте полученное значение коду ActionScript.
3. Поместите значение в подходящую позицию сообщения, отправляемого через канал той же аренды. Если элемент состоит из одного канала, вызовите `outgoing.send(reversePort)`. Кодек проверяет адрес, ключ, форму и признак ёмкости. Значение из другой аренды вызывает исключение AS до отправки.

## Примите делегированный канал модуля

Когда DisVM отправляет полномочие модуля встречному ресурсу, хост связывает этот ресурс с выдавшим результатом. Диспетчер C может использовать [политику маршрутов](../../lib/styxrpc/reference/channel_read_routed.ru.md), чтобы принять и передать кадр. В потоке-владельце FlashVM передайте полный кадр и открытый канал результата [функции допуска сообщения](STYX_RPC_CHANNEL_ADMIT_MESSAGE.ru.md). SDK предъявляет каждый токен модулю, удерживаемому результатом. FlashVM декодирует типизированное значение и переиспользует живой объект AS для повторного полномочия. Полученным каналам доступны `send()`, `receive()` и неблокирующие методы. Для уже проверенного маршрута по-прежнему доступен [допуск отдельного полномочия](STYX_RPC_CHANNEL_ADMIT_MODULE.ru.md).

[Рекурсивная проверка Limbo](../../disVM/examples/remote-scalar/styx-channel-recursive-owner.b) получает PID от FlashVM, посылает дочерний канал модуля этому встречному ресурсу и принимает тот же канал обратно. Затем [хост FlashVM](../tests/styxrpc/channel-delegated.c) передаёт через полученный канал модуля второй PID, за которым стоит очередь ActionScript на два слота. Dis записывает 43, читает заранее поставленное 81 и возвращает 81 через канал результата. FlashVM освобождает семейство и читает 43 из исходной очереди.

Граф локальных очередей допускает точные ключи своей шины. Отдельно адресуемые PID и токены модулей обрабатывает ресурс хоста с соответствующей политикой маршрутов. Хост передаёт принятое сообщение владельцу FlashVM вместе с каналом исходного результата.

После [сборки интеграционных проверок](../../lib/styxrpc/examples/README.ru.md) выполните `ctest --test-dir build -R 'channel-(delegated|pid-graph)' --output-on-failure`. Оба сценария запускаются на нативном интерпретаторе и JIT.
