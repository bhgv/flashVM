# Двоичные S-записи: профиль 1

[English](SRECORD.md) · [Публичный C89 API](../include/flashvm/srecord.h) · [План](ROADMAP_STATUS.md).

Реализовано предложенное пользователем двоичное обрамление, без текстовых
S-выражений. Неоговорённые решения первого профиля указаны явно. Это не
существующий диалект 9P/Styx; VM-каналы автоматически на него не переключаются.
Указатели VM, native-структуры и порядок байтов машины в поток не копируются.

## Целые числа

Группы идут от старших к младшим, big endian. Бит 7 означает **последний** байт.
Бит 6 первого байта — знак, остальные шесть бит — начало модуля числа. Дальнейшие
байты несут по семь бит. Это знак/модуль, не zigzag и не LEB128. Избыточные
группы и отрицательный нуль отвергаются. Модуль допускается до 2^64-1; два
32-битных C89 поля представляют его и на платформах с 32-битным unsigned long.

| Число | Байты hex |
| --- | --- |
| 0 | `80` |
| 63 | `bf` |
| -63 | `ff` |
| 64 | `00 c0` |
| -64 | `40 c0` |
| 8191 | `3f ff` |
| 8192 | `00 40 80` |

Содержимое payload непрозрачно для обрамления. Схемы float32/float64, samples,
времени и изображений отдельно фиксируют точное big-endian представление.
Сам codec не преобразует произвольные бинарные данные.

## Обрамление и checksum

```text
checksum : неотрицательное каноническое целое
length   : неотрицательное каноническое целое
body     : неотрицательный канонический тег и непрозрачное тело тега
```

Length включает байты тега и payload, исключая свои байты и checksum. Теги —
неотрицательные 32-битные числа. Нуль зарезервирован для метаданных привязок
конкретного направления. Body непустое, максимум 16 MiB; читатель дополнительно
задаёт меньший лимит. Пустой payload и NUL допустимы. Внутри могут находиться
другие полные S-записи, порции данных или метаинформация. Это определяется
схемой: codec не начинает автоматически рекурсивное исполнение/разбор.

Checksum покрывает точные байты **length + tag + payload**. В предлагаемом
профиле 1 выбрана CRC-32/ISO-HDLC: reflected polynomial edb88320, initial
ffffffff, final xor ffffffff. Сохраняются младшие min(32, 6+7*(L-1)) бит, где
L — число байтов length. Результат записывается как обычное неотрицательное
каноническое целое. Короткое body имеет меньшую верхнюю границу длины checksum;
небольшое значение CRC может кодироваться ещё короче. Строгой монотонности длины
нет. При текущем лимите 16 MiB сохраняется максимум 27 бит CRC; для однобайтной
length — шесть бит. Это ограниченная проверка случайного повреждения, не
аутентификация и не защита от активного противника. Полномочия и защищённый
транспорт — отдельный слой.

Алгоритм checksum пользователь не задавал: этот выбор является явным первым
профилем. Его изменение требует другого согласованного вне потока профиля.
Magic/version в предложенное обрамление не добавлены.

Reader сначала проверяет целые и лимиты, затем checksum; лишь после этого
интерпретирует тег и отдаёт view. MORE означает неполный префикс. Автоматического
поиска следующей записи после повреждения нет. Транспорт ограничивает память/
время ожидания и выбирает закрытие/сброс сеанса. Checksum не позволяет безлимитно
выделять память по непроверенной длине.

## C API: владение и ошибки

| API | Контракт |
| --- | --- |
| [`fvm_sinteger_write`](../include/flashvm/srecord.h#L50) | Заимствует число и output хоста, проверяет limbs/знак и ёмкость до записи. Used публикуется только при OK; ошибка сохраняет bytes/used. |
| [`fvm_sinteger_read`](../include/flashvm/srecord.h#L52) | Заимствует префикс, value/used обязательны. Публикация только при OK. При MORE вызывающий сохраняет и дополняет префикс. |
| [`fvm_srecord_write`](../include/flashvm/srecord.h#L60) | Заимствует tag/payload, пишет лишь после полной проверки. Payload не пересекается с output. Без выделений памяти, VM и транспорта. |
| [`fvm_srecord_read`](../include/flashvm/srecord.h#L66) | Возвращает одну проверенную заимствованную view и consumed. Limit считает body. При MORE/ошибке выходы прежние; следующие записи не потребляются. |

Независимое хранение делает вызовы реентерабельными. Глобального изменяемого
состояния, входа в VM/GC/SDL/device нет. Общие буферы синхронизирует хост.
Все указатели должны обозначать доступную память; выходы не перекрывают входы
и друг друга. Доступность произвольного адреса не проверяется. [FVM_S_OK](../include/flashvm/srecord.h#L24)/MORE/
INVALID/LIMIT/CHECKSUM различают полный результат, ожидание, неверные данные,
лимит и повреждение. Исключения через C не проходят. Native view не передаётся
копированием sizeof(struct).

## Сборка и проверка

Из корня workspace, с C89/C++98 компилятором, CMake и Python 3:

```sh
cmake -S flashVM -B build-srecord -DFVM_BUILD_TESTS=ON \
  -DFVM_DEFS_FILE="$PWD/flashVM/cmake/profiles/minimal.defs"
cmake --build build-srecord --target flashvm_srecord flashvm_srecord_oracle --parallel
ctest --test-dir build-srecord -R '^flashvm_srecord_' --output-on-failure
```

Отдельная статическая цель flashvm_srecord содержит лишь C-исходники протокола.
Те же файлы входят в обычный VM SDK; хост выбирает один способ линковки.
SDL/сеть/startup VM для codec не нужны. Тестовая shared-библиотека проверяется
независимыми Python big integers и zlib. Cross задаёт target toolchain file;
тесты исполняются на target. Native foreign OS и интеграция 9P/Inferno ФС пока
не реализованы; формат не зависит от endian/native ABI.
## Независимые привязки направлений, тег 0 (v0.723)

[sbindings.h](../include/flashvm/sbindings.h) добавляет ограниченную таблицу хоста.
Для каждого направления каждого сеанса нужна отдельная таблица: исходящие
декларации A заполняют входящую таблицу B и наоборот. Поэтому тег 3 может быть
ieee754.f64.be в A→B и boolean в B→A. Глобального числового соответствия нет.
Нуль перепривязать нельзя. Неизвестный ненулевой тег остаётся неизвестным;
сырой codec может вернуть байты, но dispatcher не должен угадывать их тип.

Двоичный payload тега 0, схема 1:

```text
unsigned версия_схемы_payload = 1
unsigned число_привязок
повторить число_привязок раз:
    unsigned ненулевой_тег
    unsigned ненулевая_версия_схемы_типа
    unsigned длина_идентификатора
    байты_идентификатора
```

Все числа записаны тем же каноническим способом. Идентификатор — 1..63
печатных ASCII-байта без пробелов; он называет схему, не предоставляет кодек
или полномочия. Ограничение не касается пользовательских строк/UTF-16/UTF-8/
бинарных данных. В первой таблице максимум 256 привязок; декларация с count=0
допустима. Вложенные записи требуют объявленной прикладной схемы sequence.

Привязка неизменна внутри направления/сеанса. Точный повтор идемпотентен;
повтор тега внутри одной декларации недопустим даже при одинаковой схеме.
Конфликт, повреждение/truncation/checksum, лишние байты и нехватка slots
оставляют всю таблицу прежней. Сброс — явная переинициализация после остановки
старого сеанса и удаления его queued records. Уже отправленные теги нельзя
внезапно переинтерпретировать новой схемой.

| API | Контракт |
| --- | --- |
| [`fvm_sbindings_init`](../include/flashvm/sbindings.h#L33) | Заполняет descriptor/capacity, не меняя slots. Без выделений/VM/GC; reinit создаёт пустую таблицу направления. |
| [`fvm_sbindings_lookup`](../include/flashvm/sbindings.h#L37) | Копирует metadata в output; UNKNOWN для нуля/неизвестного тега. Ошибка сохраняет output. Указатель объекта или полномочия не выдаёт. |
| [`fvm_sbindings_payload_write`](../include/flashvm/sbindings.h#L43) | Проверяет весь список и ёмкость, пишет только двоичный payload декларации. Его оборачивают record_write с тегом 0 в отдельный буфер. |
| [`fvm_sbindings_apply`](../include/flashvm/sbindings.h#L49) | Проверяет целую запись тега 0/checksum и все элементы до атомарного добавления. Идентификаторы копируются; вход нужен лишь на время вызова. Used меняется только при OK. |

Descriptor/slots/input/output не перекрываются. Скрытых выделений/блокировок
нет; общий доступ lookup/apply/reset синхронизирует хост. Двухпроходная проверка
ограничена числом элементов и не выделяет стек размером с запись. Это пока
декларации схем: float/objects/audio/video требуют собственных реализаций схем
и dispatcher с полномочиями/исполнением у владельца. Native-ресурсы и живые
VM-объекты автоматически не сериализуются и не перемещаются.
