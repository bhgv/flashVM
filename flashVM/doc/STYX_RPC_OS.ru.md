# Файловые методы vfs и os

[English](STYX_RPC_OS.md) · [Плеер](STYX_RPC_PLAYER.ru.md) · [Открытие и атрибуты](../src/styxrpc/os_open.c) · [Методы дескрипторов](../src/styxrpc/os.c)

В штатном плеере `os` ссылается на тот же объект, что и `vfs`.
У обоих имён общая подключённая сессия libstyxrpc и общий рабочий каталог.
Начальная косая черта отсчитывает путь от корня сессии. Относительные пути
начинаются от [`pwd()`](STYX_VFS_PWD.ru.md). Начальный каталог — `"/"`. Служебные узлы, включая
`.prog`, `.var` и корни UniBus, скрыты.

[Файл с колбэком из Limbo](../../disVM/runtime/STYX-NODES.ru.md) доступен через эти же файловые методы.

| Вызов | Результат |
| --- | --- |
| `vfs.open(path[, mode])` | Дескриптор файла. Режимы `"r"` по умолчанию, `"w"` для записи с сохранением длины при открытии, `"rw"` для обоих направлений и `"wx"` для создания нового файла с доступом на запись. |
| [`vfs.unload(module)`](STYX_RPC_UNLOAD.ru.md) | Закрыть проверенный прокси Dis в этом контексте. |
| `vfs.opendir(path)` | Итератор с одним открытым fid каталога. |
| `vfs.attr(path[, root])` | Текущие атрибуты записи. Если параметр `root` передан, `"/"` выбирает подключённую VFS. |
| [`vfs.mkdir(path)`](STYX_VFS_MKDIR.ru.md) | Создать один каталог. |
| [`vfs.rm(path)`](STYX_VFS_RM.ru.md) | Удалить файл либо пустой каталог. |
| [`vfs.rmnode(path)`](STYX_RPC_RMNODE.ru.md) | Отозвать один файл, опубликованный фильмом. |
| [`vfs.cd(path)`](STYX_VFS_CD.ru.md) | Сменить общий рабочий каталог. |
| [`vfs.pwd()`](STYX_VFS_PWD.ru.md) | Получить канонический рабочий путь. |
| [`vfs.exec(path[, bytes])`](STYX_VFS_EXEC.ru.md) | Вызвать исполняемый узел и вернуть байты ответа. |

Режим `"wx"` требует существующего каталога с правами на создание. Если
имя уже занято, вызов завершается ошибкой. В штатной паре DisVM применяет
правила текущей VFS и режим создания файлов хоста. Провайдеры без поддержки
создания возвращают ошибку. Вызовы выполняются в потоке владельца фильма и
могут ждать ответа до истечения срока запроса Styx.

Атрибуты и результаты `next_file()` имеют поля `name`, `directory`, `mode`,
`lengthHigh` и `lengthLow`. Последние два поля дают точную пару UInt32 для
длины в байтах. `length` содержит AS Number до 2⁵³−1 или `undefined`.
Итератор возвращает `undefined` в конце каталога. Для нового обхода
открытого каталога используйте [`rewind()`](STYX_VFS_DIR_REWIND.ru.md).

| Метод файла | Результат |
| --- | --- |
| `read(count)` | Массив подтверждённых байтов с текущей позиции. Короткий результат и пустой массив возможны на EOF. |
| `write(bytes)` | Число подтверждённых байтов. Принимает плотный массив чисел 0–255. |
| `seek(delta[, origin])` | Новая позиция в байтах. Начало `"set"` по умолчанию, текущая позиция `"cur"` или конец `"end"`. |
| `len()` | Текущая длина открытого файла в байтах. |
| `flush()` | Состояние подтверждения записи. Клиент посылает записи сразу. `false` означает, что подтверждение последней записи потеряно. Проверку сохранности данных на носителе определяет провайдер. |
| `load()` | Дочерний `MovieClip` для `.swf` либо проверенный прокси методов Dis. |
| `close()` | Закрытие дескриптора, включая итератор каталога. Повторный вызов успешен. |

Одна операция чтения или записи ограничена 2048 байтами. Курсор сдвигается
на подтверждённое число байтов. Ошибки операций передаются скрипту. После
неопределённой записи потребуется новое открытие для следующих записей.
Когда ни объект, ни извлечённые из него методы больше недостижимы,
сборщик ставит закрытие fid в очередь сессии без сетевого I/O из сборщика.

```actionscript
var file = vfs.open("/movies/intro.swf");
var clip = file.load();
file.close();
clip.play();

var image = os.open("/mounted/counter.dis");
var counter = image.load();
image.close();
var result = counter.next(41);
```

SWF читается целиком с открытого fid без изменения байтового курсора. Плеер
синхронно добавляет клип на следующую свободную глубину корневого фильма.
Кадры исполняются по обычному циклу плеера. Загрузка сохраняет исходный путь
для последующих относительных загрузок клипа.

Для `.dis` нужен образ с опубликованным интерфейсом StyxRPC. Загрузчик
считывает имена, сигнатуры и схемы и возвращает методы для прямых вызовов.
В штатной паре поддерживаются Int32 и профили managed/graph без встречного
PID. Контекстные вызовы требуют встречного PID. Обычный файл `.dis` можно
загрузить непосредственно в [сессии живой загрузки](STYX_RPC_LIVE_DIS.ru.md).
Дескриптор опубликованного модуля удерживает точный образ с момента открытия. `load()`
проверяет этот образ и закрепляет отдельный fid за прокси. Закрытие
исходного дескриптора оставляет загруженный клип или прокси доступным.
Если владелец отзывает образ, старые дескрипторы и методы прокси
возвращают ошибку даже после публикации нового образа под тем же именем.

В штатной паре с DisVM фильм и отделённые задачи получают независимые
встречные PID и шины аргументов. См. [прямые контекстные вызовы](STYX_RPC_LIVE_DIS.ru.md)
и [VFS в задачах](ASINC_VFS.ru.md).
