# Системный объект os

[English](STYX_RPC_OS.md) · [Плеер](STYX_RPC_PLAYER.ru.md) · [Открытие и атрибуты](../src/styxrpc/os_open.c) · [Методы дескрипторов](../src/styxrpc/os.c)

`os` доступен фильмам в штатном плеере с подключённой VFS libstyxrpc.
Пути с начальной косой чертой и без неё отсчитываются от корня этой
сессии. `"/"` обозначает её корневой каталог. Служебные узлы, включая
`.prog`, `.var` и корни UniBus, скрыты.

| Вызов | Результат |
| --- | --- |
| `os.open(path[, mode])` | Дескриптор существующего файла. Режимы `"r"` по умолчанию, `"w"` для записи с сохранением длины при открытии и `"rw"` для обоих направлений. |
| `os.opendir(path)` | Итератор с одним открытым fid каталога. |
| `os.attr(path[, vfs])` | Текущие атрибуты записи. Если параметр `vfs` передан, `"/"` выбирает подключённую VFS. |

Атрибуты и результаты `next_file()` имеют поля `name`, `directory`, `mode`,
`lengthHigh` и `lengthLow`. Последние два поля дают точную пару UInt32 для
длины в байтах. `length` содержит AS Number до 2⁵³−1 или `undefined`.
Итератор возвращает `undefined` в конце каталога. Новое открытие начинает
обход заново. Изменение каталога во время чтения может прервать обход.

| Метод файла | Результат |
| --- | --- |
| `read(count)` | Массив подтверждённых байтов с текущей позиции. Короткий результат и пустой массив возможны на EOF. |
| `write(bytes)` | Число подтверждённых байтов. Принимает плотный массив чисел 0–255. |
| `seek(delta[, origin])` | Новая позиция в байтах. Начало `"set"` по умолчанию, текущая позиция `"cur"` или конец `"end"`. |
| `len()` | Текущая длина открытого файла в байтах. |
| `flush()` | Состояние подтверждения записи. Клиент посылает записи сразу. `false` означает, что подтверждение последней записи потеряно. Проверку сохранности данных на носителе определяет провайдер. |
| `load()` | Дочерний `MovieClip` для `.swf` либо объект с удалёнными методами для опубликованного образа `.dis`. |
| `close()` | Закрытие дескриптора, включая итератор каталога. Повторный вызов успешен. |

Одна операция чтения или записи ограничена 2048 байтами. Курсор сдвигается
на подтверждённое число байтов. Ошибки операций передаются скрипту. После
неопределённой записи потребуется новое открытие для следующих записей.
Когда ни объект, ни извлечённые из него методы больше недостижимы,
сборщик ставит закрытие fid в очередь сессии без сетевого I/O из сборщика.

```actionscript
var file = os.open("/movies/intro.swf");
var clip = file.load();
file.close();
clip.play();

var image = os.open("/mounted/counter.dis");
var counter = image.load();
image.close();
var result = counter.next(41);
```

SWF читается целиком с открытого fid без изменения байтового курсора. Плеер
синхронно добавляет клип на следующую свободную глубину корневого фильма.
Кадры исполняются по обычному циклу плеера. Загрузка сохраняет исходный путь
для последующих относительных загрузок клипа.

Для `.dis` нужен образ с опубликованным интерфейсом StyxRPC. Загрузчик
считывает имена, сигнатуры и схемы и возвращает методы для прямых вызовов.
В штатной паре поддерживаются Int32 и профили managed/graph без встречного
PID. Контекстные вызовы требуют встречного PID. Для произвольного файла
`.dis` в обычной VFS нужна публикация интерфейса со стороны DisVM.
Закрытие исходного дескриптора не отзывает загруженный клип или прокси.

Сценарии приёмки собраны из [AS](../tests/styxrpc/os-client.as) и
[Limbo](../../lib/styxrpc/tests/flashvm/os_check.b). Для явного выбора
контрактов см. [styxrpc.loadModule](STYX_RPC_LOAD_MODULE.ru.md).
