# vfs.exec

[English](STYX_VFS_EXEC.md) · [Сессия](STYX_RPC_DEFAULT.ru.md) · [Реализация AS](../src/styxrpc/session_exec.c#L16) · [SDK C](../../lib/styxrpc/reference/node_exec.ru.md)

```actionscript
reply = vfs.exec(path[, bytes])
```

Метод вызывает колбэк, опубликованный другой программой как исполняемый
узел через [`vfs.newnode`](STYX_RPC_NEWNODE.ru.md) или SDK C. В парном
плеере `os.exec` вызывает тот же метод того же объекта. Вызов проходит
через присоединённую сессию libstyxrpc.

| Аргумент | Назначение |
| --- | --- |
| `path` | Путь VFS длиной до 1024 байт после нормализации, без начальной косой черты. Абсолютный путь начинается от корня другой стороны. Относительный берётся от [рабочего каталога](STYX_VFS_PWD.ru.md) сессии. Корень и служебные компоненты недопустимы. |
| `bytes` | Необязательный плотный массив точных чисел от 0 до 255. Максимум 65 536 байт. Без аргумента или с пустым массивом передаётся ноль байт. |

Метод возвращает новый плотный Array с подтверждёнными байтами ответа.
Ответ может быть пустым, его длина ограничена длиной входа. Метод
снимает копию входа перед вызовом, исходный массив сохраняет своё
содержимое. Чтение длины и элементов может вызвать геттеры до отправки.

Ошибки аргументов обнаруживаются до удалённого запроса. Отсутствие
службы, отказ провайдера или сбой транспорта дают исключение. Ответ
может потеряться после исполнения колбэка. SDK не повторяет вызов.
Вызов ждёт ответа в потоке владельца фильма. Колбэку другой стороны
следует вернуть ответ до синхронного вызова обратно в ожидающий фильм.

Узлы могут публиковать FlashVM, хостовый сервер SDK и штатная DisVM.
[Публикация из Limbo](../../disVM/runtime/STYX-EXEC-PUBLISH.ru.md) использует
то же двунаправленное соединение.

```actionscript
os.cd("/tools");
var args = [255, 40, 0, 23];
var result = vfs.exec("apply", args);
```

[Парный обработчик AS](../../lib/styxrpc/tests/flashvm/execute_apply.as)
возвращает номер вызова и крайние байты входа.
[Проверочный фильм](../tests/styxrpc/peer-exec-caller.as) использует оба
имени метода. Чтобы выполнить только этот сценарий, добавьте
`--exec-only` к [проверке двух плееров](STYX_RPC_PLAYER.ru.md).
