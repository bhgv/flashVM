# Идентичность звука в очереди

## v0.793: длительность готового голоса на выходной сетке

[`fvm_swf_sound_voice_output_frames`](../include/flashvm/swf_sound_mixer.h#L44) считает точное число оставшихся выходных
кадров для голоса, передаваемого с ТЕКУЩЕЙ позиции исходного PCM и нулевой фазой
конвертации. Учитывает оставшиеся повторы, округляет рациональную длительность
вверх и возвращает ноль на EOF. Не читает PCM, не выделяет память, не вызывает
callbacks, не обращается к VM и не меняет позицию. Выходная частота ограничена
диапазоном configured-микшера. Неверные аргументы дают INVALID_ARGUMENT без
изменения выхода; превышение SOUND_OUTPUT_MAX_CLOCK — UNSUPPORTED. Голос остаётся
у вызывающего и требует сериализации. Результат — целое double, а не секунды или
позиция DAC. Уже переданный микшеру голос имеет собственные lookahead/фазу и
не описывается этим расчётом новой выходной сетки.

`swf_sound_voice_output_frames` сравнивает каждую позицию трёх повторов при
четырёх исходных и восьми выходных частотах с реальным завершением микшера при
чтении по одному кадру, включая EOF и чтение после уничтожения VM. Это учёт
нативных отсчётов, а не полная приёмка таймлайна Flash или физических устройств.

## v0.794: необязательное фиксированное хранилище ID

[`fvm_swf_sound_output_set_identity_tracking`](../include/flashvm/swf_sound_output.h#L61) включает/выключает фиксированную
нативную таблицу OUTPUT_ID_SLOTS double-границ завершения (512 KiB на этом хосте).
Настройка разрешена без голосов, принятых или pending PCM. Включение выделяет
память транзакционно, выключение действительно освобождает таблицу. Ошибка
состояния/аргументов — INVALID_ARGUMENT, аллокации — OOM с прежней таблицей.
Backend/VM не вызываются; выход и микшер сериализуются вызывающим.

[`fvm_swf_sound_output_storage_info`](../include/flashvm/swf_sound_output.h#L74) копирует точные размеры объекта, retry PCM,
history, таблицы ID и проверенную сумму. Заимствованные микшер/устройство, VM и
накладные расходы аллокатора исключены. Неверные размер/null/reentry сохраняют
выход. [`fvm_swf_sound_output_sound_active`](../include/flashvm/swf_sound_output.h#L81) опрашивает эксклюзивную FIFO и сравнивает
границу ID с принятыми минус оставшимися в очереди кадрами. Выключенный учёт —
UNSUPPORTED, неверный ID/reentry — INVALID_ARGUMENT. Ошибки/исключения backend
сохраняют выход. Callback может блокировать по контракту backend; VM и новых
аллокаций нет. Используйте только tracked start/stop: прямое изменение микшера
не входит в контракт учёта.

`swf_sound_output_identity_storage` проверяет размеры, повторное включение,
реальное освобождение таблицы, ограничения состояния и ошибки запроса.

## v0.795: передача с SyncNoMultiple до конца очереди

[`fvm_swf_sound_output_submit_prepared_bounded`](../include/flashvm/swf_sound_output.h#L114) опрашивает FIFO, затем передаёт
голос с позиции submitted+pending. Точная оставшаяся длительность на выходной
сетке задаёт исключающую конечную границу ID. Обычные старты одного ID могут
перекрываться, сохраняется максимальный конец. NoMultiple потребляет ненужного
владельца, пока зарегистрированное время ID ещё не прошло, даже если микшер уже
освободил голос. Подавление не требует нового бюджета микшера. Пустые голоса не
продлевают границу. Принятый и pending PCM не перемешивается заново: новый голос
начинается со следующей границы композиции.

Сначала включите tracking; все start/read/stop заимствованного микшера должны
идти через выход. Бюджет микшера исключает выход/таблицу/устройство/шаблоны.
Нет аллокаций, decode и VM; callback запроса FIFO может блокировать. Владельцы
сериализованы и живы. Успех потребляет/обнуляет указатель; отказ сохраняет его
позицию, старые интервалы и голоса, но успешное наблюдение FIFO может обновить
скопированные счётчики. Переполнение часов/длительности и выключенный tracking —
UNSUPPORTED; ошибки микшера/backend передаются вызывающему.

`swf_sound_output_identity` воспроизводит случай retired-but-queued, проверяет
точную рациональную границу вместо конца целого блока, retained write failure
с точным retry, подавление без бюджета и сохранение владельца при отказе запроса
очереди после уничтожения VM.

## v0.796: владение при stop и clear

[`fvm_swf_sound_output_stop_id`](../include/flashvm/swf_sound_output.h#L122) применяет immediate/DECLICK-политику будущего
микширования и снимает регистрацию NoMultiple этого ID. Отсутствующий ID — успех,
неверный ID/null/reentry — INVALID_ARGUMENT, выключенный tracking — UNSUPPORTED.
Аллокаций, callbacks и VM нет. Принятый и pending PCM неизменяем: команда не
вынимает уже поставленные в очередь сэмплы этого ID. Новый NoMultiple разрешён
после команды, даже пока звучит прежний PCM/release-хвост. Сериализуйте выход/
микшер внешним mutex.

Общие stop и stop_release сбрасывают регистрации только ПОСЛЕ подтверждённого
backend clear. Ошибка pause/clear сохраняет ID, старые голоса и pending PCM;
успешная pause остаётся видимой. Успешный clear отменяет ID даже при последующем
отказе записи release. Такой retained release анонимен; новые голоса начинаются
после точного числа его pending кадров, без повторного микширования при retry.
`swf_sound_output_identity_stop` проверяет эти отказы, явный повторный старт,
отсутствующие/неверные ID и неизменность уже принятых PCM-байтов.

## v0.797: планирование событий в desktop

Desktop включает фиксированный учёт ID до запуска worker. Owner-проверка
NoMultiple и окончательная передача готового голоса используют FIFO-часы выхода;
decode остаётся вне mutex. Stop-by-ID идёт через tracked-управление выхода,
StopSounds сохраняет политику подтверждённого clear. Это поведение корневого
событийного звука; stream-only путь прежний, сочетание root stream и StartSound
по-прежнему не поддерживается.

Устройство/выход/микшер сериализуются прежним native mutex; VM и managed-указатели
не попадают в worker. Память таблицы ID/выхода отделена от EVENT_BYTES источников/
микшера и видна в storage_info. Исправлено преждевременное снятие NoMultiple при
software retirement, но не добавлены аппаратная слышимость, авторские sub-frame
моменты или эталонные A/V-часы Flash.

## v0.798: регрессия через реальные SDL-кадры владельца

`flashvm_frontend_queued_identity` удерживает в настоящей приостановленной
SDL-очереди голос из семи исходных кадров после освобождения слота микшера.
Второй реальный корневой кадр доставляет NoMultiple и не должен создать голос.
Следующие кадры выполняют stop-by-ID/restart, AVM1 StopSounds и новый NoMultiple;
между доставками запускается GC. После возобновления worker FIFO-часы завершают
регистрацию ID. Пять реальных действий AVM1 проверяют счётчики интерпретатора/
нативного JIT. Короткий голос подготавливается под mutex при приостановленном
worker; запрос очереди идёт к настоящему SDL, без подставного backend.
Это Linux/SDL dummy-проверка владения, а не измерение физического DAC.

## v0.799: ABI C89 и повторный вход backend

`swf_sound_identity_c89` компилируется как строгий C89 и использует независимый
raw SWF с ID 7 и 65535. Оба голоса завершаются в одном блоке, но сохраняют
NoMultiple до проигрывания; отмена одного ID сохраняет другой. Проверены новые
C-сигнатуры/память и точная восьмикадровая выходная длительность после teardown VM.
Backend queued намеренно повторно вызывает tracking/storage/adoption/stop-ID с
живыми владельцами: каждый возвращает INVALID_ARGUMENT без изменения выхода или
владения. Внешняя сериализация обязательна; защита от reentry — не mutex потоков.

## v0.800: откат аллокации и владение при отказах

`swf_sound_output_identity_allocation` изолирует единственную аллокацию таблицы
с разрешениями ноль/один. Отказ сохраняет прежнюю память выхода; одна аллокация
достаточна для включения. При запрете всех дальнейших new/new[] выполняются
передача голосов, pending write rejection/exact retry, подавление дубликатов,
запрос ID, сохранение регистрации при failed clear, clear/release/disable и
освобождение владельцев после teardown VM. `swf_sound_output_identity_exceptions`
проверяет преобразование bad_alloc/прочих исключений backend в OOM/ERROR без
потребления входящего указателя или публикации query-выхода. Storage и stop-ID
не обращаются к такому backend. Внешняя сериализация владельцев обязательна.

## v0.801: учебный C89-хост FIFO

Исполняемый [учебник swf_queued_identity](../examples/multimedia/swf_queued_identity/README.md)
подготавливает исходный SWF из семи сэмплов, уничтожает VM и показывает разницу
между освобождением голоса микшера и временем ID в явно моделируемой FIFO.
Проверяет точный восьмой выходной кадр, NoMultiple restart, один failed write/
exact retry, отмену ID и подтверждённый общий clear. Необязательный файл содержит
ровно два одинаковых принятых стереоблока по 16 кадров; независимый целочисленный
oracle проверяет каждый S16 и ошибки CLI/выхода. Детерминированной моделью владеет
хост; устройство не открывается. Владение, бюджеты и каждая строка C/заголовков
описаны отдельно.

## v0.802: скопированная диагностика границ ID

[`fvm_swf_sound_output_identity_info`](../include/flashvm/swf_sound_output.h#L99) опрашивает FIFO и копирует ID, played-позицию
epoch, последнюю исключающую конечную границу, время до неё и активность.
Требуются точный struct_size и ID 1..65535. Ошибки null/размера/reentry —
INVALID_ARGUMENT, выключенный tracking — UNSUPPORTED; статусы/исключения backend
передаются как для sound_active. Отказ сохраняет выход. Нет аллокаций, decode,
VM или managed-указателя; сериализуйте живых владельцев до возврата callback.
Истёкший ID хранит исторический end, но имеет active=0/until_end=0; отменённый/
очищенный ID имеет end=0. until_end включает queued-паузу до будущего старта:
это НЕ число оставшихся ненулевых отсчётов и не задержка DAC. Boolean-запрос
активности использует тот же проверенный путь диагностики.

`swf_sound_output_identity_info` проверяет live/expired/restart/clear поля,
промежуток queued silence и сохранение выхода при отказах. API также проверяют
C89 reentry-fixture и исполняемый учебник FIFO.

## Итоговые проверки v0.802 и границы

Один выход/микшер соответствует одному словарю SWF. Одинаковые числовые ID из
разных фильмов — один ключ; замена корня требует clear/rebuild владельца.
Прежний desktop joined root-clear освобождает старую таблицу. FIFO-позиция не
означает слышимость DAC или эталонные A/V-часы Flash.

На этом Linux-хосте прошли 89 целевых native sound/stream/codec и настоящих
C89-проверок, а также 15 тестов реального SDL-плеера с dummy-драйверами. Оба
независимых MP3 stream/three-codec event oracle выполнены с реальными действиями
интерпретатора/нативного JIT. Полное minimal-ядро ASan/UBSan прошло 15 выбранных
success/status/C89-проверок плюс отдельный успешный путь включения таблицы с
последующим запретом аллокаций. Расширенная проверка короткого/длинного same-ID
старта прошла обычный запуск и полный ASan/UBSan. LeakSanitizer отключён из-за
недоступного /proc. Внедрённые исключения/отказы аллокаций под ASan не заявляются:
обе изолированные границы выделения таблицы и исключения backend прошли обычный
запуск и UBSan изменённых voice/output-модулей с остальным обычным ядром.
ThreadSanitizer, устройства и выполнение на других платформах не заявляются.

Проверены CMake version-only refresh, детерминированные source links, сортировка
каталога и комментарии/API нового учебника. Общий multimedia comment checker
по-прежнему сообщает только о двух побайтово неизменённых baseline Windows
speech-файлах; глобальный PASS не заявляется. Все девять стадий плана открыты.
Root stream вместе с event, дочерние потоки, эталонные seek/A/V, оставшиеся кодеки
и прочие графика/текст/AS/JIT/GC/debugger остаются отдельными задачами завершения.
