# Отладка AVM1 в парном плеере

[English](STYX_RPC_DEBUG.md) · [Парный плеер](STYX_RPC_PLAYER.ru.md) · [API отладчика VM](DEBUG_API.ru.md) · [Адаптер плеера](../src/styxrpc/playback_debug.c)

Штатный плеер может остановиться внутри интерпретируемого действия шкалы
AVM1. Управляющая программа использует существующее подключение Styx,
например `/flash/.state` в DisVM. Команда `debug` приостанавливает такты,
подключает отладчик и выбирает интерпретатор до замены фильма. Встраивающее
приложение может использовать свой колбэк отладчика.

На каждую команду открывайте новый fid для записи со смещения ноль.
Перевод строки в конце необязателен. Отклонённая команда даёт ошибку записи.

| Команда | Действие |
| --- | --- |
| `debug` | Поставить фильм на паузу и установить обработчик точки останова. |
| `break <offset> [function]` | Поставить точку на десятичном смещении в байтах внутри функции AVM1. Без имени выбирается верхний уровень. |
| `clear <offset> [function]` | Убрать указанную точку. |
| `start` | Запустить приостановленную шкалу до ближайшей сработавшей точки. |
| `continue <stop>` | Продолжить текущую активацию по номеру остановки. |
| `step <stop>` | Продолжить с текущей остановки и снова остановиться на границе следующего действия интерпретатора. |

Для нового фильма с действиями в первом кадре запишите `debug`, `break 0`
и `start`. Для каждого снимка открывайте новый fid на чтение. Дождитесь
`debug.state=stopped` и прочитайте `debug.stop`. При первой остановке в
соединении запишите `clear 0` и `step 1`. Следующая остановка получит новый
номер. Запишите `continue` с этим номером, чтобы закончить кадр. Устаревший
номер отклоняется, фильм продолжает ждать. Во время остановки точки также
можно ставить и снимать. В командах допускается до 127 байтов имени функции
без перевода строки и NUL. Одноимённые функции используют общие точки.

При остановке `state=debug`, а поля `debug.*` содержат номер, смещение,
исходник, строку и до четырёх внутренних кадров стека со смещением,
[движком](../include/flashvm/crash.h#L29) и именем. Без карты исходников поле
исходника пустое, номер строки равен нулю. В отображаемых подписях
непечатные и не-ASCII байты заменяются на `?`. Между остановками
`debug.state=armed` означает, что отладчик подключён.

При настоящей остановке вызов шкалы остаётся на стеке VM. Плеер обслуживает
`.state`, отказывая в остальном файловом вводе-выводе, загрузке и перезапуске.
При разрыве соединения выполнение прерывается. Интерфейс останавливает
выполнение шкалы. Колбэк внутри обычного запроса Styx продолжает выполняться.
Загрузка или перезапуск между остановками заменяют контекст вместе с точками
останова. Номера остановок в одном соединении не повторяются.

После настройки libstyxrpc с исполняемым файлом плеера и сборкой DisVM
запустите тесты `styxrpc-native-debug-*`. Они проверяют положение реальной
остановки, шаг по действию, отказ устаревшего номера и операций при
остановке, продолжение SWF через локальные сокеты и TCP.
[Проверка на Limbo](../../lib/styxrpc/tests/flashvm/native_debug.b).
