# Регистры JIT — v0.352

[English reference](JIT_REGISTERS.md)

ActionPush register и StoreRegister компилируются в прямые вызовы нативных
сервисов. StoreRegister сохраняет верхний операнд на стеке. Порядок смешанных
литералов и регистров внутри Push сохраняется. Некорректные длины отвергаются
до публикации нового code handle.

Используется банк, подготовленный общим построителем activation:

| Вызов | Банк |
| --- | --- |
| Загруженная legacy-функция / Function2 с нулём регистров | Общие четыре регистра контекста |
| Загруженная Function2 с регистрами | Объявленный частный диапазон |
| Host legacy-функция | Новые четыре частных регистра |
| Host Function2 | Прежний совместимый диапазон с дополнительным слотом |
| Корневой блок загруженного SWF | Постоянный общий банк контекста |
| Корневой host-блок | Новые четыре регистра в корнях GC на каждый вход |

За пределами диапазона загруженный код получает undefined при чтении и игнорирует
запись; host-код возвращает INVALID_ARGUMENT. Пустой StoreRegister использует
прежнюю политику undefined для SWF и строгую ошибку host. Общая запись строки
вызывает [`fvm_exec_global_register`](../include/flashvm/execution.h#L607), сохраняет длину/метатаблицу и обеспечивает
владение текстом до публикации. Частные банки удерживаются activation, корневой
host-банк явно включён в GC-корни нативного входа. Code handle не хранит банк.

Function2 preload остаются обязанностью общего построителя: JIT читает готовые
this/arguments/global/параметры, не создаёт собственную модель preload. Определения
функций в байткоде пока не компилируются, но тело уже созданной Function2 может
исполняться нативно.

`jit_registers` сравнивает интерпретатор, явный и автоматический JIT в host/SWF4–8:
запись/чтение, сохранение операнда, строки, границы, пустой StoreRegister,
регистровые параметры и preload this/arguments/global. Проверяются независимость
частного банка, корневой блок и последующее чтение общей/свежей банки функцией.
Счётчики подтверждают нативный вход.

`jit_register_gc` получает новый объект из script getter, сохраняет только в
регистре, удаляет ссылку со стека и вызывает другой getter со сборкой мусора.
Проверяются legacy, частная Function2 и нативный корень. Объект не закреплён pin,
сырой указатель теста сборщик не учитывает. `jit_register_allocation` проходит
отказы памяти при частной/общей записи строки с NUL и проверяет корни/глубины/
состояние code handle. `jit_invalid` проверяет усечённый регистр и неверный StoreRegister.

ConstantPool, вызовы/определения функций, полнота остальных инструкций, реальные
другие CPU/ОС и окончательная приёмка roadmap ещё открыты.

Linux Release: все 709 AGG, 709 Cairo и 690 minimal проверок имеют успешный
результат. Промежуточные отказы запуска потребовали восстановления прав; два
Cairo и один minimal исполняемый файл оказались пустыми/повреждёнными и были
перелинкованы перед успешным повтором. Тесты не обходились. Девять целевых
heap/global ASan+UBSan проходят; stack ASan и LeakSanitizer отключены согласно
прежним ограничениям среды. В новых фикстурах также исправлены дескрипторы getter
и недопустимый регистровый параметр Function2: это ошибки подготовки теста,
отдельные от выполнения регистров. Реальные другие ОС/CPU и полная приёмка
roadmap ещё не подтверждены.
