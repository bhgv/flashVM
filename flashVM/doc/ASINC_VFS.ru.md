# Подключённая VFS в задачах AS2

[English](ASINC_VFS.md) · [Задачи AS2](ASINC_TASK.ru.md) ·
[Файловые методы](STYX_RPC_OS.ru.md) · [Парный плеер](STYX_RPC_PLAYER.ru.md)

В парном плеере AS2-функция `asinc` и задача `Async.run` могут
обращаться к `vfs` и `os`. Оба имени указывают на один объект
в контексте рабочего потока. Его текущий каталог начинается с `/`.
Смена каталога оставляет рабочий каталог фильма и других задач прежним.

`open`, `opendir`, `attr`, `mkdir`, `rm`, `cd` и `pwd` работают
с тем же пространством обычных имён, что и фильм. Файлы и каталоги
закрываются явно либо при завершении задачи. Пути разрешаются через
libstyxrpc с обычной фильтрацией служебных имён. Задача может читать и
писать файлы на другой стороне. Например:

```actionscript
asinc function firstByte(path) {
    var file = vfs.open(path);
    var bytes = file.read(1);
    var closed = file.close();
    return bytes[0];
}
```

Задача работает в отдельном системном потоке. Пока она ждёт чтение,
фильм может продолжать кадры и обслуживать запросы управления.
Одновременные RPC-вызовы могут ждать общий клиент Styx. Отмена через
`cancel()` кооперативная и может ждать завершения текущего запроса или
его тайм-аута. Парный плеер удерживает подключение до завершения задач.

Этот интерфейс охватывает обычные файлы. `load()`, именованные каналы,
публикация узлов и модулей и управление плеером остаются у фильма.
В самостоятельном контексте с одним [`fvm_async_install`](../include/flashvm/async.h#L15) подключения
к VFS у рабочих потоков нет.

В [команде парного теста](../../disVM/runtime/STYX-CHANNEL.ru.md)
укажите `--asinc-vfs`. Допустимы `--tcp` и `--jit`. Провайдер Limbo
ждёт два дополнительных кадра и добавляет верхнюю ветвь перед ответом
на чтение. Запись попадает в эту ветвь. Проверка также сверяет фильтрацию
служебных имён и отдельный cwd.
[Исходник задачи](../../lib/styxrpc/tests/flashvm/asinc-vfs_worker.as) ·
[Проверка на Limbo](../../lib/styxrpc/tests/flashvm/asinc-vfs_pair.b).
