# Подключённая VFS в задачах AS2

[English](ASINC_VFS.md) · [Задачи AS2](ASINC_TASK.ru.md) ·
[Файловые методы](STYX_RPC_OS.ru.md) · [Парный плеер](STYX_RPC_PLAYER.ru.md)

В парном плеере AS2-функция `asinc` и задача `Async.run` могут
обращаться к `vfs` и `os`. Оба имени указывают на один объект
в контексте рабочего потока. Его текущий каталог начинается с `/`.
Смена каталога оставляет рабочий каталог фильма и других задач прежним.

`open`, `opendir`, `attr`, `mkdir`, `rm`, `cd` и `pwd` работают
с тем же пространством обычных имён, что и фильм. Файлы и каталоги
закрываются явно либо при завершении задачи. Пути разрешаются через
libstyxrpc с обычной фильтрацией служебных имён. Задача может читать и
писать файлы на другой стороне. Например:

```actionscript
asinc function firstByte(path) {
    var file = vfs.open(path);
    var bytes = file.read(1);
    var closed = file.close();
    return bytes[0];
}
```

Задача работает в отдельном системном потоке. Пока она ждёт чтение,
фильм может продолжать кадры и обслуживать запросы управления.
Для `file.read(count)` и `file.write(bytes)`
[`cancel()`](ASINC_CANCEL.ru.md) отправляет
`Tflush` по тегу ожидающего запроса данных. Если отмена победила,
плеер закрывает точный fid, а задача сообщает ошибку. Парный сервер
DisVM откладывает передачи данных прерываемых провайдеров,
включая позиционные файлы с колбэком Limbo, и может обслуживать flush
и другие fid в ожидании ответа колбэка. Подтверждённый префикс записи
сохраняется, а ожидающий фрагмент мог уже изменить файл. Метаданные
и чтение каталогов используют сроки сессии. Парный плеер удерживает
подключение до завершения задач.

Если пара согласовала именованные каналы, `vfs.chan(path)` и
`os.chan(path)` открывают собственное участие задачи. `send(value)` и
`recv()` могут ждать, пока фильм продолжает кадры. `cancel()` отправляет
`Tflush` для ожидающего обмена данными и закрывает дескриптор. Если отмена совпала
со встречной операцией, другая сторона могла уже принять значение.
Задаче доступны снимки и дескрипторы именованных ячеек. Ссылки на
экспортированные переменные модулей требуют участия владельца.

Задача также может открыть опубликованный образ `.dis` на чтение и
вызвать `load()`, чтобы получить прокси в своём контексте. После закрытия
исходного дескриптора прокси продолжает вызывать методы по своему fid.
Прокси привязан к этой публикации. После её отзыва вызов возвращает ошибку,
даже если имя VFS используют снова. Штатный плеер выделяет каждой
активной задаче собственный встречный PID и шину аргументов. Задача может
вызвать контекстный метод, передать ему [локальную очередь](ASINC_LOCAL_CHANNEL.ru.md)
и работать с каналом, который вернула DisVM. Оба направления используют
парное соединение Styx. Фильм получает примитивный результат через `poll()`.

В [сессии с живой загрузкой Dis](STYX_RPC_LIVE_DIS.ru.md) `cancel()`
останавливает ожидающую загрузку образа и вызов метода во время обмена
данными. Задача закрывает точный fid
вызова. Контекстный код Dis может выйти из ожидания локального канала.
[`os.unload(proxy)`](STYX_RPC_UNLOAD.ru.md) освобождает прокси внутри задачи.

Загрузка дочернего SWF, публикация узлов и модулей и управление плеером
выполняются в контексте фильма.
В самостоятельном контексте с одним [`fvm_async_install`](../include/flashvm/async.h#L15) подключения
к VFS у рабочих потоков нет.

В [команде парного теста](../../disVM/runtime/STYX-CHANNEL.ru.md)
укажите `--asinc-vfs`. Допустимы `--tcp` и `--jit`. Провайдер Limbo
ждёт два дополнительных кадра и добавляет верхнюю ветвь перед ответом
на чтение. Запись попадает в эту ветвь. Проверка также сверяет фильтрацию
служебных имён и отдельный cwd.
[Исходник задачи](../../lib/styxrpc/tests/flashvm/asinc-vfs_worker.as) ·
[Проверка на Limbo](../../lib/styxrpc/tests/flashvm/asinc-vfs_pair.b).
Профиль `--cancel-vfs-read` проверяет отмену остатка после подтверждённого
префикса, пока другой файл тоже ожидает ответа.
[Сценарий Limbo](../../lib/styxrpc/tests/flashvm/cancel-vfs-read_pair.b)
проверяет, что поздний ответ отклоняется, а новое открытие того же файла
может прочитать данные. Затем пара завершает работу с ещё одним чтением
в ожидании. Профиль `--cancel-vfs-write` проверяет короткое подтверждение
записи, отмену остатка, независимое чтение, новое открытие и разрыв
с ожидающей записью. Для других режимов добавьте `--jit` или `--tcp`.
[Проверка записи](../../lib/styxrpc/tests/flashvm/cancel-vfs-write_pair.b)
Профиль `--asinc-chan` проверяет эхо, отмену посылки и приёма без пары,
удаление точных имён и разрыв с ожидающей задачей. Для пары FlashVM
запустите `ide/tests/check_flash_peers.py --asinc-only`. Параметры
`--runtime` и `--limbo` добавляют сборку провайдера Dis и проверку прокси
из рабочего потока по TCP в режимах интерпретатора и JIT.
[Задача AS](../tests/styxrpc/peer-asinc-load-worker.as) закрывает исходный
дескриптор перед вызовом `next`.
[Фильм](../tests/styxrpc/peer-asinc-load-caller.as) проверяет ответ `42`
и удалённый отказ во второй задаче.
[Задача с контекстным вызовом](../tests/styxrpc/peer-asinc-scope-worker.as)
передаёт очередь в [экспорт Limbo](../../lib/styxrpc/tests/flashvm/asinc-scope_owner.b),
читает и закрывает возвращённый канал Dis. Фильм запускает два таких
вызова параллельно и проверяет оба ответа.
