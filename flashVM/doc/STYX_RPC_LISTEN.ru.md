# rpc.listen

[English](STYX_RPC_LISTEN.md) · [Подключение через newchan](STYX_RPC_NEWCHAN.ru.md) · [Реализация](../src/styxrpc/session_channel.c)

`rpc.listen("/.rpc")` возвращает объект обмена приложения, опубликованного
парным плеером FlashVM. Укажите точное имя `.rpc` с начальной косой чертой
или без неё. Плеер регистрирует обмен при подключении сессии Styx. Корень
скрыт при обычном просмотре каталогов и открытии файлов. Другая сторона
открывает порт через libstyxrpc, например
[из DisVM через Styxchannel](../../disVM/runtime/STYX-CHANNEL.ru.md).

Объект доступен до открытия fid другой стороной. Он заимствует нативную
очередь плеера и делит её с другими объектами, созданными в той же сессии.
Одновременно допускается один fid другой стороны. После clunk другая сторона
может открыть новый. Закрытие объекта AS освобождает его обёртку. Другая
сторона владеет своим fid. При его закрытии ожидающие сообщения удаляются.

В потоке владельца фильма [ready](STYX_RPC_CHAN_READY.ru.md) проверяет наличие
полной записи, а [recv](STYX_RPC_CHAN_RECV.ru.md) её забирает. Серверный
send ставит один снимок значения в очередь и при успехе возвращает true.
False означает, что другая сторона отсутствует или очередь заполнена.
Сохраните исходное сообщение, чтобы повторить отправку после false.
Другая сторона читает поставленные в очередь байты самостоятельно.
Серверные send и recv обращаются к локальной очереди. Поддерживаются числа,
логические значения, строки с длиной и null. Публикация живых ячеек FlashVM
остаётся следующим этапом.

[Сценарий AS для проверки](../../lib/styxrpc/tests/flashvm/mixed_pair.as)
работает в обработчике кадра и удерживает принятое значение до постановки
ответа в очередь. Порядок сборки и запуска обоих исходников приведён в
[проверке пары](../../disVM/runtime/STYX-CHANNEL.ru.md#проверка).
