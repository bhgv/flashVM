# Парная работа FlashVM и DisVM

[English](STYX_RPC_MODULES.md) · [Сценарий Styx RPC](STYX_RPC.ru.md) · [Обычные файлы](STYX_RPC_FILESYSTEM.ru.md) · [Запуск штатного парного плеера](STYX_RPC_PLAYER.ru.md)

## Файловая система и загрузка модуля DisVM

В свежем контексте FlashVM [смонтируйте подключение Styx](STYX_RPC_FILESYSTEM_MOUNT.ru.md) к DisVM в `/`, затем установите `fs`. Абсолютные и относительные пути сценария разрешаются от корня DisVM. Ошибка поиска возвращается сценарию. Корень действует до уничтожения контекста. Файловые каналы используют то же пространство. Обычный просмотр убирает `.prog` до разбивки списка на страницы и отклоняет пути с этим компонентом. Хост по-прежнему может привязать явно выданную типизированную ячейку через [API внешних переменных](STYX_RPC_INT_VARIABLE_BIND.ru.md).

Опишите нужные импорты компилированными сигнатурами и схемами Dis-модуля. [Нативный загрузчик](STYX_RPC_MODULE_LOAD.ru.md) возвращает готовый объект ActionScript. Можно также [установить функцию загрузки](STYX_RPC_MODULE_LOADER_INSTALL.ru.md) с каталогом известных интерфейсов. Например, с объявленным у хоста методом `int next(int)` на указанном удалённом пути этот вызов исполняет функцию в DisVM.

```actionscript
var dis = loadDis("/mounted/limbo.dis");
trace(dis.next(41)); // 42 с тестовым модулем
```

Входы модуля становятся обычными методами объекта ActionScript. До создания объекта SDK проверяет компилированный контракт через удерживаемый каталог. Каждый вызов использует существующий проверяемый профиль Styx/UniBus. Объект владеет своими описателями, а сессию и встречную канальную шину предоставляет хост.

## Публикация живого объекта Flash

1. Создайте объект ActionScript и выберите публичные имена его методов и переменных окружения. Для каждого метода задайте компилированную сигнатуру и профиль скалярного вызова, управляемых значений, позиционного графа или фабрики каналов.
2. Передайте объект и описатели в [конструктор образа](STYX_RPC_OBJECT_IMAGE_CREATE.ru.md). Он копирует объявления и удерживает объект. Каждый вход вызывает текущий метод с исходным `this`. В одном модуле доступно до восьми функций и восьми явно опубликованных знаковых целых свойств в `.var`.
3. Опубликуйте [образ модуля](STYX_RPC_OBJECT_IMAGE_MODULE.ru.md) через дерево модулей SDK. DisVM монтирует сессию и пользуется обычным типизированным `load` Limbo для `mounted/<имя>.dis` под точкой монтирования. Закройте сервер перед [освобождением образа](STYX_RPC_OBJECT_IMAGE_DESTROY.ru.md).

Образ выглядит как каталог уже загруженного модуля. В нём находятся `.interface`, файлы функций и опубликованные переменные окружения. Отдельно устанавливаемый C SDK собирает такой же образ из колбэков любой программы. См. [контракт C-модуля](https://github.com/bhgv/flashVM/blob/master/lib/styxrpc/reference/module_create.ru.md) и [исполняемую проверку на Limbo](https://github.com/bhgv/flashVM/blob/master/lib/styxrpc/tests/flashvm/object_image_client.b).

## Загрузка и управление SWF

Хост создаёт [владельца плеера](STYX_RPC_PLAYBACK_CREATE.ru.md) и публикует [дерево управления](STYX_RPC_PLAYBACK_CONTROL.ru.md) отдельно или рядом с модулями в том же корне. Стартовый фильм и все последующие загружаются через один файл.

| Файл | Операция | Контракт |
| --- | --- | --- |
| `.upload` | Запись | Откройте новый fid на запись. Передайте число байтов SWF беззнаковым четырёхбайтовым числом в порядке big-endian, затем байты SWF со смежными смещениями. Последняя запись принимает проверенный фильм в состоянии `ready`. |
| `.state` | Запись | Одна команда на открытие со смещения ноль. Допустимы `start`, `pause`, `restart` и `debug` с необязательным LF в конце. |
| `.state` | Чтение | Снимок строк `ключ=значение`. Все чтения с одного fid используют один снимок. Для новых измерений откройте файл снова. |

Одновременно открывается один fid загрузки. Закрытие незавершённой записи отбрасывает её. После неверной загрузки прежний фильм остаётся доступен. `start` и `restart` сразу выполняют первый кадр, а хост планирует [следующие такты](STYX_RPC_PLAYBACK_TICK.ru.md) в потоке владельца. `pause` приостанавливает такты. `restart` создаёт свежий контекст из сохранённого SWF и восстанавливает парный корень, если он настроен. `debug` приостанавливает фильм в режиме интерпретатора и вызывает функцию подключения отладчика, если она задана. Приложение управляет временем жизни отладчика и [освобождает плеер](STYX_RPC_PLAYBACK_DESTROY.ru.md) после завершения сервера.

Снимок содержит состояние, последний результат, завершённые такты, размер SWF и строк в байтах, счётчики GC, интерпретатора и JIT. На Linux он также содержит резидентную память, число потоков процесса и загрузку до 48 системных потоков по двум снимкам. В число потоков процесса входят хост и транспорт. Для процента загрузки нужен предыдущий снимок. Процент для потока владельца доступен при наличии часов CPU для потоков POSIX. Хост может дописать статистику приложения.

Мост предоставляет встраиваемый плеер. Приложение задаёт тактовый цикл, подключает отладчик и может устанавливать свои привязки в каждом новом контексте. У настольного плеера свой путь запуска. При исключительном корне отключён старый запуск потоков сценария, поскольку он создаёт независимое файловое пространство.

## Загрузка других SWF из ActionScript

[Встраиваемый плеер](STYX_RPC_PLAYBACK_CREATE.ru.md) автоматически подключает загрузку фильмов AVM1, если в описателе передана подключённая сессия Dis. В загруженном фильме создайте клип и откройте опубликованный в VFS файл.

```actionscript
var slot = _root.createEmptyMovieClip("slot", 1);
slot.loadMovie("/movies/chapter/child.swf");
```

Тот же мост обслуживает глобальную функцию `loadMovie(url, target)`, команду AVM1 `GetURL2` для загрузки в клип и `loadMovieNum(url, 0)`. В загрузке стартового SWF имя файла отсутствует, поэтому относительный путь из него отсчитывается от корня сессии. Для загруженного дочернего фильма сохраняется его канонический путь. При запросе `../leaf.swf` из `/movies/chapter/child.swf` плеер открывает `/movies/leaf.swf`. Начальная косая черта всегда обозначает корень той же VFS. Имена передаются буквальными байтами UTF-8. Схемы URL, запросы и фрагменты, выход за корень и служебный компонент `.prog` отклоняются.

Загрузка фиксирует клип назначения и источник во время кадра. Между кадрами владелец читает весь SWF через один открытый fid Styx и заменяет содержимое клипа после проверки. Загруженный клип может выполнить первый кадр на следующем такте. В очередь помещается до 16 запросов за кадр. Для одного файла действует меньший из лимита загрузки плеера и общего предела SWF. Отсутствующий, повреждённый или слишком большой файл оставляет клип в прежнем состоянии и отражается в `.state` в полях `movie_load_errors` и `last_movie_result`. Успешная замена увеличивает `movies_loaded`. Загрузка нового фильма или перезапуск сбрасывает эти счётчики. Все данные для загрузки берутся из подключённой VFS.

Этот профиль покрывает загрузку поддерживаемых SWF в клипы AVM1 и на нулевой уровень. Уровни выше нуля, методы HTTP кроме принимаемого обозначения GET, загрузка переменных и события MovieClipLoader в этот интерфейс не входят. Такты по-прежнему задаёт хост. Нативные проверки `playback-movies` исполняют два уровня вложенных SWF и используют настоящий локальный файл, имя которого отсутствует в подключённом дереве.

Для нативных проверок настройте тесты SDK с путём сборки DisVM и тестовым хостом FlashVM.

```sh
ctest --test-dir build/styxrpc -R 'object-image|module-load|playback' --output-on-failure
```
