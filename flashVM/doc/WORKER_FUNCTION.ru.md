# AVM1-функция в отдельном потоке

`fvm_worker_run_function(owner, config, function, &worker)` копирует функцию и
сериализуемое лексическое окружение, затем запускает отдельный OS-поток со своими
runtime, контекстом и кучей. Функция исполняется без аргументов. Исходный контекст
после успешного запуска можно уничтожить. Циклы и общие ссылки сохраняются внутри
копии; изменения захватов обратно автоматически не попадают.

Сериализация при запуске синхронная, поэтому большие захваты ещё могут задерживать
вызывающий поток. Граф ограничен4096 объектами,65536 записями и64MiB. Временная
передача кодирует каждый байт двумя UTF-8-буквами: обычный строковый вход worker
проверяет UTF-8. Это не zero-copy. Указатели исходной кучи не передаются.

Нативная корневая функция, её нативное присоединённое тело и режим live-transfer
отклоняются. Нативные/JIT-присоединения не переносятся, пользовательский реестр C
callback в получателе не устанавливается. Захваченные неподдержанные ресурсы
могут привести к отказу сериализации или восстановления. UI остаётся у владельца.

Результат только примитивный; объект из чужой кучи отклоняется. Ошибки исполнения
возвращаются через result/join. Строка живёт до уничтожения worker. В IDE следует
проверять result без блокировки ввода; после завершения сделать join и destroy.
Сохраняются лимит инструкций и кооперативная отмена существующего worker.

Это основа исполнения `asinc`, а не готовая реализация синтаксиса. Lowering
замыканий Coco/R → FIR, COW/dirty-синхронизация захватов перед/после кадров,
события изменения переменных и полный перенос IDE ещё открыты. `Async.post`
остаётся доставкой в цикл владельца. Форматы SWF/Dis64 не меняются.
