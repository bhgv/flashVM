# Каналы внутри сообщений UniBus

[English](STYX_RPC_NESTED_CHANNELS.md) · [Каналы-аргументы](STYX_RPC_CHANNEL_ARGUMENTS.ru.md) · [Живые результаты](STYX_RPC_CHANNELS.ru.md) · [C SDK](../../lib/styxrpc/reference/channel_leases.ru.md)

ActionScript может принять канал DisVM внутри типизированного сообщения. Внешний канал можно получить как результат функции DisVM или как аргумент обработчика AS. Сообщение может содержать канал, массив либо кортеж с полями-каналами. Новый ключ допускается на том же маршруте UniBus, через который пришло сообщение. Очереди остаются у DisVM.

## Приём, использование и возврат сообщения

[Проверочный модуль DisVM](../../lib/styxrpc/tests/flashvm/channel_owner.b) публикует `nested: fn(value: int): chan of array of chan of int;`. Подготовьте [импорт результата](STYX_RPC_CHANNEL_IMPORT.ru.md) и зарегистрируйте имя в AS, например `nestedRPC`. Используйте точную компилированную сигнатуру и форму результата `(c[a[c[i]]])`.

```actionscript
var inbox = nestedRPC(41);
var batch = inbox.receive();
var first = batch[0];
var number = first.receive();
inbox.send(batch);
inbox.close();
first.send(42);
first.close();
```

Проверочный модуль кладёт один канал в первые две позиции массива. Обе позиции дают один объект AS. Повторные доставки используют тот же объект, пока он открыт и достижим. Начальное значение этого канала равно 41. Позиции с каналом nil дают `null`. При отсутствии готовой операции `tryReceive()` возвращает `undefined`.

При отправке массива обратно используются допущенные ключи исходной шины. Объект канала из другого вызова отклоняется до отправки операции. Токен модуля и выдавший fid остаются действующими, пока открыта хотя бы одна обёртка результата. После закрытия внешнего канала принятый дочерний канал доступен. Закрытие дочернего канала действует на все ссылки AS на тот же объект.

## Вложенный аргумент в обработчике FlashVM

Смонтируйте в DisVM [модуль обработчика FlashVM](../../lib/styxrpc/tests/flashvm/channel_incoming.b) и передайте буферизованный канал с подходящим типом элемента. В обработчике работают те же методы `receive()` и `send()`. Транспорт проверяет принятое сообщение и допускает ключи текущей шины под исходным встречным PID. При выходе из колбэка FlashVM закрывает все заимствованные обёртки, включая дочерние каналы, полученные в последующих сообщениях. Завершённые операции видны в DisVM.

Мост учитывает до восьми разных ключей в одном вызове или аренде, включая внешний канал и принятые вложенные ключи. ActionScript поддерживает обмен каналами DisVM на одной шине. [Делегирование через привязку хоста](STYX_RPC_CHANNEL_DELEGATION.ru.md) поддерживает отдельные PID и проверенные токены модуля. Программы на C, которые управляют такими адресами, могут применять [явную политику маршрутов](../../lib/styxrpc/reference/channel_read_routed.ru.md).

Оба направления проверяются в нативном интерпретаторе и JIT DisVM. После [настройки интеграционных проверок](../../lib/styxrpc/examples/README.ru.md) выполните `ctest --test-dir build -R 'styxrpc-channel(-incoming-dis-to-flash|-flash-to-dis)' --output-on-failure`.

## Выдача вложенных каналов, принадлежащих FlashVM

Инициализатор AS может описать группу новых живых очередей для DisVM. Используйте [обычный экспорт канала](STYX_RPC_CHANNEL_EXPORT.ru.md) или [обработчик с заимствованными аргументами и каналом результата](STYX_RPC_CHANNEL_HANDLER_EXPORT.ru.md). Компилированный экспорт возвращает один внешний канал. Тип его элемента может содержать каналы, в том числе в массивах и кортежах.

Для предложения Limbo `tree: fn(seed: int): chan of array of chan of int;` задайте форму результата `(c[a[c[i]]])` и ёмкость внешней очереди в один слот. Инициализатор возвращает одно начальное сообщение:

```actionscript
function makeTree(seed) {
    var data = [2, [seed, seed + 1]];
    var sync = [0, []];
    return [data, data, null, sync];
}
```

В позиции канала `[ёмкость, элементы]` описывает новую вложенную очередь. `элементы` — плотный список начальных значений длиной до ёмкости. Каждая запись следует компилированному типу элемента. Повтор одного описателя того же типа выдаёт одну общую очередь. `null` задаёт nil. Для канала нулевой ёмкости нужен пустой список. Инициализатор внешней очереди также может вернуть `undefined` для пустого результата. Во всей группе до восьми очередей, включая внешнюю, и до восьми слотов FIFO в каждой очереди.

Очереди принадлежат модулю, который выдаёт их ключи под токеном результата на `.unibus`. Limbo может принять массив, использовать вложенные каналы и отправить массив обратно, пока действует токен. Повторяющиеся каналы и rendezvous сохраняют идентичность. Доступный дочерний канал удерживает выдавший fid после освобождения внешней ссылки. При закрытии fid реестр отзывает всю группу. C SDK создаёт и хранит буферы через [ресурс группы](../../lib/styxrpc/reference/channel_group_output.ru.md).

Нативные проверки охватывают [инициализатор с аргументом по значению](../../lib/styxrpc/tests/flashvm/channel_client.b) и [обработчик с заимствованным аргументом](../../lib/styxrpc/tests/flashvm/channel_incoming.b). После [настройки интеграционных проверок](../../lib/styxrpc/examples/README.ru.md) выполните `ctest --test-dir build -R 'channel-(incoming-)?dis-to-flash|^styxrpc-channel-group$' --output-on-failure`.

## Передача вложенных очередей FlashVM как аргументов

Используйте [конструктор локальных очередей](STYX_RPC_CHANNEL_FACTORY.ru.md) и [импорт с аргументами-каналами](STYX_RPC_CHANNEL_ARGUMENTS_IMPORT.ru.md). Для аргумента Limbo типа `chan of array of chan of int` создайте внешнюю очередь с типом элемента `"a[c[i]]"`. Для [нативной проверки](../../lib/styxrpc/tests/flashvm/channel_args_owner.b) привяжите функцию `nested` со схемой аргументов `(c[a[c[i]]]c[i]i)` и результата `(i)`.

```actionscript
var batch = newRpcChannel("a[c[i]]", 1);
var item = newRpcChannel("i", 1);
var direct = newRpcChannel("i", 1);
item.trySend(41);
batch.trySend([item, item, null, direct]);
var original = nested(batch, direct, 0);
var again = batch.tryReceive();
var updated = again[0].tryReceive();
```

Проверочный вызов возвращает 41 и ставит в очередь сообщение с теми же каналами. Первые две позиции содержат общий `item`, четвёртая содержит `direct`, а `updated` равно 42. Очередь удерживает вложенные объекты при сборке мусора, пока сообщение в ней. Каждый вызов заимствует прямые очереди и открытые дочерние очереди, достижимые из их сообщений, всего до восьми разных очередей. SDK выдаёт очереди свежий ключ области и использует его для прямого аргумента и вложения. Закрытый объект, несовместимый тип или превышение размера графа приводят к отказу до публикации.

При отзыве встречная шина отменяет ожидающие операции и отзывает все ключи. FlashVM восстанавливает оставшиеся сообщения с исходными объектами, включая сообщения, которые DisVM отправила обратно. Завершённые операции очередей сохраняются при ошибке RPC или тайм-ауте. Область допускает очереди FlashVM, захваченные перед вызовом. Для отдельно адресованных и новых каналов DisVM в сообщениях заимствованной очереди нужен отдельный маршрут делегирования.
