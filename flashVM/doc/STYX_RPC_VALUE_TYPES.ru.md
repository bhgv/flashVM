# Типы значений и время жизни объектов в мосте FlashVM–DisVM

[English](STYX_RPC_VALUE_TYPES.md) · [Подключение моста](STYX_RPC.ru.md) · [Запускаемый пример пары](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md) · [Живые переменные VFS](STYX_RPC_LIVE_VARIABLES.ru.md)

У FlashVM и DisVM собственные кучи. Типизированный вызов проверяет скомпилированную сигнатуру Limbo и позиционную схему, затем использует те же S-записи UniBus, что и SDK для C. От профиля RPC зависит, вернётся ли копия, изменение существующего объекта AS или дескриптор для следующих операций.

## Как передать данные

| Задача | Интерфейс | Время жизни и поведение |
| --- | --- | --- |
| Передать функции строки, числа, массивы, списки или кортежи | [Импорт](STYX_RPC_IMPORT_MANAGED.ru.md), [экспорт](STYX_RPC_EXPORT_MANAGED.ru.md) или [проверяемый `file.load()`](STYX_RPC_LIVE_DIS.ru.md) | Каждая сторона владеет декодированными значениями. Присваивание элемента на принимающей стороне оставляет массив отправителя прежним. Чтобы передать изменение, верните значение. |
| Разрешить функции изменить плоский аргумент `ref ADT` | [Обычные аргументы ref](STYX_RPC_REFS.ru.md) | Array в AS хранит поля ADT по порядку. После проверки ответа изменения записываются в исходный Array. |
| Передать вложенные ссылки, массивы ссылок, вернуть ссылку или гибридную таблицу | [Графовая привязка](STYX_RPC_GRAPH.ru.md), [гибридные таблицы](STYX_RPC_HYBRID.ru.md) | В пределах вызова сохраняется идентичность ссылок. При ответе можно обновлять отдельные поля. Гибридная таблица переносит строковые ключи, знаковые 64-битные числовые ключи и значения. |
| Передать пропуски через скомпилированный RPC | [`packSparse`](STYX_RPC_PACK_SPARSE.ru.md), [`unpackSparse`](STYX_RPC_UNPACK_SPARSE.ru.md) | Логическая длина и упорядоченные пары индекс–значение. В Limbo это кортеж `(int, array of (int, T))`. |
| Менять ref или таблицу и получить канал тем же вызовом | [Контекстный канальный профиль](STYX_RPC_CHANNELS.ru.md#граф-и-канал-в-одном-вызове) | Ответ связывает изменения с исходными ссылками и выдаёт отдельную аренду канала. |
| Передать разреженный Array или переносимый граф объектов | [Именованный `port.send(value)`](STYX_RPC_NAMED_SEND.ru.md), [Limbo `Styxnamed`](../../disVM/runtime/STYX-NAMED-VALUES.ru.md) | Снимок с собственными данными, пропусками, общими узлами и циклами в поддерживаемом профиле FVMG. Получатель владеет своим графом. |
| Читать и заново присваивать общее значение | [Именованный `port.send(ref slot)`](STYX_RPC_NAMED_SEND.ru.md), [пример C и Limbo](../../lib/styxrpc/examples/shared-cell/README.ru.md) | Аренда общей записываемой ячейки или собственного свойства. Чтение графа возвращает снимок. Чтобы опубликовать правку, присвойте снимок обратно либо выдайте ссылку на отдельную записываемую ячейку, например `ref rows[index]`. |
| Читать и заменять нативные значения через VFS | [Живая привязка](STYX_RPC_LIVE_VARIABLES.ru.md) | Int32, массив Int32, `big`, вектор `big`, числовые ключи гибридной таблицы, строки и именованные поля записи. Каждый запрос обращается к удерживаемому узлу владельца. |
| Обращаться к конкретному экспорту целого числа | [Привязка Int32](STYX_RPC_INT_VARIABLE_BIND.ru.md), [пересылаемая ссылка на Int32 модуля](../../disVM/runtime/STYX-MODULE-REFS.ru.md) | Живые операции чтения и записи через сессию владельца. Ссылка на экспорт модуля проверяет его идентичность и Qid. |
| Вызвать метод позже или обмениваться значениями через очередь | [Прокси загруженного модуля](STYX_RPC_LIVE_DIS.ru.md), [типизированные каналы](STYX_RPC_CHANNELS.ru.md) | Прокси удерживает загруженный образ и его глобальное состояние. Аренда канала удерживает маршрут до освобождения. Обычные данные внутри сообщения копируются по схеме. |

Функция может вернуть граф, узлы которого сохранят идентичность у вызывающей стороны. Следующий вызов использует свою таблицу идентичности. Для наблюдаемых изменений после завершения вызова используйте общую ячейку, живую привязку VFS или канал.

## Типы в схеме вызова

| Тип Limbo | Запись в схеме | Вход и результат в AS |
| --- | --- | --- |
| `int`, `byte` | `i`, `y` | Целый `Number` в пределах −2147483648…2147483647 или 0…255 соответственно. |
| `big` | `b` | Целый `Number` в точном диапазоне или десятичный `String` с длиной для полного знакового 64-битного диапазона. Тип результата описан ниже. |
| `real` | `f` | `Number` формата binary64. |
| `string` | `s` | Unicode `String` с длиной, допускает нулевой символ. Для nil используется `null`. Строка с цифрами сохраняет свой текст. |
| `array of T` | `a[T]` | Плотная индексируемая последовательность элементов типа `T` или `null` для nil. У каждого вложенного массива своя длина. |
| `list of T` | `l[T]` | Плотный Array с копиями элементов или `null` для nil. Пустой входной Array также кодируется как nil. |
| Кортеж | `(T1T2…)` | Array полей в порядке объявления, с точным числом элементов. |
| `ref ADT` | `r[T1T2…]` | Позиционный Array или `null` для nil. Допустимые позиции и правила обратной записи задаёт профиль ссылок. |
| Гибридная таблица | `h` | Таблица с отдельными пространствами строковых и числовых ключей в графовом профиле. |
| `chan of T` | `c[T]` | Живой объект канала или `null` для nil в канальном профиле с контекстом вызова. Сообщение передаётся по схеме `T`. |
| Пустой результат | Пустой список результатов `()` | `undefined`. |

Полная схема состоит из списка аргументов, `=>` и списка с одним результатом либо без него. `(a[s]a[b]) => ((a[s]a[b]))` принимает два массива и возвращает один кортеж из двух массивов. Внешние скобки справа ограничивают список из одного типа.

Типизированное преобразование FlashVM допускает до 2048 элементов на массив и глубину до шести уровней для каждого типа. Лимит закодированного кадра managed RPC составляет 64 КиБ. Схема различает nil-массив, пустой массив и пропуск элемента. Пропуск в типизированном массиве приводит к ошибке преобразования. Чтение свойств при преобразовании может вызвать геттеры в потоке владельца VM. У именованного канала свои правила снимка с поддержкой разреженных данных.

Для сохранения пропусков сначала вызовите `vfs.packSparse(values)`. В схеме с элементом `T` используется кортеж `(ia[(iT)])`. Например, для строки это `(ia[(is)])`. После вызова `vfs.unpackSparse(reply)` создаёт Array с исходной логической длиной ответа и только присланными индексами. Обычные `array of T` используют плотную последовательность. [Пример с изменением индекса](../../lib/styxrpc/examples/disvm/LIVE_STAGE.ru.md#копия-списка-и-разреженного-массива).

## Передача знакового 64-битного целого

Для `b` передайте конечный целый `Number` в пределах ±9 007 199 254 740 991 либо десятичную строку ASCII для диапазона −9 223 372 036 854 775 808…9 223 372 036 854 775 807. Формат строки — `[+-]?[0-9]+`. Знак и начальные нули допустимы. Пробелы, нулевые байты внутри строки, экспонента, точка и переполнение приводят к ошибке преобразования до отправки вызова.

В точном диапазоне результат имеет тип `Number`. За его пределами результат — десятичный `String` без начальных нулей и знака плюс. Например, после эха `"-00042"` вернётся как число `-42`, а `"+09223372036854775807"` как `"9223372036854775807"`. Записывайте большие литералы в кавычках. Арифметику над ними выполняйте в DisVM с типом `big` или в C со знаковым 64-битным типом.

Правило действует для типизированных аргументов, результатов, элементов массива, кортежей, обратной записи ref и сообщений канала. Его же использует [привязка гибридной таблицы FlashVM](STYX_RPC_HYBRID_BIND.ru.md). По проводу во всех этих случаях идёт знаковое целое `big`, включая случай, когда AS передал десятичную строку. [Кодировщик C](../../lib/styxrpc/reference/value_integer.ru.md) · [Кодек FlashVM](../src/styxrpc/managed_values.c)

У именованного сообщения нет скомпилированной позиции `b`. Такой же литерал в кавычках остаётся текстом при отправке через `vfs.chan` и в общей ячейке.

## Ограничения

- В обычном профиле обратная запись поддерживает до восьми плоских аргументов ref. В графовом профиле допускается до 256 идентификаторов на вызов, до восьми непосредственных полей в Array ссылки и до восьми полей в развёрнутом разреженном обновлении. Графовый профиль проверяет ответ целиком до записи в ячейки вызывающей стороны.
- Элементы `list of T` копируются. Допустимы скаляры, строки, кортежи, плотные массивы и вложенные списки. Предел для массива или списка — 2048 элементов. На проводе непустой список состоит из записей элементов под тегом 8, nil имеет тег 9. Функции, прототипы и нативные файловые дескрипторы не входят в типизированные схемы.
- В канальном профиле `r[…]`, `h` и `c[…]` допустимы в отдельных позициях одной схемы. Поля копируемого ref не содержат каналов. Сообщения канала передают значения и допущенные вложенные каналы. Живая запись VFS состоит из полей, которые владелец опубликовал явно.
- Загрузку Dis нужно включить для сессии. При обнаружении поддерживается до восьми вызываемых экспортов на загруженный образ. На сессию допускается до 32 одновременно загружаемых или удерживаемых поколений модуля. Условия профиля, ABI и метаданных описаны в [загрузчике DisVM](../../disVM/runtime/VFS-SCALAR-LOADED-EXPORTS.ru.md) и [справке плеера](STYX_RPC_LIVE_DIS.ru.md).

Если синхронный вызов оборвался после отправки, перед повтором проверьте статус вызова и состояние приложения. Освобождайте прокси модуля через [`os.unload()`](STYX_RPC_UNLOAD.ru.md), закрывайте [типизированные каналы](STYX_RPC_CHANNELS.ru.md) и освобождайте [именованные порты и ячейки](STYX_RPC_NAMED_CHANNEL.ru.md) по завершении работы.
