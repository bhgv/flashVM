# Внутренние контейнеры FlashVM (русский)

## Замена стандартных контейнеров

Во внутренних файлах FlashVM используются собственные типы C++98 из `src/details/`:

| Ранее | Теперь | Файл |
| --- | --- | --- |
| `std::string` | `fvm_detail::string` | `src/details/string.hpp` |
| `std::vector<T>` | `fvm_detail::vector<T>` | `src/details/vector.hpp` |
| `std::map<string,T>` | `fvm_detail::map<fvm_detail::string,T>` | `src/details/hash_table.hpp` |

Это **внутренние реализации**, не часть стабильного публичного C ABI. Для встраивания и расширений используются непрозрачные [`FVM_Context`](../src/core/runtime.hpp#L239), [`FVM_Object`](../src/core/runtime.hpp#L119) и [`FVM_Value`](../include/flashvm/value.h#L24) из `include/flashvm/`.

### Строка

`fvm_detail::string` владеет байтовым буфером с завершающим NUL. Можно создавать строку из обычной C-строки либо указателя с явной длиной; поддерживаются копирование, присваивание, сравнение, `size()`, `empty()`, `data()` и `c_str()`. Копии независимы. Строки с внутренними нулевыми байтами сравниваются по всей длине; имена свойств публичного C API пока передаются как NUL-терминированные строки.

**Ограничения:** это байтовый контейнер, **не** полноценные Unicode-строки AVM1. Указатель `c_str()` действителен, пока существует и не изменена строка. Выделение памяти внутри может выбрасывать `std::bad_alloc`; на границе C ABI исключения должны преобразовываться в коды ошибок. Оптимизация коротких строк пока отсутствует.

### Хэш-таблица и вектор

Собственная хэш-таблица использует корзины для поиска и связанный список для перечисления в порядке вставки. В отличие от `std::map`, сортировки по ключу нет. Хэш строк вычисляется по всем байтам, включая внутренние NUL. Числовые ключи также хранятся в хэше. Вектор — динамически расширяемый непрерывный массив.

### Гибридная таблица и метатаблицы: фактическое состояние

Сейчас [`FVM_Object`](../src/core/runtime.hpp#L119) содержит **два контейнера**: `properties` для строковых ключей и `indexed` для беззнаковых числовых ключей. Это **пока не** единая гибридная таблица Lua (массив + хэш + очередь). Запланированы плотная массивная часть, разреженная хэш-часть и операции очереди с определённым порядком.

`FVM_Object::metatable` — ссылка на обычный объект-таблицу; копия не создаётся. Подстановка через `__index` и `__newindex` пока ограничена табличными значениями. Функциональные метаметоды, метатаблицы примитивных типов, общая диспетчеризация метаметодов и полноценные `setmetatable`/`getmetatable` ещё не реализованы. Прототипы AVM1 и метатаблицы — разные механизмы.

### Пример и тестирование

См. `tests/detail_string.cpp`: владение строками, бинарные ключи, копирование и поиск в хэше. После сборки запускайте `ctest --output-on-failure`. Примеры поддерживаемого публичного API: `examples/embedding/tables_debug/`. Расширения не должны включать внутренние заголовки.
