## Передача каналов из FlashVM в DisVM

Контекстная функция Limbo может получать живые каналы FlashVM и работать с ними, пока вызывающий ждёт ответа. FlashVM временно передаёт типизированные очереди через libstyxrpc. Встречный диспетчер Styx обслуживает операции во время ожидания владельца контекста. Диспетчер не вызывает методы ActionScript.

### Настройка хоста и вызов из ActionScript

1. Используйте одно двустороннее соединение с прямым монтированием DisVM и встречным сервером Styx. Зарегистрируйте PID вызывающего [в дереве процессов C SDK](../../lib/styxrpc/reference/program_add.ru.md).
2. Создайте [шину аргументов](../../lib/styxrpc/reference/argument_bus_create.ru.md) для этого PID и опубликуйте её ресурс как [`.prog/<pid>/.unibus`](../../lib/styxrpc/reference/program_unibus.ru.md) до запуска сервера. Удерживайте шину на этом соединении до остановки встречного сервера.
3. Установите [конструктор локальных каналов](STYX_RPC_CHANNEL_FACTORY.ru.md) и [импорт с аргументами](STYX_RPC_CHANNEL_ARGUMENTS_IMPORT.ru.md) в контексте владельца FlashVM. Используйте точную компилированную схему, подпись и PID.
4. Создайте типизированный канал, поместите в него начальные значения и передайте импортированной функции. Например, для импорта `exchange` с формой `fn(port: chan of int): int`:

```actionscript
var port = newRpcChannel("i", 1);
port.trySend(41);
var observed = exchange(port);
var reply = port.tryReceive();
```

Функция может принять значение из `port` и отправить ответ в ту же очередь до возврата. Limbo также использует обычный `alt` с выданными каналами. Ссылки на каналы могут находиться в массивах и кортежах. Повторная ссылка получает тот же ключ и ту же очередь. Значение AS `null` обозначает nil-канал.

### Срок жизни и ошибки

SDK сверяет контекстное предложение, PID и ключи, затем активирует шину непосредственно перед первой записью. При завершении, истечении срока или ошибке SDK отзывает поколение и снимает незавершённые встречные операции. Изменения очереди от завершённых операций доступны в AS. При удалённом исключении или неопределённом исходе отправка либо приём уже могли состояться. Канал, отдельно возвращённый DisVM, может продолжить работу по своей аренде результата.

Один вызов допускает до восьми разных очередей. В каждой локальной очереди от нуля до восьми слотов. Нулевая ёмкость позволяет синхронизировать две операции DisVM во время вызова. Очереди аргументов FlashVM передают копируемые значения и [вложенные каналы той же области вызова](STYX_RPC_NESTED_CHANNELS.ru.md).

## Передача каналов из DisVM во FlashVM

1. На владельце FlashVM определите функцию AS и подготовьте точное компилированное предложение Limbo со схемой через [привязку обработчика](STYX_RPC_CHANNEL_HANDLER.ru.md). Например, тело функции AS `relay(p)` может быть `return p.receive();`.
2. Создайте [хостовый модуль обработчиков C](../../lib/styxrpc/reference/channel_handlers_create.ru.md). Смонтируйте встречный клиент Styx в той же двунаправленной сессии. Обслуживайте прямое дерево в отдельном диспетчере. На владельце FlashVM [выполняйте колбэки](../../lib/styxrpc/reference/channel_handlers_step.ru.md). Диспетчер подтверждает полную запись и обслуживает опрос, пока колбэк AS работает со встречной шиной.
3. В нативной DisVM смонтируйте прямое дерево через `--styx-mount-fd FD --at /rpc` и загрузите `load Incoming "/rpc/mounted/flash-incoming.dis"` с [компилированным объявлением модуля](../../lib/styxrpc/tests/flashvm/channel_incoming.m). Для канала нулевой ёмкости запустите второй процесс Dis для отправки значения, затем вызовите `api->relay(port)`.
4. При отключении освободите сервер и [остановите очередь колбэков](../../lib/styxrpc/reference/channel_handlers_stop.ru.md). После завершения обоих потоков уничтожьте модуль и освободите встречный клиент.

AS использует [те же методы каналов](STYX_RPC_CHANNELS.ru.md). Повторные ссылки на канал в массивах и кортежах по значению используют один объект внутри колбэка. Nil становится `null`. Сохранённая ссылка AS закрывается при возврате из колбэка или исключении. Следующий вызов с тем же каналом Limbo получает новый объект. Закрытие заимствованного объекта действует на все его алиасы и оставляет канал DisVM открытым.

Входящая привязка допускает до восьми разных ключей, включая [дочерние каналы, принятые на той же шине](STYX_RPC_NESTED_CHANNELS.ru.md). Завершённая отправка или приём видны даже при последующей ошибке колбэка. При истечении срока выполняется clunk операции и возникает исключение AS.

### Возврат отдельного живого канала в том же вызове

Для предложения `make: fn(port: chan of int): chan of int;` используйте [привязку результата](STYX_RPC_CHANNEL_HANDLER_EXPORT.ru.md) и опубликуйте её через [модуль SDK с реестром аренд](../../lib/styxrpc/reference/channel_handlers_create_with_results.ru.md). При ёмкости результата в один слот колбэк может заполнить FIFO полученным значением.

```actionscript
function makeResult(port) {
    return port.receive();
}
```

```limbo
port := chan[1] of int;
port <-= 41;
result := api->make(port);
initial := <-result;
```

В `initial` будет 41. После возврата `make` вызывающий использует `result` как обычный канал. Временный аргумент ActionScript и новый результат имеют независимые сроки жизни. Каждый fid результата выдаёт отдельный токен на `.unibus` модуля. Диспетчер отзывает операции при clunk. Для пустого rendezvous задайте нулевую ёмкость и верните `undefined`.

Запустите две нативные проверки из сборки с установленным SDK командой `ctest --test-dir build -R channel-incoming --output-on-failure`. Они работают в режимах интерпретатора и JIT DisVM и проверяют FIFO, строки с NUL, алиасы, nil, rendezvous, тайм-аут, явное закрытие, отзыв полномочий и независимость аренд результата.
