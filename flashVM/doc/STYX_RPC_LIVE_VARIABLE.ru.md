# vfs.liveVariable

[English](STYX_RPC_LIVE_VARIABLE.md) · [Живые переменные](STYX_RPC_LIVE_VARIABLES.ru.md) · [Типы моста](STYX_RPC_VALUE_TYPES.ru.md) · [Реализация](../src/styxrpc/session_live_values.c#L310)

## Синтаксис

```actionscript
vfs.liveVariable(path:String [, writable:Boolean]):Object
```


## Параметры

| Имя | Назначение |
| --- | --- |
| `path` | Путь в смонтированной сессии. Один начальный слеш допустим. Используйте имена узлов и опубликованные компоненты `.var`, `.prog`, если они есть. |
| `writable` | Верхняя граница прав. По умолчанию `false`, привязка доступна для чтения. `true` разрешает запись в пределах прав публикации. Служебные файлы коллекции сохраняют свои права. |

## Результат

Объект в контексте владельца с методами `get`, `set`, `length`, `field` и `close`. Допустимые операции зависят от объявленного типа узла. Объект владеет одним неоткрытым fid и запоминает Qid.path публикации. Каждая операция сверяет путь и обращается через исходный fid. Сессия должна оставаться открытой до конца работы. Освободите прокси после использования.

## Ошибки и доступность

Доступно через смонтированную сессию `vfs` фильма или задания `asinc` в сборке с поддержкой Styx RPC. Неверный путь или флаг другого типа приводят к ошибке аргумента. Неизвестная проекция, отсутствующая публикация или недоступный режим приводят к исключению. Обход и сверка типа синхронны, в `asinc` ожидание прерывается. При отказе прокси не выдаётся.

## Пример

```actionscript
// Удерживаем точный массив Int32 владельца с правом чтения.
var scores = vfs.liveVariable("/live/.var/numbers");
var firstScore = scores.get(0);
var closed = scores.close();
```
