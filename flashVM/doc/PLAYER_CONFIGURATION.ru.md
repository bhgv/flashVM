# Структурированные параметры плеера — v0.672

[English](PLAYER_CONFIGURATION.md).

Приложение C89/C++98 может линковать необязательную статическую цель CMake
`flashvm_player_host` и вызывать [fvm_desktop_run](../frontend/common/player.h#L30) без сборки командной строки.
Цель содержит общий планировщик, интеграцию VM/сцены, ввод, вывод и аудиоадаптер;
FlashVM и выбранный SDL SDK подключаются транзитивно. Консольный
[fvm_desktop_main](../frontend/common/player.h#L37) разбирает аргументы и вызывает тот же runner. Это внутренний
контракт frontend, а не новый стабильный ABI VM или установленный SDK.

## API и владение

Подключите frontend/common/player.h; цель экспортирует каталог заголовка.
[fvm_desktop_options_init](../frontend/common/options.h#L45) принимает обязательную структуру [FVM_DesktopOptions](../frontend/common/options.h#L27),
возвращает 1 при успехе, 0 для null. По умолчанию: автоматический режим,
качество HIGH, авторская частота на 100 процентов, пустой плейлист, нулевые
ограничения и флаги. Выделения памяти и запуска устройств нет. Перед run
задайте хотя бы один файл.

[fvm_desktop_options_validate](../frontend/common/options.h#L48) возвращает 1 при корректных параметрах, иначе 0.
Необязательный error получает null при успехе или статический текст ошибки;
освобождать его нельзя. Проверка не меняет структуру, не открывает файлы,
не запускает SDL/VM, не выделяет память, не печатает и не меняет локаль процесса.

Проверяются режим исполнения, качество, конечные значения частоты, логические
флаги, конфликт once/frames, арифметика размера плейлиста и все непустые пути.
FPS равен нулю (авторская частота) либо 0.1..1000; percent — 0.1..10000 и
обязан оставаться 100 при явном FPS. Недопустимые enum и флаги кроме 0/1
отклоняются. Массив должен действительно содержать доступное число элементов:
C не позволяет проверить произвольный адрес или узнать размер выделенной памяти.

[fvm_desktop_run](../frontend/common/player.h#L30) возвращает [FVM_DESKTOP_EXIT_ARGUMENT](../frontend/common/player.h#L8) (2) до открытия первого
файла при некорректной конфигурации. Скалярные настройки копируются, массив и
строки путей с завершающим NUL заимствуются до синхронного возврата: сохраняйте
их доступными и неизменными. Пустой/null последующий путь отклоняет весь
плейлист до запуска. Успех или закрытие пользователем возвращает
[FVM_DESKTOP_EXIT_OK](../frontend/common/player.h#L6) (0); ошибка файла, VM или устройства —
[FVM_DESKTOP_EXIT_PLAYBACK](../frontend/common/player.h#L7) (1). Необязательный error получает null при успехе,
подробный статический текст валидации или общее сообщение ошибки исполнения.
Текущие ошибки воспроизведения, trace и статистика используют стандартные
потоки: интерфейс обратного вызова диагностики пока не добавлен.

Вызов выполняется на основном UI/VM-потоке. Параллельные и рекурсивные запуски
не поддерживаются. Временные VM, корни GC и окно принадлежат runner и
освобождаются до возврата; управляемые объекты наружу не выдаются.
Окончательное завершение сеанса SDL принадлежит приложению:
[владение SDL](PLAYER_HOST_OWNERSHIP.ru.md). Это синхронный проигрыватель,
не виджет, пошаговый tick API или маршрутизатор событий чужих окон.
Несколько фильмов проигрываются по авторскому числу кадров, если frames не
задан явно. Закрытие/Escape завершает весь плейлист. Ошибка файла/устройства
останавливает текущий фильм; уже завершённые фильмы не откатываются.

## Сборка и пример

Включите FVM_BUILD_DESKTOP_FRONTEND и FVM_BUILD_EXAMPLES, графический профиль
DEFS и целевой SDL SDK версии 2.0.9+. Настройка зависимостей и toolchain описана
в [руководстве сборки](DESKTOP_FRONTEND.ru.md). Для каждой ОС/CPU нужны отдельный
каталог и соответствующий целевой SDL; инструменты сборки запускаются на хосте.
Кросс-линковка не проверяет работу программы на целевой платформе.

```sh
cmake -S flashVM -B build-player -DFVM_BUILD_DESKTOP_FRONTEND=ON -DFVM_BUILD_EXAMPLES=ON -DFVM_DEFS_FILE="$PWD/flashVM/cmake/profiles/player-jit.defs" -DSDL2_DIR=/path/to/native-sdl/lib/cmake/SDL2
cmake --build build-player --target flashvm_player_host flashvm_example_configured_host --parallel
SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software ./build-player/frontend/flashvm_example_configured_host flashVM/examples/player/muted_stream/muted-stream.swf
ctest --test-dir build-player -R 'frontend_configuration|frontend_build_info|example_configured_host' --output-on-failure
```

Добавленная в ту же сборку программа линкует flashvm_player_host, не компилируя
OS main.c и не вызывая CLI-парсер. Сгенерированные метаданные версии остаются
в каталоге соответствующей целевой сборки. Android сохраняет SDLActivity и
линкует PIC-вариант библиотеки; отдельный desktop-пример для Android исключён.

[Построчно пояснённый C89-пример](../examples/player/configured_host/README.ru.md)
выполняет два muted interpreter tick через структуру. C89-регрессия проверяет
семейства ошибок и неизменность входа. C++98-регрессия линкует C-интерфейсы и
отклоняет null во втором пути до попытки открыть первый несуществующий файл
или устройство. Dummy-rendering проверяет протокол хоста, не физическое
видео/аудио и не полную приёмку платформ.

## Проверки v0.672

На Linux x86-64 прошли 65 выбранных проверок: 52 frontend/player/capture,
метаданных и примеров, ещё 13 — сцены, звука, таймеров и GC. Использованы
SDL 2.30.12, dummy video/software rendering; аудиомост SDL отключён. Новый
пример действительно загрузил SWF и выполнил два tick. Это выбранные регрессии,
а не полный набор тестов проекта.

Полные плееры и новый C89-пример также слинкованы для ARM64 Linux (musl),
RISC-V64 Linux (musl) и Windows x86-64 (GNU), с отдельными статическими SDL SDK
и существующим адаптированным для sandbox Zig 0.13. Проверены типы ELF/PE и
архитектуры. Целевые программы не запускались; штатный SDK, физические устройства,
macOS и Android этим не сертифицированы. Все девять этапов остаются открытыми.
