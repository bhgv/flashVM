# vfs.rmnode

[English](STYX_RPC_RMNODE.md) · [Публикация](STYX_RPC_NEWNODE.ru.md) · [Штатная сессия](STYX_RPC_DEFAULT.ru.md) · [SDK на C](../../lib/styxrpc/reference/module_slot_remove_node.ru.md) · [Реализация](../src/styxrpc/player_services.c#L189)

```actionscript
removed = vfs.rmnode(path)
```

Отозвать файл с колбэком, опубликованный текущим фильмом через
[`vfs.newnode`](STYX_RPC_NEWNODE.ru.md). В парном плеере `os.rmnode`
работает с той же публикацией. `path` — имя в UTF-8 от корня экспорта
фильма с необязательной начальной косой чертой. Применяются правила
пути публикации. Допустимо до 1024 байтов без учёта начальной косой
черты. Текущий каталог не влияет на путь.

Результат `true` означает, что файл отозван. Существующие fid этого
файла больше не принимают запросы данных и метаданных. Опустевшие
каталоги, созданные для файла, удаляются. Остальные файлы и непустые
каталоги сохраняют идентификаторы. Повторная публикация получает
новый идентификатор. Для доступа к ней откройте файл заново.
После изменения дерева обход открытого каталога может потребовать
повторного открытия.

Вызов возвращает `false` для отсутствующего файла, каталога, служебного
пути или попытки из работающего колбэка. Отсутствующий аргумент,
неверный тип, пустая или слишком длинная строка дают ошибку.
Встроенный нулевой байт также недопустим. Вызывайте из потока-владельца активного фильма
в подключённом парном плеере. Отзыв выполняется локально и синхронно.
Опубликованная функция освобождается. Для обычной VFS другой стороны
служит [`vfs.rm`](STYX_VFS_RM.ru.md).

```actionscript
if (vfs.rmnode("/app/value")) {
    vfs.newnode("/app/value", "r", readNewValue);
}
```

Добавьте `--withdraw` к [парной проверке](../../disVM/runtime/STYX-CHANNEL.ru.md#проверка).
[SWF на AS](../../lib/styxrpc/tests/flashvm/withdraw_pair.as) отзывает
файл, пока [клиент на Limbo](../../lib/styxrpc/tests/flashvm/withdraw_pair.b)
держит открытыми его и соседний файл. Замена доступна клиенту после
нового открытия.
