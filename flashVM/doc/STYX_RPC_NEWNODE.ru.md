# rpc.newnode

[English](STYX_RPC_NEWNODE.md) · [Штатная сессия](STYX_RPC_DEFAULT.ru.md) · [Реализация](../src/styxrpc/session_nodes.cpp)

`rpc.newnode(path, permissions, callback)` публикует файл с колбэком в
VFS действующего фильма. Путь разрешается от корня парной сессии,
независимо от cwd. Отсутствующие родительские каталоги создаются
вместе с файлом. Допустимы неповторяющиеся буквы `r`, `w`, `x`
в строке прав. Коллизии, пустые компоненты, `.`, `..` и служебные
имена отклоняются. Успех возвращает `true`.

Колбэк получает `(op, buf, len)` в потоке владельца. При `op == "r"`
он заполняет начало массива байт `buf` и возвращает число заполненных
байт. При `op == "w"` массив содержит входные байты, а возвращаемое
число подтверждает принятый префикс. `len` — длина массива в байтах.
Ноль при чтении означает EOF. Исключение или число вне диапазона
0–len даёт ошибку запроса. Бит `x` сейчас хранится в метаданных.
Формат передачи параметров для вызова `x` ещё предстоит определить.
Колбэк вызывается для каждого запроса транспорта. Его три аргумента содержат операцию, копию байтов и длину. Смещение ведётся у fid.

Пример на AS2 публикует файл, из которого одно чтение возвращает байт
`42`. Другой стороне файл доступен через обычные VFS-операции.

```actionscript
function readValue(op, buf, len) {
    if (len == 0) return 0;
    buf[0] = 42;
    return 1;
}
rpc.newnode("/app/value", "r", readValue);
```

Колбэк остаётся в контексте фильма до его смены или закрытия сессии.
Старые открытые fid отзываются одновременно с узлами. Колбэк выполняется
синхронно с запросом Styx. [Нативный тест через Styx](../tests/styxrpc/node-files.c)
проверяет буферы чтения и записи, запрет записи и отзыв открытого fid.
