# vfs.newnode

[English](STYX_RPC_NEWNODE.md) · [Штатная сессия](STYX_RPC_DEFAULT.ru.md) · [Реализация](../src/styxrpc/session_nodes.cpp#L158)

`vfs.newnode(path, permissions, callback)` публикует файл с колбэком в
VFS действующего фильма. Путь разрешается от корня парной сессии,
независимо от cwd. Отсутствующие родительские каталоги создаются
вместе с файлом. Допустимы неповторяющиеся буквы `r`, `w`, `x`
в строке прав. Коллизии, пустые компоненты, `.`, `..` и служебные
имена отклоняются. Успех возвращает `true`.

Колбэк получает `(op, buf, len)` в потоке владельца. При `op == "r"`
он заполняет начало массива байт `buf` и возвращает число заполненных
байт. При `op == "w"` массив содержит входные байты, а возвращаемое
число подтверждает принятый префикс. При `op == "x"` массив содержит
входные байты. Запишите результат в начало массива и верните его длину.
Право `x` действует независимо от `r` и `w`. Колбэк запускается один раз
после приёма полного запроса. Вызов доступен из [Limbo](../../disVM/runtime/STYX-EXEC.ru.md)
и [C](../../lib/styxrpc/reference/node_exec.ru.md) через действующую сессию.

`len` — длина входа и ёмкость массива в байтах. Ноль при чтении означает
EOF. Ноль при исполнении подтверждает пустой ответ. Исключение или число
вне диапазона 0–len даёт ошибку. Обычное чтение и запись вызывают колбэк
на каждый запрос транспорта. Смещение ведётся у fid.

Пример на AS2 публикует файл, из которого одно чтение возвращает байт
`42`. Другой стороне файл доступен через обычные VFS-операции.

```actionscript
function readValue(op, buf, len) {
    if (len == 0) return 0;
    buf[0] = 42;
    return 1;
}
vfs.newnode("/app/value", "r", readValue);
```

Колбэк остаётся в контексте фильма до его смены или закрытия сессии.
Старые открытые fid отзываются одновременно с узлами. Колбэк выполняется
синхронно с запросом Styx. [Нативный тест через Styx](../tests/styxrpc/node-files.c)
проверяет буферы чтения, записи и исполнения, права доступа и отзыв открытых fid.
