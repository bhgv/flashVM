# Интерфейсы оригинальных функций (v0.407)

Функция передаётся как вызываемый интерфейс оригинала, включая C callback без
кодека сериализации. Замыкание, глобальные переменные, userdata и управляемый
capture остаются в исходном контексте. Вызов исполняет существующий поток
брокера через тот же TCP-порт, что обслуживает каналы и мутексы. Пока каждый
внешний вызов открывает отдельное соединение. Сообщения содержат ID цели, процесса и
контекста источника и случайный ID запроса; несовпадающие ответы отклоняются.

Привяжите исходный контекст через [`fvm_context_set_broker`](../include/flashvm/capability.h#L58), включите
`fvm_context_function_transfer(context, 1)` и передайте функции, пока контекст
принадлежит хосту. Затем `fvm_context_function_serve(context, 1)` передаёт
бездействующий контекст исключительно потоку брокера. Хост не должен обращаться
к этой куче во время обслуживания. `fvm_context_function_serve(context, 0)`
запрещает новые вызовы и ждёт завершения активного вызова, кодирования ответа и
очистки исключения. Уничтожение контекста также ждёт вызовы и снимает корни
экспортированных функций до освобождения кучи. Userdata принадлежит хосту и
должна жить до завершения вызовов; управляемый capture удерживается функцией.

Получатель и аргументы идут одним графом с сохранением внутренних алиасов.
Обычные изменяемые объекты копируются; общей кучи нет. Вызов без явного
получателя использует исходный global. Возвращаются результаты, исключения со
строками с NUL и диагностические поля ошибок; исходное исключение очищается.
Повторная передача интерфейса сохраняет URI оригинала. Уничтожение источника
отзывает цели, остановка брокера разрывает доступ. Чужие указатели не передаются.

По умолчанию сохранено прежнее клонирование функций; новый режим включается
явно. Уже импортированные интерфейсы всегда передаются как интерфейсы. Это
вызываемый фасад: копирование свойств/prototype и прозрачность конструктора не
сертифицированы. Все вызовы одного брокера последовательны. Вложенный вызов
функции того же брокера выполняется напрямую на его потоке с сохранением графов
и защиты оригинальных куч. Предел — 32 активных вызова; превышение возвращает
[`FVM_UNSUPPORTED`](../include/flashvm/flashvm.h#L48). Блокирующие ресурсные
операции из обслуживающей функции и циклы обратных вызовов между брокерами не
образуют поддерживаемую реентерабельную модель. Таймаут сокета — две секунды;
автоповтора нет, поскольку действие могло исполниться до потери ответа.
Постоянное мультиплексированное соединение, отмена, аутентификация, шифрование и
параллельный доступ к одной VM-куче не реализованы. URI даёт право вызова;
используйте доверенную сеть.

Тесты: `function_remote` — оригинальные native/AVM1 состояния, C без кодека,
GC-корни, NUL-исключения, ошибки, диагностика, пересылка и отзыв;
`function_remote_protocol` — четыре поля маршрутизации ответа;
`function_remote_concurrent` — 100 вызовов из четырёх независимых клиентских
контекстов и очистка после остановки брокера. Все девять стадий остаются открыты.

В v0.398 отклоняются ответы OK/EXCEPTION без графа значения и ответы OK с
признаком ошибки. Проверяются также недопустимые коды результата.
`function_remote_graph` проверяет циклы, алиасы получателя/аргументов, отдельность
копий, возврат интерфейса C-функции и запрет вызова после возврата кучи хосту.

В v0.399 URI новой цели формируется до публикации и установки GC-корня.
Проверка отказов C++-выделений подтверждает отсутствие цели/корня при ошибке;
повторный экспорт удерживает один корень. Это не гарантирует откат более ранних
экспортов всего графа или отказа malloc-копии URI в публичном API. Проверка
prepared body исполняет оригинальную привязку, снимает её внутри вызова,
запускает GC с живыми capture/циклическими аргументами и подтверждает переход
следующего вызова на исходный байткод.

В v0.400 обратные вызовы внутри одного брокера переходят между обслуживаемыми
контекстами и возвращаются в уже активный исходный контекст без соединения с
собственным слушателем. Все исходные контексты должны быть переданы брокеру.
Обычные native/script барьеры и правила GC сохраняются. Счётчик глубины
освобождается при успехе, ошибке и исключении, включая кодирование графа.
Циклы между разными брокерами остаются неподдержанными; ресурсные операции не
используют этот маршрут. `function_remote_nested` проверяет разные оригинальные
кучи, A→B→A, предел рекурсии, NUL-исключение, диагностику, возврат хосту и повтор.

Пример C89 в v0.401: `examples/embedding/function_rpc/main.c`. Запустите
исполняемый файл с `serve`, скопируйте напечатанный URI и в другом процессе
выполните `call URI`. После завершения клиента введите строку в терминале
сервера: он вернёт контекст хосту и завершится. Оригинальный процесс проверяет
четыре обращения по своей userdata; клиент проверяет 42, NUL-исключение,
UNSUPPORTED и ERROR. Кодек callback, адрес нативного кода и общая userdata не
используются. `flashvm_function_independent_processes` автоматизирует обмен,
ограничивает ожидания запуска/вызова/остановки и убирает дочерние процессы.
Проверка включается для нативной сборки с сокетами, тестами, примерами и Python.
Без аргументов пример сразу выводит подсказку и завершает работу.

[Команды для процессов, независимых VM-потоков и LAN](FUNCTION_RPC_EXAMPLES.ru.md) — v0.402.

В v0.403 `fvm_context_function_revoke(context, function)` отзывает одну
каноническую цель и снимает только её GC-корень брокера. Сначала верните
контекст хосту через `function_serve(context, 0)`: обслуживаемый или активный
источник возвращает [`FVM_ERROR`](../include/flashvm/flashvm.h#L45) до чтения объекта. Нет экспорта —
[`FVM_NOT_FOUND`](../include/flashvm/flashvm.h#L49). Старые интерфейсы становятся недействительными, повторный
экспорт создаёт новый URI; другие цели и корни хоста сохраняются. Токены целей
теперь хранятся внутри записи фиксированным массивом: отзыв, отключение функций
и удаление записей при stop не выделяют строки во время снятия корней/ресурсов.
`function_remote_cleanup_allocation` запрещает все C++-выделения на этих шагах
и проверяет смешанные записи канала/функций двух исходных куч. Это не обещание
безаллокаторности пользовательских финализаторов или отката всего графа.

В v0.405 остановка после работы с мутексами освобождает постоянные контексты
клиентов без выделения строк идентификаторов: ключи nonce/context хранятся
фиксированно. Проверка удерживает два удалённых мутекса и экспорт функции,
запрещает все C++-выделения при stop, подтверждает освобождение блокировок
и сохранение корня функции до отключения источника.

В v0.406 запуск брокера перехватывает ошибки выделения в конструкторах полей
на границе C API и сохраняет явные статусы отказа. Неудачный запуск с допустимыми
аргументами возвращает пустой дескриптор; нехватка памяти — [`FVM_OUT_OF_MEMORY`](../include/flashvm/flashvm.h#L46).
Перебор проверяет конструкторы/runtime/строки, занятый порт и успешный повторный
запуск на том же порту после остановки исходного слушателя.

В v0.407 ID владельца мутекса и ID источника/запроса функции проверяются как
полные последовательности канонических строчных hex-байтов, а не префиксы C-строк.
Нулевой контекст источника функции отклоняется. Повреждённые ID не создают
клиентские кучи и не вызывают оригинал; следующие корректные сообщения работают.
Идентификаторы служат маршрутизации/сопоставлению, а не аутентификации.
