# Нативные Try/Catch/Finally — v0.372

ActionTry компилирует try, catch и finally в принадлежащие parent-handle нативные
блоки. Используется общий с With runner: стек, подготовленные регистры, выбранный
пул, исходные смещения, бюджет и Return относятся к одной внешней активации.
Неподдерживаемый вложенный Action отклоняет всю компиляцию; автоматический режим
сохраняет interpreter fallback всего тела. Поддержанный native Try не вызывает
интерпретатор AVM1.

Парсер проверяет флаги, размеры трёх тел и завершённое имя catch либо байт
регистра. Вложенные отображения входят в прежние ограничения размера/глубины и
защиту активного кода. Неявный конец блока не расходует инструкцию, явный End
учитывается. Return проходит через Try и With; finally может заменить результат
возврата или исключение.

До тела сохраняется отдельно укоренённый снимок стека. При перехвате script
исключения стек восстанавливается до очистки pending-состояния. Регистровый catch
использует private/global банк, включая копирование counted-строк и различия
host/loaded. Loaded-имя записывается обычным присваиванием с выбранным target и
лексической областью; запись сохраняется. Host-имя временно заменяет привязку в
активации, затем восстанавливает прежнюю. Корневой host catch публикует временную
управляемую активацию, в которой работают и объявления; перед finally и внешними
Actions эта область снимается.

Брошенное значение, прежняя host-привязка, Return и pending-исключение удерживаются
корнями независимо от живого стека. Во время finally pending-состояние очищено.
При нормальном завершении восстанавливаются прежнее значение исключения, флаги,
подробности ресурсной ошибки и Return. Return/исключение из finally заменяют
предыдущий исход. Это прежняя семантика интерпретатора FlashVM: ошибки статуса
вроде лимита инструкций пропускают finally; ошибка привязки catch выходит до
finally. Записи callbacks и отказы памяти не имеют транзакционного отката.

Выбор корневого JIT-пути теперь целиком внутри обработчика отказов памяти.
Раньше создание пустого ключа breakpoint могло выбросить `std::bad_alloc` до
защитного блока и вывести C++-исключение через корневой C API. Регрессия
воспроизвела аварийное завершение; теперь возвращается [`FVM_OUT_OF_MEMORY`](../include/flashvm/flashvm.h#L46) с
корректно установленным признаком обработанного входа.

| Тест | Проверки |
| --- | --- |
| `jit_try` | Host/SWF4–8, три режима, обычные/заменяющие/повторные выходы, оба End, снимок стека, host/loaded привязки, global/private/игнорируемые регистры, встроенный NUL, общий пул и вложенные With/Try |
| `jit_try_callbacks` | GC при единственном корне в снимке стека, сохранённом Return, pending-исключении или прежней host-привязке; GC в catch/finally; rich fault, замена finally и запрет удаления активных отображений |
| `jit_try_allocation` | Отказы компиляции/вызова, включая cold/warm automatic входы, именной/регистровый catch, host/loaded, manual/automatic функция, публичный root и bounded-кадр; прежний handle, восстановление/повтор, снятая активность всех блоков и точный размер кэша |
| `jit_try_validation` | Повреждённые записи/тела, переходы между блоками, неподдерживаемые Actions, 64/65 уровней, корневые локальные области, бросающий loaded setter, точный бюджет, пропуск finally при ошибке бюджета/привязки, смещения и breakpoint при наличии кэша |

Проверяется согласование интерпретатора и JIT FlashVM; полной сверки с эталонным
Flash нет. Actions звука/качества, остальные API, полная мультимедиа и реальные
запуски Windows/macOS/Android остаются открытыми. Ни одна стадия не закрыта.

Linux Release: успешные результаты всех 767 AGG, 767 Cairo и 748 minimal после
восстановления прав ELF и повторов. Восемь целевых проверок прошли heap/global
ASan+UBSan; stack ASan и LeakSanitizer отключены. Расширенный OOM-перебор прогретого
кэша прошёл все профили и санитайзер. Свежие backend fixtures прошли 26
синтетических сценариев Unicorn ISA/ABI.
