# vfs.unload

[English](STYX_RPC_UNLOAD.md) · [Файловые методы](STYX_RPC_OS.ru.md) ·
[Реализация](../src/styxrpc/module_import.c)

```actionscript
vfs.unload(module)
os.unload(module)
```

Закройте проверенный прокси Dis в штатном парном плеере из фильма либо
отделённой задачи, которой он принадлежит. Передайте объект, полученный
через [`file.load()`](STYX_RPC_OS.ru.md) либо через проверяющий загрузчик
модулей в этом контексте. Другой объект или неверное число аргументов
приводят к ошибке аргумента.

Первый вызов возвращает `true`. Повторный вызов для того же прокси
возвращает `false`. Все ссылки на него и извлечённые методы используют
общее состояние. Новый вызов через закрытый прокси приводит к исключению.
Если getter закрывает прокси при преобразовании аргументов, уже начатый
вызов может завершиться со своим исходным fid.

Прокси освобождает fid каталога и свою ссылку на аренду живого модуля.
Возвращённые каналы удерживают собственную ссылку. Они работают после
выгрузки и освобождают ссылку при закрытии или сборке мусора.
Последний владелец отзывает поколение в DisVM. Метод может ждать
подтверждения Styx clunk. Парный DisVM завершает поток владельца и
освобождает слот асинхронно.

```actionscript
var source = os.open("/library/counter.dis");
var counter = source.load();
source.close();
var answer = counter.next(41);
var released = os.unload(counter);
```

Закрытие исходного файла оставляет прокси доступным для вызова. После
выгрузки `released` равен `true`. Новая загрузка создаёт свой прокси.
См. [живую загрузку](STYX_RPC_LIVE_DIS.ru.md) и
[объекты каналов](STYX_RPC_CHANNELS.ru.md).
