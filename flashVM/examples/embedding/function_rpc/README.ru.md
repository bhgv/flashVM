# Интерфейсы оригинальных функций: процессы, потоки и LAN

[English](README.md) · [Исходник](main.c)

Пример C89 в `examples/embedding/function_rpc/` показывает три схемы. Оригинал
функции и userdata остаются в исходной FlashVM; получатель хранит вызываемый
интерфейс. Вызовы идут через один слушающий TCP-порт брокера и содержат ID
маршрутизации и запроса.

Требуются CMake и компиляторы C/C++ с поддержкой C89/C++98. Минимальный профиль
включает сокеты и потоки, отключает графику/медиа и собирает поставляемые
зависимости из репозитория. Для автоматической межпроцессной проверки нужен Python 3.
Файлы: `main.c` — учебная программа, `function_rpc_example.h` — её константы.

Выполняйте команды из корня репозитория FlashVM, а не из этого каталога:


```sh
cmake -S . -B build-rpc -DFVM_DEFS_FILE=cmake/profiles/minimal.defs -DCMAKE_BUILD_TYPE=Release
cmake --build build-rpc --config Release --target flashvm_examples_embedding_function_rpc_main
```

В Windows запускайте созданный `.exe`; генератор может помещать его в каталог
конфигурации. Аргументы те же.

## Две отдельные FlashVM в разных потоках одного процесса

```sh
./build-rpc/flashvm_examples_embedding_function_rpc_main threads
```

Первая среда выполнения передаёт свой контекст исключительно потоку брокера.
[`fvm_worker_run`](../../../include/flashvm/worker.h#L21) создаёт вторую независимую среду и контекст на рабочем потоке.
В него копируется только примитивная строка URI. Вторая VM импортирует интерфейс
и вызывает оригинал через TCP, хотя обе работают в одном процессе. Объекты VM,
адрес функции и указатель userdata в VM-получатель не передаются.
После join хост возвращает себе исходный контекст и проверяет счётчик оригинала.
Вывод содержит `two independent runtime threads via TCP passed` и
`original calls=4`.

## Два отдельных процесса на одном компьютере

В терминале A запустите источник:

```sh
./build-rpc/flashvm_examples_embedding_function_rpc_main serve
```

Скопируйте первую строку вывода — полный URI `fvm://...`. В терминале B:

```sh
./build-rpc/flashvm_examples_embedding_function_rpc_main call "URI_ИЗ_ТЕРМИНАЛА_A"
```

Клиент проверит результат 42, исключение из трёх байтов `C\0E`, возвраты
UNSUPPORTED и ERROR. После завершения клиента нажмите Enter в терминале A.
Сервер вернёт контекст хосту, проверит четыре обращения к исходной userdata и
завершится. Кодек сериализации нативного callback не регистрируется.

## FlashVM на двух компьютерах в LAN

Соберите пример на обоих компьютерах. Если LAN-адрес компьютера A —
`192.168.1.10`, на нём выполните:

```sh
./build-rpc/flashvm_examples_embedding_function_rpc_main serve 0.0.0.0 192.168.1.10 9210
```

`0.0.0.0` выбирает локальные интерфейсы прослушивания, а `192.168.1.10`
публикуется в URI и должен быть доступен компьютеру B. Для прослушивания только
LAN-интерфейса укажите `192.168.1.10` обоими аргументами. Вместо публикуемого IP
можно использовать доступное DNS-имя. TCP-порт 9210 должен быть доступен из B в A.
URI даёт право вызова: передавайте его только нужному получателю.

На компьютере B подставьте полный URI, напечатанный A:

```sh
./build-rpc/flashvm_examples_embedding_function_rpc_main call "URI_С_КОМПЬЮТЕРА_A"
```

Проверяются те же четыре результата. Затем нажмите Enter на A для возврата
контекста и остановки. Замените пример IP/порта действительными значениями;
для другого компьютера нельзя публиковать `127.0.0.1` или `0.0.0.0`.
Все оригинальные функции обслуживает один выбранный слушающий порт. Клиенты
создают обычные исходящие TCP-соединения, без дополнительных слушающих портов.
Порт 0 означает автоматический выбор; URI содержит фактически выбранный порт.

Локальные автопроверки покрывают независимые VM-потоки, отдельные процессы,
прослушивание интерфейса/всех адресов, публикацию IPv4/DNS и неверные порты.
Они не подтверждают запуск на двух физических компьютерах и в других ОС.
[Владение и ограничения](../../../doc/REMOTE_FUNCTIONS.ru.md): циклы вызовов разных брокеров,
постоянное мультиплексированное соединение и произвольный параллельный доступ
к одной куче остаются открытыми.

## Автоматическая проверка

После сборки выполните из корня репозитория:

```sh
ctest --test-dir build-rpc -C Release -R "function_independent|examples_embedding_function_rpc_main" --output-on-failure
```

Проверяются подсказка без аргументов, две VM в разных потоках, отдельные процессы,
адреса прослушивания/публикации и неверные порты. Межпроцессный тест включается,
если CMake нашёл Python 3; потоковый тест от Python не зависит. Не отключайте
`FVM_BUILD_EXAMPLES` и `FVM_BUILD_TESTS` для этой команды.
