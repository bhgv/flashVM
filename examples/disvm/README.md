# Типы Limbo и многопоточные сценарии DisVM

Эти примеры запускаются в hosted DisVM. Компилятор `limbo-bootstrap`
выдаёт образ для этого рантайма, а `init: fn()` служит точкой входа.
Обычный Inferno Shell использует другой интерфейс `Command.init`.
В исходниках примеров прокомментирована каждая содержательная строка.

## Сборка и запуск

Из корня репозитория, с CMake, C/C++ toolchain и Python:

```sh
cmake -S disVM/runtime -B build/runtime -DDVM_RUNTIME_TESTS=OFF
cmake --build build/runtime --target disvm limbo-bootstrap
mkdir -p build/disvm-examples
for source in examples/disvm/*.b; do
    name=$(basename "$source" .b)
    build/runtime/bootstrap/limbo-bootstrap \
        -I disVM/upstream/module -I disVM/module \
        -o "build/disvm-examples/$name.dis" "$source" || exit 1
done
for mode in --no-jit --jit; do
    for image in build/disvm-examples/*.dis; do
        build/runtime/disvm "$mode" --gc-worker --managed-workers 3 "$image" || exit 1
    done
done
```

Для проверки автоматического пула замените `3` на `auto`. Режим
`--managed-workers 1` оставляет одного исполнителя. `spawn` создаёт
гостевой процесс, а пул распределяет гостевые кванты по OS-потокам.
В текущем рантайме эти кванты входят в эксклюзивный `NativeWorld`.
Аудированные нативные ожидания могут отпускать этот допуск.

## Карта типов

| Тип или конструкция | Что хранит или делает | Пример |
|---|---|---|
| `byte` | Беззнаковый байт. Приведение к `int` позволяет считать и сравнивать | [types.b](types.b) |
| `int`, `big` | Целые. `big` используется для широких значений, индексов и значений Bigtable | [types.b](types.b), [table.b](table.b) |
| `real`, `fixed(scale)` | Вещественное значение и фиксированная шкала. Шкала является частью объявления типа | [types.b](types.b), [advanced.b](advanced.b) |
| `string`, `array of byte` | Строка Unicode и отдельное байтовое представление UTF-8. Число байтов может отличаться от числа рун | [types.b](types.b) |
| `array of T` | Массив с индексируемыми элементами. `len` возвращает число элементов | [types.b](types.b) |
| `list of T` | Список из узлов `::`. `hd` читает голову, `tl` возвращает хвост, `nil` задаёт пустой список | [types.b](types.b) |
| Кортеж | Позиционные значения разных типов, в том числе результаты с кодом статуса | [types.b](types.b), [table.b](table.b) |
| `adt`, `ref`, `pick`, `adt[T]` | Именованное значение, ссылка, размеченные варианты и параметризация типа | [types.b](types.b), [advanced.b](advanced.b) |
| `fn`, `ref fn`, `module` | Функция, типизированная ссылка на функцию и интерфейс загрузки модуля | [advanced.b](advanced.b) |
| `exception(T)` | Именованное исключение с типизированным значением | [advanced.b](advanced.b) |
| `chan of T`, `chan[n] of T` | Канал с типом сообщения и, при наличии `n`, буфером. `<-=` отправляет, `<-` принимает, `alt` выбирает готовую ветвь | [workers.b](workers.b) |
| `nil`, `con`, `iota` | Пустое значение ссылочного типа, константа и счётчик констант. Условия используют `int`, где ноль ложен | [types.b](types.b), [channel-proxy.b](channel-proxy.b) |

## Как читать примеры

- **[types.b](types.b)** создаёт числа, текст, массив, список, кортеж и
  ссылку на ADT. Успех печатается как `PASS DisVM types`.
- **[advanced.b](advanced.b)** использует точный масштаб в одну восьмую,
  функцию через ссылку, обобщённый контейнер, разбор `pick` и исключение
  с данными. Успех печатается как `PASS DisVM advanced`.
- **[workers.b](workers.b)** отправляет задачу через канал без буфера
  и принимает ответ из буферизованного канала через `alt`.
- **[process-control.b](process-control.b)** получает PID дочернего
  гостя, вызывает `killwait` и проверяет, что результат завершения
  потребляется один раз. `cancelwait` снимает ожидание прямого ребёнка,
  `kill` запрашивает завершение, `killwait` также ждёт освобождения
  ресурсов. Полный интерфейс находится в [processctl.m](../../disVM/module/processctl.m).
- **[table.b](table.b)** показывает числовые и строковые ключи. Записанный
  ноль и отсутствие ключа различаются по статусу. Срез и снимок ключей
  сохраняют свои данные после изменения исходной таблицы.
- **[table-workers.b](table-workers.b)** передаёт двум гостям один
  `ref Bigtable->Handle`. Аренда охватывает чтение, вычисление и запись,
  поэтому оба инкремента учитываются. Ответ в канал отправляется после
  `release`.
- **[channel-proxy.b](channel-proxy.b)** хранит переменную в одном госте.
  Другой гость читает и пишет её через явные запросы. Каждый запрос несёт
  собственный канал ответа. Письмо считается выполненным после подтверждения.

## `table` и библиотечные возможности

Hosted [Bigtable](../../disVM/module/bigtable.m) предоставляет управляемые
дескрипторы. Числовые и строковые ключи образуют разные пространства,
значения имеют тип `big`. `count` считает пары, а `length` — плотный
числовой префикс от нуля. Удаление ключа сохраняет остальные индексы.
`slice` копирует полуинтервал `[first,end)`, `splice` транзакционно
заменяет диапазон плотным префиксом другой таблицы. `keysof` выдаёт
независимый снимок, а `keyat` различает вид ключа.

Для синтаксиса `table` в ограниченном фронтенде см.
[примеры FIR](../../fir/v1/examples/tables/README.ru.md).
Для исключений, освобождения аренд и снимков см.
[table-guards](../../disVM/examples/table-guards/README.ru.md) и
[table-leases](../../disVM/examples/table-leases/README.md).
Гостевые расширения задач и представлений имеют отдельные интерфейсы и
примеры [Asinctasks](../../disVM/examples/asinctasks) и
[Asincviews](../../disVM/examples/asincviews). Поддержка стандартных
модулей перечислена в [аудите](../../disVM/MODULE_AUDIT.md), а
пример их запуска находится в [standard-modules](../../disVM/examples/standard-modules).

## Сетевая граница и прокси

Пример `channel-proxy.b` работает внутри одного DisVM. Прозрачный
импорт удалённой переменной как канального прокси в DisVM пока
не реализован. При проектировании сетевой версии транспорт передаёт
типизированный запрос с идентификатором объекта и операции. Владелец
применяет его у себя и возвращает подтверждение или ошибку. Локальный
канал ответа в примере показывает, где клиент ждёт результат. На
сетевой границе потребуются корреляция ответов, обработка разрыва,
повторов и отзыв доступа. Контракт и статус описаны в
[расширениях FIR](../../fir/v1/doc/EXTENSIONS.ru.md).
Рабочие сетевые примеры другого рантайма находятся в
[FlashVM embedding/network](../../flashVM/examples/embedding/network/README.md).

## Граница с C и входной формат

Для нативного интерфейса сверяйте фреймы, дескрипторы и карты GC с
компилятором той же ABI. Ссылки, строки, массивы, списки и каналы требуют
согласованного срока жизни и правил передачи владения. Пример
[нативного модуля DisVM](../../disVM/examples/native-module/README.md)
показывает регистрацию и вызов такого интерфейса.

Компилируемые здесь образы используют hosted NC64. Согласование
отдельного входного Dis64 с Inferno описано в
[типизированной проверке](../../disVM/envelope/TYPED-CHECKPOINT.md).
Скалярные сигнатуры Dis64, выбранные координаты экспорта и профиль
библиотеки можно проверять независимо. Сетевые ссылки и сигнатуры со
строками и списками строк требуют дальнейшего согласования.
