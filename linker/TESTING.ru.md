# Проверка SWL

```sh
cmake -S linker -B build/linker
cmake --build build/linker
ctest --test-dir build/linker --output-on-failure
```

Проверки форматов через подпроцессы не требуют компилятора, Coco/R или VM. Python stdlib
независимо проверяет объектный заголовок/checksum, SWF теги, RECT/shape edges,
bitmap matrix/JPEG bytes, все 16 PCM-профилей, exports, placement и sound events.
Неверные объекты/архивы/ресурсы не портят существующий выход. [C embedding test](tests/embed.c)
проверяет частичный отказ архива с откатом и вывод после отказа callback.
Опционально `FIR_FLASHVM_RUNNER` задаёт host для загрузки SWF и исполнения двух
DoAction в порядке входов. [Сквозной C-пример](examples/ide/README.ru.md).
Историческая проверка обычной и ASan/UBSan-сборок описана ранее; ограничения санитайзеров и полная
сводка — [FIR TESTING](../fir/v1/doc/TESTING.ru.md). Проверка загрузки не является
тестом физического отображения или аудиоустройства.

## SWL 0.3.10: просмотр и параметры сцены

Три нативных CTest проходят: форматы/консоль, прежнее встраивание и новый C API
просмотра. Python проверяет все усечённые префиксы библиотеки, позднее повреждение
без частичных метаданных, точные RECT/частоту SWF на минимуме и максимуме,
неверные параметры сцены и операнд ресурса с именем `--extensions`.
Отдельный C-тест проверяет отмену и отсутствие вызовов при неверном входе.
Учебный C-хост собирается и работает также после переноса SDK и клиента
в независимо переименованные каталоги с пробелами.

Консоль и учебный просмотрщик кросс-компилируются и линкуются для Linux ARM64,
Linux RISC-V64 и Windows x64. Использована явная конфигурация SDK и прежняя
адаптация хостовой оболочки из [описания проверки](../toolchains/VALIDATION.ru.md).
Чужие исполняемые файлы не запускались. Это не закрывает этап 9 роудмапа.
Нового sanitizer-прогона и полной проверки VM в этой серии не заявляется.
