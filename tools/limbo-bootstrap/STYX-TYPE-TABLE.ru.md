# Компиляция метаданных типов Styx в образ Dis

[English](STYX-TYPE-TABLE.md) · [Врезка в компилятор](host/styx_export.c) · [Загрузчик](../../disVM/runtime/vfs/module_shapes.c)

Используйте hosted-компилятор Limbo из сборки CMake с
`LIMBO_BOOTSTRAP_CELL_BYTES=8`. Обычная компиляция Dis сохраняет разрешённые
типы аргументов и результата экспортов и импортов по умолчанию. Например,
из корня репозитория с уже собранным hosted-компилятором:

```sh
build/scalar-runtime/bootstrap/limbo-bootstrap \
  -I disVM/examples/remote-scalar \
  -o build/blend-owner.dis disVM/examples/remote-scalar/blend-owner.b
```

Компилятор сохраняет прежние имя экспорта и 32-битную сигнатуру Dis.
Он дописывает таблицу типов после завершающего нуля старого поля пути
к исходнику. Для таблицы берутся типы, уже разрешённые из реализации и
подключённых интерфейсов. Четырёхбайтовая сборка CMake
и сборка через shell выводят прежний формат. Hosted DisVM также загружает
ранее собранные образы без таблицы.

Таблица описывает `int`, `big`, вложенные кортежи и ссылки на ADT без
`pick` и полиморфизма со скалярными полями `int` и `big`. Длина каждой
схемы ограничена 48 байтами, глубина типов значения шестью уровнями.
Экспорты с другими типами или превышением этих границ пропускаются.
Тело таблицы занимает до 65536 байтов. Если очередная запись превысит
лимит, компилятор завершает таблицу на предыдущей. В образе только с экспортами после маркера `STYXCS1!` идут записи
в порядке экспортов и четырёхбайтовый терминатор `0xffffffff`. Запись
содержит 32-битные номер экспорта и сигнатуру в сетевом порядке, две
однобайтовые длины и две ASCII-схемы этих длин. Нумерация начинается с нуля
в существующей таблице экспортов.

Hosted-загрузчик читает обе таблицы из того же открытого образа. Он
отклоняет распознанную повреждённую таблицу либо несовпадение номера
или сигнатуры с образом. См.
[формат публикуемого профиля](../../disVM/native/terminal/UNIBUS-SERVER-LOAD-PROFILE.ru.md#скомпилированные-типы)
и [пример с двумя VM](../../disVM/examples/remote-scalar/STYX.ru.md#вызов-с-тремя-аргументами).


## Типы импортов

Образ с таблицей связей Dis использует маркер `STYXCS2!`. После той же
секции экспортов с терминатором идёт секция импортов. Запись импорта
начинается с 32-битного номера группы в сетевом порядке. Далее идут те
же поля, что у записи экспорта. Индекс в этой секции задаёт слот внутри
группы. Оба номера отсчитываются с нуля в существующей таблице связей
Dis. Записи отсортированы по группе и слоту. Записи неподдерживаемых
типов могут отсутствовать. Номер группы `0xffffffff` завершает секцию
импортов и образ. Для каждой секции действует свой предел 65536 байтов.

При загрузке образа загрузчик сверяет слоты и сигнатуры импортов с
разобранной таблицей связей. При `load` смонтированного `.dis` клиент
сравнивает типы фактического локального импорта с типами провайдера,
когда доступны обе схемы. Имена и 32-битные сигнатуры также должны
совпасть. Для старых образов без схем импортов сохраняется прежняя
проверка для поддерживаемых профилей шлюза.
См. [пример несовпадения между двумя VM](../../disVM/examples/remote-scalar/STYX.ru.md#вызов-с-тремя-аргументами).
