# Сборка Inferno iyacc

[English](README.md) · [Манифест](UPSTREAM.json) · [Поддержка mk](../mk/README.ru.md)

Источник: bhgv/Inferno-OS-bhgv experiment, 3e3536578b969cf1a460210d8ec667713869ccfc.
Выбраны 17 файлов upstream: utils/iyacc/yacc.c, yaccpar, исходный mkfile, три
дополнительных C-файла lib9/BIO и лицензии. В utils/iyacc находятся C-генератор
и шаблон; сама грамматика Limbo — limbo/limbo.y в выборке компилятора.
Системные yacc/bison и всё дерево Inferno не нужны. Поддержка lib9/BIO берётся из
явно собираемого архива mk без повторного импорта целых библиотек. При отдельной
сборке пути задаются MK_SOURCE_ROOT и MK_SUPPORT_ROOT.

Один запуск из корня:

```sh
./build-workspace.sh --projects iyacc,limbo-bootstrap,ide
```

Скрипт собирает поддержку mk, iyacc, заново генерирует y.tab.c/.h по настоящему
limbo.y, собирает временный нативный Limbo, затем idecore.dis/.sbl. Достаточно
CMake 3.10. Копия лексера компилируется рядом с новым заголовком токенов;
импортированные исходники и заголовки не перезаписываются. Независимая CMake-сборка
bootstrap может не задавать IYACC_EXECUTABLE/IYACC_ROOT и по-прежнему использовать
сохранённые сгенерированные файлы.

Только нативные инструменты: `./build-workspace.sh --backend mk --projects iyacc`.
Исходный yaccpar копируется в BUILD/iyacc/utils/lib/yaccpar согласно поиску ROOT.
В бинарник записывается этот путь сборки; после переноса нужно задать ROOT с новым
корнем шаблонов. Это промежуточный инструмент разработки.

При --tests проверяются генерация настоящего limbo.y и точное совпадение заголовка
токенов. Проверка продуктов нативного компилятора затем собирает Dis и отладочные
данные. Нативные парсер/компилятор Inferno остаются временным bootstrap; все новые
собственные AS/Limbo/FIR парсеры используют Coco/R. Проверен Linux AMD64; другие
хосты и исправление upstream-ошибок не заявляются. Обёртки/mkfile размещены отдельно
от upstream/.
